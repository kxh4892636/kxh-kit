# Code Delivery

以唯一且可核查的 spec、issue 或已确认设计结论为权威输入；前置未决时保持 `not ready`，基线实质漂移时更新权威输入并重新准入。

1. **准入**：核对输入已澄清、相关领域结论已落盘，从输入、工作区配置和用户约束建立或复用执行基线：
   - **工作环境**：实现、运行与验证所需的环境、服务及入口。
   - **执行契约**：范围、固定比较点、步骤、停止点、交付物与状态变更授权。
   - **质量门禁**：`/code-test` 与 `/verifying` 的最小集合，每项带事实来源、执行入口和通过条件。

   基线完整、无矛盾且未决项已清空时为 `ready`，再开始实现。

2. **实现**：遵循 `/code-spec`，完成本轮全部交付物。
3. **测试**：执行 `/code-test`，补齐所需测试并通过测试类门禁。
4. **验收**：执行 `/verifying`，取得当前 diff 的 `passed` 结论。
5. **审查**：执行 `/code-review`，处理双轴发现至无阻塞项；修复后重跑受影响的测试、验收与审查。
6. **提交**：按执行契约与用户已有授权提交通过门禁的变更，报告 commit；缺少授权时先请求。
