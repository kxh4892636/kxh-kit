# Simplify

**证据**：每个候选有 file:line、消费方证据和现状成本；只有“看起来复杂”的 nit 不入选。

**删减**：deletion over addition，以保持行为、约束并降低复杂度为成功标准；净删除量只作辅助证据。正确性审查归 `/code-review`，调查中发现的真实 bug 单独显著报告。

## 1. 确定范围

默认整个工作区的 production 代码；用户可缩至域、目录或文件。未交付的工作区/branch 增量与存量统一评判，排除构建产物、依赖和生成物。

范围及排除项明确时完成；用户只要报告时，以建议呈现为交付，后续应用和修改后验证不适用。

## 2. 读取领域约束

按 DOMAIN.md（`<nano-flow-skill-root-dir>/references/DOMAIN.md`） 定位范围内所有业务域，读取 map、各域 `CONTEXT.md`，以及适用 `AGENTS.md` 和 `/code-spec`；按涉及的职责、契约与术语检索 ADR 和 active/reference Plan，完整读取相关文档。

- ADR 与 CONTEXT 保护 intentional design、seam、契约和术语。候选与 ADR 冲突时列出冲突及重议理由，交用户决定。
- active/reference Plan 约束方向：保留未交付 requirement 和已确认路线；需解释设计理由时再读取相关 archived Plan，仅作历史依据。

全部相关约束已读取、受保护设计已列出时完成。

## 3. Survey

按域或顶层目录分区，并行派遣 subagents；每人取得一个分区、完整约束及下列角度。用户指定 focus 时只调查对应角度。单目录以内直接调查；无 subagent 能力时按分区顺序执行并在报告说明。

| 角度     | 寻找                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **复用** | 重复实现、可用 stdlib/平台/已安装依赖替代的手写逻辑；点名复用对象及位置                                                                |
| **删减** | dead code、speculative generality、单实现抽象、转发 wrapper、冗余状态、复述代码的注释及更短等价形态                                    |
| **深度** | generic path 的单调用方特例、层叠 workaround、绕开根因的 wrapper；深层修复只标记                                                       |
| **性能** | 冗余计算/读取/调用、N+1、独立操作串行、启动或请求热路径重活、过宽读取、无界增长、未清理 listener/handle；TOCTOU 改为直接操作并处理错误 |

按 **Chesterton's fence**，删除前用 blame、消费方检索和领域约束核对存在理由；理由不明标 low，猜测项丢弃。只有测试/文档消费且行为不承重是强候选；删除生产消费者依赖的行为属于 feature decision，保持行为的结构简化属于 cleanup。

每个分区覆盖全部选定角度后才结束；每项均有位置、消费方与成本证据。

## 4. 汇总与应用

发现格式：`file:line → 问题 → 现状成本 → 建议 | confidence: high/medium/low | risk: SAFE/CAREFUL/RISKY`。

合并去重，丢弃证据不足项。冲突按“正确性 > 用户 focus > 可读性与复用 > 微优化”裁决；微优化仅在已确认热路径上优先。互斥且均可行时选改动较小者，备注另一方案。

| Risk        | 定义                                                                          | 应用                                                   |
| ----------- | ----------------------------------------------------------------------------- | ------------------------------------------------------ |
| **SAFE**    | 已证明行为不变，如无生产消费方的 dead code、未使用 import                     | 直接应用，运行 targeted tests                          |
| **CAREFUL** | extract、inline、局部重命名、拍平嵌套等语义保持修改                           | 逐文件应用并运行 targeted tests，失败回退该条          |
| **RISKY**   | 公共契约（导出名/API/配置键）、行为可能改变、受保护设计、并发化或访问模式重构 | 只呈现风险、覆盖情况及新 issue 或 `/questing` 跟进建议 |

只报告模式完成呈现即可；应用模式限于发现及修复所需最小邻域，SAFE/CAREFUL 均应用或回退、RISKY 逐条呈现时完成。

## 5. 验证与收口

有修改时运行触及文件的 targeted tests 和仓库 linter/typecheck；失败则单独回退对应修复并报告。有意保留的全局锁、O(n²) 扫描、naive heuristic 等上限，按 `/code-spec` 注明原因及升级触发条件。

按分区、角度、tier 报告发现与建议、已应用项、跳过及理由、净删除量；顺序替代并行时说明。适用验证通过且报告完整时完成。

`/code-spec` 要求的校验与错误处理、安全措施、用户明确要求均保留；深层或超出本 pass 范围的重构通过 RISKY 跟进。
