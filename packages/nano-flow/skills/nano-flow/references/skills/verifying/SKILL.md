# Verifying

**证据链**：交付主张 → 适用门禁 → 实际结果 → 结论。失败时进入**最小循环**: 失败 → 证据定位 → 最小修复 → 重验.

## 证据链

1. **明确主张**：确定变更、受影响单元、外部契约、消费者和目标环境。每项主张均映射到影响面，未知与非范围已明确时完成。
2. **选择门禁**：从工作区声明的格式、静态检查、测试、构建、运行态和消费者路径中选取足以支撑主张的最小集合。每项均有事实来源、执行入口和通过条件时完成。
3. **执行门禁**：按依赖顺序从最早缺少可信证据处开始；旧证据仅在目标、版本、配置和前置仍适用时复用。每项均有实际结果、可信证据或明确阻塞前置时完成。
4. **最小循环**：从最早失败门禁取证，在授权范围内做最小修复，从最早受影响门禁重验；仍失败则以新证据继续。每轮失败、修复与重验一一对应，受影响证据链通过或明确 `blocked` 时完成。
5. **闭合结论**：先给结论，再记录各门禁结果、关键证据、未验证范围和剩余风险。结论不超出证据覆盖范围，另一执行者可复现失败或阻塞项时完成。

## 结论门禁

- `passed`：范围内适用门禁均实际通过，或有仍适用于当前目标的可信通过证据；修复影响的门禁以修复后的重验结果为准。
- `failed`：必要前置满足，门禁结果与主张矛盾。
- `blocked`：必要门禁因前置无法满足而没有结果；记录缺失条件和恢复入口。

局部通过只支持对应范围，未验证部分保持显式。
