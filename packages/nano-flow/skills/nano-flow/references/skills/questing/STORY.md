# 用户故事

使用 **3C**：`story.md` 是 card，分轮访谈形成 conversation，可判定验收形成 confirmation。

## 1. 定位 Plan

按 领域定位规则（`<nano-flow-skill-root-dir>/references/DOMAIN.md`） 确定 owner，读取相关 CONTEXT、ADR 与已有 Plan；按 [故事模板](#故事模板) 创建或续写：

```text
docs/{domain-name}/plans/active/YYYY-MM-DD-中文工作名/story.md
```

owner、Plan 路径、原始想法和相关现有产物均已确定时完成。候选决策只进入 `story.md`；领域术语与 ADR 由 `domain` 分支确认后维护。

## 2. 逐轮澄清

按 Design [tree](DESIGN-TREE.md) 推进，将角色、用户结果、收益、边界、验收与未知项纳入问题；每轮由用户回答后再继续，问题使用以下格式：

```markdown
❓ **Q1 - {问题标题}**：{问题；需要时列出互斥选择}

➡️ **建议**：{推荐答案与关键理由}
```

每轮就地更新 `story.md`：已确认角色和完整用户结果进入对应章节，较大结果归入 epic；未知项进入「迷雾」，澄清后迁移；使用的产物记入「上下文」。

用户确认共同理解前，工作限于取证、访谈与维护 `story.md`。拷问收敛，且已复述故事地图并获用户确认时完成。

## 3. 闭合故事集

核对每条故事具有唯一且单调递增的 `US-NNN`、明确角色与收益、至少一项可判定验收；迷雾为空或保留项均获用户明确接受；每个原始意图恰好映射到故事或已接受的非范围。

从工作区根运行 `node <nano-flow-skill-root-dir>/scripts/check-domain.mjs .`。校验通过且用户确认故事集覆盖原始想法时完成。

## 故事模板

属于 epic 的故事使用四级标题；独立故事使用三级标题，不创建空壳 epic。

```markdown
# {工作名}

## 原始想法

{用户的最初表述，保留原话}

## 角色

- **{角色名}**：{是谁、处境与工作方式}

## 故事

### {Epic 标题}

{这组故事共同完成什么}

#### US-001 {故事标题}

作为 {角色}，我 {想要}，以便 {收益}。

- [ ] {可判定的验收结果}

### US-002 {独立故事标题}

作为 {角色}，我 {想要}，以便 {收益}。

- [ ] {可判定的验收结果}

## 迷雾

{尚未澄清的空白；澄清后迁移到权威章节}

## 上下文

{通过路径或 URL 引用生成故事时使用的现有产物；域内文档使用相对路径}
```

模板可扩展：仅当内容无法归入现有章节，且缺少它会损失执行或验收信息时新增中文章节。
