# UI 原型

同一路由比较多个变体，默认 3 个、上限 5 个；写明问题、数量与比较依据。

## 1. 宿主与设计

优先挂在既有页面，只切换渲染子树，保留数据获取、params 与鉴权；没有合理宿主时按项目约定创建一次性路由。在真实页面框架、数据与密度中评估。

- **视觉探索**：遵循简报、受众与项目体系。每个变体先列 4–6 个命名色值、display/body 字体角色、布局线框及一个主题特征；布局、信息层级与主要操作实质不同。
- **局部交互**：继承现有配色、字体与组件，仅设计和比较相关布局、状态或操作差异。

变体独立布局，可共享页头；差异不足时围绕问题重做。默认只读，写操作接 stub；文案遵循 [共同写作规则](SKILL.md#设计中的写作)。

## 2. 切换

导出 `VariantA`、`VariantB` 等组件，通过 router 更新 `?variant=`，默认 A，支持分享与刷新。

底部中央放置 `PrototypeSwitcher`，显示左右箭头与当前 key，循环切换；键盘左右键同效，焦点在 input、textarea、contenteditable 时保留编辑行为。切换栏与被评估页面可区分，仅开发环境显示。

## 3. 交付与吸收

走查全部变体，覆盖移动端、可见键盘焦点与 reduced motion，环境支持时截图。提供 URL 与全部 keys，接受组合反馈，按 [共同规则](SKILL.md#共同规则) 保存整套变体及选择依据。

正式实现将选定方案并入既有页面或提升为正式路由，移除落选变体、切换栏与一次性路由。
