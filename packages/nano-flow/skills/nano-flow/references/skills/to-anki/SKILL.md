# Anki 制卡

## 1. 对齐批次

从材料和环境推断可验证的配置, 只询问阻塞预览的缺项:

- **来源**: 路径、文件列表或用户提供的内容;
- **卡片类型**: 学习笔记基础卡、词汇卡、问答卡或完形填空卡;
- **目标**: 根牌组、子牌组映射、笔记类型和字段映射;
- **格式**: 正反面、来源链接、标签和需保留的 HTML;
- **重复策略**: 委托 `nnf anki` / AnkiConnect 判重, 默认在整个集合判重, 跳过并记录重复项; 仅用户明确要求时创建重复项.

**完成标准：** 每张候选卡的上述配置均有明确值, 未验证信息已标为假设.

## 2. 解析源材料

按章节和语义知识点划分材料, 保留标题层级与来源行号:

- **原子化**: 每张基础卡聚焦一个主要回忆目标;
- **忠实**: 答案只来自源材料, 补充内容单独标明;
- **可复现**: 相同输入和规则产生相同牌组、字段与卡片边界.

### Markdown 学习笔记约定

- 记录 YAML frontmatter 中已有的 `id`; 默认每个 Markdown 一张卡, 子牌组取文件名去除数字前缀和 `.md`, 如 `010-Go-入门.md` → `Go-入门`.
- **默认配置**: 根牌组为 `<topic>` (用户未指定时的预览假设); 笔记类型 `基础`, 字段 `正面` / `背面`; 正面 `根牌组-章节名-知识点`, 背面 `<a href="https://wiki.kongxiaohan.cn/<id>">跳转wiki</a>`.
- 链接基址与 `id` 齐全才生成链接, 否则将背面格式列为待确认.

**完成标准：** 每张候选卡已记录一个源条目或明确的 Markdown 范围 (可用稳定标识追溯); 每个源条目恰好归入候选或排除之一.

## 3. 生成强制预览

预览版本递增 (`v1`, `v2`…), 标明源条目与候选总数. 每个候选占一表格行, 展示唯一序号、来源标识、完整牌组路径及全部字段实际值 (HTML 原样展示). 公共笔记类型、字段映射、标签和重复策略集中列出, 差异写入对应行; 同时列出排除项及原因、假设、未验证项和冲突.

**完成标准：** 表格行数等于候选总数, 展示范围覆盖全部源条目, 仅凭预览即可复现待执行批次.

## 4. 等待确认

用户提出修改、源文件变化或字段映射改变时, 重新预览并等待确认.

**完成标准：** 当前预览版本获用户明确确认且批次未变, 才进入创建.

## 5. 创建

Anki 操作先读 `/nano-flow-cli` 的 Anki 路由, 命令与 option 以现场 `nnf anki --help` 为准. 写入一律用 `nnf anki` 经 AnkiConnect 操作本机 Anki, 不直接读写数据库或 collection 文件.

1. 创建缺失牌组, 按确认预览的序号与重复策略逐条或批量创建卡片.
2. 工具明确返回的重复结果记为跳过, 其他错误记为失败, 保留原因.
3. 实际模板、字段或目标状态与预览不符时, 重新预览.

**完成标准：** `创建数 + 跳过数 + 失败数 = 已确认候选数`, 每个结果对应预览中的唯一序号.

## 6. 核验交付

写入后从 Anki 回读目标笔记. 报告已确认版本与候选总数、各牌组创建数、笔记类型与字段映射、创建/跳过/失败数及原因、核验方式与结果及未解决问题.

**完成标准：** 已逐项核对回读笔记的牌组、笔记类型和关键字段与确认预览一致, 报告数量与原因符合回读结果; 不一致项已明列.
