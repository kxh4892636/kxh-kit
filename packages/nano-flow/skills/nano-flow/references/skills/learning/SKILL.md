# Learning

制作笔记执行第 1–4 步，Anki 制卡为最后的可选步骤；仅需制卡时，以已有材料直接进入第 5 步。

## 1. 建立覆盖账本

完整读取材料，将每个有意义的内容单元登记为知识点；合并语义相同的重复项，保留全部来源位置。源内容均已登记、知识点均有来源且已去重时完成。

## 2. 组织笔记

按概念体系与知识边界分组，一个笔记承载一个可独立学习的语义概念：

- 篇幅与知识密度正比，限 144 行；超出时按语义拆分，不可再拆的连贯主题可超出并保留理由。
- 对齐工作区已有笔记结构，目录最多二级，末级目录最多 13 个 Markdown 文件。

为覆盖账本中的每个知识点记录唯一目标文件与标题；归属明确且上述约束均满足时完成。

## 3. 写入笔记

新建笔记使用 [TEMPLATE.md](TEMPLATE.md)，将 `<uuid>` 替换为新的唯一 UUID；修改时保留原 UUID。

先用**费曼技巧**讲清内容，再用**电报体**压缩表达；冲突时费曼技巧优先：

- 面向初学者，用简单语言讲解，保留准确术语并在首次出现时通俗解释；发现理解盲点时反思、优化，直至知识点清晰。
- 顶部问题覆盖全部知识点，回答后可完整讲解与主动复习；仅凭各级标题即可知道需要讲解的内容。
- H1 仅用于主题，正文从 H2 连续递进，层级由知识关系决定。
- 普通文本每个 bullet 承载一个独立知识点，使用 `term: explanation;`；富文本优先使用代码块、表格、公式或图示。
- 优先讲清概念与权衡，精确记忆处补充说明。

覆盖账本中的所有目标文件均成功写入时完成。

## 4. 验证笔记

逐项核对覆盖账本，源内容无未映射项，知识点无重复主归属。检查所有目标文件：新建 UUID 已替换且在工作区内唯一，原有 UUID 未变，各级标题可独立展示知识结构。

运行工作区已有且适用的 Markdown 检查或文档构建；上述核对及全部适用检查通过时，笔记完成。

## 5. Anki 制卡（可选）

需要制卡时，读取 [ANKI.md](ANKI.md)，以本次笔记或用户指定材料为来源，执行其中的流程与完成标准；否则笔记验证通过即完成。
