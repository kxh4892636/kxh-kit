# Do

一次 `/skill:do` 是一个 loop：定基线 → 实现 → 验证 → 审查，直到适用门禁全部通过。基线见 spec、note、领域文档与工作区事实。

## dev gate

动手前明确三项基线：

- **工作环境**：执行与验证所需的环境、服务与入口。
- **执行契约**：规格来源、交付边界、实施顺序与检查点。
- **质量门禁**：本次适用的最小门禁集合，取自 `## verifying`。

交付期间基线实质漂移时，更新受影响的权威输入并重跑本 gate。

## execution

按执行契约实现，一次交付一个可独立验收的单元。触及代码时遵循 `/skill:code-spec`。

## verifying

1. **选门禁**：从工作区声明的规范、格式与静态检查、测试、构建、评审、运行态与消费者路径中取最小集合；选中评审即执行 `## review`。
2. **跑门禁**：按依赖顺序依次执行。
3. **最小循环**：从最早失败的门禁取证，做最小修复，从最早受影响的门禁重验。

- **代码**：补齐所需测试并通过基线内全部测试；覆盖率按仓库口径（见各包 `vite.config.ts` / `vitest.config.ts` 的 `thresholds`），无法测量则标记未验证。
- **收口**：全部适用门禁通过、审查发现已处理才算验收；未执行或未通过项在交付说明里写清，保持待验收。

## review

- **Spec**：读交付产物对应的 spec、note、领域文档与其他来源，验证是否满足工作需求。
- **Standards**：遵循 `AGENTS.md` 与适用的规范 skill，判断是否符合工作规范。

汇总去重后逐项修复或说明不采纳的依据；修复后复验受影响门禁并复查原发现。代码审查使用 `/skill:ponytail-review`。
