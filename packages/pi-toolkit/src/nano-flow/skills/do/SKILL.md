# Do

## dev gate

基于 plan 和领域文档，根据工作区事实和用户输入，明确交付基线：

- **工作环境**：执行与验证所需的环境、服务和入口。
- **执行契约**：执行所需的规格、交付边界、实施顺序与检查点。
- **质量门禁**：适用的 `## verifying` 的最小集合。

交付期间基线实质漂移时，更新受影响的权威输入并重新执行本 gate。

## execution

基于 plan 和领域文档，根据 `## dev gate`，实现。

## verifying

1. **选择门禁**：从工作区声明的规范、格式与静态检查、测试、构建、评审、运行态和消费者路径中选取验收门禁的最小集合；
2. **执行门禁**：按依赖顺序依次执行最小集合中的门禁。
3. **最小循环**：从最早失败门禁取证，做最小修复，从最早受影响门禁重验。

基线内所有适用门禁通过且审查发现已处理时完成验收；未执行或未通过项明确记录，保持待验收。

## review

从两个视角进行审查：

- **Spec**：读取交付产物对应的领域文档、plan和其他来源，验证是否符合工作需求。
- **Standards**：基于已有知识，额外遵循 `AGENTS.md` 和适用的规范 skill，判断交付产物是否符合工作规范。

汇总去重后说明并修复，修复好进行复验，所有项均解决时结束。

## 代码工作

- 执行：遵循 `/skill:code-spec`，完成全部代码实现。
- 验证：
  - 补齐所需测试，通过基线内全部测试；覆盖率采用仓库口径，增量覆盖率 >= 80% 为准；无法测量则标记未验证。
- 审查：使用 `/skill:ponytail-review` 进行代码审查。
