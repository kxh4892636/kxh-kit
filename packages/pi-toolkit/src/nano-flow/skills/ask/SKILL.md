# Ask

持续拷问用户，直到双方达成共识。一次 `/skill:ask` 是一个 loop：一轮取证、提问、修订，直到 frontier 为空。

## 逐轮拷问

**Design tree** 按决策依赖展开：每个决策分出挂在它下面的下游决策。**Frontier** 是前置决策均已定案、此刻就能提问的全部决策。

1. **取证**：事实是 agent 的职责，不向用户索取——查文件、跑命令、读工作区自己拿。取证不阻塞整轮：仍在查的事实算未定前置，只有它的下游问题等它，其余 frontier 本轮照常提问。
2. **拷问**：每轮用一次 `ask_questions` 覆盖整个 frontier；每题编号、给出推荐答案（推荐项放首位，用户答「是」即接受推荐项）、2–3 个互斥选项，每个选项一句话说明取舍。答案依赖本轮其他未决问题的题，归下一轮。
3. **修订**：每轮回答重塑这棵树——定案把 frontier 向外推，解锁依赖它的问题；上游改变时复核并修订失效的下游结论。更新选择、被排除路径与假设，重算 frontier。
4. **收敛**：frontier 为空即完成——每个分支都已访问，没有静默假设。**用户确认达成共识之前不动手实现**；确认后按 `/skill:do` 推进，拷问记录随本轮批量写落盘。

## 每轮记录

拷问记录写进相关 note 的正文，按轮保留仍影响当前决策的问答；同一决策的后续轮次就地改写，不追加重复段落。

```markdown
**Q1** - **<question title>**: <question body, 含互斥选项>
➡️ 推荐：<recommended answer 与依据>
✅ 结论：<用户选择或确认，以及它对下游的影响>
```
