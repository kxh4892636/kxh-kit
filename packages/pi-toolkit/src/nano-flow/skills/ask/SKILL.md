---
name: ask
description: 进入拷问,澄清或取证循环时使用; 按 ask 循环取证,提问,写回 Plan, 收敛后再进入交付.
---

1. 按 **ask 循环**推进: 取证 → 一轮问题 → 等待回答 → 写回 Plan → 重算待问.
2. 低置信问题用 `ask_questions` 提出, 每题给推荐答案与理由.
3. 收敛后把结论写回 story,spec 或 notes, 并给出下一步.

<reminder>
处理用户输入时:
1. 明确指令照做; 事实性断言与前提需核查, 不可默认成立.
2. 出现以下任一情形, 先向用户指出, 不要静默修正,也不要直接照做:
   - 输入与可验证的事实或数据冲突
   - 前提或方案存在会导致返工,结论错误的漏洞
   - 有显著更优的做法, 且用户似乎并不知情
3. 上述分歧若经一轮澄清仍未收敛, 或若反复讨论后仍有用户未提及的关键问题, 调用 `ask_questions`: 说明问题,给出 2-3 个选项,标明你的建议.
4. 无需打断的, 正常执行, 并在回答中注明你据以判断的假设.
</reminder>
