# Rule

笔记分知识型与使用型，约束不同。先判定类型，再套对应约束；两类可以并存于同一材料，但正文不重复。

## 1. 怎么判定类型？

| 判据                   | 知识型               | 使用型                  |
| ---------------------- | -------------------- | ----------------------- |
| 读者要不要闭卷复述     | 要                   | 不要，照着做即可        |
| 换框架或版本后还成立吗 | 成立                 | 会过时                  |
| 有没有唯一正确流程     | 没有，只有权衡       | 有，步骤固定            |
| 典型内容               | 原理、判断规则、症状 | API、配置、最小代码、坑 |

- 同一材料两类都产时：知识型写「为什么、什么情况会错」，使用型写「怎么接、抄哪段」;
- 判不准时按知识型处理：多写的原理可以剪，漏掉的原理只能返工。

## 2. 知识型笔记

- 目标: 记住、复述、主动复习;
- 组织: 按概念体系分层（目录最多三级），一篇承载一个可独立学习的概念;
- H2: 问题式，标题本身就是复习提纲；正文必须能把该问题讲完整，不含标题未声称的内容;
- 覆盖: 账本全量；每个知识点有产出位置或明确排除理由，不允许以「细枝末节」为由丢掉原理;
- 篇幅: 平均 55 行、±20%（44–66），单篇上限 144；超限按语义拆篇;
- 制卡: 默认 `anki: true`，它本身就是复习单元;
- 链接: 相关概念互链；同一解释只出现一次，别处只指向。

## 3. 使用型笔记

- 目标: 用时查得到、抄得走，不要求背下来;
- 组织: 按使用流程排（跑通 → 开发 → 上线 → 按需），篇号即阅读顺序（001…0N）;
- 每篇: 一条走通的主流程 + 一段可直接抄的代码 + 一两条坑；能照抄跑起来才算写完;
- 覆盖: 只留最常用、最关键的路径；细枝末节直接删，但要在账本写「有意删除」，不叫遗漏;
- 原理: 一律回指知识型笔记（如 `000-服务端知识`），本篇不展开「为什么」;
- 篇幅: 不守 55 行均值，以流程完整为界，通常 40–90 行，上限同为 144;
- 目录: 平铺，不设二级目录；条目多于 21 篇时按阶段拆目录，编号连续;
- 合并: 同一链路上的主题可以合成一篇（如校验 + 类型 + 类型安全客户端），合并后仍只保留一处完整解释。

## 4. 两类共同约束

- frontmatter: `id` 为稳定 UUID、`anki` 为布尔；README 是索引，不带 frontmatter、不制卡;
- 目录: 同一层要么全文件、要么全目录，README 不计入，不允许文件与目录间杂;
- 链接: 相对 `.md` 链接必须可达；改目录或改名后全量重写，按解析后的旧目标映射到新路径;
- 正文: 费曼技巧 + 电报体，优先代码块、表格、公式、图示;
- 完成前跑构建与链接校验，UUID 不重复。

## 5. 合并、删除与重编号

- 覆盖账本: 精简前后取「API / 术语 token 差集」——旧笔记有、新笔记没有的 token 逐条判定「有意删除」或「补回」;
- UUID: 主题存续就复用主导篇的 UUID，短链与卡片继续有效；被合并掉的篇目 UUID 随之失效，需重同步 Anki;
- 删除前确认没有入站相对链接；改名只改路径与编号，正文保持不动;
- 重编号后同步更新索引（README）与引用方笔记里的篇号。

## 6. 验收条件

| 类型   | 通过条件                                                       |
| ------ | -------------------------------------------------------------- |
| 知识型 | 账本逐项有落点；每篇能独立讲解与复习；篇幅在区间内；卡片可建   |
| 使用型 | 关键流程各有一条可抄代码；原理都指向知识型；无断链；篇号即顺序 |
