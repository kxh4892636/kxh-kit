# Learning

整理笔记执行下方流程；制作 Anki 卡片时读取 [ANKI.md](ANKI.md)，可独立执行。

笔记约束分两类，动手前按 [RULE.md](RULE.md) 判定：知识型要可复述，使用型要可照抄。

## 1. 覆盖账本

完整读取材料，记录有意义的知识点，合并语义重复并保留全部来源位置；为每项记录产出位置或明确的排除理由。

知识型账本必须全量；使用型只留关键路径，其余写明「有意删除」的理由，不算遗漏。

## 2. 组织笔记

- 知识型: 按概念体系分层，一篇承载一个可独立学习的概念;
- 使用型: 按使用流程平铺，篇号即阅读顺序，不设二级目录;
- 通用: 单篇限 144 行，超限按语义拆分；末级目录最多 21 个 Markdown 文件；同一层只能是全文件或全目录。

## 3. 写入笔记

- 笔记风格使用 **费曼技巧**, 笔记格式使用 **电报体**;
- 每个 H2 使用问题形式, 正文完整回答问题, 不含标题未声称的内容；标题独立展现知识结构, 可完整讲解和主动复习;
- 每个知识点只有一处完整解释，其他 H2 需要时只作指向。
- 使用型每篇给可直接抄的代码与坑，原理回指知识型笔记;
- 优先使用代码块、表格、公式或图示等富文本格式。

写入后逐项核对覆盖账本：范围内知识点均能定位到产出且无遗漏，UUID 无冲突、相对链接有效，并通过适用的文档格式与构建校验时完成。

frontmatter 使用 `id` 与 `anki` 两个字段：`id` 为稳定 UUID；`anki` 缺省为 true，标记 `anki: false` 的笔记不制作卡片。

````markdown
---
id: <uuid>
anki: true
---

# 文档主题

## 这个概念是什么？

- term: 最短完整解释;

## 如何应用这个概念？

- term: 最短完整解释;

```text
最小示例
```
````
