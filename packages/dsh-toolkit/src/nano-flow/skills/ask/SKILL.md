# Ask

使用同一循环逐轮拷问，复用仍成立的结论和确认；领域文档更新遵循 `prompts/system.md` 的维护循环。

## 逐轮拷问

**Design tree** 按决策依赖展开，答案决定下游问题。**Frontier** 是前置已有答案、当前可回答的全部问题。

1. **取证**：事实从工作区与工具查明并保留来源；需进一步探索时委派 subagent，将其作为未决前置，仅暂停下游，其余 frontier 继续。
2. **拷问**：每轮覆盖整个 frontier，问题按本 quest 唯一递增编号，附推荐与理由；依赖本轮未决答案的问题留到下一轮。
3. **修订**：处理用户回答与评价，把结论就地写入权威文档（spec、note、CONTEXT、ADR、question），保留用户反馈及处理结论；更新选择、被排除路径与假设，重算 frontier；上游改变时复核并修订失效的下游结论。
4. **收敛**：可达问题均已处理、frontier 为空、无静默假设，用户反馈有结论；同步进度与恢复入口并跑 `nano_flow_check`。

## 每轮记录

在相关 note 的正文中记录拷问，按轮保留仍影响当前决策的问答；合并重复问答时保留来源、反馈与结论。正文不强制固定章节，能支撑当前决策即可。

```markdown
### 第 {round} 轮

#### Q{question} — {标题}

- 问题：{问题及必要的互斥选择}
- 前置问题：{Q 编号或无}
- 下游边界：{该答案会改变什么}
- 推荐答案及理由：{选择与证据}
- 修改意见：{用户反馈或待评价}
- 处理结论：{已确认/暂定/待取证，以及受影响的文档位置}

每题重复以上结构，编号递增，按轮追加，补充说明始终位于末尾。

### 补充说明

{尚未被问题覆盖的用户输入及处理结论；没有则写无}
```

## 垂直切片

方案收敛后，拆成 note 垂直切片。每个切片对应一个完整用户结果或业务能力，贯穿所需的所有层级；直接依赖成立后可独立完成、交付和验收。降低后续交付难度的前置准备排最前。唯一例外是大范围机械重构：expand → 按影响面分批 migrate（每批一个 note）→ contract 删除旧形态。

结果写进 Plan 的 note 文件，复用已有稳定 name 与有效证据；`related_noted` 只表达关联，不构成 DAG。
