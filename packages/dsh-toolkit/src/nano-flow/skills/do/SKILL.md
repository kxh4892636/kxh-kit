# Do

## 交付流程

1. **基线**：遵循 `## dev gate`，明确交付基线，复用用户已确认的基线与授权；尚未确认时等待用户手动确认。
2. **执行**：按交付物适用的规范完成全部产出；交付物为代码时执行 `## 代码交付`。
3. **验证**：执行 `## verifying`，进行验收。
4. **交付**：交付物可用且证据可回读；通过维护循环更新 spec 与 note，并跑 `nano_flow_check`。

## dev gate

基于 spec、note 或已确认设计作为权威来源，根据工作区事实和用户输入，明确三项交付基线：

- **工作环境**：执行、运行与验证所需的环境、服务和入口。
- **执行契约**：范围、固定比较点、步骤、停止点、交付物和状态变更授权。
- **质量门禁**：该交付物适用的验证门禁与 `## verifying` 的最小集合。

执行、取证、验证与验收后，实时更新 spec 与 note 的受影响内容和执行检查点。交付期间基线实质漂移时，更新受影响的权威输入并重新执行本 gate。

## verifying

1. **选择门禁**：从工作区声明的规范、格式与静态检查、测试、构建、评审、运行态和消费者路径中选取验收门禁的最小集合；选中评审时执行下方 `## review`。
2. **执行门禁**：按依赖顺序依次执行最小集合中的门禁。
3. **最小循环**：从最早失败门禁取证，做最小修复，从最早受影响门禁重验。

基线内所有适用门禁通过且审查发现已处理时完成验收；未执行或未通过项明确记录，保持待验收。

## review

启动两个 subagent，并行审查：

- **Spec**：读取交付产物对应的 spec、note、adr、context 和其他来源，验证是否符合工作需求。
- **Standards**：基于已有知识，额外遵循 `AGENTS.md` 和适用的规范 skill，判断交付产物是否符合工作规范。

汇总去重后逐项修复或说明不采纳的依据；修复后复验受影响门禁并复查原发现，所有项均有结论且无未解决的阻断项时结束审查。

## 代码交付

- 遵循 `/code-spec skill`，完成全部代码实现。
- 补齐所需测试，通过基线内全部测试；覆盖率采用仓库口径，增量覆盖率 >= 80% 为准；无法测量则标记未验证。
- 提交 commit。

## 完成与登记

- 交付物可用且证据可回读后，把 note 的 `status` 置 `completed`（除非仍在等待验收），并在 note 正文写清交付物、验证命令/结果、证据链接与遗留限制。
- 等待用户验收或回答时，把 note 置 `blocked`，`reason` 写清在等什么；解除后回 `in_progress`。
- 完成后同步受影响的 spec 章节与领域文档，再跑 `nano_flow_check`。
- 暂停或切换上下文前更新检查点，恢复时按 spec 的恢复入口继续。
