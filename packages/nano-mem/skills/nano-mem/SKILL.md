# nano-mem

`nm` 是 agent 的长期记忆 CLI：记忆存进用户级全局记忆库，用 SQLite + FTS5 全文检索、FSRS 调度，随使用增强、随闲置遗忘，以 agent/run 分区隔离。按以下纪律读写，不凭感觉。

## 契约

- 现场运行 `nm --help`，以其生成的命令/选项/默认值为事实来源。
- `--json`：成功 JSON → stdout，错误 JSON → stderr；退出码 0 成功 / 1 运行时错误 / 2 用法错误；失败先按错误中的 `hint` 修正前置条件。
- `--db <path>` 覆盖库路径（默认 `$NANO_MEM_DB` → `~/.nano-mem/mem.db`）——使用默认即可，仅在需要独立库时定制。

## 使用纪律

### 何时 add

完成项目决策、获知用户偏好、踩坑、形成事实性结论时，写下后续可复用的表述（1-2 句）：

```sh
nm add "..." [--tag <t> ...] [--meta <k=v> ...]
```

同 agent + run 分区内同文本自动去重（重复 add 返回既有 id）；文本为 `-` 时从 stdin 读取。

### 何时 search

任务开始前先回顾相关记忆；做相似的工作（同类问题/改动/咨询）时先检索：

```sh
nm search <关键词> [--tag <t> ...] --json
```

命中按 score 排序（相关性 × 强度，默认权重 0.65/0.35）；默认只显示活跃记忆（`--include-dormant` 可见休眠）。

### 何时 use

- 记忆实际用于回答或写入产物后，`nm use <id> --grade good` 记强使用。
- `nm search` 命中已自动记一次弱使用（Hard）——不必重复记账；真正用上时升级为强使用（`--no-touch` 关闭自动记账）。
- 使用评级 again/hard/good/easy（默认 good）；强使用让记忆更牢固、检索排名更高。

## 遗忘语义

- 三态「活跃 → 休眠 → 已删」：R < 0.35 即休眠，默认检索隐藏，`--include-dormant` 可见；已删恒不进检索结果。
- `nm gc --dry-run` 预览清理计划（标删 + 清除超期已删），确认后执行 `nm gc`。
- **搜不到不代表没有**：可能在休眠、已删，或属于其他 agent/run 分区；`nm list --state all` 盘点当前分区，`--agent *` 跨分区盘点。
- 写命令先 `--dry-run` 预演；首次运行自动创建默认库，无需初始化。
