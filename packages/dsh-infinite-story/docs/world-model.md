# 世界模型 · 通用规范

> 适用于任何故事：把世界建成一张**有类型的图**，正文是图上走出来的轨迹，账目由插件守着。
> 这份是抽象，不绑定具体故事；具体人物、地名、禁忌写在各自故事的 `rules.md` 与 `world/*.json` 里。

---

## 1. 世界是图

四类节点，两类边。

| 节点             | 文件                   | 关键字段                                                     |
| ---------------- | ---------------------- | ------------------------------------------------------------ |
| 人物             | `world/chars.json`     | `id` `name` `tier` `affinity` `knows` `revealed` `hidden`    |
| 场景             | `world/locations.json` | `id` `name` `links` `focus`                                  |
| 故事线           | `world/threads.json`   | `id` `title` `status` `participants` `dependsOn` `nextMoves` |
| 节点（时效机会） | `beats.json`           | `id` `title` `scene` `opensAt` `expiresAt` `status`          |

| 边                 | 文件                   | 含义                                                                |
| ------------------ | ---------------------- | ------------------------------------------------------------------- |
| 关系               | `world/relations.json` | `{a,b,type,weight,secret}`——谁与谁是什么关系                        |
| 邻接 / 依赖 / 参与 | 内嵌在场景、线、人物上 | `links` 场景互通；`dependsOn` 线的前置；`participants` 谁在这条线上 |

**四条不变量**（插件强制）：

1. `links` 双向，且目标场景存在。
2. `focus` / `participants` / 关系边两端的人，必须在 `chars.json` 登记。
3. 故事线依赖存在、不自依赖、不成环。
4. 节点挂的 `scene` 必须存在。

## 2. 创作：模型自由发挥，用户可引导

- **自动推进**：每章由模型自己挑一条「依赖已满足」的线、一个「窗口已开」的节点往下写；不等指令。
- **用户优先**：用户指定情节时按用户走，冲突的节点标 `失效`，不复活、不回溯。
- **不凭空造**：要加人先写卡，要加地方先写场景，加完再写进正文。
- **一弧一章**：一章 = 一条叙事弧；弧内换场景只写 `---`。

## 2.5 章节粒度：一条弧一章

**弧** = 一次有始有终的变化：某事被提出、被推动、落到一个结果上（哪怕结果是「没成」）。判定一章是否成立的唯一问题是：

> 这一章能不能用一个**阶段名**概括？（海边的两天 / 回到家 / 腰 / 家长会那天）

只能概括成「某个下午」「某一顿饭」的，说明它不是一个弧，并进相邻章。

**三种错误切法**：

- **按场景切**：换房间、换时刻就开新章 → 弧被切碎，读者读到的是碎片。
- **按自然日切**：跨夜就换章 → 一天里可能两个弧，也可能半个弧。
- **按字数切**：写到 N 字就收 → 收口落在哪全看运气。

**章首与章末各有一份职责**：

- 章首：落状态锚点（此刻、在场、上一拍留下的东西），不重述前情。
- 章末：让这一章的事变落地，并把账结掉（节点、好感、伏笔、摘要）。

**规模是结果，不是目标**：一个弧写到 3000 字可能刚起来，写到 15000 字可能刚好收住。默认区间 3000–15000 字、20–60 拍；超了说明弧选太大，该拆成两个阶段名。

具体数值由故事 `rules.md` 覆盖；机制只给这条判据。

## 3. 账目：插件只约束结构，不约束文笔

插件能拦的（违反即报，能唯一确定的自动修）：

- 章号连续、`cursor` 与文件一致
- `clock.advances` 单调、尾对齐、按日压缩
- 节点状态 = 按时间窗推导的结果
- 好感 `level` = `value` 落档
- `hidden` / `revealed` 不重叠
- 未触发伏笔 ≤ 12，同场景开窗 ≤ 3
- 世界图四条不变量
- 换章前 brief 必须新鲜

插件拦不住的（靠机制条款与章末自检）：文笔、语气漂移、伏笔是否埋得动人、节奏是否匀速。

## 4. 时间与因果

- 时间只进不退；推进以 `minutes` 记账，按自然日压缩归档。
- 节点过期即废：不补写、不复活、想重来开新 `id`。
- 正文进 WAL（`log/beats.jsonl`），章末从 WAL 聚合，崩溃可恢复。

## 5. 记忆：三层

| 层       | 载体                           | 用途                                         |
| -------- | ------------------------------ | -------------------------------------------- |
| 世界全量 | `brief.md`（人读 + JSON 字段） | 开章前读；在场、可推的线、伏笔、近章         |
| 章索引   | `chapters/index.json`          | 每章一行：字数、拍数、时间、参与人、线、摘要 |
| 原始正文 | `chapters/NN-*.md`             | 需要细节时按需读，不预载                     |

## 6. 扩张纪律

- 上限：core 8 / major 15 / minor 20；即用即弃的路人只进 `extras` 流水，不进主表。
- 一条线同时只推 1 条主线 + 最多 1 条支线。
- 一章至多新增 1 个人物、1 个地点。
- 好感变动必须给理由，一章至多两处。
