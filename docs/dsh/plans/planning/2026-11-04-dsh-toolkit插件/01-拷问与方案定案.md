## 决策与证据

### 第 1 轮

#### Q1 撤回的实现路径

- 问题：宿主没有删除会话/事件的 API，撤销一轮按哪条路径落地：fork / 原地截断 / 只停止。
- 前置问题：无。
- 下游边界：决定「撤回」工具的宿主实现、UI 反馈文案，以及是否需要重启宿主。
- 推荐答案及理由：A 分支式撤销（cancel → fork 到上一轮结束 → 打开子会话），因为 fork 是唯一被支持的历史截断手段。
- 修改意见：用户选 **B 原地截断**。
- 处理结论：**B 在进程内不可行**，证据见下，转入 Q5。

B 不可行的取证（subagent + 直读宿主包）：

- 会话控制器 remote 只有 `attachment/cancel/create/fork/list/modelCatalog/openWorkspacePath/projections/prompt/rename/search/selectModel/updateQueue/workspacePathApplications`，无删除/截断（`dsh-api-session-controller/lib/index.js`）。
- 存储契约「事件从 seq 0 连续、永不重写」：`dsh-session-persistence/lib/index.js:242-249`。
- 存活会话遮蔽磁盘：`dsh-api-session-controller/lib/index.js:1088-1093`（`ctx.sessions.get(sessionId)` 命中即用 `snapshotEvents()`）；`dsh-session-query/lib/index.js:120-132`（"A known live target never consults persistence"）。
- 改文件后存活会话追加会撞 seq gap，读取端按损坏拒绝：`dsh-session-format-v1-to-v2/lib/index.js:243-244`。
- zstd 帧内切会把切帧内完整记录在下次写入前重新落盘：`dsh-session-persistence-jsonl/lib/index.js:3011-3038`、`:232-235`。
- 无公开 API 丢弃存活会话：`SessionStore` 只有 `create/prepare/enter/announce/get/list/fork`（`dsh-session/lib/index.js`），agent 的 detach 是 `enter()` 返回的私有闭包。
- 工作区「会话删除」明确为未提供能力：`dsh-workspace/README.zh.md`「移除绝不删除数据……会话删除与文件夹移除是彼此独立且尚未提供的功能」。

### 第 2 轮

#### Q5 撤回路径修订

- 问题：既然 B 不可行，改走 fork(+归档) / fork(不归档) / 只停止。
- 前置问题：Q1。
- 下游边界：同上。
- 推荐答案及理由：fork + 归档原会话（视觉上等价于原地撤销，且不删数据）。
- 修改意见：用户答「探索会话撤回的实现, 我要原封不动的恢复到{上一轮结束的状态}, 同时保留本轮输入的用户输入」。
- 处理结论：目标可被 fork 精确满足（fork 复制切点前的逐事件前缀），但「保留本轮输入」需要额外把该轮 `user/message` 文本回填到新会话输入框；回填通道取证：`conversation-input.requestDraftInitialization(options)` 支持 `whenDraftExists: 'replace'`（`dsh-client-ui-conversation/lib/client.js:15107-15121`），调用范式见 `dsh-client-ui-workspace/lib/client.js:1487-1491`（`ctx.get('conversation').input.requestDraftInitialization(binding, options)`）。

### 第 3 轮

#### Q6 撤回机制定案

- 问题：C1 无感 fork / C2 启动时离线截断 / 两者都做。
- 前置问题：Q1、Q5。
- 下游边界：实现工作量、是否需要重启宿主、数据风险。
- 推荐答案及理由：C1（fork 后归档原会话、不改标题、回填输入），一次点击即时生效、无重启、无数据损坏面。
- 修改意见：用户答「C1 基础上, 不是归档原会话, 而是直接删除原会话」。
- 处理结论：**采用 C1 + 删除原会话**。宿主无「删除会话」API，等价路径取证并组合为四步：
  1. 归档（把会话移出所有分组视图、并 stopActivity 停掉在跑的回合）：`dsh-workspace/lib/index.js:500-541`；remote 见 `dsh-api-workspace-controller/lib/index.js:289-299`。
  2. 从 workspace 记账里摘掉会话 id：`WorkspaceRecord.detachSession`（`dsh-workspace/lib/index.js:148-151`）。
  3. 删除该会话的持久化目录（`~/.dsh/sessions/<slug>/<sessionId>/`）——这是宿主未提供的文件级操作，但它是纯删除、不会造成日志损坏；若会话仍存活在内存里则**推迟到下次宿主启动时执行**，避免存活会话向已删除路径续写。
  4. 归档集合中对已不存在会话的条目被上游显式容忍：`dsh-workspace/README.zh.md`「恢复只是从归档集合中移除 id，因此会话已不存在的条目仍能取消归档」。
- 首轮（会话只有一轮、没有可切回的上一轮）按用户选择「置灰不可点」处理：`session/fork` 的 `atSeq` 必须 ≥ 0（`session.events[boundary]?.seq !== boundary` 即拒绝，`dsh-api-session-controller/lib/index.js:870-871`）。

### 补充说明

- 依赖结论（Q4）后，工具开关权威位置按推荐落在宿主侧：`nested-skill` 工具的开关必须真正卸载宿主 `skill provider`（`ctx.skills.registerProvider` 返回 disposer，`dsh-skill/lib/index.js`），客户端 localStorage 无法驱动宿主，故取「宿主 JSON 状态 + 宿主 HTTP 路由 + 面板读写」。路由范式取证：`ctx.connection.fetch.register`（`dsh-api-session-controller/lib/index.js:2480-2490`、`dsh-client-ui-deliverables/lib/index.js:49-53`），客户端同源相对 `fetch("api/…")`（`dsh-client-ui-deliverables/lib/client.js:281-283,423`）。
- 撤销的副作用范围：不回滚已写入的文件/已执行命令，也不恢复图片/文件附件；只有文本输入回填。这是宿主能力的边界，写入 README。
