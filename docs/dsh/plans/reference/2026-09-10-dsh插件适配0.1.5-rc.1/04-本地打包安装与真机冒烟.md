# 本地打包安装与真机冒烟

## 交付

本地打包并安装后的 3080 实例在 `0.1.5-rc.1` 上端到端正确：web profile 装的是本轮 `vp pack` 产出的插件 tarball（与工作区解耦，不再是 `file:` 硬链接），全局 `dsh-alive` 是本轮重建的本地版本，工具目录仍含 9 个自有 `session_*` 与 5 个上游搜索工具，普通会话与既有子会话的 `session_read` 都读出 assistant 正文，任意深度 skill 发现仍生效。

## 范围

- 做什么：在主工作区（`main`，已含 03 的合并）`vp pack` 产出 `dsh-nested-skill`、`dsh-session-manager`、`dsh-keep-alive` 三个 tarball 到 `.temp/pack/`（构建产物不进 git）；校验 tarball 内容（`dist/main.mjs`、`cordis.patch.yml`、`README.md` 齐备）并记录 sha256；`dsh plugin --profile web add <tarball>` 装两个插件（替换原 `file:` 声明），`npm install -g <dsh-keep-alive tarball>` 更新全局 `dsh-alive`；核对 profile 实装的 `@kxh4892636/*` 与 tarball 逐文件哈希一致、`@deepseek-ai/dsh-tool-session-query` 为 `0.1.5-rc.1`；`dsh-alive start --port 3080` 重启；真机冒烟：工具目录清点、`session_list`、`session_read`（普通会话，同一批旧会话读出正文）、`session_read`（带 `parentSessionId` 读既有子会话，回归 `ctx.get`/`stateOf` 修复）、嵌套 skill 目录；一次端到端（`session_spawn` → `session_prompt` → `session_wait` → `session_read` → `session_rename` → `session_archive`）；检查 `dsh.log` 无未预期堆栈与 `SESSION_MANAGER_TOOL_FAILED`。
- 不做什么：不改代码（冒烟暴露的新缺陷按新 Issue 处理）、不 bump 版本号、不发布 npm、不建标签、不验证其他发布通道、不重跑 9 工具全量实调矩阵。
- `file:` → tarball 的安装形态变更是本 Issue 的交付内容之一；tarball 留在 `.temp/pack/` 供复装，不提交入库。
- 重启 3080 会中断当时正在执行的会话：这是交付最后一步，执行前停下告知用户，执行后请用户刷新页面。
