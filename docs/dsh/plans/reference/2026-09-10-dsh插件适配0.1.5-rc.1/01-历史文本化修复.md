# 历史文本化修复与 chunk 行去除

## 交付

`session_read` 在 `0.1.5-rc.1` 宿主上读出 assistant 正文与工具事件文本：assistant 条目的 `text` 不再是空串，`[event tool/call]` 占位行变为带工具名与参数摘要的可读行，`tool/result` 带正文或错误码；同时移除已不可达的 chunk 行分支（`chunk-rows` 子路径在 0.1.5 被移除），使「旧宿主与 0.1.5 同时正确」由一个取法保证。

## 范围

- 做什么：改 `packages/dsh-session-manager/src/host.ts` 的正文取法与死代码：`eventTextOf` 按上游 `extractSessionEventText` 语义读块级正文（`user/message` → `data.content`；`assistant/message` → `data.message.content`，保留顶层 `data.content`/`data.texts` 回退；`tool/call` → `[data.name, data.arguments]`；`tool/result` → `data.message.content` + `data.error.name`/`code`；`reasoning` 块不计入）；`entryOf` 为 `tool/call`/`tool/result` 给出 `[tool/call] <name>(<参数摘要>)` 与 `[tool/result] <正文首行或错误码>`，其余事件保留 `[event <type>]`；删除 `ChunkRowEventLike`、`chunkEventOf`、`isChunkRowEvent` 与 `HistoryRecordVariantLike` 的 `{ type: "chunks" }` 成员，`HistoryRecordLike` 收敛为唯一记录形态；`test-support.ts` 的假 `assistant/message` 数据改为真实 wire 形状 `{ turn, step, message: { role, content } }`；`host.test.ts` 补覆盖与「无 chunk 行分支」断言。
- 不做什么：不动 `session-context.ts`/`main.ts`/`tools.ts`（工具 schema、`inject`、`ctx.get` 装配、`stateOf` 调用均不改）；不引入 `@deepseek-ai/dsh-session` 或 `dsh-session-query` 作为依赖；不读 `data.stream`、不呈现 reasoning；不扩展 `HistoryEntry.kind`；不拆分超限的 `host.ts`（本轮只做净减法）。
- 参数摘要为有界短摘要（截断并标注），避免把任意长度的工具参数灌进读取窗口。
