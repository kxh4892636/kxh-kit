## 决策与证据

### 安装

`& '<app>\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add '<repo>\.temp\pack\kxh4892636-dsh-nested-skill-0.1.3.tgz'`（绝对路径）→ `Packages: +4`、`+ @kxh4892636/dsh-nested-skill 0.1.3`、`Done in 1.7s using pnpm v11.28.5`；**没有** `incompatible` 提示，说明 rc.3 兼容性校验通过。pnpm 的 `[WARN] Issues with peer dependencies found` 是预期现象：profile 的 `autoInstallPeers: false`，peer 由宿主运行时提供。

### profile 清单（安装后）

```json
"dependencies": { "@kxh4892636/dsh-nested-skill": "file:C:/Users/kxh/kxh-awesome/projects/kxh-kit/.temp/pack/kxh4892636-dsh-nested-skill-0.1.3.tgz" },
"dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "@deepseek-ai/dsh-experimental-session-search", "@kxh4892636/dsh-nested-skill"] } }
```

`node_modules/@kxh4892636/dsh-nested-skill/package.json` 的 version = `0.1.3`；其 `dist/main.mjs` 的 sha256 与工作区构建产物一致（`323E42BA5B8C376B405294AA7671F5A61DE6A074AF09D88BC7974CE51F747AFE`）；安装进去的 README 也是 rc.3 版本（证明装的是重打过的 tarball）。

### `--dump-config` 变体不可用（替代证据）

`& '<app>\resources\runtime\cli\bin\dsh.cmd' --profile desktop --dump-config` → `error: profile "desktop" is managed exclusively by the Electron application`（exit 1）。desktop 宿主对该 profile 禁止一切本地 boot/dump，因此组合层证据改由「profile 清单 + 运行中宿主目录」给出；这也解释了为何 desktop 场景下没有 `--dump-config` 这一手。

### 运行中宿主（重启前后都未重启）

- 安装后本会话收到的 skill 目录被整体替换：新增 `code-delivery`、`code-spec`、`domain`、`questing`、`to-issues`、`to-skill`（嵌套 skill），同时 `nano-flow`、`nano-flow-cli`、`browser-skill`、`herdr`、`office*`、`diagnose-windows-sandbox-acl` 等顶层 skill 仍在。

- 结论：bundle 列表变化在运行中的 desktop 宿主里**无需重启即生效**（与前序 rc.2 的观察一致）；嵌套发现与顶层共存同时成立。
