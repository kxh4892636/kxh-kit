### 阻断项：0.2.x 插件兼容性校验

从 `app.asar` 抽出的 `@deepseek-ai/dsh-app-boot/lib/index.js`（203,572 B）确认：

- `unmetRequirements(fields, runtimeVersion)`（279–299 行）：有 `engines.dsh` 时**只看它**；否则遍历 `peerDependencies` 中名字等于 `@deepseek-ai/dsh` 或以 `@deepseek-ai/dsh-` 开头的项，逐个 `satisfies(runtimeVersion, range)`。
- `satisfies` 用 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })`（276–278 行）；`getDshRuntimeVersion()` 读的是 app-boot 自身 `package.json` 的版本，即 `0.2.1-rc.3`。
- `evaluatePluginCompatibility`（311–326 行）在 requirements 非空时返回结构体，CLI 打印 `Plugin … is incompatible with dsh 0.2.1-rc.3 …`，并提示 `dsh plugin allow-version` 或插件管理器给「精确版本豁免」。

结论：本包 peer 现为精确 `0.2.1-rc.2`，`includePrerelease` 也只会让同一元组内的 prerelease 参与比较，`rc.2 ≠ rc.3` 仍不满足 → **当前状态下安装必然被拒**。

## 拷问记录

### 第 1 轮

#### Q1 — 声明对齐用哪种机制

- 问题：把 peer 重钉 `0.2.1-rc.3`、改加 `engines.dsh: 0.2.1-rc.3`、还是保留 rc.2 用 `allow-version` 豁免？
- 前置问题：无。
- 下游边界：决定 `package.json` 形状与是否需要 profile 豁免记录。
- 推荐答案及理由：重钉 peer。`unmetRequirements` 优先读 `engines.dsh`，没有才校验 `@deepseek-ai/dsh*` peer；peer 已表达同一语义，二者并存会出现两个真相；豁免会掩盖声明漂移，与 ADR-0003 冲突。
- 修改意见：（auto 模式，agent 依证据推进；用户可在 dev gate 推翻）
- 处理结论：已确认（本轮）。精确钉 `0.2.1-rc.3`，不带 caret（`^` 会放过 rc.4，与 ADR-0003 的「声明等于已验证版本」冲突）。

#### Q2 — 安装形态与 CLI 入口

- 问题：tarball + desktop 自带 CLI、`file:` 目录、还是 GUI 插件管理器？
- 前置问题：Q1（声明对齐后才有可安装的产物）。
- 下游边界：决定 profile 依赖形态、是否需要重建后同步、以及验证能否脚本化。
- 推荐答案及理由：tarball + `resources\runtime\cli\bin\dsh.cmd`。tarball 与工作区解耦（`file:` 是链接投影，重建 dist 需手工同步，前序 Plan 已踩坑）；desktop CLI 与宿主同版，避免 0.1.6-alpha.1 的跨代规则；GUI 路径不可脚本化复核。
- 修改意见：（auto 模式）
- 处理结论：已确认（本轮）。

#### Q3 — 验证层级与重启

- 问题：`--dump-config` + 运行中宿主、另起独立 dsh 进程、还是重启 desktop 应用？
- 前置问题：Q2（安装形态决定验证对象）。
- 下游边界：决定验收证据强度与会话中断风险。
- 推荐答案及理由：`--dump-config` + 运行中宿主的 skill 目录。两者可复核且不动宿主；独立进程要 `DEEPSEEK_API_KEY`（本机 shell 没有，前序 Plan 已失败）；重启会中断本会话，收益只是「同进程内看到」，交给用户择机。
- 修改意见：（auto 模式）
- 处理结论：已确认（本轮）。

#### Q4 — 版本号

- 问题：`0.1.2 → 0.1.3`、保持 `0.1.2` 重打、还是 `0.2.0`？
- 前置问题：无（与安装链路解耦）。
- 下游边界：决定 tarball 文件名与 profile 里记录的版本；影响「换版本重装要先 remove 再 add」的操作顺序。
- 推荐答案及理由：`0.1.3`。契约与行为无变化，仅声明跟随宿主，按最小升级口径；改版本号还能让 profile 里的依赖与旧 tarball 区分开。
- 修改意见：（auto 模式）
- 处理结论：已确认（本轮）。
