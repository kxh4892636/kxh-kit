## 决策与证据

- tarball 路径用绝对路径传给 `dsh plugin add`（相对路径会被 `parseInstallSpec` 拒绝）。
- `pnpm pack` 会触发 `prepublishOnly: vp run build`，等于再验一次构建。
- 原计划的「独立 headless 进程 + `--patch`」在本机不可行：shell 环境缺 `DEEPSEEK_API_KEY`，headless 会在 LLM 路由处失败（`MISSING_CREDENTIAL`），与插件无关。改用运行中宿主取证——它是真实的 `0.2.1-rc.2` 进程，且 bundle 新增在未重启的前提下被加载，证据强度更高。
- 意外收获：bundle 列表变更在 `patchReload: live` 的 profile 上**无需重启**即生效（宿主 PID 237090 自 14:14:18 起未变，安装后 skill 目录立即出现嵌套 skill）。
- 换版本重装的注意事项（2026-10-26 用户要求改最小版本时实测）：直接 `add` 新 tarball 会先按 profile 里的旧依赖解析，旧 `.tgz` 删掉后报 `ENOENT ... 0.2.0.tgz`；必须先 `remove` 再 `add`。`remove` 到 `add` 之间宿主目录会短暂回退（本会话观察到嵌套 skill 一度从 skill 目录消失），`add` 完成后自动恢复，无需人工干预。
- **界面可见性与模型可见性不同步**（用户追问「当前会话看不见、新会话可以」后定位）：Web 客户端按 `sessionId` 缓存 skill 目录（`dsh-client-ui-skill/lib/client.js` 的 `fetchCatalog`，376–405 行），只有 `agent-preset/selected`、`plugin-manager/changed`、`connection/reset` 三个事件会失效它（482–484 行）；`plugin-manager/changed` 只由 GUI 内插件管理器的 `change()` 发出（`dsh-plugin-manager/lib/index.js:2398`），CLI 的 `dsh plugin add` 一个都不触发。宿主侧是 `dsh-hmr` 监听 profile 的 `package.json`/patch 重新组合（`dsh-hmr/lib/index.js:849–870`），所以**模型侧**当步即生效（`dsh-tool-skill` 的 `agent/pre-step` 每步重取 `skills.snapshot`），**界面侧**的 `/` 菜单要刷新页面或新开会话才更新。
