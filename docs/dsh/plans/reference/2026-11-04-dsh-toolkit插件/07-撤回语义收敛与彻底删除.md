## 决策与证据

### 1. 工具默认关闭

`defaultEnabled: false`（三个工具）。开关仍由 `state.json` 持久化；实测面板显示 `nested-skill:false, undo-turn:false, office-skills:false`（单测断言）。

### 2. 样式对齐宿主原生

- 面板：复刻设置页 `section / rows / rowCard / rowHead / rowName / rowTag / rowActions` 度量（`--dsw-alias-settings-card-fill/-stroke`、`--dsw-radius-xl`、0.5px 描边）；开关用 `ui-primitives` 的 `Switch`。
- 撤回触发器：逐条复刻权限选择 `.trigger`（28px、13px/500、`--dsw-radius-sm`、`0 4px 0 8px`、hover `--dsw-alias-interactive-bg-hover`、disabled `--dsw-alias-label-dimmed`、同一焦点环表达式）。
- 弹窗：说明走 `Modal` 的 `description` 位、正文只放原文预览与错误、宽度/滚动/按钮复刻 `RiskConfirmation`；动作只留原生 `Button`（outline/primary，宽度随内容）。
- 侧边栏图标：`stroke-width: 1`（宿主 112 处图标统一值），原先 1.4 明显偏粗。
- 全部样式集中在一张带 `data-plugin-css` 的 token 样式表；单测断言「不含字面色值」。

### 3. 草稿回填时序

`uiWorkspace.openSession()` 是同步换引用（`retain` + `selection.set`），composer 之后才挂载；旧实现立刻按 binding 调 `requestDraftInitialization`，草稿落在随后被替换的 shell 上而丢失。现改为：

1. 撤回成功后把原文登记到 `draft-restore`（模块级、按 sessionId）。
2. 新会话的「撤回」按钮与 composer 同时挂载，用宿主公开的 `inputActions.setDraft(prompt)` 写入并 `persistDraft()`（动作面未就绪时 100ms × 20 重试）。
3. 1.5s 后仍未被消费则走 `conversation.input.requestDraftInitialization` 兜底（`applyPendingDraft`），写完即消费。

### 4. 原会话的彻底删除

**修订（0.3.5）**：先前的实现把「日志删除 + 撤销归档」推迟到下次启动，浏览器端又不主动重读目录，于是撤回后原会话被移到「未分组」、还挂在归档视图里。现在改为当场完成：归档停活后等 150ms 让收尾写入落盘 → 删日志 → 删干净即撤销归档；客户端在 600ms / 1800ms 各 `sessions.refresh()` 一次，让被删的行立刻消失。删成功的 id 仍排一条启动复核，防止存活实例把日志写回来。

顺序：归档（`stopActivity:true`，隐藏 + 停在跑的一轮 + 丢弃排队输入 + 摘 pin）→ `insertSessionBefore(child, 原后继)` 接管记账序 → `detachSession(原)` → 删日志目录 → `unarchiveSession(原)`。

存活会话不能立刻删日志（存活实例会向已删路径续写出 seq gap），因此日志与撤销归档都进队列：`state.json` 新增 `pendingUnarchives`，启动时先删日志再撤销归档。启动还会清扫「归档集合里既无日志、也不存活」的 id，历史版本留下的占位由此自愈。

### 4b. 删除一直没生效的根因（0.3.6）

`deleteSessionLogs` 用**会话 id 的严格规则**（`^[A-Za-z0-9][A-Za-z0-9._-]*$`，首字符必须是字母数字）去校验工作区 slug 目录名。宿主的 slug 形如 `--C-Users-kxh-kxh-awesome-projects-kxh-kit--`，首字符是 `-`，于是每个 slug 都被跳过：删除退化成空操作，却因为「没有异常」而报告成功。接着 `unarchiveSession` 把归档位摘掉，原会话于是从「未分组 + 已归档」变成「未分组 + 未归档」留在列表里 —— 用户看到的三次反馈（没有完全删除 / 移到未分组 / 未归档）都是这一个 bug 的表现。

改法：新增 `isSafeDirName`（允许 `-`/`.` 开头，拒绝 `.`、`..` 与分隔符）专用于 slug；`removeDir` 返回 `removed | absent`，把「删不掉」和「本来不存在」分开；回归测试用 `--C-Users-...--` 形态的 slug 覆盖内存替身与真实临时目录两条路径。

### 4c. 事故记录（2026-11-05，我执行的过度清理）

为了清掉上一版遗留的两条「已撤回但没删掉」的会话，我写了一个一次性脚本，按「被别的会话当作 `parentSession` 引用」判定残留并 `rmSync` 删除。这个判据过宽：任何被 fork 过的会话都会命中，不只撤回的原会话。结果**删掉了 22 个会话日志目录**（清理前 100 个，现存 78 个），其中 13 个 id 现在只以「缺失的父会话」形式存在：

```
session-8de288dc / 9b5eb77c / 521d531e / 576e604d / 4560057f / 2f846a9a / 86498858
session-0bc423a8 / dec88a81 / 8974d302 / f10560c0 / 3dfd8541 / b0b4218f
```

`rmSync` 不进回收站，也没有备份，这些会话历史**不可恢复**。当前会话（`session-ed0cb5fb`）与其余 78 个会话完好。

教训（已作为约束）：清理类操作先列出目标、交用户确认再执行；脚本必须先复制一份候选目录再删，而不是直接 `rmSync`。

### 5. 位置语义的取舍

客户端手动排序把 fork 子会话排在父会话之前（`placeFork` 需要父会话仍在记账里）。既然要「完全删除」，记账锚点一并摘掉，手动排序模式下新会话会落到手动排序之外（按更新时间模式则按时间排序）；置顶位与记录顺序仍然接管。已写入 README。

### 6. 排队输入不再被带进子会话

切点跳过 `turn/start` 之前紧邻的 `agent/inbox/*` 记账事件（排队提示词先写 inbox 才有 `turn/start`）；否则 fork 会继承那条待发消息，表现为「撤回后又发了一次」。真机日志核对：`session-f10560c0` 的切点从 `#21 inbox` 改到 `#20 turn/end`。
