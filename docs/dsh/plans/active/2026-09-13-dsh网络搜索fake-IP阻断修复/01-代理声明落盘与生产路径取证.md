# 代理声明落盘与生产路径取证

## 交付

1. harness home `C:\Users\kxh\.dsh\.env` 含两行代理声明，DSH 启动环境层把 `HTTPS_PROXY` 解析为来自该文件的 `user-env` 层。
2. 生产路径对照证据：无该文件时 `proxyRouteFor` 为直连并复现 `WEB_BLOCKED_URL`；有该文件时路由为 `proxied: true` 且 `HttpFetchProvider.fetch` 对 `https://www.weather.com.cn/` 返回 200 与页面正文。
3. 3080 实例重启使配置生效，端口自检可达（401 未认证首页属正常）。
4. ADR-0005 落盘。

## 交付记录

- **配置**：`C:\Users\kxh\.dsh\.env`（harness home 层，DSH 启动器唯一受理代理名的落盘位置）写入 `HTTP_PROXY=http://127.0.0.1:7890` 与 `HTTPS_PROXY=http://127.0.0.1:7890` 两行；未纳入仓库（用户级运行时配置）。
- **证据（对照实验，生产代码路径）**：`.cache/exec-evidence.txt` 四节——① `.env` 内容；② 删除 `.env` 时 `loadLayeredEnv('dsh')` 返回 `HTTPS_PROXY entry: undefined`、`proxyRouteFor` 为 `{"proxied":false}`、`HttpFetchProvider.fetch` 抛 `WebError WEB_BLOCKED_URL URL hostname "www.weather.com.cn" resolves to a non-public IP address`（原报错逐字复现）；③ 恢复 `.env` 后同一调用返回 `{"value":"http://127.0.0.1:7890","source":"user-env","path":"C:\\Users\\kxh\\.dsh\\.env"}`、`{"proxied":true,"proxy":"http://127.0.0.1:7890"}`、`fetch ok: {"status":200,"chars":100000}`、标题 `天气网`；④ 首轮独立复现脚本显示本机 DNS 答案 `198.18.1.197`。
- **取证脚本**：`.cache/env-layer-probe.mjs`（走 DSH 自身 `dsh-app-boot` + `dsh-http-proxy` + `dsh-web-fetch-http`，可用 `node .cache/env-layer-probe.mjs` 复跑）、`.cache/proxy-probe.mjs`（首轮定位）。两者位于 gitignore 的 `.cache/` 下，不随仓库分发。
- **领域文档**：[ADR-0005](../../../adr/0005-fake-ip解析经代理声明修正.md)（新增，15 行）。
- **生效动作**：`.cache/restart-dsh.ps1` 由脱离父进程的辅助进程在本次会话结束后重启 3080 实例（清掉从 DSH 会话继承的代理/`DSH_*` 标记，再 `dsh.cmd web --host 127.0.0.1 --port 3080 --no-open`），自检 `http://127.0.0.1:3080/` 可达后写入 `.cache/restart-dsh.log`。
- **重启证据**：重启日志 `.cache/restart-dsh.log` 中 `RESTART OK` 行与端口状态码；该文件在重启后生成，由用户在恢复的会话中复核。
