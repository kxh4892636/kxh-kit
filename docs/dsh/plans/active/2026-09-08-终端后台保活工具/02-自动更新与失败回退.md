# 自动更新与失败回退

## 交付

后台受管实例每 13 小时检查 DSH 更新，安装完成自动切换；网络、安装或新版本启动失败时保留或恢复可运行版本。

## 范围

负责 spec 更新与恢复契约：已有版本先启动及立即检查、13 小时调度、精确版本准备、串行切换、回退、失败版本抑制与重试；扩展状态与日志，完成更新文档和最终包验收。

## 直接依赖

- 01：更新必须运行在可使用的受管实例上；消费其精确版本安装、就绪判定、受管进程树停止/启动和生命周期串行化契约。

## 验收

- [ ] 已有版本先服务再检查；使用可控时钟证明默认周期恰为 13 小时，生产默认值未因测试缩短。
- [ ] latest 解析为精确版本，允许发布标签指向 rc；准备新版本期间旧实例仍提供服务。
- [ ] 新版本就绪后 status 显示新版本；网络/安装失败保持旧实例运行并记录错误。
- [ ] 新版本 60 秒未就绪时恢复旧版；失败版本后续周期不重复切换，latest 改变或重复 start 后可重试。
- [ ] 更新与 start/stop 竞争时无双实例、无停止后复活，跨端口准备同版本不暴露半安装目录。
- [ ] 替身验证更新与回退失败路径；真实 DSH 冒烟检查共享 home 下版本切换影响，记录上游用户数据回退限制。
- [ ] 最终类型检查、相关测试、构建、打包通过，使用文档包含更新周期、任务中断和回退边界，提交与证据完整。
