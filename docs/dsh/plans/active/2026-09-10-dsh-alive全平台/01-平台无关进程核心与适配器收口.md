# 平台无关进程核心与适配器收口

## 交付

进程身份、进程树与终止循环成为平台无关的一份实现，三个平台各自只提供「读一次进程表」与「终止一个进程」；Windows 行为与现有测试不变。

## 范围

- 新建 `src/platform/processes.ts`：`sameProcess`、`descendants`、`terminateTree`（多次快照循环、追查两次快照之间的后代、终止前复核身份）。
- 身份判据收敛为 `pid` + `birth`；`parent` 只用于构树，`command` 只用于诊断。
- 平台适配器接口收敛为 `snapshot(port)` 与 `terminate(identity, port)`；`src/platform/windows.ts` 只保留 PowerShell 快照与终止，删除已抽出的树算法；按 `process.platform` 选择适配器的入口就位，未知平台给出可读错误。
- 既有测试迁移到新边界；平台无关测试在任意平台可跑。

不做：Linux/macOS 实现、路径与控制通道改动、包元数据与文档改动。

## 直接依赖

无。Plan 级 /dev-gate ready 后可领取。

## 验收

- [ ] `sameProcess` 只比较 `pid` 与 `birth`：同一进程在 `parent`/`command` 变化后仍判定为同一进程；`birth` 变化（PID 重用）判定为不同进程。
- [ ] `descendants` 保持既有语义：排除被重用 PID 的子树，保留已退出父进程的受管后代。
- [ ] 终止循环保持既有语义：先停父进程、跨两次快照追查后代、终止前用当前快照复核身份、10 轮后仍未退出报错。
- [ ] Windows 快照与终止经适配器仍由 PowerShell 实现；Windows 专属测试在非 win32 平台跳过而不是失败。
- [ ] 平台无关测试在本机（Linux）执行并通过，且不依赖任何平台专属代码。
- [ ] `pnpm --filter dsh-keep-alive check` 与 `test:coverage` 通过，全部生产源码覆盖率仍 >= 80%，未排除任何平台文件。
- [ ] 本 issue 不改动 `paths.ts`、`transport.ts`、`commands.ts` 的对外行为，CLI 在 Linux 上仍按现值报「仅支持 Windows」。

## 审查记录

Standards 轴（首轮结论 fail，1 blocker + 5 minor judgement，产品代码无阻塞）：

- B1 修复：`windows.test.ts` 里「当前平台适配器被复用」断言 `platformFor(process.platform) === currentPlatform()`，而 `platformFor` 每次构造新对象——该用例只在 win32 执行，本机 Linux 门禁无法暴露。已把平台选择与未知平台错误移到新的 `src/platform/current.test.ts`（任意平台可跑），并把缓存移入 `platformFor`，使同一平台名返回同一实例。
- M1 修复：`UNSUPPORTED_PLATFORM_MESSAGE` 改为按已接入的适配器集合生成（当前只有 win32），不再声称支持尚未接入的 Linux/macOS。
- M2 修复：删除只为测试提取而加的 base64 前缀与 `Substring(10)` no-op，测试改为从 `FromBase64String` 参数取值。
- M3 修复：把「terminate 必须在终止前复核 pid + birth」写成 `ProcessSource.terminate` 的接口契约注释；`terminateTree` 第一轮的目标里就包含根进程，且可能已被回收或 PID 被重用，该前提是承重条件。
- M4 修复：`current.ts` 用单一 `platformFor` + 按平台名缓存，去掉模块级可变 `selected` 的双来源。
- M5 修复：抽出 `src/testing/platform.ts` 的共享 `onWindows`，替换三处逐字复制；`current.ts` 的用例从 win32 门控文件中移出。
- M6 修复：`TERMINATE_ATTEMPTS` 收回模块私有；`UNSUPPORTED_PLATFORM_MESSAGE` 保留导出用于断言错误文案。

Spec 轴（首轮结论 fail，2 blocker + 3 low + 4 info；两轮后全部解除）：

- B1「先终止根进程再快照」在 POSIX 上会丢掉整棵子树：根进程退出后子进程被 reparent 到 pid 1，`descendants` 再按父进程关系搜索已找不到它们，`terminateTree` 会在子树仍存活时返回成功——`stop`/重启会留下 DSH 子树与占用端口。Windows 不受影响（`ParentProcessId` 在创建时冻结），因此本机既有用例无法暴露。修复分三处：① 去掉循环前的 `terminate([root])`，第一轮必须先快照，在同一轮里按父进程优先终止根进程与当时可见的后代；② 搜索锚点集合随发现扩张，已发现的进程即使之后被 reparent，仍作为锚点继续搜索它后来派生的后代；③ `descendants` 改为返回快照中的当前身份，而不是入参里的旧身份，否则状态变化（如变成僵尸）对调用方不可见。
- B2「用 `command === null` 判定进程已退出」会在活进程上静默提前返回成功：Windows 上活进程也可能读不到 `CommandLine`，该判定会把它们永久排除出终止目标，并在无新目标时直接返回成功。修复：删除该启发式与「全部已退出即返回」的捷径，恢复基线的有界语义——每轮对仍存活的受管进程重发终止信号，10 轮后仍未退出则以明确失败收尾。僵尸的豁免改由平台适配器负责（Linux 侧按 `/proc` 状态直接跳过）。
- L1（已随 B2 修复）：重发语义回到基线，spec 中「终止循环语义不变」重新成立。
- L2/L3（已修复）：spec 的适配器签名与「用当前快照复核身份」措辞改为与实现一致——`terminate(identities)` 批量下发、身份复核由适配器用平台当前状态完成；`command` 不作为判据、也不作为存活性判据，`descendants` 返回快照中的当前身份，均写入 spec。
- I1（已修复）：POSIX「根进程在首次快照前已被回收则后代不可归属」的有界边界写入 spec 与本记录，并由用例锁定。
- 反例辨析：审查建议的「根进程已被回收、子进程仍以 root.pid 为 parent」在真实系统不可达——能通过 `sameProcess` 与根进程比较的前提是根进程在快照里，而它一旦退出，POSIX 已把子进程 reparent 到 pid 1。可实现的保证是「首次快照必须发生在根进程仍可见时」，该保证已由第一轮快照先于终止信号落实。

回归用例（对应上述两条阻塞项与低优先项）：`第一轮终止根进程与当时可见的后代，之后追查新出现的后代`（锁定首轮快照先于终止信号与逐轮重发）、`中间层被 reparent 后，其更深后代仍能被追查`（锁定搜索锚点扩张）、`根进程已被回收且后代已被 reparent 时提前返回，不误杀外部进程`（锁定已知边界）、`树已退出即返回，持续存活则有限轮后明确失败`（锁定「读不到命令行的活进程仍被终止且不静默成功」与 10 轮失败语义）。

交付过程中自查发现并修复的另一个实质缺陷：`terminateTree` 曾把根进程放进 `tracked` 后就不再发终止信号（第一轮目标被永久排除），`haltInstance` 必然以「Managed process tree did not exit」失败、受管 DSH 进程不会被停止。该问题在首轮修复中改为「先终止根进程」，随后被 Spec 轴 B1 判定为引入 POSIX 回归，最终以本轮的「首轮快照 + 同轮终止根与可见后代」形态收敛。

两轴修复后复验：`vp test --run` 11 个测试文件全通过，52 项通过 / 5 项按平台跳过；覆盖率 statements 87.47%、branches 83.21%、functions 86.06%、lines 88.39%，`src/platform/{processes,current}.ts` 四项均 100%；`vp check` 与 `vp pack` 通过。
