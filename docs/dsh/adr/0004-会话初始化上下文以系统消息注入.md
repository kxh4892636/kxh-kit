# 会话初始化上下文以系统消息注入

会话创建时注入的上下文（会话上下文注入）以**系统消息**形态加入新会话，而不是用户消息：不触发模型调用，首次模型调用等待第一条用户消息。机制为 `create` 后经 `session/created`（或 `ctx.agents.get`）取得 Agent，在 `agent.ctx.systemPrompt.section({ name, order, text })` 注册会话作用域 prompt 段，从首次请求起生效（`agent-loop/scope-lifecycle.spec.ts` 契约）。

## Considered Options

- **系统消息注入（选定）**：上下文进入会话作用域系统 prompt；创建零调用成本；上下文恒在用户消息之前。
- **用户消息 seed**：创建后立即 `prompt` 投递种子用户消息；直接触发一次真实模型调用（消耗 token、产生首轮回复），上下文与用户消息同面混存。

## Consequences

- 创建新会话不产生模型调用；首个模型请求由第一条用户消息驱动。
- 上下文经会话作用域 prompt 段生效，段内容稳定时保持 KV 缓存前缀稳定。
- 与 `session_prompt`（用户消息，触发调用）语义严格区分；错误地把上下文作为用户消息注入会造成非预期调用。
