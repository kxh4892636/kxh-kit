# 交付作用域化记忆存储与维护

## 交付

用户可以通过 `nnm` 在一个本地 SQLite 数据库中新增、查看、列举、修改和永久删除 project/global 记忆；重复写入幂等，项目移动不改变默认记忆空间。

## 范围

- 建立 versioned SQLite schema、migration、FTS 同步字段与事务 repository，但本 issue 不交付 search 排序。
- 实现 OS 数据目录、`NANO_MEM_HOME`、Git root basename/cwd basename 与 `--project` 解析。
- 实现 `add/get/list/update/delete --force`、scope 过滤、公开 DTO 与精确规范化哈希去重。
- 初始化生命周期字段；其计算和状态迁移由 04 消费，不在本 issue 展开。

## 直接依赖

- 01：需要可执行 CLI、JSON/error 契约和 composition seams；消费其包骨架与 public command boundary。

## 验收

- [x] 通过真实 CLI + 临时 SQLite 验证 project 默认写入、global 显式写入、默认 list 可观察两者且不会越过显式 project 边界。
- [x] Git 仓库内使用根目录名、非 Git 目录使用 cwd 名；不同路径同名根共享，`--project` 能隔离。
- [x] 同 scope 的 NFKC/whitespace 规范化精确重复 add 返回同一 ID，不同大小写或不同 scope 不被静默合并。
- [x] content 更新保留 ID/created-at 并重置生命周期字段，source-only 更新保留生命周期；未带 `--force` 的 delete 不产生物理删除。
- [x] schema migration、FTS trigger 与写操作处于可回滚事务，外部边界失败不会留下半写状态。

- 交付物：SQLite v1 schema/migration、事务 repository、OS 数据目录与 project resolver，以及 `add/get/list/update/delete` CLI。

- repository 测试证明 NFKC/whitespace 幂等、大小写与 scope 区分、content 重置/source 保持、`delete --force`、FTS trigger 同步和失败回滚。
