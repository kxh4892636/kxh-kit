# 交付使用强化与软遗忘

## 交付

实际采用的记忆会增强稳定性并提高相关检索中的优先级；长期不用或显式忘记的记忆从 search 隐藏但能被检查和恢复，永久删除仍需明确确认。

## 范围

- 实现 versioned FSRS-6 RetentionPolicy、连续时间、Good use、R=0.5 自然遗忘阈值与推导 forget-at。
- 实现有界 RankPolicy，将可检索性、use-count 与 retrieval-count 按 40%/40%/20% 分配为 FTS 候选内最多 38.2% 的黄金比例乘法 boost。
- 实现 `use/forget/restore`，以及 get/list 的有效状态与遗忘原因；接通 update 的生命周期重置。
- 用可注入 clock 验证时间推进和频率性质，并补充 FSRS 参数/公式的第三方声明。

## 直接依赖

- 03：需要 FTS 候选、lexical score 和 retrieval-count；消费其候选/计数契约并在候选内接入生命周期重排。

## 验收

- [x] 使用同一已知时间线时，多次实际 use 的记忆比少次 use 的同类记忆具有不低的稳定性、更晚的自然遗忘时间和更高的相关检索优先级。
- [x] search 返回只影响 retrieval-count/有界热度，不改变 stability、last-used 或自然遗忘时间；无论热度多高都不能越过 FTS 门槛。
- [x] 未使用的新记忆按 policy v1 在约 208 天越过 R=0.5；阈值前后边界使用连续毫秒时间可重复验证。
- [x] 自然与显式软遗忘都从 search 隐藏，get/list 展示状态与原因且不加热；显式 forget 不会因高稳定性自动复活。
- [x] 软遗忘记忆 use 失败并提示先 restore；restore 清空生命周期/热度统计、保留身份与内容且不产生 use。

## 交付记录

- 交付物：versioned FSRS-6 RetentionPolicy、归一化 BM25 × 黄金比例 RankPolicy，以及 `use/forget/restore` CLI 和有效状态 DTO。
- 验证证据：包级 `check`、`build`、74 个测试全部通过；coverage 为 statements 98.09%、branches 94.38%、functions 98.50%、lines 98.55%。
- policy 测试锁定本地 ts-fsrs 5.4.1 的 21 个默认参数、Good 连续时间更新、首个 `R < 0.5` 整数毫秒边界和约 208 天初始寿命。
- ranking 测试证明 BM25 lexical 门槛/先后保持，实际 use 可在同词法候选内提升稳定性、遗忘时间与优先级，三类 boost 在 100 次封顶且总上限 38.2%。
- repository/CLI 测试证明 search 只增加返回项 retrieval-count，自然/显式软遗忘不进入 search，get/list 展示原因，restore 保留身份并重置全部生命周期与热度。
- 真实 built CLI smoke 使用临时 `NANO_MEM_HOME` 验证 use、显式 forget 隐藏、restore 和恢复后重新可检索。
