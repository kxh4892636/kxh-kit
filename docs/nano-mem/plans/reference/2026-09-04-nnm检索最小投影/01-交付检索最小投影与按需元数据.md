# 交付检索最小投影与按需元数据

## 交付

agent 默认搜索时只接收采用记忆所需的最小投影，并能在需要追溯来源或诊断时间时逐项请求元数据；现有维护读取、检索排序和生命周期行为保持不变。

## 范围

- 在 CLI command boundary 建立 search 专用投影与可重复 `--include source|createdAt|updatedAt`，不改变 repository 和记忆 schema。
- 实现默认 project/global shape、固定适用字段顺序、重复去重、缺失 source 的 null 语义，以及 `INVALID_INCLUDE` 用法错误。
- 保持成功/失败 envelope、maintenance DTO、检索事件、排序和生命周期契约。
- 更新包 README、command help、两份同步维护的 `nano-mem` skill，并刷新受管 skill manifest。
- 不增加任意字段投影、metadata/filter DSL、逗号列表、大小写别名或新的 selector 协议。

## 直接依赖

- 无。现有 `nnm search`、稳定 JSON envelope 与 nano-mem skill 已提供完整改造 seam。

## 验收

- [x] 真实 CLI 默认搜索的 project 结果精确包含 `id/content/scope/project`，global 结果精确包含 `id/content/scope`；两者保持 `{data:{memories:[...]}}` envelope，且不出现 `status/forgottenReason/source/createdAt/updatedAt`。
- [x] `--include source`、`--include createdAt`、`--include updatedAt` 可单独或重复组合；重复值幂等，无 source 时返回 null，可选字段按固定适用顺序输出且不改变命中集合。
- [x] 未知、错误大小写和逗号形式的 include 返回 `INVALID_INCLUDE`、退出码 2 与既有错误 envelope；不产生搜索检索事件或部分输出。
- [x] `get/list` 与其他命令继续返回现有完整 DTO；既有 FTS、scope、limit、排序、检索计数、软遗忘测试保持通过。
- [x] 两份 skill 内容一致：普通检索使用默认投影，来源敏感任务传 `--include source`，并按返回的 scope/project 准确重放 `use` selector；README、help 和 manifest 与其一致。
- [x] `pnpm --filter @kxh4892636/nano-mem check`、`test`、`build` 全部通过，测试不接触真实 `NANO_MEM_HOME`。
