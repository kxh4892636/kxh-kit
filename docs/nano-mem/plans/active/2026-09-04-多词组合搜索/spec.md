# 多词组合搜索

## 问题

`nnm search` 当前把查询产生的全部 token 用 `AND` 连接。只要记忆缺少任一输入词，整个查询就返回空结果；例如包含 `Pi` 与 `subagent` 的记忆无法被 `Pi subagent domain glossary ADR` 找到。

需要让多词查询按完整命中词组数从高到低逐层返回相关活跃记忆，同时保持组内全文匹配精度、现有作用域和生命周期边界、稳定 JSON 输出及检索事件原子性。

## 方案

将查询解析为去重的词组集合。每个词组继续使用现有 tokenizer，并以派生 token 全部命中作为该词组的全文相关性门槛；记忆完整命中的词组数形成覆盖层级。

`search` 从最高覆盖层向下回填结果：高层不足 `limit` 时继续下一层；某层填满剩余名额时，完整收集并排序该边界层，截取后停止处理更低层。这样无需枚举所有非空词组组合，也不会让低覆盖结果挤掉高覆盖结果。

## 已排除的备选

- 所有 tokenizer token 独立组合：CJK 1–3 gram 会退化为单字召回，破坏完整词组的全文相关性门槛。
- 所有至少命中一个词组的记忆统一进入最终候选：返回结果可与逐层回填等价，但仍会探索 `limit` 边界以下的低覆盖层，不符合已确认的停止边界。
- 仅在更高层完全为空时回退：高层有少量结果时无法用低层补足 `limit`。
- 纯 BM25 排序：不能保证完整命中更多查询词组的记忆优先。
- 枚举 `2^N-1` 个 AND 组合：查询规模指数增长，且不是表达覆盖层级所必需。
- 保留 BM25 前 50 个候选预截断：可能在层内生命周期重排前丢弃最终应返回的记忆。
- 扩张输出以返回 matched terms 或 score：当前用户结果不需要公开内部检索信号，会无谓扩大 CLI 契约。

## 实施决策

### 查询分组

- 以连续 Unicode 空白划分用户输入词组；标点仍作为普通文本交给现有 tokenizer，不解释为分组或 FTS 运算符。
- 每个词组独立执行现有 NFKC、CJK 1–3 gram、英文/数字与代码标识符 tokenizer。
- 丢弃没有有效 token 的词组；按派生 token 集去重，重复输入不能增加覆盖数。全部词组无效时返回空数组且不产生检索事件。
- 一个词组只有在其全部派生 token 都命中同一条记忆时才算完整命中；多个词组之间形成可回填的覆盖层级，而不是放宽组内门槛。

### 候选与排序

- FTS 仍是唯一全文候选入口。作用域、显式遗忘和自然遗忘过滤保持不变，生命周期信号不能让未完整命中任何词组的记忆进入结果。
- 以所有有效词组的派生 token 全局去重后构造安全转义的 flat `OR` FTS 查询，取得 BM25 词法相关性；用户文本永不直接成为 MATCH 语法。
- flat `OR` 中只命中部分 token、但未完整命中任何词组的记录不属于任何覆盖层，不能参与归一化、`limit` 或检索计数。
- 一级顺序为完整命中词组数降序。从最高层向下回填；高于边界层的结果全部入选，边界层完整排序后只取剩余名额，并停止处理更低层。
- 每个覆盖层以该层全部合格记录独立执行现有 BM25 relevance 归一化与 lifecycle boost 公式；层内依次按组合分数、BM25、`id ASC` 排序。
- 不枚举词组组合，不新增公开词数上限，也不锁定单 SQL 或多 SQL；实现可以采用任何结果等价、相对于词组/token 数非指数的策略。数据库内部扫描不视为对低层结果的获取或排名。
- 移除旧的 BM25 前 50 个候选预截断。单组查询保持 tokenizer、组内 `AND` 门槛、排序公式、final `limit` 与输出契约，但极端数据下允许因修复预截断而改变结果。

### 输出与副作用

- `nnm search` 的参数、`--limit` 范围及现有最小检索投影保持不变：默认返回 `id/content/scope/project?`，`--include source|createdAt|updatedAt` 继续按需追加元数据；不公开覆盖数或评分。
- 跨词组命中的同一记忆只返回一次。仅最终返回的去重记忆各产生一次检索事件并增加一次 `retrieval_count`；未返回层、边界层被截掉的记录、`get` 与 `list` 均不增加。
- 候选读取、最终选择与检索计数更新保持现有事务原子性；失败不能留下部分计数。
