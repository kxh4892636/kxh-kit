# 采用可恢复软遗忘与惰性评估

Nano Mem 不运行后台进程；搜索和维护读取依据固定版本的 FSRS 参数与连续经过时间惰性计算当前可检索性。低于策略阈值会触发自然软遗忘；显式 `forget` 产生持续覆盖的软遗忘原因，不能因当前稳定性较高而自动复活。两者都从默认 `search` 隐藏，但可被 `get/list` 观察。

软遗忘记忆不能直接 `use`，必须先 `restore`。恢复保留 ID、content、source、scope 与创建时间，重置记忆稳定性、最后使用时间、使用次数、检索次数、检索热度和遗忘原因，按新记忆的初始生命周期转为活跃且不产生使用事件。只有 `delete --force` 执行不可恢复的物理删除。

## Considered Options

- 衰减后自动物理删除：节省空间，但会把参数或时间误判变成不可恢复的数据损失。
- 使用后台调度器维护状态：状态更及时，但扩大部署、并发和故障边界。
- `use` 隐式恢复：命令更少，但混合两个生命周期迁移并伪造恢复时的使用证据。

## Consequences

- 数据会持续占用本地空间，除非用户明确永久删除。
- `get/list` 必须计算并展示当前有效状态与软遗忘原因，但不得产生检索事件。
