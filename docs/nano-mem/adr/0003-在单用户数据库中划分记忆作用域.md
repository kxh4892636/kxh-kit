# 在单用户数据库中划分记忆作用域

Nano Mem 使用一个用户级 SQLite 数据库集中保存记忆，并以 `project` 与 `global` 记忆作用域形成逻辑空间。新增默认写入当前 project；检索默认组合当前 project 与 global，不读取其他 project。

项目标识默认取 Git 根目录的目录名；没有 Git 根目录时取当前目录名，并允许 `--project` 显式覆盖。不同路径下的同名根目录有意共享 project 记忆；需要隔离时使用不同的显式项目标识。数据库位置遵循操作系统用户数据目录，并允许 `NANO_MEM_HOME` 覆盖。

## Considered Options

- 每个 workspace 独立数据库：隔离直接，但难以共享 global 记忆并产生多库维护成本。
- 使用规范化绝对路径：避免同名碰撞，但项目移动后会形成新的记忆空间。
- 引入 user/agent/session/run 多维 scope：表达力更强，但超出本地单用户 v1 的实际边界。

## Consequences

- 项目移动不改变默认 project 记忆空间。
- 同名项目会默认共享记忆，这是刻意接受的碰撞；`--project` 是显式隔离机制。
