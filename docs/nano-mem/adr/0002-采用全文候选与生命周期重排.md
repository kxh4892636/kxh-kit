# 采用全文候选与生命周期重排

Nano Mem 使用 SQLite FTS 形成全文相关候选，不使用 embedding、向量模型或向量数据库。只有通过 FTS 门槛的记忆才能进入结果；在候选内部，再以 FSRS 可检索性和使用次数重排。

`search` 返回记忆只产生检索事件并增加统计次数，不影响排序；实际采用后的显式 `use` 才产生使用事件并增强记忆稳定性。生命周期信号不得使不具备全文相关性的记忆进入候选集。

2026-09-05 调整：取消检索次数的排序贡献，避免“排名高 → 更常返回 → 排名更高”的反馈。检索次数保留为统计数据。同命中组数层内采用相关性与生命周期的加权加法，相关性使用 `(-BM25) / 同层最大(-BM25)`，避免 min-max 将相近候选强制拉成 1 和 0；生命周期可以独立补偿一定的相关性差距。

总分为 `0.618 × 相关性 + 0.382 × (0.618 × 可检索性 + 0.382 × 使用次数得分)`。使用次数得分采用对数增长，100 次封顶。同层最大 BM25 相关性变化可能改变两类信号的相对影响，这是除法归一化与加法组合接受的取舍。

## Considered Options

- 向量检索：语义召回更强，但引入模型、索引服务、成本和不可解释依赖。
- search 返回即增强稳定性：会产生“排名高 → 更常返回 → 更难遗忘”的自强化回路。
- 只按 FTS 排名：无法表达高频实际使用更难遗忘、检索更优先的目标。

## Consequences

- 系统保持单机、离线和可解释，但同义改写的召回能力取决于查询词与 skill 的检索策略。
- 中文自然短语、英文、路径和代码标识符必须由 FTS 验收；具体 tokenizer、阈值和权重留给 spec。
