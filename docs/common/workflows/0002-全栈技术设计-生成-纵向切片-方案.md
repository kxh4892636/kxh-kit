# 全栈技术设计——按纵向切片生成方案

本工作流规格化从需求与现场事实生成全栈技术设计文档的循环。文档只说明设计、职责边界和关键实现概要，不展开代码级实现、实施步骤、任务拆解或详细测试用例。

## 运行契约

### 触发条件

用户要求生成技术设计、技术方案或同类设计文档时运行。

### 输入

- 当前对话中已经确认的目标、范围与约束；
- 工作区内相关的 PRD、设计稿、Issue、领域文档、代码与既有契约；
- 用户明确给出的输出路径（如有）。

### 前置条件

1. 从 `CONTEXT-MAP.md` 定位所触及业务域，读取对应 `CONTEXT.md`、相关 ADR 和 Workflow。
2. 探索相关代码仓库，查明现状、可复用模块、跨层边界、数据来源与外部依赖。
3. 区分现场事实、已确认决策与尚未验证的假设，不把假设写成事实。

在相关领域语言、既有决策、代码现状和需求来源均已覆盖，且可从现场查明的事实缺口已经清空时开始设计。

### 委派边界

默认根据现有信息直接完成设计，不为可用假设、占位符或 TODO 表达的缺口采访用户。

只有缺失信息会使核心方案无法成立或导致不可逆的关键选择时暂停。向用户提交可直接决策的简报，包含现场事实、证据链接、待决问题、可选方案及推荐答案；用户确认后继续。

### 结束边界

每项需求责任都落入恰好一个纵向切片；每个切片形成从用户结果到前端、服务端和数据层的设计闭环；直接依赖、假设、风险与待办均已显式记录；全文没有用实现细节替代设计决策。

### 输出

默认在对话中交付技术设计文档。只有用户明确给出保存路径时才写入工作区文件。

## 设计方法

### 纵向切片

以可独立验收的用户结果或业务能力划分切片。每个切片只贯穿实现该结果所需的界面、交互、API 或事件、服务端、数据与可观测性边界，不按前端、服务端或数据层建立横向切片。

多个切片共同需要的组件、接口或基础能力归入首个实际消费它的切片，后续切片引用其产物或契约。只有必须先行且可独立验收的平台能力才单独成为前置切片。依赖只记录直接依赖，并说明消费的产物或契约。

### 设计深度

说明用户如何完成目标、系统各层如何协作、数据如何流动、契约如何约束双方，以及关键边界为何如此划分。关键实现概要只描述影响方案成立的机制、模块关系与技术选择。

验收信号只描述用户或系统可观察的成功结果和关键失败表现。具体代码、函数级设计、逐步实施过程、任务拆解、测试命令与详细测试用例留给后续实现流程。

## 文档结构

```markdown
# {{技术设计名称}}

## 概览

- 目标：{{用户或业务结果}}
- 范围：{{本次设计覆盖的内容}}
- 非范围：{{明确不处理的内容}}
- 代码仓库位置：{{相关仓库与相对路径}}
- 依据：{{PRD、设计稿、Issue、ADR、Workflow 等链接}}

## 切片索引

| 切片               | 用户结果             | 直接依赖                   | 验收信号       |
| ------------------ | -------------------- | -------------------------- | -------------- |
| {{稳定 ID 与名称}} | {{可独立得到的结果}} | {{依赖的切片及所消费契约}} | {{可观察结果}} |

## {{切片 ID：切片名称}}

### 用户结果与验收信号

### 范围、非范围与直接依赖

### 现状与约束

### 设计稿与交互逻辑

### 端到端数据流

### API、事件及数据契约

### 前端、服务端与数据层职责

### 关键实现概要

### 埋点、监控与异常设计

### 假设、风险与 TODO
```

除“用户结果与验收信号”及表达完整跨层设计所需的章节外，其余章节按适用性保留。设计稿缺失时保留链接占位符并记录为 TODO；外部图片、图标、字体等静态资源只在相关切片中列出。

## 失败恢复

- 现场事实互相冲突：标明冲突来源及其影响，以更新且权威的来源继续；无法判定时进入委派边界。
- 切片无法独立验收：重新按用户结果合并或调整边界，不以技术层补齐切片。
- 出现循环依赖：重新分配责任或提取可独立验收的前置切片，直到依赖图无环。
- 关键契约未知：先从代码、IDL、Schema 或既有文档取证；仍未知时使用明确占位符，只有影响核心方案成立时进入委派边界。
- 用户指定的输出路径不可用：保留完整文档并在对话中交付，同时报告路径问题与恢复方式。

## 完成证据

- 列出已读取的需求、领域文档、代码位置和既有契约；
- 切片索引覆盖全部范围，责任无遗漏或重复，直接依赖无环；
- 每个切片都包含用户结果、完整跨层设计和可观察的验收信号；
- 假设、风险、TODO 与占位符可逐项定位；
- 读回最终输出，确认文档保持在设计层级，并报告交付位置。

## 推荐技能

- `/codebase-design`：当模块边界、接口深度或 seam 是方案核心时，用其词汇打磨设计。
- `/domain-modeling`：当设计暴露出未定义、含混或 overloaded 的领域术语时，先统一 domain language。
- `/to-issues`：当工作大到一次上下文无法安全完成时，将整体工作维护为业务域 plans 目录下的 spec 和可独立交付的 tracer-bullet issue；本工作流仍负责每个技术设计内部的纵向设计结构。
- `/grill-with-docs`：技术设计获批并准备进入实现前，用它确认实现决策、TDD 选择和验收门禁。
