## 决策与证据

### 目标版本

`npm view vite-plus dist-tags` → `{"latest":"1.0.0", ...}`；`@voidzero-dev/vite-plus-core` 同步 `latest = 1.0.0`。1.0.0 内置 Vitest `5.0.1`、tsdown 0.23（来源：vitest-v5 与 migrate-rules 文档）。工作区现为 `vite-plus: 0.2.6`。

### 迁移路径

官方 [migrate](https://viteplus.dev/guide/migrate) 的「Upgrade from Vite+ 0.3 to 1.0」两条路径：

- 有全局 CLI：`vp upgrade` 到 1.0，再 `vp migrate --no-interactive`。
- 无全局 CLI：`pnpm dlx --package=vite-plus@1.0.0 vp migrate --no-interactive`，随后用项目本地 CLI 验证。

文档禁止用旧 local CLI 跑迁移；已存在 Vite+ 项目走默认 upgrade，不加 `--full`。工作区已是 Vite+ 项目（root `vite.config.ts` 用 `vite-plus` `defineConfig`），故不加 `--full`。

### 受影响面（代码基线盘点）

**版本声明**：`pnpm-workspace.yaml` 的 catalog 有 `vite: npm:@voidzero-dev/vite-plus-core@0.2.6`、`vite-plus: 0.2.6`、`vitest: ^4.1.10`、`@vitest/browser-playwright: ^4.1.10`、`@vitest/coverage-v8: ^4.1.10`、`vitest-browser-react: ^2.2.0`；`overrides` 有 `vite: "catalog:"`、`vitest: "catalog:"`；`peerDependencyRules` allowAny vite/vitest。所有包用 `catalog:` 引用，例外：`apps/diff-viewer` 的 `@vitejs/plugin-react: ^6.0.5`（非 catalog）、`packages/dsh-opencode-session` 的裸 `vitest: ^4.1.10`。`vite`/`vite-plus`/`vitest` 均为 devDependencies，无生产依赖。

**定义入口**：`defineConfig` from `vite-plus` 8 处；from `vitest/config` 4 处（`apps/diff-viewer`、`apps/etf-dashboard`、`apps/etf-service`、`packages/nano-flow` 的 `vitest.config.ts`）；`apps/diff-viewer/vite.config.ts` 用 `vite`。

**测试导入**：194 个测试文件中 179 个导入 `vitest`/`vitest/config`/`vitest/browser`（diff-viewer 77、nano-flow 49、etf-dashboard 8、dsh-keep-alive 13、herdr-limit-resume 8、dsh-session-manager 7、pi-deepseek-web 5、other）；1 个（`packages/docusaurus-plugin-link/tests/path.test.ts`）已用 `vite-plus/test`；4 个非测试支撑文件导入 vitest（`apps/diff-viewer/vitest.setup.ts`、`packages/nano-flow` 两个 testing 辅助、`packages/dsh-keep-alive/src/testing/platform.ts`）；4 个 etf-dashboard 测试用 `vitest/browser`（`page`/`userEvent`）；无 `declare module 'vitest'` 增强，仅有 `apps/diff-viewer/src/types/vitest.d.ts` 的 `import "vitest"`（上游身份引用）。14 个 Playwright e2e 不涉 vitest。

**pack 块**：6 处 —— `docusaurus-plugin-link`（`dts:true`、`exports:true`、`deps.neverBundle`）、`dsh-keep-alive`、`dsh-nested-skill`、`dsh-opencode-session`、`dsh-session-manager`、`herdr-limit-resume`（后 5 者 `entry:["src/main.ts"]`、`exports:false`）。`packages/nano-flow` 无 pack 块，脚本为 `vp pack src/main.ts`（位置参数）。无 `tsdown.config.*`、无独立 eslint/prettier 配置。

**hooks / 脚本**：`.vite-hooks/pre-commit` = `vp staged`；root `vite.config.ts` 有 `staged` 块；root `prepare` = `vp config`；`.vite-hooks/_` 由 `vp config` 生成（`git config core.hooksPath = .vite-hooks/_`）。包脚本大量使用 `vp pack`/`vp test`/`vp check`。无 `.github` CI。

### 风险点与未验证项

1. `apps/diff-viewer/vitest.config.ts` 打补丁到 Vite 内部：正则 `/\/vite\/dist\/client\/env\.mjs$/` 与 `\0virtual:@vite/env` id。Vite 8.1 / Rolldown 是否仍成立未验证。
2. `apps/etf-dashboard/vitest.config.ts` 用 `projects` + `@vitest/browser-playwright` `provider: playwright({launchOptions:{channel:"chrome"}})`；Vitest 5 的 browser/locator 语义变化未验证。
3. `packages/nano-flow/vitest.config.ts` 的 `excludeAfterRemap: true` 与 `type Plugin` 导入较脆弱。
4. `apps/diff-viewer` 的 client 测试用 happy-dom + `globals: true` + `pool: "forks"`，v5 对 globals/pool 行为可能有变。
5. `vitest-browser-react`（etf-dashboard 浏览器测试用，5 个导入方）的 `^2.2.0` 与 Vitest 5 兼容性未验证；迁移按第三方集成保留其版本。
6. `apps/diff-viewer/src/types/vitest.d.ts` 曾为 Vitest 4.1 的 `jest.Matchers` TS2320 做过裁剪，v5 类型面可能再变。

#### Q1 — 目标版本与迁移命令

- 问题：升级目标是 `vite-plus@1.0.0`（latest）还是其它具体版本？用哪条命令执行迁移？

- 推荐答案及理由：目标 `1.0.0`；用 `pnpm dlx --package=vite-plus@1.0.0 vp migrate --no-interactive`，不改全局环境即可用目标 CLI 的迁移规则，符合官方「Without the Global CLI」路径。
