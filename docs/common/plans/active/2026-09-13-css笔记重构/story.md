## 原始想法

> /learning apps/wiki/docs/00-中转/33-css 重构笔记, 允许笔记内容和目录结构的重构, 保存到 .tmp 中

## 角色

- **自学者**：为自己的 CSS 学习维护 `33-css` 一组提纲式笔记，需要一套能直接用来讲解与主动复习的重构笔记，并保留与源材料的可核对关系。

## 故事

### 从提纲到可独立学习的笔记

源材料是 22 篇扁平提纲：`###/####` 碎片式条目、结论式短语、部分文件只有标题。重构把每个可独立学习的概念写成一篇自足笔记，按知识依赖分组存放。

#### US-001 得到一套按概念重组的 CSS 笔记

作为自学者，我想要源材料被重组成一套一篇一概念、按知识依赖分组的笔记，以便按顺序学习，也能单独查一篇解决具体问题。

- [ ] 源目录 `apps/wiki/docs/00-中转/33-css` 的 22 个 Markdown 文件（含 `README.md`）逐个登记知识点，语义重复合并、来源位置保留，产出的覆盖账本 `coverage.json` 让每条知识点都能追到源文件与行段。
- [ ] 笔记写入 `.tmp/33-css/`，按「语法与接入 / 选择器与层叠 / 值与单位 / 排版 / 盒模型与视觉 / 布局 / 表格与列表 / 变换 / 媒体查询」分组；目录层级不超过三级，每个末级目录不超过 13 个 Markdown 文件，另有目录级 `README.md` 索引。
- [ ] 每篇笔记以问题形式的 H2 组织，每个 H2 仅凭自身正文即可完整回答该问题；一篇只承载一个可独立学习的概念，普通文本每 bullet 一个知识点并以 `term: explanation;` 收尾，能用代码块、表格或图示表达处优先于文字。
- [ ] 单篇不超过 144 行，无法再拆的连贯主题若超出则在账本中说明理由；新笔记使用工作区内唯一的 UUID，源目录的 UUID 不修改也不复用。
- [ ] 源笔记中的事实性、语法性与层级缺陷（如缺单位的 `calc()`、错挂的「重绘」小节、无效的 `aspect-ratio` 写法）在笔记中修正，并在账本 `corrections` 中逐条记录源位置、修正内容与理由。
- [ ] 源目录 `33-css` 保持原样；三篇空源文件（`170-上下文.md`、`190-过渡.md`、`200-动画.md`）登记为覆盖缺口并在 `README.md` 说明，不臆造正文。
- [ ] 被新笔记引用的图片迁移到 `.tmp/33-css/images/`，其余图像语义改写为正文或表格。

#### US-002 重构结果可复核

作为自学者，我想要重构结果能被脚本核对，以便相信「没有丢内容」不是口头承诺。

- [ ] 结构自检 `node check-notes.mjs .tmp/33-css` 输出 `problems=0`（frontmatter、唯一 H1、H2 问句、bullet 尾分号、代码围栏配对、图片与相对链接可解析）。
- [ ] 覆盖校验确认源 22 个文件的正文行全部落在映射区间内或被显式登记为缺口，且 `coverage.json` 中登记的每个目标文件与 H2 都真实存在。
- [ ] UUID 校验确认 `.tmp/33-css` 内无重复，且不与工作区既有 Markdown 的 `id` 冲突。
- [ ] `node .agents/skills/nano-flow/scripts/check-domain.mjs .` 通过（本轮会先清理阻塞它的空 stale Plan 目录）。
