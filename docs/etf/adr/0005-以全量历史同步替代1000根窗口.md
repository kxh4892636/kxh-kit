# 以全量历史同步替代 1000 根窗口

上游适配器原固定 `count=-1000`，本地缓存只有最近约 1000 根日线；已有缓存的最新日期是昨日，增量刷新不会补更早历史。实测 `count=-10000` 可返回两个证券全量（932315.CSI 3108 根、930955.CSI 5048 根）。因此把请求数量改为 -10000，并新增显式 `syncMarketData` workflow 与 `sync:market` CLI：遍历证券、裁剪到上海昨日、构建交易日历、事务 upsert 并输出覆盖摘要。服务刷新与同步共用 `buildTradingDays`。

Considered Options：只改 count 不提供 workflow（无法补齐已有部分缓存、不可复跑）；查询时自动检测缺口并回填（让读请求承担历史写入与失败风险）；分页/日期窗口循环（当前 -10000 已覆盖全量，未来上游上限下降再引入）。

Consequences：首次同步会写入数千根日线与日历，响应体积明显增大；同步幂等可重复执行；上游若降低单次上限，需要改为分页或按日期窗口同步；日常增量刷新逻辑保持不变。
