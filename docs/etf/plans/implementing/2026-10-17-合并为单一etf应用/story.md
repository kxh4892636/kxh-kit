# 合并为单一 ETF 应用

## 原始想法

重构 apps/etf-dashboard 与 apps/etf-service，前后端统一合并为 etf，前端保持不变，后端服务端技术栈切换为 ts + hono；之后前后端就是一个目录了，所以项目结构推荐

## 角色

- **维护者**：在 kxh-kit 单仓库内启动、测试和构建 ETF 行情，希望一次安装、一条命令、一个应用目录，而不是同时照看两个应用。
- **看板用户**：通过浏览器使用证券目录、K 线、MA 与虚拟均线，不感知代码位置，只要求现有行为不变。
- **后续 agent**：依据单一入口和领域文档继续开发，需要快速判断前端、后端、共享代码、第三方接入、纯逻辑、契约、测试与构建产物各自的位置。

## 故事

### 单一应用合并

#### US-001 统一目录与依赖

作为维护者，我希望能在一个 `apps/etf` 应用内看到 ETF 前端、后端与双端共享代码，共用一份依赖和锁文件，以便减少安装、构建与认知成本。

- [ ] 仓库中不再存在 `apps/etf-dashboard` 与 `apps/etf-service`，只有 `apps/etf`，workspace 安装与锁文件与之一致。
- [ ] 应用根直接分为 `client`、`server`、`shared`，不再有 `src` 层；第三方接入归 `libs`，纯逻辑归 `utils`。
- [ ] 双端共用的契约类型和纯函数只定义一次，放在 `shared`。
- [ ] 前端技术栈维持 React + Vite + antd + Tailwind，用户可见功能与交互不变；后端仍为 TypeScript + Hono + Drizzle + Zod，业务实现不重写。

#### US-002 一体化开发与构建

作为维护者，我希望一条命令启动前端与行情服务，并能分别产出两者的构建结果，以便本地开发与部署都从同一应用出发。

- [ ] `pnpm run dev:etf` 同时启动 Vite 看板与 Hono 行情服务，默认端口与现有文档一致。
- [ ] 构建产出前端静态资源与服务端可执行 JS，`start` 从构建产物启动行情服务。
- [ ] E2E 仍启动并管理自有后端进程，停服恢复旅程真实执行，不复用用户进程。

#### US-003 测试与文档回归

作为维护者，我希望合并后原有测试、覆盖率与五组浏览器旅程保持通过，文档只指向唯一目录。

- [ ] 前端纯逻辑/浏览器测试、后端服务测试与五组 E2E 全部通过，覆盖率门槛维持 80%。
- [ ] 领域 CONTEXT、README、ADR 与根命令反映单一应用结构、共享目录与 libs/utils 约定，旧应用路径不再作为权威入口。

## 约束与澄清

- 2026-10-17 用户要求：前后端统一合并为 etf；前端保持不变；后端服务端技术栈为 ts + hono；并给出项目结构推荐。
- 2026-10-17 用户澄清：「前端保持不变」指技术栈维持现状（React + Vite + antd + Tailwind 等），代码与目录结构允许调整；前后端同为 TypeScript，公用代码可放统一目录。
- 2026-10-17 用户确认：结构不使用 `src` 层；工具函数按职责命名，`utils` 放项目内部单纯逻辑，`libs` 放与第三方服务/数据库/API 的接入。
- 2026-10-17 用户确认：后端以 Hono RPC 暴露 API；目录按业务域组织，业务域内分 handler + service + repository 三层，并使用依赖注入，参考 kitex 分层。
- 2026-10-17 用户确认：数据库访问接口与 SQLite 实现解耦，SQLite 只是可替换实现，未来可换 MySQL/PostgreSQL；接入库沿用 better-sqlite3 + Drizzle。
- 2026-10-17 用户澄清三层职责：handler 是控制层，service 是业务逻辑层，repository 同时是数据库接口与实现；service/repository 与后端服务框架无关，只有 handler 依赖 Hono。
- 2026-10-17 用户要求：Hono 以 RPC 形式暴露接口，并按官方「Using RPC with larger applications」做路由链式组合与类型优化。
- 2026-10-17 用户要求：引入 `hcWithType`，以单一类型实例化点复用 Hono RPC 客户端类型。
- 2026-10-17 用户要求：成功与失败统一响应结构 `{ code: number; message: string; extra: Record<string, any>; data: T }`；code 是业务码，HTTP 状态由服务端框架单独返回。
- 后端在 2026-09-06 已迁移为 TypeScript + Hono（ADR [0001](../../../adr/0001-前后端共同迁移为类型化接口.md)、[0002](../../../adr/0002-以新缓存切换到Drizzle持久化.md)），本次不重写行情用例、存储与上游集成实现。
- 2026-10-17 选择 manual 模式：结构与脚本选择经 /questing 与用户确认后，再进入 /code-delivery。
