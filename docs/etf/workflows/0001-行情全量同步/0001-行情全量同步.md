# 行情全量同步

## 何时使用

- 首次部署或数据库为空，需要预填证券全量历史。
- 现有缓存起点晚于证券的 `earliestTradeDate`（历史被上游 `count` 截断）。
- 上游历史窗口或请求上限变化后，需要重建本地缓存。

日常最新行情由看板查询按需刷新，不需要每次运行本工作流。

## 前置条件

- 网络可访问 `https://hongsehuojian.com`。
- 在 `apps/etf` 目录执行；`DATABASE_DSN` / `.env` 指向目标 SQLite。
- 同步是幂等 upsert，不删除证券目录或旧日线；仍建议确认目标数据库。

## 步骤

1. 执行：

   ```sh
   pnpm --filter @kxh4892636/etf run sync:market
   ```

2. workflow 遍历证券目录，按 `period=day`、`adjust=1`、`count=-10000` 拉取全量，裁剪到上海时间昨日。
3. 按 `security.earliestTradeDate` 到昨日构建交易日历：有日线记为开市，缺失工作日记为闭市；周末不入表。
4. 日线与日历通过 `MarketRepository.saveRefresh` 在一个事务内 upsert。
5. 命令输出每个证券的 `symbol/name/rows/earliestTradeDate/latestTradeDate` 摘要。

## 失败处理

- `not_found`：检查传入/目录中的证券代码。
- `upstream_unavailable` / `deadline_exceeded`：检查网络与上游可用性；事务未提交时重跑即可。
- `SQLITE_BUSY`：停止本地 dev 服务或等待当前写入结束后重跑；WAL 下通常可直接并发。
- 上游返回被截断：`-10000` 是当前全量上限，若未来证券历史超过该值，需要分页或按日期窗口拆分（见 ADR 0005）。

## 限制

- 上游单次最多返回约 10000 根日线；当前两个证券全量为 3108 / 5048 根。
- 仅同步前复权（`qfq`）；数据上界为上海时间昨日。
- 闭市日由缺失工作日推断，不代表权威交易日历。
- 单进程串行同步，不并发请求上游。
