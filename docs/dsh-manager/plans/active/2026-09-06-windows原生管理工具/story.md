# Windows 原生 DSH 管理工具

## 原始想法

创建一个 windows 原生的小工具GUI,要求性能尽可能的高,使用go编程语言;用于 DeepSeek harness 的自动更新, 端口启动和保活. dsh 官方仓库 https://github.com/deepseek-ai/deepseek-harness. 最后产物是一个单文件可执行程序.

## 角色

- **Windows 本机 DSH 使用者**：希望通过轻量 GUI 管理 DSH，减少手动更新、启动和恢复操作。

## 故事

2026-09-06 用户确认全部建议，并补充 Node.js 不需要内嵌。硬约束为 Windows 原生 GUI、Go、高性能、自动更新、端口启动、保活、单文件可执行程序。以下故事地图已确认，技术参数进入设计审阅。

### US-001 运行轻量原生管理器

作为 Windows 本机 DSH 使用者，我希望双击一个 exe 打开原生管理窗口，以便快速管理服务。

- [ ] 管理器使用 Go，采用 Windows 原生控件，交付单个 exe。
- [ ] 使用本机 Node.js，exe 不内嵌 Node.js；首次联网自动准备 DSH，允许用户数据目录保存依赖和配置。
- [ ] 提供启动时间、空闲 CPU 和工作集内存的实测数据；具体平台与预算在设计阶段确定。
- [ ] 下载、更新和服务启动期间窗口仍能响应。

### US-002 按端口启动服务

作为 Windows 本机 DSH 使用者，我希望设置端口和工作目录、启动及停止服务，以便直接进入 DSH Web UI。

- [ ] 展示服务状态和访问地址，支持打开浏览器、启动、停止及重启。
- [ ] 端口冲突有明确提示，不终止非本工具管理的进程。
- [ ] 管理单个实例，仅监听本机，默认端口 3080，可配置端口和工作目录并保存配置。

### US-003 自动更新 DSH

作为 Windows 本机 DSH 使用者，我希望工具检查并安装官方更新，以便免去手工升级。

- [ ] 显示当前版本、可用版本和更新结果，支持手动触发检查。
- [ ] 定时自动检查下载，下次启动应用；运行中可手动立即更新并重启。检查周期与失败恢复技术参数进入设计。
- [ ] 更新失败不会把不可用版本记录为已成功运行。

### US-004 服务保活

作为 Windows 本机 DSH 使用者，我希望意外退出的服务自动恢复，以便保持可访问。

- [ ] 服务异常退出后延迟重启，连续失败采用退避，状态与错误可见。
- [ ] 用户主动停止后不被保活立即重新拉起。
- [ ] 关闭窗口进入托盘并继续保活；支持可选登录自启。完整退出与注销行为进入设计。

## 上下文

- [官方仓库与安装入口](https://github.com/deepseek-ai/deepseek-harness)：2026-09-06 查阅，官方入口为 `npx @deepseek-ai/dsh web`，依赖 Node.js，默认 `http://127.0.0.1:3080`，支持 `--no-open`。
- [官方 Web UI 指南](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/index.md)：启动目录作为默认文件系统位置，Web UI 中选择工作区。
- [官方根 package.json](https://github.com/deepseek-ai/deepseek-harness/blob/master/package.json)：源码当前声明 Node.js `^22.19.0 || >=24.0.0`；交付前须另核对实际安装的 npm 包要求。
- 管理器作为候选独立领域 `dsh-manager`；现有 `dsh` 领域负责插件。领域索引与 glossary 待设计确认后建立。
