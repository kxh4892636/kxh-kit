# Fyne 界面重写

## 问题

用户在 Windows 原生管理器交付并合入 main 后，明确选择 Fyne 重写 GUI，希望使用持续维护的框架获得更现代的界面。Go、单文件 exe、系统 Node.js/npm、高性能与现有管理能力继续适用。本轮先通过 to-issues 固化可恢复的任务图，图确认后进入实现。

## 方案

用 Fyne 重写展示和交互层，复用 manager、process、releases、runtime、settings、startup 的已验证行为。采用中文、清晰分区的单窗口：顶部服务状态与主要动作，中部运行设置与更新信息，下部有界日志；使用一致间距、主题色、图标和自适应布局，支持明暗主题及高 DPI。

每个 issue 都交付可操作的用户能力，顺序为 01 → 02 → 03。01 提前验证真实窗口、工具链、单 exe 和资源占用，02 完成后台生命周期及全部更新交互，03 完成兼容、性能、旧 GUI 退出与最终交付。

## 已排除的备选

- 继续使用手写 Win32 控件：用户已明确选择 Fyne。
- Gio、Wails 或 WebView：本轮框架选择已确定，不继续比较或引入浏览器运行时。
- 重写进程与更新核心：已有行为和竞态测试可复用，迁移应集中于 GUI 与必要的 Windows 集成边界。
- 长期维护两套 GUI：迁移完成后 Fyne 是唯一正式入口。

## 实施决策

### 权威与兼容

- owner 为 dsh-manager。旧 reference Plan 保持历史完成事实，本 Plan 拥有 GUI 迁移的新增要求。
- 本次用户选择覆盖 ADR 0001 中“Win32 系统控件”的决策；外部 Node.js、私有 DSH 安装与用户数据隔离继续有效。Fyne 使用原生桌面窗口与自行绘制的控件，不承诺 Windows 系统控件或 WinUI 外观。该变更记录于 ADR 0002。
- 保留 `%LOCALAPPDATA%/DSHManager` 下现有配置、版本记录、安装目录与默认 DSH profile；升级工具不要求重配端口、路径、选项或重新下载完整有效的安装。
- 保留 `--background` 和现有登录项语义，保留用户级单实例身份；旧版正在运行时，新版不得另外接管同一份配置或启动第二个受管实例。

### 界面与线程

- 初始依赖候选为官方稳定版 Fyne 2.8.1，实施时核验并固定具体版本及依赖；不自动追踪预发布版本。
- GUI 消费 Manager 快照和合并后的变更通知，后台结果通过 Fyne 的 UI 调度 API 更新控件；不得在渲染线程执行网络、安装、停止等待或磁盘清理。
- 继续合并日志与状态更新，空闲不持续主动重绘，隐藏窗口避免无效渲染；保留现有日志容量与访问令牌脱敏规则。
- 状态使用文字与颜色共同表达；配置错误就地显示，失败后控件恢复实际持久配置。滚动日志可选中复制，查看历史时不强行跳到底部。
- 保留停止在启动、运行和退避中的可用性，以及异步请求末次意图优先规则。浏览器使用内存认证地址，界面和日志不展示令牌。
- 托盘优先使用 Fyne 支持的接口；单实例激活、注销等平台行为以窄 Windows adapter 实现，避免将窗口消息细节引入管理核心。

### 验证与性能

- 继承旧版启动、端口所有权、保活、停止取消、更新回退及目录归属契约；框架替换不是删减这些行为的理由。
- Fyne 控件测试覆盖用户操作与快照显示；真实桌面测试覆盖渲染、中文输入/粘贴、DPI、托盘、重复启动、退出。测试使用独立实例身份、数据目录与端口。
- 保留所有自有生产代码的整体 statement 覆盖率至少 80%，不通过排除 GUI 或 adapter 缩小分母。gofmt、go vet、Go 测试、真实 DSH 冒烟和 Standards/Spec 双轴审查均须通过。
- 暂沿用已确认预算：窗口可交互低于 1 秒，空闲工作集低于 40 MiB，60 秒 CPU 累计低于 0.6 秒。01 做早期测量，03 对最终 exe 验收；不能将旧版约 20 MiB 的数据当作 Fyne 实测结果，也不能自动放宽预算。
- 同机同条件测量首次及五次暖启动，分别报告窗口可见和托盘隐藏的内存/CPU，区分进程创建、首帧和可交互信号；旧测量依赖 Win32 子控件 ID，迁移后必须更换探测机制，不能因失去子控件而虚报就绪。
- 构建需验证 CGO/C 编译器与图形驱动要求。交付只需一个管理器 exe，不要求用户安装构建工具或携带额外非系统 DLL；Node.js/npm 仍为明确的外部运行依赖。最终记录大小、SHA256、图形环境和未验证平台。

## 范围

- 三个 issue 唯一分担基础操作、后台完整操作与最终交付责任；必要的边界提取在消费它的 01 中完成，不单开无用户结果的重构任务。
- GUI、必要 Windows 集成、测试、构建、测量脚本、说明、许可与领域决策；保留单 Windows x64 exe 的交付形式。
- 本轮已授权需求拆分和文档落盘。任务图确认后复用原交付的本地实现、测试和逐项提交方式；远端推送和发布不在本 Plan 内，主分支合入沿用明确的后续指令。

## 非范围

- Node.js 内嵌、自动安装或升级，管理器自身在线更新，服务/多实例/跨平台交付。
- 修改官方 DSH、迁移凭据或会话、修改全局 npm 安装、重写已验证更新与进程算法。
- 无条件承诺 Fyne 达到旧版体积和内存数值；引入额外商业主题或重型持续动画。
