# 修复对比视图响应性回归

## 交付

选择项目并打开仓库的激活对比后，应用在失败 fixture 上恢复可交互和可滚动状态，同时保留大对比的 DOM 有界、文件/行导航与评论契约。

## 范围

- 消费 Issue 01 的 causal hotspot 和同机性能预算，只修改被证据命中的渲染管线。
- 优先移除重复滚动观察、同步 commit、每次 commit 的强制布局或不必要 App 级状态更新；只有证据要求时才合并或关闭虚拟层。
- 让 Issue 01 的真实 Electron responsiveness 用例由失败转为通过。
- 覆盖多小文件、单巨型 chunk、多 hunk 大文件，以及 split/unified 文本路径。
- 回归 DOM 有界、文件树跳转、键盘导航、评论导航和构建。
- 不做无关性能重构、生产遥测或未经证据支持的虚拟化依赖替换。

## 直接依赖

- 01：生产修复必须建立在可重复失败和 causal hotspot 上；消费其失败 fixture、同机性能预算、layer/commit 对照、profile 与最小修复边界。

## 验收

- [ ] 失败 fixture 在同机首次稳定、静止期收敛、代表性按钮响应、滚动响应和 long task 预算上全部通过。
- [ ] profile 证明静止期收敛，且修复命中 Issue 01 确认的 causal hotspot，没有以关闭全部虚拟化换取小对比流畅。
- [ ] 多小文件、单巨型 chunk、多 hunk 大文件在 split/unified 下均有真实 Electron 或与风险层级匹配的回归证据。
- [ ] 既有行/文件虚拟化测试、100 文件导航 e2e、键盘/评论导航、typecheck 与 build 继续通过。
