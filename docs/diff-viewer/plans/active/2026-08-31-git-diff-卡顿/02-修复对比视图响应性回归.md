# 修复对比视图响应性回归

## 交付

选择项目并打开仓库的激活对比后，应用在失败 fixture 上恢复可交互和可滚动状态，同时保留大对比的 DOM 有界、文件/行导航与评论契约。

## 范围

- 消费 Issue 01 的 causal hotspot 和同机性能预算，只修改被证据命中的渲染管线。
- 优先移除重复滚动观察、同步 commit、每次 commit 的强制布局或不必要 App 级状态更新；只有证据要求时才合并或关闭虚拟层。
- 让 Issue 01 的真实 Electron responsiveness 用例由失败转为通过。
- 覆盖多小文件、单巨型 chunk、多 hunk 大文件，以及 split/unified 文本路径。
- 回归 DOM 有界、文件树跳转、键盘导航、评论导航和构建。
- 不做无关性能重构、生产遥测或未经证据支持的虚拟化依赖替换。

## 直接依赖

- 01：生产修复必须建立在可重复失败和 causal hotspot 上；消费其失败 fixture、同机性能预算、layer/commit 对照、profile 与最小修复边界。

## 验收

- [x] 失败 fixture 在同机首次稳定、静止期收敛、代表性按钮响应、滚动响应和 long task 预算上全部通过。
- [x] profile 证明静止期收敛，且修复命中 Issue 01 确认的 causal hotspot，没有以关闭全部虚拟化换取小对比流畅。
- [x] 多小文件、单巨型 chunk、多 hunk 大文件在 split/unified 下均有真实 Electron 或与风险层级匹配的回归证据。
- [x] 既有行/文件虚拟化测试、100 文件导航 e2e、键盘/评论导航、typecheck 与 build 继续通过。

## 实施记录

- 真实 wheel 的 Node 侧总派发墙钟时间包含浏览器输入调度：修复态文件 fixture 曾为健康基线的 3.16 倍，但同轮同步 burst 仅 0.5ms、连续滚动最长帧 16.8ms 且无 long task。因此它保留 5 倍健康基线的宽松防退化上限；同步 burst、滚动帧和 long task 是响应性硬门禁。
- 异步 virtualizer 通知下，动态高度校正可能让一次 `scrollToIndex` 停在目标前方；DOM-id 导航在有界的 60 帧窗口内重试索引滚动，目标挂载后再执行既有精确定位，不恢复同步 flush。
- 文件序列以 repositoryId、请求及解析后的 base/target/baseMode 和路径列表共同形成导航 scope；即使两个仓库或 revision 的路径完全相同，上下文切换、启用状态或滚动容器变化及卸载时，layout-effect cleanup 也会使旧的帧重试失效，避免陈旧请求滚动新列表。
- 行窗口以 cursor 的行索引与 DOM id 形成导航 scope；cursor 清空或切换时同样取消旧行的挂载重试。
- 最终全量 Electron 复核中，健康/行/chunk/文件/嵌套 fixture 的同步 burst 为 0.3/0.5/0.7/0.7/0.8ms；全部静止 task ratio 低于 0.12%、0 个 long task、工具栏响应低于 88ms、连续滚动最长帧低于 17.4ms，五形状预算通过。
- 回归证据：定向虚拟化 Vitest 13/13（含文件/行导航 scope 切换与卸载取消）、package Vitest 880 通过/1 跳过、Electron e2e 14/14、typecheck 与 build 通过；全部四个变更生产模块的 V8 coverage 为 statements 98.6%、branches 87.61%、functions/lines 100%。
- 根级 `pnpm ready` 在首步 `vp check` 被 Windows 工作树既有的 1015 个换行格式问题拦截，未进入 root tests/build；没有批量改写这些超出本 issue 的文件。本次 issue 改动文件的 `vp check` 为零问题，package 级完整门禁如上通过。
