命令：`fallow health --format json --quiet --complexity-breakdown`。

### 4. 误报（保留，不建议删）

- `@typescript/native` 被判为 `unused_dev_dependency`（两包 package.json 各 1 条）。实际用途是提供 `tsc` 二进制：`packages/pi-nested-skill/node_modules/@typescript/native/bin/tsc` 存在，包内 `vite.config.ts` 开启 `lint.options.typeCheck: true`，`vp check` 报告的类型检查即由它完成；fallow 看不到 CLI 消费。建议在 fallow 配置里 `ignoreDependencies: ["@typescript/native"]`，或原样保留。

### 5. 重复代码

- fallow `dupes` 在两包及仓库范围内均报 0 clone group / 0 duplicated lines。
- 未被工具捕获的轻度重复：`messageOf(error)` 三份拷贝（`pi-deepseek-web/src/config.ts:209`、`fetch.ts:219`、`search.ts:243`），实现完全相同，低于 fallow 阈值。可提取到共享模块。
- 与 `packages/dsh-nested-skill/src/provider.ts` 的嵌套 skill 扫描逻辑相似（`DEFAULT_EXCLUDED_DIRS` 多 `.turbo`、带 chokidar 监听），但两者宿主不同、无互相依赖，属有意重复，当前不建议合并。

### 6. 逻辑与风险

- **`truncated` 恒为 `false`**：`mapAnthropicResponse` 固定返回 `truncated: false`，`format.ts:47` 的截断提示分支不可达（v8 覆盖率显示 `format.ts` 未覆盖行 47）。这不是回归——上游 spec 明确写「`truncated` 固定 `false`」——但字段与分支是死面：要么接上截断信号，要么删字段与分支。
- **`web_fetch` 无 SSRF 防护**：`fetch.ts` 用 `redirect: "follow"` 且只校验协议为 http(s)，模型可让 `web_fetch` 访问 `localhost`、私网或云元数据端点（如 `169.254.169.254`）。当前 spec/ADR 未表态，属待决取舍（见 story「迷雾」），非缺陷判定。
- **`resources_discover` 同步全量遍历**：每次 startup/`/reload` 都用 `readdirSync` 递归扫描 agent、`~/.agents/skills`、cwd 祖先与已知 skill 目录（`agent-session.js:1928 extendResourcesFromExtensions` 每次触发）。当前规模无问题，属可观测的扩展性上限。
- **`$` 展开不感知 Markdown**：代码块/行内代码中的 `$name` 也会被展开；spec 未承诺排除，属已知边界。
- 符号链接目录不跟随是上游 spec 的显式决策（避免环），非缺陷。

### 7. 宿主 API 一致性（核对通过）

- `resources_discover` 返回 `skillPaths: string[]` 与 pi 0.85.1 类型 `ResourcesDiscoverResult` 一致；`resource-loader.js:mapSkillPath` 对含 `SKILL.md` 的目录取其 `SKILL.md`，与插件「只返回目录」的约定吻合。
- 插件前提成立：`dist/core/skills.js:117` 注释与 `loadSkillsFromDirInternal` 实现确为「目录含 `SKILL.md` 即视为 skill root 且不再下钻」，隐藏 skill 因此不可见。
- `input` 事件使用合法：`InputSource` 含 `"extension"`（插件据此防自环），`InputEventResult` 的 `transform` 形态与返回一致。
- `SlashCommandInfo.sourceInfo.path` 存在，`dirname` 取目录正确；`getCommands()` 的 `source === "skill"` 与 `skill:` 名称前缀同宿主实现一致。

### 8. 测试缺口（语句/函数级）

- `packages/pi-nested-skill/src/index.ts` 未覆盖语句：`knownSkillDirs` 的 `filter`/`map` 回调（`index.test.ts` 的 `resources_discover` 用例传空命令表）与 `lookupSkill` 的 `catch` 分支（读文件失败回退 `undefined`）。建议补一条「已知 skill 目录下方发现隐藏 skill」的用例。
- 其余未覆盖项均为分支级噪声：`options.env ?? process.env` 的默认回退（测试总是注入 env）、`messageOf` 的 `String(error)` 分支、`search.ts:224-225` 的不可读响应体分支、`errorDetail` 的 `message` 回退分支。
