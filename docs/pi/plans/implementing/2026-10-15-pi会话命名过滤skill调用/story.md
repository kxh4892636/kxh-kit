# pi 会话命名过滤 skill 调用

## 原始想法

> pi-session-name 进行升级, 进行重命名时, 用户的输入过滤调用的 skill

（用户输入，2026-10-15）

## 角色

- **pi 使用者**：经常以 skill 调用（`$skill-name`、`/skill:name` 或直接粘贴 skill 块）作为会话首句；现有自动命名把 skill 正文当成标题来源，会话列表出现 `<skill name="` 之类无意义名称，难以扫读。
- **插件维护者**：维护 `packages/pi-session-name`，需要在不引入配置项、不改变既有命名边界（模型优先、失败降级、≤13 码点）的前提下修正输入来源。

## 故事

### 命名输入过滤

会话首句包含 skill 调用时，自动命名依据过滤后的真实用户请求生成，而不是 skill 正文。

#### US-001 skill 调用不再污染名称

作为 pi 使用者，我在首句调用 skill 后会话名仍能反映我真正要做的事，以便在会话列表里认出这次会话。

- [ ] 首句为 `<skill name="…" location="…">…</skill> <请求>` 时，名称依据 `<请求>` 生成，不包含 skill 正文
- [ ] 首句为 `/skill:<name> <请求>` 时，名称依据 `<请求>` 生成
- [ ] 首句为纯 skill 调用（无附加文本）时，名称取该 skill 名，而不是 skill 正文或以 `<skill name="` 开头的截断
- [ ] 首句含多个 skill 块时，名称依据剩余文本；无剩余文本时取第一个 skill 名

#### US-002 普通输入与既有边界不受影响

作为 pi 使用者，我不调用 skill 时的命名行为与升级前一致。

- [ ] 不含 skill 调用的首句仍按既有行为命名（模型优先、失败降级确定性截断、≤13 码点）
- [ ] 既有跳过条件不变：已有名称、分支已有用户消息、扩展来源、装饰性输入
- [ ] 首轮不阻塞（`input` handler 立即返回）

## 约束与澄清

- 用户原话（2026-10-15）：重命名时过滤调用的 skill。
- 沿用上一 Plan 已确认的约束（2026-10-14「全部 ok」）：模型优先 + 失败降级确定性截断；使用当前会话模型；零配置；按 Unicode 码点截断、不加省略号。
- 已确认变更（2026-10-15，commit `871dd71`）：命名长度上限由 8 调整为 13 字。
- 只过滤「命名输入」：发给模型的真实用户消息、被调用的 skill 正文均不变。

## 迷雾

无。过滤范围、无剩余文本时的兜底、用户文本与 skill 名共存时的取舍已在 [01 note](01-skill调用过滤.md)「拷问记录」收敛。
