## 决策与证据

- 取证：内置 `/name` 实现落在 `interactive-mode.js` 的 `handleNameCommand`，最终调用 `session.setSessionName()`；`SessionManager.appendSessionInfo()` 仅折叠换行并 trim，无长度限制。故「调用 /name」等价于扩展里的 `pi.setSessionName()`（来源：`dist/core/session-manager.js:914`、`dist/core/agent-session.js:3211`）。
- 取证：`prompt()` 先尝试扩展命令分派，再执行 `input` 处理器，随后才展开 skill 并启动 run；即在 `input` 内异步命名不会阻塞 run（来源：`dist/bundle/chunks/*` 的 `prompt`/`_runInputHandlers`、`docs/extensions.md`「Respect the runtime lifecycle」）。
- 真机取证（关键）：`opencode-go` 等按会话路由的 provider 需要 `sessionId`，缺失时报 400 `MissingSessionID`；故 `complete()` 必须传 `sessionId: ctx.sessionManager.getSessionId()`。
- 真机取证（关键）：`deepseek-v4.1-flash` 等推理模型在出标题前先产出 thinking，`maxTokens: 32` 时 `stopReason=length` 且无 text 块而被降级；`reasoning: "off"` 经 `complete()` 不生效（`complete → stream` 走 provider 原生 API）。故默认预算提到 256，让 thinking 与标题都装得下。
- 第 1 轮确认（2026-10-14「全部 ok」）：混合生成（模型优先、失败降级截断）；模型取 `ctx.model`；≤ 8 按 Unicode 码点、不加省略号；零配置。
- 代码审查（Spec + Standards 两路 subagent）发现并已修：markdown 强调符（`**`/`__`/`*`/`~~`）未清洗、多 text 块拼接切断首行语义、`ctx.model`/`hasConfiguredAuth` 在 try 外、`session_start` 后在途调用仍可能写入、`void nameSession` 未兜底、测试替身未校验模型与参数。未采纳：默认导出用 `function`（pi 扩展既有约定，与同级包一致）。

## 拷问记录

### 第 1 轮

#### Q1 — 名称生成方式

- 问题：模型生成 / 确定性截断 / 混合（模型失败降级截断），三选一？
- 前置问题：无。
- 下游边界：决定是否需要模型调用、异步编排、提示词与降级路径，影响 US-001/US-002 的验收项与单测范围。
- 推荐答案及理由：混合。优先用模型生成语义化标题，失败或超时降级为确定性截断。理由：既满足「简短且有辨识度」，又能在无鉴权/网络失败时仍产出名称；pi 已提供 `ctx.modelRegistry.complete()`。
- 修改意见：全部 ok。
- 处理结论：已确认（2026-10-14）——混合生成；已写入 spec「实施决策 · 名称生成与截断」。

#### Q2 — 模型来源

- 问题：当前会话模型 `ctx.model` / 插件配置文件指定 / pi 分类器模型，选哪个？
- 前置问题：Q1。
- 下游边界：决定配置面、成本与鉴权前提，以及是否新增配置文件读取。
- 推荐答案及理由：默认当前会话模型 `ctx.model`，无鉴权或调用失败即降级；本轮不引入配置文件。理由：零配置、复用用户已选模型；分类器模型不保证存在。
- 修改意见：全部 ok。
- 处理结论：已确认（2026-10-14）——默认 `ctx.model`，不引入配置文件；已写入 spec「实施决策 · 名称生成与截断」。

#### Q3 — 「≤ 8 个字」口径

- 问题：按 Unicode 码点截断（中英文统一 8 个字符）还是按汉字数？超长是否加省略号？
- 前置问题：无。
- 下游边界：决定清洗/截断实现与验收断言。
- 推荐答案及理由：按 Unicode 码点计 ≤ 8，不加省略号；提示词要求中文优先。理由：实现确定、跨语言一致；省略号占位且易被误读。
- 修改意见：全部 ok。
- 处理结论：已确认（2026-10-14）——Unicode 码点 ≤ 8、不加省略号；已写入 spec「实施决策 · 名称生成与截断」。
