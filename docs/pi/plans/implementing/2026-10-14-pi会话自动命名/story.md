# pi 会话自动命名

## 原始想法

在 kxh-kit 中制作一个 pi 插件, 根据每个 pi 会话的第一句用户输入, 调用 /name 给这个 pi session 重命名, 要求名称简短, 小于等于 8 个字

## 角色

- **pi 使用者**：同时在多个项目、多个会话间来回切换，依赖会话列表（`/session`、会话选择器）找回之前的任务；会话默认只显示首句原文，长且难扫读。

## 故事

### 会话自动命名

会话开始后，依据第一句用户输入自动生成一个简短显示名，让会话列表可扫读，且不打断首轮对话。

#### US-001 首句输入后自动命名

作为 pi 使用者，我提交第一句输入后会话自动获得一个基于该输入的显示名，以便在会话列表里一眼认出这次会话。

- [x] 新会话的第一次用户提交（非扩展来源）后，`pi.getSessionName()` 返回一个非空名称
- [x] 名称写入会话文件（`session_info` 条目），`/session` 与会话选择器可见
- [x] 触发不阻塞首轮对话：提交到模型首响的时间不因命名增加
- [x] 会话中已手工执行过 `/name` 的，不被自动命名覆盖

#### US-002 名称简短

作为 pi 使用者，我希望名称短到能在列表里完整显示，以便扫读。

- [x] 自动生成的名称长度 ≤ 8 个字符
- [x] 名称不含换行、成对引号包裹等噪声
- [x] 长度按 Unicode 码点截断，不把字符截成半个

#### US-003 会话边界不被误伤

作为 pi 使用者，我恢复、继续或派生会话时不应被重新命名。

- [x] 恢复（resume）后已有名称或已有历史用户消息的会话不触发自动命名
- [x] 非交互来源（扩展注入，`source === "extension"`）不触发
- [x] 命名失败（模型不可用、无鉴权等）静默降级，不阻断首轮对话

## 约束与澄清

- 原始要求（2026-10-14）：以「第一句用户输入」为依据；名称简短、≤ 8 个字；等价于调用 `/name`（即 `pi.setSessionName()`）。
- 用户澄清（2026-10-14）：Plan 落到 `repos/kxh-kit/docs/pi`，不写在工作区根目录。
- 已确认（2026-10-14「全部 ok」）：混合生成（模型优先、失败降级确定性截断）；默认当前会话模型；≤ 8 按 Unicode 码点截断、不加省略号；零配置。

## 迷雾

无。名称生成方式、模型来源、截断口径与配置面均已收敛（见 [01 note](01-会话自动命名实现.md)「拷问记录」第 1 轮）。
