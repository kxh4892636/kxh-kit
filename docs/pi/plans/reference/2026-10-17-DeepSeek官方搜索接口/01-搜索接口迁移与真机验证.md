## 决策与证据

### 官方接口事实（2026-10-17 查阅并实测）

- 官方指南：Search 为 `POST https://api.deepseek.com/v1/tools/search`，Bearer 鉴权；`query` 必填 1–128 字符；`count` 1–50、默认 10；`need_content` 默认 false；响应 `results[]` 含 `rerank_score/title/url/snippet/summary/content/site_name/site_icon/date/authority`。
- 官方 Fetch 为 `POST https://api.deepseek.com/v1/tools/fetch`，请求 `{ url }`（≤8192 字符、含 host 的 HTTP/HTTPS、不含用户名/密码），响应 `{ title, content }`（Markdown）。
- 用本机 key 实测 Search：HTTP 200，返回 `results[0]` 含 `title`、`url`、`summary`、`authority`、`rerank_score`、`date`、`site_name`；未请求正文。
- 用本机 key 实测 Fetch：`https://example.com` HTTP 200，返回 `title: "Example Domain"` 与 Markdown `content`；`https://raw.githubusercontent.com/.../README.md` 返回 HTTP 404，`https://api.github.com/repos/...` 返回转义 JSON 文本。说明官方 Fetch 适合网页正文，但不保证原始文本/文件形态。
- Search/Fetch 各 5 QPS，按成功请求计费（每 1000 次 5 元）；Search 408/429/5xx 建议等待后重试，其他 4xx 不重试。
- 2026-10-17 dev gate：用户确认「两个 api 全部切换, 然后允许更新, go」，即两个工具均迁移，且允许更新本机配置。
- 2026-10-17 用户补充：以官方指南为重构依据，暴露的工具契约需包含对应的请求体、搜索语法与响应。据此 `web_search` 参数扩展为 `query`、`count`、`ori_question`、`localization`、`need_content`；`query` 描述列出官方搜索语法；`details` 保留 `results[]` 全部官方字段；`web_fetch` details 暴露 `{ url, title, content, truncated }`。

### 现有实现事实

- `src/search.ts` 向 `${baseURL}/messages` 发送 `web_search_20250305`，从 `web_search_tool_result` 与 `text.citations` 合成结果；`src/config.ts` 默认 `https://api.deepseek.com/anthropic/v1`、`deepseek-v4-flash`、`maxUses` 等。
- `src/format.ts` 把 answer、sources、truncated 投影为模型文本；`src/index.ts` 注册 `web_search`（仅 `query`）与 `web_fetch`。
- `src/fetch.ts` 直连 HTTP + turndown + GFM；`fetch` 的 `details` 为 `{ url, statusCode, contentType, truncated }`。
- 本机 `~/.pi/agent/settings.json` 的 `packages` 已包含 `packages/pi-deepseek-web`；用户配置含 `apiKey`、`baseURL`、`model`。
- 本机 `deepseek-harness` 的 `web-search-deepseek` 仍使用 Anthropic Messages 服务端工具，不能作为官方 Search API 的现成参考；官方文档与实测是权威来源。

### 选定方案与理由

- `web_search` 直连官方 Search API：省掉模型轮次与工具触发不确定性，结构化字段齐全，`count` 可直接控制条数。
- `web_fetch` 切到官方 Fetch API：由服务端完成抓取与 Markdown 提取，删除 turndown、content-type 分类、字节流限额与直连解码，减少依赖与维护面；代价是失去原始文本/HTTP 状态，按次计费。
- 共享 `http.ts`：两个端点共用鉴权、超时、取消与错误解析，避免复制；错误消息保留工具 label 以便定位。
- `baseURL` 继续作为唯一 API 根地址，`toolEndpoint` 同时接受根地址与带 `/v1` 的地址；旧 Anthropic 端点用显式错误而非静默改写。
- `count` 作为可选工具参数，配置 `searchCount` 作为默认值；模型可按需扩大结果，避免每次改配置。
- `ori_question`、`localization`、`need_content` 按官方请求体暴露，但仅在模型提供时发送；`need_content: true` 时在模型可见文本中展示正文，并提示上下文代价。
- 搜索结果保留官方字段（含 `rerank_score`、`authority`、`site_icon`、`snippet`、`summary`、`content`），`details` 使用 `{ count, results }` 直接暴露响应；文本投影只挑选模型需要的字段，图标不进入文本。
- 结果摘要优先用 `summary`（官方说明适合模型阅读）；仅当 `need_content: true` 且响应带 `content` 时在文本中追加正文，避免默认放大上下文。
- 不自动重试：错误信息足以让模型决策，避免隐藏等待与取消语义冲突。
