# 以独立插件补充发现与原位展开

Pi Nested Skill 以独立 workspace package 交付，不修改 Pi core：`resources_discover` 从已载入原生 skill 的路径向下补充被父 `SKILL.md` 遮挡的后代路径，`input` 在 Pi 内建展开前把任意位置、任意数量的 `/skill:<name>` 原位替换为原生 skill block。Pi 继续拥有 frontmatter 解析、校验、目录、冲突诊断与系统提示，从而避免插件维护第二套 skill 规范。

## Considered Options

- **修改 Pi core**：可直接扩展原生发现与命令解析，但不满足独立插件交付，并把实验语义绑定到上游发布节奏；被拒绝。
- **插件自建 parser 与 catalog**：能完全控制发现和调用，却会与 Pi 的 skill 规范、优先级和诊断持续漂移；被拒绝。
- **新增 marker 语法或逐 skill 参数**：会引入第二套命令语言，而自然语言没有可靠的隐式参数边界；被拒绝。
- **实时 watcher 或每次输入重扫**：Pi extension 没有资源失效 seam，前者需额外生命周期机制，后者增加输入延迟；统一使用 startup 与 `/reload`；被拒绝。

## Consequences

- 插件只扫描已进入 Pi catalog 的原生 skill 子树；无效父 `SKILL.md` 未进入 catalog 时，其有效后代仍可能被遮挡。
- 原生 skill 同名时优先；嵌套 skill 按父 skill 既有顺序和规范化相对路径确定胜者，canonical path 去重。
- marker 按 occurrence 从左到右展开、允许重复、不会递归扫描插入的正文；其他文本作为共享用户输入，不提供逐 skill 参数。
- 未知或读取失败的 marker 保留原文，局部失败不阻断其他展开；`\/skill:name` 表示字面量。受 Pi 现有公开 input seam 限制，已知且不可读的 marker 位于输入开头时，Pi core 仍可能追加一次原生读取 diagnostic；插件不通过改写文本或异步重投来隐藏它。
- interactive 与 RPC 输入参与展开，extension 注入消息不参与；资源变更通过 `/reload` 生效。
