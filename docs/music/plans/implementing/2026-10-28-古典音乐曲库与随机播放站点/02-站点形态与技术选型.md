## 决策与证据

候选方案（尚未定论）：

| 方案         | 形态                                                     | 优点                               | 代价                                                 |
| ------------ | -------------------------------------------------------- | ---------------------------------- | ---------------------------------------------------- |
| A 纯静态     | Vite + React，`tracks.json` 构建期生成，音频作为静态资源 | 无后端、部署即文件夹、开发最快     | 无法做跨设备同步的收藏/历史；曲库变大要重新构建      |
| B 轻服务端   | Node（Hono/Fastify）+ 静态音频                           | 可加收藏、历史、按需转码、LAN 多端 | 多一层进程与部署；本机自用收益有限                   |
| C 现成服务器 | Navidrome / Jellyfin                                     | 随机播放、客户端、转码开箱即用     | 界面与随机策略不可改；与「自己做一个站点」的目标冲突 |

待验证的技术前提：

- 浏览器对 FLAC 的支持：Chrome、Firefox、Safari（11+）均可在 `<audio>` 直接播放；体积是主要问题，不是兼容性。
- 静态服务器需支持 `Accept-Ranges: bytes`，否则拖动进度条与部分浏览器播放会异常。
- 145 首曲目的 `tracks.json` 体积很小（几十 KB），无需分页或懒加载。
- 9.6 GB 不适合公网托管；若只在本机/局域网，静态直出即可。
