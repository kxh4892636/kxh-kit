## 决策与证据

2026-11-01 用户确认：

1. **部署范围**：暂只本机部署（`127.0.0.1`），不做局域网/公网。
2. **功能边界**：随机播放 + 下一首 + 近 13 条播放历史；不做筛选、收藏、搜索。
3. **音频**：FLAC 直出；必须支持流式与分片加载，压低单次请求压力。原始下载数据需要先处理再入库。
4. **完全自建**：TypeScript；前端 React 静态站点；后端 Hono 只负责音乐的分片/流式加载与索引；数据库 SQLite；实现范式参考 `apps/etf`。

### 参照片事实（`apps/etf`，2026-11-01 核对）

- 运行时：Node ≥22.12；服务端开发用 `node --watch --experimental-strip-types server/main.ts`，构建用 `tsc`（`@typescript/native`）双 tsconfig，产物 `dist/server/main.js`。
- 前端：React 19.2 + TanStack Router 1.169 + TanStack Query 5.100；antd 6 + Tailwind 4；`vite-plus`（`vp dev` / `vp build` / `vp test`）。
- 后端：Hono 4.13.7 + `@hono/node-server` 2.1.1，`serve({ fetch: app.fetch, port, hostname: "127.0.0.1" })`；zod 4.5 校验 `.env`（`PORT`、`DATABASE_DSN`）；类型化接口用 `hono/client` 的 `ApplyGlobalResponse` + `shared/api.ts`。
- 数据层：better-sqlite3 13 + drizzle-orm 0.45 + drizzle-kit 0.31，schema 在 `server/**/schema.ts`，迁移在 `migrations/`。
- 测试：vitest 5（含 `@vitest/browser-playwright`、`vitest-browser-react`）+ Playwright e2e（带证据截图）。
- 静态资源：etf 由前端独立构建，Hono 不托管；本 Plan 需要 Hono 直接出音频，属于新增能力。

### 关键证据：Hono 静态托管已支持 Range

`@hono/node-server@2.1.1` 的 `serve-static` 内含 `BYTE_RANGE_PATTERN`、`parseByteRange`、`resolveByteRange`，会返回 `Accept-Ranges: bytes`、`Content-Range` 与 206，并用 `createReadStream` 流式发送（`node_modules/@hono/node-server/dist/serve-static.mjs` 第 114–140 行）。因此「分片加载」不需要手写 206，直接用 `serveStatic` 即可；手写只在需要鉴权/统计/自定义路径映射时才值得。
