## 决策与证据

**BT 不可行（2026-10-28 实测）**：torrent 237,083 字节，tracker 为 `bt1/bt2.archive.org:6969`，web seed 三个（`archive.org/download/`、`ia601204`、`ia701204`）。libtorrent 2.1.1 + SOCKS5 代理运行 45 秒：peers 1–3、seeds 0–1、速率 2.6–4.1 KB/s、下载量 0 字节——该 2012 年众筹条目已无有效做种。改 HTTP 代理后 web seed 生效，但只有 260–350 KB/s，9.61 GB 约需 8 小时。

**HTTP 可行**：单连接实测 0.22 MB/s（5 MB 用 22.9 秒、20 MB 用 90 秒）；3 并发 3×3 MB 用 2.7 秒，约 3.3 MB/s；实际 8 并发下载器约 1.25 MB/s（受代理与 IA 节点波动影响）。因此采用并发 HTTP，而非 P2P。

**网络前提**：直连 `archive.org` 8 秒超时，必须经 `127.0.0.1:7890`；libtorrent 的 SOCKS5 只代理 TCP peer 与 tracker，UDP 无法穿透，这也是放弃 BT 的次要原因。

**清理动作**：开工前删除探针留下的 13.4 MB 稀疏分片，避免 `curl -C -` 从错的偏移续传。

**校验口径**：以 IA 元数据的 `md5` 为准，`size` 为副证；不一致即删文件重下，最多 4 轮。
