# 古典音乐曲库与随机播放站点

## 原始想法

> 使用 bt 下载全部, 并下载的本地, 创建 plan, 后续会使用这些音乐, 创建一个随机播放网站

（2026-10-28 用户原话；上一轮的语境是把 Internet Archive 的 Musopen 镜像整包拉到本地。BT 实测不可用后按用户「下载全部」的意图改用同条目的 HTTP 直链，见 [01](01-曲库落地与校验.md)。）

## 角色

- **曲库主人**：本机 Windows 工作站用户，音乐文件落盘后长期保存；不接受每次听音乐都要联网、注册账号或受每日下载配额限制。
- **站点使用者**：与曲库主人是同一人；打开页面就想有声音，不想先建歌单、选作曲家；会在后台长期挂着当背景音乐。

## 故事

### 曲库落地

这一组故事把镜像整包变成可离线读取的本地文件，并要求可核对、可续传。

#### US-001 整包落到本地并可校验

作为曲库主人，我希望把 `MusopenCollectionAsFlac` 的 580 个文件（145 首曲目 × FLAC / MP3 / OGG / 封面 PNG）完整落到本地目录，并且每个文件都能用来源 md5 核对，以便日后不必再回源下载。

- [ ] 580 个文件、9.61 GB 全部就位在 `C:\Users\kxh\Music\musopen-flac`
- [ ] 每个文件的 md5 与 Internet Archive 元数据一致，失败清单为空
- [ ] 中断后重跑脚本只补缺，不重复下载已完成文件

### 随机播放站点

这一组故事把本地曲库变成可用的随机播放器，先本机可用，再谈部署范围。

#### US-002 打开即随机播放

作为站点使用者，我希望打开页面就自动开始播放，并能下一首、暂停、看到当前曲目名称与作曲家，以便不操作也能一直有音乐。

- [ ] 首屏无需点击即可开始播放（或给出一次浏览器要求的确认入口）
- [ ] 「下一首」按洗牌袋抽取，一轮内不重复
- [ ] 正在播放的曲目显示作曲家、作品名、乐章/段落

#### US-003 曲目信息来自索引而非文件名

作为站点使用者，我希望界面显示的是整理过的作曲家与作品名，而不是 `LudwigVanBeethoven-SymphonyNo.3InEFlatMajorEroicaOp.55-01-AllegroConBrio` 这样的文件名，以便知道在听什么。

- [ ] 站点只读构建期生成的 `tracks.json`，运行时不扫盘、不解析文件名
- [ ] 索引含作曲家、作品、乐章、时长、格式、封面路径、来源链接与许可

#### US-004 回看最近听过的十三首

作为站点使用者，我希望页面能显示刚刚听过的最近 13 首，以便回想起「刚才那段是什么」而不是靠记忆猜。

- [ ] 每次开始播放写入一条历史，按时间倒序展示最近 13 条
- [ ] 历史存 SQLite，重启浏览器与服务后仍在
- [ ] 同曲连续重播不刷屏（同一曲目只保留最新一条）

## 约束与澄清

- 2026-10-28 用户指令：先「使用 bt 下载全部」，再「下载到本地」，并「创建 plan」。
- 2026-10-28 实测修正：该 2012 年条目的 BT swarm 已基本无种子（1 个 seeder、约 3 KB/s），改走同条目的 HTTP 直链并行下载；用户「下载全部」的目标未变，传输手段变更记录在 [01](01-曲库落地与校验.md)。
- 2026-10-28 落盘位置：`C:\Users\kxh\Music\musopen-flac`（仓库外，避免 9.6 GB 进 Git）；仓库只保留脚本、状态与文档。
- 许可口径：条目为 CC Public Domain Mark 1.0，可自由复制；站点仍标注来源与许可，不做「无版权」的绝对表述。
- 站点技术栈、部署范围（仅本机 / 局域网）、是否需要移动端，均未确认，见 [02](02-站点形态与技术选型.md)。

## 迷雾

- **部署范围**：仅 `localhost`、还是局域网其他设备也要能播？后者涉及静态音频服务的监听地址与 9.6 GB 传输带宽。
- **播放形态**：只要「随机下一首」，还是要按作曲家/时期筛选、收藏、播放历史？后者会把索引与状态推到服务端。
- **格式策略**：浏览器对 FLAC 支持良好但体积大（约 6–7 GB 的 FLAC 部分）；是否需要在构建期转一份 Opus/MP3 供移动端。
- **是否真的自建**：Navidrome / Jellyfin 这类现成开源音乐服务器已自带随机播放与客户端；自建的收益在于完全贴合自己的界面与随机策略。
