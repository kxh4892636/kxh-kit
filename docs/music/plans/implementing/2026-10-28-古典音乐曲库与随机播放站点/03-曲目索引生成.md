## 决策与证据

- **曲目单元 = 一个 `.flac`**：每首在元数据里有 `.flac`/`.mp3`/`.ogg`/`.png` 四件同名文件；FLAC 为主音频，MP3/OGG 留作兜底，PNG 作封面。
- **时长以 ffprobe 为准**：IA 的 `length` 是秒的数字字符串，能直接用，但 flac 头里才有采样率/位深/声道；两者都记，冲突时以 ffprobe 为准并在日志里标注。
- **字段来源**：`composer` 取 `title` 首段并以目录前缀交叉校验；`work` 取目录名（如 `Beethoven_SymphonyNo.3Eroica`）；`movement` 取 `title` 末段；`path`/`cover` 存相对曲库根的路径。
- **数据源形态待定**（见 [02](02-站点形态与技术选型.md#2026-11-01-第二轮框架选择与数据库必要性)）：S 形态生成 `tracks.json`，J 形态同样生成 JSON 但不引入数据库，F 形态写 `works` / `tracks` 表；字段定义一致，差异只在落地形态。
- **离线优先**：`external-identifier` 的 AcoustID / MusicBrainz recording id 一并入库，不在生成期联网。
