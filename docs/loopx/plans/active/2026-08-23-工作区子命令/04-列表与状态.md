# 列表与状态

## 交付

`loopx workspace list` 输出配置视图（每个子仓的 name/url/path/branch 与本机 clone_path）；`loopx workspace status` 输出运行态视图（克隆是否存在，以及每个已注册 worktree 的路径、当前分支、dirty、能否 fast-forward 到基准分支、是否主 worktree）。

## 范围

- `list`：合并 `workspace.yaml` 与 `workspace.local.yaml` 的纯配置视图，不访问 git；`workspace.local.yaml` 中未知 name 的记录以孤儿项标出。
- `status`：对每个子仓执行只读 git 探测（克隆存在性、worktree 注册枚举、`rev-parse --abbrev-ref HEAD`、`status --porcelain`、与基准分支的 fast-forward 可行性）；主 worktree（配置 path 对应）单独标注。
- 二者均为 Query，无 `--dry-run`。
- 不做：人类可读表格渲染（遵守 JSON-only）。

## 直接依赖

- 03: 消费其物化布局契约（克隆存储路径解析、worktree 分支命名）；status 的运行态判读以 03 建立的产物为基准。

## 验收

- [ ] `list` 在配置合并、clone_path 缺失、`workspace.local.yaml` 含孤儿记录三种场景下输出正确
- [ ] `status` 覆盖：未物化、已物化且干净、dirty、可 fast-forward、不可快进（有本地提交）、存在多个已注册 worktree 六种运行态
- [ ] 两个命令均不产生任何写副作用
- [ ] `pnpm --filter @kxh4892636/loopx check` 与 `pnpm --filter @kxh4892636/loopx test` 通过
