# 子仓克隆存储使用浅克隆

`loopx workspace` 把子仓以 `git clone --depth 1 --branch <基准分支>` 保存到克隆存储（默认 `~/workspaces/<name>`），工作区目录只放 worktree。克隆存储是带工作树的普通浅克隆，可直接查看与手动操作；浅克隆将磁盘与网络成本压到单个基准分支的最新快照，代价是历史不可用、`git pull` 语义需要以 fetch + fast-forward 重建。worktree 一律从基准分支创建工作分支（默认 `worktree/<仓库名>-<yyyymmddhhmmss>`，可在 pull 时指定），避免同一基准分支被多个 worktree 占用。

**Considered Options**：bare 克隆（被拒绝——克隆自身无工作树，不便直接查看与手动操作）；完整克隆不限深度（被拒绝——多仓库场景下磁盘成本随历史线性增长，而工作区用法只需要基准分支头部）。

**Consequences**：需要完整历史时必须另行 unshallow 或全量克隆；克隆存储自身检出基准分支，不应在其中开发；fast-forward 之外的更新策略（rebase、merge）由用户在工作区的 worktree 中手动执行，CLI 不自动改写工作分支历史。
