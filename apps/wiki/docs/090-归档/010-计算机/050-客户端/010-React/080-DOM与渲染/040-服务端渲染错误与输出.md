# 服务端渲染错误与输出

## 流开始前后怎样处理失败与超时？

- 外壳范围: html、head、body、Suspense 外的布局与各边界 fallback;
- 作用: 构成首批可用页面;
- 外壳失败: 必要内容抛错时, Web 的 Promise 拒绝;
- Node: 调 `onShellError`;
- 可补救: 响应尚未发送, 能返回 500 后备页;
- 边界内失败: Suspense children 在服务端抛错时保留该边界的 fallback;
- 同时: 继续输出其他部分;
- 之后: 客户端重试真实内容;

## 客户端重试的结果如何落地？

- 重试结果: 客户端成功则替换 fallback;
- 仍失败: 交给最近的错误边界, Suspense 本身不是错误提示;
- 取消工作: Node 用 `abort`, Web 用 `AbortSignal`;
- 之后: 让客户端接手剩余边界;

```text
Header 抛错（边界外）     → 外壳失败，返回后备响应
PostList 抛错（边界内） → 保留 PostsSkeleton，客户端重试
PostsSkeleton 抛错         → 当前边界无法保护自己的 fallback，继续向外传播
```

## 什么时候需要等待全部内容或同步字符串？

- 完整输出: 爬虫或静态生成要全量内容时, Node 等 `onAllReady`, Web 等 `stream.allReady`;
- `renderToString`: 同步返回可水合 HTML;
- 但不等挂起数据, 而是立刻输出最近的 Suspense fallback;

## 什么时候需要等待全部内容或同？

- `renderToStaticMarkup`: 输出不用于 React 水合的静态 HTML;
- 适用: 邮件等场景;
- 注意: 它不同于可水合的静态预渲染;

## 如何继续先前推迟的渲染？

- 恢复输入: `resume` 或 `resumeToPipeableStream` 收同一应用树与 `prerender` 得到的 `postponed` 数据;
- 输出: 分别返回 Web 或 Node 流形态;
- 保持一致: 恢复过程要与先前的树和数据对应;

## postponed 与配置怎么协调？

- 注意: `postponed` 是不透明状态, 不要自行编辑;
- 配置协调: bootstrap、`identifierPrefix`、资源提示与错误回调;
- 要求: 与客户端入口及部署环境一致;
