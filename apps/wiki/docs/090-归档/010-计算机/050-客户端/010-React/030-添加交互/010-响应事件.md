# 响应事件

## 如何让交互触发事件处理器？

- 处理器: 传给 `onClick` 等事件 prop 的函数;
- 调用者: React 在事件发生时调用;
- 写法: `onClick={handleClick}`, 不要在渲染时调用它;

## 内联函数与语义元素怎么用？

- 内联函数: 要传参数时写 `onClick={() => save(id)}`;
- 效果: 箭头函数把 `save` 推迟到事件发生时执行;
- 语义元素: 可点击操作优先使用 button, 使键盘、焦点与无障碍行为符合预期;

```jsx
function SaveButton({ id, onSave }) {
  return <button onClick={() => onSave(id)}>保存</button>;
}
```

## 如何给业务组件设计事件接口？

- 业务命名: 自定义组件可收 `onPlayMovie` 这类表达意图的 prop;
- 内部: 再转接到原生事件;
- 数据读取: 处理器读本次渲染的 props 与 state;
- 快照含义: 见 state 快照笔记;
- 回调链: 子组件可以先处理本地操作, 再显式调用父回调; 这种方式能清楚展示执行顺序;

## 如何控制事件的向上传播？

- 冒泡: 多数 React 事件从目标向祖先传播, 子按钮和外层容器的点击处理器都可能执行;
- 阻止传播: 子处理器调用 `event.stopPropagation()`;
- 例外: `onScroll` 不冒泡;
- 捕获: `onClickCapture` 在目标处理与冒泡之前运行;
- 用途: 记录捕获阶段的事件, 它不等于阻止默认行为;

```jsx
function Toolbar() {
  return (
    <div onClick={() => console.log("工具栏")}>
      <button
        onClick={(event) => {
          event.stopPropagation();
          console.log("按钮");
        }}
      >
        执行
      </button>
    </div>
  );
}
```

## 如何阻止浏览器默认动作？

- 默认动作: 表单提交可能导航, 链接点击可能跳转;
- 接管: 调用 `event.preventDefault()`;
- 区别: 阻止默认动作不会自动阻止冒泡, 二者解决不同问题;
- 副作用位置: 处理器可以提交请求、修改状态或弹出提示, 不需要像渲染函数一样保持纯粹;

```jsx
function Form() {
  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        console.log("在这里执行提交逻辑");
      }}
    >
      <button>提交</button>
    </form>
  );
}
```
