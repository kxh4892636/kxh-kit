# ref 引用值

## ref 保存的是什么？

- 可变容器: `useRef(initialValue)` 返回带 `current` 字段的对象;
- 稳定性: 同一组件的后续渲染拿到同一个对象;
- 不触发渲染: 改 `current` 不会通知 React;
- 适用: 定时器 ID、DOM 节点等不直接决定 UI 的信息;
- 初始参数: 只用于初始化容器, 后续传入不同初始值不会自动替换 current;

## 怎样选择 state 或 ref？

| 需求             | 选择     | 原因               |
| ---------------- | -------- | ------------------ |
| 显示点击次数     | state    | 变化需要更新 UI    |
| 保存定时器 ID    | ref      | 只为以后清理使用   |
| 保存 DOM 节点    | ref      | 需要调用浏览器方法 |
| 渲染期间临时计算 | 局部变量 | 不需要跨渲染保存   |

## 如何在事件之间保存一个可变值？

- 读写位置: 在事件或 Effect 中读写 ref;
- 定位: 它是外部操作的句柄, 不要用来藏该进 state 的数据;
- 生命周期: ref 只随组件实例存活, 组件卸载后需要长期保留的数据应放到更稳定的位置;

```jsx
import { useRef } from "react";

function DelayedAlert() {
  const timeoutRef = useRef(null);
  function schedule() {
    clearTimeout(timeoutRef.current);
    timeoutRef.current = setTimeout(() => alert("完成"), 1000);
  }
  return <button onClick={schedule}>稍后提示</button>;
}
```

- 清理责任: 上例只演示事件间保存句柄;
- 卸载要取消的任务: 另由 Effect 清理, 完整生命周期见闭包与定时器;

```jsx
// 放在持有 timeoutRef 的组件顶层，并导入 useEffect。
useEffect(() => {
  return () => {
    clearTimeout(timeoutRef.current);
  };
}, []);
```

## 为什么渲染时通常不能读写 current？

- 纯度要求: ref 的变更不进入 React 的快照机制;
- 渲染中读写: 结果会依赖可变的时序, 重试时不一致;
- 初始化例外: 可预测, 且只在 `current` 为空时执行的一次性初始化可以用;

## ref 能替代 state 吗？

- 写法: 见 Context 与 Ref 参考;
- 不可替代: UI 要显示的值用 state;
- 反例: 不要靠强制重渲染补救用 ref 代替 state 的设计;
