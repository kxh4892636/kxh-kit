# 同步工具选择

## 为什么需要同步工具？

- 同步: 协调多个 goroutine 的执行顺序或共享数据访问;
- 目的: 避免读到一半状态或互相覆盖写入;
- 数据竞争: 定义与检测见[并发设计](../001-执行与设计/020-并发设计.md);
- 本篇范围: 只讲工具选择;
- 选择起点: 先判断目标是“保护共享状态”“等待任务完成”还是“只初始化一次”, 再选择工具;

## 如何根据问题选择工具？

| 工具             | 优先使用场景                                   |
| ---------------- | ---------------------------------------------- |
| `sync/atomic`    | 简单计数器、状态标记的原子读写                 |
| `sync.Mutex`     | 共享变量, map 或多项状态, 复合不变量的互斥访问 |
| `sync.RWMutex`   | 共享数据读多写少, 需要允许多个读取并发执行     |
| `sync.WaitGroup` | 等待多个并发任务结束                           |
| `sync.Once`      | 只执行一次的初始化                             |

- 并发计数: 用 atomic;
- 扣款与余额校验要整体成立: 用 Mutex;
- 批量请求收尾: 用 WaitGroup;
- 固定配置初始化: 用 Once;

```text
保护一份共享状态？  → 先考虑 Mutex
只是一个计数的增减？→ 可评估 atomic
只等所有任务结束？  → WaitGroup
初始化必须最多一次？→ Once
需要交接数据或事件？→ channel
```

## 选择时容易犯什么错误？

- atomic 误用: 多个字段要一起满足业务规则时, 分别原子读写保护不了整体不变量;
- 替代: 使用 Mutex;
- RWMutex 误用: 读多写少只是候选条件;
- 更简单: 临界区很短或竞争很低时用普通 Mutex;

## 这些工具能组合使用吗？

- WaitGroup 边界: 只等待任务完成, 不保护任务读写的共享数据;
- Once 适用范围: 失败重试与资源刷新都不适合;
- 执行与 panic 规则: 见[Once](./030-Once.md);
- channel: 适合传递数据所有权或表达事件顺序;
- 反例: 不是所有并发问题都要改成共享内存加锁;

- 组合边界: 等待与互斥是不同责任, 同一批任务可能两者都要;
- 前提: 加工具前先说明它保护什么状态、建立什么完成关系;
