# 编程系统产品的九倍成本

## 程序、编程产品、编程系统、编程系统产品有什么区别？

| 形态                                       | 定义                                                                                   | 成本      |
| ------------------------------------------ | -------------------------------------------------------------------------------------- | --------- |
| 程序 (Program)                             | 本身是完整的, 作者可在所开发的系统平台运行; 通常是车库产品; 单个程序员生产率的评估标准 | 基准      |
| 编程产品 (Programming Product)             | 可被任何人运行、测试、修复和扩展; 可运行在多种操作系统平台, 供多套数据使用             | 至少 3 倍 |
| 编程系统中的构件单元                       | 功能上能相互协作的程序集合中的一员; 规范格式, 可交互, 可组装和搭建整个系统             | 至少 3 倍 |
| 编程系统产品 (Programming Systems Product) | 同时沿两个方向升级后的形态                                                             | 高达 9 倍 |

- 图 1.1 结构: 水平边界以下是产品化（程序 → 编程产品）;
  - 垂直边界右边是系统化（程序 → 系统构件）, 右下角是编程系统产品;
- 定位: 只有编程系统产品才是真正有用的产品, 是大多数系统开发的目标;
- 用词提醒: 报纸上"两个程序员在车库里编出超过大型团队工作量的重要程序", 说的只是第一种形态;

## 程序要变成编程产品，必须补齐什么？

- 风格: 必须按照普遍认可的风格来编写;
- 输入扩展: 输入的范围和形式必须扩展, 以适用于所有可以合理使用的基本算法;
- 测试: 对程序进行彻底测试, 确保它的稳定性和可靠性, 使其值得信赖;
- 测试用例库: 必须准备、运行和记录详尽的用例, 检查输入的边界和范围;
- 文档: 要有完备的文档, 每个人都可以加以使用、修复和扩展;
- 成本数据: 相同功能的编程产品的成本, 至少是已经过测试的程序的三倍;

## 程序要变成系统构件，必须补齐什么？

- 接口: 必须按照一定的要求编制, 输入和输出在语法和语义上与精确定义的接口一致;
- 资源: 程序还要符合预先定义的资源限制——内存空间、输入输出设备、计算机时间;
- 组合测试: 必须同其它系统构件单元一道, 以任何能想象到的组合进行测试;
- 测试规模: 测试用例随组合不断增加, 所以测试的范围非常广;
- 意外交互: 意想不到的交互会产生许多不易察觉的 bug, 测试工作将会非常耗时;
- 成本数据: 相同功能的编程系统构件的成本至少是独立程序的三倍;
- 成本递增: 如果系统有大量的组成单元, 成本还会更高;

## 为什么"车库里的两个人"的神话会流行？

- 现象: 报纸常讲两个程序员如何在简陋车库中编出重要程序;
  - 程序的工作量甚至超过大型团队;
- 传播基础: 每个编程人员准备相信这样的神话;
- 自估生产率: 他知道自己能以超过产业化团队的 1000 代码行/年开发任何程序;
- 追问: 为什么不是所有的产业化队伍都会被专注的二人组合所替代? 必须看一下产出的是什么;
- 答案: 车库产出的是图 1.1 左上角的"程序";
  - 产业化团队要交付的是右下角的"编程系统产品";
- 差距: 两者之间隔着三倍与三倍的差距;

（source: 人月神话 · 第 1 章 焦油坑）
