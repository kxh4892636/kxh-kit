# 程序库与受控拷贝

## 程序库解决什么问题？

- 案例: OS/360 中最成功的辅助机器应用之一是维护程序库;
- 负责人: W. R. Crowley 带领开发;
- 结构: 连接两台 7010 机器, 共享一个很大的磁盘数据库;
- 附带能力: 7010 同时提供 System/360 汇编程序;
- 内容: 所有经过测试或者正在测试的代码都保存在库中;
- 包括: 源代码和汇编装载模块;
- 划分: 库实际上划分成不同访问规则下的子库;
- 版本管理: 7010 上的一个程序目录跟踪每个模块的每个版本;
- 记录: 包括它的状态、用途和变更;
- 评价: 这是 OS/360 工作中最优秀的成果之一;
- 性质: 它实际上是管理技术的一部分;
- 独立发展者: 很多大型项目都独立发展了这些技术;
- 例如: Bell 实验室、ICL、剑桥大学等;

## 三层子库各自的权限规则是什么？

| 子库         | 权限规则                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 开发库       | 每个组或编程人员分配一个区域, 存放自己的程序拷贝、测试用例和单元测试辅助例程与数据; 无任何限制, 开发人员是它们的拥有者（又名 playpen） |
| 系统集成子库 | 开发人员准备集成软件单元时向集成经理提交拷贝; 原作者不可再改变代码, 除非得到集成经理批准                                               |
| 当前版本子库 | 被广泛应用的版本提升到此; 该拷贝不可更改, 除非有重大缺陷; 可用于所有新模块的集成和测试                                                 |

- 集成经理职责: 系统合并在一起时, 集成经理开始进行所有系统测试工作;
- 工作内容: 识别和修补 bug;

## 受控拷贝的两个理念是什么？

- 理念一 受控: 程序的拷贝属于经理, 他可以独立地授权程序的变更;
- 理念二 正式化: 使发布的进展变得正式;
- 分离: 开发库 (playpen) 与集成、发布的正式分离;
- 适用范围: 同样适用于文档, 是一种不可缺少的技术;

（source: 人月神话 · 第 12 章 干将莫邪）
