# Kitex 服务端开发

Kitex 是 CloudWeGo 的 Go RPC 框架: IDL 生成桩、Client 与 Server 两端装配、内置服务治理。对外 HTTP 服务用 [Hertz](../020-Hertz/README.md)。

本目录只写「术」: 生成命令、选项名与默认值、协议常量、关闭语义、框架错误入口。原理与判断规则在 [000-服务端知识](../000-服务端知识/README.md)，需要时只留一句指向，不重复解释。

## 阅读顺序

1. [001-心智模型](./001-心智模型.md): 对象分工、开发五步;
2. [002-IDL与代码生成](./002-IDL与代码生成.md): IDL 形状、`kitex` flag、Protobuf 何时走 gRPC;
3. [003-服务端开发](./003-服务端开发.md): `NewServer`、Server 选项表、Handler 与 `kerrors`;
4. [004-客户端调用](./004-客户端调用.md): 复用 Client、默认超时、寻址写法、失败分类、Client 选项表;
5. [005-Option作用域与Suite](./005-Option作用域与Suite.md): 三层作用域、Suite 打包组织级默认值;
6. [006-协议与连接](./006-协议与连接.md): 消息类型、五个传输常量、连接池参数;
7. [007-StreamX流式](./007-StreamX流式.md): `-streamx` 门槛与三种流的关闭语义;
8. [008-扩展与排障](./008-扩展与排障.md): 扩展能力、注册与配置中心、`kitexcall`、错误入口、RPCInfo 冻结;
9. [009-超时重试与熔断限流](./009-超时重试与熔断限流.md): 超时默认值、重试、熔断、限流;
10. [010-发现与观测接入](./010-发现与观测接入.md): Registry、负载均衡算法、Tracer 与 logger 注入;
11. [011-运行与测试接入](./011-运行与测试接入.md): 退出接入、RPC 集成测试。

## 按需回查

- 默认值: 超时与退出的四个默认值（`ConnectTimeout` 50ms、`RPCTimeout` 0、`ReadWriteTimeout` 5s、`ExitWaitTime` 5s）在 009，Client 默认超时在 004;
- 选项表: Server 侧在 003，Client 侧在 004，两处不重复；作用域与 Suite 在 005;
- 治理装配（重试、熔断、限流）在 009，观测注入在 010，退出与 RPC 测试在 011;
- 超时预算、重试幂等、熔断三态、错误分层、分层依赖、退出顺序: 只查 000。

## 版本

- 示例按 Kitex tool `v0.16.3`、thriftgo `v0.4.5` 编写，本机与 CI 用同一组版本;
- 框架用法依据 CloudWeGo 官方文档; 示例只演示接入，不代表推荐的项目结构。
