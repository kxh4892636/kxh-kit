# 000-服务端知识

这里是「道」：换掉框架仍然成立的服务端知识。值得记住的是不变量、模型和判断规则；API 与代码模板会过时，原理不会。

三个框架目录是「术」：只回答「这个框架怎么接」，用时查，不用背。

## 怎么用

1. 先读本目录，建立模型：一次请求经过什么、哪些事情必须做对、做错了是什么症状；
2. 写代码时去对应框架目录查接入方式与 API；
3. 换框架时只重读各篇的「各框架接入」小节，其余不用重读。

## 维护约定

- 一个知识点只在本目录解释一次；框架目录只写「怎么接」，需要原理时链接回来；
- 每篇先写「记住什么」，再写「为什么」和「怎么做对」，最后才是框架代码；
- 新增框架时，只补「各框架接入」小节，不新开一篇原理。
