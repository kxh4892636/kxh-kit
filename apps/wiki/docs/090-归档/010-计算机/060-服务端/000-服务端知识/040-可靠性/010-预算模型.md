# 超时预算模型

## 超时为什么是预算而不是单个配置？

- 预算: 入口拿到 deadline, 向下逐层分配, 下游必须小于上游剩余;
- 超时不是越大越好: 过大会让故障请求长期占用连接与 goroutine;

```text
入口 deadline（如 2s）
  ├─ 排队/解析
  ├─ 业务处理 (响应/错误处理留 10–20% 余量;)
  ├─ 下游调用
  └─ 重试退避
```

## 超时预算设错会看到什么症状？

| 症状                     | 原因                               |
| ------------------------ | ---------------------------------- |
| 下游一直跑, 上游已返回   | 没有把 deadline 继续传下去         |
| 调大超时后故障更严重     | 超时掩盖了容量问题, 连接被长期占用 |
| 重试把预算吃光           | 只算了单次调用时间                 |
| 流式接口频繁断开         | 套用了短的写超时                   |
| 服务端读超时被当成业务慢 | 混淆了读写超时与 Handler 执行时间  |
