# 配置与启动顺序

## 配置的优先级顺序是什么？

- 优先级: 代码默认值 < 配置文件 < 环境变量 < 启动参数;
- 覆盖规则: 后者覆盖前者;

```text
# 同一份配置的三个来源，后者覆盖前者
config/default.yaml
ENV=production
./server --listen=:8080
```

- 配置在启动时冻结: 运行中不改路由、中间件和监听地址;
- 运行中改配置要热加载、锁与回滚机制, 成本远高于重启发布;

## 配置里的 Secret 从哪里注入？

- 只来自环境变量或 Secret Manager, 不进仓库、镜像、日志与错误响应;
- 密码、token、证书私钥用环境变量注入; 配置文件只放可提交项;
- `.env`: 只提交示例文件, 真实值进 `.gitignore`;
- 容器: 用 `--env-file` 或 Secret 挂载;
- 反例: 不要把 `.env` 打进镜像;

## 服务启动顺序是什么？

```text
读取配置 → 校验 → 初始化日志/追踪 → 连接数据库/缓存/注册中心（带超时 Ping）
→ 创建 Repository → Service → Handler → 启动 Server → readiness 通过
```

- 退出按相反顺序执行, 见 [优雅退出](../040-可靠性/050-退出顺序.md);
- 依赖连接失败要区分「重试可恢复」与「配置错误」: 前者有限次重试, 后者直接退出;
