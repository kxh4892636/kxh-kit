# 模型选型与编排模式

## 选择驱动 Agent 的模型时看哪些维度？

- 总原则: 模型是 Agent 的智能基座，选对模型往往比优化提示词更有效；不要只看排行榜，**要在自己的任务上做评估**（见第七章）;
- 闭源模型: OpenAI（GPT/o 系列）与 Anthropic（Claude 系列）最常用，能力通常领先，但成本较高且受厂商 API 策略限制;
- 开源模型: 与闭源差距在 6 个月以内，成本显著更低，可私有化部署、支持微调，适合成本敏感或有数据合规要求的场景；DeepSeek、Kimi、GLM 的 Agent 能力较强;
- 工具调用差异: 不同模型在工具调用方面差异很大，选型前务必在具体场景中测试;
- 策略边界: 基准测试具备某种能力，不代表产品允许调用——厂商对网络安全、模型蒸馏、模型提取、隐私数据和高风险操作设有不同边界；同一任务在聊天产品、Coding Agent 和 API 中也可能结果不同;
- 使用条件: 需确认模型是否愿意执行、接口是否暴露所需能力、服务条款是否允许；业务关键任务要准备人工接管或合规替代模型;
- 思考能力: 绝大多数 Agent 需要支持 Reasoning 的模型；仅单步简单任务或固定位置 GUI 点击等极少数场景例外;
- 速度与多模态: 输出 token 速度直接决定端到端延迟（20 轮推理每轮慢 2 秒就多等 40 秒）；需要理解图片、音频、视频时多模态是硬性要求;

## 工作流（Workflow）模式的机制与取舍是什么？

- 定义: 通过预定义代码路径编排 LLM 与工具，执行路径确定性，LLM 只在每个节点内部负责理解与生成;
- 优势一（流程控制）: 关键步骤不会被跳过或乱序——“付款前不能预订”这类业务规则由代码强制执行，不依赖 LLM 判断;
- 优势二（安全性）: 攻击面被限制在单个节点内，提示注入或模型犯错无法跳到不该执行的分支;
- 局限（缺乏变通）: 出现预设流程未覆盖的情况（付款环节想改签、航班取消需替代方案）时只能走异常分支或交还人类;
- 适配层: 专门给工具或模型的能力短板打补丁的 Harness 代码，如文生图工作流中的“提示词改写”节点（LLM 做的是翻译）;
- 消失条件: 换成具备原生图像生成能力的多模态模型后，提示词改写不再需要;

## 自主 Agent 模式适合什么场景？

- 定义: 执行路径不预先定义，由 Agent 根据**环境反馈**实时决定;
- 能力要求: 自主规划、识别失败、调整策略，而不是出错就停;
- 实现本质: 在循环中使用工具的 LLM——即 ReAct 循环;
- 停止条件: 必须显式设计——任务完成、达到最大迭代次数、遭遇不可恢复错误、调用最终输出工具、模型返回无工具调用的响应;
- 适用: 难以预测步骤数的开放式问题——SWE-bench 类 Coding Agent、Computer Use、迭代搜索与研究任务;
- 代价: 更高成本与复合错误风险；部署需沙盒测试、护栏与监控，并在关键决策点加入人机协作检查点;

## 两种模式如何选择与混合？

- 递进顺序: 先优化单个 LLM 调用 → 多步骤且可清晰分解时用工作流 → 需要动态决策时才用自主 Agent;
- 反面教材: 一开始就构建复杂工作流或多 Agent 系统——执行拓扑固定，遇到新例外只会继续加节点，架构越复杂而通用性越差，模型原本可做的语义判断被写死;
- 取舍原则: **Harness 很重要，不等于 Harness 越复杂越好**；Manus 的 “Less structure, more intelligence.”;
- 编程式分工: 程序只固化权限、不得覆盖原始材料、原子发布等必须始终成立的边界；其余决策空间还给模型;
- 升级条件: 只有业务约束本身要求，或评估反复暴露某类稳定失败时，才把步骤升级为专门验证器、独立 Agent 或确定性流程;
- 混合方式一: 同一系统中关键合规流程用工作流、灵活部分用自主模式（如 n8n 同时支持两类节点）;
- 混合方式二: **先由自主 Agent 把工作流写出来，再由工作流执行**——Agent 自行决定拓扑并生成编排代码，执行阶段退回确定性（第十章展开）;

## 主流 Agent 框架如何选型？

| 框架/平台             | 核心定位                  | 编排模式         | 开发方式                 | 适用场景                              |
| --------------------- | ------------------------- | ---------------- | ------------------------ | ------------------------------------- |
| Codex Harness         | Codex 的开源 Agent 运行时 | 自主             | 代码优先，可嵌入自有应用 | Coding Agent、把 Agent 嵌进产品       |
| Claude Agent SDK      | 生产级 Agent 开发框架     | 自主             | 代码优先                 | 复杂自主任务、Coding Agent            |
| LangChain / LangGraph | 通用 LLM 应用框架         | 工作流 + 自主    | 代码优先                 | 复杂链式思考、多步骤工作流            |
| n8n                   | 可视化工作流自动化        | 工作流 + 自主    | 低代码                   | 业务自动化、非技术团队                |
| Dify                  | LLM 应用开发平台          | 工作流 + 对话式  | 低代码                   | 企业级 RAG、知识库应用                |
| CrewAI                | 角色化多 Agent 编排       | Multi-Agent 协作 | 代码优先                 | 团队式任务分解与执行                  |
| OpenClaw              | 开源全能个人 Agent        | 自主 + 事件驱动  | 配置 + 代码              | 个人助理、Deep Research、Computer Use |
| DeepSeek Harness      | Agent 自进化框架          | 一切皆插件       | 代码优先                 | Agent 开发者、研究者                  |
| Pi                    | 极简 Coding Agent 框架    | 自主             | 代码优先                 | Agent 开发者                          |

- Codex Harness 的三条集成路径: `codex exec`（脚本与 CI 一次性任务）、Codex SDK（第三方应用启动、恢复、流式处理）、app-server（JSON-RPC，持久会话、事件流与审批回调）;
- 选型关键: 不在于框架本身复杂度，而在于能否用尽可能少的抽象层让你专注业务逻辑；框架迭代快，学会具体用法并不重要;
