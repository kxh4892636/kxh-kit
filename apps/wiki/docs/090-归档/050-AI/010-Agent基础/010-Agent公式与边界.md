# Agent 的核心公式

## 现代 Agent 的最小工程公式是什么？

- 公式: **Agent = LLM + 上下文 + 工具**;
- 加号: 表示工程组件的组合，不是强化学习中的形式化定义;
- 边界: 公式只描述 Agent 边界之内的实现，**不含 Agent 与之交互的 Environment（环境）**;
- 广义理解: 三个词都取广义但边界清楚——LLM 是决策内核，上下文是每个决策点保留的信息表示，工具是感知或改变外部世界的接口;
- 组件来源: LLM 的能力来自**预训练**（世界知识与语言能力）与**后训练**（固化的决策策略，见第八章）;

## 大脑、眼睛、手脚分别对应什么？

| 直觉理解 | 实现组件     | 学术概念       | 含义                                     |
| -------- | ------------ | -------------- | ---------------------------------------- |
| 大脑     | LLM          | 策略（Policy） | 面对当前信息，从可选行动中挑出下一步     |
| 眼睛     | 上下文构造   | 观察与历史     | 把环境观察与已有历史组织成决策所需信息   |
| 手脚     | 工具与适配器 | 观察/行动接口  | 规定可读取哪些观察、可发出哪些行动及格式 |

- 映射边界: 上下文是观察与历史在 Agent 内部的表示，不等于整个观察空间；工具定义接口，工具背后的对象仍属于环境;
- RL 闭环: 环境返回观察 → Agent 选择行动 → 行动改变环境 → 新状态产生下一次观察，循环继续;

## Agent 与 Environment 的边界在哪里？

- Environment 内容: 文件、数据库、网页、用户、其他 Agent，以及物理或仿真世界;
- 交互方式: Agent 只能通过观察通道与动作接口和它交互;
- 归属判断: 物理部署位置不决定概念归属——仿真环境即使与 Agent 同进程，仍是 Environment;
- Harness 侧: 工具定义、调用适配器、沙箱的权限与重置机制属于 Harness；沙箱内随行动变化的文件与进程属于 Environment;

## Agent = Model + Harness 是怎样展开的？

- Model: 负责策略决策，即公式中的 LLM;
- Harness: Agent 边界内**环绕模型的运行与治理层**，负责构造上下文、暴露工具接口、维护循环与状态，并实施权限、验证与纠正;
- 词源: Harness 原指马具——不是限制马的奔跑能力，而是把力量引导到正确方向;
- 展开式: `Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正`;
- 最小 Demo: 只需 Model 与能构造上下文、暴露工具的 Harness;
- 生产系统: 在同一边界内再加入约束、验证、纠正（退款 Agent 的例子：政策进上下文、权限与金额规则约束调用、数据库状态验证结果、超时重试回退）;
- 关系: `Agent = Model + Harness` 不是与核心公式并列的第二套骨架，而是“构建”部分在生产形态下的观察视角;
