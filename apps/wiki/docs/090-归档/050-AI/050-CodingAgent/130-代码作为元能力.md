# 代码作为元能力

## 什么是元能力？

- 普通能力: Agent 能做某件具体的事——回答问题、调用某个 API、生成一段文字;
- 元能力: 一种“能创造其他能力”的能力——用它当场写出新工具、新约束、新表达形式来完成任务，而不必事先把所有能力预制好;
- 候选者: 代码生成正是这样的元能力，因为它精确、可执行、可组合;
- 产出形态一: 新工具——脚本、API 调用序列;
- 产出形态二: 新约束——断言、校验规则;
- 产出形态三: 新表达形态——HTML 表单、PPT、视频帧;

## 代码对 Agent 的两个层面价值是什么？

- 思考层面: 形式化代码让思考高度严谨——“年龄大于 18 且已实名认证”用自然语言有多种理解，写成代码就毫无歧义;
- 表达层面: 一段能跑通的代码本身就是逻辑自洽的证明，执行结果提供客观的对错标准;

## 六个应用方向如何组织？

| 由内向外 | 方向       | 代码替代或产出的对象               |
| -------- | ---------- | ---------------------------------- |
| 1        | 思维本身   | 用代码替代易错的自然语言推理       |
| 2        | 业务规则   | 把模糊政策编码为可执行约束         |
| 3        | 内容呈现   | 生成 PPT、视频与可视化产物         |
| 4        | 系统接口   | 桥接异构 API，自动适应数据格式演化 |
| 5        | 用户界面   | 动态构造表单与交互界面             |
| 6        | Agent 自身 | 用代码创造或修复新 Agent，形成自举 |

- 组织逻辑: 按“元能力作用对象”由内向外排列，而非六个平行方向;

## 这套能力对通用 Agent 架构意味着什么？

- 结论: 代码不只是完成任务的手段，也是积累知识、创造工具、优化自身的机制;
- 承接: 前几类元能力加上上下文、知识与工具，共同构成通用 Agent 的基础架构;
