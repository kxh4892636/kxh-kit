# 对等协作模式

## 对等协作模式是什么？

- 定义: 通常涉及 2-3 个平等身份的 Agent，通过多轮迭代互相提供反馈;
- 潜在价值: 引入独立视角与认知多样性;
- 前提警告: "多个实例"不等于"多种思路"——模型、上下文与脚手架高度相似时，不同 Agent 往往做出相同选择，使局部错误演变为系统性故障;
- 获得多样性的条件: 主动区分模型、上下文、工具、可见证据或职责，并让各 Agent 先独立判断、再汇总结果;
- 实现成本: 相比管理者与去中心化模式更低——只要定义好两个 Agent 的角色、通信机制与迭代终止条件就能跑起来;

## 对等协作有哪些经典形态？

| 形态          | 结构                                 | 适用场景                                        |
| ------------- | ------------------------------------ | ----------------------------------------------- |
| 提议者—审核者 | 产出方与评判方分离，评判基于独立证据 | 代码、PPT、视频、日志可视化、安全审查、内容审核 |
| 辩论模式      | 多个 Agent 各持立场对抗性对话        | 方案评估、正反两面论证                          |
| 头脑风暴模式  | 多个 Agent 独立生成创意再相互启发    | 产品创新、开放解空间                            |
| 专家小组模式  | 各代表一个专业视角，互补而非对抗     | 跨学科可行性评估                                |

## 辩论模式的效果为什么仍有争议？

- 设计意图: 单一 Agent 分析时模型往往倾向某个观点而忽视反面证据；辩论通过制度化对抗确保正反两面都得到论证;
- 反证: 2026 年 Tran 与 Kiela 在多跳推理任务上对比单 Agent 与五种多 Agent 架构（顺序、辩论、集成、并行角色、子任务并行）;
- 结论: 当思考 token 预算被严格控制为相同时，单 Agent 表现与多 Agent 持平甚至更好;
- 理论解释: 数据处理不等式——辩论中的多个 Agent 处理完全相同的文本信息，串行传递中间结论只可能丢失信息、不可能凭空创造信息;
- 归因: 辩论模式在部分论文中的收益很可能来源于消耗了更多的总计算量;
- 该结论不否定的做法: 对同一问题多次独立采样再聚合（自一致性、多数投票），以及利用生成与验证的难度不对称做生成—验证分工;

## 头脑风暴模式与专家小组模式分别解决什么？

- 头脑风暴: 多个 Agent 独立生成创意后相互分享、彼此启发，不同"思维偏好"（由不同提示词或模型实现）用来探索更广阔的解空间，找到单一 Agent 难以想到的创意组合;
- 头脑风暴实例: Agent 1 提出"增加社交分享功能"，Agent 2 受启发提出"生成个性化分享海报"，Agent 3 综合前两者提出"用户自定义海报模板并形成模板市场";
- 专家小组: 多个 Agent 各代表一个专业领域视角共同讨论跨学科问题，彼此是互补关系，共同拼出问题全貌并识别跨领域约束与机会;
- 专家小组实例: 工程师 Agent 分析技术实现难度，产品 Agent 评估市场吸引力，运营 Agent 分析成本与资源可行性;
- 共同前提: 两类模式的有效性同样受"是否引入新信息"约束，见 [多 Agent 协作的价值与边界](./010-多Agent协作的价值与边界.md);
