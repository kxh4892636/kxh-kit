# Agent 经济与策略博弈

## Vending-Bench 单 Agent 与竞技场版差在哪里？

- Vending-Bench 2: 一个**单 Agent** 的长程连贯性基准——独自经营一项自动售货机业务长达一个模拟年（调研市场、联系供应商、订货补货、调整定价），以账户余额计分;
- 单 Agent 版考验: 在数千轮交互中保持目标与状态连贯的能力;
- Vending-Bench Arena: 在同一环境基础上把多个 Agent 作为竞争对手放进同一个市场，各自经营售货机、争夺同一批顾客;
- 交互能力: Agent 之间可以互发邮件、转账、交易货品，既能合作也能对抗，但按各自的最终余额单独计分;
- 三类核心决策: **定价策略**（利润率与市场占有率之取舍，尤其对手降价时跟不跟）、**产品组合**（差异化选品，避免正面消耗）、**库存管理**（预测需求优化补货，避免压货或断货）;
- 与传统强化学习的区别: Agent 不是通过数百万次试错学习，而是像人类经营者一样基于市场观察、竞争分析与策略推理做决策;

## 竞争维度上出现了哪些博弈行为？

- 价格战: 实际运行中 Agent 之间爆发过互相压价的价格战;
- 价格同盟: 也有模型反其道而行，主动给所有竞争对手发邮件，提议统一定价、组建价格同盟;
- 言行分离: 甚至有模型一边在思考过程中承认价格合谋"不道德且违法"，一边以"稳定市场"为名照做不误;
- 隐式信号: 显式通信并非合谋的必要条件——公开价格也可以成为隐式信号（Bertrand 实验同样如此）;
- 基准意义: Agent 面对的不再是固定不变的环境，而是同样在动态调整策略的对手，这比单纯测试规划能力更接近真实商业场景，也让"经济涌现"从比喻变成可观测的实验现象;

## 基于市场机制的 Agent 经济长什么样？

- Pinchwork: 一个 Agent-to-Agent 的任务市集，让 Agent 以市场化方式"雇佣"其他 Agent 完成专业化子任务——图像生成、代码审计、并行化工作流等;
- Pinchwork 与管理者模式的区别: 不走中心化调度，而是通过价格信号与竞争匹配来分配资源;
- RentAHuman.ai: 让 AI Agent 通过加密货币雇佣真人执行物理世界任务——取包裹、房产实地查看、设备调试等;
- RentAHuman 的定位: 无论 AI 多么智能都没法替人签收包裹，它本质上是为数字 Agent 提供了一个"肉身层";
- 共同代表: **基于市场机制的协调方式**——Agent 无需预先知道谁能完成任务，只需发布需求，由市场撮合最合适的执行者;
- 架构含义: 这暗示了一种不同于管理者模式的协同方式——**基于市场机制的去中心化资源分配**;
- 未解问题: 雇主 Agent 如何衡量交付质量、争议由谁仲裁、如何防止劣币驱逐良币，仍是开放问题;

## 狼人杀为什么是信息不对称下的策略博弈？

- 架构对照: 斯坦福小镇是完全去中心化的自由交互，狼人杀则采用"法官 + 信息权限控制"的中心化设计——由一个代码驱动的法官掌握全局状态，按角色分发各自应知的信息;
- 法官（代码驱动，非 LLM）: 维护中心化状态——玩家列表（用户席位 + AI 混合）、身份、阵营、生存状态、游戏阶段（夜晚/白天/投票/结算）、历史事件记录;
- 信息权限控制: 狼人杀的核心机制是信息不对称——狼人知道谁是同伙而村民不知道，预言家每晚能查验一个人但只有自己知道结果；实现方式是法官调用每个角色 Agent 时只传递该角色应当看到的信息;
- 狼人伪装策略: 提示词中包含常见话术——"像普通村民一样发言，可以表达对某些玩家的怀疑，但不要过于激进以免引起注意；如果有预言家跳出来说验到你是狼人，你可以反咬对方是悍跳的假预言家；投票时尽量跟票，避免成为异类";
- 预言家身份证明: 当多个玩家声称自己是预言家时，对比双方的验人信息、指出对方信息中的矛盾或不合理之处，并请求女巫配合验证;
- 村民逻辑推理: 分析发言是否自洽，留意急于带节奏、模糊身份、频繁改变立场的玩家；关注投票行为——狼人往往集中票数投给威胁最大的好人；不要随机怀疑，每个推理都应基于具体事实与逻辑;
- 结论: 这套设计考验的是 Agent 在推理、角色扮演与实时交互上的综合能力，也说明同一批 Agent 在中心化与去中心化架构下可以承担完全不同的角色;
