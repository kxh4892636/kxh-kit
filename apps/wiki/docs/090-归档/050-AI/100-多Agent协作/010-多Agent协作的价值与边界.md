# 多 Agent 协作的价值与边界

## 为什么需要多个 Agent 而不是一个更强的 Agent？

- 单 Agent 上限: 受限于自身模型的能力边界与上下文窗口，与训练得多好无关;
- 突破口: 让多个 Agent 通过分工、通信与相互验证承担单个 Agent 难以承担的任务;
- 价值层次: 不只是让不同专长的 Agent "取长补短"，更是让**群体的智能高于个体**;
- 类比: 单个人智力有限，但经由分工、协作、辩论与知识的代际累积，人类社会整体智能远超任何个体;
- 推论: 每个 Agent 都只相当于人类专家水平时，组织得当的整体也可能超过所有人类专家的总和;

## OpenAI 五级能力框架把多 Agent 放在哪里？

| 级别    | 名称                  | 含义                    |
| ------- | --------------------- | ----------------------- |
| Level 1 | 对话者                | 能进行自然语言对话      |
| Level 2 | 思考者（Reasoners）   | 能推理                  |
| Level 3 | 智能体                | 能自主执行任务          |
| Level 4 | 创新者                | 能产生新知识            |
| Level 5 | 组织（Organizations） | AI 能完成整个组织的工作 |

- 多 Agent 协作常被类比为通向 Level 5 的路径之一;
- 关键澄清: `Organizations` 指能力级别而非架构要求，足够强大的单个 Agent 理论上也能达到;
- 现实约束: 今天的工程现实中，单 Agent 仍受模型能力与上下文窗口限制;

## 集体智能为什么可能是通往超级智能的路径？

- 依据: Google DeepMind《From AGI to ASI》把"大规模多 Agent 集体"列为从通用人工智能通往超级智能（ASI）的关键路径之一（arXiv:2606.12683）;
- 机制: 人类的通用智能能聚合成超越个体的社会与组织实体，众多 AGI 级 Agent 协同形成的群体智能也可能超过成员简单相加;
- 定位: 多 Agent 协作因此既是突破上下文窗口与能力边界的工程手段，也是从"专家级 AI"迈向"超越人类整体"的可能路径;

## 什么判据决定多 Agent 是否真正优于单 Agent？

- 唯一判据: **协作过程是否引入了单个 Agent 在生成时无法获得的新信息**;
- 无新信息: 多 Agent 通常无效甚至有害，只是"让模型再想一遍";
- 有新信息: 显著提升，因为反馈在生成时刻并不存在于上下文中;

表10-1 多 Agent 协作模式的信息增量对比

| 协作模式                               | 是否引入新信息 | 效果                        |
| -------------------------------------- | -------------- | --------------------------- |
| 同一模型自我审查（重新阅读自己的输出） | 否             | 通常无效甚至有害            |
| 不同 Agent 辩论同一段文本              | 否             | 在等计算量下与单 Agent 持平 |
| 审核者使用测试执行结果审查代码         | 是（执行反馈） | 显著提升                    |
| 审核者查看渲染截图审查前端/PPT 代码    | 是（视觉反馈） | 显著提升                    |
| 审核者使用外部工具验证事实             | 是（工具反馈） | 显著提升                    |

- 执行反馈证据: RLEF（Reinforcement Learning from Execution Feedback，arXiv:2410.02089）用真实编译错误、测试失败、运行时异常做强化学习，效果远超让模型独立多次采样;
- 视觉反馈证据: WebGen-Agent（arXiv:2509.22644）用"截图 + 视觉语言模型描述"的多层级反馈脚手架，把 Claude 3.5 Sonnet 在网页生成基准上的表现从 26.4% 提升到 51.9%;
- 规模化证据: 45 个 Agent 经共享论坛协调搜索、互相审查、独立 Agent 仲裁，用 2700 万 token 找到 266 个漏洞；独立 Agent 并行方案用 650 万 token 只找到 21 个;
- 机制解释: 开放搜索空间里，通信让群体动态转移搜索重点、形成专门分工，用更高 token 预算换取更广覆盖与更多样的发现路径;

## 为什么学术研究与工程实践对多 Agent 的结论相反？

- 学术研究的对象: 多为"多个 Agent 看着同一段上下文互相讨论"，此类设置不引入新信息，因此在等计算量下不优于单 Agent;
- 工程实践的对象: 有效的多 Agent 系统往往包含外部反馈环路——代码执行、视觉渲染、工具调用;
- 结论: 两边并无真正矛盾，差别只在是否引入新信息;

## 多 Agent 的收益必须覆盖什么代价？

- 成本项: 并行探索与反复迭代都要消耗大量 token，额外开销可达数倍乃至一个数量级;
- 决策规则: 多 Agent 的收益必须足够大才能覆盖这笔开销，否则调校得当的单 Agent 更划算;
- 前提核查: 先确认存在可引入的外部反馈，再确认收益能覆盖成本，最后才选择协作拓扑;
