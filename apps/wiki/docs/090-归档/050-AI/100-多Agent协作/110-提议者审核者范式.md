# 提议者—审核者范式

## 提议者—审核者范式是什么？

- 结构: Proposer Agent 负责生成产物，Reviewer Agent 渲染或执行结果、评估质量并给出结构化改进建议，两者反复迭代直到效果达标;
- 范式定义与第一章的应用清单见 [设计模式](../010-Agent基础/090-设计模式.md);
- 适用场景: PPT 生成、视频编辑、日志可视化、安全审查（提议者生成操作方案，审核者检查合规性与风险）、内容审核（起草回复 vs 检查业务规则与用语规范）、代码审核（写代码 vs 检查安全性与最佳实践）;

## 为什么不能让一个 Agent 自己生成再自己审查？

- 判据: 审查若不引入新信息，就只是"让模型再想一遍";
- 实证一: Huang 等在 ICLR 2024《Large Language Models Cannot Self-Correct Reasoning Yet》中发现，让 GPT-4 在没有外部反馈的情况下审查并修正自己的回答，准确率反而下降——把正确答案改错的次数多于把错误答案改对的次数;
- 实证二: 2024 年 TACL 综述《When Can LLMs Actually Correct Their Own Mistakes?》（arXiv:2406.01297）确认，除非提供可靠外部反馈（测试用例执行结果、外部工具验证输出），纯靠模型自身的"自我纠正"几乎不起作用;
- 实证三: ICLR 2024 的 CRITIC 让模型用外部工具（搜索引擎、Python 解释器）验证自己的回答时效果显著提升，一旦移除工具验证、只保留自我评估，大部分提升消失;
- 机制: 审核者的价值不在于"用同一个模型再看一遍"，而在于它执行了提议者生成时无法获得的信号——渲染截图承载视觉信息，执行测试产生通过/失败结果;

## 提议者—审核者循环的最小不变量是什么？

- 不变量一: 审核者读取**独立证据**，而不是只复述提议者的解释;
- 不变量二: 退回时必须给出可定位的修复条件;
- 不变量三: 审核者不能修改测试、证据采集器或发布门槛，否则"独立验证"会退化成自我批准;
- 参考实现:

```python
candidate = proposer(task, constraints)
evidence = execute_or_render(candidate)       # tests, state, screenshot, facts
review = independent_reviewer(candidate, evidence)

while review.veto and budget_remaining:
    candidate = proposer.repair(candidate, review.findings)
    evidence = execute_or_render(candidate)
    review = independent_reviewer(candidate, evidence)

if review.pass:
    publish(candidate, evidence, review)
else:
    escalate_or_reject(review)
```

## 三 Agent 生产架构给出了什么证据？

- 结构: Anthropic 2026 年长程应用开发实验实现为规划者–生成者–评估者三 Agent;
- 流程: 规划者把用户需求展开为产品规格；生成者与评估者先约定每轮完成标准，再由生成者实现，然后评估者用 Playwright 操作真实应用并提交缺陷报告;
- 通信: Agent 之间通过文件交接状态;
- 结论: 当任务超出当前模型单独可靠完成的范围时，带外部证据的独立审核可以用显著更高的成本换取更好的开发质量;
- 与 Loop 的关系: 验证器之所以成为循环瓶颈、以及"模型不能批准自己的完成"，见 [Loop 工程与过早终止](./100-Loop工程与过早终止.md);
