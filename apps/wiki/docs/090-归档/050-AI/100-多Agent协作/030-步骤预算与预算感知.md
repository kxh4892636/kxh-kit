# 步骤预算与预算感知

## 更多步骤预算为什么不会自动带来更好的表现？

- 直觉: 30 步预算只能快速实现核心功能；300 步预算还可以先规划、再实现、再测试、再改进;
- 反直觉结论: Google 2025 年论文《Budget-Aware Tool-Use Enables Effective Agent Scaling》发现，单纯增加可用步骤数并不能保证性能提升;
- 机制: 标准 Agent 缺乏"预算意识"，即使有 300 步预算仍倾向执行浅层搜索，很快"饱和";
- 结论: 要让更多步骤转化为更好的结果，Agent 需要**显式的预算感知机制**，根据剩余资源动态调整策略;

## 预算感知机制应该怎么设计？

- 阶段切换原理: 前期广泛探索，后期聚焦最有希望的方向;
- BAVT（Budget-Aware Value Tree Search，2026）: 提出步骤级别的价值评估，在每一步按剩余预算比例调整探索与利用的权重;
- 切换规律: 随着预算减少，Agent 从"广撒网"逐渐切换到"深挖掘";

## 预算管理如何指导多 Agent 系统设计？

- Manager 的职责: 不应只是分发任务后等待结果，而应根据任务复杂度**动态分配步骤预算**——简单子任务给较少步骤，复杂子任务给充足步骤;
- 子 Agent 的引导: 还要引导子 Agent 合理利用预算（先规划、再实现、再测试、再改进），而不是一头扎进去直接开干;
- 与资源调度的关系: 具体的预算上限、并发额度与抢占在 [终止级联与资源调度](./080-终止级联与资源调度.md) 中展开;
- 成本含义: 预算最终以 token 计价，因此预算分配同时是成本控制手段，见 [多 Agent 协作的价值与边界](./010-多Agent协作的价值与边界.md);
