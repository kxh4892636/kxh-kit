# 成品软件包与元编程

## 微型计算机革命为什么让数百万人获得创造力？

- 最惊人新事物: 作者交谈过的计算机带头人都感到惊讶;
- 指微型计算机革命与薄膜包装软件产业;
- 这是《人月神话》之后 20 年中最重要的改变;
- Schumacher 20 年前的挑战: 设备价格低廉、适合小型应用、满足创造渴望;
- 实现: 微型计算机革命把这三点带给计算机产业与用户(含普通公众);
- 一般人买得起计算机, 也负担得起 20 年前国王薪水才买得起的软件;
- 逐领域: 普通人和专家都能用新的自我表达方法;
- 每目标达成度值得品评, 尤其"满足创造渴望"这一条;
- 文书处理曾经僵化: 合并更改要重新打字, 成本和时间高昂;
- 300 页手稿常每 3 到 6 个月重输一遍, 同时还在产生新稿;
- 逻辑流程与语句韵律的修订也很难;
- 现在文书处理已方便流畅;
- 相似领域: 绘画、计划、机械制图、音乐创作、摄影、摄像、幻灯、多媒体、电子表格;
- 这些手工操作原本要重拷大量未改部分;
- 可立刻修订和评估结果, 不丢思维连贯性, 如同分时之于软件开发;
- 写作工具: 拼写检查、语法检查、风格顾问、目录生成、最终排版预览;
- 量变引起质变: 工作刚成形时, 介质灵活性便于探索彻底不同的方案;
- 时间变化引起工作方式的巨大变化;
- 绘图工具让建筑设计人员每小时的投资展现更多选择;
- 计算机与合成器互联加自动演奏软件更易捕获灵感;
- 数字相机与 Adobe Photoshop 把暗室数日工作压到几分钟;
- 电子表格可对大量 what-if 情况做实验与比较;
- Vannevar Bush 1945 年提出超文本, 只能在计算机实现;
- 多媒体表现形式和体验更是如此;
- 尚不便宜和普遍的虚拟环境系统将成为另一创造性媒介;

## 20 年后开发软件的方式被如何改变？

- 70 年代软件过程被微处理器革命和科技进步改变;
- 很多次要困难被消除;
- 个人计算机成为常规工具, 周转时间概念几乎成为历史;
- 如今个人计算机比 1960 年超级计算机快, 也比 1985 年 Unix 工作站快;
  - 使在最差计算机上编译也快;
- 大内存消除了基于磁盘链接的等待时间;
- 符号表与目标代码可留内存, 高级调试无需重新编译;
- 1975 年分时刚替换批处理成为最常用技术;
- 网络让构建人员访问共享文件与强大编译、链接、测试引擎;
- 个人工作站提供计算引擎, 网络共享团队工作产品;
- 客户-服务器系统简化测试用例检入、开发与应用的共享访问;
- WIMP 界面比一般文本更方便迅捷地编辑程序文本;
- 24 行、72 列屏幕被整页甚至双页屏幕取代;
- 程序员能看到所作更改的更多上下文;

## 成品软件包产业的经济学与传统产业有何不同？

- 传统软件产业旁爆发全新产业, 产品以成千上万甚至数百万规模销售;
- 整套丰富的软件包价格可少于开发成本;
- 两个产业很多方面不同, 但共同存在;

| 传统软件组成部分 | 内容                                                   |
| ---------------- | ------------------------------------------------------ |
| 计算机提供商     | 操作系统、编译器和实用程序                             |
| 应用程序用户     | 公共事业、银行、保险、政府机构等自研应用包             |
| 定制程序开发者   | 为用户承包开发私用软件包; 需求、标准、行销步骤与众不同 |
| 商业包开发者     | 为专业市场开发大型应用, 如统计分析与 CAD 系统          |

- 分裂信号: Tom DeMarco 注意到传统软件产业分裂, 尤其应用程序用户;
- Ada 是最后一个通用语言, 已慢慢变成专业语言;
- 第 4 代语言在日常商业应用中贡献巨大;
- Boehm: 成功的第 4 代语言是把某应用领域系统化的选项与参数;
- 常见形态: 带查询语言、数据库-通讯软件包的应用生成程序;
- 1975 年每个硬件提供商每条产品线至少有一种操作系统, 很多有两个;
- 如今开放系统是基本原则;
- 主要在 5 大环境上行销应用程序包(按时间顺序);
- 5 大环境: IBM MVS、VM、DEC VMS、Unix 某版本、IBM PC、Apple Macintosh;
- IBM PC 上跑 DOS、OS-2 或 Windows;
- 软件成本是开发成本与数量的比值, 包装和市场成本很高;

| 维度                 | 传统内部应用开发 | 竞争激烈的成品软件市场       |
| -------------------- | ---------------- | ---------------------------- |
| 进度与功能           | 可以协商         | 支配了开发成本               |
| 开发成本             | 可能不可协商     | 由市场与数量决定（笔记补充） |
| 成功指标（笔记补充） | 交付满意         | 结果与销量                   |

- 传统产业被大型公司以指定管理风格和企业文化支配;
- 成品软件产业始于数百家创业公司, 行事自由, 更关注结果而不是流程;
- 天才的个人程序员更容易获得认可;
- 隐含观点: 卓越的设计来自杰出的设计人员;
- 创业文化能按贡献奖励杰出人员;
- 传统产业的公司社会化因素与薪资管理计划使这难以实施;
- 很多新一代明星人物被吸引到薄膜包装的软件产业;

## 元编程是什么、为什么它能提升概念级别？

- 总纲: 彻底提高健壮性和生产率的唯一途径是提升一个级别, 用模块或对象组合开发程序;
- 趋势: 把大众市场软件包当平台, 开发更丰富和更专业化的产品;
- 例: 用塑料包装的数据库和通讯软件包开发货运跟踪或学生信息系统;
- 杂志征文常见 Hypercard Stack、Excel 模板;
  - 有 Minicard 的特殊 Pascal 函数、AutoCad 的 AutoLisp 函数;
- 定义: 元编程(metaprogramming)=为部分用户定制软件包功能的过程;
- 不新: 60 年代早期很多计算机提供商与信息管理系统(MIS)厂商已有专家小组;
- 他们用汇编语言的宏来装备应用编程语言;
- Eastman Kodak 的 MIS 开发车间用 IBM 7080 宏汇编定义自有应用语言;
- IBM OS/360 的 QTAM 中, 遇到机器级别指令前可读若干页汇编通讯程序;
- 现在元编程人员提供要素的规模是宏的若干倍;
- C++ 类开发的高效市场还在期待, 可重用元程序市场已悄然崛起;
- 成品软件包提供大型功能模块和精心定制接口, 内部概念结构无需再设计;
- Excel 或 4th Dimension 这类功能强大的产品就是大模块;
- 作为广为人知、文档化、测试过的模块, 可用来搭建用户化系统;
- 下一级应用开发者可获得丰富功能、更短开发时间、测试过的组件、良好文档和彻底降低的成本;
- 障碍: 包开发现象没有影响一般 MIS 编程人员, 所以对软件工程领域不明显;
- 作者认为它将快速发展, 因为它针对概念结构要素打造的根本问题;
- 成品软件是作为独立实体设计的, 元程序员无法改变它的功能和接口;
- 更严肃: 把产品变成更大型系统中的模块, 对开发者没什么吸引力;
- 作者认为这种感觉错误, 为元程序员开发软件包有未开拓的市场;

## 成品软件需要什么样的接口和用户分层？

- 四层用户: 让同一份成品软件服务于不同深度的利用方式;

| 层次 | 用户           | 用法                                                                                                                                       |
| ---- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | 直接使用用户   | 以简便直接的方式操作, 对设计者提供的功能和接口感到满意                                                                                     |
| 2    | 元程序员(定制) | 在单个应用程序基础上使用已提供的接口开发模板或函数, 主要为最终用户节省工作量                                                               |
| 3    | 外部功能作者   | 向应用程序添加自行编制的功能, 本质上是新的应用语言原语, 调用通用语言编写的独立模块; 往往需要命令中断、回调或重载函数技术向原接口添加新功能 |
| 4    | 元程序员(构件) | 使用一个和多个特殊应用程序作为更大型系统的构件; 这是需求未得到满足的用户群, 也是能在构建新应用方面获得较大收获的用法                       |

- 第四类用户还需额外的文档化接口: 元编程接口(metaprogramming interface, MPI);
- 元程序需在整个软件集控制之下, 而每个软件通常假设受自己控制;
- 软件集必须控制用户界面, 而应用程序一般认为这是自己的职责;
- 软件整体要能调用任何应用程序的功能, 就像用户用命令行传参那样;
- 软件集应像屏幕一样接受应用程序的输出;
- 屏幕只显示字符串, 它需把输出解析成适当数据类型的逻辑单元实体;
- 现状: 某些应用(如 FoxPro)提供接收命令的后门接口(wormhole);
  - 返回信息不够充分且未被解析;
- 这类接口只是通用解决方案所需的特殊补充;
- 脚本语言能控制应用程序集合之间的交互, 很有力;
- Unix 首先用管道和标准 ASCII 字符串格式提供这种功能;
- 今天 AppleScript 是优秀例子;
- 相关: WIMP 界面与概念一致性;
- 见 [图形界面的概念完整性](./../030-概念完整性/050-图形界面的概念完整性.md);
