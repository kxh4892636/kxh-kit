## 这本书讲了什么？

- 主题: 大型软件项目为什么难, 以及管理与技术上的应对办法;
- 素材: 作者 1964-1965 年主持 IBM OS/360 开发的失败经验, 加上对其他大型项目的访谈;
- 结构: 1975 年原著 15 章提出观点, 二十周年纪念版新增第 16-19 章做回顾和修正;

## 为什么读这本书要注意版本？

- 不一致: 新增章节会推翻或修正原著的部分结论, 例如"瀑布模型是错误的""信息隐藏, Parnas 是正确的, 我是错误的";
- 阅读方式: 笔记中把原著观点与作者 20 年后的修正分别标出, 避免把已被作者本人否定的结论当成结论;
- 时效: 生产率数据、工具和语言的结论有时代烙印, 引用时需核对当前实践;

## 如何阅读这组笔记？

- 篇幅: 普通笔记最多 144 行, 平均约 55 行;
- 顺序: 010 讲"为什么难", 020-040 讲"怎么组织", 050-090 讲"怎么做", 100 讲"靠谁做";
- 来源: 每篇笔记对应原著章节, 见下方覆盖表和各分组 README 的章节对照表;
