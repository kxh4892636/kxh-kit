# 焦油坑：编程的乐趣与苦恼

## 为什么大型软件项目像焦油坑？

- 焦油坑: 史前恐龙、猛犸象、剑齿虎陷进焦油;
- 过程: 越挣扎焦油纠缠越紧, 任何猛兽都无法挣脱, 最后沉到坑底;
- 比喻对象: 大型系统开发;
- 表面现象: 没有单个问题会造成困难, 每个问题都能被解决;
- 真实难处: 问题相互纠缠、累积, 团队行动越来越慢;
- 结果: 大多数项目开发出可运行的系统;
- 结果数据: 只有极少数同时满足目标、时间进度和预算;
- 认知困境: 每个人似乎都惊讶于麻烦程度, 很难看清问题本质;
- 教训: 想解决问题, 必须先理解问题;
- 理解层面: 先认识软件开发这个职业的乐趣与苦恼;

## 编程为什么有趣？

- 创建的快乐: 创建事物的纯粹快乐, 如同小孩玩泥巴;
- 比喻: 是"上帝创造世界"的折射;
- 有用的快乐: 开发对他人有用的东西, 期望他人使用并受益;
  - 如同小孩为"爸爸办公室"捏铅笔盒;
- 魔术般的力量: 把相互啮合的零部件组装起来, 看它们精妙运行并得到预期结果;
- 魅力对照: 程序化的计算机不逊于弹珠游戏或点唱机;
- 学习的乐趣: 问题具有非重复特性, 总能学到新东西;
- 学习范围: 实践上、理论上或兼而有之;
- 易驾驭的介质: 程序员像诗人, 几乎仅仅工作在单纯的思考中;
- 表现: 可以凭空建造自己的"城堡";
- 评价: 很少有这么灵活、易于精炼和重建的介质;
- 与诗歌的差别: 程序是实实在在的东西, 可以移动和运行;
- 可见输出: 打印结果、绘制图形、发出声音、移动支架;
- 该特性也是问题: 原文只写"容易驾驭的特性也有它自己的问题";
- 引申: 易驾驭也意味着可以轻易地不断堆砌功能;
- 展开见 [概念完整性](../030-概念完整性/010-概念完整性.md);

## 编程有哪些固有的苦恼？

| 苦恼                 | 内容                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------- |
| 必须追求完美         | 咒语中一个字符、一个停顿与正确形式不一致, 魔术就不出现; 人类很少活动要求完美          |
| 调整难度             | 最难的是把做事方式调整过来                                                            |
| 目标与资源由他人设定 | 编程人员很少能控制工作环境和工作目标; 责任与个人权威不相配                            |
| 实际权威             | 实际（相对于正式）权威来自每次任务的完成                                              |
| 依赖他人的产出       | 所依赖的程序常设计不合理、实现拙劣、发布不完整或文档很糟                              |
| 发布不完整           | 无源代码或测试用例, 只得自行研究和修改                                                |
| 找 bug 单调          | 概念性设计有趣, 寻找琐碎 bug 只是重复性活动; 创造性活动常伴随枯燥沉闷的时间和艰苦劳动 |
| 调试收敛慢           | 调试和查错往往线性收敛, 或者更糟——二次方复杂度                                        |
| 测试拖延             | 测试一拖再拖, 寻找最后一个错误比第一个花费更多时间                                    |
| 产品完成即过时       | 产品即将完成或终于完成时已显得陈旧                                                    |
| 竞争压力             | 同事和竞争对手已在追逐新的、更好的构思, 替代方案可能不仅在构思, 而且已在安排          |

- 事先了解的意义: 只有事先了解编程固有的烦恼, 出现时才能更加坦然地面对;

## 产品过时的现实为什么没有想象中糟？

- 替代品通常尚未可用: 产品完成时, 更优秀的新产品通常还不能投入使用, 只是被大家谈论;
- 仍需开发: 新替代品同样需要数月开发;
- 需求节奏: 只有实际需要时才会用到最新的设想;
- 原因: 所实现的系统已经能满足要求, 体现了回报;
- 判断基准: 应根据其它已有的系统判断, 而不是根据未实现的概念;
- 任务定义: 在现有时间和有效资源范围内, 寻找解决实际问题的切实可行方案;

## 本书的立场是什么？

- 编程: 一个许多人痛苦挣扎的焦油坑;
- 另一面: 也是一种乐趣和苦恼共存的创造性活动;
- 对许多人而言, 其中的乐趣远大于苦恼;
- 本书剩余部分试图搭建一些桥梁, 为通过这样的焦油坑提供指导;

（source: 人月神话 · 第 1 章 焦油坑）
