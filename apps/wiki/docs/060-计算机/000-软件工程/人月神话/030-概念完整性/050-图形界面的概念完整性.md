# 图形界面的概念完整性

## 什么是 WIMP 界面？

- 缩写含义: 窗口（Windows）、图标（Icons）、菜单（Menus）、指针选取（Pointing）;
- 提出与传播: 1968 年由斯坦福研究机构的 Doug Englebart 公开提出; 被 Xerox PARC 采纳用于 Bob Taylor 团队开发的 Alto 工作站; Steve Jobs 用于 Apple Lisa（太慢）和 Macintosh（商业成功）; 之后被 IBM PC 及兼容机的 Microsoft Windows 采用;
- 为什么单列: 作者认为它是过去 20 年软件开发领域最令人印象深刻的进步, 也是"通过类比获得概念完整性"的最佳范例;

## 为什么说 WIMP 体现了概念完整性？

- 获得方式: 采用大家非常熟悉的概念模型--对桌面的比喻, 以及一致、细致的扩展;
- 扩展来源: 充分发挥计算机图形化实现的能力;
- 具体映射:

| 界面元素                       | 桌面类比                     |
| ------------------------------ | ---------------------------- |
| 窗口采用覆盖而非排列           | 直接来自类比（尽管成本很高） |
| 窗口可调整尺寸                 | 图形介质提供的一致概念延伸   |
| 拖放                           | 直接出自对用手拾起东西的模仿 |
| 图标和嵌套文件夹               | 桌面的文档                   |
| 回收站                         | 桌面的废纸篓                 |
| 剪切、复制、粘贴               | 使用文档的习惯               |
| 向回收站拖拽磁盘图标来弹出磁盘 | 象征手法贴切, 扩展连贯一致   |

## 桌面比喻在哪些地方被超越了？

- 真正的桌面上: 人们实际是操作文档, 而不是叫某人来完成动作; 要求他人活动时, 常新产生口头或书面祈使句;
- 技术限制: 现有处理能力无法对自由产生的命令形式进行可靠的翻译和解释;
- 设计者的聪明做法: 从桌面文档操作中选取一些常用命令, 形成类似"便条"的强制命令菜单, 用户只需从语义标准的菜单中选取;
- 延伸: 这个概念接着被延伸到水平菜单和垂直的下拉子菜单中;
- 两个超越点: 菜单, 以及单手操作;

## 双光标问题是什么？

- 命令结构: 命令是祈使句, 通常有一个动词和一个直接宾语; 任何动作都必须指定一个动词和一个名词;
- 理想方案: 用屏幕上两个不同的光标同时指定两件事物, 每个光标分别由左右手的鼠标控制;
- 现实基础: 在真实桌面上我们通常用两只手操作, 而且我们习惯用双手打字、驾驶、烹饪;
- 商业现实: 提供一个鼠标已是个人计算机制造商向前迈进的一大步, 没有任何商业系统可以容纳由双手分别控制两只鼠标同时进行的动作;
- 接受的折中: 为一只鼠标设计, 句法习惯是先指出（选择）名词, 再从菜单中选动词;
- 代价: 光标必须在数据区和菜单区之间来回移动, 每次都丢弃"上次在这个空间的什么地方"的位置信息, 是一个低效的过程;

## 一个卓越的解决方案是什么？

- 观察: 即使软件和器材可以很容易实现两个同时活动的光标, 仍存在空间布局困难--WIMP 的桌面包含打字机, 必须容纳物理键盘; 键盘加两个鼠标垫会占据大量双手所及空间;
- 反转思路: 键盘问题实际上是一个机会--一只手在键盘上指定动词, 另一只手用鼠标指定名词;
- 收益: 光标停留在数据区, 为后续点击拾取提供充分的空间活动能力;
- 评价: 真正的高效, 真正强大的用户功能;

## WIMP 如何在新手和熟练用户之间过渡？

- 最困难问题: 软件结构师面临的最困难问题是如何确切地平衡用户功能和易用性--为初学者/偶尔使用者设计简单操作, 还是为专业用户设计强大功能;
- 理想答案: 通过概念一致的方式把两者都提供给用户, 这正是 WIMP 界面达到的目标;
- 机制: 每个频繁使用的菜单动词都有快捷键, 可作为组合通过左手一次性输入;
- 实例: Mac 上命令键正好在 Z 和 X 键下方, 因此最频繁的操作被编码成 `⌘z`、`⌘x`、`⌘c`、`⌘v`、`⌘s`;
- 平滑过渡: 快捷键显示在菜单动词旁边, 拿不准的用户可以激活下拉菜单检查对应的快捷键; 新手大量使用菜单, 熟练用户几乎不用, 中间用户偶尔访问;
- 安全网: `⌘z` 可以撤消任何单一操作, 所以新手可以尝试任何感到不确定的快捷键;

## Mac 如何强制界面一致性？

- 做法: 设计人员在所有应用程序中使用标准界面, 包括大量第三方程序;
- 效果: 用户在界面上获得的概念一致性不局限在机器配备的软件, 而是遍及所有应用程序;
- 关键手段: 把界面固化到只读内存（ROM）中, 从而开发者使用这些界面比开发自己的特殊界面更容易、更快速;
- 配套: Apple 的管理投入和大量说服工作; 产品杂志中独立评论家通过批评不遵从产品的反面例子进行补充;
- 理论定位: 这是第 6 章推荐技术的杰出例子--通过鼓励其他人直接把某人的代码合并到自己的产品中来获得一致性, 而不是试图根据技术说明各自开发;

## WIMP 的未来如何？

- 作者预测: 尽管 WIMP 有很多优点, 仍期望它在下一代技术中成为历史;
- 保留与替换: 指针选取仍将是表达名词的方式, 语音则无疑成为表达动词的方法;
- 当时证据: Mac 上的 Voice Navigator 和 PC 上的 Dragon 已提供这种能力;
