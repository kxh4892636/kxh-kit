# 图形界面的概念完整性

## 20 年中最令人印象深刻的界面进步是什么？

- WIMP: 窗口 (Windows)、图标 (Icons)、菜单 (Menus)、指针选取 (Pointing);
- 地位: 是 20 年内软件开发领域最令人印象深刻的进步;
- 普及: 到 1995 年已熟悉到无需解释;
- 提出: 1968 年西部联合计算机大会 (Western Joint Computer Conference);
- 提出者: 斯坦福研究机构 (Stanford Research Institute);
  - Doug Englebart, 首次公开提出;
- 采纳: Xerox Palo Alto Research Center;
  - 用于 Bob Taylor 及其团队开发的 Alto 个人工作站;
- 商业化: Steve Jobs 用在 Apple Lisa 上;
- 缺陷: 但 Lisa 运行太慢, 承载不了这个令人激动的易用性概念;
- 1985 年: Jobs 在取得商业成功的 Apple Macintosh 上体现了这些想法;
- 扩散: 之后被 IBM PC 及其兼容机的 Microsoft Windows 采用;
- 作者: 自己用的是 Mac 版本;
- 结论: WIMP 是概念完整性的范例;
- 机制: 采用大家熟悉的概念模型(桌面比喻);
  - 并做一致、细致的扩展, 充分发挥计算机的图形化实现能力;
- 基础概念见 [概念完整性](./010-概念完整性.md);

## 桌面比喻如何换来概念完整性？

| 界面元素         | 与桌面比喻的关系                                                                   |
| ---------------- | ---------------------------------------------------------------------------------- |
| 窗口覆盖而非排列 | 直接来自对桌面的类比; 尽管实现成本很高, 却是正确的决定                             |
| 窗口尺寸可调整   | 图形介质提供的一致概念延伸, 给用户新的处理能力; 桌面上的文件无法轻易调整大小和形状 |
| 拖放             | 直接出自模仿; 用指针选择图标是对人用手拾起东西的直接模拟                           |
| 图标与嵌套文件夹 | 源于桌面的文档                                                                     |
| 回收站           | 同样源于桌面的文档; 甚至可以把磁盘图标拖进回收站来弹出磁盘                         |
| 剪切、复制、粘贴 | 完全反映我们使用文档的习惯                                                         |

- 效果: 象征手法贴切、扩展连贯一致, 新用户常会被它体现出的理念打动;

## WIMP 在哪些地方超越了桌面的比喻？

- 超越集中在两点: 菜单与单手操作;
- 现实桌面: 在真正的桌面上人们直接操作文档, 而不是叫某人来完成动作;
  - 要求他人活动时通常新产生一个口语或书面祈使句;
- 例: "请将这个归档""请找出前面一致的地方""请把这个交给 Mary 去处理";
- 限制: 现有处理能力还无法对自由产生的命令形式进行可靠的翻译和解释;
- 解法: 从用户对文档的直接动作中去掉"请某人做"和"自由造句"两步;
  - 从桌面文档操作中选取常用命令, 做成类似公文的"便条";
  - 用户只需从语义标准的强制命令菜单中选择;
- 延伸: 该概念再延伸到水平菜单与垂直下拉子菜单;
- 代价: 菜单化了命令, 就放弃了自由造句的表达力;
- 换来: 可学习性与可发现性（笔记引申）;
- 论据 (022[55]): 买件商品带回家, 紧记购买目的, 按菜单上的不同动词略为试验即可开始使用;
- 论据续: 不必查看手册;

## 双光标为什么会成为一个未兑现的机会？

- 语言学观察: 命令是祈使句, 通常有动词和直接宾语;
- 推论: 任何动作都必须指定一个动词和一个名词;
- 直接模仿: 用屏幕上两个不同的光标同时指定两件事物;
  - 每个光标分别由左右手各一只鼠标控制;
- 依据: 现实中人们常用两只手操作, 一只手常只是固定东西;
  - 这一点在计算机桌面是默认的; 我们本来就会用双手打字、驾驶、烹饪;
- 商业现实: 提供一个鼠标已是个人计算机制造商向前迈进的一大步;
  - 没有任何商业系统能容纳双手分别控制两只鼠标同时动作;
- 现实句法: 界面设计人员为一只鼠标设计;
  - 采用"先指出(选择)名词, 再指出动词菜单项"的习惯;
- 代价: 这牺牲了很多易用性;
- 观察: 作者观察用户、用户录像或光标移动跟踪时;
  - 立刻惊讶于一个光标必须完成两件事;
- 两件事: 在桌面区选择对象, 再到菜单区选择动词;
- 损耗: 光标从数据区到菜单区周而复始地往返;
  - 每次都丢弃"上次在什么位置"的有用空间信息;
- 评价: 整体是低效过程;
- 更好方案: 既然键盘必须占据双手所及的空间;
  - 就让一只手在键盘上指定动词, 另一只手用鼠标指定名词;
- 效果: 光标留在数据区, 为后续点击拾取保留充分的空间活动能力;
  - 真正高效、真正强大的用户功能, 但未被商业系统采纳（笔记引申）;

## 如何在用户功能与易用性之间取得平衡？

- 最困难的问题: 软件结构师要平衡"为初学者或偶尔使用的用户设计简单操作"与"为专业用户设计强大功能";
- WIMP 的答案: 通过概念一致的方式把两者都提供给用户;
- 快捷键: 每个频繁使用的菜单动词都有快捷键, 可由左手一次性输入;
- Mac: 命令键正好在 Z 和 X 键下方;
- 编码: 最频繁操作被编码成 ⌘z、⌘x、⌘c、⌘v、⌘s;
- 过渡: 快捷键字符显示在菜单动词旁边;
  - 拿不准的用户可拉下菜单核对, 而不是直接选取;
  - 新手从最常用命令学起;
  - ⌘z 可撤消任何单一操作, 使新手敢于尝试不确定的快捷键;
  - 也可检查菜单确认命令是否有效;
- 分布: 新手大量使用菜单, 熟练用户几乎不用;
  - 中间用户偶尔访问菜单;
  - 每个人都了解自己大多数操作所对应的少数快捷键;
- 观察: 大多数开发设计人员对这样的界面熟悉;
  - 对其优雅而强大的功能感到欣慰;

## 概念完整性如何跨应用扩散？

- 事实: Mac 界面的设计人员没有任何强迫, 就让所有应用程序使用标准界面;
- 范围: 含大量第三方程序; 概念一致性不局限于机器自带软件, 而是遍及所有应用;
- 机制: 把界面固化到只读内存 (ROM) 中;
- 效果: 使开发者使用标准界面比开发自己的特殊界面更容易、更快速;
- 配套: 广泛采用后形成实际标准;
  - Apple 的管理投入与大量说服工作协助了这些措施;
  - 产品杂志的独立评论家认识到跨应用概念完整性的价值, 通过批评不遵从的反面例子加以补充;
- 原理: 这是原著第 6 章推荐技术的杰出例子;
- 做法: 鼓励其他人直接把某人的代码合并进自己的产品来获得一致性;
- 对比: 而不是照着技术说明自行开发;
- 见 [贯彻体系结构决策](./040-贯彻体系结构决策.md);

## WIMP 的命运是什么？

- 预期: 尽管 WIMP 有很多优点, 它仍会在下一代技术中成为历史;
- 分工预测: 指针选取仍将是表达名词的方式, 如同我们支配机器一样;
  - 语音则无疑成为表达动词的方法;
- 早期证据: Mac 上的 Voice Navigator 与 PC 上的 Dragon 已提供这种能力;

（source: 人月神话 · 20年后的人月神话）
