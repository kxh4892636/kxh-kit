# 批量写入

## 一次写多少行合适？

| 做法                  | 何时用              | 代价                                  |
| --------------------- | ------------------- | ------------------------------------- |
| 一个 `.values([...])` | 几十~几千行、列一致 | 单条 SQL 过长会被 SQLite 参数上限挡住 |
| 事务里分批 insert     | 上万行导入          | 代码多一些，吞吐更稳                  |
| 批量 upsert           | 数据可能已存在      | 需要唯一索引支撑                      |

- SQLite 单语句参数上限是 32766（`MAX_VARIABLE_NUMBER`），列多时每批行数要相应减小;
- 超限时报错文本是 `too many SQL variables`，不是「行数太多」。

## 怎样分批写入？

```ts
const chunkSize = 500;

await db.transaction().execute(async (trx) => {
  for (let i = 0; i < rows.length; i += chunkSize) {
    await trx
      .insertInto("person")
      .values(rows.slice(i, i + chunkSize))
      .execute();
  }
});
```

- 批大小按「列数 × 行数 < 3 万」估算;
- 整批放进一个事务，省掉每批的提交开销，失败还能整体回滚;
- 事务语义见 [事务与保存点](../040-事务与迁移/010-事务.md)。

## 批量 upsert 怎么写？

```ts
await db
  .insertInto("stock")
  .values(rows)
  .onConflict((oc) => oc.column("sku").doUpdateSet((eb) => ({ qty: eb.ref("excluded.qty") })))
  .execute();
```

- 冲突目标必须覆盖唯一索引，规则见 [冲突处理](./040-冲突处理.md);
- 想「累加」而不是「覆盖」，把值改成 `eb('stock.qty', '+', eb.ref('excluded.qty'))`。

## 大批量写入为什么慢？

| 原因                       | 缓解                    |
| -------------------------- | ----------------------- |
| 每条语句一次事务提交       | 包进 `db.transaction()` |
| 默认日志模式，写时阻塞读   | `journal_mode = WAL`    |
| 缺索引导致逐行扫描唯一约束 | 补齐唯一索引            |
| 一次性构造几十万行对象     | 边读边写，流式分批      |

- 并发与运维参数见 [SQLite 并发与运维](../060-速查/040-SQLite并发与运维.md)。

## 写完怎么核对结果？

- `executeTakeFirst()` 只看第一条结果，批量插入要看 `numInsertedOrUpdatedRows`;
- 核对总数用 `countAll()`，别在应用里累加返回值;

```ts
const result = await db.insertInto("person").values(rows).executeTakeFirst();
console.log(result.numInsertedOrUpdatedRows); // bigint
```
