# 可复用条件函数

## 怎样把一整段条件封成函数？

- 用 `expressionBuilder<DB>()`（不绑定表）建条件，表相关的东西从参数传进来;
- 别在 helper 里写死表名：调用方可能没有那张表，编译能过但运行报错;

```ts
import { expressionBuilder, type Expression } from "kysely";

function hasDogNamed(name: Expression<string>, ownerId: Expression<number>) {
  const eb = expressionBuilder<DB>();
  return eb.exists(
    eb
      .selectFrom("pet")
      .select("pet.id")
      .where("pet.owner_id", "=", ownerId)
      .where("pet.species", "=", "dog")
      .where("pet.name", "=", name),
  );
}

const persons = await db
  .selectFrom("person")
  .selectAll()
  .where((eb) => hasDogNamed(eb.val("Doggo"), eb.ref("person.id")))
  .execute();
```

## 为什么不能依赖调用方的表上下文？

- `expressionBuilder<DB, 'person'>()` 让 helper 里能直接写 `person.id`，但只有「刚好在查 person」时成立;

```ts
// ❌ 编译能过，运行时 SQL 里没有 person 表
const bad = db.selectFrom("movie").selectAll().where(hasDogNamedFixed("Doggo"));
```

- 正确做法：需要的列全部作为 `Expression` 参数传入;
- 只有确认「这个 helper 永远只用于某张表」时，才可以绑定表上下文。

## 什么时候该写成子查询、什么时候写成布尔表达式？

| 形式                           | 返回                  | 用在                                    |
| ------------------------------ | --------------------- | --------------------------------------- |
| 布尔表达式（`eb.exists(...)`） | `Expression<SqlBool>` | `where`、`having`、`on`                 |
| 子查询                         | `SelectQueryBuilder`  | `where in (...)`、`select(...)`、`join` |

- 只是「有没有」时用 `exists`，通常比 `in` 更快短路，见 [子查询与CTE](./090-子查询与CTE.md);
- 需要返回标量时 `$asScalar()`，见 [修正查询结果类型](../050-进阶/060-修正查询结果类型.md)。

## 怎样让条件函数支持可空列？

- 入参声明成 `Expression<T | null>`，内部用 `coalesce` 或 `is null` 兜底;
- 与 `NotNull` 的组合见 [修正查询结果类型](../050-进阶/060-修正查询结果类型.md)。

## 什么时候不该抽函数？

- 只用一次的条件留在原地更好读;
- 参数超过 3 个、或内部判断业务分支时，说明它在隐藏复杂度，不是复用;
- 单个表达式的复用见 [可复用表达式函数](./050-可复用表达式函数.md)。
