# 过滤条件

## `where` 支持哪些操作符？

- 只接受固定清单里的操作符，写错会在**编译期**报 `invalid operator`;
- 清单来自 Kysely 的类型定义，各方言通用；数据库不支持的运算符则由运行时报错;

| 类别       | 操作符                                                      |
| ---------- | ----------------------------------------------------------- |
| 比较       | `=`、`==`、`!=`、`<>`、`>`、`>=`、`<`、`<=`                 |
| 集合       | `in`、`not in`                                              |
| 空值与布尔 | `is`、`is not`                                              |
| 模式       | `like`、`not like`、`ilike`、`not ilike`、`regexp`、`match` |
| 区间       | **没有** `between`，用 `eb.between()`                       |

```ts
const rows = await db
  .selectFrom("person")
  .selectAll()
  .where("first_name", "like", "%a%")
  .where("last_name", "is not", null)
  .where("id", "in", [1, 2, 3])
  .where((eb) => eb.between("age", 18, 60))
  .execute();
```

## 多个条件、或、非怎么组合？

- 链式多个 `where` 之间是 `and`;
- 需要 `or`、`not`、`exists` 时，用回调拿到表达式构造器;

```ts
const rows = await db
  .selectFrom("person")
  .selectAll("person")
  .where(({ eb, or, and, not, exists, selectFrom }) =>
    and([
      or([eb("first_name", "=", "Jennifer"), eb("age", "<", 60)]),
      not(exists(selectFrom("pet").select("pet.id").whereRef("pet.owner_id", "=", "person.id"))),
    ]),
  )
  .execute();
```

## 对象写法有什么用？

- `eb.and({ 列: 值 })` 适合「一堆等值条件」，键就是列名;
- 值可以是普通值，也可以是表达式（`eb.ref('first_name')` 表示与另一列比较）;

```ts
const rows = await db
  .selectFrom("person")
  .selectAll()
  .where((eb) => eb.and({ first_name: "Jennifer", last_name: eb.ref("first_name") }))
  .execute();
```

## `where` 与 `having`、`on` 有什么区别？

| 方法     | 作用对象        | 执行时机    |
| -------- | --------------- | ----------- |
| `where`  | 行              | 分组/聚合前 |
| `having` | 分组结果        | 聚合后      |
| `on`     | join 的匹配条件 | 连接时      |

- 三者都接受同样的操作符与表达式，组合方式也一致;
- 聚合场景见 [聚合与分组](./100-聚合与分组.md)，join 见 [连接查询](./070-连接查询.md)。

## 条件能按需拼接吗？

- 能，但要看方法是否改变结果类型：`where` 可以 `if` 后重新赋值，`select` 必须用 `$if`;
- 写法见 [列比较与动态条件](./030-列比较与动态条件.md) 与 [语句顺序与条件构建](../010-快速上手/080-语句顺序与条件构建.md)。
