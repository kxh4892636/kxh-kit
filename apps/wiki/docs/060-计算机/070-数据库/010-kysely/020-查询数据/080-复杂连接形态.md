# 复杂连接形态

## 自连接和表别名要注意什么？

- 同一张表出现两次必须起别名，否则列引用有歧义;
- 别名写在 `selectFrom` / `join` 的表名里，之后全程用别名;
- 下例假设 `person` 表里有 `mother_id` 指向 `person.id`;

```ts
const rows = await db
  .selectFrom("person")
  .innerJoin("person as mother", "mother.id", "person.mother_id")
  .select(["person.first_name", "mother.first_name as mother_name"])
  .execute();
```

## 能把子查询当表连吗？

- 能。`innerJoin` 第一个参数可以是返回子查询的回调，`as` 之后当普通表用;

```ts
const rows = await db
  .selectFrom("person")
  .innerJoin(
    (eb) =>
      eb
        .selectFrom("pet")
        .select(["owner_id as owner", "name"])
        .where("name", "=", "Doggo")
        .as("doggos"),
    (join) => join.onRef("doggos.owner", "=", "person.id"),
  )
  .selectAll("doggos")
  .execute();
```

- 子查询里必须把 join 用的列 `as` 成稳定名字，否则外侧无法引用;
- 子查询当表时，SQLite 可能会把它物化，数据量大时注意执行计划。

## 什么时候用 CTE 代替子查询？

| 需求                 | 建议                                 |
| -------------------- | ------------------------------------ |
| 一次性派生表         | 子查询当表                           |
| 同一段结果被多处引用 | CTE（`with`）                        |
| 递归结构             | CTE（`with recursive` 需手写 `sql`） |

- CTE 写法见 [子查询与CTE](./090-子查询与CTE.md)。

## 多表连接怎么避免写乱？

- 一个查询里超过 3 张表时，先写 `selectFrom` + 主 join，再逐条 `where` 收窄;
- 生成的 SQL 用 `.compile()` 检查，确认没有笛卡尔积（缺 `on` 条件）;
- 基础 join 语法见 [连接查询](./070-连接查询.md)。
