# 修正查询结果类型

## 明明不为空，类型却是 `| null` 怎么办？

- `$narrowType<{ 列: NotNull }>()`：告诉 Kysely 结果里这列不为空，不改 SQL;
- 适合「已用 `where ... is not null` 过滤」或「业务保证一定存在」的场景;

```ts
import { type NotNull } from "kysely";

const rows = await db
  .selectFrom("person")
  .select(["id", "last_name"])
  .where("last_name", "is not", null)
  .$narrowType<{ last_name: NotNull }>()
  .execute();
```

## 报 `TS2589` 类型过深怎么办？

- 成因：查询链太长（`with` 十几个、嵌套子查询多），类型推导超出 TS 能力;
- 用 `$assertType<目标类型>()` 就地掐断推导链，**不降低类型安全**——目标类型必须与真实结果结构一致;

```ts
const res = await db
  .with("w1", (qb) => qb.selectFrom("person").select("first_name as fn1"))
  // ... 省略若干 with ...
  .with("w12", (qb) =>
    qb.selectFrom("person").select("first_name as fn12").$assertType<{ fn12: string }>(),
  )
  .selectFrom("w1")
  .selectAll()
  .execute();
```

- `type Simplify<T> = { [K in keyof T]: T[K] } & {}` 只让悬停好看，解决不了 TS2589。

## 子查询当标量用为什么类型不符？

- 子查询是 `Expression<{ name: string }>`，而函数参数要 `Expression<string>`;
- 加 `.$asScalar()` 做类型层转换（不改 SQL），需要非空时再 `.$notNull()`;

```ts
upper(
  eb
    .selectFrom("pet")
    .select("name")
    .whereRef("person.id", "=", "pet.owner_id")
    .limit(1)
    .$asScalar()
    .$notNull(),
).as("pet_name");
```

## `$notNull()` 和 `$narrowType` 有什么区别？

| 手段                   | 作用位置                            | 适用                   |
| ---------------------- | ----------------------------------- | ---------------------- |
| `$notNull()`           | 单个表达式（`sql` / helper 返回值） | 表达式本身可空         |
| `$narrowType<{...}>()` | 整条查询的结果类型                  | 列级收窄，可一次改多列 |
| `$assertType<{...}>()` | 整条查询的结果类型                  | 掐断过深推导           |

- 三者都不改生成的 SQL，只是让类型贴近事实;
- 子查询选择出来的列（`select(...).as('x')`）用 `$narrowType`，`$notNull` 在这些位置不可用。

## 类型的边界在哪里？

- Kysely 只做编译期检查，运行时类型由驱动决定，见 [SQLite 类型与运行时差异](../060-速查/020-SQLite类型与运行时差异.md);
- 表结构与类型不一致时先修类型来源，见 [生成数据库类型](./050-生成数据库类型.md);
- 表名/列名要到运行时才知道时，见 [动态表名与结果类型](./070-动态表名与结果类型.md)。
