# 嵌套关联查询

## Kysely 有「关系」吗？

- 没有。Kysely 只是查询构建器，不做懒加载、不做级联装配;
- 想要 `person.pets` 这种嵌套结构，得用 SQL 的 JSON 聚合能力自己拼出来。

## SQLite 上怎么一次查出主子表？

- 用官方 helper：`jsonArrayFrom`（数组）、`jsonObjectFrom`（对象），从 `kysely/helpers/sqlite` 引入;
- 必须同时装 `ParseJSONResultsPlugin`，否则拿到的是 JSON 字符串;

```ts
import { jsonArrayFrom, jsonObjectFrom } from "kysely/helpers/sqlite";

const rows = await db
  .selectFrom("person")
  .selectAll("person")
  .select((eb) => [
    jsonArrayFrom(
      eb
        .selectFrom("pet")
        .select(["pet.id", "pet.name"])
        .whereRef("pet.owner_id", "=", "person.id")
        .orderBy("pet.name"),
    ).as("pets"),

    jsonObjectFrom(
      eb
        .selectFrom("pet")
        .select(["pet.id", "pet.name"])
        .whereRef("pet.owner_id", "=", "person.id")
        .where("pet.species", "=", "dog")
        .limit(1),
    ).as("favorite_pet"),
  ])
  .execute();

console.log(rows[0].pets[0].name); // 类型: { id: number; name: string }[]
console.log(rows[0].favorite_pet?.name); // 类型: { id: number; name: string } | null
```

## 结果为什么带 null / 可选？

- Kysely 无法知道关联行是否一定存在，所以对象是 `| null`，数组元素类型仍按行给;
- 业务上确定存在时，用 `.$notNull()` 或 `$narrowType` 去掉 null;

```ts
jsonObjectFrom(
  eb.selectFrom("pet").select(["pet.id"]).whereRef("pet.owner_id", "=", "person.id").limit(1),
)
  .$notNull()
  .as("first_pet")

  // 或者对整行收窄
  .$narrowType<{ first_pet: NotNull }>();
```

## helper 的生成原理是什么？

- 生成的是相关子查询 + JSON 聚合，整体仍是一条 SQL;

```sql
select "person".*,
  (select coalesce(json_group_array(json_object('id', "agg"."id", 'name', "agg"."name")), '[]')
   from (select "pet"."id", "pet"."name" from "pet"
         where "pet"."owner_id" = "person"."id" order by "pet"."name") as agg) as "pets"
from "person"
```

- 所以必须写 `whereRef` 关联外表，写成 `where` 会变成常量条件;
- 不同方言 helper 不同：SQLite 用 `json_group_array`，PostgreSQL 用 `json_agg`，**不要混用 import 路径**。

## 一对多再套一对多怎么处理？

- 在外层再嵌一层 helper，每层都要带 `whereRef` 关联条件；
- 层数超过 2 层时先 `.compile()` 看 SQL，再决定是否拆成两次查询;
- 抽函数与性能取舍见 [关联查询的复用与取舍](./040-关联查询的复用与取舍.md)。
