# 关联查询的复用与取舍

## 怎样把常用关联抽成函数？

- 参数用 `Expression`（列引用），外层就能传 `person.id`，也能传 `mother.id`;
- 函数返回 helper 表达式，由调用处 `.as('别名')` 命名;

```ts
import { type Expression } from "kysely";
import { jsonArrayFrom } from "kysely/helpers/sqlite";

function petsOf(ownerId: Expression<number>) {
  return jsonArrayFrom(
    db
      .selectFrom("pet")
      .select(["pet.id", "pet.name"])
      .where("pet.owner_id", "=", ownerId)
      .orderBy("pet.name"),
  );
}

const rows = await db
  .selectFrom("person")
  .selectAll()
  .select(({ ref }) => [petsOf(ref("person.id")).as("pets")])
  .execute();
```

- helper 内部用全局 `db` 而不是传入的 `eb`，因为 `jsonArrayFrom` 接受任意 `Expression` 子查询;
- 需要在事务里复用时，把 `db` 当参数传入，或用 `trx` 版本。

## 抽函数能避免什么问题？

- 重复写 `whereRef` 关联条件容易写错成 `where`（变成常量比较）;
- 关联的排序、字段裁剪集中一处，改结构时不用全局搜;
- 类型跟着 `Expression` 走，调用处仍有补全。

## 什么时候不该用嵌套查询？

| 做法               | 查询次数 | 适用                          |
| ------------------ | -------- | ----------------------------- |
| 嵌套 JSON 查询     | 1        | 一次取少量主表行 + 其子表列表 |
| 主表 + 循环子查询  | 1 + N    | 几乎不用，N 一大就崩          |
| 两次查询再内存拼装 | 2        | 主表需要分页、子表数据量大    |

- **分页场景优先两次查询**：`limit` 作用在外层时，JSON 子查询只对当页行执行；但对子表再分页就做不到;
- 关联列（`pet.owner_id`、`person.id`）必须有索引，否则每条主表行都全表扫描;
- 超宽子表（几十列 × 上千行）用 JSON 聚合会把结果集撑大，改为两次查询更好。

## 结果很大时怎么验证性能？

- `.compile()` 出的 SQL 可以拿到 SQLite 里 `explain query plan`，确认走了索引;
- 先量主表行数与子表平均行数，再决定嵌套还是两次查询;
- 相关工具与索引建法见 [建表与索引](../010-快速上手/050-建表与索引.md)。
