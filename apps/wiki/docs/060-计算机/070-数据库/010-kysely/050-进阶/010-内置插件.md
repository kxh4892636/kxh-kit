# 内置插件

## 插件在什么时机介入？

- 执行链上两个钩子：`transformQuery`（编译前改语法树）、`transformResult`（返回前改结果）;
- 全局插件写在 `new Kysely({ plugins: [...] })`，单个查询用 `.withPlugin(new XxxPlugin())`;
- 完整链路见 [查询的执行流程](../010-快速上手/070-查询的执行流程.md)。

## 内置插件分别解决什么问题？

| 插件                       | 解决                                       | 什么时候装                  |
| -------------------------- | ------------------------------------------ | --------------------------- |
| `ParseJSONResultsPlugin`   | 把 JSON 字符串列解析成对象                 | SQLite 上做嵌套查询基本必装 |
| `CamelCasePlugin`          | 库里的 `snake_case` ↔ 代码里的 `camelCase` | 团队约定代码用驼峰时        |
| `DeduplicateJoinsPlugin`   | 动态拼查询时重复 join                      | 有可选 join 分支时          |
| `HandleEmptyInListsPlugin` | `in ()` 语法错误                           | 过滤条件可能传空数组时      |
| `SafeNullComparisonPlugin` | `= null` 永远为假                          | 条件值可能为 null 时        |

```ts
import { CamelCasePlugin, Kysely, ParseJSONResultsPlugin, SqliteDialect } from "kysely";

export const db = new Kysely<Database>({
  dialect: new SqliteDialect({ database: new SQLite("dev.sqlite") }),
  plugins: [new ParseJSONResultsPlugin(), new CamelCasePlugin()],
});
```

## 用驼峰插件时 `Database` 接口要改吗？

- 要。插件在结果层把列名转成驼峰，`Database` 的键必须写成驼峰，否则类型对不上;
- 生成的 SQL 仍是 `snake_case`，不用改库结构;

```ts
interface Database {
  person: { id: number; firstName: string; lastName: string | null };
}

await db.insertInto("person").values({ firstName: "Ada", lastName: null }).execute();
// 生成: insert into "person" ("first_name", "last_name") values (?, ?)
```

- 代价：原生 `sql` 片段里的列名不再受检查，写错了只能靠运行时发现。

## 空 `in` 列表怎么处理？

```ts
import { HandleEmptyInListsPlugin, replaceWithNoncontingentExpression } from "kysely";

const db = new Kysely<Database>({
  dialect,
  plugins: [new HandleEmptyInListsPlugin({ strategy: replaceWithNoncontingentExpression })],
});
// where id in ()      → where 1 = 0
// where id not in ()  → where 1 = 1
```

- 也可以把 `strategy` 写成会抛错的函数，把「不该出现的空数组」当 bug 拦住;
- 语义细节见 [过滤条件](../020-查询数据/020-过滤条件.md)。

- 日志怎么配、`LogEvent` 有哪些字段，见 [查询日志](./020-查询日志.md)。
