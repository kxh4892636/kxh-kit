# 查询日志

## 怎样打开查询日志？

- 方式一：`log: ['query', 'error']`，只记 SQL、不记参数;
- 方式二：传函数，能拿到 `sql`、`parameters`、耗时和错误，适合接自己的 logger;

```ts
export const db = new Kysely<Database>({
  dialect,
  log(event) {
    if (event.level === "error") {
      console.error("query failed", {
        sql: event.query.sql,
        ms: event.queryDurationMillis,
        error: event.error,
      });
      return;
    }
    console.log("query", {
      sql: event.query.sql,
      params: event.query.parameters,
      ms: event.queryDurationMillis,
    });
  },
});
```

## `LogEvent` 里有什么？

| 字段                             | 出现时机   | 用途                   |
| -------------------------------- | ---------- | ---------------------- |
| `level`                          | 总是       | `'query'` 或 `'error'` |
| `query.sql` / `query.parameters` | 总是       | 实际执行的 SQL 与参数  |
| `queryDurationMillis`            | 总是       | 耗时，做慢查询告警     |
| `error`                          | 仅 `error` | 原始异常对象           |
| `isStream`                       | 仅流式查询 | 区分流式结果           |

- `level` 是判别字段，先判断再取 `error`，否则类型不通;
- 类型定义见 `KyselyConfig['log']`。

## 日志里要注意什么？

- `parameters` 可能含个人信息，落盘前脱敏;
- 不要在生产开 `'query'` 全量日志：高 QPS 下日志本身就是瓶颈;
- 慢查询告警按 `queryDurationMillis` 阈值过滤，而不是全量打点。

```ts
log(event) {
  if (event.queryDurationMillis > 200) {
    console.warn('slow query', { sql: event.query.sql, ms: event.queryDurationMillis })
  }
}
```

## 除日志外还有哪些观察手段？

- `.compile()` 直接打印 SQL 与参数，比日志更直观，见 [查询的执行流程](../010-快速上手/070-查询的执行流程.md);
- SQLite 侧用 `explain query plan` 看索引是否命中;
- 插件链路的顺序见 [内置插件](./010-内置插件.md)。
