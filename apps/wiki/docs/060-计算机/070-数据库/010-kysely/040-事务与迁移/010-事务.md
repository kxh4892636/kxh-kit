# 事务

## 最简单的事务怎么写？

- `.transaction().execute(回调)` 自动提交/回滚：回调抛错即回滚，正常返回即提交;
- 回调里的 `trx` 与 `db` 用法一致，但只有 `trx` 在事务内;

```ts
const pet = await db.transaction().execute(async (trx) => {
  const person = await trx
    .insertInto("person")
    .values({ first_name: "Jennifer", last_name: "Aniston", gender: "woman" })
    .returning("id")
    .executeTakeFirstOrThrow();

  return await trx
    .insertInto("pet")
    .values({ owner_id: person.id, name: "Catto", species: "cat" })
    .returningAll()
    .executeTakeFirstOrThrow();
});
```

- 回调的返回值就是事务的返回值，写操作与返回值可以一起拿到。

## 需要自己控制提交时机怎么办？

- `startTransaction().execute()` 拿到显式事务对象，手动 `commit()` / `rollback()`;
- 适合「先做事，再根据外部结果决定是否提交」的流程;

```ts
const trx = await db.startTransaction().execute();

try {
  await trx
    .insertInto("person")
    .values({ first_name: "A", last_name: null, gender: "other" })
    .execute();
  await trx.commit().execute();
} catch (error) {
  await trx.rollback().execute();
  throw error;
}
```

- 显式事务忘记 `commit()` 时，连接释放会回滚，表现为「写成功了但查不到」;
- 只有 `startTransaction()` 返回的对象有保存点能力，`transaction()` 回调里的 `trx` 没有。

## 事务能嵌套吗？

- 不能。在事务回调里再调 `transaction()` 会直接抛错
  `calling the transaction method for a Transaction is not supported`;
- 需要「部分回滚」语义时用保存点，见 [保存点与事务禁忌](./020-保存点与事务禁忌.md)。

## 事务里通常放什么？

| 放进去             | 原因                   |
| ------------------ | ---------------------- |
| 多条相关写操作     | 要么全成功，要么全失败 |
| 读后写（先查再改） | 避免读到中间状态       |
| 迁移脚本           | 失败可整体回滚         |

- 批量写放进一个事务能显著提速，见 [批量写入](../030-写入数据/060-批量写入.md);
- 迁移执行的加锁机制见 [编写迁移文件](./030-编写迁移文件.md)。

## 事务失败时怎么排查？

- 先看抛出的错误是不是业务错误：业务错误也会触发回滚;
- `SQLITE_BUSY` 表示抢锁失败，需要重试或缩短事务，见 [SQLite 并发与运维](../060-速查/040-SQLite并发与运维.md);
- 想知道实际执行的语句，配 `log` 回调，见 [内置插件](../050-进阶/010-内置插件.md)。
