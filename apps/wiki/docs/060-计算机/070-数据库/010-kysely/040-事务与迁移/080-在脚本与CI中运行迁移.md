# 在脚本与 CI 中运行迁移

## 不上 CLI 时怎么跑迁移？

- 用 `Migrator` + `FileMigrationProvider` 写一个脚本，`error` 非空就设退出码 1;
- `migrationFolder` 必须是**绝对**路径，相对路径会静默找不到迁移;

```ts title="scripts/migrate.ts"
import { promises as fs } from "node:fs";
import * as path from "node:path";
import { FileMigrationProvider, Migrator } from "kysely/migration";
import { db } from "../src/db";

const migrator = new Migrator({
  db,
  provider: new FileMigrationProvider({
    fs,
    path,
    migrationFolder: path.join(import.meta.dirname, "../migrations"),
  }),
});

const { error, results } = await migrator.migrateToLatest();

for (const r of results ?? []) {
  console.log(`[${r.status}] ${r.migrationName}`);
}

if (error) {
  console.error("migration failed", error);
  process.exitCode = 1;
}

await db.destroy();
```

```bash
npx tsx scripts/migrate.ts
```

## 除了 `migrateToLatest` 还有哪些方法？

| 方法                | 作用                           |
| ------------------- | ------------------------------ |
| `migrateToLatest()` | 执行所有未跑过的迁移           |
| `migrateUp()`       | 执行下一个未跑过的迁移         |
| `migrateDown()`     | 撤销最后一个已执行的迁移       |
| `migrateTo(名字)`   | 迁移到指定版本（可前进可后退） |
| `getMigrations()`   | 列出迁移与状态，不执行         |

- 返回值统一是 `{ error, results }`，`results[].status` 为 `Success` / `Error` / `NotExecuted`。

## 脚本里怎么保证失败就停？

- 检查 `error` 而不是只看 `results`;
- 迁移失败时不要继续启动应用，否则代码会访问不存在的列;
- 退出码非 0 才能让 CI 任务失败。

```ts
const { error } = await migrator.migrateToLatest();
if (error) {
  console.error(error);
  process.exit(1);
}
```
