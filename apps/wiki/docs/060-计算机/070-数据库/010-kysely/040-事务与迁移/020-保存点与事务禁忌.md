# 保存点与事务禁忌

## 保存点解决什么问题？

- 一个大事务里，某段失败只想撤销这一段，其余保留;
- 前提：保存点只在 `db.startTransaction().execute()` 返回的受控事务上可用，`transaction()` 回调里的 `trx` 没有 `savepoint`;
- `savepoint(名字)` 打点，`rollbackToSavepoint(名字)` 回退，`releaseSavepoint(名字)` 释放;

```ts
const trx = await db.startTransaction().execute();

try {
  await trx.insertInto("audit").values({ action: "start" }).execute();

  const sp = await trx.savepoint("after_audit").execute();
  try {
    await sp.insertInto("pet").values({ owner_id: 1, name: "Bad", species: "cat" }).execute();
  } catch {
    await sp.rollbackToSavepoint("after_audit").execute();
  }
  await sp.releaseSavepoint("after_audit").execute();

  await trx.commit().execute();
} catch (error) {
  await trx.rollback().execute();
  throw error;
}
```

## 三个保存点方法分别做什么？

| 方法                        | 作用                         | 注意                         |
| --------------------------- | ---------------------------- | ---------------------------- |
| `savepoint(name)`           | 打一个标记，返回新的受控事务 | 名字在同一事务内唯一         |
| `rollbackToSavepoint(name)` | 回到标记处，标记仍在         | 之后可继续用同一个受控事务写 |
| `releaseSavepoint(name)`    | 释放标记                     | 释放后数据仍然保留           |

- 只在受控事务或 `transaction()` 回调里有效，脱离事务会报错;
- 保存点常用于「批量导入时容忍部分失败」。

## 事务里哪些事不能做？

| 禁止                        | 原因                                           |
| --------------------------- | ---------------------------------------------- |
| 用外层 `db` 执行写操作      | 不在事务内，与 `trx` 抢锁，SQLite 下会等锁超时 |
| 事务里做长耗时外部调用      | 写事务持有库级写锁，其他写入全部阻塞           |
| 嵌套 `db.transaction()`     | 直接报错，嵌套语义用保存点                     |
| 事务里 `await db.destroy()` | 会回滚并让后续语句直接失败                     |

## 出错后该回滚还是提交？

- 业务校验失败：回滚，把错误抛给调用方;
- 部分数据已成功但业务允许：先 `rollbackToSavepoint` 再提交;
- 不确定状态时宁可行回滚：SQLite 事务是原子的，重试成本低于脏数据。

## 事务与并发的关系是什么？

- SQLite 同一时刻只允许一个写事务，并发写会等到超时后报 `SQLITE_BUSY`;
- 缓解手段（WAL、`timeout`、拆短事务）见 [SQLite 并发与运维](../060-速查/040-SQLite并发与运维.md);
- 事务的基本写法见 [事务](./010-事务.md)。
