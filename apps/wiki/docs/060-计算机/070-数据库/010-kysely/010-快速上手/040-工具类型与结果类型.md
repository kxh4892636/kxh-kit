# 工具类型与结果类型

## 为什么用 `Selectable`/`Insertable`/`Updateable` 而不是表接口？

- 表接口带 `Generated`、`ColumnType` 等包装，直接当结果类型会得到错误的形状;
- 三个工具类型按操作分别展开，得到真正对外的行类型;

```ts title="src/types.ts"
export type Person = Selectable<PersonTable>;
export type NewPerson = Insertable<PersonTable>;
export type PersonUpdate = Updateable<PersonTable>;
```

| 工具类型        | 得到的形状                                   |
| --------------- | -------------------------------------------- |
| `Selectable<T>` | 全列必填，`id: number`、`created_at: string` |
| `Insertable<T>` | `Generated` 列与带默认值的列可选             |
| `Updateable<T>` | 全列可选，`never` 列被剔除                   |

## 三个工具类型具体怎么变？

| 列声明                            | `Selectable`     | `Insertable`          | `Updateable`          |
| --------------------------------- | ---------------- | --------------------- | --------------------- |
| `Generated<number>`               | `number`         | `number \| undefined` | `number \| undefined` |
| `string \| null`                  | `string \| null` | 可选                  | 可选                  |
| `ColumnType<Date, string, never>` | `Date`           | `string`              | 不可写                |
| `JSONColumnType<T>`               | `T`              | `string`              | `string`              |

- 表格可以直接当「这个列能不能写」的速查;
- 列包装的语义见 [列类型包装](./030-列类型包装.md)。

## 函数的参数和返回值该用哪个？

- 入参接收整行：用 `Person`（读）；
- 入参接收待写入的数据：用 `NewPerson` / `PersonUpdate`;
- 不要用 `PersonTable` 当函数签名，它会让 `Generated`、`ColumnType` 泄漏到业务层;

```ts
export async function createPerson(person: NewPerson): Promise<Person> {
  return await db.insertInto("person").values(person).returningAll().executeTakeFirstOrThrow();
}
```

## 类型的边界在哪里？

- Kysely 只做编译期检查，**运行时类型由驱动决定**;
- 声明 `Date` 但驱动返回字符串，代码看着是 `Date`、跑起来是 `string`;
- SQLite 的实际行为见 [SQLite 类型与运行时差异](../060-速查/020-SQLite类型与运行时差异.md)。

## 表多时怎么少写类型？

- 手写适合表少、结构稳定的项目;
- 表多时用 `kysely-codegen` 反向生成，见 [生成数据库类型](../050-进阶/050-生成数据库类型.md)。
