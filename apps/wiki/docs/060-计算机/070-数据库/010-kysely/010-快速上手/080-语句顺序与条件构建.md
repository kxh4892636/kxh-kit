# 语句顺序与条件构建

## 为什么每次调用都要把结果赋回给变量？

- 每个查询方法**返回一个新的 builder**，不修改原对象（不可变）;
- 所以 `query.where(...)` 单独一行等于丢弃了新 builder;

```ts
let query = db.selectFrom("person").selectAll();

query.where("first_name", "=", "Jennifer"); // ❌ 结果被丢弃
query = query.where("first_name", "=", "Jennifer"); // ✅ 赋回
```

## 为什么 `.select()` 必须写在 `innerJoin()` 后面？

- 类型上下文随链式调用累积：`innerJoin` 之后的 `select` 才能看到新表的列;
- 顺序错了不是风格问题，而是编译报错——这正是 Kysely「只允许引用当前可见表和列」的体现;

```ts
const ok = db
  .selectFrom("person")
  .innerJoin("pet", "pet.owner_id", "person.id")
  .select(["person.id", "pet.name as pet_name"]); // ✅ pet 已在上下文

const bad = db
  .selectFrom("person")
  .select(["person.id", "pet.name"]) // ❌ 此时还没有 pet
  .innerJoin("pet", "pet.owner_id", "person.id");
```

## 条件分支怎么写才不丢类型？

- `where`、`orderBy`、`limit` 这类方法不改变结果类型，用 `if` + 重新赋值就行;
- `select`、`returning`、`innerJoin` 会改变结果类型，`if` 赋值会把类型「降级」，要用 `$if`;

```ts
// ✅ 过滤是加法，可以 if
let q = db.selectFrom("person").selectAll();
if (keyword) q = q.where("first_name", "like", `%${keyword}%`);
const rows = await q.execute();

// ✅ 选列会变类型，用 $if；没选中的列在结果里变成可选
const one = await db
  .selectFrom("person")
  .select("first_name")
  .$if(withLastName, (qb) => qb.select("last_name"))
  .where("id", "=", id)
  .executeTakeFirstOrThrow();
// 类型: { first_name: string; last_name?: string | null }
// —— 被 $if 选中的列在结果里变成可选（带 undefined）
```

## `$if` 的代价是什么？

- 拿不到「是否选了」的判别联合，被选中的列只能变可选;
- 需要精确区分两种返回值时，写成两个分支分别 `return`;
- 更多的类型收窄手段见 [修正查询结果类型](../050-进阶/060-修正查询结果类型.md)。

## 为什么不能先建好 builder 再到处传？

- builder 是不可变值，「修改」其实是新建；到处传同一份 builder 会得到陈旧上下文;
- 需要复用的应该是**表达式或 helper 函数**，见 [可复用查询函数](../020-查询数据/050-可复用表达式函数.md)。
