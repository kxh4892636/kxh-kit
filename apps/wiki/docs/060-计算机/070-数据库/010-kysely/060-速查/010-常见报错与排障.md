# 常见报错与排障

## 先做什么能省一半时间？

- 把查询 `.compile()` 打印出来，看真实 SQL 和参数，多数问题一眼可见;

```ts
const compiled = db.selectFrom("person").select("first_name").where("id", "=", 1).compile();
console.log(compiled.sql, compiled.parameters);
// select "first_name" from "person" where "id" = ? [ 1 ]
```

- 参数化不代表值写错：`where('owner_id', '=', 'person.id')` 会把字符串当值传进去，要改成 `whereRef`。

## 类型层面的报错怎么定位？

| 报错                                                                             | 原因                                                                       | 处理                                                                    |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `Property 'xxx' does not exist`                                                  | 列名/表名拼错，或 join 还没发生                                            | 检查拼写；`select` 放到 `join` 之后                                     |
| `Argument of type ... is not assignable to parameter of type 'InsertExpression'` | 列类型与 `Database` 声明不符（常见：JSON 列需要字符串、可空列漏写 `null`） | 对齐 [类型定义](../010-快速上手/030-列类型包装.md)                      |
| `TS2589 Type instantiation is excessively deep`                                  | 查询层数过多                                                               | `$assertType`，见 [生成与修正类型](../050-进阶/060-修正查询结果类型.md) |
| 结果字段是 `X \| null` 但业务上不会为空                                          | Kysely 无法推断                                                            | `$narrowType<{ 列: NotNull }>`                                          |
| `never` 出现在更新类型里                                                         | 该列被声明为 `ColumnType<..., ..., never>`                                 | 正常，这列禁止更新                                                      |

## 运行时错误对照表？

| 报错文本                              | 含义                         | 处理                                                                  |
| ------------------------------------- | ---------------------------- | --------------------------------------------------------------------- |
| `SQLITE_ERROR: no such table: xxx`    | 没建表/连错库文件            | 跑迁移或检查 `new SQLite(path)` 的路径                                |
| `SQLITE_ERROR: no such column: xxx`   | 迁移没跑、或列名与代码不一致 | 重跑迁移，核对 `Database`                                             |
| `SQLITE_ERROR: syntax error near ")"` | 多半是 `in ()` 空数组        | 判空或装 `HandleEmptyInListsPlugin`                                   |
| `NOT NULL constraint failed`          | 必填列没给值                 | 补值或加 `defaultTo`                                                  |
| `UNIQUE constraint failed`            | 唯一索引冲突                 | 改用 `onConflict`                                                     |
| `FOREIGN KEY constraint failed`       | 父行不存在/删除顺序错        | 先写父表；级联删除用 `onDelete('cascade')`                            |
| `The database connection is not open` | `db.destroy()` 之后还在查询  | 检查关闭时机（常见于测试 `after` 钩子）                               |
| `SQLITE_BUSY: database is locked`     | 并发写冲突                   | 包事务、缩短写事务、见 [SQLite 差异](./020-SQLite类型与运行时差异.md) |
| `invalid operator "between"`          | `where` 不支持该操作符       | 改 `eb.between('age', 18, 60)`                                        |
| `too many SQL variables`              | 单条语句参数超 32766         | 分批插入                                                              |

## 为什么 `executeTakeFirst()` 返回了 `undefined`？

- 查询确实没有匹配行；用 `executeTakeFirstOrThrow()` 让「没查到」直接抛错，避免后续空指针;
- 也可能是条件写错：确认比较值没被当成列名、`is null` 与 `= null` 没混用;

```ts
// ❌ = null 在 SQL 里永远不成立
.where('last_name', '=', null)

// ✅
.where('last_name', 'is', null)
```

## 为什么改了数据但查不出来？

- 查询和写入用的不是同一个 Kysely 实例 / 同一个库文件;
- 写完没提交：显式事务里忘了 `commit()`;
- 写事务还在跑，读的是旧快照（SQLite WAL 下读写不互斥，但要确认已提交）;

## 排查顺序推荐？

1. `.compile()` 看 SQL 与参数;
2. 把同一条 SQL 拿到 `sqlite3` 或 `npx kysely sql "<sql>"` 里直接跑;
3. 确认库文件路径、迁移是否已执行（`db.introspection.getTables()`）;
4. 最后才怀疑 Kysely 版本行为，对照官方 [Kysely API 文档](https://kysely-org.github.io/kysely-apidoc/)。
