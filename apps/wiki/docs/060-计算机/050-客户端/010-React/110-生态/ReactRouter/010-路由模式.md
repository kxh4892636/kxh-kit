# React Router 路由模式

## 声明式路由怎样接入应用？

- 适用范围: 以下讨论 react-router 的声明式组件路由;
- 注意: 数据加载与框架模式另有能力, 不要混用接口假设;
- 入口包: 用与项目版本匹配的 react-router;
- 顺序: 先建 Router 上下文, 再在内层用 Route、Link 与路由 Hook;

```bash
npm install react-router
```

## BrowserRouter 怎样把页面位置映射到 URL？

- History 模式: 用浏览器路径与 History API;
- 效果: 导航不必整页刷新就能更新位置;
- 部署条件: 服务器要让应用路径回退到入口 HTML;
- 否则: 直接打开或刷新子路径可能 404;

```jsx
import { BrowserRouter } from "react-router";

const app = (
  <BrowserRouter>
    <App />
  </BrowserRouter>
);
```

## 无法配置服务器路径回退时如何选择？

- HashRouter: 把应用路径放在 URL 的 hash 里;
- 特点: hash 不随普通 HTTP 请求发出, 因此不必逐条配服务端回退;
- 取舍: 三种模式的 URL 形式、外部链接与服务端可见性不同;
- 依据: 按部署约束选, 不要断定 hash 不能用于产品;

## 测试中如何独立控制导航历史？

- MemoryRouter: 在内存里维护历史栈;
- 起点: `initialEntries` 与 `initialIndex`;
- 适用: 测试或没有地址栏的环境;
- 隔离作用: 不修改真实浏览器 URL, 便于为某个路由直接构建测试状态;

```jsx
import { MemoryRouter } from "react-router";

const testView = (
  <MemoryRouter initialEntries={["/users/1"]}>
    <App />
  </MemoryRouter>
);
```

## 服务端如何按指定位置渲染路由？

- StaticRouter: 按请求的 location 渲染匹配结果;
- 边界: 不做客户端式的有状态导航;
- 模式区别: 带 loader/action 的服务端数据路由需要对应的数据路由集成;
- 反例: 只包 StaticRouter 不代表数据已加载;
