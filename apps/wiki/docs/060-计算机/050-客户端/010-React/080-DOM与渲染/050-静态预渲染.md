# 静态预渲染

## prerender 与同步字符串渲染有什么区别？

- 等待数据: `prerender` 生成完整内容前会等数据;
- 适用: 构建或预生成阶段, 不是拿到第一段外壳就发的实时 SSR;
- 输出载体: 成功时返回 Promise 结果里的 `prelude` 流;
- 注意: 没有 `result` 字段;
- 类型: Web 与 Node 版本各有对应流类型;
- 可交互性: 静态预生成也能交互, 输出可由 `hydrateRoot` 水合;
- 不加载客户端脚本: 仍保留纯 HTML;

```jsx
import { prerender } from "react-dom/static";

async function renderPage() {
  const { prelude, postponed } = await prerender(<App />, {
    bootstrapScripts: ["/client.js"],
  });
  return { htmlStream: prelude, postponed };
}
```

## 如何选择 Web 或 Node 的静态输出？

- Web Streams: `prelude` 可放进 `Response`;
- 也可: 读出后写成静态文件;
- Node.js: `prerenderToNodeStream` 返回 Node 流形式的 `prelude`, 按 Node 流的方式消费;
- 文档入口: 应用通常渲染整份 html;
- 要求: 客户端脚本、模块脚本与 ID 前缀要和之后的水合入口一致;

```jsx
import { prerenderToNodeStream } from "react-dom/static";
import { createWriteStream } from "node:fs";
import { pipeline } from "node:stream/promises";

async function writePage(filename) {
  const { prelude, postponed } = await prerenderToNodeStream(<App />);
  if (postponed !== null) {
    throw new Error("本次任务要求完整预渲染");
  }
  await pipeline(prelude, createWriteStream(filename));
}
```

## 中断后怎样保存并继续预渲染？

- 推迟状态: 未完成的预渲染会产生可序列化但不透明的 `postponed`;
- 完成时: 该值为 `null`;
- 继续预生成: `resumeAndPrerender` 或 `resumeAndPrerenderToNodeStream` 收推迟状态;
- 产出: 下一份 `prelude` 与 `postponed`;
- 请求时恢复: 决定在请求阶段继续时, 用 resume 系列实时流式恢复;
- 区别: 见服务端 HTML 渲染;

## 静态生成怎样处理资源与安全选项？

- 资源提示: `onHeaders` 收到可发送的 Link 提示, `maxHeadersLength` 控制总长;
- 责任: 提示与 HTML 输出由宿主协调保存或发送;
- Import map: 用模块脚本时可通过 `importMap` 配置模块标识解析;
- 前提: 必须与实际发布路径匹配;
- Nonce 限制: 静态预渲染不接受每次请求唯一的 nonce;
- 反例: 不要把它烘焙进共享静态文件;
- 错误处理: Promise 拒绝时给出明确的后备结果, `onError` 用于记录;
- 反例: 不把半份未完的内容当作完整产物;
