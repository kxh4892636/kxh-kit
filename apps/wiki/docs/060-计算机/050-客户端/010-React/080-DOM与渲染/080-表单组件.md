# DOM 表单组件

## 如何保持受控输入与状态同步？

- 文本控制: input、textarea 与 select 的 `value` 来自 state;
- 更新: 在 `onChange` 中同步;
- 避免: 同一生命周期里从 `undefined` 切成受控字符串;
- 勾选控制: checkbox 与 radio 用 `checked` 与 `event.target.checked`;
- 反例: 不能用文本 `value` 代替布尔勾选状态;
- 只读意图: 给了 `value` 或 `checked` 又不允许编辑时, 明确设 `readOnly`;
- 避免: 看起来能输入却立刻恢复;

```jsx
const [name, setName] = useState("");
const [agreed, setAgreed] = useState(false);
const fields = (
  <>
    <input value={name} onChange={(event) => setName(event.target.value)} />
    <input type="checkbox" checked={agreed} onChange={(event) => setAgreed(event.target.checked)} />
  </>
);
```

## 如何让浏览器保存非受控输入？

- 初始值: 用 `defaultValue` 或 `defaultChecked`;
- 特点: 只设初始内容, 之后由 DOM 保存用户输入;
- 读取提交: 控件设 `name`, 提交时从 `FormData` 读;
- 多选字段: 用 `getAll`, 直接 `Object.fromEntries` 会丢掉同名多值;
- textarea: 用 `value` 或 `defaultValue`, 不用 children;
- select: 由父元素 `value` 控制, 不用 `option.selected`;
- 多选 select: 传数组;

```jsx
function TagsForm({ saveTags }) {
  function submit(formData) {
    return saveTags(formData.getAll("tags"));
  }
  return (
    <form action={submit}>
      <select name="tags" multiple defaultValue={["react"]}>
        <option value="react">React</option>
        <option value="typescript">TypeScript</option>
      </select>
      <button>保存标签</button>
    </form>
  );
}
```

## 函数 action 如何处理表单提交？

- 提交载荷: `<form action={fn}>` 调函数时传入 `FormData`;
- 语义: 函数 action 走 POST, 成功后重置非受控字段;
- 提交按钮: button 的 `formAction` 可覆盖 form 的 `action`;
- 标识操作: 用按钮的 `name` 与 `value`;
- 非提交按钮: 显式写 `type="button"`;
- 状态组合: pending 展示见表单提交状态, 结果与错误见 Action 状态;
- 反例: 不要把三个契约混成一个 Hook;

```jsx
async function submit(formData) {
  await save(String(formData.get("message")));
}
const form = (
  <form action={submit}>
    <textarea name="message" defaultValue="" />
    <button type="submit">发送</button>
  </form>
);
```

## 如何保证表单可访问且提交数据完整？

- 标签关联: label 包住控件, 或用 `htmlFor` 与 `id` 对应;
- 生成唯一 ID: 见标识与调试 Hooks;
- 浏览器校验: `required`、`min`、`max` 改善交互;
- 前提: 服务端仍要独立验证输入与权限;
- 进度指示: 用 `progress` 的 `value` 与 `max` 表达完成度;
- 不确定进度: 省略 `value`, 不要把 0 当作不确定;
