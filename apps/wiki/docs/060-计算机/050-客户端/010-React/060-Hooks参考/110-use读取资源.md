# 使用 use 读取资源

## use 如何读取尚未完成的 Promise？

- 资源读取: `use(promise)` 在渲染中读结果;
- 待完成: 挂起最近的 Suspense 边界, 成功后继续渲染;
- 失败: 交给错误边界;
- 稳定 Promise: 必须复用缓存的 Promise;
- 反例: 每次渲染新建, 重试永远面对新资源;
- 服务端输入: Server Component 可把 Promise 传给 Client Component;
- 前提: 最终结果必须能跨边界序列化;

```jsx
import { Suspense, use } from "react";

function Message({ messagePromise }) {
  const message = use(messagePromise);
  return <p>{message}</p>;
}

function Page({ messagePromise }) {
  return (
    <Suspense fallback={<p>加载中……</p>}>
      <Message messagePromise={messagePromise} />
    </Suspense>
  );
}
```

## use 的调用规则与 Hook 有何区别？

- 允许分支: `use` 不是普通 Hook, 可以放在条件与循环里;
- 仍受限: 必须在组件或 Hook 中, 不能在普通函数里调用;
- 异常边界: 不要把 `use` 包在 try/catch 里;
- 做法: 用错误边界, 或先让 `Promise.catch` 转成替代值;
- 服务端偏好: async Server Component 取数据通常优先 `await`;
- 效果: 执行从等待处继续;
- 反例: 不要照搬客户端的资源读取模式;

## use 如何读取 Context？

- 读取规则: `use(SomeContext)` 取最近祖先提供者的值, 可在条件分支中读;
- 契约: 提供与默认值仍按 Context 主笔记;
- 服务端限制: 目前 Server Components 不支持用 `use` 读 Context;
- 反例: 不要把客户端 Context 模式直接搬到服务器;

## 如何声明一个只在浏览器渲染的组件？

- Browser 资源: `use(browser(reason))` 在服务端保留最近的 Suspense fallback;
- 之后: 在浏览器继续渲染;
- 注意: 单独调 `browser` 没有效果, 也不要 throw 它的返回值;
- 边界条件: 服务端必须有 Suspense;
- RSC 应用: 从 Client Component 调用, 不在 Server Component 里直接用;
- 版本核对: 用 `browser` 前先核对项目实际的 `react-dom` 导出;
- 反例: 不要假定所有 React 19 小版本都有;

```jsx
import { use } from "react";
import { browser } from "react-dom";

function BrowserContent() {
  use(browser("需要浏览器尺寸"));
  return <p>浏览器宽度：{window.innerWidth}</p>;
}
```

```jsx
import { Suspense } from "react";

function Page() {
  return (
    <Suspense fallback={<p>浏览器内容准备中……</p>}>
      <BrowserContent />
    </Suspense>
  );
}
```

- 服务端输出: 页面先显示 fallback, 浏览器接手后才运行需要 `window` 的内容;
- 澄清: 只加 `use client` 不能替代这个边界;
