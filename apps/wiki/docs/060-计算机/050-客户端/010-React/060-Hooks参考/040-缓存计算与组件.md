# 缓存计算与组件

## 什么时候值得缓存渲染中的计算？

- `useMemo`: `useMemo(calculateValue, dependencies)` 缓存纯计算结果;
- 复用条件: 依赖按 `Object.is` 逐项相等;
- 适用条件: 计算昂贵、结果常复用, 或结果引用影响下游优化;
- 前提: 先测量生产场景, 而不是只看开发时的重复调用;
- 非语义保证: React 可能丢弃缓存, 所以重新计算时正确性仍要成立;
- 需要稳定记忆的数据: 用 state 或 ref;

```jsx
const visibleTodos = useMemo(() => todos.filter((todo) => todo.tab === tab), [todos, tab]);
```

## 如何让回调引用配合子组件缓存？

- `useCallback`: 缓存函数本身而非调用结果;
- 效果: 依赖不变时给同一引用, 常配合 `memo` 子组件;
- 依赖闭包: 读到的响应式值仍要进依赖, 不能为稳定引用保留旧数据;
- 替代: 从旧状态计算时用更新函数;

```jsx
const addOne = useCallback(() => setCount((count) => count + 1), []);
```

## memo 可以跳过哪些组件更新？

- 默认比较: `memo(Component)` 按每个 prop 的 `Object.is` 结果判断能否跳过;
- 澄清: 它不做整个对象的深比较;
- 保留更新: 组件自身 state 或读取的 Context 变化仍会更新, memo 不是冻结 UI 的工具;
- 自定义比较: `arePropsEqual` 要比较全部影响输出与行为的 props, 包括函数闭包;
- 前提: 比较成本低于重新渲染;

```jsx
import { memo } from "react";

const List = memo(function List({ items }) {
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.text}</li>
      ))}
    </ul>
  );
});
```

## 为什么已经缓存了却仍然重新计算？

- 不稳定输入: 每次新建 options、数组或回调都会让依赖失效;
- 做法: 把构造移进 `useMemo`, 或让上游身份保持稳定;
- 无效优化: 一个总在变的 prop 就能破坏整次 `memo`;
- 顺序: 先缩小状态范围、去掉多余 Effect, 再加缓存;
- 编译器关系: React Compiler 能自动完成许多缓存;
- 前提: 实际启用且符合规则, 装了 React 不等于自动优化;
