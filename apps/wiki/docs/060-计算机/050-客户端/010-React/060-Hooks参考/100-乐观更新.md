# 乐观更新

## useOptimistic 如何提前展示操作结果？

- 临时覆盖: `useOptimistic(value, reducer?)` 返回乐观值与更新函数;
- 待完成期间: 展示预测结果, 结束后回到真实的 `value`;
- 调用范围: 乐观 setter 必须在 Action 里调用, 不能在渲染中更新;

## 乐观 setter 的调用范围在哪？

- 反例: 在范围外调用还想有持续 pending 显示;
- 真实来源: 服务端成功后仍要更新父级 props 或 state;
- 澄清: 乐观值不会永久替代真实数据;

## 如何为一次异步操作加入乐观反馈？

```jsx
import { startTransition, useOptimistic, useState } from "react";

function LikeButton({ saveLike }) {
  const [liked, setLiked] = useState(false);
  const [optimisticLiked, setOptimisticLiked] = useOptimistic(liked);
  const [error, setError] = useState("");
  function like() {
    startTransition(async () => {
      setOptimisticLiked(true);
      setError("");
      try {
        await saveLike();
        startTransition(() => setLiked(true));
      } catch {
        setError("未能点赞，请重试");
      }
    });
  }
  return (
    <>
      <button disabled={optimisticLiked} onClick={like}>
        {optimisticLiked ? "已点赞" : "点赞"}
      </button>
      {error && <p role="alert">{error}</p>}
    </>
  );
}
```

## 多个乐观操作如何叠加在最新真实数据上？

- Reducer: 用最新基础状态与 action 算临时结果, 且必须纯粹;
- base value 变化时: React 会重新应用乐观计算;
- 避免旧闭包: 列表追加用 reducer 的 currentState;
- 反例: 不要从创建回调时的旧 items 拼接;
- 多种动作: 用 `action.type` 表达新增、删除等操作;
- 乐观条目: 可带临时 ID 与 pending 标记, 服务端确认后换成真实结果;

```jsx
const [visibleMessages, addOptimistic] = useOptimistic(messages, (current, newMessage) => [
  ...current,
  { ...newMessage, pending: true },
]);

async function sendAction(text) {
  const draft = { id: crypto.randomUUID(), text };
  addOptimistic(draft);
  await sendMessage(text);
  // 在此等待上层真实 messages 更新完成。
}
```

- 调用约定: `sendAction` 应由所属 Action 路径调用;
- 集成 `sendMessage` 时要更新真实列表, 否则 Action 结束后临时消息会消失;
