# 包初始化

## init 函数的调用规则是什么？

- `init`: 包初始化时自动调用一次;
- 调用限制: 不能被代码显式调用;
- 使用位置: package 中可声明用于初始化的 `init` 函数;

```go
package config

var Loaded bool

func init() {
	Loaded = true
}
```

## init 的声明限制是什么？

- 声明限制: init 不接收参数, 也不返回值;
- 数量: 同一个包甚至同一个文件可有多个 init;
- 边界: 由运行时初始化流程安排, 不是可调用的函数值;

## 包初始化按什么依赖顺序执行？

- 多个 init: 按文件顺序及文件内声明顺序执行;
- 实际顺序: 构建工具通常按文件名排序;
- 反例: 不要把复杂业务依赖藏在文件名里;
- 包变量依赖: 变量初始化会先满足同包变量依赖, 不能简单理解为只按书写顺序执行;

| 阶段 | 初始化对象             |
| ---: | ---------------------- |
|    1 | 被导入 package         |
|    2 | 当前 package 变量      |
|    3 | 当前 package 的 `init` |

```go
package config

var Limit = base + 1 // 依赖 base，先初始化 base
var base = 2

func init() {
    println(Limit) // 3：包变量已经初始化完成
}
```

## 包初始化何时执行、执行几次？

- 生命周期: 包初始化在 main 之前完成;
- 次数: 同一个被导入包只初始化一次;
- 边界: 多个包依赖它也不会重复执行 init;

## init 里的 goroutine 会并发吗？

- 并发边界: 初始化流程顺序调用 init;
- 但 init 里起的 goroutine: 可以并发运行;
- 结论: 不能假定它在 main 开始前完成;
