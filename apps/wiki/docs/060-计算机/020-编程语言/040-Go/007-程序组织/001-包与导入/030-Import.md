# Import

## 基本导入如何通过包名访问导出标识符？

- 普通导入: `import "路径"` 引入包;
- 访问: 用包声明的名字取导出成员;
- 范围: 其他源文件要各自 import;

```go
package main

import "fmt"

func main() {
	fmt.Println("hello") // 通过包名访问导出标识符
}
```

## 分组导入如何组织多个 import？ gofmt 会做什么？

- 分组导入: 使用括号组织多个 `import`;
- `gofmt`: 自动排序和整理 `import`;

```go
import (
	"fmt"
	"math/rand"
)
```

## 别名导入如何使用别名访问包？

- 别名: 在导入路径前指定本文件用的名字;
- 用途: 解决包名冲突, 或写清用途;
- 边界: 不修改目标包自身的名字;

```go
import random "math/rand"

func main() {
	println(random.Intn(10))
}
```

## 空导入有什么作用？

- 空导入: `_` 只取包初始化的副作用;
- 副作用包括: 依赖初始化、包变量与 init;
- 常见场景: 数据库驱动注册;
- 边界: 不能通过它访问成员;

```go
// 只触发目标包 init 副作用,不直接使用导出标识符
import _ "database/sql"
```

## 点导入有什么作用？ 为什么不推荐？

- 点导入: 把导出成员直接放进当前文件的名字空间;
- 代价: 读者难判断来源, 也更容易撞名;
- 建议: 普通业务代码避免;

```go
// 将 fmt 的导出标识符放入当前文件作用域;普通业务代码不推荐
import . "fmt"

func main() {
	Println("hello")
}
```

## 如何根据本文件需要的能力选择导入形式？

- 正常使用成员: 普通导入;
- 名字冲突: 别名导入;
- 只需初始化: 空导入;
- 点导入的风险: 见本篇对应小节;
