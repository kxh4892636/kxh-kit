# 单线程与事件循环

## JavaScript 为什么是单线程？

- 目的: 作为浏览器脚本语言, 核心职责是用户交互与 DOM 操作;
- 冲突: 多线程同时修改 DOM 会引入复杂的线程同步问题;
- 取舍: 即使可以用锁解决, 也会显著提高语言复杂度, 因此选择单线程;

## 为什么要引入异步？

- 问题: 单线程下长时间任务会阻塞主线程, 进而阻塞 UI 渲染;
- 方案: 把耗时任务交给宿主, 主线程只处理回调, 避免阻塞;

## 事件循环由哪些部分组成？

- 主线程: 顺序执行同步代码;
- 宏任务队列: 存放宿主发起的任务;
- 微任务队列: 存放 JavaScript 发起的任务;
- 渲染阶段: 视口刷新与回调调度;

| 类别   | 典型来源                                                              |
| ------ | --------------------------------------------------------------------- |
| 宏任务 | `script` 标签、`setTimeout`/`setInterval`、`postMessage`、IO、UI 渲染 |
| 微任务 | Promise、`MutationObserver`、`async`/`await`、`process.nextTick`      |

## 事件循环的执行顺序是什么？

1. 执行主线程同步代码 (只有第一轮事件循环存在同步代码); 遇到宏任务或微任务时分别入队;
2. 取出宏任务队列中的第一个任务执行, 完成后出队;
3. 清空微任务队列, 且本轮新增的微任务也在本轮清空;
4. 执行 `requestAnimationFrame` 回调与 DOM 渲染;
5. 执行 `requestIdleCallback`, 本轮结束, 回到第 2 步;
6. 循环直至宏任务队列清空;

## 计时器为什么不准时？

- 计时线程: `setTimeout`/`setInterval` 由独立线程计时, 到点后把回调推入宏任务队列;
- 精度: 时间精度约 6ms, 且回调要等当前宏任务与全部微任务执行完;
- 累积误差: `setTimeout` 存在延迟积累问题;
- 任务跳过: `setInterval` 在前一次回调仍未执行完时会跳过或叠加, 详见 [定时器](../010-浏览器对象模型/040-定时器.md);
