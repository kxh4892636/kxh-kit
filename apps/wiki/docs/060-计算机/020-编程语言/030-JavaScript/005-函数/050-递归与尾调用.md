# 递归与尾调用

## 递归函数直接引用自身名有什么风险？

```js
function factorial(num) {
  if (num <= 1) return 1;
  return num * factorial(num - 1);
}
```

- 风险: 函数名是指向函数对象的指针, 若外部改写了这个名字, 递归调用就会失效;

```js
const anotherFactorial = factorial;
factorial = null;
anotherFactorial(4); // TypeError; 内部仍引用名为 factorial 的指针
```

- 规避: 使用命名函数表达式, 让内部递归引用一个不会外泄的名字;

```js
const factorial = function self(num) {
  return num <= 1 ? 1 : num * self(num - 1);
};
```

## 尾调用优化做了什么？

- 机制: 外部函数的返回值就是某个内部函数的返回值时, 销毁外部函数的栈帧, 只保留一层栈帧;
- 前提: 严格模式, 且返回值直接是对尾调用函数的调用, 返回后不再做额外运算;
- 不可检测: 引擎不暴露优化是否生效, 只能按条件编写;

## 哪些写法会阻止尾调用优化？

```js
"use strict";
function noReturn() {
  innerFunction(); // 尾调用没有返回
}
function storeFirst() {
  const result = innerFunction(); // 尾调用没有直接返回
  return result;
}
function convert() {
  return innerFunction().toString(); // 返回后还要转型
}
function closure() {
  const foo = "bar";
  return function () {
    return foo; // 尾调用是引用外层自由变量的闭包
  };
}
```

## 如何把递归改写成可尾调用的形式？

```js
// 优化前: 返回后还要做加法, 无法复用栈帧
function fib(n) {
  if (n < 2) return n;
  return fib(n - 1) + fib(n - 2);
}

// 优化后: 用累加参数把中间结果传给下一次调用
("use strict");
function fib(n) {
  return fibImpl(0, 1, n);
}
function fibImpl(a, b, n) {
  if (n === 0) return a;
  return fibImpl(b, a + b, n - 1);
}
```
