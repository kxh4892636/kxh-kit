# 错误处理

## try/catch/finally 如何控制执行流？

```js
try {
  window.someNonexistentFunction();
} catch (error) {
  console.log(error.message);
} finally {
  console.log("finally");
}
```

- try: 代码出错时中断, 跳转到 `catch`;
- catch: 接收包含错误信息的对象;
- finally: 无论 `try` 还是 `catch` 执行, 最后都会执行;
- 覆盖 return: 只要包含 `finally`, `try`/`catch` 中的 `return` 会被 `finally` 的返回值覆盖;

```js
function f() {
  try {
    return 2;
  } catch {
    return 1;
  } finally {
    return 0; // 最终返回 0
  }
}
```

## 内置错误类型各表示什么？

| 类型             | 含义                                 |
| ---------------- | ------------------------------------ |
| `Error`          | 基类型                               |
| `InternalError`  | 引擎内部错误                         |
| `EvalError`      | `eval()` 相关错误                    |
| `RangeError`     | 数值越界                             |
| `ReferenceError` | 找不到引用                           |
| `SyntaxError`    | 语法错误 (如 `eval()` 中的非法语法)  |
| `TypeError`      | 变量不是预期类型                     |
| `URIError`       | `encodeURI()`/`decodeURI()` 相关错误 |

## 如何区分与抛出错误？

- 区分: 用 `instanceof` 按类型分支处理;

```js
try {
  someFunction();
} catch (error) {
  if (error instanceof TypeError) {
    // 类型错误
  } else if (error instanceof ReferenceError) {
    // 引用错误
  } else {
    // 其它
  }
}
```

- 抛出: `throw` 可抛任意值, 建议抛出内置错误类型的实例;

```js
throw new TypeError("What type of variable do you take me for?");
```

## window.onerror 捕获什么？

- 时机: 捕获没有被 `try/catch` 处理的错误;
- 用法: 只能用 DOM0 写法, 回调依次收到错误信息、错误所在 URL 与行号;
- 定位: 最后一道防线, 不建议作为主要错误处理手段;

```js
window.onerror = (message, url, line) => {
  console.log(message, url, line);
};
```
