# 状态 Hooks 的初始化与契约

## 如何避免每次渲染都计算初始状态？

- 惰性初始化: 给 useState 传初始化函数，让 React 在建立状态时调用；传 `createInitial()` 则 JavaScript 在每次执行组件时先调用它;
- 初值变化: 后续传入不同 initialState 不会覆盖已存在的状态，重置方式见保留与重置 state;
- 纯度检查: 初始化函数不接收参数，应为纯函数，StrictMode 开发检查可能调用两次并忽略一次结果;

| 写法                             | 初始化时         | 普通重新渲染时            |
| -------------------------------- | ---------------- | ------------------------- |
| `useState(createInitial())`      | 计算并采用       | 仍计算，但 React 忽略结果 |
| `useState(createInitial)`        | React 调用并采用 | 不因传参再次调用          |
| `useReducer(reducer, arg, init)` | 使用 `init(arg)` | 保留当前状态              |

```jsx
function initializeTasks(initialTasks) {
  return initialTasks.map((task) => ({ ...task, selected: false }));
}

function Tasks({ initialTasks }) {
  const [tasks, dispatch] = useReducer(tasksReducer, initialTasks, initializeTasks);
  return <TaskList tasks={tasks} dispatch={dispatch} />;
}
```

## 如何把函数本身存进 state？

- 函数歧义: useState 的函数参数被当成 initializer，setter 的函数参数被当成 updater，不能直接用它们保存函数值;
- 包一层返回: 使用 `useState(() => fn)` 初始化，以 `setFn(() => nextFn)` 更新，外层函数返回真正要保存的函数;

```jsx
const [handler, setHandler] = useState(() => initialHandler);
function replaceHandler() {
  setHandler(() => nextHandler);
}
```

## setter 与 dispatch 有哪些共同契约？

- 引用稳定: 同一挂载实例中的 setter 与 dispatch 身份稳定，依赖检查允许时可以省略，把它们列入依赖也不会单独导致重跑;
- 无返回值: 调用只提交更新，不返回新状态，也不是可 await 的更新完成 Promise;
- 相等优化: 新旧状态按 Object.is 相等时 React 可跳过后续渲染工作，某些情况下仍会调用组件后再跳过子树，不应依赖调用次数;
- 计算归属: setter 队列规则见排队更新 state；dispatch 的 action 设计与 reducer 纯度见 reducer 笔记;

## 如何定位状态更新后结果异常？

- 旧值日志: 先核对快照时机，不把 setter 后的旧日志当作更新失败;
- 状态消失: 检查 reducer 是否漏 return、是否只返回局部字段而丢弃其余状态;
- 无限渲染: 检查是否无条件在渲染中调用 setter，或把 `onClick={handleClick()}` 写成立即执行;
- 引用未变: 检查是否直接修改旧对象后再次提交同一引用，不可变更新见对象与数组 state;
