# 定义路由与嵌套布局

## Routes 怎样根据位置选择页面？

- 匹配集合: Routes 根据当前 location 匹配 Route，Route 的 path 描述路径，element 描述对应界面;
- 动态片段: `:id` 表示路径参数，`*` 可匹配未消费路径，具体值可在路由组件中读取;

```jsx
import { Routes, Route } from "react-router";

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="users/:id" element={<User />} />
      <Route path="*" element={<NotFound />} />
    </Routes>
  );
}
```

## 嵌套子路由怎样进入父布局？

- Outlet: 父布局在需要显示匹配子路由的位置渲染 Outlet，否则即使子路由匹配也没有可见插槽;
- 相对路径: 子 path 相对父路径组成完整 URL，index 表示父路径本身的默认内容，不再提供自己的 path;

```jsx
import { Outlet } from "react-router";

function DashboardLayout() {
  return (
    <main>
      <h1>控制台</h1>
      <Outlet />
    </main>
  );
}

const routes = (
  <Route path="dashboard" element={<DashboardLayout />}>
    <Route index element={<Overview />} />
    <Route path="messages" element={<Messages />} />
  </Route>
);
```

## 如何用对象表达相同的路由结构？

- useRoutes: 接收路由对象数组并返回匹配的元素，仍需要位于 Router 上下文中;
- 结构对应: path、element、children 与 JSX Route 表达相同的层级关系，选择项目更易维护的形式;

```jsx
function RouteContent() {
  return useRoutes([
    { path: "/", element: <Home /> },
    { path: "/users/:id", element: <User /> },
    { path: "*", element: <NotFound /> },
  ]);
}
```

## 如何避免路由结构与 UI 布局失配？

- 可见边界: 检查每个有 children 的布局是否包含 Outlet，并验证父路径、索引路由、深层路径和未匹配路径;
- 数据模式: 组件 Routes 不会自动获得所有框架 loader 能力，先明确使用模式再加入数据加载;
