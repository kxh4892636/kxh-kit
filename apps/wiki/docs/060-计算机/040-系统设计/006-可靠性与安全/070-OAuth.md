# OAuth 2.0 授权

## OAuth 2.0 怎样让应用获得有限资源访问权？

- OAuth 2.0: 授权框架，使客户端无需拿到用户密码，也能在获准范围内访问受保护资源;
- 资源所有者: 有权批准访问的用户或系统;
- 客户端: 希望调用资源的应用，可能是能保密的服务端，也可能是无法保密的浏览器或移动应用;
- 授权服务器: 验证身份与授权条件后发放令牌;
- 资源服务器: 验证访问令牌及权限后提供资源;
- Scope: 表达授予的权限范围，具体字符串和含义由资源系统定义;
- Access Token: 调用资源时出示的授权凭据，格式不必是 JWT;

## 授权码流程怎样避免把密码交给第三方？

```text
客户端 → 浏览器前往授权服务器：client_id、scope、redirect_uri 等
用户 → 授权服务器登录并同意
授权服务器 → 已登记回调地址：一次性授权码
客户端 → 令牌端点：授权码与所需校验信息
客户端 → 资源服务器：访问令牌
```

- 客户端认证: 机密客户端可以使用凭据，公开客户端不能安全保存共享 secret，不能强制每个客户端都内置密钥;
- PKCE: 客户端先承诺一个随机校验值的摘要，换令牌时出示原值，使被截获授权码更难被他人兑换;
- Refresh Token: 在获准条件下用来换取新访问令牌，属于需要保护的长期凭据，不直接用于普通资源调用;
- 安全条件: 使用 TLS、严格回调地址校验和适当的请求绑定，遵循 [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)的安全要求;
- 原文修正: 不以直接返回访问令牌的旧式浏览器流程作为推荐范例，也不说 OAuth 缺乏标准实现规则;
