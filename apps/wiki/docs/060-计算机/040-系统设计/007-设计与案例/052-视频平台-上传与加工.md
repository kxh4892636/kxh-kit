# 视频平台上传与加工

## 处理队列怎样组织长时间视频任务？

- 异步目的: 转码可能远超普通 API 超时, 队列把上传与昂贵处理解耦并吸收突发;
- 任务状态: 保存 videoID、输入版本、处理步骤和输出位置, 失败后可以从明确边界重试;
- 幂等输出: 同一输入和处理参数应生成可识别的结果, 重试不能重复发布多个互相冲突的版本;

## 队列工具与投递保证怎么选？

- 工具示例: 原文用 SQS 或 RabbitMQ 作任务队列;
- 前提: 处理保证仍靠应用的确认与重试逻辑;

## 文件分块如何帮助上传和媒体处理？

- 分块: 把大文件分成可独立传输或处理的小片段, 减少失败后重传范围;
- 去重条件: 只有建立内容识别和复用机制, 分块才可能节省重复数据, 切碎文件本身不会自动去重;

## 切片边界能带来什么、不能保证什么？

- 切片边界: 可按时间、关键帧或内容场景规划;
- 收益: 场景感知有助于编码优化;
- 不保证: 任何网络下都不会卡顿;
- 原文归因: Netflix 场景切块的叙述只是作者给的设计示例;
- 边界: 不当作全部现网实现事实;

## 内容检查如何阻止不合规视频直接发布？

- 检查阶段: 根据平台要求检测内容类型、版权、敏感内容和分级等, 具体判断规则由产品定义;
- 人工复核: 自动检查不确定或失败时, 进入专门复核任务, 必要时使用隔离队列保存问题输入;
- 状态边界: 尚未审核完成的对象可以已存储, 但不能因此被公开检索或播放;
- 失败区分: 不符合内容规则与基础设施暂时失败应分别处理, 不能无限重试业务拒绝;

## 转码如何生成适配不同设备的版本？

- 转码: 解码原始媒体, 再以目标编码、码率和分辨率生成输出, 降低传输或存储成本并适配设备;
- 清晰度梯度: 生成 4K、1440p、1080p、720p 等版本;
- 依据: 内容质量与带宽需求;
- 流水线边界: 原文把转码和清晰度转换分为两步, 真实实现可以在同一处理阶段生成多种输出;

## 转码产物与工具怎么定？

- 附加产物: 按需要生成缩略图、字幕和播放清单, 并保持它们与视频版本对应;
- 工具: FFmpeg 或云端 MediaConvert;
- 完成后: 产物写入对象存储, 并更新发布状态;
