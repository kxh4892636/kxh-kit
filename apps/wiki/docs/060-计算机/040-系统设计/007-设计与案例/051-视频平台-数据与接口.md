# 视频平台数据与接口

## 视频元数据与观看记录怎样建模？

| 表         | 关键字段                                                            | 作用                       |
| ---------- | ------------------------------------------------------------------- | -------------------------- |
| users      | id、name、email、dob、location、createdAt                           | 用户资料                   |
| videos     | id、userID、title、description、thumbnailURL、streamURL、uploadedAt | 视频信息与媒体引用         |
| tags       | id、value                                                           | 标签字典                   |
| video_tags | videoID、tagID                                                      | 补齐一个视频多个标签的关联 |
| views      | userID、videoID、offset、platform、createdAt                        | 观看和续播信息             |
| comments   | userID、videoID、comment、createdAt                                 | 用户评论                   |

- 原图修正: videos 里单个 tags UUID 无法表示多个标签;
- 改法: 显式增加多对多关联;
- 内容存储: 数据库保存元数据与对象引用, 大视频字节存对象存储或分布式文件存储;

## 发布状态与存储选型怎么定？

- 发布状态: 可补 `uploaded`、`processing`、`ready`、`failed`;
- 目的: 未处理完的视频不会被当成可播放内容;
- 存储选择: 元数据关系与观看事件的访问模式不同, 可以分别选择关系库或分布式存储;

## 上传 API 如何表达异步处理？

```text
uploadVideo(title, description, byteStream, tags?) → videoID, status
```

- 数据通道: 上传服务授权, 并接收或签发上传地址;
- 做法: 大文件交存储层, 不长时间占用普通 API 线程;
- 响应语义: 原文返回 boolean, 此处区分原件已接收与处理完成可播放;
- 查询进度: 客户端用 `videoID`;

## 上传失败的恢复前提是什么？

- 失败恢复: 对分块上传记录已完成部分, 允许断点重试并验证完整性;
- 发布前提: 原件持久保存成功后再进入处理队列, 避免任务引用不存在或未完成的文件;

## 播放与搜索接口应携带哪些信息？

```text
streamVideo(videoID, codec, resolution, offset?) → manifest / stream
searchVideo(query, nextPage?) → VideoPage
comment(videoID, text, requestID?) → commentID
```

- 播放参数: 编码如 H.264、H.265、VP9, 清晰度与偏移用于选版本;
- 边界: 不要承诺任何设备都支持所有编码;
- 搜索游标: 以稳定 nextPage 表达分页, 避免一次返回整个匹配集合;

## 评论与权限在接口层怎么处理？

- 评论: 验证用户与视频状态, 按请求 ID 处理重试, 评论删除和审核也应有明确状态;
- 权限: 在签发播放地址前确认订阅、资源权限和地域规则, 不能只依赖 videoID 不易猜测;

## 服务和媒体路径如何划分？

```text
用户 → API 入口 → 用户 / 搜索 / 播放服务 → 元数据存储
上传者 → 媒体服务 → 原件存储 → 任务队列 → 处理 worker
处理产物 → 对象存储 → CDN → 播放器
播放事件 → 分析管道
```

- 媒体服务: 负责上传和处理状态, worker 可按 CPU 或加速设备需求独立扩展;
- 播放服务: 校验权限并提供清单或播放信息, 实际大文件尽量由存储与 CDN 交付;
- 搜索服务: 维护可检索元数据, 不把全文搜索负担全部放在事务库;

## 分析与通信方式怎么定位？

- 分析服务: 消费播放事件形成指标, 避免统计失败阻塞观看;
- 通信方式: 按接口选 HTTP 或 gRPC;
- 服务发现与网格: 按规模采用, 不是每个教学系统都必需;
