# 事务

## 最简单的事务怎么写？

```ts
const pet = await db.transaction().execute(async (trx) => {
  const person = await trx
    .insertInto("person")
    .values({ first_name: "Jennifer" })
    .returning("id")
    .executeTakeFirstOrThrow();

  return await trx
    .insertInto("pet")
    .values({ owner_id: person.id, name: "Catto" })
    .returningAll()
    .executeTakeFirstOrThrow();
});
```

- 回调抛错自动回滚, 正常返回自动提交; 返回值就是事务返回值;
- 事务内的读写全部用 `trx`; 用外层 `db` 会脱离事务, SQLite 下抢写锁;

## 要自己控制提交时机怎么办？

```ts
const trx = await db.startTransaction().execute();

try {
  await trx.insertInto("person").values({ first_name: "A" }).execute();
  await trx.commit().execute();
} catch (error) {
  await trx.rollback().execute();
  throw error;
}
```

- 忘 `commit()`: 连接释放时回滚;
- 症状: 写成功了但查不到;
- 排查: 见 [查询与访问路径](../000-服务端知识/050-数据访问/030-查询与访问路径.md);

## 部分回滚和禁忌是什么？

```ts
const sp = await trx.savepoint("after_audit").execute();
await sp.rollbackToSavepoint("after_audit").execute(); // 只回滚这一段
```

- 保存点: 只在 `startTransaction()` 的受控事务上可用;
- 边界: `transaction()` 回调里拿不到;
- 禁忌一: 用外层 `db` 写, 不在事务内, SQLite 下会等锁超时;
- 禁忌二: 嵌套 `db.transaction()` 直接抛错;
- 禁忌三: 事务里 `db.destroy()` 会回滚;
- 禁忌四: 事务里做 RPC、发消息、等用户输入会把写锁占住;
- 边界规矩: 见 [Repository 与事务](../000-服务端知识/050-数据访问/010-Repository与事务.md);

## 出错怎么查？

- `SQLITE_BUSY: database is locked` 是抢不到写锁;
- 处理: 缩短事务、开 WAL、加 `timeout`;
- 配置: 见 [001](./001-安装与连接.md);
- 看实际执行的语句: 开 log 回调, 见 [009](./009-排障与SQLite差异.md);
