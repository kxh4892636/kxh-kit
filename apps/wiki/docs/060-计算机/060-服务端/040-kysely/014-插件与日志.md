# 插件与日志

## 常用插件有哪些？

```ts
import { CamelCasePlugin, Kysely, ParseJSONResultsPlugin, SqliteDialect } from "kysely";

export const db = new Kysely<Database>({
  dialect: new SqliteDialect({ database: new SQLite("dev.sqlite") }),
  plugins: [new ParseJSONResultsPlugin(), new CamelCasePlugin()],
});
```

| 插件                       | 解决什么                             | 什么时候装              |
| -------------------------- | ------------------------------------ | ----------------------- |
| `ParseJSONResultsPlugin`   | JSON 文本列解析成对象                | SQLite 上做嵌套查询必装 |
| `CamelCasePlugin`          | 库里 `snake_case` ↔ 代码 `camelCase` | 代码统一用驼峰时        |
| `DeduplicateJoinsPlugin`   | 动态拼接导致的重复 join              | 有可选 join 分支时      |
| `HandleEmptyInListsPlugin` | 空 `in ()` 语法错误                  | 过滤条件可能传空数组    |

- 全局插件写在 `new Kysely({ plugins })`，单个查询用 `.withPlugin(new XxxPlugin())`;

## 驼峰插件要注意什么？

- `Database` 的键必须写成驼峰，否则类型对不上; 库结构不用改;
- `{ firstName: "Ada" }` 会生成 `insert into "person" ("first_name") values (?)`;
- codegen 生成类型时加 `--camel-case` 保持一致;

## 查询日志怎么开？

```ts
log(event) {
  if (event.level === "error") {
    console.error("query failed", { sql: event.query.sql, error: event.error });
    return;
  }
  if (event.queryDurationMillis > 200) {
    console.warn("slow query", { sql: event.query.sql, ms: event.queryDurationMillis });
  }
}
```

- 只想要 SQL 不想要参数: `log: ["query", "error"]`;
- `LogEvent` 字段: `level`（判别字段）、`query.sql`、`query.parameters`、`queryDurationMillis`、`error`;
- `parameters` 可能含个人信息，落盘前脱敏; 生产别开全量 `"query"` 日志;
- 只想看一条 SQL 用 `.compile()`，见 [动态条件与原生 SQL](./006-动态条件与原生SQL.md)。
