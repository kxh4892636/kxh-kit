# 连接、聚合与嵌套结果

## 表怎么连？

```ts
const rows = await db
  .selectFrom("person")
  .leftJoin("pet", "pet.owner_id", "person.id")
  .select(["person.id", "pet.name as pet_name"]) // leftJoin 后 pet.name 带 null
  .execute();

// 多条件: onRef 比两列，on 比列与值
.innerJoin("pet", (join) => join.onRef("pet.owner_id", "=", "person.id").on("pet.species", "=", "dog"))
```

| 方法        | 语义                      | SQLite |
| ----------- | ------------------------- | ------ |
| `innerJoin` | 两边都匹配才留            | 支持   |
| `leftJoin`  | 左表全留, 右表缺失补 null | 支持   |
| `rightJoin` | 右表全留                  | 3.39+  |

- `.select()` 必须写在 join 之后, 否则引用的表还不在上下文里;

## 只查「有没有」、聚合怎么写？

```ts
// exists: 只关心有没有，通常比 in 先短路
.where((eb) => eb.exists(eb.selectFrom("pet").select("pet.id").whereRef("pet.owner_id", "=", "person.id")))

// 聚合与分组
const rows = await db
  .selectFrom("person")
  .innerJoin("pet", "pet.owner_id", "person.id")
  .select((eb) => ["person.id", eb.fn.count<number>("pet.id").as("pet_count")])
  .groupBy("person.id")
  .having((eb) => eb.fn.count("pet.id"), ">", 1)
  .execute();
```

- 聚合函数: `eb.fn.count / countAll / avg / sum / max`, 泛型参数决定结果类型;
- join 后行会重复; 要数人就用 `count(distinct 列)` 的 `sql` 片段;
- 子查询只选一列, 别先 `execute` 再塞数组;

## 一次查出主子表怎么写？

```ts
import { jsonArrayFrom, jsonObjectFrom } from "kysely/helpers/sqlite";

const rows = await db
  .selectFrom("person")
  .selectAll("person")
  .select((eb) => [
    jsonArrayFrom(
      eb
        .selectFrom("pet")
        .select(["pet.id", "pet.name"])
        .whereRef("pet.owner_id", "=", "person.id"),
    ).as("pets"),
    jsonObjectFrom(
      eb.selectFrom("pet").select(["pet.id"]).whereRef("pet.owner_id", "=", "person.id").limit(1),
    )
      .$notNull() // 确定一定有一行时用它，省掉业务层判空
      .as("favorite_pet"),
  ])
  .execute();
```

- 必须用 `whereRef` 关联外表; 写成 `where` 就成了常量条件;
- 必须装 `ParseJSONResultsPlugin`, 否则拿到的是 JSON 字符串; 见 [001](./001-安装与连接.md);
- helper 的 import 路径跟方言绑定; SQLite 用 `kysely/helpers/sqlite`;
- 对象默认类型是 `| null`, 因为 Kysely 不知道关联行一定存在;
- 子查询要复用就包成函数, 入参用 `Expression<number>`, 调用方传 `eb.ref("person.id")`;

## 什么情况下该换成两次查询？

| 做法             | 查询次数 | 适用                  |
| ---------------- | -------- | --------------------- |
| 嵌套 JSON 查询   | 1        | 少量主表行 + 子表列表 |
| 两次查询内存拼装 | 2        | 主表要分页、子表很宽  |

- 关联列没索引时, 每条主表行都全表扫描, 见 [003](./003-建表与增删改查.md);
- 子表几十列 × 上千行, JSON 聚合会把结果集撑大, 改两次查询;
- 判断依据见 [查询与访问路径](../000-服务端知识/050-数据访问/030-查询与访问路径.md);
