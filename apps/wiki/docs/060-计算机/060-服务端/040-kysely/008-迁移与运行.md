# 迁移与运行

## 迁移文件怎么写？

```ts title="migrations/2026-01-01T00-00-00-init.ts"
import { Kysely, sql } from "kysely";

export async function up(db: Kysely<any>): Promise<void> {
  await db.schema
    .createTable("person")
    .addColumn("id", "integer", (col) => col.primaryKey().autoIncrement())
    .addColumn("created_at", "text", (col) => col.notNull().defaultTo(sql`CURRENT_TIMESTAMP`))
    .execute();
}

export async function down(db: Kysely<any>): Promise<void> {
  await db.schema.dropTable("person").execute();
}
```

- 参数必须是 `Kysely<any>`; 迁移冻在时间里, 不跟业务类型走;
- `up` 必需, `down` 可选; 文件名用 ISO 时间戳前缀, 按字母序执行;
- 合入主干后不再改内容, 只追加新迁移; 理由见 [迁移与演进](../000-服务端知识/050-数据访问/020-迁移与演进.md);

## 改表怎么写？

| 操作      | 写法                                                    |
| --------- | ------------------------------------------------------- |
| 加列      | `alterTable('t').addColumn('c', 'text', cb)`            |
| 改列名    | `alterTable('t').renameColumn('old', 'new')`            |
| 删列      | `alterTable('t').dropColumn('c')`                       |
| 加/删索引 | `createIndex(...)` / `dropIndex('i').ifExists()`        |
| 建/删视图 | `createView('v').as(查询)` / `dropView('v').ifExists()` |

- 加非空列必须带 `defaultTo`, 否则已有行违反约束;
- SQLite 不支持改列类型、加外键; 改结构走: 建新表 → `insert ... select` → 删旧表 → 改名, 整段放一个事务;
- 迁移里能改数据; `db` 就是普通连接, 用 `sql` 模板加 `update ... where ...`, 数据量大就分批;
- 别在迁移里写业务逻辑, 条件写死在当时的数据形态上;

## 怎么跑迁移？

```bash
npm i -D kysely-ctl
npx kysely init                      # 生成 .config/kysely.config.ts
npx kysely migrate:make add_pet_age  # 新建迁移
npx kysely migrate:latest            # 跑到最新（migrate:up / :down 单个，migrate:rollback 全撤）
npx kysely migrate:list              # 看已执行 / 待执行
```

- 配置文件默认在 `.config/` 下, 找不到就先看这里; Kysely 建 `kysely_migration` 与 `kysely_migration_lock` 两张表, 加库级锁后多进程并发也串行;

## 不装 CLI 怎么写脚本跑？

```ts
import { promises as fs } from "node:fs";
import * as path from "node:path";
import { FileMigrationProvider, Migrator } from "kysely/migration";
import { db } from "./db";

const migrator = new Migrator({
  db,
  // 必须是绝对路径，相对路径会静默找不到迁移
  provider: new FileMigrationProvider({
    fs,
    path,
    migrationFolder: path.join(import.meta.dirname, "../migrations"),
  }),
});

const { error } = await migrator.migrateToLatest(); // 也有 migrateUp / migrateDown / migrateTo(名字)
if (error) process.exitCode = 1; // 失败必须让退出码非 0，且不要继续启动应用
await db.destroy();
```

## 上线和测试怎么守？

- 部署顺序固定: 先跑迁移, 再启动新代码; `down` 只还原结构, 数据回不去, 生产回滚优先用「新迁移反向修」; 规矩见 [迁移与演进](../000-服务端知识/050-数据访问/020-迁移与演进.md);
- 测试用 `new SQLite(":memory:")` 加一遍 `migrateToLatest()`, 用完 `await db.destroy()` 否则挂住进程; 分层见 [测试策略](../000-服务端知识/060-观测与交付/040-测试策略.md);
