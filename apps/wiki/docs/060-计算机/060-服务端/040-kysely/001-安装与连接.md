# 安装与连接

## 装什么包？

```bash
npm init -y && npm pkg set type=module
npm i kysely better-sqlite3
npm i -D typescript tsx @types/node @types/better-sqlite3
```

- 驱动: Kysely 不带驱动, 需自行安装;
- SQLite: 用 `better-sqlite3`; Postgres: 用 `pg`;
- `tsconfig`: 开 `strict: true`;
- 还需: `module` 设 `Preserve`, `moduleResolution` 设 `Bundler`;
- 少一个配置, 类型推导就失效, `tsx` 也解析不了;

## db 实例怎么写？

```ts title="src/db.ts"
import SQLite from "better-sqlite3";
import { Kysely, ParseJSONResultsPlugin, SqliteDialect } from "kysely";
import type { Database } from "./types";

const sqlite = new SQLite("dev.sqlite", { timeout: 5000 });
sqlite.pragma("journal_mode = WAL");

export const db = new Kysely<Database>({
  dialect: new SqliteDialect({ database: sqlite }),
  plugins: [new ParseJSONResultsPlugin()],
});
```

- `ParseJSONResultsPlugin`: 把 JSON 文本列解析成对象;
- 前提: 嵌套查询必装;
- 详见: [005](./005-连接聚合与嵌套结果.md);
- 驼峰命名: 加 `CamelCasePlugin`, 见 [002](./002-表结构与类型.md);
- 单条查询: 用 `.withPlugin(new XxxPlugin())`;
- `DeduplicateJoinsPlugin`: 去掉重复 join;
- `HandleEmptyInListsPlugin`: 兜住空的 `in ()`;
- 慢查询与错误日志见 [009](./009-排障与SQLite差异.md);

## 怎么确认连上、怎么关库？

```ts
const { rows } = await sql<{ ok: number }>`select 1 as ok`.execute(db);

process.on("SIGTERM", async () => {
  await db.destroy();
  process.exit(0);
});
```

- 驱动是懒初始化; 建实例成功不等于连通, 必须真跑一条查询; 连不上就在启动阶段退出;
- 不关库会占着文件句柄, 进程退不掉; 谁创建谁关闭, 别两边都关;
- 启动顺序: 见 [配置与启动顺序](../000-服务端知识/010-基础模型/030-配置与启动顺序.md);
- 关库时机: 见 [退出顺序](../000-服务端知识/040-可靠性/050-退出顺序.md);
