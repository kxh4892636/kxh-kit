# 运行迁移与上线

## 用 kysely-ctl 怎么跑？

```bash
npm i -D kysely-ctl
npx kysely init                      # 生成 .config/kysely.config.ts
npx kysely migrate:make add_pet_age  # 新建迁移
npx kysely migrate:latest            # 跑到最新
npx kysely migrate:list              # 看已执行 / 待执行
```

```ts title=".config/kysely.config.ts"
export default defineConfig({ migrations: { migrationFolder: "migrations" } });
```

| 命令                   | 作用             |
| ---------------------- | ---------------- |
| `migrate:latest`       | 跑所有未执行的   |
| `migrate:up` / `:down` | 跑 / 撤一个      |
| `migrate:rollback`     | 撤销全部         |
| `sql "<query>"`        | 临时执行一条 SQL |

- 配置文件默认在 `.config/` 下，找不到就先看这里。

## 不装 CLI 怎么写脚本跑？

```ts
const migrator = new Migrator({
  db,
  // migrationFolder 必须是绝对路径，相对路径会静默找不到迁移
  provider: new FileMigrationProvider({
    fs,
    path,
    migrationFolder: path.join(import.meta.dirname, "../migrations"),
  }),
});

const { error } = await migrator.migrateToLatest();
if (error) process.exitCode = 1;
await db.destroy();
```

- `Migrator` 来自 `kysely/migration`; 其他方法: `migrateUp()`、`migrateDown()`、`migrateTo(名字)`;
- 失败必须让退出码非 0，并且不要继续启动应用。

## 上线要守哪些规矩？

- 部署顺序固定: 先跑迁移，再启动新代码;
- `down` 只还原结构，数据回不去; 生产回滚优先用「新迁移反向修」;
- 兼容性变更的分阶段做法见 [接口契约](../000-服务端知识/020-契约与错误/010-契约.md)。

## 测试怎么重建库？

- 每个测试文件一个 `new SQLite(":memory:")` 库 + 跑一遍 `migrateToLatest()`，得到干净结构;
- 用完 `await db.destroy()`，否则挂住测试进程。
