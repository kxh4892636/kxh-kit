# 嵌套关联结果

## 一次查出主子表怎么写？

```ts
import { jsonArrayFrom, jsonObjectFrom } from "kysely/helpers/sqlite";

const rows = await db
  .selectFrom("person")
  .selectAll("person")
  .select((eb) => [
    jsonArrayFrom(
      eb
        .selectFrom("pet")
        .select(["pet.id", "pet.name"])
        .whereRef("pet.owner_id", "=", "person.id")
        .orderBy("pet.name"),
    ).as("pets"),

    jsonObjectFrom(
      eb
        .selectFrom("pet")
        .select(["pet.id", "pet.name"])
        .whereRef("pet.owner_id", "=", "person.id")
        .limit(1),
    ).as("favorite_pet"),
  ])
  .execute();

console.log(rows[0].pets[0].name); // { id: number; name: string }[]
console.log(rows[0].favorite_pet?.name); // { id: number; name: string } | null
```

- 必须用 `whereRef` 关联外表，写成 `where` 就成了常量条件;
- 必须装 `ParseJSONResultsPlugin`，否则拿到的是 JSON 字符串:

```ts
new Kysely<Database>({ dialect, plugins: [new ParseJSONResultsPlugin()] });
```

- helper 的 import 路径跟方言绑定: SQLite 用 `kysely/helpers/sqlite`;

## 结果是 null 怎么办？

- Kysely 不知道关联行一定存在，所以对象是 `| null`;
- 确定存在就加 `.$notNull()`: `jsonObjectFrom(子查询).$notNull().as("first_pet")`;
- 要复用就把它包成函数，入参用 `Expression<number>`，调用方传 `ref("person.id")`;

## 什么时候不该用嵌套查询？

| 做法             | 查询次数 | 适用                  |
| ---------------- | -------- | --------------------- |
| 嵌套 JSON 查询   | 1        | 少量主表行 + 子表列表 |
| 两次查询内存拼装 | 2        | 主表要分页、子表很宽  |

- 关联列（`owner_id`）没索引时，每条主表行都全表扫描;
- 子表几十列 × 上千行，JSON 聚合会把结果集撑大，改两次查询;
