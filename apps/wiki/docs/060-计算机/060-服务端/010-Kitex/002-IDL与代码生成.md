# IDL 与代码生成

## 一份 IDL 决定两端的哪些代码？

- 机制: 一份 IDL 定义方法形状，`kitex` 生成 `kitex_gen`; 服务端与客户端都基于生成桩写代码; 契约先行与字段演进见 [接口契约与演进](../000-服务端知识/020-契约与错误/010-契约不变量与形状.md);

## 一个 Thrift IDL 包含哪些部分？

```thrift
namespace go user

struct GetUserRequest {
  1: required i64 id
}

struct GetUserResponse {
  1: optional string name
}

service UserService {
  GetUserResponse GetUser(1: GetUserRequest req)
}
```

- 字段: field id 是字段在二进制协议里的身份，发布后不能改含义或复用给其他字段; 新增字段用 `optional`，未设置时不序列化，也能区分「没传」与「传了零值」;

## kitex 命令怎么装、flag 怎么选？

```powershell
go install github.com/cloudwego/kitex/tool/cmd/kitex@v0.16.3
go install github.com/cloudwego/thriftgo@v0.4.5
kitex --version
kitex -module example.com/user-service idl/user.thrift
```

| flag       | 作用                                                     |
| ---------- | -------------------------------------------------------- |
| `-module`  | 生成代码的 Go module path; 必须与 `go.mod` 一致          |
| `-service` | 额外生成 Server scaffold; 不指定时只生成类型与 Client 桩 |
| `-use`     | 复用另一 module 已生成的 `kitex_gen`，避免重复类型       |
| `-I`       | 增加被 `include` 的 IDL 搜索目录                         |

- 版本与产物: Kitex tool `v0.16.3`、thriftgo `v0.4.5`，本机与 CI 用同一组版本，避免生成结果漂移; 生成 `kitex_gen/user` 与 `kitex_gen/user/userservice`;
- 派生与复跑: `kitex_gen` 不手改、不放业务逻辑，业务写 Handler 与 `internal/`; 改 IDL 后重复同一条命令，先看生成 diff 再改业务; 删除、重命名、字段变化都可能破坏调用方;

## Protobuf 请求什么时候走标准 gRPC？

- 触发: IDL 含 stream method 自动切 gRPC; 没有 stream 也要 gRPC 互通时显式指定传输协议;

```go
func newGRPCClient() (userservice.Client, error) {
	return userservice.NewClient("user-service",
		client.WithTransportProtocol(transport.GRPC), // 无 stream 但要求 gRPC 互通
	)
}
```

- 支持面: Kitex 只支持 proto3; `option go_package` 要指向稳定导入路径; unary 默认走 Kitex Protobuf，自定义信封，**不是标准 gRPC wire**;
- 流式写法: 见 [007-StreamX流式](./008-StreamX流式.md); 传输常量与对端要求见 [006-协议与连接](./007-协议与连接.md);
