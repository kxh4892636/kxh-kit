# IDL 与代码生成

## 一份 IDL 生成哪些代码？

- `kitex_gen/user`: 结构体与编解码; `kitex_gen/user/userservice`: Server、Client 与 Handler 接口;
- 服务端与客户端都基于生成桩写代码, 契约先行;

## 一个 Thrift IDL 最小形状是什么？

```thrift
namespace go user

struct GetUserRequest {
  1: required i64 id
}

struct GetUserResponse {
  1: optional string name
}

service UserService {
  GetUserResponse GetUser(1: GetUserRequest req)
}
```

- field id 是字段在二进制协议里的身份, 发布后不可改含义、不可复用;
- 新增字段用 `optional`: 未设置时不序列化, 且能区分「没传」与「传了零值」;

## kitex 命令怎么装、flag 怎么选？

```powershell
go install github.com/cloudwego/kitex/tool/cmd/kitex@v0.16.3
go install github.com/cloudwego/thriftgo@v0.4.5
kitex -module example.com/user-service idl/user.thrift
```

| flag       | 作用                                                     |
| ---------- | -------------------------------------------------------- |
| `-module`  | 生成代码的 module path; 必须与 `go.mod` 一致             |
| `-service` | 额外生成 Server scaffold; 不指定时只生成类型与 Client 桩 |
| `-use`     | 复用另一 module 已生成的 `kitex_gen`, 避免重复类型       |
| `-I`       | 增加被 `include` 的 IDL 搜索目录                         |

- 版本固定: 本机与 CI 用同一组 tool 与 thriftgo, 否则生成结果漂移;
- `kitex_gen` 不手改、不放业务逻辑; 改完 IDL 复跑同一条命令, 先看生成 diff 再改业务;

## Protobuf 请求什么时候走标准 gRPC？

- 自动切: IDL 含 stream method;
- 显式切: 没有 stream 但要 gRPC 互通, 加 `client.WithTransportProtocol(transport.GRPC)`;
- 都没加时 unary 走 Kitex Protobuf: 自定义信封, 不是标准 gRPC wire;
- 只支持 proto3; `option go_package` 要指向稳定导入路径;

```go
func newGRPCClient() (userservice.Client, error) {
	return userservice.NewClient("user-service",
		client.WithTransportProtocol(transport.GRPC),
	)
}
```
