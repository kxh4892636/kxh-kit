# 服务端开发

## Server 怎么装配并启动？

- 骨架: 实现生成的服务接口，用 `NewServer` 装配选项后 `Run`; 退出时序与预算见 [优雅退出](../000-服务端知识/040-可靠性/050-退出顺序.md);

```go
func main() {
	svr := userservice.NewServer(
		new(UserServiceImpl),
		server.WithServiceAddr(&net.TCPAddr{Port: 8888}), // 不设置时缺省 :8888
		server.WithServerBasicInfo(&rpcinfo.EndpointBasicInfo{ServiceName: "user-service"}),
		server.WithExitWaitTime(5*time.Second),
		server.WithEnableContextTimeout(true), // v0.9.0+
		server.WithMetaHandler(transmeta.ServerTTHeaderHandler),
	)
	if err := svr.Run(); err != nil {
		log.Fatalf("run user service: %v", err)
	}
}
```

- 上游 deadline: 需 TTHeader 协议、两端 MetaHandler、Client 设了 `RPCTimeout`，并打开 `WithEnableContextTimeout`;
- `WithReadWriteTimeout`: 只限制网络读写等待（默认 5s），不限制 Handler 执行时间;

## Handler 里错误和 context 怎么处理？

```go
type UserServiceImpl struct{}

func (s *UserServiceImpl) GetUser(ctx context.Context, req *api.GetUserRequest) (*api.GetUserResponse, error) {
	if req == nil || req.Id <= 0 {
		return nil, kerrors.NewBizStatusError(40001, "invalid user id")
	}
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	name := "Ada"
	return &api.GetUserResponse{Name: &name}, nil
}
```

- 业务拒绝: 用 `kerrors.NewBizStatusError(code, message)`; 系统错误保留 error chain 交框架层; 业务码语义与脱敏见 [错误分类与响应](../000-服务端知识/020-契约与错误/030-错误分层与响应.md);
- context: 向下传，不存进长期对象; 响应每请求新建，不复用可能被并发修改的对象; 生成代码通常保证 req 非空，防御性 nil 检查成本低;

## Server 选项分别管哪段生命周期？

| 选项                              | 语义                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `WithServiceAddr`                 | 监听地址，缺省 `:8888`                                          |
| `WithServerBasicInfo`             | 服务身份，注册、日志与链路标签都依赖                            |
| `WithRegistry`                    | 启动时注册、退出时注销                                          |
| `WithMiddleware`                  | 注册顺序决定调用顺序，先注册者包裹后注册者                      |
| `WithReadWriteTimeout`            | 传输读写等待，默认 5s                                           |
| `WithExitWaitTime`                | 退出等在途请求，默认 5s                                         |
| `WithEnableContextTimeout`        | v0.9.0+，把上游 deadline 写进 Server context                    |
| `WithLimit` / `WithQPSLimiter`    | 内置 QPS 与连接数限制，见 [005](./005-作用域与Suite.md)         |
| `WithListener` / `WithExitSignal` | 测试用临时端口与退出注入，见 [009](./010-超时重试与熔断限流.md) |

- 延伸: 注册中心与适配器见 [008-扩展与排障](./009-扩展与排障.md); 依赖组装顺序（配置 → 观测 → 外部依赖 → Repository → Service → Handler → Server）见 [配置与启动顺序](../000-服务端知识/010-基础模型/040-配置与启动顺序.md);
