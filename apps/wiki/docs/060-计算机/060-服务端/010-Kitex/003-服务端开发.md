# 服务端开发

## NewServer 怎么装配并启动？

```go
func main() {
	svr := userservice.NewServer(
		new(UserServiceImpl),
		server.WithServiceAddr(&net.TCPAddr{Port: 8888}), // 缺省 :8888
		server.WithServerBasicInfo(&rpcinfo.EndpointBasicInfo{ServiceName: "user-service"}),
		server.WithExitWaitTime(5*time.Second),
		server.WithEnableContextTimeout(true), // v0.9.0+
		server.WithMetaHandler(transmeta.ServerTTHeaderHandler),
	)
	if err := svr.Run(); err != nil {
		log.Fatalf("run user service: %v", err)
	}
}
```

- 全部选项与默认值见 [006-选项清单](./006-选项清单.md)，本篇不重复;
- 退出时序与预算见 [优雅退出](../000-服务端知识/040-可靠性/050-退出顺序.md)。

## Handler 里错误和 context 怎么写？

```go
func (s *UserServiceImpl) GetUser(ctx context.Context, req *api.GetUserRequest) (*api.GetUserResponse, error) {
	if req == nil || req.Id <= 0 {
		return nil, kerrors.NewBizStatusError(40001, "invalid user id")
	}
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	name := "Ada"
	return &api.GetUserResponse{Name: &name}, nil
}
```

- 业务拒绝: `kerrors.NewBizStatusError(code, message)`；系统错误原样返回，保留 error chain 给框架层;
- 响应每请求新建，不复用可能被并发修改的对象;
- 业务码语义与脱敏见 [错误分层与响应](../000-服务端知识/020-契约与错误/020-错误分层与响应.md)。

## 上游 deadline 什么时候能从 ctx 读到？

- 四个条件同时成立: 两端都是 TTHeader、两端都装了 MetaHandler、Client 设了 `RPCTimeout`、Server 开了 `WithEnableContextTimeout`;
- `WithReadWriteTimeout`（默认 5s）只限制网络读写等待，不限制 Handler 执行时间。
