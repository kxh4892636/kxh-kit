# 协议与连接

## 一条连接要定哪三件事？

- 三件事: 消息交互类型、传输协议常量、连接池行为;
- 前提: IDL、序列化、传输是三件事; 契约层见 [接口契约与演进](../000-服务端知识/020-契约与错误/010-契约不变量与形状.md);

## 消息交互分成哪几种？

| 类型      | 交互               | 约束                                                   |
| --------- | ------------------ | ------------------------------------------------------ |
| PingPong  | 一次请求、一次响应 | 常规 RPC，默认选择                                     |
| Oneway    | 只发不等业务响应   | 仅 Thrift; 可丢失，不承担可靠业务                      |
| Streaming | 一次调用内多次收发 | 处理 EOF、半关闭与取消，见 [007](./008-StreamX流式.md) |

- Thrift: 支持 PingPong、Oneway，以及 TTHeader Streaming 或基于 HTTP/2 的 streaming;
- Kitex Protobuf: 只支持 unary PingPong，不支持 streaming;
- gRPC: unary、client streaming、server streaming、bidirectional streaming;

## 传输协议常量怎么选？

| 对端要求             | Client 配置                                          |
| -------------------- | ---------------------------------------------------- |
| TTHeader             | `transport.TTHeader`（业务异常还需两端 MetaHandler） |
| Apache Thrift Framed | `transport.Framed`                                   |
| Thrift Buffered      | `transport.PurePayload`（不携带 TTHeader 元信息）    |
| TTHeaderFramed       | `transport.TTHeaderFramed`                           |
| 标准 gRPC            | `transport.GRPC`（普通 proto3 默认并不等于 gRPC）    |

```go
func newTTHeaderClient() (userservice.Client, error) {
	return userservice.NewClient("user-service",
		client.WithTransportProtocol(transport.TTHeader),
		client.WithMetaHandler(transmeta.ClientTTHeaderHandler),
	)
}
// Server 侧配对: server.WithMetaHandler(transmeta.ServerTTHeaderHandler)
```

- 版本默认: v0.13.0 起 Thrift 默认 Framed，旧版默认 PurePayload;
- 约定: 不要用默认值代替双方约定; 联调或升级前先确认两端版本与显式配置;

## 连接池怎么配？

- 默认模型: 长连接池，每个 address 维护可复用连接;
- 短连接: 每次建连，只在实例数量或连接约束要求时使用;
- gRPC: 走 HTTP/2 原生多路复用，一条连接承载多个并发 stream;

| 参数                | 语义                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| `MaxIdlePerAddress` | 每个目标的空闲连接上限; 池空时会新建连接，**不是并发连接硬上限**     |
| `MaxIdleTimeout`    | 空闲回收时间; 官方页示例与文字默认值不一致，必须显式设置并按版本核对 |
| `MaxIdleGlobal`     | 全局空闲连接上限，过小会降低复用率                                   |

- 调参依据: 下游实例数、并发、请求耗时、突发流量与文件描述符预算;
- 排查: 先按目标实例看 active、idle 与建连失败; 复用率过低先查 Client 是否复用;
