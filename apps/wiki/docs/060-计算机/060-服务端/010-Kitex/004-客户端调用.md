# 客户端调用

## Client 为什么必须复用？

- 结论: 只创建一次，每次调用只传 `context` 与请求对象; 每个请求 `NewClient` 会放大连接、CPU、配置拉取与 goroutine;

```go
func newUserClient() (userservice.Client, error) {
	return userservice.NewClient(
		"user-service",
		client.WithHostPorts("127.0.0.1:8888"),
		client.WithConnectTimeout(200*time.Millisecond),
		client.WithRPCTimeout(time.Second),
	)
}
```

- 构造: 第一个参数是 service name，服务发现与观测的核心维度; `ConnectTimeout` 默认 50ms、`RPCTimeout` 默认 0（不限时），生产必须显式设 `RPCTimeout`; 预算与幂等原则见 [超时预算](../000-服务端知识/040-可靠性/010-预算模型.md)、[重试与幂等](../000-服务端知识/040-可靠性/030-重试与幂等.md);

## 发起一次调用要写哪些代码？

```go
func getUser(ctx context.Context, cli userservice.Client, id int64) (*api.GetUserResponse, error) {
	resp, err := cli.GetUser(ctx, &api.GetUserRequest{Id: id})
	if err != nil {
		return nil, fmt.Errorf("get user %d: %w", id, err)
	}
	return resp, nil
}
```

- Call Option: 走方法尾参，只对单次生效，通常覆盖同类 Client Option; `callopt.WithRPCTimeout` 只用于特例; 寻址用 `WithHostPorts`（本地）、`WithResolver` + LoadBalancer（动态环境）、`callopt.WithURL`（URL/DNS），`callopt.WithHostPort` 单次直连只适合诊断;
- context: 只约束本地取消与 deadline; 跨进程传播要 TTHeader 与 MetaHandler，见 [006](./007-协议与连接.md);

## 调用失败怎么判断？

- 顺序: 先判 `err` 再读 response，失败时不假设 response 可用; 分类用 `errors.Is`、`kerrors.IsTimeoutError`、`kerrors.FromBizStatusError`; 业务拒绝不要当网络错误重试，框架错误入口 `ErrServiceDiscovery`、`ErrGetConnection`、`ErrRPCTimeout`、`ErrCircuitBreak`、`ErrOverlimit`，查法见 [008-扩展与排障](./009-扩展与排障.md);

```go
if biz := kerrors.FromBizStatusError(err); biz != nil {
	log.Printf("biz code=%d msg=%s", biz.BizStatusCode(), biz.BizMessage())
}
```

## 重试与熔断怎么配？

```go
func newRetryClient() (userservice.Client, error) {
	policy := retry.NewFailurePolicy()
	policy.WithMaxRetryTimes(2)
	policy.WithMaxDurationMS(800)
	return userservice.NewClient("user-service",
		client.WithRPCTimeout(300*time.Millisecond),
		client.WithFailureRetry(policy), // streaming 不支持常规重试
	)
}
```

- 前提: 接口幂等，且首次 + 退避 + 重试 < 上游 deadline; `WithBackupRequest` 的延迟阈值参考 TP99，过小会长期制造双倍请求;
- 熔断与降级: 默认不启用，错误率 50%、最小样本 200、OPEN 冷却 10s，用 `client.WithCircuitBreaker` 注入实例; 降级只在存在可接受替代结果时使用; gRPC streaming 不支持 unary fallback，返回旧值要标 freshness; 治理选项见 [005-Option配置体系](./005-作用域与Suite.md)，装配见 [009-治理与观测接入](./010-超时重试与熔断限流.md);
