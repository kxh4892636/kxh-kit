# Kitex 心智模型

## Kitex 与 Hertz 怎么分工？

- 定位: CloudWeGo 的 Go RPC 框架; 用 IDL 生成桩，专注服务间调用;
- 分工: 对外 HTTP 服务用 Hertz，服务之间用 Kitex;

## 一次 RPC 经过哪些环节？

```text
业务代码
  → Client middleware（日志、超时、重试等横切逻辑）
  → 服务发现 + 负载均衡（选一个实例）
  → 序列化 + 传输
  → Server 接收 → Server middleware → Handler
  → 原路返回响应
```

- 边界: 横切逻辑该放哪一层见 [请求生命周期](../000-服务端知识/010-基础模型/010-请求生命周期.md); 图示只覆盖对象名与装配点;

## IDL、Handler、Client、Option、Middleware 各管什么？

| 对象             | 职责                               |
| ---------------- | ---------------------------------- |
| IDL / 生成代码   | 定义契约，生成类型、编解码与调用桩 |
| Handler / Server | 实现方法，接收 RPC                 |
| Client           | 按契约调用远端方法                 |
| Option / Suite   | 在明确作用域配置行为               |
| Middleware       | 在业务前后执行公共逻辑             |

## 从 IDL 到上线分哪五步？

1. 写 Thrift 或 proto3 的 IDL: service、method、请求、响应;
2. `kitex` 命令生成 `kitex_gen` 桩;
3. 服务端实现 Handler，用 `NewServer` 启动;
4. 客户端用 `NewClient` 创建可复用 Client 后调用;
5. 按生产需要配寻址、超时、重试、熔断、可观测性;

## Server 与 Client 各创建几次？

```go
// 两端各建一次：Server 只 Run 一次，Client 只 New 一次，然后复用。
func runServer(h userservice.UserService) error {
	svr := userservice.NewServer(h) // 缺省监听 :8888
	return svr.Run()
}

func callOnce(ctx context.Context, cli userservice.Client, id int64) (*user.User, error) {
	return cli.GetUser(ctx, &user.GetUserRequest{Id: id})
}
```
