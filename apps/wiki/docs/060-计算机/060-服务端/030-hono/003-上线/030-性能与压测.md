# 性能与压测

## 适配器开关要不要动？

- 默认值: 两个开关已兼顾正确性与性能，没有压测证据不要改;
- `autoCleanupIncoming: false`: 只适合「请求方可信且一定读完 body」，否则半开连接拖死进程;

```ts
import { serve } from "@hono/node-server";

serve({
  fetch: app.fetch,
  overrideGlobalObjects: true, // 默认 true：轻量 Request/Response，更快
  autoCleanupIncoming: true, // 默认 true：未读完请求体时主动销毁连接
});
```

## 慢在哪一段，怎么量？

- 顺序: 先测量再改; Hono 侧只调适配器开关、压缩、缓存与路由，通用优化顺序归 000;
- 定位: `timing()` 写 `Server-Timing`，标出耗时落在哪一段;

## Server-Timing 怎么标出数据库与缓存耗时？

- 做法: `timing()` 收集各段耗时，写进标准 `Server-Timing` 响应头;

```ts
import { timing, setMetric, startTime, endTime, wrapTime } from "hono/timing";

app.use(timing());

app.get("/", async (c) => {
  setMetric(c, "region", "cn-north");
  startTime(c, "db");
  const rows = await db.query();
  endTime(c, "db");
  const cache = await wrapTime(c, "cache", redis.get("k"));
  return c.json({ rows, cache });
});
```

- 开关: `timing({ enabled: (c) => c.req.method === "POST" })` 只对部分请求开启;
- 输出: 浏览器 DevTools 可见;
- `wrapTime`: Promise 抛错时也结束计时; 只做诊断，长期指标走 APM/Prometheus;

## 优化与压测按什么顺序做？

- 压缩: `compress()`，默认 1KB 阈值，Node 必须显式挂;
- 缓存: ETag / `Cache-Control`;
- 数据: 减少 N+1 与串行 `await`; 大 JSON 分页或流式;
- 路由: 最后才换路由器;
- 压测: `npx hono benchmark --plain` 走 `app.request()`、不含网络; `bombardier -d 10s http://localhost:3000/` 含 Node HTTP 栈; 压测时关日志中间件;
- 指标: 看 P99、内存增长与事件循环延迟，不只看 RPS;
