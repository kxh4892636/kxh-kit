# 退出与探针

## 优雅退出为什么不能先关连接池？

- 顺序: 停止接收新连接 → 等在途请求 → 关连接池; 反了就是「连接池已关、请求还在用」;
- 责任: Node 适配器返回原生 `http.Server`，关闭责任在应用;
- 长连接: WebSocket 单独 `wss.close()` 并逐连接 `close(1001, ...)`; 定时任务要 `clearInterval`; 原理: [优雅退出](../../../000-服务端知识/040-可靠性/040-优雅退出/010-退出顺序.md);

```ts
import { serve } from "@hono/node-server";
import { app } from "./app.js";

const server = serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 3000) });

const shutdown = () => {
  server.close(async (err) => {
    if (err) {
      console.error(err);
      process.exit(1);
    }
    await pool.end(); // 在途请求结束后再关连接池
    process.exit(0);
  });
  setTimeout(() => process.exit(1), 10_000).unref(); // 兜底，小于平台宽限期
};

process.on("SIGTERM", shutdown);
process.on("SIGINT", shutdown);
```

## 探针为什么要分成 liveness 和 readiness？

- 分工: `/healthz` 永远快速返回、不查外部依赖; `/readyz` 才查数据库/缓存，失败只摘流量;
- 挂载: 探针端点不要套鉴权、限流、`bodyLimit`; 统一前缀时放在前缀之外;
- 参数: 间隔通常 5–10 秒、超时 1–3 秒、失败阈值 3 次; readiness 初始延迟覆盖冷启动; 语义: [健康检查与摘流](../../../000-服务端知识/040-可靠性/050-健康检查与摘流.md);

```ts
app.get("/healthz", (c) => c.json({ ok: true })); // liveness：不查依赖

app.get("/readyz", async (c) => {
  const ok = await checkDb(); // 关键依赖，失败只摘流量
  return c.json({ ok }, ok ? 200 : 503);
});
```
