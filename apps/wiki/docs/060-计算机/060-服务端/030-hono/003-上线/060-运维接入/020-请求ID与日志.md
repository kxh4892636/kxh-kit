# 请求 ID 与日志

## 请求 ID 怎么生成、复用与透传？

- 默认: 头名 `X-Request-Id`、长度上限 255; 合法请求头复用并自动回写响应头;
- 选项: `requestId({ headerName: "X-Trace-Id", limitLength: 128 })` 换头名并限长; `headerName: ""` 禁用复用与回写; `generator` 自定义生成;

```ts
import { Hono } from "hono";
import { requestId, type RequestIdVariables } from "hono/request-id";

const app = new Hono<{ Variables: RequestIdVariables }>();
app.use(requestId()); // 默认头名 X-Request-Id；合法请求头会复用，并自动回写响应头
```

- 透传: 跨服务调用时把 ID 带到下游请求头; 字段与脱敏: [日志与请求 ID](../../../000-服务端知识/060-观测与交付/010-日志与请求ID.md);

## 访问日志的字段、级别与脱敏怎么定？

- 开发: `logger()` 给方法、路径、状态码、耗时，`NO_COLOR` 关闭颜色;
- 生产: 用 `createMiddleware` 输出 JSON; 内置 `logger` 支持 `PrintFunc`（`logger((message, ...rest) => console.log(JSON.stringify({ message, rest })))`），但没有 requestId、不能按级别分流;

```ts
import { logger } from "hono/logger";
import { createMiddleware } from "hono/factory";

app.use(logger()); // 开发：方法、路径、状态码、耗时；NO_COLOR 关闭颜色

// 生产：JSON 结构化，必须带 requestId
export const accessLog = createMiddleware(async (c, next) => {
  const start = performance.now();
  await next();
  console.log(
    JSON.stringify({
      requestId: c.get("requestId"),
      method: c.req.method,
      path: c.req.path,
      status: c.res.status,
      ms: Math.round(performance.now() - start),
      error: c.error?.message,
    }),
  );
});
```

- 必记: `requestId`、method + path（用 `c.req.path`）、status + 耗时、`c.error`; 慢请求提级;
- 级别: `debug` 本地 / `info` 启动与关键动作 / `warn` 可恢复异常与降级 / `error` 未处理异常; 生产默认 `info`;
- 禁止进日志: 手机号/身份证/地址、`Authorization`/Cookie/密钥/连接串、完整请求体、内网地址与拓扑; 规范: [日志与请求 ID](../../../000-服务端知识/060-观测与交付/010-日志与请求ID.md);
