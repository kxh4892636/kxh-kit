# 请求 ID 与追踪

## 如何让每条日志都能串起来？

```ts
import { requestId, type RequestIdVariables } from "hono/request-id";

const app = new Hono<{ Variables: RequestIdVariables }>();

app.use("*", requestId());
app.get("/", (c) => c.text(c.get("requestId")));

// 自定义：从上游网关注入，或用平台 ID
app.use("*", requestId({ headerName: "X-Trace-Id", limitLength: 128 }));
```

- 默认用 `crypto.randomUUID()` 生成，若请求带了 `X-Request-Id` 头会直接复用;
- 想禁用复用，把 `headerName` 设为空字符串;
- 生成规则可自定义：`generator: (c) => ...`;

## 如何把 ID 传给调用方？

```ts
app.use("*", async (c, next) => {
  await next();
  c.res.headers.set("X-Request-Id", c.get("requestId"));
});
```

- 响应头带 ID，前端反馈问题时报这个 ID 就能定位;
- 与结构化日志中间件的配合见 [日志与结构化日志](./070-日志中间件.md);
- 跨服务调用时把 ID 透传到下游请求头，才能串起整条链路;

## 需要更细的链路耗时怎么办？

```ts
import { timing, startTime, endTime, wrapTime, setMetric } from "hono/timing";

app.use(timing());

app.get("/", async (c) => {
  setMetric(c, "region", "cn-north");
  startTime(c, "db");
  const rows = await db.query();
  endTime(c, "db");
  const cache = await wrapTime(c, "cache", redis.get("k"));
  return c.json({ rows, cache });
});
```

- 结果是标准 `Server-Timing` 响应头，浏览器 DevTools 能直接看到;
- 只想在部分请求上开启：`timing({ enabled: (c) => c.req.method === 'POST' })`;
- 它只用于诊断，正式指标走 Prometheus/APM，见 [Timing 与上下文存储](./080-Timing.md);
