# 健康检查

## 健康检查该检查什么？

```ts
app.get("/healthz", (c) => c.json({ ok: true }));

// 需要判断依赖时单独开一个就绪端点
app.get("/readyz", async (c) => {
  const ok = await checkDb();
  return c.json({ ok }, ok ? 200 : 503);
});
```

| 端点                   | 用途         | 检查内容                   |
| ---------------------- | ------------ | -------------------------- |
| `/healthz`（liveness） | 进程是否活着 | 不查外部依赖，永远快速返回 |
| `/readyz`（readiness） | 是否可接流量 | 数据库/缓存等关键依赖      |

- liveness 查库会导致「数据库抖动 → 容器被重启」的雪崩;
- readiness 失败只摘流量，不重启进程，才是正确语义;

## 端点应该放在哪些中间件之外？

```ts
app.get("/healthz", (c) => c.json({ ok: true })); // 先注册
app.use("/api/*", authMiddleware); // 鉴权只覆盖业务路径
```

- 鉴权、限流、bodyLimit 都可能让探针失败，探针端点不要套这些中间件;
- 探针响应要小：不要返回版本号、环境变量、内部地址;
- 若用统一前缀（如 `/api/v1`），探针放在前缀之外，避免版本升级时探针失效;

## 探针频率与超时怎么定？

- 间隔通常 5–10 秒，超时 1–3 秒，失败阈值 3 次;
- readiness 初始延迟要覆盖冷启动时间（连接池预热、加载配置）;
- 发布时配合 `terminationGracePeriodSeconds`，给优雅退出留足时间，见 [优雅退出](./030-优雅退出.md)。
