# 上下文存储

## 日志函数里怎么拿到当前请求的 Context？

- 机制: `contextStorage()` 把本次 `Context` 存进 `AsyncLocalStorage`，任意深度都能取;
- 前提: Node 原生支持 `AsyncLocalStorage`，无需配置;
- 位置: 日志函数、埋点、ORM 日志等非 Handler 代码，避免一路传参;

```ts
import { contextStorage, getContext, tryGetContext } from "hono/context-storage";

app.use(contextStorage()); // 必须第一个挂载
app.use(async (c, next) => {
  c.set("traceId", "abc");
  await next();
});

export const log = (msg: string) => {
  const c = tryGetContext(); // 无上下文时返回 undefined，不抛错
  console.log(`[${c?.var.traceId ?? "-"}] ${msg}`);
};
```

## contextStorage 为什么必须是第一个中间件？

- 顺序: 必须第一个挂; 挂载晚了，排在它之前的中间件整段都在存储作用域外;
- 异步: 后续异步链要正确 `await`，否则上下文丢失;

## 什么情况下取不到 Context？

- 没 `await` 的异步回调;
- 模块顶层调用;
- 定时器 / 任务队列里调用;
- `contextStorage()` 不是第一个;

## getContext 和 tryGetContext 怎么选？

- `getContext()`: 无上下文时抛错;
- `tryGetContext()`: 返回 `undefined`，工具函数里用它更安全;
- 分工: `c.set` 存本次请求的数据; `contextStorage` 解决「拿不到 `c`」; 深层函数读 `getContext().var.traceId`;
- 边界: 不要用它替代显式传参，核心业务逻辑仍收普通参数，便于测试;
