# 路由器与预设

## Hono 有哪几种路由器？

| 路由器          | 匹配方式                           | 特点                             |
| --------------- | ---------------------------------- | -------------------------------- |
| `RegExpRouter`  | 所有路由合成一个巨大正则，一次匹配 | 最快，但不支持全部路由写法       |
| `TrieRouter`    | 字典树                             | 支持全部模式，比线性匹配快得多   |
| `SmartRouter`   | 启动时探测并选用上面两者之一       | 默认组合，兼顾速度与兼容性       |
| `LinearRouter`  | 线性遍历，注册极快                 | 适合「每个请求都重建应用」的环境 |
| `PatternRouter` | 简单模式匹配                       | 体积最小                         |

- 常见框架（Express 系）用线性循环逐条匹配，路由越多越慢；RegExp 方案把匹配压成一次;
- 单条正则的代价: 极端路由组合下编译期更慢、可读性差，所以默认由 `SmartRouter` 兜底;

```ts
// 默认组合
new SmartRouter({ routers: [new RegExpRouter(), new TrieRouter()] });
```

## 三种预设怎么选？

```ts
import { Hono } from "hono"; // SmartRouter(RegExp + Trie)，默认推荐
import { Hono } from "hono/quick"; // SmartRouter(Linear + Trie)，冷启动优先
import { Hono } from "hono/tiny"; // PatternRouter，体积优先
```

| 预设         | 适合                                                          |
| ------------ | ------------------------------------------------------------- |
| `hono`       | 长期运行的服务：Node、Deno、Bun、Fastly；启动稍慢但跑起来最快 |
| `hono/quick` | 每个请求都重新初始化应用的场景                                |
| `hono/tiny`  | 资源受限、体积第一（整体小于 15KB）                           |

- **Node 后端用默认 `hono` 即可**，进程生命周期长，注册耗时可忽略;
- 想换路由器也可以显式传入：`new Hono({ router: new RegExpRouter() })`;

## 基准数据说明了什么？

```text
Hono        x 402,820 ops/sec
sunder      x 297,036 ops/sec
itty-router x 212,598 ops/sec
worktop     x 197,345 ops/sec
```

```text
Express v5          24,380 req/s
Hono + node-server  74,428 req/s
```

- 前半段是 Workers 上的路由基准，后半段是 Node 适配器与 Express 的对比;
- 结论: Hono 在路由层几乎不是瓶颈，真正的瓶颈在数据库、外部调用与序列化;
