# 构建与运行产物

## 从开发到生产要做哪几步？

```text
tsx watch 开发 → tsc 编译到 dist → node dist/index.js 运行
→ 反向代理/负载均衡 → 健康检查 → 日志与指标
```

| 步骤     | 命令                     | 说明                             |
| -------- | ------------------------ | -------------------------------- |
| 开发     | `npm run dev`            | `tsx watch src/index.ts`，热重载 |
| 构建     | `npm run build`          | `tsc` 输出到 `dist/`             |
| 运行     | `npm run start`          | `node dist/index.js`             |
| 生产依赖 | `npm prune --production` | 去掉 devDependencies 减小镜像    |

## 编译配置要注意什么？

```json
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "rootDir": "./src",
    "outDir": "./dist",
    "types": ["node"]
  }
}
```

- ESM 项目 `package.json` 必须有 `"type": "module"`，否则 `dist/*.js` 会被当 CJS 执行报错;
- 相对导入建议带扩展名（`./app.js`），NodeNext 下最稳;
- 编译产物是纯 JS，生产镜像不需要 `tsx`、`typescript` 等开发依赖;

## 部署形态怎么选？

| 形态            | 适用                 | 说明                                  |
| --------------- | -------------------- | ------------------------------------- |
| 单机 + 反代     | 中小流量、内网服务   | Nginx 终结 TLS、做压缩与静态          |
| 容器 + 编排     | 多实例、需要滚动发布 | 见 [Docker 部署](./020-Docker部署.md) |
| Serverless/边缘 | 已有平台时           | 需换适配器，见各平台文档              |

- 无论哪种形态，应用本身都只做一件事：`serve({ fetch: app.fetch })`;
- 端口、主机名一律来自环境变量，不写死;
