# 静态文件

## 如何在 Node 上提供静态文件？

```ts
import { serveStatic } from "@hono/node-server/serve-static";

app.use("/static/*", serveStatic({ root: "./" }));
app.use("/favicon.ico", serveStatic({ path: "./favicon.ico" }));
app.use("*", serveStatic({ root: "./static" }));
```

| 目录结构             | 请求                | 配置                        |
| -------------------- | ------------------- | --------------------------- |
| `./static/hello.txt` | `/static/hello.txt` | `{ root: './' }`            |
| `./static/hello.txt` | `/hello.txt`        | `{ root: './static' }`      |
| `./favicon.ico`      | `/favicon.ico`      | `{ path: './favicon.ico' }` |

- 只处理 GET/HEAD，其他方法自动放行给后续中间件;
- 静态中间件应挂在不带鉴权的路径上，且访问控制要覆盖同一路径模式（否则可被绕过）;
- 404 时不会短路，可以继续挂兜底 Handler;

## 为什么静态文件在生产环境路径会失效？

- `root` 相对于**进程工作目录**（`process.cwd()`），不是源码文件位置;
- 从别的目录启动进程（容器、systemd、IDE）时相对路径就错位了;
- 用 `import.meta.url` 锚定到源码/产物所在目录：

```ts
import { fileURLToPath } from "node:url";
import { serveStatic } from "@hono/node-server/serve-static";

app.use(
  "/static/*",
  serveStatic({
    root: fileURLToPath(new URL("./", import.meta.url)),
  }),
);
```

## 路径重写与命中后的钩子怎么用？

```ts
app.use(
  "/static/*",
  serveStatic({
    root: "./",
    rewriteRequestPath: (p) => p.replace(/^\/static/, "/statics"), // /static/x → ./statics/x
    onFound: (_path, c) => {
      c.header("Cache-Control", "public, max-age=31536000, immutable");
    },
  }),
);

// 文件名本身含 % 时才需要放开
app.use("/weird/*", serveStatic({ root: "./weird", allowPercentInPath: true }));
```

- `rewriteRequestPath` 用于「URL 前缀 ≠ 磁盘目录」的场景;
- `onFound` 是给静态资源加长缓存头的正位;
- `allowPercentInPath` 默认关闭，避免二次解码绕过路由层的访问控制;

## 生产环境要不要让 Node 直接服务静态文件？

- 小流量、内网、单体服务：可以，配合 ETag 与缓存头即可;
- 大流量：交给 Nginx/CDN，Node 只处理动态请求，减少进程负担;
- 无论哪种，静态资源都该带 `Cache-Control` 与内容哈希文件名;
