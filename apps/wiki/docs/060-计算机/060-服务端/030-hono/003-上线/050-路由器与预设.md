# 路由器与预设

## Node 长驻进程为什么用默认路由器就够？

- 前提: Node 是长生命周期进程，路由只在启动时注册一次，注册耗时可忽略;
- 默认: `new Hono()` 用 `SmartRouter(RegExp + Trie)`;

```ts
import { Hono } from "hono";
import { RegExpRouter } from "hono/router/reg-exp-router";

const app = new Hono(); // 默认 SmartRouter(RegExp + Trie)

const explicit = new Hono({ router: new RegExpRouter() });
```

## 五种路由器的匹配方式差在哪？

| 路由器          | 匹配方式                           | 特点                             |
| --------------- | ---------------------------------- | -------------------------------- |
| `RegExpRouter`  | 所有路由合成一条巨大正则，一次匹配 | 最快，但不支持全部路由写法       |
| `TrieRouter`    | 字典树                             | 支持全部模式                     |
| `SmartRouter`   | 启动时探测并选用上面两者之一       | 默认组合，兼顾速度与兼容性       |
| `LinearRouter`  | 线性遍历，注册极快                 | 适合「每个请求都重建应用」的环境 |
| `PatternRouter` | 简单模式匹配                       | 体积最小                         |

- 默认组合: `new SmartRouter({ routers: [new RegExpRouter(), new TrieRouter()] })`;
- 大正则代价: 极端路由组合下编译更慢，`SmartRouter` 探测后兜底;

## 三种预设分别适合什么部署形态？

| 预设         | 路由器                     | 适合                           |
| ------------ | -------------------------- | ------------------------------ |
| `hono`       | SmartRouter(RegExp + Trie) | 长期运行的服务，Node 推荐      |
| `hono/quick` | SmartRouter(Linear + Trie) | 每个请求都重新初始化应用的场景 |
| `hono/tiny`  | PatternRouter              | 资源受限、体积优先             |

- 换之前先压测，确认瓶颈真的在路由匹配;
- 预设只换路由实现，`Hono` 的 API 与中间件用法不变;
