# 错误处理

## 抛出的异常最后去了哪里？

- 去向: 任何异常都被 Hono 捕获并交给 `app.onError`；没写 `onError` 时自动 500，错误信息只进日志;

```ts
import { Hono } from "hono";
import { HTTPException } from "hono/http-exception";

const app = new Hono();

app.onError((err, c) => {
  if (err instanceof HTTPException) return err.getResponse();
  console.error(err);
  return c.json({ ok: false, error: "internal_error" }, 500);
});

app.get("/boom", () => {
  throw new HTTPException(401, { message: "Unauthorized" });
});
```

- 优先级: 父子应用都写 `onError` 时路由级优先;
- 中间件读错: `await next()` 之后可读 `c.error` 做日志/埋点；响应已由 `onError` 决定，不要再返回新响应;
- 该抛什么: 预期内错误（校验失败、未授权）直接 `return c.json(..., 4xx)`；深层 Service/第三方库抛 `HTTPException`；不可恢复的程序错误抛普通 `Error`；取舍规则见 [错误分类与响应](../../000-服务端知识/020-契约与错误/020-错误分类与响应/010-错误分层与响应.md);

## HTTPException 怎么带自定义响应体？

- 两种载荷: 传 `res` 自定义完整响应，或传 `message` + `cause` 保留原始错误;

```ts
// 自定义响应体或响应头
throw new HTTPException(401, {
  res: new Response("Unauthorized", { headers: { Authenticate: 'error="invalid_token"' } }),
});

// 附加原始错误，便于日志排查
throw new HTTPException(401, { message: "登录失败", cause });
```

- 状态码: 以构造函数参数为准，`res` 里的 status 被忽略；`err.getResponse()` 按 status + message（或自定义 `res`）生成响应;
- 不感知 Context: `getResponse()` 不带 `c.header()` 设过的头;
- 流式: 流式响应内不可用，响应已发出时错误只能走流内事件，见 [流式响应](../090-按需查阅/100-流式与SSE.md);

## 404 和中间件里的错误怎么传播？

- 404 定制: `c.notFound()` 交给 `app.notFound` 统一处理；有类型安全客户端时改用 `c.json(..., 404)`，否则客户端推不出错误体类型;

```ts
app.notFound((c) => c.json({ ok: false, error: "not_found" }, 404));
```

- 作用域: `app.notFound` 只有顶层应用生效，子应用的 `notFound` 不生效；路径存在但方法不对默认也是 404，要 405 挂 `methodNotAllowed({ app })`;
- 传播路径: Handler 抛错 → 调用它的那层中间件捕获（`c.error = err`）→ `onError` 生成响应 → 外层中间件的 `await next()` 正常返回，after 代码继续执行;
- 不写 try/catch: 抛错那一层自己的 after 代码不会执行；`next()` 永不抛错；同一个 `next()` 调两次会抛 `next() called multiple times`;
- 相邻主题: 日志字段（`requestId`、method + path、错误类型、堆栈、`cause`）与脱敏见 [日志与请求 ID](../../000-服务端知识/060-观测与交付/010-日志与请求ID.md)；中间件执行顺序见 [中间件](../002-服务端开发/040-中间件.md);
