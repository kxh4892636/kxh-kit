# 响应与状态码

## Handler 返回什么就等于发什么吗？

- 是: 返回值就是 HTTP 响应；用 `c.*` 快捷方法构造标准 `Response`，或用 `new Response` 完全自定义，中间件还能改写已生成的响应;

```ts
import { Hono } from "hono";

const app = new Hono();

app.get("/text", (c) => c.text("hello"));
app.get("/json", (c) => c.json({ ok: true }));
app.get("/page", (c) => c.html("<h1>hi</h1>"));
app.get("/bin", (c) =>
  c.body(new Uint8Array([0x48, 0x69]), 200, { "Content-Type": "application/octet-stream" }),
);
app.get("/go", (c) => c.redirect("/", 301)); // 默认 302
```

- 产出类型: `c.text` / `c.json` / `c.html` / `c.body` 分别产出 `text/plain`、`application/json`、`text/html` 与自定义类型；`c.redirect(url, status?)` 默认 302；`c.notFound()` 触发 404，可被 `app.notFound` 定制;

## 状态码和响应头怎么写？

- 两种写法: 先 `c.status()` / `c.header()` 再返回，或一次传给 `c.json(body, status, headers)`；200 是默认值不用显式设置，`c.header()` 必须在 `return` 之前调用;

```ts
app.post("/posts", (c) => {
  c.status(201); // 先设状态码
  c.header("X-Message", "created"); // 再设头，可多次
  return c.json({ ok: true });
});

// 一步到位
app.post("/posts2", (c) => c.json({ ok: true }, 201, { "X-Message": "created" }));
```

- 契约与类型: 统一成功/失败结构、业务码与状态码的映射是框架无关的，见 [错误分类与响应](../../000-服务端知识/020-契约与错误/020-错误分类与响应/010-错误分层与响应.md)；有类型安全客户端时失败一律 `return c.json(..., status)`，客户端才能推出错误体类型，见 [hc 客户端](../090-按需查阅/050-hc客户端.md);

## 已经生成的响应还能改吗？

- 能: 中间件 `await next()` 之后拿到真实响应再改头或整体替换；流式响应一旦开始写就改不了，见 [流式响应](../090-按需查阅/100-流式与SSE.md);

```ts
app.get("/raw", () => new Response("Good morning!")); // Hono 不再插手

app.use(async (c, next) => {
  await next(); // 之后才能拿到真实响应
  c.res.headers.append("X-Debug", "1");
});

app.use(async (c, next) => {
  await next();
  c.res = undefined; // 想完全替换时先清空
  c.res = new Response("masked", { status: 200 });
});
```

- 占位与赋值: `c.res` 首次访问返回 body 为 `null` 的占位 `Response`，`await next()` 之后才是真实响应；赋新值会保留旧响应的头（`content-type` 除外），适合脱敏、统一错误页、加调试头;
- 相邻主题: 中间件里改响应的完整写法见 [中间件](../002-服务端开发/040-中间件.md)；错误响应统一出口见 [错误处理](./060-错误处理.md);
