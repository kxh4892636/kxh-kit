# 路径匹配规则

## 路径参数有哪几种写法？

| 写法                         | 匹配                             | 读取                           |
| ---------------------------- | -------------------------------- | ------------------------------ |
| `/user/:name`                | `/user/张三`                     | `c.req.param('name')`          |
| `/api/animal/:type?`         | `/api/animal`、`/api/animal/dog` | `c.req.param('type')` 可能为空 |
| `/post/:date{[0-9]+}`        | 只匹配数字                       | 同上                           |
| `/posts/:filename{.+\\.png}` | 允许多段与点号                   | 同上                           |
| `*`                          | 任意路径                         | —                              |

```ts
app.get("/posts/:id/comment/:commentId", (c) => {
  const { id, commentId } = c.req.param(); // 一次取全部
  return c.json({ id, commentId });
});
```

- 正则写在 `{}` 里，必须能匹配整段，否则该路由不命中;
- 通配符 `*` 只能出现在需要吞掉剩余路径的位置，写 `'*'` 常见于中间件或兜底;
- 参数支持不含斜杠的段；要吞斜杠用 `:id{.+}` 这类正则;

## 如何修改 URL 匹配方式？

```ts
// 严格模式默认开启: /hello 不等于 /hello/
const app = new Hono({ strict: false });

// 把 hostname 也纳入匹配
const byHost = new Hono({
  getPath: (req) => req.url.replace(/^https?:\/([^?]+).*$/, "$1"),
});
byHost.get("/www1.example.com/hello", (c) => c.text("hello www1"));

// 按 Host 头路由
const byHeader = new Hono({
  getPath: (req) =>
    "/" + req.headers.get("host") + req.url.replace(/^https?:\/\/[^/]+(\/[^?]*).*/, "$1"),
});
```

- `getPath` 把「请求」映射成「参与匹配的路径字符串」，是唯一需要改匹配行为时的钩子;
- 多租户、灰度分流可以借用它，但更推荐在网关层做;
- 尾斜杠的自动重定向用 `appendTrailingSlash` / `trimTrailingSlash`，见 [内置中间件速查](../090-按需查阅/010-内置中间件速查.md);
