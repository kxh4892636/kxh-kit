# 最小可运行代码

## 三个文件怎么配？

```json title="package.json"
{
  "type": "module",
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js"
  },
  "dependencies": { "hono": "^4", "@hono/node-server": "^2" },
  "devDependencies": { "typescript": "^5", "tsx": "^4", "@types/node": "^22" }
}
```

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "NodeNext",
    "strict": true,
    "rootDir": "./src",
    "outDir": "./dist",
    "types": ["node"]
  },
  "exclude": ["node_modules"]
}
```

```ts title="src/index.ts"
import { serve } from "@hono/node-server";
import { Hono } from "hono";

const app = new Hono();

app.get("/", (c) => c.text("Hello Node.js!"));

serve({ fetch: app.fetch, port: 3000 }, (info) => {
  console.log(`Server is running on http://localhost:${info.port}`);
});
```

## 为什么 `strict` 和 `NodeNext` 不能省？

- `strict: true`: Hono 的类型推导在非严格模式下会放宽，`c.req.param()` 之类的字面量类型会退化;
- `module: NodeNext` + `"type": "module"`: 让编译产物按 ESM 执行，否则 `import` 语句在 Node 里直接报错;
- `rootDir`/`outDir`: 保证 `dist/index.js` 的相对层级与源码一致，静态文件与 `import.meta.url` 才不会错位;

## 目录一开始怎么组织？

```text
src/
├── index.ts          # 入口: serve() + 挂载路由
├── app.ts            # Hono 实例组装（便于测试导入）
├── routes/           # 按资源拆分的子路由
├── middleware/       # 自定义中间件
└── lib/              # 数据库、外部调用等
```

- 为什么入口要拆成 `index.ts` + `app.ts`：测试直接 `import app`，不必起端口;
- 分层与依赖注入细节见 [目录与分层](../002-服务端开发/010-目录与分层.md);
