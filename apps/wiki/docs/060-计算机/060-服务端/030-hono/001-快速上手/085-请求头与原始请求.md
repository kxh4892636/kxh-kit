# 请求头与原始请求

## 如何读取请求头？

```ts
app.get("/", (c) => {
  const ua = c.req.header("User-Agent"); // 大小写不敏感
  const headers = c.req.header(); // 全部键为小写
  return c.json({ ua, hasAuth: !!headers["authorization"] });
});
```

- 坑: `c.req.header()` 返回的对象的键全是小写，`headers['X-Foo']` 永远取不到；要取就写 `c.req.header('X-Foo')`;
- 头部值缺失时是 `undefined`;
- `Cookie` 头不要自己解析，用 Cookie Helper，见 [Cookie 读写](../002-服务端开发/160-Cookie读写.md);

## 请求体被读过了还想再读怎么办？

```ts
import { cloneRawRequest } from "hono/request";
import { validator } from "hono/validator";

app.post(
  "/forward",
  validator("json", (v) => v),
  async (c) => {
    const cloned = await cloneRawRequest(c.req);
    const body = await cloned.json(); // 不会抛「body already used」
    return c.json({ body });
  },
);
```

- 原始 `Request` 的 body 是一次性流，校验器读过之后 `c.req.raw` 已耗尽;
- `cloneRawRequest()` 在校验之后依然可用，适合转发、审计日志;

## 原始对象和客户端 IP 怎么拿？

```ts
app.get("/info", (c) => {
  const raw = c.req.raw; // 标准 Request
  const ip = c.env.incoming?.socket.remoteAddress; // 仅 Node 适配器
  return c.json({ url: raw.url, ip });
});
```

- `c.req.raw` 用于平台特性或流式转发;
- Node 的原始连接对象在 `c.env.incoming`，见 [启动与验证](./040-启动与验证.md);
- 更通用的取 IP 方式：`getConnInfo(c).remote.address`，见 [运行时信息与路由内省](../090-按需查阅/045-运行时信息与路由内省.md)。
