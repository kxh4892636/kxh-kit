# 路由注册

## 如何注册一条路由？

```ts
app.get("/", (c) => c.text("GET /"));
app.post("/", (c) => c.text("POST /"));
app.put("/x", (c) => c.text("PUT /x"));
app.delete("/x", (c) => c.text("DELETE /x"));

app.all("/any", (c) => c.text("所有方法")); // 任意方法
app.on("PURGE", "/cache", (c) => c.text("自定义方法")); // 自定义方法
app.on(["PUT", "DELETE"], "/post", (c) => c.text("两种方法"));
app.on("GET", ["/hello", "/ja/hello"], (c) => c.text("两条路径"));
app.get("/wild/*/card", (c) => c.text("通配符"));
```

- `app.HTTP_METHOD(path, handler...)` 覆盖标准方法，`app.on(method, path, ...)` 覆盖自定义方法;
- 一条路由可以挂多个处理函数，按顺序执行，最后一个负责返回 `Response`;
- 路径参数与匹配细节见 [路径匹配规则](./060-路径匹配规则.md);

## 注册顺序为什么重要？

```ts
app.get("/book/a", (c) => c.text("a")); // a
app.get("/book/:slug", (c) => c.text("common")); // /book/b 才命中

app.get("*", (c) => c.text("common")); // 写在前面会吞掉一切
app.get("/foo", (c) => c.text("foo")); // 永远不会执行
```

- 规则: 注册顺序即匹配顺序，命中 Handler 后立即结束;
- 中间件必须写在 Handler 之上;
- 兜底 Handler 写在最后：

```ts
app.get("/bar", (c) => c.text("bar"));
app.get("*", (c) => c.text("fallback"));
```

## 链式写法解决什么问题？

```ts
app
  .get("/endpoint", (c) => c.text("GET /endpoint"))
  .post((c) => c.text("POST /endpoint"))
  .delete((c) => c.text("DELETE /endpoint"));
```

- 链式会带上路径和方法，后续调用的 Handler 可省略路径;
- 更重要的用途是类型推断：只有链式写法才能让 `AppType` 完整推理，RPC 与 `testClient` 都依赖这一点（见 [RPC 服务端准备](../090-按需查阅/060-RPC服务端准备.md)）;

## HEAD 请求怎么处理？

- Hono 在路由匹配前把 `HEAD` 当 `GET` 处理，然后丢弃响应体;
- 因此 `app.head(...)` 和 `app.on('HEAD', ...)` 永远不会被调用，不要写;
- 想让 HEAD 少算重活，在中间件里判断 `c.req.method === 'HEAD'` 后改写响应;
- 测试要同时断言 GET 与 HEAD 的状态码和头部一致;
