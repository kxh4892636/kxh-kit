# 错误处理

## 未捕获的错误去了哪里？

```ts
app.onError((err, c) => {
  if (err instanceof HTTPException) return err.getResponse();
  console.error(err);
  return c.json({ ok: false, error: "internal_error" }, 500);
});
```

- Handler 或中间件抛出的任何异常都会被 Hono 捕获，交给 `app.onError`;
- 没写 `onError` 时自动变成 500 响应，错误信息只进日志;
- 父子应用都写了 `onError` 时，**路由级优先**;

## 中间件里如何感知 Handler 抛出的错误？

```ts
app.use(async (c, next) => {
  await next();
  if (c.error) {
    // 记录、上报、附加上下文
  }
});
```

- 错误对象会被放进 `c.error`，中间件可用它做日志与埋点;
- 响应已经被 `onError` 决定，不要在中间件里再返回新响应;
- 需要对外隐藏细节时，在 `onError` 里统一映射成业务错误码;

## 什么时候该抛异常，什么时候直接返回？

| 场景                                | 做法                                           |
| ----------------------------------- | ---------------------------------------------- |
| 校验失败、未授权等预期内错误        | 直接 `return c.json(..., 4xx)`                 |
| 深层函数/第三方库抛出、需要统一映射 | `throw new HTTPException(status, { message })` |
| 不可恢复的程序错误                  | 直接抛普通 `Error`，交给 `onError` 记 500      |

- `HTTPException` 的构造、`getResponse` 行为与 `cause` 用法见 [HTTPException](./122-HTTPException.md);
- 404 与错误传播路径见 [404 与错误传播](./125-404与错误传播.md)。
