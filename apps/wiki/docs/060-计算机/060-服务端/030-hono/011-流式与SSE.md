# 流式与 SSE

## 什么时候该流式，用哪个 Helper？

- 流式: 普通响应全部算完才发；大文件、日志、LLM 逐字输出、进度推送要边算边发;
- 选型: 只需要服务端推用 SSE，双向通信用 [WebSocket](./012-WebSocket.md)；普通接口别用流;

```ts
app.get("/text", (c) =>
  streamText(c, async (s) => {
    await s.writeln("Hello");
    await s.sleep(1000);
    await s.write("Hono!"); // 不换行
  }),
);

app.get("/sse", (c) =>
  streamSSE(c, async (s) => {
    while (!s.aborted) {
      await s.writeSSE({ data: `now: ${Date.now()}`, event: "tick", id: String(id++) });
      await s.sleep(1000);
    }
  }),
);
```

## 三种流各发什么，谁来关闭？

- `stream(c, cb)`: Content-Type 自己定，默认二进制，也可 `s.pipe(readable)`;
- `streamText`: `text/plain` + `Transfer-Encoding: chunked`;
- `streamSSE`: `text/event-stream`，`writeSSE({ data, event, id })`，`data` 里的换行自动拆成多行 `data:`;
- 关闭: 回调执行完自动关闭，不用手动 `close()`；`s.onAbort()` 是清理计时器、取消上游订阅的唯一挂点;

## 流开始后哪些事不能再做？

- 头与状态码: 一旦开始写就不能再改;
- 错误: 流已开始时 `app.onError` 不会触发；第三个参数接错误 `stream(c, cb, (err, s) => ...)`，或用 `event: error` 告知客户端;
- 超时: `timeout()` 与流式冲突，自己 `setTimeout(() => s.close(), 3000)` 并在 `onAbort` 里 `clearTimeout`;

## 心跳、代理与鉴权怎么配？

- 心跳: 每 15s 一条 `: ping` 注释，间隔 ≤30s，防 Nginx/ELB 空闲断链;
- 代理: Nginx 需 `proxy_buffering off`、`proxy_read_timeout 3600s`；不要压缩 `text/event-stream`;
- 鉴权: `EventSource` 不能自定义头，用 Cookie 或 query token;
