# 校验、类型与类型安全客户端

## 参数怎么校验，结果怎么取？

- 校验器: `sValidator(target, schema)`（`@hono/standard-validator`, 吃 Standard Schema; 手写逻辑仍用 `validator(target, fn)`）;
- 目标位置: `json`、`form`、`query`、`header`、`param`、`cookie`, 每个位置挂一个校验器, 按注册顺序执行, 前一个失败后一个不跑;
- 取结果: `c.req.valid("json")`, 类型是 schema 的输出——`default()` 补过、`coerce` 转过的值, 不是原始字符串;

```ts
import { z } from "zod";
import { sValidator } from "@hono/standard-validator";

app.post(
  "/posts/:id",
  sValidator("param", z.object({ id: z.coerce.number().int() })),
  sValidator("json", z.object({ title: z.string().min(1), tags: z.array(z.string()).default([]) })),
  (c) => {
    const { title, tags } = c.req.valid("json"); // tags: string[]
    return c.json({ id: c.req.valid("param").id, title, tags }, 201);
  },
);
```

## c.env 和 c.set/get 分别装什么？

| 泛型        | 访问                        | 典型内容                      | 可写       |
| ----------- | --------------------------- | ----------------------------- | ---------- |
| `Bindings`  | `c.env.X`                   | 环境变量、连接池、平台绑定    | 否         |
| `Variables` | `c.set` / `c.get` / `c.var` | 中间件注入的用户、db、traceId | 仅本次请求 |

- `c.var.x` 等价 `c.get("x")`; `Variables` 是跨中间件传值的唯一正路, 别用模块级变量;
- Node 上 `Bindings` 通常写成 `HttpBindings & { TOKEN: string }`; 跨运行时用 `env<T>(c)`（`hono/adapter`, 只能在 handler 里）;

## hc 客户端怎么拿到端到端类型？

- 三件事: 服务端链式注册并 `export type AppType = typeof app`; 客户端 `hc<AppType>(baseUrl)`（`hono/client`）; 状态码写进 `c.json` 才有对应分支;

```ts
// server.ts：export type AppType = typeof route;
const client = hc<AppType>("http://localhost:3000/");
const res = await client.posts.$post({ json: { title: "Hi" } });
if (res.ok) await res.json(); // 201 返回体类型
```

- 传参 key 与服务端数据来源一一对应: `param` / `query` / `json` / `form`;
- 类型退化: `res.json()` 是 `unknown` 说明用了 `c.notFound()` 或没写状态码; 请求体是 `any` 说明没挂校验器或没链式注册; `Type instantiation is excessively deep` 多是前后端 `hono` 版本不一致;
