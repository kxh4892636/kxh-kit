# 校验、类型与类型安全客户端

## 参数怎么校验，结果怎么取？

- 两种写法: 手写 `validator(target, fn)`，或用 schema 的 `zValidator("json", schema)`（`@hono/zod-validator`）;
- 目标位置: `json`、`form`、`query`、`header`、`param`、`cookie`，多个位置各挂一个校验器，顺序无关;
- 取结果: `c.req.valid("json")`，已收窄成 schema 类型；手写时返回值就是 `valid()` 的数据;

```ts
app.post(
  "/posts/:id",
  zValidator("param", z.object({ id: z.string() })),
  zValidator("json", z.object({ title: z.string().min(1), tags: z.array(z.string()).default([]) })),
  (c) => c.json({ id: c.req.valid("param").id, title: c.req.valid("json").title }, 201),
);
```

- 坑: 缺 `Content-Type` 时 `json`/`form` 校验器收到 `{}`，测试也要带；查询值都是字符串，数字用 `z.coerce.number()`；header 键一律小写;
- 换库: `sValidator`（`@hono/standard-validator`）兼容任意 Standard Schema（Zod/Valibot/ArkType）;
- 文件: `zValidator("form", z.object({ file: z.instanceof(File) }))`，要在 `bodyLimit` 之后；拿到 `File` 后大小看 `file.size`、类型看 `file.type`，不信任客户端 MIME;

## c.env 和 c.set/get 分别装什么？

| 泛型        | 访问                        | 典型内容                      | 可写       |
| ----------- | --------------------------- | ----------------------------- | ---------- |
| `Bindings`  | `c.env.X`                   | 环境变量、连接池、平台绑定    | 否         |
| `Variables` | `c.set` / `c.get` / `c.var` | 中间件注入的用户、db、traceId | 仅本次请求 |

- `c.var.x` 等价 `c.get("x")`；`Variables` 是跨中间件传值的唯一正路，别用模块级变量;
- Node 上 `Bindings` 通常写成 `HttpBindings & { TOKEN: string }`；纯 Node 直接读 `process.env`，跨运行时用 `env<T>(c)`（`hono/adapter`，只能在 handler 里）;

## Handler 抽成独立函数会丢什么，factory 怎么补？

- 丢两样: `c.req.param()` 的字面量类型与 `AppType` 推断，RPC 与 `testClient` 跟着失效；要保留独立 Handler 就用 `createFactory`（`hono/factory`）;

```ts
const factory = createFactory<Env>({
  initApp: (app) =>
    app.use(async (c, next) => {
      c.set("db", createDb(c.env.DATABASE_URL)); // 全应用装配放这里
      await next();
    }),
});

const handlers = factory.createHandlers(auth, (c) => c.json({ user: c.var.user }));
const app = factory.createApp().get("/api", ...handlers);
```

- 一处声明: `createFactory<Env>()` 之后 `createApp` / `createMiddleware` / `createHandlers` 共用同一 `Env`，不用写两遍;
- 何时抽 Service: 只有多个路由复用时才抽，且只收普通对象、不收 `Context`，见 [依赖方向](../000-服务端知识/010-基础模型/020-分层与依赖方向/010-依赖方向.md);

## hc 客户端怎么拿到端到端类型？

- 三件事: 服务端链式注册并 `export type AppType = typeof app`；客户端 `hc<AppType>(baseUrl)`（`hono/client`）；状态码写进 `c.json` 才有对应分支;

```ts
// server.ts：export type AppType = typeof route;
const client = hc<AppType>("http://localhost:3000/");
const res = await client.posts.$post({ json: { title: "Hi" } });
if (res.ok) await res.json(); // 201 返回体类型
```

- 传参 key 与服务端数据来源一一对应: `param` / `query` / `json` / `form`;
- 类型退化: `res.json()` 是 `unknown`，说明用了 `c.notFound()` 或没写状态码；请求体是 `any`，说明没挂校验器或没链式注册；`Type instantiation is excessively deep` 多是前后端 `hono` 版本不一致;
- 边界: 只适合同仓 TypeScript，跨语言调用改用 OpenAPI/IDL;
