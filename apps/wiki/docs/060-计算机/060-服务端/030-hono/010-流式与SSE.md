# 流式与 SSE

## 三个流式 Helper 各发什么？

```ts
// HTTP 流式传输
app.get("/text", (c) =>
  streamText(c, async (s) => {
    await s.writeln("Hello");
    await s.sleep(1000);
    await s.write("Hono!"); // 不换行
  }),
);

// SSE 协议
app.get("/sse", (c) =>
  streamSSE(c, async (s) => {
    while (!s.aborted) {
      await s.writeSSE({ data: `now: ${Date.now()}`, event: "tick", id: String(id++) });
      await s.sleep(1000);
    }
  }),
);
```

- `stream(c, cb)`: Content-Type 由自己定, 默认二进制;
- 也可: `s.pipe(readable)`;
- `streamText`: `text/plain` + `Transfer-Encoding: chunked`;
- `streamSSE`: 响应类型为 `text/event-stream`;
- 写入: `writeSSE({ data, event, id })`;
- 细节: `data` 里的换行自动拆成多行 `data:`;

## 流何时关闭、怎么清理？

- 关闭: 回调执行完自动关闭, 不用手动 `close()`;
- `s.onAbort()`: 清理计时器、取消上游订阅的唯一挂点;
- SSE 与 WebSocket 的选型见 [流式选型](../000-服务端知识/070-通信/020-选型与边界.md);

## 流开始后哪些事不能再做？

- 头与状态码: 一旦开始写就不能再改;
- 错误: 流已开始时 `app.onError` 不会触发;
- 接错误: 第三个参数 `stream(c, cb, (err, s) => ...)`;
- 或: 用 `event: error` 告知客户端;
- 超时: `timeout()` 与流式冲突;
- 做法: 自己 `setTimeout(() => s.close(), 3000)`, 并在 `onAbort` 里 `clearTimeout`;

## 心跳、代理与鉴权怎么配？

- 心跳: 每 15s 一条 `: ping` 注释, 间隔不超过 30s;
- 目的: 防 Nginx 或 ELB 空闲断链;
- 代理: Nginx 需 `proxy_buffering off` 与 `proxy_read_timeout 3600s`;
- 不要压缩: `text/event-stream`;
- 鉴权: `EventSource` 不能自定义头;
- 做法: 用 Cookie 或 query token;
