# 运维接入

## 退出怎么接？

- 适配器返回原生 `http.Server`，关闭由应用负责；`server.close` 停止接收新连接并在在途请求结束后回调;

```ts
const server = serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 3000) });

const shutdown = () => {
  server.close(async (err) => {
    if (err) process.exit(1);
    await pool.end(); // 在途请求结束后再关连接池
    process.exit(0);
  });
  setTimeout(() => process.exit(1), 10_000).unref(); // 兜底，小于平台宽限期
};

process.on("SIGTERM", shutdown);
process.on("SIGINT", shutdown);
```

- 长连接: WebSocket 先逐连接 `close(1001, ...)` 再 `wss.close()`；定时任务要 `clearInterval`;
- 顺序与摘流窗口见 [退出顺序](../000-服务端知识/040-可靠性/050-退出顺序.md)。

## 探针怎么分、挂在哪？

```ts
app.get("/healthz", (c) => c.json({ ok: true })); // liveness：不查依赖
app.get("/readyz", async (c) => {
  const ok = await checkDb();
  return c.json({ ok }, ok ? 200 : 503);
});
```

- 探针端点不套鉴权、限流、`bodyLimit`，统一前缀时放在前缀之外；间隔 5–10s、超时 1–3s、失败 3 次;
- 两个探针的分工见 [退出顺序](../000-服务端知识/040-可靠性/050-退出顺序.md)。

## 请求 ID 与访问日志怎么写？

```ts
app.use(requestId()); // 默认头名 X-Request-Id，合法请求头复用并回写响应头

const accessLog = createMiddleware(async (c, next) => {
  const start = performance.now();
  await next();
  console.log(
    JSON.stringify({
      requestId: c.get("requestId"),
      method: c.req.method,
      path: c.req.path,
      status: c.res.status,
      ms: Math.round(performance.now() - start),
      error: c.error?.message,
    }),
  );
});
```

- 必记: `requestId`、method + path、status + 耗时、`c.error`；生产默认 `info`；内置 `logger()` 只适合开发;
- 禁记: 手机号/身份证、`Authorization`/Cookie/密钥、完整请求体、内网地址；字段与脱敏见 [日志与请求 ID](../000-服务端知识/060-观测与交付/010-日志与请求ID.md);
- 非 Handler 位置取 `Context`（日志函数、ORM 日志）: `app.use(contextStorage())` 必须第一个挂，再用 `tryGetContext()`；不要拿它替代显式传参。
