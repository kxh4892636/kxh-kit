# 文件上传

## 上传接口怎么写？

- 两道关卡: `bodyLimit` 先限体积，`zValidator("form")` 再取出并校验文件;

```ts
import { Hono } from "hono";
import { bodyLimit } from "hono/body-limit";
import { zValidator } from "@hono/zod-validator";
import * as z from "zod";

const app = new Hono();

app.post(
  "/user/picture",
  bodyLimit({ maxSize: 5 * 1024 * 1024, onError: (c) => c.text("too large", 413) }),
  zValidator("form", z.object({ note: z.string().optional(), file: z.instanceof(File) })),
  async (c) => {
    const { file, note } = c.req.valid("form");
    return c.json({ ok: true, size: file.size, note }, 201);
  },
);
```

- 顺序: `bodyLimit` 必须在解析前挂，否则请求体已经进内存;
- 类型: 用 `z.instanceof(File)` 才能把类型收窄成 `File`（Node 20+ 有全局 `File`）;
- 校验: 大小看 `file.size`，类型看 `file.type`；不信任客户端 MIME，按扩展名与文件头校验;
- 落盘: 文件名用服务端生成的 ID，不要用用户文件名；上传目录与站点不同源；原理与风险清单见 [文件上传](../../000-服务端知识/020-契约与错误/040-文件上传.md);

## 多文件与流式怎么处理？

- 取多文件: `body["photos[]"]` 返回数组，同名多文件必须带 `[]` 后缀;

```ts
const body = await c.req.parseBody();
body["avatar"]; // string | File，多文件时只留最后一个
body["photos[]"]; // (string | File)[]，多文件必须带 [] 后缀
const all = await c.req.parseBody({ all: true }); // 同名多值统一成数组
const dotted = await c.req.parseBody({ dot: true }); // 'a.b' → { a: { b } }
```

- 大文件: 要边读边写时用 `c.req.raw.body`，不要 `parseBody`;
- 存储: 对象存储直传 + 服务端只发签名，避免大文件穿过后端进程;
- 上限提醒: `bodyLimit` 不显式设 `maxSize` 时默认上限较小，只挂在上传路由，不要全局放大;
