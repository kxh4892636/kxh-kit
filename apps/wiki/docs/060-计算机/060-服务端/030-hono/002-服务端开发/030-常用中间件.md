# 常用中间件

## 要哪项能力就 import 什么？

| 需求         | 导入                      | 用法                                          |
| ------------ | ------------------------- | --------------------------------------------- |
| 跨域         | `hono/cors`               | `cors({ origin, credentials })`               |
| Bearer Token | `hono/bearer-auth`        | `bearerAuth({ token })` / `{ verifyToken }`   |
| Basic 认证   | `hono/basic-auth`         | `basicAuth({ username, password })`           |
| JWT / JWK    | `hono/jwt`、`hono/jwk`    | `jwt({ secret, alg })`、`jwk({ jwks_uri })`   |
| 安全响应头   | `hono/secure-headers`     | `secureHeaders()`                             |
| CSRF         | `hono/csrf`               | `csrf()`                                      |
| Cookie       | `hono/cookie`             | `setCookie` / `getCookie` / `setSignedCookie` |
| 压缩         | `hono/compress`           | `compress()`                                  |
| 请求体上限   | `hono/body-limit`         | `bodyLimit({ maxSize, onError })`             |
| 请求超时     | `hono/timeout`            | `timeout(ms)`                                 |
| IP 限制      | `hono/ip-restriction`     | `ipRestriction(getConnInfo, { allowList })`   |
| ETag / 304   | `hono/etag`               | `etag({ weak })`                              |
| 请求 ID      | `hono/request-id`         | `requestId()`                                 |
| 日志         | `hono/logger`             | `logger()`                                    |
| 405 替代 404 | `hono/method-not-allowed` | `methodNotAllowed({ app })`                   |

## 鉴权与跨源怎么配才不出错？

```ts
app.use("/auth/*", (c, next) => bearerAuth({ token: c.env.API_TOKEN })(c, next)); // 固定 token
app.use("/v2/*", bearerAuth({ verifyToken: async (token) => token === expected })); // 动态校验
app.use("/api/*", jwt({ secret: c.env.JWT_SECRET, alg: "HS256" })); // payload 在 c.get("jwtPayload")
app.use("/api/*", cors({ origin: ["https://app.example.com"], credentials: true, maxAge: 600 }));
```

- CORS: 必须挂在路由之前，否则预检命不中；默认 `origin: "*"`；`credentials: true` 时不能是 `*`，要回显具体来源；反代也加会出现重复头;
- JWT: 默认 `HS256`，`exp`/`nbf`/`iat` 存在才校验，`iss`/`aud` 要显式传；`decode()` 不验签，不能用于鉴权；token 在 Cookie 里用 `jwt({ ..., cookie: "token" })`;
- 原理: [认证与授权](../../000-服务端知识/030-安全/010-认证与授权.md)、[跨源访问](../../000-服务端知识/030-安全/020-跨源访问.md);

## Cookie、安全头与 CSRF 怎么一次配好？

```ts
app.use(secureHeaders()); // 删除 X-Powered-By，加 HSTS、nosniff、SAMEORIGIN 等
app.use(csrf()); // 默认同源校验

await setSignedCookie(c, "uid", "42", secret, {
  path: "/",
  httpOnly: true,
  secure: true,
  sameSite: "Lax",
});
const uid = await getSignedCookie(c, secret, "uid"); // 字符串=通过、false=被篡改、undefined=没有
deleteCookie(c, "session", { path: "/" }); // 必须带原来的 path/domain
```

- Cookie: 签名走 HMAC-SHA256，读写都是 `async`；`sameSite: "None"` 必须同时 `secure: true`；`__Host-` / `__Secure-` 前缀用 `{ prefix: "host" | "secure" }`，读取也要声明;
- CSRF: 只校验非安全方法 + 可被表单提交的 content-type，同时看 `Origin` 与 `Sec-Fetch-Site`，任一通过即放行；反代剥掉 `Origin` 时要显式配 `origin`;
- 会话: Hono 不自带存储，有状态方案 Cookie 只放不透明 sessionId、数据放 Redis，见 [会话与 CSRF](../../000-服务端知识/030-安全/030-会话与CSRF.md);

## 体积、超时、压缩与缓存怎么配？

```ts
app.post(
  "/upload",
  bodyLimit({ maxSize: 5 * 1024 * 1024, onError: (c) => c.text("too large", 413) }),
  handler,
);
app.use("/api/*", timeout(5000)); // 超时抛 408，可换自定义异常
app.use(compress()); // Node 不自动压缩，默认 1KB 以上才压
app.use("/assets/*", etag()); // 命中 If-None-Match 返回 304
```

- `bodyLimit` 必须在解析前挂，只挂上传路由，不要全局放大;
- `timeout` 与流式响应不兼容，SSE 自己 `setTimeout(() => s.close(), ms)`;
- `ipRestriction` 支持精确 IP 与 CIDR；`getConnInfo` 来自 `@hono/node-server/conninfo`，反代后真实来源要先信任代理;
- `etag` 的 304 只保留 `Cache-Control`/`Date`/`ETag`/`Vary` 等头；`Cache-Control` 要自己写，Hono 不会替你加;
- Node 上不能用 `hono/cache`（依赖全局 Cache API），服务端缓存用 Redis 或反向代理;
- 原理: [请求边界与来源可信](../../000-服务端知识/030-安全/050-请求边界与来源可信.md)、[HTTP 缓存与 ETag](../../000-服务端知识/020-契约与错误/030-HTTP缓存与ETag.md);
