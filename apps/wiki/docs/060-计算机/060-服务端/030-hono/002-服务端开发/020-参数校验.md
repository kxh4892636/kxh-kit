# 参数校验

## 手写 validator 怎么写？

- 职责: 从请求里挑出需要的字段，失败时返回统一错误响应；手写用 `hono/validator`，schema 用 `zValidator` / `sValidator`;

```ts
import { Hono } from "hono";
import { validator } from "hono/validator";

const app = new Hono();

app.post(
  "/posts",
  validator("form", (value, c) => {
    const body = value["body"];
    if (!body || typeof body !== "string") return c.text("Invalid!", 400);
    return { body }; // 返回值即 c.req.valid('form') 的数据
  }),
  (c) => {
    const { body } = c.req.valid("form");
    return c.json({ body }, 201);
  },
);
```

- 目标与串联: 可用目标 `json`、`form`、`query`、`header`、`param`、`cookie`，多个目标串联多个 `validator`;
- 缺 `Content-Type`: `validator("json"/"form")` 收到 `{}`，测试也要带 `application/json` 或表单类型;
- header 键: 一律小写（如 `"idempotency-key"`），大写键永远 `undefined`;

## 用 Zod 等 schema 怎么校验？

- 一行 `zValidator("json", schema)` 就够，失败默认 400，响应体含 Zod 的 issue 列表;

```ts
import * as z from "zod";
import { zValidator } from "@hono/zod-validator";

const schema = z.object({ title: z.string().min(1), tags: z.array(z.string()).default([]) });

app.post("/posts", zValidator("json", schema), (c) => {
  const data = c.req.valid("json"); // 已收窄为 schema 类型
  return c.json({ ok: true, data }, 201);
});

// 多个位置：每个位置一个校验器，顺序无关
app.post(
  "/posts/:id",
  zValidator("param", z.object({ id: z.string() })),
  zValidator("query", z.object({ draft: z.coerce.boolean().optional() })),
  zValidator("json", schema),
  (c) => c.json({ id: c.req.valid("param").id }),
);
```

- 查询参数: 都是字符串，数字用 `z.coerce.number()`;
- 换库: `sValidator`（`@hono/standard-validator`）兼容任意 Standard Schema（Zod/Valibot/ArkType），换库不换中间件;
- 类型与契约: `zValidator("json", schema)` 让 `AppType` 的请求体类型变成 schema 的输入类型，客户端因此获得补全，前提是链式注册；失败响应统一结构、错误码集中定义属于契约设计，见 [接口契约与演进](../../000-服务端知识/020-契约与错误/010-接口契约与演进/010-契约不变量与形状.md);
- 相邻主题: 读请求体其他方法见 [读取请求](../001-快速上手/040-读取请求.md)；RPC 类型链路见 [hc 客户端与 AppType](../090-按需查阅/050-hc客户端.md);
