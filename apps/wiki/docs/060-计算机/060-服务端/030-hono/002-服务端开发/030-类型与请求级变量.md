# 类型与请求级变量

## c.env 和 c.set/get 分别装什么？

- 分工: `Bindings` 装环境提供、请求期间只读的东西，走 `c.env`；`Variables` 装请求期间可写的值，走 `c.set` / `c.get` / `c.var`;

```ts
import { Hono } from "hono";
import type { HttpBindings } from "@hono/node-server";

type Bindings = HttpBindings & { TOKEN: string }; // c.env.*: 环境提供、请求期间只读
type Variables = { user: { id: string } }; // c.set/get: 请求期间可写

const app = new Hono<{ Bindings: Bindings; Variables: Variables }>();

app.use(async (c, next) => {
  c.set("user", { id: "1" });
  await next();
});

app.get("/me", (c) => c.json({ user: c.var.user, ip: c.env.incoming.socket.remoteAddress }));
```

| 泛型        | 访问方式                    | 典型内容                      | 可否赋值         |
| ----------- | --------------------------- | ----------------------------- | ---------------- |
| `Bindings`  | `c.env.X`                   | 环境变量、连接池、平台绑定    | 否               |
| `Variables` | `c.set` / `c.get` / `c.var` | 中间件注入的用户、db、traceId | 是（仅本次请求） |

- 等价与累加: `c.var.x` 完全等价 `c.get("x")`；类型来自 `Variables`，链式 `.use()` 会自动累加;
- 唯一正路: `Variables` 是跨中间件传值的唯一正路，别用模块级变量;
- Node 上的 `Bindings`: 通常写成 `HttpBindings` 再交叉自有类型;

## 全局类型怎么增强？

- 适用: 全局增强对全应用生效，不用在每个 `new Hono()` 上写泛型；入口要 `import "./types"` 才生效;

```ts
// src/types.ts
declare module "hono" {
  interface ContextVariableMap {
    result: string;
  }
}
```

- 风险: 没挂载该中间件的 Handler 里 `c.get("result")` 依然被标成 `string`，运行时是 `undefined`；只在「全应用强制挂载」时用;
- 其余场景: 用 `new Hono<{ Variables }>()`；渲染场景还可以增强 `ContextRenderer`;
- 生命周期: 请求开始 → 中间件 `c.set` → Handler `c.get` → 响应结束丢弃；不能跨请求共享，`c.set` 在 Handler 之后调用无效;
