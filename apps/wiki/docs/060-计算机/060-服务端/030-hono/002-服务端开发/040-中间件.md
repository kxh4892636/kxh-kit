# 中间件

## 中间件按什么顺序执行？

- 顺序: 注册顺序决定进入顺序（1 进 → 2 进 → handler → 2 出 → 1 出），退出顺序相反;

```ts
import { Hono } from "hono";
import { logger } from "hono/logger";
import { cors } from "hono/cors";
import { basicAuth } from "hono/basic-auth";
const app = new Hono();
app.use(logger()); // 所有方法、所有路径
app.use("/posts/*", cors()); // 路径前缀
app.post("/posts/*", basicAuth({ username: "admin", password: "secret" })); // 方法 + 路径
app.use(async (c, next) => {
  const start = performance.now();
  await next();
  c.res.headers.set("X-Response-Time", `${performance.now() - start}`);
});
```

- 继续还是短路: `await next()` 后不返回 → 继续，返回 `Response` → 立即短路;
- 异常: 任何异常都交给 `app.onError`，`next()` 永不抛错，**不需要** `try/catch/finally`；传播细节见 [错误处理](../001-快速上手/060-错误处理.md);
- 注册位置: 中间件必须注册在 Handler 之前；`app.get("*")` 写在前面会吞掉所有请求;
- 洋葱模型: 与横切位置是通用知识，见 [请求生命周期](../../000-服务端知识/010-基础模型/010-请求生命周期.md);

## 自定义中间件怎么写？

- 写法: `createMiddleware` 只保住 `c` 与 `next` 的类型，行为等价 `app.use(async (c, next) => {})`;

```ts
import { createMiddleware } from "hono/factory";

const auth = createMiddleware<{ Variables: { user: { id: string } } }>(async (c, next) => {
  const token = c.req.header("Authorization");
  if (!token) return c.json({ ok: false, error: "unauthorized" }, 401);
  c.set("user", { id: "1" });
  await next();
});

// 带参数：参数放外层，中间件本体放内层
const header = (value: string) =>
  createMiddleware(async (c, next) => {
    await next();
    c.res.headers.set("X-Message", value);
  });

app.use(auth, header("hello"));
```

- 类型与短路: 泛型里声明 `Variables` 后下游 Handler 的 `c.var.user` 才有类型；不返回值的中间件不要乱 `return`，否则短路;
- 累加与注册: 链式 `.use()` 每次返回带合并 `Variables` 的新实例，不用手写组合后的 `Env`；分开 `app.use(...)` 注册则不累加;
- 按请求构造: `(c, next) => cors({ origin: c.env.CORS_ORIGIN })(c, next)`；无状态中间件在顶层构造复用;

## 中间件怎么改写响应？

- 改写要点: 必须 `await next()` 之后才能拿到真实响应；追加头用 `c.res.headers.append`，整体替换先 `c.res = undefined` 再赋值；流式响应开始写之后改不了;
- 相邻主题: `c.res` 的占位与保留头规则见 [响应与状态码](../001-快速上手/050-响应与状态码.md)；变量类型见 [类型与请求级变量](./030-类型与请求级变量.md)；内置中间件清单见 [内置中间件速查](../090-按需查阅/010-内置中间件速查.md);
