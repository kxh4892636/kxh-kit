# 中间件模型

## 中间件的执行模型是什么？

- 一条请求穿过一串「洋葱」：注册顺序决定进入顺序，退出顺序相反;

```text
middleware 1 start
  middleware 2 start
    handler
  middleware 2 end
middleware 1 end
```

```ts
app.use(async (c, next) => {
  const start = performance.now();
  await next();
  c.res.headers.set("X-Response-Time", `${performance.now() - start}`);
  // 不要 return 任何值
});
```

- 规则: `await next()` 后什么都不返回 → 交给下一层；返回 `Response` → 立即短路结束;
- 只要 Handler 或中间件抛错，Hono 一律捕获并交给 `app.onError`，所以 `next()` 永不抛错，**不需要** `try/catch/finally`;
- 错误传播的细节见 [错误处理](../001-快速上手/120-错误处理.md);

## 中间件的挂载范围怎么控制？

```ts
app.use(logger()); // 所有方法、所有路径
app.use("/posts/*", cors()); // 指定路径前缀
app.post("/posts/*", basicAuth()); // 指定方法 + 路径
```

- `app.use` 只挂中间件；`app.get/post/...` 可以挂中间件 + Handler;
- 顺序陷阱: `app.get('*', ...)` 写在具体路由之前会吞掉所有请求;
- 想让中间件生效，必须注册在 Handler 之前;

## 需要在中间件内部构造另一个中间件怎么办？

```ts
app.use("*", async (c, next) => {
  const middleware = cors({ origin: c.env.CORS_ORIGIN }); // 依赖运行时值
  return middleware(c, next);
});
```

- 适用场景: 配置来自环境变量或 `c.req` 的中间件（CORS、JWT secret、限流阈值）;
- 内置中间件大多无状态，不依赖 `c` 时直接在顶层 `const mw = cors({...})` 构造即可复用;

## 中间件能改响应吗？

```ts
// 追加头
app.use(async (c, next) => {
  await next();
  c.res.headers.append("X-Debug", "1");
});

// 整体替换（先清掉旧头）
app.use(async (c, next) => {
  await next();
  c.res = undefined;
  c.res = new Response("replaced");
});
```

- 必须 `await next()` 之后才能拿到真实响应;
- 改写规则与副作用见 [自定义响应与改写](../001-快速上手/110-自定义响应与改写.md);
- 流式响应一旦开始写，中间件再改也没用;
