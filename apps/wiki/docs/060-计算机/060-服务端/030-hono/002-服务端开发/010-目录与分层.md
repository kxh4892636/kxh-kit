# 目录与分层

## 目录怎么划分？

```text
src/
├── index.ts            # 只做 serve()
├── app.ts              # 组装所有子路由，导出 AppType
├── factory.ts          # createFactory + Env + initApp
├── routes/
│   ├── users.ts        # 子路由（链式注册）
│   └── posts.ts
├── middleware/         # auth.ts、request-id.ts
├── services/           # 纯业务函数，不碰 Context
└── repositories/       # 数据访问，隔离 SQL / ORM
```

- 原则: 路由层只做「解析 → 调 service → 映射响应」;
- service 不接收 `Context`，只收普通对象，便于单测;
- 数据库句柄通过 `c.var.db` 或模块级单例注入，不要每个 Handler 内部 `new` 一次;

## 各层之间允许怎么调用？

```text
Handler ──→ Service ──→ Repository ──→ DB
   │            │
   └── 只做 HTTP 相关: 解析、校验、状态码
```

| 层         | 可以有                    | 不可以有                  |
| ---------- | ------------------------- | ------------------------- |
| Handler    | `c.req`、`c.json`、状态码 | SQL、第三方 SDK、业务规则 |
| Service    | 业务规则、事务编排        | `Context`、`Response`     |
| Repository | SQL/ORM、缓存读写         | HTTP 概念                 |

- 这样拆的好处: Service 可以在任务、定时器、CLI 里复用，测试不需要造 Request;

## 拆分粒度多大合适？

| 信号                            | 处理                                        |
| ------------------------------- | ------------------------------------------- |
| 单文件超过 ~300 行              | 按资源拆成 `routes/*.ts`                    |
| 多个路由共用鉴权/限流           | 下沉为 `middleware/*.ts`，用 `app.use` 挂载 |
| Handler 里出现 SQL 或第三方 SDK | 抽到 `services/` 或 `repositories/`         |
| 出现同一份错误响应代码          | 收进 `app.onError` 或工具函数               |

- 不要为了「分层」把 Handler 包成类；Hono 的类型红利来自「就地写」，原因见 [不写控制器，用 factory](./020-不写控制器.md);
- 应用拼装与 `AppType` 导出见 [RPC 服务端准备](../090-按需查阅/060-RPC服务端准备.md);
