# 请求边界与缓存

## 体积、超时与来源怎么设边界？

- 三个中间件: `bodyLimit` 限请求体、`timeout` 限处理时间、`ipRestriction` 控来源，都要挂在业务逻辑之前;

```ts
import { Hono } from "hono";
import { bodyLimit } from "hono/body-limit";
import { timeout } from "hono/timeout";
import { ipRestriction } from "hono/ip-restriction";
import { getConnInfo } from "@hono/node-server/conninfo";

const app = new Hono();

app.post(
  "/upload",
  bodyLimit({
    maxSize: 5 * 1024 * 1024,
    onError: (c) => c.text("too large", 413),
  }),
  (c) => c.text("ok"),
);
app.use("/api/*", timeout(5000)); // 超时抛 408，可传自定义 HTTPException
app.use(
  "*",
  ipRestriction(
    getConnInfo,
    { allowList: ["127.0.0.1", "10.0.0.0/8"], denyList: [] },
    async (remote, c) => c.json({ ok: false, error: "forbidden" }, 403),
  ),
);
```

- `bodyLimit`: 必须在解析前挂；优先用 `Content-Length`，没有长度时分块读取并累计；不显式设 `maxSize` 时默认上限较小，只挂上传路由;
- `timeout(ms)`: 超时抛 408，可换成任意异常工厂；与流式响应不兼容，SSE 要用 `stream.close()` + `setTimeout`;
- `ipRestriction`: 支持精确 IP、CIDR（如 `192.168.2.0/24`）与 `*`；Node 的 `getConnInfo` 来自 `@hono/node-server/conninfo`，反代后真实来源在 `X-Forwarded-For`，要先信任代理;
- 原理: 见 [请求边界与来源可信](../../000-服务端知识/030-安全/050-请求边界与来源可信.md) 与 [超时预算](../../000-服务端知识/040-可靠性/010-超时预算/010-预算模型.md);

## 协商缓存怎么配？

- 一个 `etag()` 中间件: 命中 `If-None-Match` 返回 304，省掉重复传输;

```ts
import { etag, RETAINED_304_HEADERS } from "hono/etag";

app.use("/assets/*", etag({ weak: false }));
app.use("/assets2/*", etag({ retainedHeaders: ["x-message", ...RETAINED_304_HEADERS] }));
```

- 生成与保留: `etag()` 默认用 SHA-1 摘要生成 ETag（以当前版本为准）；304 只保留 `Cache-Control`、`Date`、`ETag`、`Expires`、`Vary` 等头;
- weak: `weak: true` 时 ETag 带 `W/` 前缀;
- `Cache-Control`: Hono 不会替你写，静态资源用 `public, max-age=31536000, immutable`，带身份的接口用 `private` 或 `no-store`;
- Node 上不能用 `hono/cache`: 它依赖全局 `Cache API`，服务端缓存改用 Redis 或反向代理;
- 原理: 见 [HTTP 缓存与 ETag](../../000-服务端知识/020-契约与错误/030-HTTP缓存与ETag.md);
