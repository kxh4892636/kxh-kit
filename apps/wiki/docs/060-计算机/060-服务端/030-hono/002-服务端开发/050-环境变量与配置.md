# 环境变量与配置

## 环境变量在 Node 上怎么读？

```ts
// 方案一：直接读，最简单，仅限 Node
const port = Number(process.env.PORT ?? 3000);

// 方案二：跨运行时抽象，只能放在 handler 里
import { env } from "hono/adapter";

app.get("/env", (c) => {
  const { NAME } = env<{ NAME: string }>(c); // Node/Bun 读 process.env
  return c.text(NAME);
});
```

- 只在 Node 跑就用 `process.env`；将来可能搬到 Workers/Deno 才需要 `env()`;
- `env()` 需要 `c`，不能在模块顶层调用;
- `env()` 属于 Adapter Helper，见 [Helper 与运行时速查](../090-按需查阅/045-运行时信息与路由内省.md);

## 配置该怎么组织才不出事故？

```ts
// config.ts —— 启动即校验，快速失败
import * as z from "zod";

const schema = z.object({
  PORT: z.coerce.number().default(3000),
  DATABASE_URL: z.string().url(),
  JWT_SECRET: z.string().min(32),
});

export const config = schema.parse(process.env);
// 缺变量时进程直接退出，而不是等某个请求才 500
```

- 原则: 启动时校验一次，之后全用 `config.X`，不在 Handler 里散读 `process.env`;
- 原因: 配置错误应该在部署时暴露，而不是在第一次请求时;
- 敏感值不要写默认值：缺失即失败，避免用测试密钥上了生产;

## 配置如何注入到 Handler？

```ts
app.use(async (c, next) => {
  c.set("config", config);
  await next();
});

app.get("/info", (c) => c.json({ port: c.var.config.PORT }));
```

- 类型写进 `Variables`，见 [类型声明与请求级变量](./060-类型声明与请求级变量.md);
- 只想用服务级单例时直接 `import { config }`，不必进 Context;

## 本地开发怎么管这些变量？

```sh
# Node 20+ 原生支持从文件加载，无需额外依赖
node --env-file=.env dist/index.js
```

- `.env` 进 `.gitignore`，只提交 `.env.example`;
- Docker 用 `--env-file` 或编排平台的环境变量注入，不要把 `.env` 打进镜像;
