# 响应与错误

## 响应怎么构造，状态码与头怎么写？

- 返回值即响应: `c.text/json/html/body` 产出对应 `Content-Type`；`c.redirect(url, 301)` 默认 302；`c.notFound()` 交给 `app.notFound`;
- 状态码与头: 先 `c.status()` / `c.header()` 再 return，或一次传给 `c.json(body, status, headers)`；200 不用显式设置，`c.header()` 必须在 return 之前;

```ts
app.post("/posts", (c) => {
  c.status(201);
  c.header("X-Message", "created");
  return c.json({ ok: true });
});

app.post("/posts2", (c) => c.json({ ok: true }, 201, { "X-Message": "created" }));
app.get("/bin", (c) =>
  c.body(new Uint8Array([0x48]), 200, { "Content-Type": "application/octet-stream" }),
);
```

- 契约: 统一成功/失败结构与业务码映射见 [错误分层与响应](../000-服务端知识/020-契约与错误/020-错误分类与响应/010-错误分层与响应.md)；有类型安全客户端时失败一律 `return c.json(..., status)`，客户端才推得出错误体类型;

## 已经生成的响应还能改吗？

- 能，但只能在 `await next()` 之后: 追加头用 `c.res.headers.append`；整体替换先 `c.res = undefined` 再赋值（会保留旧响应除 `content-type` 外的头）;
- 流式响应一旦开始写就改不了;

```ts
app.use(async (c, next) => {
  await next();
  c.res.headers.append("X-Debug", "1");
});
```

## 抛出的异常最后去哪，该抛什么？

- 去向: 任何异常都被捕获并交给 `app.onError`，没写则自动 500；中间件读 `c.error` 记日志，不要再返回响应;
- 取舍: 预期内错误直接 `return c.json(..., 4xx)`；深层 Service 或第三方库抛 `HTTPException`；不可恢复的程序错误抛普通 `Error`;

```ts
import { HTTPException } from "hono/http-exception";

app.onError((err, c) => {
  if (err instanceof HTTPException) return err.getResponse();
  console.error(err);
  return c.json({ ok: false, error: "internal_error" }, 500);
});

// 自定义响应体；或用 { message, cause } 保留原始错误
throw new HTTPException(401, { res: new Response("Unauthorized") });
```

- `HTTPException`: 状态码以构造参数为准，`res` 里的 status 被忽略；`getResponse()` 不带 `c.header()` 设过的头；流式响应内不可用;
- 404: `app.notFound((c) => c.json({ ok: false, error: "not_found" }, 404))`，只有顶层应用生效；路径存在但方法不对默认也是 404，要 405 挂 `methodNotAllowed({ app })`;
- 传播: Handler 抛错 → 那层中间件捕获（自己的 after 代码不再执行）→ `onError` 出响应 → 外层 `next()` 正常返回；`next()` 永不抛错，不用 try/catch;
- 日志字段与脱敏见 [日志与请求 ID](../000-服务端知识/060-观测与交付/010-日志与请求ID.md);
