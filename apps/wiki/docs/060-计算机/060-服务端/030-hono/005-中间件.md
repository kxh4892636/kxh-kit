# 中间件

## 中间件按什么顺序执行，什么时候短路？

- 顺序: 注册顺序进入，退出顺序相反（1 进 → 2 进 → Handler → 2 出 → 1 出）;
- 短路: `await next()` 后不返回就继续，返回 `Response` 立即短路;
- 异常: 都交给 `app.onError`，`next()` 永不抛错，不用 try/catch，见 [响应与错误](./003-响应与错误.md);
- 位置: 必须注册在 Handler 之前，`app.get("*")` 写前面会吞掉所有请求;

```ts
app.use(logger()); // 所有方法与路径
app.use("/posts/*", cors()); // 路径前缀
app.post("/posts/*", basicAuth({ username: "admin", password: "secret" })); // 方法 + 路径
```

## 自定义中间件怎么写？

- 写法: `createMiddleware`（`hono/factory`）只保住 `c` 与 `next` 的类型，行为等价 `app.use(async (c, next) => {})`；带参数把参数放外层;

```ts
const auth = createMiddleware<{ Variables: { user: { id: string } } }>(async (c, next) => {
  if (!c.req.header("Authorization")) return c.json({ ok: false, error: "unauthorized" }, 401);
  c.set("user", { id: "1" });
  await next();
});

const header = (value: string) =>
  createMiddleware(async (c, next) => {
    await next();
    c.res.headers.set("X-Message", value);
  });

app.use(auth, header("hello"));
```

- 类型: 泛型里声明 `Variables` 后下游才有 `c.var.user`；链式 `.use()` 每次累加，分开 `app.use(...)` 注册则不累加;
- 按请求构造: `(c, next) => cors({ origin: c.env.CORS_ORIGIN })(c, next)`；无状态中间件在顶层构造一次复用;
- 改写响应必须 `await next()` 之后，写法见 [响应与错误](./003-响应与错误.md);

## 注册顺序怎么排？

- 参考顺序: 安全头 → 请求 ID → 日志 → 压缩 → 跨域 → 超时 → 体积限制 → 鉴权 → 业务路由；鉴权靠后，少做无用功;

```ts
app.use(secureHeaders());
app.use(requestId());
app.use(logger());
app.use(compress());
app.use("/api/*", cors());
app.use("/api/*", timeout(10_000));
app.use("/api/*", bodyLimit({ maxSize: 1024 * 1024 }));
app.use("/api/*", auth);
app.route("/api", apiRoutes);
```

- 洋葱模型与横切位置是通用知识，见 [请求生命周期](../000-服务端知识/010-基础模型/010-请求生命周期.md)；各中间件的导入与选项见 [常用中间件](./006-常用中间件.md);
