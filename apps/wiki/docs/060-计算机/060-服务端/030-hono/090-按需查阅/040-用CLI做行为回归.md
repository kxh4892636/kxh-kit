# 用 CLI 做行为回归

## 不启服务怎么给 app 打一次请求？

- 做法: 加载 app 后用 `app.request()` 打请求并输出 JSON，不监听端口;
- 本地: 快速验证一次改动;
- CI: 跑固定请求集做回归;

```sh
npm i -D @hono/cli

npx hono routes --plain       # 列出路由，含挂载与 basePath 展开
npx hono request /posts       # 用 app.request() 打一次请求
npx hono snapshot > snap.jsonl
# 改代码（重构、加中间件）
npx hono diff                 # 对比行为变化
```

## 七个子命令各做什么？

| 命令                 | 作用                                     |
| -------------------- | ---------------------------------------- |
| `hono routes`        | 列出所有路由（含挂载与 `basePath` 展开） |
| `hono request /path` | 用 `app.request()` 打一次请求            |
| `hono batch <file>`  | 跑一批带期望的请求                       |
| `hono snapshot`      | 把当前行为导出为 batch JSONL             |
| `hono diff`          | 对比未提交改动带来的行为变化             |
| `hono benchmark`     | 测应用内部性能                           |
| `hono init`          | 在当前目录加一个 Hono 应用               |

## CLI 怎么找入口、输出什么契约？

- 找入口: `file` 省略时自动找 `src/index.ts(x)`、`src/index.js(x)`;
- 输出: 加 `--plain` 得人类可读结果，否则是 JSON;
- 成功: `{ ok, data }`;
- 失败: `{ ok: false, error: { code, message, suggestions } }`，便于脚本判断;

## diff 与单测怎么分工？

- `diff`: 回答「行为变没变」;
- 单测: 回答「逻辑对不对」，两者互补; 不需要为 CLI 改代码;
- 自查: 给编码 agent 一个不启服务就能跑的行为入口;
- `app.request()` 与 `testClient` 单测: [002-服务端开发](../002-服务端开发/README.md); 路由打印 `showRoutes`: [Helper 速查](./020-Helper速查.md);
