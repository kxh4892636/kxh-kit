# 流式与 SSE

## 什么时候边算边发，用哪个 Helper？

- 流式: 普通响应全部算完才发出; 流式边算边发，适合大文件、日志、LLM 逐字输出与进度推送;
- 选型: 只需要服务端推就用 SSE; 双向通信用 WebSocket;

```ts
import { stream, streamText, streamSSE } from "hono/streaming";

app.get("/stream", (c) =>
  stream(c, async (s) => {
    s.onAbort(() => console.log("客户端断开"));
    await s.write(new Uint8Array([0x48, 0x69]));
    await s.pipe(anotherReadableStream);
  }),
);

app.get("/text", (c) =>
  streamText(c, async (s) => {
    await s.writeln("Hello");
    await s.sleep(1000);
    await s.write("Hono!"); // 不换行
  }),
);

let id = 0;
app.get("/sse", (c) =>
  streamSSE(c, async (s) => {
    while (!s.aborted) {
      await s.writeSSE({
        data: `now: ${new Date().toISOString()}`,
        event: "tick",
        id: String(id++),
      });
      await s.sleep(1000);
    }
  }),
);
```

## 三种流各发什么、谁来关闭？

- `stream(c, cb)`: Content-Type 由你定，默认二进制;
- `streamText`: `text/plain` + `Transfer-Encoding: chunked`;
- `streamSSE`: 用 `writeSSE({ data, event, id })`，`data` 里的换行自动拆成多行 `data:`; 循环条件用 `s.aborted`;
- 关闭: 回调执行完流自动关闭，不需要手动 `close()`;
- 中断: `s.onAbort()` 是清理计时器、取消上游订阅的唯一挂点;

## 流开始后哪些事不能再做？

- 头: 一旦开始写，状态码与响应头不能再改;
- 错误: 流已开始时 `app.onError` 不会触发，业务错误用 `event: error` 告知客户端; 流内错误用第三个参数，`stream(c, cb, (err, s) => { console.error(err); s.writeln("error occurred"); })`;
- 超时: `timeout()` 与流式响应冲突，用 `setTimeout(() => s.close(), 3000)` + `s.onAbort` 里 `clearTimeout` 自己做;

## 心跳、代理与鉴权怎么配？

- 心跳: SSE 每 15s 一条 `: ping` 注释; 长连接间隔 ≤30s，防 Nginx/ELB 空闲断链;
- 代理: Nginx 需 `proxy_buffering off`、`proxy_read_timeout 3600s`; 不要对 `text/event-stream` 压缩;
- 鉴权: `EventSource` 不能自定义头，用 Cookie 或 query token;
