# SSR 实践

## 深层组件怎么读上下文，页面缓存怎么加？

- 做法: 在 `jsxRenderer` 范围内用 `useRequestContext()` 取 `Context`，不必一路传 props;
- 数据: Handler 或中间件放进 `c.var`，组件里不查库;
- 缓存: `c.header("Cache-Control", "public, max-age=60")` 后再 `c.render(...)` 是一行就能加上的页面缓存;

```tsx
import { jsxRenderer, useRequestContext } from "hono/jsx-renderer";

const User = () => {
  const c = useRequestContext();
  return <span>{c.get("userName")}</span>;
};

app.use(
  "/app/*",
  jsxRenderer(({ children }) => <main>{children}</main>),
);
app.use("/app/*", async (c, next) => {
  c.set("userName", "alice");
  await next();
});
app.get("/app/me", (c) => c.render(<User />));
```

## 客户端水合要自己接哪两步？

- 前提: Hono 的 JSX 是服务端渲染模板，客户端水合要自己接;
- 两步: 服务端 `renderToString` 产出 HTML，浏览器 `hydrateRoot` 接管同一棵组件树;

```tsx
// server.tsx —— 用 hono/jsx/dom 的组件产出 HTML
import { renderToString } from "hono/jsx/dom/server";
app.get("/", (c) => c.html(renderToString(<Counter />)));

// client.tsx —— 浏览器接管同一棵组件树
import { hydrateRoot } from "hono/jsx/dom/client";
hydrateRoot(document.getElementById("root")!, <Counter />);
```

- 来源: `renderToString` 来自 `hono/jsx/dom/server`，`hydrateRoot` 来自 `hono/jsx/dom/client`;
- 运行时: 客户端组件需配 `jsxImportSource: "hono/jsx/dom"`; 该运行时里 hydrate 等价于 render;
- 边界: 需要客户端路由、状态管理时用真正的 SSR 框架，Hono 只做 API 与初始 HTML;

## 错误响应怎么分流，输出怎么转义？

- 分流: 同一应用同时提供页面和 API 时，按 `Accept` 决定返回 HTML 还是 JSON;
- 安全: 生产不要把堆栈渲染进页面;
- 转义: JSX 与 `html` 默认转义，`raw` / `dangerouslySetInnerHTML` 才关闭;

```ts
app.onError((err, c) => {
  if (c.req.header("Accept")?.includes("text/html")) {
    return c.html("<h1>页面出错了</h1>", 500);
  }
  return c.json({ ok: false, error: "internal_error" }, 500);
});
```
