# hc 响应类型与工具

## 响应类型怎么利用？

```ts
import type { InferRequestType, InferResponseType } from "hono/client";

type Req = InferRequestType<typeof client.posts.$post>["form"];
type Res = InferResponseType<typeof client.posts.$post>; // 所有状态码的并集
type Res201 = InferResponseType<typeof client.posts.$post, 201>; // 仅 201
```

- 按状态码收窄分支：

```ts
if (res.status === 404) {
  const err: { error: string } = await res.json();
}
```

- 想直接拿解析后的 body 并在非 2xx 时抛错，用 `parseResponse`：

```ts
import { parseResponse, DetailedError } from "hono/client";

const data = await parseResponse(client.hello.$get()).catch((e: DetailedError) => e);
```

## 全局错误怎么进类型？

```ts
type AppWithErrors = ApplyGlobalResponse<
  typeof app,
  {
    500: { json: { ok: false; error: string } };
  }
>;
const client = hc<AppWithErrors>("http://localhost");
```

- `app.onError` 的错误体不会自动进类型，必须显式合并;
- 多个状态码可以一次声明: `{ 401: {...}, 500: {...} }`;
- 前提是服务端在各分支都显式写了状态码，见 [RPC 服务端准备](./060-RPC服务端准备.md);

## 如何取 URL 而不发请求？

```ts
const url = client.api.posts.$url(); // 需要绝对 base URL
const path = client.api.posts.$path({ query: { page: "1" } }); // '/api/posts?page=1'
const wsUrl = client.api.ws.$ws(0); // WebSocket 端点
```

- `$url()` 传相对路径会抛 `Failed to construct 'URL'`;
- `$path()` 不含 origin，适合做 SWR key、路由跳转、日志;
- `$ws()` 返回已连接的 `WebSocket` 对象，对应服务端 `upgradeWebSocket`;

## 和 SWR/React Query 怎么配合？

```ts
const $get = client.hello.$get;
const fetcher = (arg: InferRequestType<typeof $get>) => async () => {
  const res = await $get(arg);
  return await res.json();
};
```

- 用 `$path()` 作为查询键最稳，路径变了缓存自然失效;
- 类型由 `InferRequestType` 与 `InferResponseType` 提供，不需要手写 DTO;
