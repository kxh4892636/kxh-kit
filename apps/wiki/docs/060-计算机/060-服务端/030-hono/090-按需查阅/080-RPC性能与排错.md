# RPC 性能与排错

## 大项目为什么会变慢？

| 症状                                     | 原因                     | 对策                       |
| ---------------------------------------- | ------------------------ | -------------------------- |
| IDE 卡顿、类型提示延迟                   | 路由越多，类型实例化越重 | 拆分 app + 分别生成 client |
| `Type instantiation is excessively deep` | 前后端 Hono 版本不一致   | 锁同版本                   |
| 跨仓引用报错                             | 没配 project references  | 加 TS project references   |
| 只想一次性算好类型                       | tsserver 每次重算        | 编译期预算 `hcWithType`    |

```ts
// client.ts —— 编译时就算好类型
import { app } from "./app";
import { hc } from "hono/client";

const client = hc<typeof app>("");
export type Client = typeof client;
export const hcWithType = (...args: Parameters<typeof hc>): Client => hc<typeof app>(...args);
```

- 之后用 `hcWithType('http://localhost:3000/')` 替代 `hc(...)`，IDE 不再重复实例化;
- 另一条硬性要求: 前后端 `tsconfig` 都要 `"strict": true`;

## 还有哪些降低类型开销的做法？

- 按资源拆分 app，每个子应用单独 `hc`，tsserver 不必一次算全量;
- 手写路由泛型（`app.get<'foo/:id'>`）能省一次推导，但维护成本高，只在极端场景用;
- 把服务端与客户端放在同一 monorepo，用 `turborepo` / `pnpm` workspace 管依赖版本;

## 响应类型推不出来怎么排查？

| 现象                      | 原因                                                             |
| ------------------------- | ---------------------------------------------------------------- |
| `res.json()` 是 `unknown` | 用了 `c.notFound()`，或 Handler 没有显式状态码                   |
| 只有 200 分支             | `c.json()` 没传状态码                                            |
| 请求体类型是 `any`        | 没挂校验器，或路由不是链式注册                                   |
| 全部类型丢失              | `AppType` 导出的是 `typeof app` 但 app 是分开 `app.get()` 注册的 |

```ts
// ❌ 分开注册 → 类型链断了
const app = new Hono();
app.get("/foo/:id", (c) => c.json({ ok: true }));

// ✅ 链式 → 类型完整
const app = new Hono().get("/foo/:id", (c) => c.json({ ok: true }, 200));
```

- 还有一种隐蔽情况: Handler 直接返回 `.then()` 链会丢响应类型，改成 `async/await`;
- 改完记得重新编译，避免 IDE 用的是旧的声明文件;
