# JSX 组件与样式

## 什么场景要开 hono/jsx，配置改哪几处？

- 场景: 需要组件、props、类型检查与自动转义时，用 `hono/jsx` 在服务端渲染 HTML; 纯 JSON API 不引入渲染层;
- 文件名: 扩展名改 `.tsx`，`dev` 脚本入口路径同步改;

```json title="tsconfig.json"
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "hono/jsx"
  }
}
```

- 不想动 tsconfig: 用文件级注释 `/** @jsx jsx */` + `/** @jsxImportSource hono/jsx */`;

## 组件签名、Fragment 与原始 HTML 怎么写？

- `FC`: 定义组件; `PropsWithChildren`: 让 `children` 有类型; Fragment: `<Fragment>` 或 `<>...</>`;

```tsx
import type { FC, PropsWithChildren } from "hono/jsx";

const Layout: FC = (props) => (
  <html>
    <body>{props.children}</body>
  </html>
);

function Card({ title, children }: PropsWithChildren<{ title: string }>) {
  return (
    <div>
      <h1>{title}</h1>
      {children}
    </div>
  );
}

app.get("/", (c) =>
  c.html(
    <Layout>
      <Card title="Hi">body</Card>
    </Layout>,
  ),
);
```

- 原始 HTML: `dangerouslySetInnerHTML={{ __html: "<b>x</b>" }}`; 静态子树可用 `memo()` 缓存;

## 样式与数据边界怎么划？

- 样式: `hono/css` 的 `css` 标签生成类名，SSR 时收集样式; 已有 Tailwind / CSS Modules 的项目不必引入;
- 重复: 同一文件里重复定义同一组样式会生成不同类名，别重复定义;
- 边界: 组件只负责渲染; 数据在 Handler/中间件准备好; 不要查库、发网络请求或依赖全局可变状态;
- 布局复用与 `c.render`: [080-布局与元数据](./080-布局与元数据.md); 请求上下文与渲染兜底: [090-SSR实践](./090-SSR实践.md);
