# SSR 实践与注意

## 深层组件怎么拿请求上下文？

```tsx
import { useRequestContext } from "hono/jsx-renderer";

const User = () => {
  const c = useRequestContext();
  return <span>{c.get("userName")}</span>;
};
```

- 只在 `jsxRenderer` 生效的范围内可用;
- 适合「布局里显示当前用户名」这类跨层数据，避免一路传 props;
- 组件里不要做数据库查询，数据应在 Handler 或中间件准备好后放进 `c.var`;

## SSR 页面在 Node 上要注意什么？

| 事项     | 说明                                                             |
| -------- | ---------------------------------------------------------------- |
| 转义     | JSX 与 `html` 默认转义；`raw` / `dangerouslySetInnerHTML` 才关闭 |
| 缓存     | 加 `Cache-Control`，或交给反向代理缓存 HTML                      |
| 混合路由 | 渲染比 JSON 慢，纯 API 路由不要混进渲染逻辑                      |
| 依赖注入 | 布局要用数据库数据时从 `c.var` 取，不在组件内 new 连接           |
| 测试     | `app.request()` 的 `res.text()` 直接断言 HTML 片段即可           |

```ts
// 页面缓存最省事的一行
app.get('/about', (c) => {
  c.header('Cache-Control', 'public, max-age=60')
  return c.render(<p>about</p>)
})
```

## 什么时候该上真正的 SSR 框架？

- 需要客户端水合（hydrate）、路由切换、状态管理时，Hono 只做 API，前端交给框架;
- Hono 的 JSX 是「服务端渲染模板」，不带客户端运行时;
- 需要客户端 JSX 能力（`hono/jsx/dom`）时属于前端领域，不在本手册范围;

## 渲染出错该怎么兜底？

```ts
app.onError((err, c) => {
  if (c.req.header("Accept")?.includes("text/html")) {
    return c.html("<h1>页面出错了</h1>", 500);
  }
  return c.json({ ok: false, error: "internal_error" }, 500);
});
```

- 同一个应用同时提供页面和 API 时，按 `Accept` 分流错误响应;
- 生产环境不要把堆栈渲染进页面;
