# 第三方中间件与弃用项

## 第三方中间件在哪里找、要注意什么？

| 类别    | 代表包                                                                                |
| ------- | ------------------------------------------------------------------------------------- |
| 校验    | `@hono/zod-validator`、`@hono/valibot-validator`、`@hono/typebox-validator`           |
| 认证    | `@hono/oauth-providers`、`@hono/oidc-auth`、`@hono/firebase-auth`、`@hono/clerk-auth` |
| OpenAPI | `@hono/zod-openapi` + `@hono/swagger-ui`、`hono-openapi`                              |
| 监控    | Sentry、Apitally                                                                      |

- 来源: 官方集合在 [honojs/middleware](https://github.com/honojs/middleware)；
- 首要坑: 第三方包与 `hono` 的版本必须匹配，版本错位会出现类型推导失败或运行时报错;
- 第三方中间件会引入外部依赖，与「零依赖」的内置中间件不同，上生产前评估体积与维护情况;
- 需要 `-ws`、`-conninfo` 这类平台能力时，找「运行时适配器包」而不是核心包;

## 哪些 API 已弃用？

| 弃用                   | 替代                                        |
| ---------------------- | ------------------------------------------- |
| `app.mount(path, app)` | `mount()` 中间件                            |
| `app.fire()`           | `@hono/service-worker` 的 `fire()`          |
| `c.req.routePath`      | `routePath(c)`（`hono/route`）              |
| `c.req.matchedRoutes`  | `matchedRoutes(c)`                          |
| `@hono/node-ws`        | `@hono/node-server` 内置 `upgradeWebSocket` |

- 迁移到 v5 的完整清单见官方 `guides/migrating-to-v5`；新项目按本手册写即可，不会用到上面这些;

## 组合多条访问规则怎么写？

```ts
import { every, some, except } from "hono/combine";

// 任一满足即可（多来源鉴权）
app.use(
  "/api/*",
  some(bearerAuth({ token }), ipRestriction(getConnInfo, { allowList: ["10.0.0.0/8"] })),
);

// 全部满足
app.use(
  "/admin/*",
  every(authMiddleware, ipRestriction(getConnInfo, { allowList: ["10.0.0.0/8"] })),
);

// 条件不满足时才执行
app.use("/api/*", except("/api/public/*", authMiddleware));
```

| 函数                  | 语义                                       |
| --------------------- | ------------------------------------------ |
| `some(...mw)`         | 按顺序尝试，第一个通过的生效；都失败才抛错 |
| `every(...mw)`        | 全部必须通过，任意一个失败即短路           |
| `except(条件, ...mw)` | 条件命中时跳过这些中间件                   |

- 适合把「鉴权 + IP 白名单 + 限流」这类策略表达式化，避免写成一长串 if;
- 条件既可以是路径字符串（支持通配），也可以是 `(c) => boolean`;
