# 布局与元数据

## jsxRenderer 挂上后页面还写什么？

- 分工: 布局挂到一组路由上，页面只写内容; `c.render(jsx)` 输出 `setRenderer` 里拼好的整页;
- 等价: `jsxRenderer` 是 `c.setRenderer()` 的语法糖; 不用它时在中间件里 `c.setRenderer((content) => c.html(...))` 后 `await next()`，效果相同;

```tsx
import { jsxRenderer } from "hono/jsx-renderer";

app.use(
  "/page/*",
  jsxRenderer(({ children }) => (
    <html>
      <body>
        <header>Menu</header>
        {children}
      </body>
    </html>
  )),
);

app.get("/page/a", (c) => c.render(<p>content</p>));
```

- 挂载: `app.use("*", ...)` 全站页面、`app.use("/admin/*", ...)` 某个区段、每路由自己 `c.render` 适合两三页; 布局只挂页面路径，避免影响 JSON 接口;

## 布局参数怎么传给 ContextRenderer？

- 做法: 模块增强 `ContextRenderer`，让 `c.render(content, head)` 多收标题等参数;

```tsx
declare module "hono" {
  interface ContextRenderer {
    (content: string, head: { title: string }): Response | Promise<Response>;
  }
}

app.use("/pages/*", async (c, next) => {
  c.setRenderer((content, head) =>
    c.html(
      <html>
        <head>
          <title>{head.title}</title>
        </head>
        <body>{content}</body>
      </html>,
    ),
  );
  await next();
});

app.get("/pages/me", (c) => c.render(<p>Ramen</p>, { title: "My favorite" }));
```

- 位置: 模块增强要放在会被入口引入的 `.ts` 文件里，否则类型不生效; 参数多了抽成对象，不要加位置参数;

## 重复的 title 和 meta 从哪来？

- 重复: 布局写默认 `<title>`、页面再写 → 两个 `<title>`; 布局与页面都写同名 meta → 重复，SEO 可能取第一个;
- 提升: `<title>`、`<meta>`、`<link>` 会自动提升到文档 `<head>`; 已有 head 元素不会移除，后出现的追加在后面;
- 约定: 布局只写 charset、viewport 这类固定 meta，业务 meta 留给页面; 需要严格去重时在布局里接收参数拼 head;
