# 用 CLI 做行为回归

## Hono CLI 解决什么问题？

- 不启服务，直接加载 app，用 `app.request()` 打请求，输出 JSON;
- 适合本地快速验证、CI 回归、以及给编码 agent 提供「能自查」的入口;
- 安装: `npm i -D @hono/cli`，或全局 `npm i -g @hono/cli`;

## 有哪些命令？

| 命令                 | 作用                                     |
| -------------------- | ---------------------------------------- |
| `hono routes`        | 列出所有路由（含挂载与 `basePath` 展开） |
| `hono request /path` | 用 `app.request()` 打一次请求            |
| `hono batch <file>`  | 跑一批带期望的请求                       |
| `hono snapshot`      | 把当前行为导出为 batch JSONL             |
| `hono diff`          | 对比未提交改动带来的行为变化             |
| `hono benchmark`     | 测应用内部性能                           |
| `hono init`          | 在当前目录加一个 Hono 应用               |

- `file` 省略时自动找 `src/index.ts(x)`、`src/index.js(x)`;
- 加 `--plain` 得到人类可读输出，其余情况输出 JSON;

## 典型工作流怎么走？

```sh
# 1. 先看路由是否如预期
npx hono routes --plain

# 2. 记录当前行为
npx hono snapshot > snap.jsonl

# 3. 改代码（重构、加中间件）

# 4. 看行为有没有变
npx hono diff
```

- `diff` 回答「行为变没变」，单测回答「逻辑对不对」，两者互补;
- 输出是 `{ ok, data }` / `{ ok: false, error: { code, message, suggestions } }`，便于脚本判断;
- 失败时 `error.suggestions` 直接给出下一步建议，`error.docs` 指向官方文档页;

## 和测试框架怎么分工？

| 工具                     | 适合                             |
| ------------------------ | -------------------------------- |
| `app.request()` + Vitest | 断言细节、覆盖分支、mock 依赖    |
| `hono batch` / `diff`    | 大量接口的冒烟回归、重构前后对比 |

- 不需要为了 CLI 改代码；它读的就是你导出的 app;
- 需要类型安全的测试客户端，用 `testClient`，见 [测试](../002-服务端开发/200-用app.request测试.md);
