# 请求绑定与校验

## 绑定和校验怎么一步做完？

- 一个调用: `c.BindAndValidate(&req)` 先按 tag 绑定，再跑 `vd` 校验，失败返回 400 与稳定业务码;

```go
type CreateArticleRequest struct {
	Title   string   `json:"title" vd:"len($)>0 && len($)<=100"`
	Content string   `json:"content" vd:"len($)>0"`
	Tags    []string `json:"tags"`
}

func createArticle(ctx context.Context, c *app.RequestContext) {
	var req CreateArticleRequest
	if err := c.BindAndValidate(&req); err != nil {
		c.JSON(consts.StatusBadRequest, map[string]string{
			"code": "INVALID_ARGUMENT", "message": "invalid request",
		})
		return
	}
	// 调 Service。
}
```

- 参数必须是结构体指针;
- `vd` 里 `$` 指字段本身：`len($)>0` 非空，`len($)<=100` 上限;

## vd 表达式能写哪些校验、哪些不该写？

- 只写字段级约束: 长度与数值范围，复杂规则留到 Service;

- 长度：`len($)>0 && len($)<=100`；Go 的 `len` 对字符串按字节算，中文按字符限制就在 Service 里用 `[]rune` 再判;
- 数值范围：`$>0`、`$>=1 && $<=100`;
- 复杂规则（所有权、状态机、跨字段一致性）不要塞进 `vd`，放 Service 里;

## 参数从 path、query、header、body、form 各怎么绑定？

- 一个来源一个 tag: 路径变量、查询串、Header、JSON body、表单各走各的;

| 来源   | tag                          | 放什么                 |
| ------ | ---------------------------- | ---------------------- |
| path   | `path:"id"`                  | 资源标识               |
| query  | `query:"page"`               | 分页、过滤、排序       |
| header | `header:"X-Idempotency-Key"` | 认证、幂等键、内容协商 |
| json   | `json:"title"`               | JSON 请求体            |
| form   | `form:"name"`                | 表单或上传元数据       |

- 用 hz 生成时，这些来源由 IDL 的 `api.path/query/header/body/form` 决定，见 [009-HTTP注解与生成布局](./009-HTTP注解.md);
- 校验失败映射成哪个状态码与业务码，见 [错误分类与响应](../000-服务端知识/020-契约与错误/030-错误分层与响应.md);
