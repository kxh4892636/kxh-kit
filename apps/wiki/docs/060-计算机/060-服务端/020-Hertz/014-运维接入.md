# 运维接入

## 优雅退出怎么接进 Spin？

- 分工: `WithExitWaitTime` 只是等待上限，摘流与传播要应用自己实现，DB 在 `Spin` 返回后关；见 [优雅退出](../000-服务端知识/040-可靠性/040-优雅退出/010-退出顺序.md);

```go
h := server.Default(server.WithExitWaitTime(10 * time.Second))
h.Engine.OnShutdown = append(h.Engine.OnShutdown, func(ctx context.Context) {
	// 并发触发，且早于在途 Handler 结束：这里只发停止通知。
})
h.SetCustomSignalWaiter(func(errs chan error) error {
	signals := make(chan os.Signal, 1)
	signal.Notify(signals, os.Interrupt, syscall.SIGTERM)
	select {
	case err := <-errs:
		return err
	case <-signals:
		ready.Store(false)      // 先让 readiness 失败，摘流
		time.Sleep(time.Second) // 示例：等摘流传播
		return nil
	}
})
h.Spin()
```

## 健康检查的 /livez 与 /readyz 各查什么？

- 分工: `/livez` 只证明进程活着，`/readyz` 才查依赖且带超时；探针不做重查询，见 000「健康检查与摘流」;

```go
var ready atomic.Bool

h.GET("/livez", func(ctx context.Context, c *app.RequestContext) { c.Status(consts.StatusOK) })
h.GET("/readyz", func(ctx context.Context, c *app.RequestContext) {
	pingCtx, cancel := context.WithTimeout(ctx, 200*time.Millisecond)
	defer cancel()
	if !ready.Load() || pool.PingContext(pingCtx) != nil {
		c.Status(consts.StatusServiceUnavailable)
		return
	}
	c.Status(consts.StatusOK)
})
```

## 请求 ID 怎么贯穿日志？

- 结构化: 请求 ID 进 `c.Set` 与 `X-Request-ID`，日志只写结构化字段，Authorization、Cookie、密码与 DSN 不进日志；传播见 000「日志与请求 ID」;

```go
h.Use(func(ctx context.Context, c *app.RequestContext) {
	var b [16]byte
	if _, err := rand.Read(b[:]); err != nil {
		c.AbortWithStatus(consts.StatusInternalServerError)
		return
	}
	id := hex.EncodeToString(b[:])
	c.Set("request_id", id)
	c.Header("X-Request-ID", id)
	c.Next(ctx)
	log.Printf("request_id=%s method=%s status=%d", id, c.Method(), c.Response.StatusCode())
})
```
