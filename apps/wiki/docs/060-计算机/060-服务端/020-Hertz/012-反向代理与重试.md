# 反向代理与重试

## 反向代理怎么写才不会变成开放代理？

- 目标只来自服务端白名单，未命中直接拒绝；上游不可达与上游 5xx 分开记指标;

```go
var upstream = map[string]string{
	"/api/v1/articles": "http://article-svc:8080",
}

func proxy(ctx context.Context, c *app.RequestContext) {
	base, ok := upstream[string(c.Request.Path())] // 目标只来自服务端白名单
	if !ok {
		c.AbortWithStatus(consts.StatusNotFound) // 明确拒绝，避免变成开放代理
		return
	}
	req := protocol.AcquireRequest()
	resp := protocol.AcquireResponse()
	defer protocol.ReleaseRequest(req)
	defer protocol.ReleaseResponse(resp)

	req.SetRequestURI(base + string(c.Request.URI().RequestURI()))
	req.Header.SetMethodBytes(c.Method())
	req.SetBody(c.Request.Body())

	if err := hc.Do(ctx, req, resp); err != nil { // hc 是进程内复用的 Client
		c.AbortWithStatus(consts.StatusBadGateway)
		return
	}
	c.Response.SetStatusCode(resp.StatusCode())
	c.Response.SetBody(resp.Body())
}
```

- 只复制状态码与 body；hop-by-hop 头（`Connection`、`Keep-Alive`、`Transfer-Encoding`、`Upgrade`）不要透传;
- 大 body 不要先 `c.Request.Body()` 读进内存，改用流式接口并限制大小;
- 逐跳头与转发头的规则见 [反向代理与网关](../000-服务端知识/070-通信/030-反向代理与网关.md)。

## 哪些请求可以重试？

- 框架没有重试策略，`retryable` 自己判方法与状态;

```go
func retryable(method string, status int) bool {
	if method != consts.MethodGet && method != consts.MethodHead {
		return false
	}
	switch status {
	case consts.StatusBadGateway, consts.StatusServiceUnavailable, consts.StatusGatewayTimeout:
		return true
	}
	return false
}
```

- 总预算要扣掉已用时间，超了就不再试；放大风险与幂等前提见 [重试与幂等](../000-服务端知识/040-可靠性/030-重试与幂等.md)。
