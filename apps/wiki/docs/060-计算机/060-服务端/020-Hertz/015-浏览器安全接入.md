# 浏览器安全接入

## CORS 怎么配才不把凭据放给任意站点？

- 带凭据时 `AllowOrigins` 必须是具体来源，预检 `OPTIONS` 要在鉴权前放行;

```go
h.Use(cors.New(cors.Config{ // github.com/hertz-contrib/cors
	AllowOrigins:     []string{"https://app.example.com"},
	AllowMethods:     []string{"GET", "POST", "PUT", "DELETE"},
	AllowHeaders:     []string{"Origin", "Content-Type", "Authorization"},
	AllowCredentials: true,
}))
```

## 会话与 CSRF 怎么配合？

- Cookie 只放随机 session ID、状态留在服务端；SameSite、token、Origin 三者一起用；现成实现是 `hertz-contrib/csrf`;

```go
// 只把随机 session ID 放进 Cookie，状态留在服务端。
c.SetCookie("sid", sid, 3600, "/", "app.example.com", protocol.CookieSameSiteLaxMode, true, true)

func checkCSRF(c *app.RequestContext) bool {
	if c.IsGet() || c.IsHead() { return true }
	return subtle.ConstantTimeCompare(c.GetHeader("X-CSRF-Token"), []byte(c.GetString("csrf_token"))) == 1
}
```

- Cookie 属性与 token 绑定的规则见 [会话与 CSRF](../000-服务端知识/030-安全/020-会话与CSRF.md)。

## 安全响应头怎么加？

- 中间件加头，按 API 与页面分别取舍；现成实现是 `hertz-contrib/secure`;

```go
h.Use(func(ctx context.Context, c *app.RequestContext) {
	c.Header("X-Content-Type-Options", "nosniff")
	c.Header("X-Frame-Options", "DENY")
	c.Next(ctx)
})
```

- 各头的取舍见 [安全响应头](../000-服务端知识/030-安全/030-安全响应头.md)。

## 请求边界怎么在解析前挡住？

```go
h := server.Default(
	server.WithMaxRequestBodySize(1<<20),   // 解析前限 body
	server.WithReadTimeout(3*time.Second),  // 慢请求不占连接
)
```

- 代理头与客户端 IP 的可信判断见 [请求边界与来源可信](../000-服务端知识/030-安全/040-请求边界与来源可信.md);
- Hertz 没有内置的 header 数量上限，网关层的限制要单独配。
