# 错误与认证接入

中间件按「观测 → 跨源 → 认证 → 校验」挂。

## 错误响应怎么保证只写一次、格式统一？

- 一处写: `writeError` 设状态码、业务码与 `request_id` 再 `Abort`，失败只在这一层写一次；`c.Abort()` 不返回，写完必须 `return`；状态码与业务码见 000「错误分类与响应」;

```go
func writeError(c *app.RequestContext, status int, code, message string) {
	c.JSON(status, map[string]string{"code": code, "message": message,
		"request_id": c.GetString("request_id")})
	c.Abort() // 阻止后续 Handler；当前函数不会自动返回，写完仍要 return
}
```

## JWT 认证中间件怎么接？

- 锁死算法: 自己写要校验 `iss`/`aud`/`exp` 并配 `WithValidMethods([]string{"HS256"})`；现成实现是 `hertz-contrib/jwt`，claims 取舍见 000「认证与授权」;

```go
type claims struct {
	UserID int64 `json:"uid"`
	jwt.RegisteredClaims
}

func RequireUser(key []byte) app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		raw := strings.TrimPrefix(string(c.GetHeader("Authorization")), "Bearer ")
		var cl claims
		_, err := jwt.ParseWithClaims(raw, &cl, func(*jwt.Token) (interface{}, error) {
			return key, nil
		}, jwt.WithValidMethods([]string{"HS256"}))
		if err != nil {
			writeError(c, consts.StatusUnauthorized, "UNAUTHENTICATED", "invalid token")
			return
		}
		c.Set("user_id", cl.UserID)
		c.Next(ctx)
	}
}
```
