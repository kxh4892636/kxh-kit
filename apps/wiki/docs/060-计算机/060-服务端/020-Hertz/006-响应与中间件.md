# 响应与中间件

## 响应内容和状态码用什么方法写？

- 默认 `c.JSON`, 纯文本 `c.String`, 无 body `c.Status`, 原始字节 `c.Data`;

```go
c.JSON(consts.StatusOK, article)  // 设状态码与 Content-Type，再序列化
c.String(consts.StatusOK, "ok")   // 纯文本
c.Status(consts.StatusNoContent)  // 204，不带 body
```

- 要自控编码用 `c.PureJSON`; 原始字节用 `c.Data(status, contentType, body)`;
- 204 不能有响应体, 写完不要再追加 JSON;
- 错误响应形状见 [错误分层与响应](../000-服务端知识/020-契约与错误/020-错误分层与响应.md);

## 中间件的顺序与执行机制是什么？

- `app.HandlerFunc`; 先注册先进入、后退出;
- `c.Next(ctx)` 先跑后续 Handler, 回来再收尾;

```go
func AccessLog() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		start := time.Now()
		c.Next(ctx) // 先跑后续 Handler，回来再收尾
		log.Printf("status=%d elapsed=%s", c.Response.StatusCode(), time.Since(start))
	}
}

h.Use(AccessLog())
```

- `server.Default` 的 Recovery 只保证 500 状态, 不保证业务错误 JSON; 要统一错误体就自己装 Recovery;
- `c.Abort()` 只阻止后续 Handler, 不会让当前 Go 函数返回: 写完响应必须 `return`;

```go
if !ok {
	c.AbortWithStatusJSON(consts.StatusUnauthorized,
		map[string]string{"code": "UNAUTHENTICATED"})
	return
}
```

- `c.AbortWithStatus` = 写状态码 + `Abort`; `c.AbortWithStatusJSON` 再带 JSON body;
- 中间件用 `ut.PerformRequest` 验证, 不经过网络;

## 中间件怎么挂到不同作用域？

```go
h.Use(RequestID(), AccessLog())
h.Use(RequireUser(verify))
api := h.Group("/api/v1", checkCSRF) // 组级：只作用于组内路由
api.GET("/articles/:id", getArticle)
```

- `h.Use` 全局、`h.Group(prefix, mw...)` 组级、`h.GET(path, mw..., handler)` 单路由;
