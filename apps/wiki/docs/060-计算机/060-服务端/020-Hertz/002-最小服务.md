# 最小服务

## 一个最小 Hertz 服务由哪几部分组成？

- 三部分: `server.Default` 建 Engine、`h.GET` 挂路由、`h.Spin` 阻塞运行;

```go
package main

import (
	"context"

	"github.com/cloudwego/hertz/pkg/app"
	"github.com/cloudwego/hertz/pkg/app/server"
	"github.com/cloudwego/hertz/pkg/protocol/consts"
)

func main() {
	h := server.Default(
		server.WithHostPorts(":8888"),
		server.WithMaxRequestBodySize(1<<20), // 请求体上限 1 MiB
	)
	h.GET("/ping", func(ctx context.Context, c *app.RequestContext) {
		c.JSON(consts.StatusOK, map[string]string{"message": "pong"})
	})
	h.Spin()
}
```

- `server.Default()`: 带 Recovery 的 Engine，默认端口就是 `:8888`;
- `WithMaxRequestBodySize(1<<20)`: body 超过 1 MiB 会在解析前被拒绝;
- `h.GET`: 方法与路径映射到 Handler；`c.JSON` 设状态码与 Content-Type 并序列化;
- `h.Spin()`: 阻塞运行，收到 SIGINT/SIGTERM 后走优雅退出;

## 从零跑起来要敲哪几条命令？

- 四步: 建 module、拉依赖、启动、curl 看响应;

```bash
go mod init example.com/hertz-start
go get github.com/cloudwego/hertz
go run .
curl -i http://127.0.0.1:8888/ping
```

## 进程内怎么验证路由通了？

- `ut.PerformRequest`: 不经过网络，直接驱动 Engine、路由与中间件，适合断言状态码和 body;

```go
rec := ut.PerformRequest(h.Engine, consts.MethodGet, "/ping", nil)
if rec.Code != consts.StatusOK {
	t.Fatalf("want 200, got %d: %s", rec.Code, rec.Body.String())
}
```

- 真实监听、TLS 和超时行为仍要用 curl 或集成测试验收;
- 健康检查与退出预算属于通用规则，见 [健康检查与摘流](../000-服务端知识/040-可靠性/070-健康检查与摘流.md)、[优雅退出](../000-服务端知识/040-可靠性/050-退出顺序.md);
- 完整 Option 与退出时序见 [003-Engine与生命周期](./003-Engine与生命周期.md);
