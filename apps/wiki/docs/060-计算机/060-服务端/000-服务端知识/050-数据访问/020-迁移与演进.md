# 迁移与演进

## 为什么表结构要靠版本化迁移，不能手工改库？

- 结构是代码的一部分：每个环境都要能从零重建出同一份结构;
- 版本表记录「哪些迁移已执行」，启动时比对差集补齐；手工改库让环境之间无账可对，故障无法复现;
- 迁移靠库级锁串行执行，多实例同时启动只有一个在跑，其余排队。

```text
环境结构 = 按版本顺序执行过的迁移集合
手工改库 → 集合失配 → 本地能跑、线上报 no such column
```

## 迁移文件的硬规则有哪些？

- 只追加不改历史：已上线的迁移被改，其他环境的结构就与生产分叉;
- 一个迁移做一件事，能独立回滚；`down` 只还原结构，数据回不去;
- 迁移冻结在时间里：不引用当前业务类型，判断条件写死在当时的数据形态上;
- 迁移只碰结构和必要的数据搬运，不写业务逻辑、不改外部系统。

## 表结构怎么改才不伤害线上？

- 加列优先可空或带默认值：已有行必须满足约束，否则整条迁移失败;
- 删列 / 改类型走三段式：双写 → 回填 → 停读写旧列 → 再删;
- 大表回填分批并限速，一条 `update` 全表会把库锁住;
- 兼容窗口内新旧代码要能同时跑：先让结构同时满足两版代码，再切换流量。

## 上线与回滚的顺序是什么？

- 部署顺序固定：先跑迁移，再启动新代码；迁移失败必须退出码非 0 并阻止应用启动;
- 回滚优先「用新迁移反向修」：生产数据已按新结构写过，直接 down 会丢数据;
- 只回滚代码不回滚结构时，旧代码必须兼容新结构（新列可空或有默认值）。

## 测试库怎么建？

- 每个测试文件一个独立库（内存库或一次性 schema），跑一遍全量迁移得到干净结构;
- 用完关闭连接，否则挂住测试进程;
- 断言依赖真实约束（唯一、外键、非空），约束本身就是要被测的对象，别用 fake 替掉。
