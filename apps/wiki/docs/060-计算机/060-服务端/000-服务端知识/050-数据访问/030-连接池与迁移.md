# 连接池与迁移

## MySQL 连接池三项怎么算？

```go
sqlDB, _ := db.DB()
sqlDB.SetMaxOpenConns(10)
sqlDB.SetMaxIdleConns(5)
sqlDB.SetConnMaxLifetime(3 * time.Minute)
```

- 最大连接 × 实例数 ≤ 数据库上限;
- `ConnMaxLifetime` 必须小于数据库/代理的回收周期;
- 连接池过大，会把数据库连接打满，故障时所有实例一起排队。

## MySQL 迁移为什么不能放启动时？

- 生产迁移用版本化脚本，不依赖启动时无条件 `AutoMigrate`;

```sql
CREATE TABLE users (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(254) NOT NULL,
  name VARCHAR(100) NOT NULL,
  created_at DATETIME(3) NOT NULL,
  UNIQUE KEY uk_users_email (email)
);
```

- 启动时 `AutoMigrate` 在多实例下并发执行 DDL，容易锁表或半成功;
- 迁移用独立命令/Job 执行，带版本表与互斥锁（如 `GET_LOCK`）;
- MySQL 的 DDL 不随普通事务回滚，迁移失败要人工核对；脚本入库、可 review、可重跑，失败要能定位到版本。
