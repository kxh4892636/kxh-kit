# 认证与授权

## 认证与授权分别回答什么？

- 认证回答「你是谁」，授权回答「你能做什么」；两件事分开写，不混在一个中间件里;

- 认证结果放进请求上下文，业务只读；业务不再解析 token;
- 401 表示未认证，403 表示已认证但无权限；不要用 404 掩盖 403，除非明确要隐藏资源存在性;
- 最终权限由服务端规则决定；token 里的 role/scope 只是提示。

## JWT 验签之后还要校验什么？

- 只验签名不够: 不校验 `aud`，A 系统签发的 token 可以拿去调 B 系统；不固定算法，攻击者可以把 `alg` 改成 `none` 或换对称算法;

- 必须固定允许的签名算法，并校验 `iss`、`aud`、`exp`、`nbf`;
- JWT 是签名声明，不是加密容器；不要放密码、手机号等敏感数据;
- 只在前端隐藏按钮，直接调接口就绕过，等于没有授权。

## JWT 载荷里放哪些字段？

```json
{
  "sub": "user_123",
  "iss": "https://auth.example.com",
  "aud": "my-api",
  "exp": 1767225600,
  "nbf": 1767222000,
  "iat": 1767222000,
  "jti": "9f2c1e7a5b",
  "scope": "article:read article:write"
}
```

- `sub` 用稳定用户 ID，不要用邮箱或昵称;
- `jti` 用于撤销、审计与防重放;
- role/scope 只放必要提示，资源归属仍要在服务端逐次判断。

## 会话从登录到失效怎么走？

```text
登录 → 校验凭据（慢散列）→ 签发短期 access token（+ 可选 refresh）
请求 → 解析 Authorization → 验签 + 校验 claims → 写入身份 → 业务/授权判断
```

- access token 短（分钟级），refresh token 长且可撤销;
- 需要立即失效的场景（登出、改密、封禁）用服务端会话或 token 版本号;
- 服务间调用不要把用户身份当信任凭据，内部身份由网关或 mesh 注入;
- 授权失败统一 403，并记录资源、操作、主体，便于审计。

## 认证与鉴权做错会有哪些症状？

| 症状                     | 原因                       |
| ------------------------ | -------------------------- |
| 改了密码旧 token 还能用  | JWT 无状态，缺少撤销机制   |
| A 系统 token 能调 B 系统 | 没校验 `aud`               |
| `alg: none` 攻击         | 没有固定允许的算法         |
| 越权访问他人资源         | 只校验登录，没校验资源归属 |
| 把 JWT 当加密用          | 载荷是 base64，可被读取    |
