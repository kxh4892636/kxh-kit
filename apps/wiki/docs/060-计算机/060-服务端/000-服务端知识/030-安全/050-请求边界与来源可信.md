# 请求边界与来源可信

## 请求中各种常见资源的边界限制有哪些？

- 所有服务端服务适用: body 大小、header 大小与数量、字段数量、文件数量，全部在解析之前生效;

| 资源          | 上限参考  | 超限响应       |
| ------------- | --------- | -------------- |
| JSON body     | 100KB–1MB | 413            |
| 上传单文件    | 5–50MB    | 413            |
| Header 总大小 | 8–32KB    | 431            |
| 单请求字段数  | 按业务    | 400            |
| 读请求        | 3–10s     | 408 / 关闭连接 |

## 请求边界按什么顺序生效？

```text
TLS/网关 → 资源限制 → 读超时
→ 解析 → 字段校验 → 业务超时 → 下游 deadline
```

## X-Forwarded-For 什么时候可以信任？

- 只有请求来自可信代理时才解析；直连客户端可以伪造它;

```text
客户端 1.2.3.4
  → 可信代理 A（追加 1.2.3.4）
  → 可信代理 B（追加 A 的地址）
  → 应用
X-Forwarded-For: 1.2.3.4, 10.0.0.8
```

- 客户端 IP: 从可信代理那一侧往左数，跳过可信代理，取第一个不可信地址;
- 代理链可信跳数写死，不猜；代理要覆盖而不是追加不可信头，直连客户端伪造的 `X-Forwarded-For` 也在代理层被覆盖;
- 直接信任 `X-Forwarded-For` 的第一段，等于让攻击者自选 IP，绕过 IP 白名单与限流。
