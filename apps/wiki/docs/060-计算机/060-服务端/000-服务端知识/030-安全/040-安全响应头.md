# 安全响应头

## 安全响应头能替代输入校验与鉴权吗？

- 不能: 它只是浏览器访问的服务在浏览器侧的最后一道默认值;

- 浏览器对缺失的头有历史兼容行为（猜 MIME、允许被 iframe），会被利用;
- API 与页面策略不同: API 通常只需要 `nosniff` + 禁止缓存敏感响应。

## 浏览器安全头各管什么？

| 头                                    | 作用                   | 注意                                                        |
| ------------------------------------- | ---------------------- | ----------------------------------------------------------- |
| `Strict-Transport-Security`           | 强制 HTTPS             | 先确认全站 HTTPS，再逐步加 `max-age`                        |
| `X-Content-Type-Options: nosniff`     | 禁止 MIME 嗅探         | 常开                                                        |
| `Content-Security-Policy`             | 限制脚本/样式/帧来源   | 先 Report-Only                                              |
| `X-Frame-Options` / `frame-ancestors` | 防点击劫持             | 二选一，别冲突                                              |
| `Referrer-Policy`                     | 控制 Referer 泄露      | 跨站默认 `no-referrer` 或 `strict-origin-when-cross-origin` |
| `Permissions-Policy`                  | 关闭不需要的浏览器能力 | 按需                                                        |

- HSTS 只在 HTTPS 稳定后开启，否则会把用户锁在打不开的站点上;
- CSP 从宽松开始、逐步收紧，先用 `Report-Only` 观察;
- 防嵌入用 CSP `frame-ancestors` 或 `X-Frame-Options`，两者不要互相矛盾;
- `nosniff` 阻止浏览器猜类型，几乎所有响应都该有。

## 安全响应头怎么下发、怎么回滚？

```http
HTTP/1.1 200 OK
Strict-Transport-Security: max-age=15552000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
X-Frame-Options: SAMEORIGIN
```

```http
# 页面型应用，CSP 先观察
Content-Security-Policy-Report-Only: default-src 'self'; report-uri /csp-report
```

- 同一个头只在一层设置: 应用或反向代理，避免重复值;
- `X-Frame-Options` 与 CSP `frame-ancestors` 同时存在时，浏览器按更严格者执行;
- HSTS 一旦下发，浏览器在 `max-age` 内强制 HTTPS，回滚只能缩短 `max-age` 并等旧值过期。

## 安全头配错会有哪些症状？

| 症状                      | 原因                                              |
| ------------------------- | ------------------------------------------------- |
| 开启 HSTS 后无法回退 HTTP | `max-age` 太长且没有测试                          |
| 页面白屏、控制台 CSP 报错 | CSP 一次收得太紧                                  |
| 同一个头出现两个值        | 应用与反向代理都设置                              |
| iframe 嵌套仍可用         | `X-Frame-Options` 与 `frame-ancestors` 冲突或缺失 |
