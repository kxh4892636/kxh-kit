# 重试与幂等

## 什么条件下才允许自动重试？重试的流程是什么? 重试会导致什么问题?

- 三道门槛: 幂等、错误可恢复、总预算够；任一不满足就快速失败;
- 幂等是前提：写请求不能确认幂等，就不要自动重试，否则重复订单、重复扣款;
- 总预算 = 首次调用 + 退避 + 所有重试 + 余量，必须小于上游 deadline;
- 重试会放大流量：下游已经过载时，重试等于二次打击;

```text
失败 → 分类（可恢复？幂等？预算够？）→ 退避（指数 + jitter）→ 换实例 → 重试
      └─ 任一不满足 → 快速失败，返回明确错误
```

## 重试退避怎么算？

- 指数退避逐次翻倍，再加抖动打散同步到达;
- 固定间隔退避会让重试请求同步到达，形成周期性尖峰。

```text
第 1 次失败：等 100ms + rand(0, 50ms)
第 2 次失败：等 200ms + rand(0, 50ms)
第 3 次失败：等 400ms + rand(0, 50ms)
超过预算或次数上限：返回最后一次错误
```

## 哪些错误可以重试，哪些必须直接失败？

| 结果                  | 默认动作                         |
| --------------------- | -------------------------------- |
| 400 / 401 / 403 / 404 | 不重试                           |
| 409 冲突              | 不重试，交给业务处理             |
| 429                   | 按 `Retry-After` 退避后重试      |
| 500 / 502 / 503 / 504 | 幂等请求可重试                   |
| 连接失败 / 建连超时   | 可重试                           |
| 业务超时              | 看幂等与剩余预算                 |
| 流式中断              | 不自动重试，重连后按幂等语义续传 |
