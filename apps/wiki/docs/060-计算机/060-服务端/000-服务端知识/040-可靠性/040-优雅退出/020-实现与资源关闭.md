# 实现与资源关闭

## 进程里怎么实现？

```go
sig := make(chan os.Signal, 1)
signal.Notify(sig, syscall.SIGTERM, syscall.SIGINT)
<-sig
// readiness=false；等传播；srv.Shutdown(ctx)；关 DB/exporter
```

```text
# Node 等价语义
server.close(cb) 停止接收新连接，回调在在途请求结束后触发
再执行 pool.end() / redis.quit()
```

- 关闭函数要幂等，部分初始化也能安全执行;
- 关闭顺序与启动顺序相反。

## 哪些资源必须在什么时机关闭？

| 资源               | 时机               |
| ------------------ | ------------------ |
| readiness / 注册   | 最先               |
| 监听 / accept      | 摘流传播之后       |
| 在途请求 / 流      | 关闭监听之后       |
| 数据库 / 缓存 / MQ | 请求排空之后       |
| exporter / tracer  | 最后，flush 后关闭 |

## 长连接怎么处理？

- SSE、WebSocket、RPC 流式不会因为停止 accept 而结束，需要单独的关闭协议;
- 关闭帧 / 取消信号要通知到客户端，并给重连退避，避免瞬间重连风暴。

## 常见失败是什么？

| 症状                      | 原因                             |
| ------------------------- | -------------------------------- |
| 发布时少量 5xx / 连接重置 | 收到信号立刻关监听，没等摘流传播 |
| `database is closed`      | 先关连接池，再等在途请求         |
| 进程被 SIGKILL            | 等待上限大于平台宽限期           |
| trace 缺最后一段          | exporter 没 flush 就退出         |
| 长连接客户端反复重连      | 只断了 TCP，没有关闭帧与重连退避 |
