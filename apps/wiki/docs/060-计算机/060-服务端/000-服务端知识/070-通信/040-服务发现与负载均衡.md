# 服务发现与负载均衡

## 服务注册, 服务发现与负载均衡各负责什么？服务注册和发现的要求有哪些?

- 服务注册: 服务启动时注册实例（地址、权重、元数据）到注册中心;
- 服务发现: 从注册中心解析可用实例列表；
- 负载均衡: 从示例列表里选一个;
- 注册与发现两端的服务名必须一致且唯一, 其为服务的唯一标识;

## 五种负载均衡算法怎么选？

| 算法                | 特点                    | 适用                 |
| ------------------- | ----------------------- | -------------------- |
| 轮询 / 加权轮询     | 简单、可预测            | 实例同构、请求均匀   |
| 随机 / 加权随机     | 大样本下趋均衡          | 实例多、无状态       |
| 最少连接 / 最少请求 | 跟随负载                | 请求耗时差异大       |
| 一致性哈希          | 相同 key 命中同一实例   | 缓存亲和、有状态分片 |
| 标签 / 区域路由     | 按 zone、版本、灰度分流 | 多活、灰度           |

## 服务实例列表变化时客户端要做什么？

```text
服务启动 → 注册实例（地址、权重、元数据）
客户端 → 解析服务名 → 订阅列表变化 → 过滤不健康实例
→ 按算法选实例 → 调用 → 失败时换实例重试
服务下线 → 先注销 → 等待摘流 → 停止进程
```
