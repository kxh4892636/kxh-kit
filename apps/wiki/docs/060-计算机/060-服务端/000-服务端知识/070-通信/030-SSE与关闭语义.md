# SSE 与关闭语义

## SSE 的线上格式与重连怎么设计？

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache

id: 42
event: progress
data: {"percent":80}

: heartbeat
```

- 每个事件后 flush；代理关闭缓冲;
- 客户端断线后带 `Last-Event-ID` 重连，服务端从该位置续发;
- 重连要能续传：SSE 用 `Last-Event-ID`，WebSocket 用业务层游标。

## 流式调用的关闭语义是什么？

```text
客户端上传流：Send* → CloseSend/CloseAndRecv → 服务端读到 EOF → 返回最终结果
服务端推送流：Client 请求 → 循环 Recv → EOF 表示正常结束
双向流：一侧 CloseSend 只表示「我不再发」，接收仍可继续
```

- 关闭要成对：发送方半关闭后，接收方仍可能继续发；读到 EOF 才是正常结束;
- 读到 EOF 前不要复用连接;
- 任何一侧失败都要通知另一侧退出，回收 goroutine、timer 与连接;
- 为接收设置超时，避免无限等待;
- 背压必须显式处理：慢客户端不能拖垮广播或耗尽内存；没有背压，一个慢客户端就能让整个服务内存上涨。

## 长连接写错会看到什么症状？

| 症状                 | 原因                            |
| -------------------- | ------------------------------- |
| SSE 客户端收不到消息 | 代理缓冲，或没有 flush          |
| 长连接固定 60s 断开  | 代理/负载均衡空闲超时           |
| 广播时内存暴涨       | 没有背压与队列上限              |
| 断线后重复消费       | 没有游标或 `Last-Event-ID`      |
| 半关闭后一直等       | 把 `CloseSend` 当成整个会话结束 |
