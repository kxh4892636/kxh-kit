# 反向代理与网关

## 正向代理、反向代理与网关有什么区别？

- 正向代理代表客户端，反向代理代表服务端；网关是反向代理 + 路由 + 治理;
- 适用: 服务前面有 Nginx、Envoy、API 网关或负载均衡的部署;
- 逐跳头描述的是「这一条连接」，转发会引发协议错误与注入;
- 客户端可伪造 `X-Forwarded-For`，直接信任会让 IP 白名单与限流失效。

## 代理链路里哪些头不能原样转发？

- 逐跳头（`Connection`、`Keep-Alive`、`Transfer-Encoding`、`Upgrade` 等）不能原样转发;
- 转发头（`X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`）只能由可信代理追加;
- 覆盖而不是追加不可信转发头;
- 代理要设自己的连接、读、写、空闲超时，且与后端预算协调;
- 代理层做 body 限制、TLS 终结、压缩、缓存与重试时，要避免与应用层重复;
- 代理与应用都加 CORS/压缩/重试，会出现重复头、重复压缩与流量放大。

## 客户端到下游的代理链路怎么分层？

```text
客户端 → CDN/WAF → 负载均衡 → 网关（TLS、路由、限流）
      → 应用（业务、鉴权）→ 下游服务
```

- 只在网关做 TLS 终结与外部鉴权；应用做资源级授权;
- 代理到应用用内网地址，应用不直接暴露公网;
- 每层都记录 request_id，代理生成或透传。

## Nginx 反代要配哪些超时与头？

```nginx
location /api/ {
    proxy_pass http://app:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 1s;
    proxy_read_timeout 5s;
    proxy_buffering off;          # SSE / 流式
    client_max_body_size 10m;
}
```

- SSE/WebSocket 要关闭缓冲并放行 `Upgrade`;
- 上游地址写死或用服务发现，不接受用户输入：反向代理天然是 SSRF 入口，上游地址必须来自白名单。

## 代理配置错会看到什么症状？

| 症状                            | 原因                                 |
| ------------------------------- | ------------------------------------ |
| 应用拿到的客户端 IP 全是代理 IP | 没解析转发头，或代理没设置           |
| 限流被绕过                      | 信任了客户端伪造的 `X-Forwarded-For` |
| SSE 不推送                      | 代理缓冲了响应                       |
| 请求体被截断                    | 代理与应用的上限不一致               |
| 代理可访问内网任意地址          | 上游由请求参数决定，形成 SSRF        |
