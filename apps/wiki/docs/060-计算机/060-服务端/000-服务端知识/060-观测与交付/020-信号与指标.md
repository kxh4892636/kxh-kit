# 信号与指标

## 日志、指标、链路各自回答什么问题？

- 日志回答「发生了什么」，指标回答「有多少、多严重」，链路回答「慢在哪一段」;
- 适用: 所有服务端服务;
- 只做平均延迟，长尾被掩盖；故障往往先体现在 P99;
- 链路断在出站调用，就无法区分「本服务慢」还是「下游慢」。

## 每个服务至少暴露哪些指标？

- 请求量、错误率、延迟分位（P50/P95/P99）、饱和度（连接/队列/CPU）四项基线;
- 指标只留可聚合的低基数维度；用户 ID、完整 URL、错误文本不能做标签;

| 信号               | 类型      | 维度                    | 用途                   |
| ------------------ | --------- | ----------------------- | ---------------------- |
| 请求量             | counter   | service、method、status | 发现流量变化           |
| 错误率             | counter   | service、method、code   | 发现故障               |
| 延迟               | histogram | service、method         | 定位长尾               |
| 重试 / 熔断 / 限流 | counter   | method、reason          | 发现流量放大与保护触发 |
| 连接池             | gauge     | target、state           | 容量与建连异常         |
| 队列 / 并发        | gauge     | queue、worker           | 饱和度                 |

```text
# 指标命名示例
http_requests_total{service="article-api",method="GET",status="200"}
http_request_duration_seconds_bucket{service="article-api",method="GET",le="0.1"}
```

- 延迟用直方图或分位，不要只报平均值;
- 同名指标在不同服务的口径要一致，否则无法聚合;
- 高基数标签会让时序数据库膨胀，甚至打挂监控。
