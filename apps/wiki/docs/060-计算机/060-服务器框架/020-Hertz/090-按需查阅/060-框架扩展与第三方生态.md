# 按需求查找 Hertz 扩展

## 先完成服务开发需要哪些扩展？

- 最小服务: Engine、路由、绑定和 JSON 响应即可；按 [文章实战](../003-完整实战/010-从零构建文章服务.md) 跑通后再增加依赖;
- 使用顺序: 每次只加入一种能力，验证失败响应、中间件顺序和退出行为;

## 常见服务端需求应该查哪个组件？

| 需求              | 可查阅的组件                                      | 笔记入口                                                 |
| ----------------- | ------------------------------------------------- | -------------------------------------------------------- |
| 登录与身份        | JWT、KeyAuth、Paseto                              | [JWT](../004-上线检查/020-JWT认证与权限.md)              |
| Cookie 登录和跨域 | Session、CSRF、CORS                               | [Web 状态](../004-上线检查/030-Web状态与跨站安全.md)     |
| 安全响应头        | Secure                                            | [请求边界](../004-上线检查/040-请求边界与安全响应.md)    |
| 请求日志          | Zap、Logrus、Zerolog、Slog、RequestID、Access Log | [日志](../004-上线检查/060-Zap日志与RequestID.md)        |
| 指标与链路        | Prometheus、OpenTelemetry                         | [观测](../004-上线检查/070-OpenTelemetry与Prometheus.md) |
| 限流              | Sentinel                                          | 按已有治理平台接入                                       |
| 实例注册发现      | Nacos、Consul、etcd、Eureka、Polaris、ZooKeeper   | 团队已有注册中心时再接入                                 |
| 压缩与缓存        | Gzip、ETag、Cache                                 | 检查私有响应是否允许缓存                                 |
| 权限与文档        | Casbin、Swagger、i18n                             | 先确定现有业务确实需要                                   |
| 诊断与错误收集    | pprof、Sentry                                     | 管理入口及敏感上下文要受控                               |

## 接入扩展失败时按什么顺序检查？

- 版本: 固定 Hertz 与扩展版本，按对应版本的官方示例构造最小 Engine;
- 顺序: 验证中间件进入、退出和 Abort 路径，再检查 context 与资源所有权;
- 依赖: 业务层不接收扩展专有类型，确保替换组件无需重写业务规则;
- 底层扩展: network、protocol、renderer、tracer、logger、response writer 仅在现成接口不满足需求时查阅，不作为快速上手内容;
