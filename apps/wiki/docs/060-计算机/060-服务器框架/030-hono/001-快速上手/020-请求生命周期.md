# 请求生命周期

## 一次请求在 Hono 里怎么走？

```text
收到连接 → 组装成标准 Request
    → 匹配路由（Router）
    → 中间件 1 前 → 中间件 2 前 → … → Handler
    → 中间件 2 后 → 中间件 1 后
    → Response 交回 HTTP 栈写网络
```

- Handler: 唯一返回 `Response` 的那一层；一条请求只会命中一个 Handler;
- Middleware: `await next()` 之前是「请求阶段」，之后是「响应阶段」，可提前返回 `Response` 短路;
- Router: 决定 URL 命中哪条路由，与业务逻辑无关;
- 适配器: 把运行时 HTTP 栈的请求/响应翻译成标准对象;

## Handler 和 Middleware 的判定规则是什么？

| 角色       | 签名                                     | 行为                                        |
| ---------- | ---------------------------------------- | ------------------------------------------- |
| Handler    | `(c) => Response`                        | 返回 `Response`，结束本请求                 |
| Middleware | `(c, next) => Promise<void \| Response>` | `await next()` 继续，或返回 `Response` 短路 |

```ts
app.use(async (c, next) => {
  const start = performance.now();
  await next();
  c.res.headers.set("X-Response-Time", `${performance.now() - start}`);
});
```

- 中间件的执行细节（顺序、错误、类型）见 [中间件](../002-服务端开发/100-中间件模型.md);

## 有哪些术语必须先分清？

| 术语           | 含义                                                           |
| -------------- | -------------------------------------------------------------- |
| `app`          | `Hono` 实例，一个应用或一个子路由                              |
| `c`（Context） | 每请求一份，读写请求、设置响应、存取请求级变量                 |
| Handler        | `(c) => Response` 的最终处理函数                               |
| Middleware     | `(c, next) => Promise<void \| Response>`                       |
| Env            | 泛型：`Bindings` + `Variables`，决定 `c.env` 和 `c.var` 的类型 |
| Adapter        | 各运行时的入口包，如 `@hono/node-server`                       |
| Helper         | 辅助函数集合，如 `hono/cookie`、`hono/streaming`               |
| Router         | 路由匹配算法，如 `RegExpRouter`、`TrieRouter`                  |

- 先记住 `c` 是「一次请求的全部上下文」，后续所有笔记都建立在这组术语上;
- 路由器选型见 [性能与路由器选择](../003-上线/060-路由器与预设.md);
