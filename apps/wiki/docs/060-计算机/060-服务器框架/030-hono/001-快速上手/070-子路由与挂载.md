# 子路由与挂载

## 如何把大应用拆成多个子路由？

```ts
// routes/book.ts
const book = new Hono();
book.get("/", (c) => c.text("List Books"));
book.get("/:id", (c) => c.text("Get Book " + c.req.param("id")));
export default book;

// index.ts
const app = new Hono();
app.route("/book", book); // /book、/book/:id
```

- `app.route(prefix, app)`：把子应用的整棵路由树挂到前缀下;
- 子应用内部路径写相对路径，不要重复写前缀;

## `basePath` 和 `route('/')` 有什么区别？

```ts
const api = new Hono().basePath("/api");
api.get("/book", (c) => c.text("List Books")); // GET /api/book

const user = new Hono().basePath("/user");
const app = new Hono();
app.route("/", api); // 前缀已在 basePath 里
app.route("/", user);
```

| 方式                          | 前缀写在哪   | 适用                                |
| ----------------------------- | ------------ | ----------------------------------- |
| `app.route('/book', book)`    | 父应用挂载时 | 一个子应用只在一个前缀下            |
| `new Hono().basePath('/api')` | 子应用自己   | 子应用自带固定前缀、可独立运行/测试 |

- `basePath` 会让子应用内部的路由路径自动带上前缀，测试时也更接近真实路径;

## 挂载顺序有什么陷阱？

```ts
// ✅ 先装配，再挂载
three.get("/hi", (c) => c.text("hi"));
two.route("/three", three);
app.route("/two", two); // GET /two/three/hi → hi

// ❌ 先挂载，后装配
app.route("/two", two); // 此时 two 还没有任何路由
two.route("/three", three); // GET /two/three/hi → 404
```

- 原因: `route()` 是把「当时已有的路由」拷贝进父应用，后续再往子应用加路由不会同步;
- 规则: 子应用先写完路由，最后一步才 `app.route()`;
- 这类错误不会报错、只会 404，排查时先看挂载顺序;
