# 响应与状态码

## Handler 必须返回什么？

- 必须返回 `Response`；返回 `undefined` 表示「我不是 Handler」，会继续往下一个匹配走;
- 最省事的做法是用 `c` 上的快捷方法，它们内部都构造标准 `Response`;

| 方法                              | Content-Type       | 用途                               |
| --------------------------------- | ------------------ | ---------------------------------- |
| `c.text(str, status?, headers?)`  | `text/plain`       | 纯文本                             |
| `c.json(obj, status?, headers?)`  | `application/json` | JSON API 主用                      |
| `c.html(str, status?, headers?)`  | `text/html`        | 返回页面                           |
| `c.body(body, status?, headers?)` | 由你指定           | 自定义二进制或特殊类型             |
| `c.redirect(url, status?)`        | —                  | 默认 302                           |
| `c.notFound()`                    | —                  | 触发 404，可被 `app.notFound` 定制 |

## 状态码和响应头怎么设置？

```ts
app.post("/posts", (c) => {
  c.status(201); // 先设状态码
  c.header("X-Message", "created"); // 再设响应头（可多次）
  return c.json({ ok: true });
});

// 一步到位：状态码与头作为 c.json 的参数
app.post("/posts2", (c) => c.json({ ok: true }, 201, { "X-Message": "created" }));
```

- 200 是默认值，不需要显式设置;
- `c.header()` 在 `return` 之后无效，必须写在 `return` 之前;
- 想在响应产出后改头，用中间件里的 `c.res.headers`，见 [自定义响应与改写](./110-自定义响应与改写.md);

## 如何统一 JSON 响应结构？

```ts
// 成功
return c.json({ ok: true, data });
// 失败
return c.json({ ok: false, error: { code: "NOT_FOUND", message: "资源不存在" } }, 404);
```

- 建议: 失败一律用 `c.json(..., status)` 而不是 `c.notFound()`;
- 原因: 用 `c.notFound()` 时类型安全客户端推不出错误体类型（见 [hc 类型安全客户端](../090-按需查阅/070-hc调用与传参.md)）;
- 全局兜底在 `app.onError` / `app.notFound` 里产出同样结构，见 [错误处理](./120-错误处理.md);
