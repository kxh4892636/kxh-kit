# 压缩、体积与超时

## 响应压缩需要自己开吗？

```ts
import { compress, COMPRESSIBLE_CONTENT_TYPE_REGEX } from "hono/compress";

app.use(compress()); // 默认 1KB 以上才压，gzip 优先

app.use("/api/*", compress({ contentTypeFilter: /^application\/json/ }));
```

- Cloudflare Workers / Deno Deploy 会自动压缩，Node 不会，Node 必须显式挂;
- `threshold` 默认 1024 字节，小响应压了反而更大;
- 已压缩的二进制类型（图片、zip）在默认白名单里被排除;
- 带 `Transfer-Encoding` 的流式响应会被自动跳过，不会破坏 SSE;

## 超大请求体如何拦住？

```ts
import { bodyLimit } from "hono/body-limit";

app.post(
  "/upload",
  bodyLimit({
    maxSize: 50 * 1024 * 1024,
    onError: (c) => c.json({ ok: false, error: "too_large" }, 413),
  }),
  handler,
);
```

- 优先用 `Content-Length` 判断；没有长度时分块读取并累计，超限即中断;
- 只挂在上传路由上，不要全局设一个很大的值;
- 默认上限是 100KB，不显式设置会挡住正常上传;

## 请求超时怎么设？

```ts
import { timeout } from "hono/timeout";
import { HTTPException } from "hono/http-exception";

app.use("/api/*", timeout(5000));

const custom = new HTTPException(408, { message: "请求超时，请重试" });
app.use("/api/long/*", timeout(60_000, custom));
```

- 单位毫秒；超时抛 408，可换成任意异常工厂;
- 与流式响应不兼容，SSE 要用 `stream.close()` + `setTimeout`（见 [SSE](../090-按需查阅/120-SSE.md)）;
- 与错误处理中间件顺序相关，注意别让外层吞掉超时;

## 如何按来源 IP 做白名单/黑名单？

```ts
import { ipRestriction } from "hono/ip-restriction";
import { getConnInfo } from "@hono/node-server/conninfo";

app.use(
  "*",
  ipRestriction(
    getConnInfo,
    {
      allowList: ["127.0.0.1", "::1", "10.0.0.0/8"],
      denyList: [],
    },
    async (remote, c) => c.json({ ok: false, error: "forbidden" }, 403),
  ),
);
```

- 规则语法: 精确 IP、CIDR（`192.168.2.0/24`）、`*` 表示全部;
- `getConnInfo` 按运行时不同来源不同，Node 用 `@hono/node-server/conninfo`;
- 放在反向代理后面时，真实来源在 `X-Forwarded-For`，需要先信任代理再取，否则限流失效;
- 多条规则要组合时用 `some`/`every`/`except`，见 [内置中间件速查](../090-按需查阅/010-内置中间件速查.md);
