# 手写参数校验

## Hono 自带校验器能做什么？

- `hono/validator` 只负责「把想要的字段挑出来或拒绝请求」，不做 schema 描述;
- 它本身是一个中间件：校验通过把结果存进 `c.req.valid(target)`，不通过就返回你给的 `Response`;

```ts
import { validator } from "hono/validator";

app.post(
  "/posts",
  validator("form", (value, c) => {
    const body = value["body"];
    if (!body || typeof body !== "string") return c.text("Invalid!", 400);
    return { body }; // 返回值即 valid 的数据
  }),
  (c) => {
    const { body } = c.req.valid("form");
    return c.json({ body }, 201);
  },
);
```

- 可用目标: `json`、`form`、`query`、`header`、`param`、`cookie`;
- 多个目标可以串联多个 `validator`，每个读一块;

## 校验时有哪两个必踩的坑？

| 坑                | 现象                                 | 解法                                               |
| ----------------- | ------------------------------------ | -------------------------------------------------- |
| 缺 `Content-Type` | `validator('json'/'form')` 收到 `{}` | 请求头必须带 `application/json` 或表单类型         |
| header 用了大写键 | 值永远 `undefined`                   | 校验 `header` 时键一律小写，如 `'idempotency-key'` |

```ts
// app.request 测试时也要带头，否则校验器看到空对象
await app.request("/testing", {
  method: "POST",
  body: JSON.stringify({ key: "value" }),
  headers: new Headers({ "Content-Type": "application/json" }),
});
```

## 校验错误如何统一成自己的格式？

```ts
app.post(
  "/posts",
  validator("json", (value, c) => {
    const parsed = schema.safeParse(value);
    if (!parsed.success) {
      return c.json({ ok: false, error: parsed.error.issues }, 400);
    }
    return parsed.data;
  }),
  handler,
);
```

- 这是同时「规范化错误结构 + 拿到类型」的最短路径;
- 统一格式后记得给 `AppType` 套 `ApplyGlobalResponse`，让客户端也能推出错误分支;
- 字段多、嵌套深时不要手写 if，改用 schema 库，见 [Schema 校验与 Zod](./040-Schema校验与Zod.md);
