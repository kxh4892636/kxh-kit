# 用 app.request 测试

## 为什么 Hono 的测试成本很低？

- 不需要起端口：`app.request()` 直接构造 `Request` 走完整链路，返回 `Response`;
- 不需要多余工具：断言就是对标准 `Response` 断言;
- 测试框架任选（Vitest / Jest / node:test）;

## 最朴素的测法怎么写？

```ts
import app from "./app";

test("GET /posts", async () => {
  const res = await app.request("/posts");
  expect(res.status).toBe(200);
  expect(await res.text()).toBe("Many posts");
});

test("POST /posts with json", async () => {
  const res = await app.request("/posts", {
    method: "POST",
    body: JSON.stringify({ message: "hello" }),
    headers: new Headers({ "Content-Type": "application/json" }),
  });
  expect(res.status).toBe(201);
  expect(res.headers.get("X-Custom")).toBe("Thank you");
  expect(await res.json()).toEqual({ message: "Created" });
});
```

| 场景           | 写法                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| 表单/上传      | `body: formData`（`FormData` 实例）                                      |
| 自定义 Request | `app.request(new Request('http://localhost/posts', { method: 'POST' }))` |
| 注入 `c.env`   | 第三个参数 `app.request(path, init, MOCK_ENV)`                           |
| 带鉴权头       | `init.headers` 里放 `Authorization`                                      |

- 关键坑: 校验 `json`/`form` 时必须带 `Content-Type`，否则 `c.req.valid()` 拿到 `{}`;
- 断言 HEAD 时同时比对 GET：状态码与头一致、body 为 `null`;

## 一份最小测试清单长什么样？

| 层     | 必测                                  |
| ------ | ------------------------------------- |
| 路由   | 正常路径、未知路径 404、错误方法      |
| 校验   | 缺字段、类型错、超长/超大             |
| 鉴权   | 无 token、过期 token、权限不足        |
| 错误   | 抛异常时的状态码与响应体结构          |
| 副作用 | 写库/发消息确实被调用（用 mock 断言） |

- 先按清单打勾，再补边界值与并发场景;
- 测试用 `import app` 而不是起服务，速度是毫秒级;
