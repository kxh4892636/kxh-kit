# 测试客户端与环境注入

## 想要类型安全的测试客户端怎么做？

```ts
import { testClient } from "hono/testing";

const app = new Hono().get("/search", (c) => {
  const q = c.req.query("q");
  return c.json({ q, results: ["a"] });
});

const client = testClient(app);

const res = await client.search.$get({ query: { q: "hono" } });
expect(await res.json()).toEqual({ q: "hono", results: ["a"] });

// 第二个参数可覆盖请求头 / init
await client.search.$get({ query: { q: "x" } }, { headers: { Authorization: "Bearer t" } });
```

- 硬性前提: 路由必须链式定义在 `new Hono()` 上，否则 `testClient` 推不出方法;
- 与 `hc` 的区别: `testClient` 进程内直连，不经过网络;
- 请求参数写法与 `hc` 完全一致，见 [hc 调用与传参](../090-按需查阅/070-hc调用与传参.md);

## 如何模拟环境变量与外部依赖？

```ts
const MOCK_ENV = { JWT_SECRET: "test-secret" };
const res = await app.request("/auth/me", {}, MOCK_ENV);
```

- `c.env` 用第三个参数注入，适合环境变量与平台绑定;
- 数据库、HTTP 客户端这类依赖：在 `initApp` 里注入，测试时用工厂函数替换成内存实现;
- 不要在业务代码里硬编码 `fetch` 到线上地址，测试无法拦截;

## 数据库与外部调用怎么测？

| 依赖        | 做法                                     |
| ----------- | ---------------------------------------- |
| 数据库      | 仓储接口 + 内存实现，或在测试里用临时库  |
| 第三方 HTTP | 注入 `fetch` 实现，返回固定响应          |
| 时间        | 注入 `now()` 函数，不直接用 `Date.now()` |
| 消息队列    | 内存队列或断言「发送被调用」             |

- 这些依赖都应在 `createFactory({ initApp })` 里注入，Handler 只读 `c.var`;
- 引入方式见 [createFactory 统一 Env](./025-createFactory统一Env.md);

## 不启服务的批量回归怎么办？

- 用 Hono CLI 的 `batch` / `snapshot` / `diff`，见 [用 CLI 做行为回归](../090-按需查阅/050-用CLI做行为回归.md);
- 与单测分工: CLI 看「行为变没变」，单测看「逻辑对不对」;
