# 自定义中间件

## 如何写可复用、类型完整的中间件？

```ts
import { createMiddleware } from "hono/factory";

export const auth = createMiddleware<{
  Variables: { user: { id: string; name: string } };
}>(async (c, next) => {
  const token = c.req.header("Authorization");
  if (!token) return c.json({ ok: false, error: "unauthorized" }, 401);
  c.set("user", { id: "1", name: "alice" });
  await next();
});
```

- `createMiddleware` 只是帮你保住 `c` 与 `next` 的类型，行为等价于 `app.use(async (c, next) => {})`;
- 泛型里声明 `Variables` 后，下游 Handler 的 `c.var.user` 才有类型;
- 不返回值的中间件不能写 `return next()` 之外的返回值，否则会短路;

## 带参数的中间件怎么写？

```ts
const header = (value: string) =>
  createMiddleware(async (c, next) => {
    await next();
    c.res.headers.set("X-Message", value);
  });

app.use(header("hello"));
```

- 参数放外层函数，中间件本体放内层，这样每次构造互不影响;
- 需要读配置时，把值从外层传进来，不要在中间件里直接读 `process.env`;

## 链式挂载时类型怎么累加？

```ts
const app = new Hono()
  .use(authMiddleware) // Variables: { user }
  .use(dbMiddleware) // Variables: { db }
  .get("/", (c) => {
    c.var.user; // ✅
    c.var.db; // ✅
    return c.json({ ok: true });
  });
```

- 每次 `.use()` 返回的新实例都带着合并后的 `Variables` 类型;
- 因此链式写法不需要手写组合后的 `Env`;
- 用 `app.use(...)` 分开注册则不累加，需要 `new Hono<{ Variables: ... }>()` 手动声明;

## 请求级数据怎么传递？

```ts
app.use(async (c, next) => {
  c.set("traceId", crypto.randomUUID());
  await next();
});

app.get("/", (c) => c.text(c.get("traceId"))); // 或 c.var.traceId
```

- 生命周期仅限本次请求，类型来源是 `Variables` 泛型;
- 全局声明 `ContextVariableMap` 的风险与选择见 [类型声明与请求级变量](./060-类型声明与请求级变量.md);
- 需要深层函数取 Context 时用 `contextStorage`，见 [Timing 与上下文存储](../003-上线/085-上下文存储.md);
