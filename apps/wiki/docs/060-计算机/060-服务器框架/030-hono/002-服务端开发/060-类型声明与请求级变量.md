# 类型声明与请求级变量

## `Bindings` 和 `Variables` 分别管什么？

```ts
type Bindings = { TOKEN: string }; // c.env.* —— 环境提供、请求期间只读
type Variables = { user: { id: string } }; // c.set/get —— 请求期间可写

const app = new Hono<{ Bindings: Bindings; Variables: Variables }>();
```

| 泛型        | 访问方式                    | 典型内容                      | 可否赋值         |
| ----------- | --------------------------- | ----------------------------- | ---------------- |
| `Bindings`  | `c.env.X`                   | 环境变量、连接池、平台绑定    | 否               |
| `Variables` | `c.set` / `c.get` / `c.var` | 中间件注入的用户、db、traceId | 是（仅本次请求） |

- Node 上 `Bindings` 通常写成 `HttpBindings`（`c.env.incoming`/`outgoing`）再交叉自己的类型;
- `Variables` 是跨中间件传值的唯一正路，别用模块级变量;

## `c.var` 与 `c.get()` 有什么区别？

- 完全等价：`c.var.x` 就是 `c.get('x')` 的属性式写法，只是更短、更符合阅读习惯;
- 类型都来自 `Variables` 泛型，链式 `.use()` 会自动累加;

```ts
app.get("/echo", (c) => c.text(c.var.echo("Hello!")));
```

## 全局类型声明有哪两种，风险在哪？

```ts
// 一、ContextVariableMap：全局生效
declare module "hono" {
  interface ContextVariableMap {
    result: string;
  }
}

// 二、模块增强 c.render 的类型
declare module "hono" {
  interface ContextRenderer {
    (content: string, head: { title: string }): Response | Promise<Response>;
  }
}
```

- `ContextVariableMap` 的风险: 没挂载该中间件的 Handler 里 `c.get('result')` 依然被标成 `string`，运行时实际是 `undefined`;
- 只有在「全应用强制挂载」时才用它，其余场景用 `new Hono<{ Variables }>()`;
- 类型放 `src/types.ts` 并在入口 `import './types'`，否则增强不生效;

## 请求级变量的生命周期是什么？

```text
请求开始 → 中间件 c.set('user', ...) → Handler c.get('user') → 响应结束丢弃
```

- 仅本次请求可见，不能跨请求共享，也不能当缓存用;
- 需要跨请求的数据请用 Redis 或进程内缓存，并显式管理失效;
- `c.set` 在 Handler 之后调用无效，因为响应已经产出;
