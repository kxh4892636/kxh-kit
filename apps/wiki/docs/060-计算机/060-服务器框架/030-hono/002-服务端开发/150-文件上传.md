# 文件上传

## 上传接口的标准写法是什么？

```ts
import { bodyLimit } from "hono/body-limit";
import { zValidator } from "@hono/zod-validator";
import * as z from "zod";

app.post(
  "/user/picture",
  bodyLimit({ maxSize: 5 * 1024 * 1024, onError: (c) => c.text("too large", 413) }),
  zValidator(
    "form",
    z.object({
      note: z.string().optional(),
      file: z.instanceof(File),
    }),
  ),
  async (c) => {
    const { file, note } = c.req.valid("form");
    await saveFile(file, note); // file.name / file.size / file.type / await file.arrayBuffer()
    return c.json({ ok: true, size: file.size }, 201);
  },
);
```

- `bodyLimit` 必须在解析前挂，否则请求体已经进内存;
- 校验里用 `z.instanceof(File)` 才能把类型收窄成 `File`（Node 20+ 有全局 `File`）;
- 判断大小用 `file.size`，判断类型用 `file.type`;

## 多文件、同名多值怎么取？

```ts
const body = await c.req.parseBody();

body["avatar"]; // string | File          单文件，多文件时只留最后一个
body["photos[]"]; // (string | File)[]      多文件必须用 [] 后缀

// 同名多值统一成数组
const all = await c.req.parseBody({ all: true });

// 点号路径还原成嵌套对象：'obj.key1' → { obj: { key1 } }
const dotted = await c.req.parseBody({ dot: true });
```

- `parseBody()` 的其他细节见 [读取请求体](../001-快速上手/090-读取请求体.md);

## 上传安全要注意什么？

| 风险                 | 防护                                                           |
| -------------------- | -------------------------------------------------------------- |
| 超大文件打满内存     | `bodyLimit` + 平台/代理层限制                                  |
| 伪造 MIME            | 不信任 `file.type`，按扩展名 + 文件头校验                      |
| 路径穿越             | 落盘时用服务端生成的 ID 做文件名，不要用用户文件名             |
| 危险类型被当页面执行 | 上传目录与站点不同源，响应加 `Content-Disposition: attachment` |
| 恶意内容扩散         | 图片做二次转码，文档走扫描/沙箱预览                            |

- 存储建议: 对象存储（S3/OSS）直传 + 服务端只发签名，避免大文件穿过后端进程;
- 需要流式接收大文件时，用 `c.req.raw.body` 边读边写，不要 `parseBody`;
