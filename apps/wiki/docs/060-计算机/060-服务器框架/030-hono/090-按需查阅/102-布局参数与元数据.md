# 布局参数与元数据

## 布局需要额外参数（标题、SEO）怎么办？

```ts
declare module 'hono' {
  interface ContextRenderer {
    (content: string, head: { title: string }): Response | Promise<Response>
  }
}

app.use('/pages/*', async (c, next) => {
  c.setRenderer((content, head) => c.html(
    <html>
      <head><title>{head.title}</title></head>
      <body><header>{head.title}</header>{content}</body>
    </html>
  ))
  await next()
})

app.get('/pages/me', (c) => c.render(<p>Ramen</p>, { title: 'My favorite' }))
```

- 模块增强必须放在会被入口引入的 `.ts` 文件里，否则类型不生效;
- 增强后 `c.render()` 的第二个参数才有类型检查;
- 参数多了就抽成对象，不要把标题、描述、canonical 一个个加成位置参数;

## 元数据写在组件里可以吗？

```tsx
app.get("/about", (c) =>
  c.render(
    <>
      <title>About Page</title>
      <meta name="description" content="about" />
      about page content
    </>,
  ),
);
```

- `<title>`、`<meta>`、`<link>` 会被自动提升到文档的 `<head>` 中;
- 已有的 head 元素不会被移除，后出现的追加在后面;
- 因此别同时在布局和页面里写同一个 `<title>`，否则会输出两个;

## 提升顺序会带来什么坑？

| 写法                                 | 结果                             |
| ------------------------------------ | -------------------------------- |
| 布局写默认 `<title>`，页面覆盖       | 两个 `<title>` 同时存在          |
| 布局不写，页面写                     | 正常，只有一个                   |
| 页面里写 `<meta>`、布局里写 `<meta>` | 同名 meta 重复，SEO 可能取第一个 |

- 约定: 布局只写「必有且固定」的 meta（charset、viewport），页面写业务相关;
- 需要严格去重时，自己在布局里接收参数拼 head，而不是依赖自动提升;
