# JSX 样式与注意

## 样式怎么写？

```ts
import { css } from 'hono/css'

const title = css`
  color: red;
  font-weight: bold;
`

app.get('/', (c) => c.html(<h1 class={title}>Hi</h1>))
```

- `hono/css` 是 CSS-in-JS：生成类名并在 SSR 时收集样式;
- 已有 Tailwind / CSS Modules 的项目不必引入，`className` 直接写即可;
- 同一个文件里多次定义会生成不同类名，注意不要重复定义同一组样式;

## `hono/css` 和传统方案怎么选？

| 方案        | 优点                   | 缺点                     |
| ----------- | ---------------------- | ------------------------ |
| `hono/css`  | 无构建配置，按组件组织 | 运行期收集样式，动态性弱 |
| CSS Modules | 构建期处理，零运行时   | 需要打包器配合           |
| Tailwind    | 类名即样式，产物小     | 需要扫描内容配置         |

- 页面少、无构建链时用 `hono/css`；已有前端工程时沿用工程内方案;

## JSX 在 Node 上要注意什么？

| 事项 | 说明                                                                |
| ---- | ------------------------------------------------------------------- |
| 转义 | JSX 默认转义插值，`dangerouslySetInnerHTML` 才关闭                  |
| 构建 | `tsconfig` 的 `jsxImportSource` 必须指向 `hono/jsx`，否则运行时报错 |
| 类型 | 模块增强（如 `ContextRenderer`）要放在被引入的 `.ts` 里才生效       |
| 性能 | 页面渲染比 JSON 慢，纯 API 路由不要混进渲染逻辑                     |

## 什么时候不该用 JSX？

- 纯 JSON API：用 `c.json()`，不要为了「统一」引入渲染层;
- 极简 HTML（邮件、一行页面）：用 [模板字符串渲染](./090-模板字符串渲染.md) 更轻;
- 需要客户端水合的 SPA：交给前端框架，Hono 只做 API。
