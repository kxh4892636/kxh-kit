# 模板字符串渲染

## 后端服务需要 JSX 吗？

- 纯 JSON API：不需要，`c.json()` 就够;
- 要输出服务端渲染页面（后台、邮件模板、文档页）：两种选择，`hono/html` 模板字符串或 `hono/jsx`;
- 取舍: 模板字符串零配置、更轻；JSX 有组件、类型检查和自动转义;

## 用模板字符串怎么写？

```ts
import { html, raw } from "hono/html";

app.get("/:username", (c) => {
  const { username } = c.req.param();
  return c.html(
    html`<!doctype html>
      <h1>Hello! ${username}!</h1>`,
  );
});
```

- `html` 会自动转义插值，防 XSS;
- `raw()` 关闭转义，仅用于插入可信 HTML;
- 返回值可作为「组件」组合，比 JSX 更省运行时：

```ts
const Footer = () => html`<footer><address>My Address</address></footer>`;

const Layout = (props: { title: string; children: any }) => html`
  <html>
    <head>
      <title>${props.title}</title>
    </head>
    <body>
      ${props.children}
    </body>
  </html>
`;
```

## 什么时候用它而不是 JSX？

| 维度       | `hono/html`              | `hono/jsx`                 |
| ---------- | ------------------------ | -------------------------- |
| 配置       | 无                       | 需要 tsconfig / 文件级注释 |
| 运行时开销 | 小                       | 略大（构建虚拟节点）       |
| 组件复用   | 函数返回字符串           | 组件 + props + children    |
| 编辑器支持 | 装 lit-html 插件后有高亮 | 原生 TSX 支持              |
| 适合       | 邮件、文档、少量页面     | 有布局与组件层级的页面     |

- 邮件模板、纯拼接页面优先用模板字符串：不引入 JSX 运行时，也不需要在构建链里加配置;
- 需要循环、条件、组件嵌套较深时再切 JSX，见 [JSX 组件与配置](./095-JSX组件.md);
