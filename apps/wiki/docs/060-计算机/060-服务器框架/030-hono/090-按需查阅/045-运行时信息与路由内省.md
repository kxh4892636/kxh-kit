# 运行时信息与路由内省

## 用 Adapter 取运行时信息？

```ts
import { env, getRuntimeKey } from "hono/adapter";

app.get("/info", (c) => {
  const { NAME } = env<{ NAME: string }>(c); // Node 上读 process.env
  return c.json({ NAME, runtime: getRuntimeKey() });
});
```

- 只在需要「同一份代码跑多运行时」时用；纯 Node 服务直接 `process.env`;
- 配置的组织方式见 [环境变量与配置](../002-服务端开发/050-环境变量与配置.md);

## ConnInfo 能拿到什么？

```ts
import { getConnInfo } from "@hono/node-server/conninfo";

app.get("/ip", (c) => {
  const { remote } = getConnInfo(c);
  return c.text(remote.address ?? "unknown");
});
```

- 常用于限流、审计日志、IP 白名单（配合 `ipRestriction`）;
- 有反向代理时 `remote.address` 是代理地址，真实来源要读 `X-Forwarded-For` 并先信任代理;

## Route Helper 与废弃属性怎么对应？

```ts
import { routePath, matchedRoutes, basePath, baseRoutePath } from "hono/route";

app.get("/posts/:id", (c) => {
  routePath(c); // '/posts/:id'
  basePath(c); // '/api'（含实际参数值）
  baseRoutePath(c); // '/:sub'（路由声明里的模式）
  matchedRoutes(c); // 所有命中的路由与中间件
});
```

- 调试「到底命中哪条路由」用它，比翻日志快;
- `routePath(c, -1)` 取最后一个匹配，用法类似 `Array.prototype.at`;
- 打印所有路由另有 `showRoutes()`，见 [Timing 与上下文存储](../003-上线/085-上下文存储.md);

## SSG 和 Node 服务有关系吗？

- `hono/ssg` 用于把应用渲染成静态文件，属于构建期能力;
- 纯 Node API 服务不需要；需要预渲染页面时再查，它与运行时部署路径是两件事;
