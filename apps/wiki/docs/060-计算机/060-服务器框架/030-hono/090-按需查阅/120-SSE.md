# SSE

## SSE 是什么，和 WebSocket 怎么选？

| 维度 | SSE                              | WebSocket      |
| ---- | -------------------------------- | -------------- |
| 方向 | 服务端 → 客户端单向              | 双向           |
| 协议 | 普通 HTTP（`text/event-stream`） | 独立升级协议   |
| 断线 | 浏览器自动重连                   | 需自己实现     |
| 适用 | 通知、进度、LLM 输出             | 聊天、协同编辑 |

- 只需要「服务端推」就用 SSE，运维与代理兼容性都更好;

## 怎么实现一个 SSE 接口？

```ts
import { streamSSE } from "hono/streaming";

let id = 0;
app.get("/sse", (c) => {
  return streamSSE(c, async (s) => {
    while (!s.aborted) {
      await s.writeSSE({
        data: `now: ${new Date().toISOString()}`,
        event: "tick",
        id: String(id++),
      });
      await s.sleep(1000);
    }
  });
});
```

- `data` 里出现换行会被自动拆成多行 `data:`，不需自己处理;
- 循环条件用 `s.aborted`，客户端断开即退出，避免泄漏;
- 事件名用 `event`，客户端用 `addEventListener('tick', ...)` 监听;

## SSE 的超时与清理怎么做？

```ts
return streamSSE(c, async (s) => {
  let running = true;
  const timer = setTimeout(() => s.close(), 3000);
  s.onAbort(() => {
    running = false;
    clearTimeout(timer);
  });
  while (running) {
    await s.writeSSE({ data: "x" });
    await s.sleep(1000);
  }
});
```

- `timeout()` 中间件与流式响应冲突，必须用 `stream.close()` + `setTimeout` 自己实现;
- 心跳（如每 15s 一条 `: ping` 注释）能防止 Nginx/ELB 在空闲时断链;
- 断开时必须清定时器、取消数据库订阅或上游请求，否则连接越多泄漏越快;

## 生产部署要配什么？

| 位置     | 配置                                                        |
| -------- | ----------------------------------------------------------- |
| Nginx    | `proxy_buffering off; proxy_read_timeout 3600s;`            |
| 负载均衡 | 空闲超时调大，或依赖心跳保活                                |
| 压缩     | 不要对 `text/event-stream` 压缩（默认也不在白名单内）       |
| 鉴权     | 浏览器 `EventSource` 不能自定义头，用 Cookie 或 query token |
