# 流式响应

## 流式响应解决什么问题？

- 普通响应: 全部内容算完才发出，首字节晚、大响应占内存;
- 流式响应: 边算边发，适合大文件、日志、LLM 逐字输出、进度推送;
- 代价: 一旦开始写，状态码和响应头不能再改，错误也不能被 `onError` 改写;

## `stream()` 和 `streamText()` 有什么区别？

| API                 | Content-Type                                | 用途                 |
| ------------------- | ------------------------------------------- | -------------------- |
| `stream(c, cb)`     | 由你定（默认二进制）                        | 自定义流、转发上游流 |
| `streamText(c, cb)` | `text/plain` + `Transfer-Encoding: chunked` | 逐行文本             |

```ts
import { stream, streamText } from "hono/streaming";

app.get("/stream", (c) => {
  return stream(c, async (s) => {
    s.onAbort(() => console.log("客户端断开"));
    await s.write(new Uint8Array([0x48, 0x69])); // 写 Uint8Array
    await s.pipe(anotherReadableStream); // 或直接管道一个 ReadableStream
  });
});

app.get("/text", (c) => {
  return streamText(c, async (s) => {
    await s.writeln("Hello");
    await s.sleep(1000);
    await s.write("Hono!"); // 不换行
  });
});
```

- 回调执行完流自动关闭，不需要手动 `close()`;
- `s.onAbort()` 是清理计时器、取消上游订阅的唯一挂点;

## 流里出错了怎么处理？

```ts
return stream(
  c,
  async (s) => {
    /* 业务 */
  },
  (err, s) => {
    // 第三个参数：错误回调
    console.error(err);
    s.writeln("error occurred");
  },
);
```

- 不传错误回调时，错误只打 `console.error`;
- 流已开始时 `app.onError` **不会**被触发，因为响应已发出、无法替换;
- 因此流式接口的业务错误要在流内用事件形式告知客户端（如 `event: error`）;

## Node 上要注意什么？

| 事项     | 说明                                                             |
| -------- | ---------------------------------------------------------------- |
| 压缩     | `compress()` 遇到已有 `Transfer-Encoding` 的响应会自动跳过       |
| 反向代理 | Nginx 需 `proxy_buffering off`，否则前端仍是一坨到齐             |
| 心跳     | 长连接间隔建议 ≤30s 发一次数据，防中间层断链                     |
| 关闭     | 客户端断开时务必清掉定时器与上游订阅，否则内存持续增长           |
| 超时     | `timeout()` 与流式响应不兼容，要自己管（见 [SSE](./120-SSE.md)） |
