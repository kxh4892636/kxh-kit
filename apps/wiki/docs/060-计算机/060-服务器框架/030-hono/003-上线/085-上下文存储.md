# 上下文存储

## 如何在非 Handler 的地方拿到 Context？

```ts
import { contextStorage, getContext, tryGetContext } from "hono/context-storage";

app.use(contextStorage());
app.use(async (c, next) => {
  c.set("traceId", "abc");
  await next();
});

// 深层工具函数里直接取
export const log = (msg: string) => {
  const c = tryGetContext(); // 没有上下文时返回 undefined，不抛错
  console.log(`[${c?.var.traceId ?? "-"}] ${msg}`);
};
```

- 依赖 Node 的 `AsyncLocalStorage`；Node 原生支持，无需额外配置;
- 适合日志、埋点、ORM 日志这类「不想一路传参」的场景;
- `getContext()` 在无上下文时抛错，`tryGetContext()` 返回 `undefined`;

## 为什么它有时取不到值？

| 原因                  | 说明                            |
| --------------------- | ------------------------------- |
| 没有 `await` 异步链   | 丢失上下文传播，回调里取不到    |
| 在模块顶层调用        | 此时还没有请求上下文            |
| 定时器/任务队列里调用 | 脱离原请求的异步上下文          |
| 中间件挂载顺序不对    | `contextStorage()` 必须在最前面 |

- 规则: `contextStorage()` 第一个挂载，后续所有异步调用都要正确 `await`;
- 不要用它替代显式传参：核心业务逻辑仍建议收普通参数，便于测试;

## 它和 `c.set` 有什么关系？

- `c.set` 存的是「本次请求的数据」，`contextStorage` 解决的是「拿不到 `c`」的问题;
- 两者配合：`c.set('traceId', ...)` 后，深层函数通过 `getContext().var.traceId` 读取;
- 请求级变量的类型声明见 [类型声明与请求级变量](../002-服务端开发/060-类型声明与请求级变量.md)。
