# 日志规范

## 生产日志该记什么？

| 必记          | 说明                                                 |
| ------------- | ---------------------------------------------------- |
| `requestId`   | 串联一次请求的所有日志                               |
| method + path | 用 `c.req.path` 而不是 `c.req.url`，避免淹没有效信息 |
| status + 耗时 | 在中间件 after 阶段取 `c.res.status`                 |
| `c.error`     | 统一在 `app.onError` 里记录堆栈                      |
| 慢请求标记    | 耗时超过阈值时提升日志级别                           |

## 日志级别怎么分？

| 级别    | 用途                         |
| ------- | ---------------------------- |
| `debug` | 本地开发、请求/响应细节      |
| `info`  | 启动、配置加载、关键业务动作 |
| `warn`  | 可恢复异常、降级、慢请求     |
| `error` | 未处理异常、依赖不可用       |

- 生产默认 `info`，用环境变量控制;
- 不要在热路径里打 `debug` 再靠级别过滤，字符串拼接本身就有成本;

## 哪些内容绝对不能进日志？

- 用户隐私：手机号、身份证、地址、聊天内容;
- 凭证：`Authorization`、Cookie、签名密钥、数据库连接串;
- 完整请求体：大 JSON、文件内容;
- 内部地址与拓扑：内网 IP、库表名（按团队规范取舍）;

```ts
// 需要定位时记录脱敏后的片段
console.log(JSON.stringify({ phone: mask(phone), tail: body.slice(0, 120) }));
```

- 排查必须看原文时，用采样 + 短期保留 + 访问审计，而不是长期全量落盘;
- 与请求 ID 的配合见 [请求 ID 与追踪](./075-请求ID与追踪.md)。
