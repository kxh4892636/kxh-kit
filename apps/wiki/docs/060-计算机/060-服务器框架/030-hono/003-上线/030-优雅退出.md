# 优雅退出

## 优雅退出为什么必须写？

- 直接 `process.exit()` 会切断在途请求与数据库连接;
- Node 适配器返回原生 server，关闭责任在应用:

```ts
import { serve } from "@hono/node-server";
import { app } from "./app.js";

const server = serve({ fetch: app.fetch, port: Number(process.env.PORT ?? 3000) });

const shutdown = (signal: string) => {
  console.log(`received ${signal}, closing...`);
  server.close((err) => {
    if (err) {
      console.error(err);
      process.exit(1);
    }
    process.exit(0); // 之后在这里关数据库连接池
  });
};

process.on("SIGINT", () => shutdown("SIGINT"));
process.on("SIGTERM", () => shutdown("SIGTERM"));
```

- 容器编排靠 `SIGTERM` 停机，监听它才有时间完成在途请求;

## 关闭顺序应该是什么？

```text
收到 SIGTERM
  → 停止接受新连接（server.close）
  → 等待在途请求完成
  → 关闭 WebSocket
  → 关闭数据库/Redis 连接池
  → exit(0)
```

- 顺序反了会出现「连接池已关、请求还在用」的报错;
- 给反向代理留出摘流时间：先 `server.close()` 再等几百毫秒，避免新请求打进来;
- 需要强制超时兜底：`setTimeout(() => process.exit(1), 10_000).unref()`;

## 有哪些资源必须显式关闭？

| 资源         | 关闭方式                   |
| ------------ | -------------------------- |
| HTTP server  | `server.close(cb)`         |
| WebSocket    | `wss.close()` + 通知客户端 |
| 数据库连接池 | `await pool.end()`         |
| Redis        | `await redis.quit()`       |
| 定时任务     | `clearInterval` / `stop()` |

- 任何「进程退出后需要外部重新建立」的资源，都要在关闭钩子里处理;
- 健康检查的配合见 [健康检查](./035-健康检查.md)。
