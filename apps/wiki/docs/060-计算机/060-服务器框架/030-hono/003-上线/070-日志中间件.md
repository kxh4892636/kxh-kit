# 日志中间件

## 一行日志中间件够用吗？

```ts
import { logger } from "hono/logger";

app.use(logger());
// <-- GET /
// --> GET / 200 12ms
```

- 默认输出: 方法、路径、状态码、耗时；状态码带颜色（设 `NO_COLOR` 可关闭）;
- 换掉输出函数即可接结构化日志：

```ts
const pinoLike = (message: string, ...rest: string[]) =>
  console.log(JSON.stringify({ message, rest }));

app.use(logger(pinoLike));
```

- 局限: 没有 requestId、没有 body、无法按级别分流；生产建议自己写一个中间件（见下）;

## 一个可直接用的结构化日志中间件长什么样？

```ts
import { createMiddleware } from "hono/factory";

export const accessLog = createMiddleware(async (c, next) => {
  const start = performance.now();
  await next();
  console.log(
    JSON.stringify({
      requestId: c.get("requestId"),
      method: c.req.method,
      path: c.req.path,
      status: c.res.status,
      ms: Math.round(performance.now() - start),
      error: c.error?.message,
    }),
  );
});
```

- 与 `requestId()` 配合使用，顺序要在它之后;
- 字段名固定下来，采集端（ELK/Loki）才好做聚合;
- 记录日志不要影响响应：避免在中间件里同步写文件;

## 该选内置 logger 还是自己写？

| 场景               | 选择                                         |
| ------------------ | -------------------------------------------- |
| 本地开发、临时排查 | 内置 `logger()`                              |
| 生产需要 JSON 日志 | 自己写 `createMiddleware`                    |
| 已有 pino/winston  | 用 `logger(自定义 PrintFunc)` 或完全自己接管 |

- 内置 logger 不依赖任何库，但字段与级别不可配;
- 自己写的时候不要在中间件里做 IO 阻塞，交给日志库异步刷新。
