# 索引与视图

## 索引什么时候该加？

- 该加：外键列、常用过滤列、常被 `orderBy` 的列、唯一约束;
- 别加：极低基数列（如性别）、只写不读的表、重复覆盖已有索引的列;

```ts
await db.schema.createIndex("pet_owner_id_index").on("pet").column("owner_id").execute();
await db.schema.createIndex("pet_name_unique").on("pet").column("name").unique().execute();
await db.schema
  .createIndex("pet_owner_species_index")
  .on("pet")
  .columns(["owner_id", "species"])
  .execute();
```

## 索引怎么命名和删除？

- 命名约定 `<表>_<列>_index`，复合索引用列名拼接;
- 删索引要 `ifExists()`，否则迁移在不同环境会失败;

```ts
await db.schema.dropIndex("pet_owner_id_index").ifExists().execute();
```

## 怎么确认索引被用上了？

- 把 `.compile()` 得到的 SQL 拿去看执行计划;
- 出现 `SCAN` 表示全表扫描，`SEARCH ... USING INDEX` 才是命中;

```sql
explain query plan select * from pet where owner_id = 1;
-- SEARCH pet USING INDEX pet_owner_id_index (owner_id=?)
```

```ts
const { sql, parameters } = db.selectFrom("pet").selectAll().where("owner_id", "=", 1).compile();
await sql`explain query plan ${sql.raw(sql)}`.execute(db); // 仅调试用
```

## 视图要写进迁移吗？

- 要。视图也是结构，写进迁移才能在不同环境一致;
- `createView('v').as(查询).execute()`、`dropView('v').ifExists().execute()`;

```ts
export async function up(db: Kysely<any>) {
  await db.schema
    .createView("adult_person")
    .as(db.selectFrom("person").selectAll().where("age", ">=", 18))
    .execute();
}

export async function down(db: Kysely<any>) {
  await db.schema.dropView("adult_person").ifExists().execute();
}
```

- 视图里引用的列改名时，先改视图再改表;
- 改表本身的操作见 [改表](./050-改表.md)。
