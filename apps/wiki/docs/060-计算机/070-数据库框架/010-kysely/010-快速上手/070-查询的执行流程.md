# 查询的执行流程

## `.execute()` 之后发生了什么？

```text
query builder
  → plugins.transformQuery   改写语法树（驼峰、去重 join、空 in…）
  → QueryCompiler            按方言编译出 { sql, parameters }
  → Driver.acquireConnection 拿连接
  → DatabaseConnection       发送 SQL + 参数，拿回原始行
  → plugins.transformResult  改写结果（解析 JSON、改列名…）
  → 你拿到的类型化结果
```

- builder 只描述意图，编译与执行是两个阶段;
- SQLite 的占位符是 `?`，参数与 SQL 分开传输，天然防注入。

## 只想看 SQL 怎么办？

- `.compile()` 不连数据库，直接拿到 `{ sql, parameters, query }`;
- 排查问题时先看它，多数「参数当成了列名」「少了个条件」一眼可见;

```ts
const compiled = db.selectFrom("person").select("first_name").where("id", "=", 1).compile();
console.log(compiled.sql, compiled.parameters);
// select "first_name" from "person" where "id" = ? [ 1 ]
```

## 编译和执行能拆开吗？

- 能。`compile()` 可在没有数据库时运行（`DummyDriver`），适合日志、审阅、跨进程传递;
- 想执行别人编译好的查询，用 `db.executeQuery(compiledQuery)`;

```ts
import {
  DummyDriver,
  Kysely,
  SqliteAdapter,
  SqliteIntrospector,
  SqliteQueryCompiler,
} from "kysely";

const cold = new Kysely<Database>({
  dialect: {
    createAdapter: () => new SqliteAdapter(),
    createDriver: () => new DummyDriver(),
    createIntrospector: (db) => new SqliteIntrospector(db),
    createQueryCompiler: () => new SqliteQueryCompiler(),
  },
});

const compiled = db.selectFrom("person").select("id").compile();
const rows = await db.executeQuery(compiled); // 用真实实例执行
```

## 插件在哪一步介入？

- `transformQuery` 在编译前改语法树，`transformResult` 在返回前改结果;
- 所以插件能改 SQL 和结果，但改不了你已经写下的类型;
- 内置插件清单见 [插件与日志](../050-进阶/010-内置插件.md)。

## 为什么写法必须一步步赋回变量？

- 那是另一件事：builder 不可变、上下文随链式调用累积;
- 见 [语句顺序与条件构建](./080-语句顺序与条件构建.md)。
