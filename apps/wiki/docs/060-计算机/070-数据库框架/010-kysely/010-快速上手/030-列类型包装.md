# 定义数据库类型

## `Database` 接口是什么？

- Kysely 全部类型推导的输入: 键是表名，值是表的列定义;
- 只描述「表长什么样」，不描述「表之间什么关系」——Kysely 没有关系概念;

```ts title="src/types.ts"
export interface Database {
  person: PersonTable;
  pet: PetTable;
}
```

## 每种列该用哪种类型？

| 需求                                | 写法                                                    | 效果                           |
| ----------------------------------- | ------------------------------------------------------- | ------------------------------ |
| 数据库自动生成（自增 id、默认时间） | `Generated<number>`                                     | 插入/更新时自动变可选          |
| 可空列                              | `string \| null`                                        | 结果类型为 `string \| null`    |
| 读/写类型不同                       | `ColumnType<Select, Insert, Update>`                    | 三个操作各用各的类型           |
| JSON 列                             | `JSONColumnType<T>`                                     | 读 `T`，写必须是 JSON 字符串   |
| 可空 JSON 列                        | `ColumnType<T \| null, string \| null, string \| null>` | `JSONColumnType` 不能表达 null |

```ts title="src/types.ts"
import {
  ColumnType,
  Generated,
  JSONColumnType,
  type Insertable,
  type Selectable,
  type Updateable,
} from "kysely";

export interface PersonTable {
  id: Generated<number>;
  first_name: string;
  gender: "man" | "woman" | "other"; // 枚举用联合类型表达
  last_name: string | null; // 可空就用 | null，不要用可选属性 ?
  created_at: ColumnType<string, string | undefined, never>; // 插入可省，永不更新
  metadata: JSONColumnType<{ plan: "free" | "premium" }>;
}
```

- 三种工具类型怎么用、结果类型长什么样，见 [工具类型与结果类型](./040-工具类型与结果类型.md)。
