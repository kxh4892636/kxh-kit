# 安装与项目配置

## 需要安装哪些包？

- 运行时: `kysely` + 驱动 `better-sqlite3`（Kysely 自身不带驱动）;
- 开发期: `typescript`、`tsx`（直接跑 `.ts`）、`@types/better-sqlite3`、`@types/node`;

```bash
npm init -y
npm pkg set type=module
npm i kysely better-sqlite3
npm i -D typescript tsx @types/node @types/better-sqlite3
```

## 项目配置要满足什么？

| 约束               | 值                 | 原因                                         |
| ------------------ | ------------------ | -------------------------------------------- |
| TypeScript         | ≥ 5.4              | Kysely 类型推导依赖新语法                    |
| `strict`           | `true`             | 官方硬性要求，关掉后类型安全失效             |
| `module`           | `Preserve`         | 允许 ES 语法 + 无扩展名相对导入              |
| `moduleResolution` | `Bundler`          | 与 `module: Preserve` 配套，`tsx` 可直接解析 |
| `package.json`     | `"type": "module"` | 顶层 `await` 与 ESM 导入不出错               |

```json title="tsconfig.json"
{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "Preserve",
    "moduleResolution": "Bundler",
    "noEmit": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["src"]
}
```

## 目录怎么安排？

```text
src/
  db.ts        # 唯一的 Kysely 实例
  types.ts     # Database 接口，见 030
  main.ts      # 业务/验证入口
dev.sqlite     # 库文件，别提交到仓库
```

- 把 `*.sqlite`、`*.sqlite-wal`、`*.sqlite-shm` 写进 `.gitignore`;
- 需要跨环境切换库文件时用环境变量，不要把路径写死。

## 用什么命令跑代码？

- 开发期用 `tsx` 直接跑 `.ts`，不需要先编译;
- 生产构建用 `tsc` 输出 JS，再 `node dist/main.js`;
- 两种方式都要求 `strict: true`，否则类型检查形同虚设。

```bash
npx tsx src/main.ts
npx tsc --noEmit   # 只做类型检查
```
