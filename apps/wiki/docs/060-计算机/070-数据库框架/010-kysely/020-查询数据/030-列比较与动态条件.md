# 列比较与动态条件

## 列与列比较怎么避免被当成参数？

- 两个操作数都是列时用 `whereRef`，否则右边会被序列化成参数值;
- `join` 的 `on` 条件里同理，用 `onRef`;

```ts
// ✅ 生成 where "pet"."owner_id" = "person"."id"
.whereRef('pet.owner_id', '=', 'person.id')

// ❌ 生成 where "pet"."owner_id" = ?，参数是字符串 'person.id'
.where('pet.owner_id', '=', 'person.id')
```

- 判断口诀：右边是**列**用 `whereRef`，右边是**值**用 `where`;
- 表达式层面等价写法是 `eb(ref('a'), '=', ref('b'))`。

## 空数组 `in ()` 为什么会炸？

- 空数组会编译成 `in ()`，SQLite 直接语法错误;
- 两种解法：调用前判空，或装 `HandleEmptyInListsPlugin` 改写成恒假/恒真;

```ts
const ids = collectIds();

const rows = await db
  .selectFrom("person")
  .selectAll()
  .$if(ids.length > 0, (qb) => qb.where("id", "in", ids))
  .execute();
```

- 插件配置与生成结果（`1 = 0` / `1 = 1`）见 [插件与日志](../050-进阶/010-内置插件.md)。

## 条件按需拼接有哪几种写法？

| 写法                        | 适用                        | 注意事项                  |
| --------------------------- | --------------------------- | ------------------------- |
| `if` + 重新赋值             | `where`、`orderBy`、`limit` | 必须把新 builder 赋回变量 |
| 收集数组后 `eb.and`/`eb.or` | 条件数量不定                | 空数组的语义要想清楚      |
| `$if`                       | 会改变结果类型的方法        | 被选中的列变可选          |

```ts
let query = db.selectFrom("person").selectAll();
if (firstName) query = query.where("first_name", "=", firstName);
if (lastName) query = query.where("last_name", "=", lastName);
const rows = await query.execute();
```

```ts
const filters: Expression<SqlBool>[] = [];
if (firstName) filters.push(eb("first_name", "=", firstName));
if (minAge) filters.push(eb("age", ">=", minAge));

const rows = await db
  .selectFrom("person")
  .selectAll()
  .where((eb) => eb.and(filters)) // 空数组 → 恒真，等价于不过滤
  .execute();
```

## 动态条件最容易出什么错？

- 空 `in` 数组（见上）;
- `eb.and([])` 恒真、`eb.or([])` 恒假，语义要确认;
- 条件里混入 `undefined`：先判空再 push，别把 `undefined` 当值传;
- 排序字段来自用户输入时走白名单，见 [动态表名与结果类型](../050-进阶/070-动态表名与结果类型.md);
- 同一组条件出现三次以上再抽函数，见 [可复用查询函数](./050-可复用表达式函数.md)。
