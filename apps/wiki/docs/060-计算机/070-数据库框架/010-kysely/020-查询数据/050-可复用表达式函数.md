# 可复用表达式函数

## 把常用表达式包成函数的口诀是什么？

- 入参用 `Expression<T>`，返回值也是 `Expression`;
- 这样调用方能传列引用、传值、传子查询，类型都跟着走;

```ts
import { type Expression, sql } from "kysely";

function upper(expr: Expression<string>) {
  return sql<string>`upper(${expr})`;
}

function lower(expr: Expression<string>) {
  return sql<string>`lower(${expr})`;
}

function concat(...exprs: Expression<string>[]) {
  return sql.join<string>(exprs, sql`||`);
}

const rows = await db
  .selectFrom("person")
  .select(["id"])
  .where(({ eb, ref, val }) => eb(upper(ref("first_name")), "=", "ADA"))
  .execute();
```

## 怎样把整段条件封成函数？

- 用 `expressionBuilder<DB>()` 建条件、把表相关依赖当参数传，见 [可复用条件函数](./060-可复用条件函数.md)。

## 函数入参是值还是列，怎么区分？

| 入参类型             | 调用方传什么                             | 生成 SQL     |
| -------------------- | ---------------------------------------- | ------------ |
| `string` / `number`  | 普通值                                   | 占位符参数   |
| `Expression<string>` | `eb.ref('列')` / `eb.val('值')` / 子查询 | 按表达式编译 |

- 写 helper 时尽量收 `Expression`，把「用列还是用值」的决定权交给调用方;
- 需要比较两列时 `whereRef` 也是这个思路，见 [过滤条件](./020-过滤条件.md)。

## 复用时的类型陷阱有哪些？

- 子查询当标量传要 `$asScalar()`；可能为 null 时再 `$notNull()`;
- 可能为 null 的表达式，helper 要按 `Expression<T | null>` 收;
- 细节见 [修正查询结果类型](../050-进阶/060-修正查询结果类型.md)。
