# 聚合与分组

## 聚合函数怎么写？

- `eb.fn` 上有 `count`、`countAll`、`avg`、`sum`、`min`、`max`;
- 泛型参数决定结果类型，按驱动实际返回值声明;

```ts
const stats = await db
  .selectFrom("person")
  .select((eb) => [
    eb.fn.countAll<number>().as("total"),
    eb.fn.avg<number | null>("age").as("avg_age"),
    eb.fn.max<number>("age").as("max_age"),
  ])
  .executeTakeFirstOrThrow();
```

## `group by` + `having` 怎么写？

- 非聚合列必须出现在 `groupBy` 里，否则 SQLite 返回任意一行的值;
- `having` 与 `where` 用法一致，只是作用在聚合结果上;

```ts
const rows = await db
  .selectFrom("person")
  .innerJoin("pet", "pet.owner_id", "person.id")
  .select((eb) => ["person.id", eb.fn.count<number>("pet.id").as("pet_count")])
  .groupBy("person.id")
  .having((eb) => eb.fn.count("pet.id"), ">", 1)
  .orderBy("pet_count", "desc")
  .execute();
```

## 一条 SQL 能同时返回明细和汇总吗？

- 能。用标量子查询把聚合结果当成一列选出;
- 也可以先算汇总 CTE 再 join，见 [子查询与CTE](./090-子查询与CTE.md);

```ts
const rows = await db
  .selectFrom("person")
  .select((eb) => [
    "person.id",
    eb
      .selectFrom("pet")
      .whereRef("pet.owner_id", "=", "person.id")
      .select(eb.fn.countAll<number>())
      .as("pet_count"),
  ])
  .execute();
```

## 聚合结果为什么和预期不一样？

- `count(列)` 不数 `null`，要数行数用 `countAll()`;
- `sum`/`avg` 在没有匹配行时返回 `null` 而不是 0，必要时 `coalesce`;
- 加了 join 后主表行会重复，`count` 要数 `distinct` 的列;

```ts
.select((eb) => [eb.fn.count<number>(sql<number>`distinct ${sql.ref('person.id')}`).as('people')])
// 或直接写整段
.select(sql<number>`count(distinct ${sql.ref('person.id')})`.as('people'))
```

## 什么时候不该用聚合？

- 需要「每行带一个子表列表」时，聚合会丢结构，改用 [嵌套关联查询](../050-进阶/030-嵌套关联查询.md);
- 分组列很多、结果又要分页时，聚合查询通常比两次查询更慢;

- 需要把聚合写进原生 SQL 时，见 [原生 SQL 片段](./110-原生SQL片段.md)。
