# 原生 SQL 片段

## 原生 SQL 应该怎么嵌？

- 值交给 `sql` 模板变参数，列名用 `sql.ref`，标识符用 `sql.id` / `sql.table`;
- `sql` 返回 `RawBuilder`，可以 `.as('别名')` 进 `select`，也能直接 `.execute(db)`;

```ts
import { sql } from "kysely";

const rows = await db
  .selectFrom("person")
  .select(["id", sql<string>`concat(first_name, ' ', last_name)`.as("full_name")])
  .execute();

const raw = await sql<{ total: number }>`select count(*) as total from person`.execute(db);
console.log(raw.rows);
```

- 表达式与 `sql` 的关系见 [表达式与表达式构造器](./040-表达式与表达式构造器.md)。

## 拼接片段的 API 有哪些？

| API                        | 生成的 SQL               |
| -------------------------- | ------------------------ |
| `sql.val(1)`               | `?`（参数）              |
| `sql.lit(2)`               | `2`（字面量，不进参数）  |
| `sql.ref('a.b')`           | `"a"."b"`                |
| `sql.id('t', 'c')`         | `"t"."c"`                |
| `sql.table('person')`      | `"person"`               |
| `sql.join([...], sql`, `)` | 用指定分隔符连接多个片段 |

```ts
sql`select ${sql.val(1)} as a, ${sql.lit(2)} as b from ${sql.table("person")}`;
// select ? as a, 2 as b from "person"
```

## 什么时候必须用 `sql.lit` 而不能用参数？

- 需要数据库在**编译期**看到常量时：`order by` 方向、`limit` 的固定值、部分 DDL;
- 除这些场景外一律用参数，避免拼接注入;
- SQLite 允许 `limit ?`，参数化没问题。

## SQLite 没有的函数怎么补？

- SQLite 有 `upper`/`lower`/`coalesce`，但没有 `concat`、`now()`、`greatest`/`least`;
- 两种办法：写成等价表达式，或在驱动层注册自定义函数;

```ts
// 方案一：换成 SQLite 原生写法，注意 null 会被吞
sql<string>`coalesce(first_name, '') || ' ' || coalesce(last_name, '')`;

// 方案二：驱动层注册（在创建 db 之前）
const sqlite = new SQLite("dev.sqlite");
sqlite.function("concat", (...args: unknown[]) => args.join(""));
```

## 原生 SQL 有什么代价？

- 混进去的列名不再受类型检查，改表时不会报错;
- 插件（驼峰、JSON 解析）对字面量片段的作用有限;
- 结果类型只能靠泛型手写，写错不会有人提醒;
- 拼不动时先 `.compile()` 看生成的 SQL，见 [查询的执行流程](../010-快速上手/070-查询的执行流程.md)。
