# Hertz 中间件

## 服务端中间件

- 中间件是请求-响应周期中的一个函数，可检查、过滤请求或在业务前后执行逻辑;
- 需要 post-handle 或调用栈延续时必须在中间件内显式调用 `c.Next(ctx)`;
- 只做 pre-handle 时可省略 `Next`;
- 注册级别: 全局 `h.Use()` > 路由组 `group.Use()` > 单路由 `h.GET(path, mw, handler)`;
- 快速中止: `ctx.Abort()` 终止后续 handler，当前中间件仍执行完;
- `AbortWithMsg(msg, code)` / `AbortWithStatus(code)`: 中止并设置响应;
- hz 生成项目时，`biz/router/*/middleware.go` 提供路由组中间件模板;
- 内置 Recovery 中间件由 `server.Default()` 注册;

## 客户端中间件

- 客户端中间件通过嵌套函数构造: `func(next client.Endpoint) client.Endpoint`;
- 必须调用 `next(ctx, req, resp)` 才能继续调用链，提前 return 可停止;
- 注册: `c.Use(MyMiddleware)`;
- `UseAsLast` 设置最后执行的中间件; `TakeOutLastMiddleware` 取出并清空;
- 重定向等场景中间件可能执行多次，需保证幂等;

## 示例

```go
func MyMiddleware() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		// pre-handle
		c.Next(ctx)
		// post-handle
	}
}
```

```go
func MyMiddleware(next client.Endpoint) client.Endpoint {
	return func(ctx context.Context, req *protocol.Request, resp *protocol.Response) (err error) {
		// pre-handle
		err = next(ctx, req, resp)
		// post-handle
		return
	}
}
```

## 常用中间件

- 官方内置: `basic_auth`、`recovery`;
- 更多第三方中间件见 [hertz-contrib](https://github.com/hertz-contrib);
