# Hertz 第三方可观测与限流

## Prometheus

- `hertz-contrib/monitor-prometheus` 提供请求量与时延监控;
- 默认 tag: HTTP Method、statusCode;
- 使用: `server.WithTracer(prometheus.NewServerTracer(":9091", "/hertz"))`;
- Client 无 Tracer 接口，用中间件实现监控;

## OpenTelemetry

- `hertz-contrib/obs-opentelemetry` 集成 Tracing、Metrics、Logging;
- Server: `hertztracing.NewServerTracer()` + `h.Use(hertztracing.ServerMiddleware(cfg))`;
- Client: `c.Use(hertztracing.ClientMiddleware())`;
- Metrics 支持 Rate/Errors/Duration、服务拓扑、go runtime 指标;
- 日志: `hlog.SetLogger(hertzlogrus.NewLogger())` 实现链路自动关联;
- Provider: `provider.NewOpenTelemetryProvider(provider.WithServiceName(...), ...)`;
- 也支持 OpenTelemetry 编译时注入方案;

## Sentinel

- `hertz-contrib/opensergo` 集成 sentinel-golang;
- Server: `h.Use(adaptor.SentinelServerMiddleware())`，默认资源名 `{method}:{path}`，block 返回 429;
- Client: `c.Use(adaptor.SentinelClientMiddleware())`，默认返回 blockError;
- `WithServerResourceExtractor` 自定义资源名（配合热点参数限流规则）;
- `WithServerBlockFallback` 自定义被阻断时的响应;

## 限流定位

- Sentinel 用于流量治理（限流/熔断），与框架内置 Recovery、Tracer 互补;
- 服务端可用 `WithLimit` 类配置的第三方实现做 QPS/连接数限制（见 Kitex 限流笔记）;
