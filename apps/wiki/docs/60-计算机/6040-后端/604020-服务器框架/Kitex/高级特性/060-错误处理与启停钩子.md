# Kitex 错误处理与启停钩子

## ErrorHandler

- RPC 错误基于协议传递, 无统一错误码规范; Kitex 提供 ErrorHandler 定制错误处理;
- Server: `server.WithErrorHandler(fn)`, 在 handler 执行后, 中间件执行前调用;
- Client: `client.WithErrorHandler(fn)`, 在远程调用结束, 中间件执行前调用; 默认返回 `ErrRemoteOrNetwork`(含 '[remote]' 标记);
- server handler 的 error 统一封装为 `kerrors.ErrBiz`, 需先 `errors.Unwrap`;
- Thrift/KitexProtobuf 返回 `remote.NewTransError(code, err)`; gRPC 返回 `status.Errorf(code, msg)`(用 Kitex fork 的 status 包);
- 内置错误码: Thrift/KitexProtobuf 为 0-10, gRPC 为 0-17, 自定义需避开;
- ErrorHandler 作为最里层 Middleware 执行;
- 企业统一异常规范建议封装进 Suite;

## 启动/退出钩子

- `server.RegisterStartHooks(fn)`: Server 触发启动后执行, 然后服务注册; 启动异步, 不保证 Server 完全就绪后执行;
- `server.RegisterShutdownHook(fn)`: 退出时先执行 ShutdownHooks, 再服务注销与 Shutdown;
- 可注册多个 Hook;
- 启动前/退出后逻辑直接写在 main.go 的 `svr.Run()` 前后; Run() 返回后 Server 已完全退出;
