# Kitex 编解码与传输扩展

## Codec 接口

- `Codec`: 整体编解码，结合传输协议与 Payload; `Encode/Decode/Name`;
- Decode 需进行协议探测判断传输协议与 Payload;
- `PayloadCodec`: 仅 Marshal/Unmarshal payload; Kitex 默认支持 Thrift、KitexProtobuf、gRPC;
- 泛化调用也是通过扩展 PayloadCodec 实现;
- 指定: `WithCodec(yourCodec)`、`WithPayloadCodec(yourPayloadCodec)`;
- 默认 Codec 包大小限制: `codec.NewDefaultCodecWithSizeLimit(maxSizeBytes)`（默认无限制）;

## TTHeader 协议

- TTHeader 透传服务信息便于治理: LENGTH、HEADER MAGIC、FLAGS、SEQUENCE NUMBER、Header Size、PROTOCOL ID、TRANSFORMS、INFO、PAYLOAD;
- 框架内置 netpoll-http2 支持 HTTP2（主要供 gRPC）;

## 传输模块扩展

- 主要接口: `TransServer`、`ServerTransHandler`、`ClientTransHandler`、`ByteBuffer`、`Extension`;
- 工厂: `TransServerFactory`、`ClientTransHandlerFactory`、`ServerTransHandlerFactory`;
- 同步 IO 场景只需实现 `Extension`，无需完整 TransHandler;
- 指定: `server.WithTransServerFactory` / `server.WithTransHandlerFactory`、`client.WithTransHandlerFactory`;

## Transport Pipeline

- 参考 Netty ChannelPipeline，提供 Inbound/Outbound Handler;
- Outbound: `Write(ctx, conn, send)`; Inbound: `OnActive/OnInactive/OnRead/OnMessage`;
- 默认扩展: 服务端限流 Handler（连接级 OnActive/OnInactive、请求级 OnRead）、元信息透传 Handler;
- 指定: `WithBoundHandler(yourBoundHandler)`;

## MetaHandler 元信息扩展

```go
type MetaHandler interface {
	WriteMeta(ctx, msg) (context.Context, error)
	ReadMeta(ctx, msg) (context.Context, error)
}
```

- 写入/读取传输协议元信息（如 TTHeader 的 from/to service、metainfo）;
- 指定: `client.WithMetaHandler(transmeta.ClientTTHeaderHandler)` 等;
- 透传字段结合内部治理能力，建议自行扩展实现;
