# Kitex 超时控制

## 客户端超时

- 连接超时 `ConnTimeout`: 建立新连接最大等待时间, 默认 50ms; 常遇 dial timeout 可调大或用长连接池;
- 请求超时 `RPCTimeout`: 一次 RPC 最大用时, 默认 0(不限); 超时返回 `kerrors.ErrRPCTimeout`; 超时默认不重试;
- 配置: `client.WithConnectTimeout(...)`, `client.WithRPCTimeout(...)`(client 级);
- 请求级: `callopt.WithConnectTimeout(...)`, `callopt.WithRPCTimeout(...)`(优先级更高);
- 动态配置: 实现 `rpcinfo.TimeoutProvider` 通过 `client.WithTimeoutProvider` 注入;
- 超时错误判断: `kerrors.IsTimeoutError(err)`;

## 超时错误拆分

- 默认 `ErrRPCTimeout` 无法区分原因; `rpctimeout.EnableGlobalNeedFineGrainedErrCode()` 开启(默认关);
- 开启后: Kitex 超时 → `ErrRPCTimeout`; 业务 `ctx.Cancel()` → `ErrCanceledByBusiness`; 业务更短 timeout → `ErrTimeoutByBusiness`;
- 判定阈值: `actualDDL + 50ms < Kitex DDL` 才判定为业务超时; 阈值可用 `rpctimeout.SetBusinessTimeoutThreshold` 修改;

## 服务端超时

- `ReadWriteTimeout`(默认 5s): 连接上读写等待时间, 防止异常连接卡协程; 不是 handler 执行超时; 服务端不支持 handler 超时配置;
- `ExitWaitTime`(默认 5s): 收到退出信号后的等待时间, 超时强制结束所有处理中的请求;
- `WithEnableContextTimeout`(v0.9.0+): 从 TTHeader 读到的 timeout 写入 server 请求 ctx; 需 client 配 TTHeader + ClientTTHeaderMetaHandler + RPCTimeout, server 配 `WithEnableContextTimeout(true)` + ServerTTHeaderMetaHandler;
- Streaming API 默认已开启 context timeout(经 grpc-timeout);
