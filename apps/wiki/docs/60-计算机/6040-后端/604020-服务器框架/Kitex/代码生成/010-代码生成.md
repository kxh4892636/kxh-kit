# Kitex 代码生成

## 工具与依赖

```shell
go install github.com/cloudwego/kitex/tool/cmd/kitex@latest
```

- 依赖 thriftgo / protoc 编译器; Windows 需 kitex >= v0.5.2;
- 生成分两部分: 底层编译器生成结构体编解码代码，kitex 生成 service 桩代码;

## 基本用法

```shell
kitex example.thrift                          # GOPATH 下
kitex -module xxx example.thrift              # GOPATH 外必须指定 module
kitex -service mydemoservice demo.thrift      # 生成服务端脚手架
```

- 生成 `kitex_gen/`（结构体 + service 包）; `-service` 额外生成 main.go、handler.go、build.sh、kitex_info.yaml;
- `-module`: 指定 go module，影响 import path; 会向上搜索 go.mod 并校验一致性;
- `-I path`: IDL 搜索路径，支持 git 仓库拉取（`git@...`、`http(s)://`、`@branch`）;
- `-use path`: 不生成 kitex_gen，使用已有 import path 的生成代码;
- `-record`: 记录命令生成 kitex-all.sh 便于批量重生成;
- `-combine-service`: 合并多个 thrift service（已弃用，方法名必须唯一）;
- `-thrift value` / `-protobuf value`: 透传编译器参数; 默认 `naming_style=golint,ignore_initialisms,gen_setter,gen_deep_equal`;
- `-protobuf-plugin`: 接入 protoc 插件生态;

## protobuf 注意事项

- 仅支持 proto3; `go_package` 必填，决定 import path 后缀;
- go_package 为完整 import path 时，必须匹配当前模块的 kitex_gen 才生成代码;
- `--protobuf Msome.proto=your.package.name/kitex_gen/wherever` 可覆盖 go_package;

## thrift 依赖

- 依赖 `github.com/apache/thrift v0.13.0`，生成时自动在 go.mod 加 replace;
- v0.14.0+ API 不兼容，`go get -u` 会导致编译失败;

## 模板扩展

- `-template-extension extensions.yaml`: 向 client.go/server.go/invoker.go 注入自定义代码（dependencies、import_paths、extend_option、extend_file）;
- 典型用于统一注入 suite option;

## 多 Handler

- `-tpl multiple_services`: 为每个 service 生成独立 handler 文件并统一注册（v0.11.0+）;
