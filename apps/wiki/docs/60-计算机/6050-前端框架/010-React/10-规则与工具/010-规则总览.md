# React 规则总览

## React 规则约束的是风格还是行为？

- 行为契约: 规则让 React 能重复计算、调度和组合组件，不只是命名或格式偏好，违反可能使重试与并发场景出现错误;
- 局部推理: 组件应能根据输入解释输出，不依赖其他组件恰好先执行或某次渲染一定提交;
- 工具辅助: ESLint、StrictMode 和编译器从不同阶段暴露问题，不能用某一个检查成功代替完整行为验证;

## 发现渲染副作用时应该到哪里查找规则？

- 主归属: [保持组件纯粹](../02-描述UI/060-保持组件纯粹.md)统一解释输入不可变、局部修改、幂等计算及副作用位置;
- 实际检查: 查找渲染过程中修改外部对象、读写可变 ref、发请求和依赖当前时间等行为，判断是否需要改成事件或同步过程;

## 发现组件或 Hook 被当成普通函数时怎样定位？

- 主归属: [React 调用组件与 Hook](./020-React调用组件与Hook.md)解释声明式调用与静态组合边界;
- 实际检查: 检查是否直接执行组件函数，或把 Hook 通过 props 动态替换；这些模式让调用者无法局部判断规则是否被遵守;

## 发现 Hook 数量或顺序错误时怎样定位？

- 主归属: [Hooks 规则](./030-Hooks规则.md)解释顶层调用、提前 return、自定义 Hook 与 use 的特殊规则;
- 实际检查: 对照每个条件分支是否执行同样顺序的 Hook，而不是只检查函数名是否以 use 开头;

## 如何将规则落实到日常修改？

- 编写时: 使用清晰 props、纯渲染和明确事件，让数据流可追踪;
- 调试时: 开启规则检查与 StrictMode，修复真正的输入、依赖和清理问题，不通过隐藏警告完成修改;
- 优化时: 先保证语义正确，再测量和缓存，不能依赖缓存次数维持业务正确性;
