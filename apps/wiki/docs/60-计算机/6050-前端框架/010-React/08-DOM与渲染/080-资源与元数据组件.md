# 资源与元数据组件

## 如何在组件中声明页面标题与元信息？

- 元数据提升: 合适的 title、meta 与 link 可在组件附近声明，由 React 放到文档 head；不是任意标签和任意属性组合都具备相同提升行为;
- 标题内容: title 接收单个字符串，插值时先拼出字符串，避免多个字符串与数字子节点形成数组;
- 页面唯一性: 同时渲染多个互相冲突的 title 或描述元数据会造成不确定结果，应由路由或页面层明确所有者;

```jsx
const metadata = (
  <>
    <title>{`商品 ${product.name}`}</title>
    <meta name="description" content={product.summary} />
  </>
);
```

## 样式表如何参与加载顺序与 Suspense？

- 样式优先级: `<link rel="stylesheet" href="..." precedence="...">` 可参与 React 的样式管理，先发现的 precedence 分组优先级较低;
- 加载协调: 需要样式的内容可以等待样式准备完成再显示，避免未样式化内容闪烁；缺少相应条件时不要假定所有 link 都会挂起;
- 行为退出: onLoad、onError、disabled 等属性可能使样式表退出部分特殊处理，应按具体需求选择，不同时假设两种模式;

```jsx
const stylesheet = <link rel="stylesheet" href="/editor.css" precedence="editor" />;
```

## 如何声明可去重的内联样式？

- Style 内容: children 为 CSS 字符串，配合 href 标识与 precedence 可让 React 提升并去重样式;
- 生命周期限制: 特殊管理模式下渲染后的属性更新会被忽略，组件卸载后样式可能继续留在 DOM，不用于频繁动态修改同一份规则;
- 动态值: 每次变化的尺寸或颜色通常使用 style prop，而非不断修改全局样式资源;

## 异步脚本的提升与去重有哪些限制？

- 脚本条件: 外部脚本的 src 与 async 等条件决定是否进入特殊管理，不能把所有 script 都视作相同资源行为;
- 属性更新: 已执行或已插入的脚本不会因修改 props 自动重新运行，卸载组件也不会撤销已经执行的脚本;
- 加载选项: crossOrigin、integrity、nonce 和 fetchPriority 等需要与资源发布及安全策略匹配，不随意复制配置;

```jsx
const script = <script async src="/analytics.js" />;
```
