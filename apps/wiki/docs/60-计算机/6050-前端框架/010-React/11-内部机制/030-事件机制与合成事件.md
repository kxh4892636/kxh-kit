# 事件系统与委托

## React 事件系统为什么不等于每个 JSX 属性各绑一次原生监听？

- 统一分发: React 通过事件系统把浏览器事件与组件处理器联系起来，可以复用根范围的监听与分发机制;
- 非全称规则: 不同事件的原生传播行为不同，存在专门监听方式，不能说所有事件都只绑定到同一个 root;
- 应用接口: 业务代码依赖 onClick、onChange 等公共行为，不直接操作内部事件注册表;

## target 与 currentTarget 应如何区分？

- Target: 事件实际发生的最内层目标，例如按钮内部的 span;
- CurrentTarget: 当前正在执行处理器所对应的元素，例如绑定处理器的 button;
- 延迟使用: 需要异步处理时先取出必要值，不把事件对象的所有字段当作永久稳定的数据快照;

```jsx
function Button() {
  return (
    <button
      onClick={(event) => {
        const button = event.currentTarget;
        const label = button.textContent;
        setTimeout(() => console.log(label), 100);
      }}
    >
      <span>保存</span>
    </button>
  );
}
```

## 为什么 Portal 的事件路径看起来与 DOM 不一致？

- 两种关系: Portal 改变宿主节点放置位置，却保留 React 父子关系，React 处理器传播仍可到达原组件祖先;
- 排查方式: 同时画出 React 树与 DOM 层级，再判断应该在哪里阻止传播或调整边界;
- 主归属: Portal 的创建与具体集成限制见 React DOM 集成笔记;

## 原生监听与 React 处理器混用时应检查什么？

- 执行阶段: 核对 capture/bubble、监听位置以及是否调用停止传播，不凭书写顺序推断两套处理器顺序;
- 重复注册: 在 Effect 中添加原生监听必须清理，避免每次同步后额外执行一次;
- 基础规则: 冒泡、默认行为与 React 特定例外分别见响应事件和 DOM 通用组件，本篇只解释系统层面的区别;
