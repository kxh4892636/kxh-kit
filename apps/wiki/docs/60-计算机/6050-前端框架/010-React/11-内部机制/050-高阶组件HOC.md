# 高阶组件 HOC

## HOC 如何复用一层组件行为？

- 高阶组件: 接收组件并返回增强后的组件，是普通函数组合模式，适合为多种组件添加一致的展示外壳;
- 非修改式增强: 不修改原组件实现，通过包装组件处理额外职责，再把输入传给原组件;

```jsx
function withLoading(Component) {
  function WithLoading({ loading, ...props }) {
    if (loading) return <p>加载中……</p>;
    return <Component {...props} />;
  }
  WithLoading.displayName = `WithLoading(${
    Component.displayName || Component.name || "Component"
  })`;
  return WithLoading;
}

const UserListWithLoading = withLoading(UserList);
```

## 为什么增强组件应在渲染之外创建？

- 类型稳定: 每次调用 HOC 都会产生新的包装组件类型，在渲染中创建会让 React 反复重建子树并重置状态;
- 模块定义: 在模块顶层调用一次，后续通过普通 props 控制其行为;
- 调试名称: displayName 帮助识别包装层，不改变组件的数据流或生命周期;

## 包装组件需要明确哪些接口边界？

- Props 透传: 只消费增强层需要的属性，其他属性继续传入，避免意外覆盖原组件的同名接口;
- 静态属性: 原组件自定义静态属性不会因为返回包装函数而自动复制，需要时明确公开接口;
- Ref 边界: 是否接收并继续传递 ref 应由组件接口决定，React 19 可把 ref 作为 prop 处理;

## 什么时候应选择 Hook 或普通组合？

- 有状态逻辑: 复用订阅、计时器等行为通常适合自定义 Hook，让组件决定展示结构;
- UI 外壳: 卡片、布局和弹窗等容器可直接用 children 组合，不必引入高阶函数;
- 使用取舍: 包装层过多会隐藏 props 的来源，只有调用方式确实更清晰时使用 HOC;
