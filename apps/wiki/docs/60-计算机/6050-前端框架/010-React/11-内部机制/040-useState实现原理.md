# useState 的概念模型

## 怎样用调用位置理解状态保存？

- 概念槽位: 可以把同一组件的 Hook 看作按稳定顺序访问的槽位，每次渲染从相应位置取回记忆;
- 模型限制: 这个类比只解释调用顺序，不是完整 React 实现，真实系统还处理组件身份、更新优先级、重试和提交;
- 不依赖名称: 改变量名不会产生新状态，但条件跳过一次 Hook 会改变后续槽位的对应关系;

```text
同一组件实例
位置 0 → 姓名状态
位置 1 → 年龄状态
位置 2 → 后续 Hook 的记录
```

## setter 为什么可以在组件返回之后继续使用？

- 关联更新: setter 与所属状态的更新机制关联，调用时提交新的更新请求，而不是修改早先那次函数调用中的局部变量;
- 身份稳定: 同一挂载实例中 setter 引用稳定，完整 API 契约见状态 Hooks;
- 生命周期: 组件重新创建会建立新的状态关联，不把旧 setter 当作全局永久数据入口;

## 直接值与更新函数可以怎样统一理解？

- 计算模型: 直接值表示替换，函数表示从前一待处理值计算下一值，可用一个纯函数描述这种区别;
- 队列应用: 多个更新按顺序参与状态计算，具体混合示例见排队更新 state;

```js
// 只解释更新语义，不实现 React 的调度与生命周期。
function applyUpdate(previous, update) {
  return typeof update === "function" ? update(previous) : update;
}

const next = [5, (value) => value + 1, 42].reduce(applyUpdate, 0);
```

## useState 与 useReducer 的共同点应该怎样理解？

- 共同模型: 二者都保留状态并提交后续更新，useReducer 额外让调用者定义 action 到新状态的转换规则;
- 非实现承诺: 用 reducer 描述 useState 语义有助于理解，不等于业务代码可以依赖二者内部实现永远相同;
- 学习边界: 优先掌握快照、纯更新和组件身份，再用实现模型解释这些行为，不用不完整的伪代码替代实际 Hook;
