# 井字棋与历史状态

## 如何把棋盘交互拆成可管理的数据流？

- 棋格职责: Square 接收当前符号和点击回调，只负责显示与报告点击;
- 棋盘职责: Board 接收九个格子的数组，计算胜者，并在允许落子时生成下一份数组;
- 游戏职责: Game 保存历史和当前步数，向棋盘提供当前快照与追加历史的回调;

## 如何保证一次落子只产生合法的新棋盘？

- 前置检查: 已经有胜者或目标格非空时直接返回，避免覆盖棋子和终局后继续下棋;
- 不可变更新: 复制棋盘后只修改目标格，保留旧数组作为可回看的快照；更新规则见[数组 state](../03-添加交互/070-更新数组state.md);
- 轮次推导: 当前步数为偶数时轮到 X，否则轮到 O，无需再维护一份独立轮次状态;

```js
function nextBoard(squares, index, nextPlayer, hasWinner) {
  if (hasWinner || squares[index] !== null) return null;
  const next = squares.slice();
  next[index] = nextPlayer;
  return next;
}
```

## 如何判断胜者而不增加冗余状态？

- 胜负计算: 检查三行、三列和两条对角线，只要三个位置具有相同非空值就返回该符号;
- 派生信息: 胜者和下一位玩家由当前棋盘与步数计算，不与棋盘分开存储，以免产生互相矛盾的状态;

```js
function calculateWinner(squares) {
  const lines = [
    [0, 1, 2],
    [3, 4, 5],
    [6, 7, 8],
    [0, 3, 6],
    [1, 4, 7],
    [2, 5, 8],
    [0, 4, 8],
    [2, 4, 6],
  ];
  for (const [a, b, c] of lines) {
    if (squares[a] && squares[a] === squares[b] && squares[a] === squares[c]) return squares[a];
  }
  return null;
}
```

## 如何实现时间旅行并从过去继续落子？

- 历史结构: `history` 保存棋盘快照数组，`currentMove` 指向当前查看的快照，跳转时只改变索引;
- 分支截断: 从过去落子时，先保留 `history.slice(0, currentMove + 1)`，再追加新棋盘，丢弃旧未来;
- 列表身份: 历史步骤不会在中间插入重排，步号可作为该场景的 key；不能把这个特例推广为所有列表都用索引;

```jsx
const [history, setHistory] = useState([Array(9).fill(null)]);
const [currentMove, setCurrentMove] = useState(0);
const squares = history[currentMove];

function handlePlay(nextSquares) {
  const nextHistory = [...history.slice(0, currentMove + 1), nextSquares];
  setHistory(nextHistory);
  setCurrentMove(nextHistory.length - 1);
}

function jumpTo(move) {
  setCurrentMove(move);
}
```
