# 安装与工程搭建

## 如何选择 React 应用的起点？

- 在线试用: 在在线沙盒中修改组件即可观察结果，适合先学习组件与状态，不必先配置本地环境;
- 框架起步: 需要路由、数据加载、部署和服务端渲染时，优先评估框架，因为这些能力需要协同设计;
- 选择依据: Web 应用可评估 Next.js App Router、React Router，原生应用可评估 Expo；按目标平台与部署方式选择，不把框架等同于必须运行专用服务器;
- 构建工具起步: 学习基础、现有约束不适合框架或需要自定义架构时，可用 Vite 等工具，但需自行补齐路由与数据策略;

## 如何启动一个最小的本地项目？

- 前置条件: 安装满足所选工具版本要求的 Node.js 和包管理器，再使用模板生成项目;
- 入口关系: HTML 提供挂载节点，入口模块创建 root，根组件组织 UI；JSX 由构建工具转换;

```bash
npm create vite@latest my-app -- --template react-ts
cd my-app
npm install
npm run dev
```

- 工程边界: 上述命令只提供开发和构建基础，生产中的路由、请求缓存、错误处理、代码拆分与渲染方式仍需设计;

## 如何将 React 加入现有页面？

- 渐进接入: 先选一个独立区域，让构建工具处理 JSX，再把该区域交给 React 管理，其余页面可继续使用原技术;
- 节点所有权: React 管理挂载节点内部内容，外部脚本不要同时改写同一区域；根节点 API 见客户端参考;

```jsx
import { createRoot } from "react-dom/client";

function Greeting() {
  return <h1>你好，React</h1>;
}

const container = document.getElementById("react-area");
if (container) createRoot(container).render(<Greeting />);
```

## 如何为从零搭建的应用补齐架构？

- 路由: 明确 URL、布局、导航与页面级加载关系，避免把 URL 当成孤立的组件变量;
- 数据加载: 设计加载时机、缓存和并行请求，避免组件挂载后层层请求形成网络瀑布;
- 渲染方式: 按首屏、SEO、部署与交互需求选择 CSR、SSR 或静态预渲染，再评估是否交给框架;
