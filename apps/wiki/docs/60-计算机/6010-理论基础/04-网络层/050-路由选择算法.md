# 路由选择算法

## 路由选择算法怎么分类?

- 集中式路由算法: 已知全局状态信息的算法; 又称链路状态算法（LS 算法）;
- 分散式路由选择算法: 无全局状态信息，仅知相邻节点信息; 通过相邻节点的信息交换和迭代计算最短路径; 常用距离向量算法（DV 算法）;
- 静态路由选择算法: 链路开销几乎不随时间变化; 路由一旦算好就长期不变;
- 动态路由选择算法: 链路开销随网络状态变化; 需要周期性或按需重算;
- 负载敏感算法: 链路开销反映网络堵塞水平; 拥堵的链路会被认为"贵"，流量随之绕开;
- 负载迟钝算法: 链路开销不明确反映网络堵塞水平; 拥塞与否不体现在开销里;
- 分类的三个维度: 按信息范围分为集中式与分散式，按开销是否随时间变化分为静态与动态，按是否反映拥塞分为负载敏感与负载迟钝;

## 链路状态算法怎样用全局信息算出路径?

- 常用算法: Dijkstra 算法; Prim 算法;
- 全局信息的来源: 每个节点把与自己直连的链路开销告诉全网，于是每个节点都能画出完整的网络图;
- 计算方式: 拿到全图之后用最短路径算法算出到每个目的地的最优下一跳;

## 链路状态算法为什么会震荡?

- 路由震荡（route flapping）: 负载敏感算法由于实时网络堵塞情况的变化，最短路径选择发生来回的切换;
- 机制: 一条链路变拥堵、开销变大，大家改走另一条; 另一条被挤满、开销又变大，大家再改回来，如此反复;
- 根源: 开销直接反映实时负载，而路由决定又会改变负载，两者互相影响;

## 距离向量算法如何只靠邻居算出路径?

- DV 算法: 分散式路由选择算法的常用算法;
- 算法思想: 每个节点只知道到邻居的链路开销和邻居通告的距离，通过反复交换和迭代，逐步得到到所有目的地的最短路径;
- 与 LS 的差别: LS 先收集全局信息再算，DV 边算边交换，从不掌握全局;

## 距离向量算法为什么会产生无穷计数?

- 路由选择环路: 局部区域交换信息的局限性获取到错误的链路开销，导致生成一个环路;
- 后果: 需要大量迭代才会获得准确开销;
- 无穷计数问题: 若开销极大会导致迭代次数极大，又称无穷计数问题;
- 代价: 环路被消除之前，分组会在环里来回转发，时延和资源都被白白消耗;

## LS 和 DV 该怎么选?

- 信息: LS 需要全局信息; DV 只需要相邻节点的信息;
- 报文复杂性: LS 需要 `N+E` 个报文; DV 根据迭代次数而定;
- 收敛速度: LS 为 `n^2`; DV 收敛速度慢且存在无穷级数问题;
- 健壮性: LS 具有一定健壮性; DV 局部节点的错误会扩散到整个网络;
- 取舍: LS 用更多的信息与报文换来更快的收敛和更好的健壮性，DV 用更少的信息换来更低的部署门槛;
