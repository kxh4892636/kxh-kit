# IPv4 与编址

## IPv4 数据报由哪些部分组成?

- 首部字段: 数据报开头的一段控制信息，描述版本、长度、地址、TTL 等; 路由器靠它决定怎么处理这个数据报;
- TTL（Time To Live）: IP 包被路由器丢弃之前 ICMP 包的转发次数，也就是跳数; 每经过一个路由器减一，减到零就丢弃，防止分组永远打转;
- 数据字段: TCP 或 UDP 报文段; 网络层只是把它当作要搬运的载荷;

## 数据报太大装不下一条链路时怎么办?

- MTU（最大传送单元）: 链路能承载的单个数据报长度上限，MTU 限制 IP 数据报的长度;
- 分片（fragmentation）: 数据报超过 MTU 时被拆成多个更小的数据报; 拆分靠标识、标志和偏移三个首部字段支撑;
- 三个字段的分工: 标识标记这些分片属于同一个原始数据报，标志说明后面还有没有分片，偏移说明该分片在原始数据报中的位置;
- 发送方对 IP 数据报进行分片; 接收方接收多个分片进行组装，拼接成初始数据报;
- 发生位置: 分片发生在路由器或发送方; 组装只能发生在接收方;
- 代价: 分片和组装都有额外开销，任一分片丢失都会导致整个原始数据报无法组装;

## IP 地址是怎么写出来的?

- 32 bit 编址: IPv4 地址是一个 32 位的二进制数; 位数固定，地址总量因此有限;
- 点分十进制记法: 每个字节使用 10 进制表示，用 `.` 分隔; 32 位被切成 4 组，每组是一个十进制数;

## 子网和 CIDR 如何描述一个网络?

- 子网（subnet）: 多个主机和一个路由器的网络形成一个子网; 判断依据是它们共享同一段网络地址;
- CIDR（无类别域间路由）: 用 `a.b.c.d/x` 的形式定义子网地址;
- 前缀: `x` 表示地址中子网地址的比特数，称作前缀;
- 剩余比特: 剩余 `32 - x` 比特称作子网掩码，用来标记子网设备;
- 前缀的意义: 前缀越长，子网越小、能容纳的主机越少; 前缀越短，覆盖的地址范围越大;

## 怎么算出网络地址和广播地址?

- 第一步: 将 IP 和子网掩码转换为二进制;
- 第二步: 子网掩码中连续的 `1` 表示其网络地址，后面的为主机地址;
- 第三步: IP 地址与子网掩码进行与运算得到网络地址;
- 第四步: 网络地址不变，主机地址全变成 `1`，即广播地址;
- 为什么要算: 同一子网内的主机网络地址相同，路由器据此判断一个目的地址是否直连;

$$ \text{Network Address} = \text{IP} \wedge \text{Subnet Mask} $$

## 为什么外界看不到子网内部的划分?

- 路由聚合（路由摘要）: CIDR 定义子网地址，如 `223.23.15.0/20`; 该子网可在内部再次划分子网，外界不可知;
- 例子: 在 `/20` 内部划分 8 个子网，每个子网地址为 `223.23.15.0/23`;
- 好处: 外部路由器只需保存一条聚合路由，转发表条目数量大幅减少;

## 广播地址为什么特殊?

- 广播地址: `255.255.255.255`;
- 行为: 主机发送该地址，报文会交付给同一网络中的所有主机;
- 用途: 需要"问一问网里所有人"时使用，比如主机还不知道自己地址、也不知道服务器在哪的时候;

## 一台主机怎样获得自己的 IP 地址?

- 向 ISP 请求: 主机向 ISP 进行请求; ISP 分配一块地址;
- 手动配置 DHCP: 保证分配同一 IP 地址; 适合需要固定地址的设备;
- 自动分配: 自动分配一个临时 IP 地址; 适合普通客户端;
- DHCP（动态主机配置协议）: 允许主机自动获取一个 IP 地址; 免去逐台手工配置的麻烦;

## DHCP 交互要经过哪几个报文?

- 第一步: 客户端发送一个 DHCP 发现报文，使用 UDP 和 IP 协议，使用 IP 广播地址进行广播;
- 第二步: DHCP 服务器收到发现报文后，使用 IP 广播地址发送一个 DHCP 提供报文;
- 第三步: 客户端接受到对应的 DHCP 提供报文，向选中的 DHCP 服务器发送一个 DHCP 请求报文;
- 第四步: DHCP 服务器接受到 DHCP 请求报文，发送一个 DHCP ACK 报文;
- 租期: 客户端接受 DHCP ACK 报文，即可在 IP 租期内使用该 IP; 租期结束前需要续租，否则地址会被收回;
- 必要性: 四个步骤中仅有后三个步骤实际必要;
