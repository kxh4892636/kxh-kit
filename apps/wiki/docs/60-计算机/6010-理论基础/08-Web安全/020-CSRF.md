# CSRF

## CSRF 是怎么借用户的身份动手的?

- 跨站点请求伪造（CSRF）: 一种被动攻击，攻击者设置陷阱代码，诱导用户访问第三方网站;
- 跳板: 第三方网站利用用户已有的权限，作为跳板向被攻击网站发送跨站请求;
- 得手的原因: 被攻击网站把这条请求误认为合法用户的合法请求，于是执行了对应的非法操作;
- 与登录状态的关系: 用户不需要重新输入任何凭据，浏览器自带的身份凭据足以让服务器认下这次请求;

## 怎么防住 CSRF?

- 验证请求来源: 基于 `Referer` 或者同源策略判断请求是否来自本站;
- 使用 token: 服务器基于随机生成的 token 验证用户身份，CSRF 难以获取 token 的执行逻辑，无法携带正确 token，进而被服务器识别并拒绝;
- 验证码: 对敏感操作进行验证码验证，让自动构造的跨站请求无法完成;
- cookie SameSite 字段: 给 cookie 加上 `SameSite`，限制跨站请求携带该 cookie;

## CSRF 和 XSS 差在哪?

| 对比项   | XSS              | CSRF                     |
| -------- | ---------------- | ------------------------ |
| 攻击对象 | 用户             | 应用程序                 |
| 目的     | 获取用户敏感信息 | 伪造用户身份执行非法操作 |
