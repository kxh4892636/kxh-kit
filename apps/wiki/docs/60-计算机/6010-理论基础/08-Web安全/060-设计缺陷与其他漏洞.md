# 设计缺陷与其他漏洞

## 强制浏览漏洞是怎么被猜出来的?

- 强制浏览: 强行访问非公开文件，文件本身没有被正确保护;
- 成因一: 基于 URL 推测出文件名;
- 成因二: 使用软件默认文件名;
- 成因三: 访问资源未进行权限控制;
- 共同点: 前两个成因让攻击者猜得到地址，第三个成因让猜到的地址真的能打开;

## 错误消息为什么会泄露信息?

- 不正确的错误消息: 通过分析 Web 应用返回的错误消息就能得到相关信息;
- 泄露方式: 返回编程语言、数据库、服务器等的默认报错信息，保留大量服务器信息;
- 代价: 攻击者不必盲猜技术栈，报错信息直接告诉他该往哪个方向尝试;

## 开放重定向为什么危险?

- 开放重定向: 网站开放了重定向功能，可以按参数把用户跳到别的地址;
- 风险: 若重定向 URL 为恶意网站，用户就会从可信站点跳到攻击者站点;
- 为什么容易上当: 链接域名本身是可信的，跳转发生在点击之后;

## 密码是怎么被破解的?

| 方式     | 做法                                    |
| -------- | --------------------------------------- |
| 穷举     | 逐个尝试可能的密码组合;                 |
| 字典攻击 | 用常见词、常见口令组成的字典逐个尝试;   |
| 彩虹表   | 预先生成散列值表，拿散列值反查对应明文; |

- 三者的共性: 都依赖大量尝试，因此密码复杂度与尝试次数限制都会抬高破解成本;

## 点击劫持怎么骗到点击?

- 点击劫持（Clickjacking）: 将 UI 透明，覆盖到 Web 页面上;
- 骗术: 诱导用户点击对应 UI，而用户以为点的是页面上看到的那个东西;
- 后果: 点击实际落在被覆盖的界面上，从而执行非法操作;

## 后门程序藏在哪里?

- 后门程序: 在程序里设置隐藏入口;
- 使用方式: 通过非正常操作执行原有功能，绕开正常的认证与权限检查;
- 为什么危险: 入口不体现在正常流程里，常规的功能测试与权限审查看不到它;

## 中间人攻击是怎么插进来的?

- 中间人攻击（MITM）: 攻击者在两个终端之间插入自己的设备或程序;
- 手法: 假扮身份与另一个终端通信，两端都以为自己在和对方直接说话;
- 后果: 从而窃取数据或操纵通信内容;

## 怎么防范中间人攻击?

- 使用 HTTPS、SSL/TLS 协议: 让通信内容被加密并校验完整性;
- 避免使用公共网络: 公共网络更容易被插入中间人;
- 更新安全硬件、软件、防火墙、策略: 及时修补已知的弱点;
- 避免使用未知连接、邮件、程序: 不从不可信来源建立通信或运行代码;
