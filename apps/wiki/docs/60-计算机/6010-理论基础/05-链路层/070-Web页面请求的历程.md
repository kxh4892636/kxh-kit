# Web 页面请求的历程

## 浏览器拿到网址后先做什么?

- 解析 URL: 浏览器解析 URL;
- 格式不正确: 若格式不正确，使用搜索引擎搜索;
- 格式正确: 反之转义 URL，再进入下一步;

## IP 地址是怎么查出来的?

- 生成查询: 客户端生成一个 DNS 查询报文;
- 发送查询: 客户端发送 DNS 查询报文;
- 逐级查询: 依次查询 DNS 根服务器、顶级服务器、权威服务器，获得 URL 对应的 IP 地址;
- 顺序: 查出来的 IP 地址正是下一步建立 TCP 连接时使用的目标地址;

## 网页数据是怎么取回来的?

- 建立连接: 根据目标的 IP 地址生成 TCP 连接，经过 TCP 三次握手过程;
- 读取响应: 主机在 TCP 套接字中解析 HTTP 响应报文，获得相应数据，进行下一步操作;
- 关闭连接: 关闭 TCP 连接，经过 TCP 四次握手过程;
- HTTPS: 若走 HTTPS，还需要 SSL 四次握手过程;

## 浏览器如何把内容渲染成页面?

- 读取响应内容: 加载 HTML;
- 解析 HTML: 构造 DOM;
- 加载外部资源: 加载 js、css、多媒体;
- 应用样式与脚本: 把 css 和 js 应用到 DOM 上;

## 网络层和链路层在其中做了什么?

| 层次   | 环节       | 作用                                                  |
| ------ | ---------- | ----------------------------------------------------- |
| 网络层 | DHCP       | 通过 DHCP 获得 IP 地址                                |
| 网络层 | 数据平面   | 路由器实现数据包的存储转发                            |
| 网络层 | 控制平面   | 路由选择; 自治系统内部使用 OSPF，自治系统之间通过 BGP |
| 链路层 | 差错检测   | 使用 CRC 进行差错检测                                 |
| 链路层 | 信道共享   | 使用多路访问协议解决多路访问问题                      |
| 链路层 | 子网内寻址 | 使用 ARP 获取子网内的 MAC 地址                        |
| 链路层 | 跨子网转发 | 使用 ARP 和网关转发请求至其他子网                     |
| 链路层 | 交换       | 使用交换机和自学习机制实现帧的存储转发                |

- 串起来看: 一次网页请求要经过 URL 解析、DNS 查询、TCP 握手、HTTP 交互、HTTPS 握手和页面渲染，每一步都落在网络层与链路层提供的寻址、转发和差错检测之上;
