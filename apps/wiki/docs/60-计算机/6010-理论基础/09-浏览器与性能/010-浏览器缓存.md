# 浏览器缓存

## 浏览器把缓存放在哪里?

| 位置           | 特点                              |
| -------------- | --------------------------------- |
| Service Worker | 独立线程;                         |
| Memory Cache   | 会话数据;                         |
| Disk Cache     | 持久性数据; 用于强缓存和协商缓存; |
| Push Cache     | 会话数据; HTTP2 内容;             |

- 会话数据与持久性数据的差别: 会话类缓存随会话结束而消失，磁盘缓存能留存下来，因此强缓存和协商缓存都落在 Disk Cache 上;

## 强缓存靠什么决定用不用本地副本?

- 强缓存: 由响应首部直接指定资源的可用期限，在期限内浏览器直接使用本地副本，不与服务器通信;
- 相关首部: `Expires` 与 `Cache-Control`;
- 收益: 省掉一次网络往返，响应速度最快;

## Expires 为什么被废弃?

- Expires: http/1.0 使用的首部，指定资源的过期时间;
- 判断规则: 当前时间早于 `Expires` 就强制使用缓存，反之不使用缓存;
- 缺陷: 服务器时间可能与浏览器时间不一致，两边的时间基准对不上就会误判;
- 结果: http/1.1 废弃了 Expires;

## Cache-Control 有哪些属性?

- Cache-Control: http/1.1 使用的首部，控制缓存行为，返回响应指定时间内可以使用缓存;
- 默认值: 默认属性值为 `private`;
- 优先级: `Cache-Control` 优先级高于 `Expires`;

| 属性       | 含义                                  |
| ---------- | ------------------------------------- |
| `private`  | 对应响应只能被浏览器缓存;             |
| `public`   | 对应响应可以被浏览器和代理服务器缓存; |
| `no-cache` | 跳过缓存，进入协商缓存阶段;           |
| `no-store` | 不使用任何缓存;                       |

```bash
Cache-Control:public, max-age=86400
```

## 强缓存失效后怎么和服务器确认?

- 协商缓存: 强缓存失效后，服务器根据协商缓存相关字段确定浏览器能否使用缓存;
- 相关首部: `Last-Modified`/`If-Modified-Since` 与 `ETag`/`If-None-Match`;
- 代价: 必须发一次请求到服务器，比强缓存慢，但能确认资源是否真的变了;

## Last-Modified 和 If-Modified-Since 怎么配合?

- 第一次请求: 服务器在响应报文添加 `Last-Modified` 首部，记录资源最后修改时间;
- 再次请求: 浏览器把 `If-Modified-Since` 首部设为上次收到的 `Last-Modified` 值;
- 服务器比较: 若请求报文首部时间晚于响应报文首部时间，使用缓存并返回 304; 反之返回 200，即新资源;
- 精度缺陷: 最小更新时间为秒，若文件在 1s 内发生变化，无法识别;

## ETag 和 If-None-Match 怎么配合?

- 第一次请求: 服务器根据资源文件哈希生成 `ETag`，通过响应报文发送给浏览器;
- 再次请求: 浏览器把 `If-None-Match` 首部值设为 `ETag` 值，发送给服务器;
- 服务器比较: 若两者相同，使用缓存并返回 304; 反之返回 200，即新资源;
- 优先级: `If-None-Match` 优先级高于 `If-Modified-Since`;

## 两种缓存分别用在哪、代价是什么?

| 缓存类型 | 适用场景                                          | 特点                                      |
| -------- | ------------------------------------------------- | ----------------------------------------- |
| 强制缓存 | 静态文件; 首部设置强制缓存命令; 不敏感的资源文件; | 使用本地缓存，无须服务器通信，响应速度快; |
| 协商缓存 | 频繁变动的实时数据; 需要验证缓存有效性;           | 需要计算文件哈希，性能耗费大; 精确度高;   |
