# 运输层概述与多路复用

## 运输层和网络层各自把数据送到哪里?

- 网络层: 在不同主机之间提供逻辑通信，负责把数据从一台主机送到另一台主机，不关心数据属于哪个进程;
- 运输层: 在不同主机上的进程之间提供逻辑通信，负责把数据交到正确的应用程序手上;
- 类比: 网络层像把信件送到某栋楼，运输层负责把信件交给楼里具体的那个人; 一台主机同时跑着浏览器、聊天软件和下载工具时，只有运输层能分辨收件人;
- 逻辑通信: 两个进程看起来像有一条直连通道，实际上数据要穿过整个网络核心; 这条通道是抽象出来的，靠下层的真实转发撑起;

## 运输层到底负责什么?

- 运输层: 负责不同主机的应用进程之间的通信服务，因特网上主要是 TCP 与 UDP 两套协议;
- 报文段（segment）: 运输层的分组; 应用层把数据交给运输层，运输层加上首部生成报文段再交给网络层;
- 分工: 网络层提供"主机到主机"的能力，运输层把它细分成"进程到进程"的通道，让同一台主机上的多个应用互不干扰;

## 应用会对运输层提出哪些要求?

- 可靠数据传输: 应用要求数据完整无误地到达对端，不能丢失也不能错乱;
- 吞吐量: 应用对数据传输速率的要求，即单位时间内能传多少数据;
- 定时保证: 应用要求数据在限定时间内到达，而不只是最终到达;
- 安全性: 应用要求通信内容保密且不被篡改，运输层可以通过加密来提供;

## TCP 提供哪些服务?

- 面向连接服务: 传输应用层数据报文之前，TCP 让客户端和服务器端交换运输层控制信息，该过程称作握手; 握手完成之后，一个 TCP 连接在两个套接字中建立;
- 全双工: TCP 连接的两端可以同时发送和接收数据;
- 可靠数据服务: TCP 具有纠错和拥塞控制机制，既保证数据正确到达，也避免把网络压垮;
- 面向字节流: 应用交给 TCP 的字节被当作连续字节流处理，TCP 不保留应用自己的消息边界;
- 单播: 一个 TCP 连接只连接一对进程，无法一次发给多个接收方;

## SSL 在 TCP 之上补了什么?

- SSL（Secure Sockets Layer，安全套接字层）: 加强版的 TCP，提供了进程到进程的安全性服务;
- 动机: TCP 只保证可靠传输，不保证内容不被偷看或篡改，安全性要求只能由上层补上;
- 位置: SSL 建立在 TCP 之上，应用通过 SSL 使用运输层的可靠通道，同时获得安全能力;

## UDP 提供哪些服务?

- 轻量级运输协议: 无握手过程，应用想发就发，省掉了建立连接的一轮往返;
- 不可靠数据服务: 不保证数据一定到达，也不保证到达顺序;
- 面向报文: 应用交给 UDP 的数据按一个个报文处理;
- 发送方式: UDP 可以实现单播、广播和多播，一次把数据送给多个接收方;

| 对比项   | TCP                | UDP              |
| -------- | ------------------ | ---------------- |
| 连接建立 | 面向连接，需要握手 | 无握手过程       |
| 可靠性   | 可靠数据服务       | 不可靠数据服务   |
| 数据边界 | 面向字节流         | 面向报文         |
| 发送方式 | 单播               | 单播、广播、多播 |

## 一台主机如何同时承载多个应用的通信?

- 多路分解（demultiplexing）: 将运输层报文段中的数据交付到正确的套接字;
- 多路复用（multiplexing）: 主机在不同套接字中搜集数据块，并为每个数据块封装首部信息（用于多路分解）从而生成报文段，最后将报文段传输至网络层;
- 一收一发的配合: 发送端做多路复用，把多个应用的字节汇进同一条主机到主机的通道; 接收端做多路分解，再把它们拆回各自的套接字;
- 复用的要求: 源端口号字段是发送数据块的套接字的唯一标识符，目的端口字段是该数据块应该交付的套接字的唯一标识符; 两个字段缺一不可;
- 端口号: 端口号为一个 16 bit（0 - 65535）; 0 - 1023 称为周知端口号，留给固定用途的服务;

## UDP 如何把报文段交到正确的套接字?

- 报文段组成: 源端口号、目标端口号、数据块以及其他信息;
- 流程: 运输层创建一个报文段; 网络层将报文段封装到一个 IP 数据报，并尽力交付给目标主机; 若目标主机接受到报文段，将报文段数据接收到对应套接字;
- 代价: 交付过程没有确认和重传，报文段能否到达只能由应用自己判断;

## TCP 如何把报文段交到正确的套接字?

- 报文段组成: 源 IP + 源端口号、目标 IP + 目标端口号、数据块以及其他信息;
- 与 UDP 的不同: 若具有两个不同 IP 地址或源端口号的报文段到达目标主机，UDP 通过相同的套接字定向到相同的进程，TCP 通过不同的套接字定向到相同的进程;
