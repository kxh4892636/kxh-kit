# TCP 拥塞控制原理

## 流量控制和拥塞控制分别在防谁?

- 流量控制: 作用于滑动窗口大小，防止发送方发送过多数据导致接收方来不及处理; 保护的是接收方;
- 拥塞控制: 作用于滑动窗口分组发送速度，防止网络链路拥塞; 保护的是网络本身;
- 区别: 前者看接收方缓存还剩多少空间，后者看网络链路还能不能承受;

## 网络为什么会拥塞?

| 场景                                         | 结论                                                                             |
| -------------------------------------------- | -------------------------------------------------------------------------------- |
| 2 个发送方和无限大缓存的路由器               | 分组传输速率接近链路容量导致拥塞; 速率小于 `r/2`                                 |
| 2 个发送方和有限大缓存的路由器               | 分组传输速率取决于重传方式; 速率小于 `r/2`                                       |
| 4 个发送方、多台有限大缓存的路由器和多条路径 | 下游路由器的拥塞会导致上游路由器转发到该路由器使用的传输容量浪费; 速率小于 `r/2` |

- 共同结论: 三种场景下的速率都小于 `r/2`; 即使路由器缓存无限大、不会丢包，速率逼近链路容量本身也会导致拥塞;

## 谁来判断网络拥塞?

- 端到端拥塞控制: 端通过观察网络层的行为判断是否拥塞，网络设备不提供任何反馈;
- 网络辅助的拥塞控制: 路由器向发送方提供关于网络拥塞状态的信息;
- 辅助方式一: 路由器向发送方发送一个拥塞分组;
- 辅助方式二: 路由器在分组中添加一个表示拥塞的信息，通过接收方发送的 ACK 告知发送方; 这种方式至少需要一个 RTT;
- 代价: 端到端方式把判断责任推给端系统，不需要网络设备配合; 网络辅助方式反馈更直接，但要求路由器参与;

## TCP 靠什么调整发送速率?

- 控制原理: 通过网络行为调整发送速率，网络顺畅就加速，出现丢包就减速;
- 拥塞窗口: 除接收窗口之外再设置一个额外变量 `cwnd`，称作拥塞窗口;
- 发送量上限: 可发送的未确认字节数同时受接收窗口和拥塞窗口限制，两者取小;

$$min\{rwnd, cwnd\} \ge LastByteSend - LastByteAcked$$

## 怎么判断网络已经丢包?

- 判据一: 报文段超时，等够了时间还没收到确认;
- 判据二: 接受到 3 个冗余 ACK;
- 动机: TCP 通过观察是否丢包确认是否拥塞，丢包是网络拥塞暴露给端系统的信号;
