# TCP 超时与流量控制

## TCP 如何估计一个报文段的往返时间?

- 往返时间（RTT）估计: 通过发送一个样本报文段估计;
- 动态变化: 由于网络环境的变化，估计往返时间也会发生变化，所以不能钉死一个固定值;
- 三个量: `EstimatedRTT` 为估计往返时间，`SampleRTT` 为实际往返时间，`DevRTT` 为偏差;
- 平滑思路: 新的估计值主要保留历史值，只吸收一小部分最新样本，避免被单次抖动带偏;

$$EstimatedRTT = 0.875*EstimatedRTT + 0.125*SampleRTT$$

$$DevRTT = 0.75*DevRTT + 0.25*|SampleRTT-EstimatedRTT|$$

- 两个公式是同一套指数加权平均: 都是"保留大部分旧值、吸收小部分新样本"，所以偏差项也用旧的 `DevRTT` 做平滑; 源材料把偏差公式写成 `0.75*SampleRTT`，与 `EstimatedRTT` 的写法不一致，此处按平滑模式写成 `0.75*DevRTT`;

## 超时间隔该怎么定?

- 初始值: `TimeoutInterval` 推荐初始值为 1 s，一旦超时乘 2;
- 计算时机: 收到第一个报文段并更新 `EstimatedRTT` 后，根据公式计算;
- 公式含义: 在估计往返时间上再加 4 倍偏差，给网络波动留出余量;
- 动机: 只按平均往返时间设超时，稍微抖动就会误判丢包; 加上偏差项后，网络越不稳定等待越久;

$$TimeoutInterval = EstimatedRTT + 4*DevRTT$$

## 接收方来不及处理时如何让发送方减速?

- 缓存溢出: TCP 发送方发送数据太快，TCP 接收方的数据缓存溢出;
- 流量控制: 让 TCP 发送方和接收方应用程序读取速度相匹配;
- 接收窗口: TCP 发送方维护一个接收窗口，根据 `rwnd` 设置滑动窗口大小;
- 全双工: TCP 为全双工，两端都维护一个接收窗口;

## 接收窗口由哪些变量算出来?

| 变量            | 含义                                       |
| --------------- | ------------------------------------------ |
| `RcvBuffer`     | 接收方缓存区大小                           |
| `LastByteRead`  | 接收方应用程序读取的数据流最后一个字节编号 |
| `LastByteRcvd`  | 接收方接受的数据流最后一个字节编号         |
| `rwnd`          | 缓存可用空间                               |
| `LastByteSend`  | 发送方发送的数据流最后一个字节编号         |
| `LastByteAcked` | 发送方确认的数据流最后一个字节编号         |

- 可用空间: 接收窗口等于缓存大小减去还堆在缓存里没被应用读走的字节数;
- 约束: 发送方已发送但未被确认的字节数不能超过 `rwnd`，否则接收方缓存就会溢出;

$$rwnd = RcvBuffer - (LastByteRcvd - LastByteRead)$$

$$rwnd \ge LastByteSend - LastByteAcked$$
