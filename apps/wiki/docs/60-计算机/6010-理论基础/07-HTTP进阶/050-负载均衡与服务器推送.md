# 负载均衡与服务器推送

## 正向代理和反向代理有什么区别?

| 对比项   | 正向代理                             | 反向代理                                   |
| -------- | ------------------------------------ | ------------------------------------------ |
| 代理谁   | 客户端的代理，转发客户端请求至服务器 | 服务器的代理，处理客户端请求并转发至服务器 |
| 隐藏谁   | 隐藏客户端信息                       | 隐藏服务器信息                             |
| 典型用途 | VPN、内网穿透等                      | 负载均衡、缓存、安全控制等                 |

- 记忆方法: 两者都在做"接受请求再转发"，区别在于替谁隐藏身份;

## 负载均衡如何把请求分给多台服务器?

- 负载均衡: 把网络请求分配给多个服务器，提高服务器集群的性能和可靠性;
- 硬件实现: 物理设备，包含交换机、路由器、防火墙等; 拓展性高、性能高，适用于大规模数据;
- 软件实现: 应用程序，基于轮询、最小连接数、IP 哈希等算法分配至不同服务器; 成本低、易于实现和管理，适用于中小规模数据;
- 可靠性: 处理硬件、软件故障、网络错误等异常故障;
- 稳定性: 运行稳定性、性能稳定性;
- 安全性: 防止 DDOS、提供 SSL 加密等;
- 可拓展性: 集群规模变化时仍能继续承担请求分配;

## 服务器推送有哪些方案，代价分别是什么?

- 短轮询: 客户端每隔一定时间发送 HTTP 请求;
- 短轮询优缺点: 实现简单，但需要重复建立连接，具有延迟;
- 长轮询: 客户端发送 HTTP 请求，若对应请求资源变化，服务器立刻返回响应，反之服务器保持请求，直至资源变化或超时; 客户端接受响应后重新发送请求;
- 长轮询的限制: 客户端代码要使用长轮询，服务器要对请求资源未变化的情况进行保持连接处理;
- 长轮询优缺点: 减少了无效请求，但仍然具有延迟;
- SSE: 服务器推送技术，建立持久连接，实现单向通信;
- WebSocket: 全双工、双向通信;

| 方案      | 通信方向                 | 实时性   | 主要代价         |
| --------- | ------------------------ | -------- | ---------------- |
| 短轮询    | 客户端反复发请求         | 有延迟   | 需要重复建立连接 |
| 长轮询    | 服务器挂起请求直到有变化 | 有延迟   | 服务器要保持连接 |
| SSE       | 服务器单向推送           | 实时性高 | 只能单向通信     |
| WebSocket | 双向通信                 | 实时性高 | 性能耗费大       |

```typescript
async function subscribe() {
  let response = await fetch("/subscribe");
  if (response.status == 502) {
    // 服务器超时重新连接
    await subscribe();
  } else if (response.status != 200) {
    // 服务器报错, 一秒后重新连接
    await new Promise((resolve) => setTimeout(resolve, 1000));
    await subscribe();
  } else {
    // 正确处理, 执行若干处理程序
    // ...
    await subscribe();
  }
}
```

## RESTful API 有哪些特征?

- RESTful API: 一种 API 描述规范;
- 统一接口: 通过 URL 和 HTTP 动词统一 API 接口;
- 体系结构: 使用 CS 结构;
- 数据传输: 支持不同数据传输;
- 无状态通信: 服务器不保存请求之间的通讯状态;
