# 编码与范围请求

## 报文太大时有哪些编码手段?

- 内容编码的目的: 压缩报文实体内容的体积;
- `gzip`: GNU zip;
- `compress`: UNIX 标准压缩;
- `deflate`: zlib;
- `identity`: 不进行编码;
- 分块传输编码（Chunked Transfer Coding）: 用于大体积数据传输，把报文实体分隔为若干块（chunk），客户端负责解码、恢复报文实体;

## MIME 与多部分对象集合解决什么问题?

- MIME（Multipurpose Internet Mail Extensions，多用途因特网邮箱拓展）: 标识数据类型;
- 多部分对象集合: 让一份报文容纳多种类型数据;
- `multipart/form-data`: 用于表单文件上传;
- `multipart/byteranges`: 配合 206 状态码，把多段范围的内容放进一份报文;

## 范围请求如何只取资源的一部分?

- 范围请求: 客户端指定请求的发送范围，使用 `Range` 首部字段;
- 服务器能响应: 返回 206 状态码，使用 `multipart/byteranges` 格式;
- 服务器无法响应: 返回 200 状态码和完整实体内容;
- 动机: 只要资源的一部分时，服务器可以只发这一段，客户端不必接收完整实体;

```bash
# 5001 - 10000 字节
Range: bytes=5001-10000
# 5001 之后所有字节
Range: bytes=5001-
# 0 - 3000 字节, 5000 - 7000 字节
Range: bytes=-3000, 5000-7000
```
