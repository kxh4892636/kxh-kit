# 应用层协议与进程通信

## 应用层负责什么?

- 应用层: 负责不同应用程序如何传递报文; 它是最靠近用户程序的一层，直接为应用程序服务;
- 报文（message）: 应用层的分组称为报文; 每一层的分组都有自己的名字，应用层的这一份就叫报文;
- 边界: 应用层只规定报文怎样交换，不规定比特如何在链路上传输; 封装、寻址与传输都交给下面的层;

## 应用层协议规定了哪些内容?

- 应用层协议: 规定不同应用程序之间如何传递报文; 它是两个应用程序之间共同遵守的约定;
- 交换的报文类型: 先确定双方会用到哪些报文，例如请求与响应就是两类不同的报文;
- 不同报文类型的语法: 规定每类报文里各字段的排列格式，也就是报文长什么样;
- 报文字段的语义: 规定每个字段的含义，也就是这些比特各自代表什么信息;
- 收发规则: 规定何时发送报文、如何发送报文、如何响应报文; 只定格式不定动作，双方仍然不知道下一步该做什么;
- 四要素的关系: 报文类型定"有哪些消息"，语法定"消息长什么样"，语义定"字段什么意思"，规则定"什么时候发、怎么回"; 少任何一项，两端都无法真正通信;

## 网络应用程序有哪些体系结构?

- 网络应用程序体系结构: 应用程序在端系统之间如何组织与分工; 它决定谁提供服务、谁发起请求;
- 客户端-服务器结构（CS 结构）: 由客户端与服务器两类角色组成，服务器处理客户端的请求;
- 服务器的固定 IP 地址: 服务器具有固定的 IP 地址; 客户端要能随时找到它，它的地址就不能变;
- 数据中心: 服务器集群; 单台服务器扛不住大量请求时，就用集群对外提供服务;
- P2P 结构: 服务器具有最小甚至没有作用，主机之间直接通信; 服务能力来自参与的主机本身，而不是某台中心服务器;

| 对比项       | 客户端-服务器结构  | P2P 结构             |
| ------------ | ------------------ | -------------------- |
| 服务器的作用 | 处理客户端的请求   | 具有最小甚至没有作用 |
| 通信关系     | 客户端向服务器请求 | 主机之间直接通信     |

## 客户进程和服务器进程如何分工?

- 进程: 运行在主机上的程序实例; 通信真正发生在进程之间，而不是主机之间;
- 客户进程: 发起通信的进程; 它主动联系对方;
- 服务器进程: 等待通信的进程; 它被动等待被联系，收到请求之后才开始工作;
- 分工: 一次通信由客户进程主动发起、服务器进程接收处理; 角色由"谁先发起"决定，而不是由硬件决定;

## 进程通过什么接口使用网络?

- 套接字（socket）: 进程和计算机网络的接口; 进程通过套接字向计算机网络发送和接收报文;
- 为什么需要套接字: 进程只面对一个可读写的接口，不必自己处理封装、寻址与传输;
- 抽象的意义: 应用面对的是接口而不是链路和交换机，网络实现的复杂度被挡在接口之下;

## 报文怎样送到对端的那个进程?

- 进程寻址: 把报文送到对端进程需要两项信息; 缺一项，报文要么到不了主机，要么到不了进程;
- 目标主机的地址: IP 地址; 它把报文定位到某台主机;
- 目标主机上对应进程的标识符: 端口号; 它把报文定位到主机里运行的那个进程;
- 两段信息的分工: IP 地址负责找到哪台机器，端口号负责找到机器里的哪个进程; 两者合起来才能唯一确定通信的终点;
