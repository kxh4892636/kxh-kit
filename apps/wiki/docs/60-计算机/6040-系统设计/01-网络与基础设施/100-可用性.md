# 可用性

## 如何量化系统可用性？

- 可用性: 在指定观察窗口内，系统能执行约定功能的程度；采用时间口径时是正常时长占总时长的比例;
- 口径: 必须定义哪些功能、地区、请求和计划维护计入统计，数字脱离口径就无法比较;

$$
A=\frac{T_{up}}{T_{up}+T_{down}},\qquad D=(1-A)T
$$

| 可用性      | 365 天内允许停机约 |
| ----------- | ------------------ |
| 90%         | 36.5 天            |
| 99%         | 3.65 天            |
| 99.9%       | 8.76 小时          |
| 99.99%      | 52.56 分钟         |
| 99.999%     | 5.256 分钟         |
| 99.9999%    | 31.536 秒          |
| 99.99999%   | 3.154 秒           |
| 99.999999%  | 0.315 秒           |
| 99.9999999% | 0.032 秒           |

- 换算: 月、周的允许停机也用同一公式，明确使用 30 天、自然月或 7 天，避免混用原文表格口径;

## 多个组件如何影响整体可用性？

| 结构                 | 在独立故障假设下的公式     | 两组件各 99.9% |
| -------------------- | -------------------------- | -------------- |
| 串联，全部可用才成功 | `A = A1 × A2`              | 99.8001%       |
| 并联，任一个可用即可 | `A = 1 − (1 − A1)(1 − A2)` | 99.9999%       |

- 条件: 并联公式假设足够剩余容量、有效切换且无共同故障，不能忽略共享电源、数据库或控制平面;
- 可靠性: 衡量持续正确运行而不发生故障的能力；频繁故障但快速恢复的系统仍可能有较高时间可用性;
- 高可用与容错: 高可用力求缩短中断，容错力求在约定故障下继续服务，后者往往需要更强冗余与协调;
