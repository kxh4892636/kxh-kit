# 系统设计面试

系统设计面试评估什么？标准流程包含哪些步骤？每一步要产出什么？

## 面试特点

- 评估能力: 考察对抽象问题产出技术方案的能力，而非唯一正确答案;
- 双向沟通: 候选人与面试官共同推进，不同经验水平策略不同;

## 需求澄清

- 功能需求: 用户要求的基本功能，如功能列表、边界情况;
- 非功能需求: 质量约束，如延迟、可用性、可维护性、安全性;
- 扩展需求: 可选增强，如指标、监控、分析;

## 估算与约束

- 明确规模: 请求量、存储量、带宽、读写比、QPS;
- 用途: 为后续容量和架构选择提供依据;

## 数据模型设计

- 定义实体与关系: 表数量、关系、主键外键;
- 选型: 判断 SQL 还是 NoSQL 更合适;

## API 设计

- 简单接口: 参数、函数、类型、实体，不写实现;
- 建议: 保持简单，扩展需求阶段再补充;

## 高层组件设计

- 识别组件: 负载均衡、API 网关、缓存、数据库等;
- 讨论: 单体或微服务、数据库类型、从客户端视角走通流程;

## 详细设计

- 深入主要组件: 数据分区、负载分布、缓存、流量尖峰;
- 展示经验: 给出多种方案和取舍，避免过于武断;

## 识别并解决瓶颈

- 关键问题: 副本是否足够、单点故障、是否需要分片、缓存可用性;
- 准备: 阅读目标公司工程博客，了解其技术栈与关注点;
