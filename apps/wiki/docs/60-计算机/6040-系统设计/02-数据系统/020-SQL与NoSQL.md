# SQL 与 NoSQL

SQL 与 NoSQL 的差异来自哪里? 文档、键值、图、时序和宽列数据库各适合什么访问模式? 应如何根据需求而非标签选型? N+1 查询与物化视图解决什么问题?

## SQL 数据库

- 关系数据库: 用预定义关系、行列、主外键和约束表达结构化数据;
- 优势: 数据模型准确、查询灵活、复杂连接成熟、事务与一致性保障强;
- 代价: 模式演进需迁移，复杂连接和维护成本较高，跨节点水平扩展更难;
- 物化视图: 预先计算并持久化查询结果，以存储与刷新成本换取复杂查询、子集读取和复制速度;
- N+1 查询: 先执行 1 次主查询，再为 N 条结果分别查询关联数据; 用连接、批量查询或 DataLoader 合并访问;

## NoSQL 模型

| 模型   | 数据形态         | 强项                       | 局限与场景                       |
| ------ | ---------------- | -------------------------- | -------------------------------- |
| 文档   | 自包含文档       | 模式灵活、通用、易水平扩展 | 跨文档关系弱; 内容与目录         |
| 键值   | `key → value`    | 极快点查、吞吐和扩展       | 复杂过滤与扫描弱; 会话、缓存     |
| 图     | 节点、边、属性   | 多跳关系查询直观           | 模型与查询语言专门; 社交、风控   |
| 时序   | 带时间戳记录     | 高速写入、时间范围聚合     | 通用事务弱; 指标、IoT、行情      |
| 宽列   | 列族             | PB 级扩展、实时大数据      | 建模与写路径复杂; 分析、稀疏属性 |
| 多模型 | 多种模型统一后端 | 复杂项目灵活               | 产品复杂、成熟度与可预测性较低   |

## 对比与选型

| 维度   | SQL                    | NoSQL                          |
| ------ | ---------------------- | ------------------------------ |
| 模式   | 固定、迁移演进         | 动态或按记录变化               |
| 查询   | 标准 SQL、连接强       | 产品与模型专用                 |
| 扩展   | 常先垂直，分布式更复杂 | 常内建水平分布                 |
| 一致性 | 常以 ACID 为默认       | 常允许更松的一致性，但并非必然 |

- 选择 SQL: 结构稳定、关系复杂、需要约束、事务或灵活索引查询;
- 选择 NoSQL: 模式快速变化、关系弱、访问路径明确、数据量与 IOPS 极高;
- 反例: “SQL 不能扩展”与“NoSQL 没有事务”都不是普遍真理; 判断具体数据库、部署模式与一致性配置;
- 核心问题: 数据怎样被写入、按什么键读取、是否跨实体原子更新、容忍多旧的数据、如何扩容与恢复;
