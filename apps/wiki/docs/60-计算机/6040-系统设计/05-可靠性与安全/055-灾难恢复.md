# 灾难恢复

## 灾难恢复要解决什么问题？

- 灾难恢复: 在自然灾害、网络攻击或重大业务中断后，恢复基础设施、数据和服务能力的过程;
- 故障域: 恢复副本或备份应避免与生产同时受灾，否则“有备份”仍可能无法恢复;
- 业务目标: 缩短中断、减少损失并恢复用户使用，而不只是把某台机器启动起来;

## RTO 与 RPO 分别限定什么损失？

- RTO: 恢复时间目标，从服务中断到恢复可用允许的最长时间;
- RPO: 恢复点目标，最多允许丢失多长时间内产生的数据，关注可恢复数据离故障有多远;
- 示例: 10:00 故障，9:55 的数据可恢复，10:20 恢复服务，则实际数据缺口为 5 分钟，恢复耗时为 20 分钟;
- 区别: 同步复制可能缩小数据缺口，但如果切换很慢，仍可能无法满足恢复时间目标;

## 不同灾备形态怎样权衡成本与恢复速度？

| 形态     | 预先准备                 | 主要代价                         |
| -------- | ------------------------ | -------------------------------- |
| 异地备份 | 可恢复的数据副本         | 恢复时还需重建运行环境           |
| 冷站点   | 异地基础设施             | 软件、数据和流量接入可能仍需恢复 |
| 热站点   | 接近就绪的计算与更新数据 | 费用及持续同步治理更高           |

- 选择依据: 用 RTO、RPO 约束方案，不能只按备份频率判断整体恢复能力;
- 恢复演练: 验证备份可读、环境可启动、依赖可访问及流量可切换，记录真实耗时;
- 与高可用关系: 日常副本切换关注局部故障，灾备还要覆盖更大故障域和历史数据恢复;
