# 服务水平目标

## SLI、SLO 和 SLA 怎样把服务承诺变成可测目标？

| 名称 | 含义                       | 例子                      |
| ---- | -------------------------- | ------------------------- |
| SLI  | 实际测量的服务水平指标     | 过去 30 天成功请求比例    |
| SLO  | 希望指标满足的目标         | 30 天内成功比例至少 99.9% |
| SLA  | 服务提供方与用户之间的协议 | 明确承诺、口径与违约处理  |

- 测量口径: 说明观察窗口、数据源、成功定义和排除条件，目标才可验证;
- 目标用途: 帮助团队发现用户体验下降并安排故障响应，内部 SLO 不一定属于对外合同;
- 指标方向: 成功率通常越高越好，延迟通常越低越好，不能笼统要求所有 SLI 都“大于 SLO”;
- 责任协作: 业务、运维和合同相关人员共同把承诺转化为可执行指标;

## 如何用指标判断一次服务目标是否达成？

- 示例: 观察窗内有效请求 100 万次，其中成功 999500 次，成功率为 99.95%，满足至少 99.9% 的目标;
- 延迟目标: 若要求 99% 的请求小于 300 ms，就应统计满足阈值的比例或相应分位数，平均 100 ms 不能证明达标;
- 细分: 全局达标可能掩盖某个地区或用户群持续失败，应按服务承诺覆盖范围检查;
- 处置: 指标接近或超过目标边界时，根据用户影响安排修复与容量工作;
- 相关概念: 灾后多快恢复、允许丢失多少数据分别由 [灾难恢复](055-灾难恢复.md)中的 RTO 与 RPO 表达;
