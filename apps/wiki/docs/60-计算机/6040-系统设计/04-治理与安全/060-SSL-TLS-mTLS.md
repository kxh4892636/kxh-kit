# SSL、TLS 与 mTLS

SSL、TLS 与 HTTPS 是什么关系? TLS 如何同时提供加密、身份认证和完整性? 证书解决了什么信任问题? mTLS 为什么适合服务间零信任通信?

## 从 SSL 到 TLS

- SSL（Secure Sockets Layer）: 早期互联网安全协议，现已废弃，但“SSL 证书”名称仍被沿用;
- TLS（Transport Layer Security）: SSL 的后继协议，为互联网通信提供隐私与数据安全;
- HTTPS: HTTP 运行在 TLS 保护的连接之上;
- 加密: 窃听者无法理解传输内容;
- 身份认证: 证书帮助确认通信方是其声称的主体;
- 完整性: 检测数据是否在传输中被伪造或篡改;

## 混合密码体系

- 对称加密: 加解密共享密钥，速度快，适合大量会话数据;
- 非对称密码: 公钥与私钥成对，便于建立身份和共享秘密，但计算成本较高;
- 混合方式: 握手阶段用非对称机制认证并协商会话密钥，数据阶段用对称密钥高效加密;
- 会话随机数: 让每次连接派生不同密钥，降低密钥复用风险;

## 证书与信任

- 问题: 拿到一个公钥不代表它确实属于目标域名，中间人可替换公钥;
- CA: 可信证书颁发机构用自己的私钥签署服务器公钥与身份信息;
- 验证: 客户端用预置信任根验证证书链、签名、域名、有效期与用途;
- 服务器证书: 同时绑定身份与公钥，使客户端能认证服务并安全建立会话;
- 自签名证书: 没有公共 CA 信任链，必须通过组织自己的信任分发机制预置信任;

## mTLS

- 单向 TLS: 通常只有服务器向客户端出示证书;
- mTLS（Mutual TLS）: 客户端和服务器都出示并验证证书，实现双向机器身份认证;
- 适用: 微服务、零信任网络、合作方 API 与无法交互登录的 IoT 设备;
- 收益: 连接双方都被密码学身份约束，降低仅依赖网络位置的信任;
- 代价: 客户端证书签发、轮换、吊销、密钥保护和故障排查复杂;
- 边界: mTLS 证明工作负载身份，不自动完成终端用户授权; 仍需把身份映射到最小权限策略;
