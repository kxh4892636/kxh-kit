# CQRS

CQRS 如何分离命令和查询？常与事件溯源如何结合？有什么优缺点？

## 定义

- CQRS: 把系统动作分为 Command 和 Query;
- Command: 指令，改变状态，不返回值，只返回成功/失败;
- Query: 请求信息，不改变状态、无副作用;

## 与事件溯源结合

- 写模型: 事件存储作为官方信息来源;
- 读模型: 物化视图，通常是高度反规范化的视图;

## 优点

- 读写负载独立扩展;
- 更易扩展、优化和演进;
- 贴近业务逻辑、松耦合;
- 查询避免复杂 Join;
- 系统行为边界清晰;

## 缺点

- 应用设计更复杂;
- 消息失败或重复;
- 最终一致是挑战;
- 维护成本增加;

## 用例

- 读性能需与写性能分别调优;
- 系统多版本演进、业务规则频繁变化;
- 与其他系统集成，结合事件溯源;
- 需要更细粒度写安全;
