# API 网关

为什么需要 API 网关？它有哪些功能和优缺点？BFF 模式何时使用？

## 定义

- API Gateway: 位于客户端和后端服务之间的 API 管理工具，是系统单一入口;
- 职责: 封装内部架构，为不同客户端提供定制 API，并处理认证、监控、负载均衡、缓存、限流、日志等;

## 为什么需要

- 微服务 API 粒度细，客户端常需调用多个服务;
- 网关提供统一入口和附加管理能力;

## 功能

- 认证与授权;
- 服务发现;
- 反向代理;
- 缓存;
- 安全;
- 重试与熔断;
- 负载均衡;
- 日志与追踪;
- API 组合;
- 限流与节流;
- 版本管理;
- 路由;
- IP 白名单/黑名单;

## 优点

- 封装内部 API 结构;
- 集中视图;
- 简化客户端代码;
- 集中监控、分析、追踪;

## 缺点

- 可能单点故障;
- 影响性能;
- 扩展不当成瓶颈;
- 配置挑战;

## BFF

- BFF: 为特定前端应用创建独立后端服务;
- 作用: 从多个服务取数、格式化后返回给前端;
- 适用: 共享后端维护成本高、需要为特定客户端优化、需为多接口定制;
- GraphQL 很适合 BFF;
