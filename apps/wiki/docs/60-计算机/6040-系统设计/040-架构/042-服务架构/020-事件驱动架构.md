# 事件驱动架构

EDA 是什么？事件是什么？有哪些组件、模式和挑战？

## 定义

- EDA: 使用事件在系统内通信，通常借助消息代理异步发布/消费;
- 目标: 实现服务间松耦合;

## 事件

- 事件: 表示系统状态变化的数据点;
- 事件不指定后续如何处理，只通知状态变化;

## 组件

- Event producers: 发布事件到路由器;
- Event routers: 过滤并推送事件给消费者;
- Event consumers: 消费事件并反映系统变化;

## 常见模式

- Sagas;
- Publish-Subscribe;
- Event Sourcing;
- CQRS;

## 优点

- 生产者和消费者解耦;
- 高可扩展、分布式;
- 易添加新消费者;
- 提升敏捷性;

## 挑战

- 投递保证;
- 错误处理困难;
- 系统整体复杂;
- 精确一次、顺序处理难;

## 用例

- 指标与元数据;
- 服务器与安全日志;
- 异构系统集成;
- Fanout 与并行处理;
