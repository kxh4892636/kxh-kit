# 限流

为什么需要限流？常见限流算法有哪些？分布式限流有什么问题？

## 定义

- 限流: 防止操作频率超过定义上限;
- 作用: 保护共享资源、维持可用性、防止 API 滥用;

## 为什么需要

- 避免 DoS 资源饥饿;
- 控制自动扩缩容成本;
- 防御常见攻击;
- 控制海量数据处理流量;

## 算法

- Leaky Bucket 漏桶: 队列 FIFO 固定速率处理，队列满则丢弃;
- Token Bucket 令牌桶: 请求需取令牌，无令牌拒绝，定期补充;
- Fixed Window 固定窗口: n 秒窗口计数，超过阈值丢弃;
- Sliding Log 滑动日志: 记录每个请求时间戳，计算窗口内总数;
- Sliding Window 滑动窗口: 混合固定窗口低成本与滑动日志边界改进;

## 分布式限流问题

- 不一致: 多节点各自计数会超过全局限制; 解决: 粘性会话或集中存储（Redis），但增加延迟和竞争;
- 竞态: get-then-set 可被并发绕过; 解决: 分布式锁（瓶颈）或 set-then-get 原子操作;
