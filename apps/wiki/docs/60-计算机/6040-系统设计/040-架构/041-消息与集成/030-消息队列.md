# 消息队列

消息队列如何工作？有哪些特性？背压是什么？

## 定义

- 消息队列: 服务间异步通信，生产者发消息，消费者取消息;
- 每条消息通常被一个消费者处理一次;

## 工作方式

- 生产者发布任务到队列并通知状态;
- 消费者从队列取任务、处理、标记完成;

## 优点

- 可扩展: 峰值时多实例并发入队;
- 解耦: 组件间不直接依赖;
- 性能: 异步交互，生产者无需等待处理;
- 可靠性: 消息持久化，减少离线错误;

## 特性

- Push/Pull 投递: 拉取轮询或推送通知;
- FIFO: 先进先出;
- 延迟投递: 定时或延迟队列;
- At-least-once: 冗余副本与重发保证至少一次;
- Exactly-once: FIFO 队列过滤重复，保证只一次;
- Dead-letter queue: 存放无法处理的消息，便于检查;
- Ordering: 尽力有序;
- Poison-pill: 特殊消息让消费者结束工作;
- Security: 认证与加密;
- Task queue: 后台执行计算密集任务;

## 背压

- 问题: 队列过大超过内存，导致缓存未命中、磁盘读、性能下降;
- 解决: 限制队列大小，满时返回 503，客户端稍后重试（可指数退避）;
