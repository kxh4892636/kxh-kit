# REST、GraphQL、gRPC

API 是什么？REST、GraphQL、gRPC 各自概念、优缺点和适用场景？如何对比？

## API 定义

- API: 应用编程接口，是信息提供方与消费方之间的契约;
- 作用: 让客户端表达需求并获得系统响应;

## REST

- 资源为基本单元;
- 约束: 统一接口、客户端-服务器、无状态、可缓存、分层系统、按需代码（可选）;
- HTTP 动词: GET、HEAD、POST、PUT、DELETE、PATCH;
- 状态码: 1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误;
- 优点: 简单、灵活、可移植、缓存好、前后端解耦;
- 缺点: 过度获取、多次往返;
- 适用: 通用 API 默认标准;

## GraphQL

- 查询为基本单元;
- Schema: 描述客户端可用功能;
- Query/Mutation: 查询或修改;
- Resolver: 生成响应的函数;
- 优点: 消除过度获取、强 Schema、代码生成、载荷优化;
- 缺点: 复杂度移到服务端、缓存难、版本化模糊、N+1 问题;
- 适用: 降低带宽、快速原型、图状数据模型;

## gRPC

- 基于 RPC 的高性能框架;
- Protocol Buffers: 语言中立、向前向后兼容的序列化;
- Service definition: 用 IDL 定义服务和消息;
- 优点: 轻量高效、高性能、内置代码生成、双向流;
- 缺点: 较新、浏览器支持有限、学习曲线陡、不可读;
- 适用: 实时双向通信、微服务间通信、低延迟高吞吐、多语言环境;

## 对比

| 类型    | 耦合 | 聊天式 | 性能 | 复杂度 | 缓存   | 代码生成 | 可发现性 | 版本化 |
| ------- | ---- | ------ | ---- | ------ | ------ | -------- | -------- | ------ |
| REST    | 低   | 高     | 好   | 中     | 好     | 差       | 好       | 易     |
| GraphQL | 中   | 低     | 好   | 高     | 自定义 | 好       | 好       | 自定义 |
| gRPC    | 高   | 中     | 极好 | 低     | 自定义 | 极好     | 差       | 难     |

- 结论: 没有银弹，按领域和需求选择;
