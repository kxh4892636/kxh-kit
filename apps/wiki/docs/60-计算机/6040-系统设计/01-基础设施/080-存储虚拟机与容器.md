# 存储、虚拟机与容器

RAID 各级如何权衡容量、性能与容错? 文件、块和对象存储适合什么数据? 虚拟机与容器隔离在哪一层? HDFS 与 NAS 的定位有何不同?

## RAID 与卷

- RAID: 把多块磁盘组织为一个阵列，在性能、容量和冗余间取舍; RAID 不是备份;
- RAID 0: 条带化，容量利用率与性能高，无容错;
- RAID 1: 镜像，至少两盘，约 50% 容量利用率，可承受单盘故障;
- RAID 5: 条带加分布式单校验，至少三盘，可承受单盘故障;
- RAID 6: 双校验，至少四盘，可承受两盘故障;
- RAID 10: 镜像组再条带化，至少四盘，性能与冗余好但约 50% 容量利用率;
- 卷: 提供给系统使用的一段逻辑存储; 一个磁盘可有多个卷，一个卷也可跨越多盘;

## 存储抽象

| 类型     | 抽象             | 优势                      | 典型用途             |
| -------- | ---------------- | ------------------------- | -------------------- |
| 文件存储 | 目录与路径       | 直观、共享方便            | 用户文件、共享目录   |
| 块存储   | 固定大小块与标识 | 低延迟、随机访问          | 数据库磁盘、虚拟机卷 |
| 对象存储 | 对象、元数据与键 | 海量扩展、耐久、HTTP 访问 | 图片、视频、备份     |

- NAS: 连接网络的集中式文件存储，适合局域网授权用户共享;
- HDFS: 面向廉价集群的大文件分布式文件系统，以分块复制换取容错与高吞吐，不以低延迟随机访问见长;
- 选择原则: 先看访问模式、对象大小、一致性、耐久性、吞吐与成本，不能只按产品名选型;

## 虚拟机

- 虚拟机（VM）: 由 Hypervisor 虚拟化硬件，每个 VM 拥有客体操作系统、虚拟硬件、应用及依赖;
- Hypervisor: 把 CPU、内存、网络与存储形成资源池，并隔离、创建和调度 VM;
- 收益: 强隔离、运行不同操作系统、提高物理服务器利用率、适合测试与生产环境隔离;
- 代价: 每个 VM 携带完整 OS，启动慢、内存和存储开销较大;

## 容器

- 容器: 打包应用及依赖，在操作系统层隔离进程、文件系统与网络;
- 共享内核: 容器不携带独立客体 OS，因此比 VM 轻量、启动快、密度高;
- 收益: 环境一致、工作负载可移植、开发与运维职责清晰、资源利用率高;
- 边界: 共享内核意味着隔离模型不同于 VM; 安全敏感、多内核或异构 OS 场景仍可能需要 VM;
- 组合: 云平台常在 VM 上运行容器，以 VM 提供租户边界、容器提供应用交付与调度效率;
