# 网络分层与 IP

网络为什么要分层? OSI 七层各负责什么? IPv4 与 IPv6 如何标识设备? 分组交换会引入哪些时延? NAT、CIDR 和 DHCP 分别解决什么问题?

## 分组网络

- 协议: 通信实体交换报文的格式、顺序，以及收发事件触发的动作;
- 分组交换: 将长报文切成分组，经交换机存储转发; 链路利用率高，但排队使延迟不可预测，缓冲区满会丢包;
- 电路交换: 通信前预留端到端资源; 延迟稳定，但空闲时仍占用频段或时隙;
- 端到端时延: 处理时延、排队时延、传输时延与传播时延之和;
- 传输时延: `分组长度 / 链路速率`; 传播时延取决于距离与介质传播速度;
- 路径吞吐量: 各段链路吞吐量的最小值，即瓶颈链路;

## OSI 七层

| 层         | 核心职责                     | 典型对象        |
| ---------- | ---------------------------- | --------------- |
| 应用层     | 为应用提供网络协议与数据语义 | HTTP、SMTP、DNS |
| 表示层     | 格式转换、压缩、加密与解密   | 编码、序列化    |
| 会话层     | 建立、维持、同步与关闭会话   | 检查点、恢复    |
| 运输层     | 进程间端到端传输、分段与重组 | TCP、UDP        |
| 网络层     | 跨网络寻址与路由             | IP 包、路由器   |
| 数据链路层 | 同一链路内传输与成帧         | 帧、MAC、交换机 |
| 物理层     | 将比特转换为物理信号         | 线缆、无线电    |

- 分层价值: 用稳定接口隔离复杂性，统一术语，便于互操作、排障与逐层安全分析;
- 封装: 数据向下穿越协议栈时，每层添加本层控制信息; 接收端反向解封装;
- 现实模型: TCP/IP 常把 OSI 的表示层、会话层职责并入应用层; OSI 是分析模型，不是互联网的直接实现;

## IP 地址

- IP 地址: 网络层标识符，使分组能定位并到达设备;
- IPv4: 32 bit 点分十进制地址，约 43 亿个地址; 例如 `102.22.192.181`;
- IPv6: 128 bit 十六进制地址，地址空间约 `3.4×10^38`; 中间路由器不分片，迁移期可经 IPv4 隧道承载;
- 公网地址: ISP 分配、可在公网路由的地址;
- 私网地址: 局域网内部使用、不能直接在公网路由的地址;
- 静态地址: 固定配置，适合服务托管、远程访问等稳定入口;
- 动态地址: DHCP 按租期分配，可复用地址，是终端常见配置;

## 子网、DHCP 与 NAT

- CIDR: 用 `a.b.c.d/x` 表示网络前缀长度; IP 与子网掩码按位与得到网络地址;
- 路由聚合: 对外只发布较短公共前缀，在内部继续划分子网，缩小路由表;
- DHCP: 客户端通过 Discover、Offer、Request、ACK 获取地址、租期与网络配置;
- NAT: 用公网 IP 与端口映射多个私网连接，缓解 IPv4 地址不足并隐藏内部地址;
- NAT 代价: 增加状态与延迟，破坏端到端可达和追踪，部分协议需要额外穿透机制;
