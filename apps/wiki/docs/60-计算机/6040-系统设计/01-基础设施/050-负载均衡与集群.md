# 负载均衡与集群

## 什么是负载均衡? L4、L7 与软件、硬件、DNS 方案如何选择?

- 负载均衡: 把入口流量分配给多个健康资源，提升容量、利用率、可用性与扩缩弹性;
- 分层部署: 客户端入口、应用服务、缓存和数据库前都可按各自协议与瓶颈独立均衡;
- L4 负载均衡: 按 IP、端口等运输层信息转发; 解析少、吞吐高，无法按请求内容路由;
- L7 负载均衡: 理解 HTTP 等应用协议，可按主机、路径、参数或内容路由，并提供 TLS 终止、缓存、压缩与追踪;
- 软件方案: 灵活、成本低、易自动化，但需自行配置运维;
- 硬件方案: 高吞吐、封闭一体化，但昂贵且升级弹性较低;
- DNS 均衡: 返回多个地址，简单且覆盖全球; 缓存与缺乏实时健康检查使故障收敛较慢;

## 负载均衡路由算法有哪些, 健康检查与粘性会话如何影响?

| 算法            | 决策依据              | 适用场景                    |
| --------------- | --------------------- | --------------------------- |
| 轮询 / 加权轮询 | 依次分配 / 按容量权重 | 请求成本相近 / 机器规格不同 |
| 最少连接        | 当前连接数            | 长连接或请求耗时不同        |
| 最短响应        | 响应时间与连接数      | 节点性能动态变化            |
| 最低带宽        | 当前流量              | 大文件或媒体传输            |
| 哈希            | 客户端 IP、URL 等键   | 会话亲和或缓存局部性        |

- 健康检查: 及时移除宕机或退化节点，恢复后再加入;
- 粘性会话: 同一用户固定到节点，简化本地会话，但削弱均衡、故障转移与无状态扩展;
- 冗余入口: 负载均衡器本身采用 active-passive 或多活集群，避免新单点;

## 什么是集群? 高可用、负载均衡、HPC 集群与运维代价是什么?

- 集群: 多台互联计算机协同完成共同目标，对外尽量表现为一个系统;
- 高可用集群: active-passive 用备用节点接管故障; active-active 同时服务并分摊负载;
- 负载均衡集群: 多节点并行处理独立请求，提高吞吐;
- 高性能计算集群: 拆分可并行任务，聚合多机计算与内存能力;
- 集群与负载均衡: 集群节点知道彼此并共同协调; 负载均衡后的独立服务器只响应分配给自己的请求;
- 运维代价: 节点软件与配置一致性、跨节点通信、共享存储冲突、分布式数据同步、资源监控与日志聚合;
