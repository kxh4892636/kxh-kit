# 代理与 API 网关

正向代理与反向代理保护的是哪一端? 反向代理、负载均衡器和 API 网关的边界是什么? BFF 何时比通用网关更合适?

## 代理

- 代理: 位于通信双方之间，转发、过滤、记录或转换请求与响应;
- 正向代理: 代表客户端访问外部服务，使服务端不直接看到具体客户端; 常用于访问控制、匿名、VPN 与地域绕行;
- 反向代理: 代表一个或多个源站接收客户端请求，使客户端不直接连接源站; 常用于安全隔离、缓存、TLS 终止与负载均衡;
- 判断方法: 正向代理隐藏客户端，反向代理隐藏服务器;
- 反向代理与负载均衡: 反向代理即使只有一个源站也有价值; 负载均衡以多个同类后端间分流为核心，反向代理可兼任负载均衡，反向不必成立;
- 风险: 单实例代理会成为瓶颈和单点，需冗余、健康检查、容量规划与配置审计;

## API 网关

- API 网关: 客户端与后端服务集合之间的单一逻辑入口，封装内部拓扑并提供面向客户端的 API;
- 典型能力: 身份认证与授权、路由、服务发现、反向代理、聚合、缓存、限流、重试、熔断、负载均衡、版本、日志与追踪;
- 核心价值: 微服务 API 往往细粒度，网关把多次内部调用组合为适合客户端的契约，降低客户端复杂度;
- 代价: 新增网络跳数与配置复杂度; 若不能水平扩展，会成为性能瓶颈和故障中心;

## BFF

- BFF（Backend For Frontend）: 为 Web、移动端或其他界面分别提供专用后端;
- 职责: 调用所需服务，裁剪、聚合并格式化为该客户端最需要的数据形状;
- 适用: 不同客户端需求差异大，通用后端被大量条件分支污染，或客户端承担过多聚合逻辑;
- 不适用: 客户端需求一致、团队无法承担多个入口的演进与运维成本;
- 与网关关系: 网关处理跨客户端公共策略; BFF 处理特定界面的体验与数据组合，两者可串联但避免重复职责;
