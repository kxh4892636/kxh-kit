# DNS

DNS 如何把域名解析为 IP? 递归解析器、根、TLD 与权威服务器各做什么? 递归、迭代和非递归查询有何区别? TTL 怎样影响一致性与性能?

## 心智模型

- DNS（Domain Name System）: 分层、分布式的命名系统，把人类可读域名映射为 IP 或其他资源记录;
- 递归解析器: 客户端第一站; 优先返回缓存，否则代表客户端继续查找;
- 根服务器: 根据顶级域后缀把解析器指向对应 TLD 服务器; 13 个根服务器标识通过全球 Anycast 部署为大量实例;
- TLD 服务器: 管理 `.com`、`.org`、国家代码等顶级域，返回目标域权威服务器;
- 权威服务器: 保存域的最终记录; 找不到域时返回 `NXDOMAIN`;

## 查询流程

1. 客户端向本地递归解析器查询域名;
2. 缓存未命中时，解析器依次询问根、TLD、权威服务器;
3. 权威服务器返回记录，解析器缓存结果并把 IP 返回客户端;
4. 客户端使用该 IP 与目标服务建立连接;

- 递归查询: 被询问的服务器必须返回最终记录或错误;
- 迭代查询: 服务器返回当前所知的最佳答案或下一台应询问的服务器;
- 非递归查询: 服务器已有缓存或本身权威，可立即回答;

## 资源记录

| 类型     | 含义                                  |
| -------- | ------------------------------------- |
| A / AAAA | 域名对应 IPv4 / IPv6 地址             |
| CNAME    | 域名别名指向另一个域名，不直接给出 IP |
| MX       | 邮件服务器                            |
| NS / SOA | 权威服务器 / 域管理元数据             |
| TXT      | 任意文本，常用于邮件安全与所有权验证  |
| SRV      | 服务位置与端口                        |
| PTR      | 反向解析，把 IP 映射回域名            |

- 记录结构: 可概括为 `(Name, Value, Type, TTL)`;
- DNS zone: 域名空间中交给某实体管理的区域，是权威数据与管理权限边界;
- 子域: 主域下的逻辑分区，例如 `blog.example.com`;

## 缓存与系统设计

- TTL: 记录可缓存的秒数; 较长 TTL 降低延迟与权威服务器压力，但变更传播更慢;
- 负载分配: 同一主机名可返回多个 IP，但 DNS 通常不了解服务器实时健康，不能替代健康感知的负载均衡器;
- 反向 DNS: 查询 PTR 记录从 IP 找回域名，常用于邮件与审计;
- 传输: 常规小查询通常使用 UDP 53 端口; 响应过大、区域传送等情况可使用 TCP;
- 风险: DNS 是关键入口，需考虑缓存投毒、DDoS、权威服务冗余和错误 TTL;
