# 缓存与 CDN

缓存为什么快? 三种写入策略怎样权衡一致性与延迟? 淘汰策略如何选择? CDN 如何把缓存扩展到全球边缘? 哪些场景不应使用缓存?

## 缓存模型

- 缓存: 在较快介质中暂存完整数据集的热点子集，用容量换取读取速度;
- 局部性: 最近或频繁访问的数据更可能再次访问，是缓存命中收益的基础;
- 命中: 请求由缓存直接满足; 未命中时回源读取，并按策略填充缓存;
- 命中率: 由缓存满足的请求占全部可缓存请求的比例;
- 边界: 缓存通常易失、非完整且可重建，不能当作唯一永久数据源;

## 写入与失效

| 策略          | 写入路径               | 收益                       | 风险               |
| ------------- | ---------------------- | -------------------------- | ------------------ |
| write-through | 同步写缓存与主存储     | 读快、两者一致             | 写延迟较高         |
| write-around  | 只写主存储             | 写路径简单，避免冷数据污染 | 写后读易未命中     |
| write-back    | 先写缓存，异步刷主存储 | 写延迟低、吞吐高           | 缓存故障可能丢数据 |

- 失效: 主数据改变后删除或替换旧缓存; 难点是并发读写、失败重试与传播窗口;
- 分布式缓存: 汇聚多台机器内存，突破单机容量并支持水平扩展;
- 全局缓存: 应用节点共享同一逻辑缓存，未命中由缓存层或应用回源;

## 淘汰策略

- FIFO / LIFO: 按进入先后淘汰，不考虑访问价值;
- LRU / MRU: 淘汰最久未使用 / 最近使用的数据;
- LFU: 淘汰访问频率最低的数据，适合稳定热点;
- Random: 随机淘汰，元数据成本低;
- 选择原则: 用真实访问分布、对象大小和过期语义验证，不把 LRU 当作默认真理;

## 何时使用

- 适合: 数据库查询、API 响应、DNS 记录、静态资源等重复读取且回源昂贵的内容;
- 不适合: 缓存访问与回源同样慢、请求随机度高、数据频繁变化且不能容忍旧值;
- 主要收益: 降低延迟、数据库负载和网络成本，提高读取吞吐;

## CDN

- CDN: 分布在多个地理位置的边缘服务器，从靠近用户的位置交付静态或可缓存内容;
- 工作流: 用户经 DNS 等机制被引导到合适边缘; 命中直接返回，未命中从源站拉取并缓存;
- Push CDN: 发布方主动上传变更; 流量可控但占用更多存储，适合内容少且更新不频繁;
- Pull CDN: 边缘按请求回源填充; 运维简单、只保留近期热点，适合高流量站点;
- 节点选择: 地理最近不等于网络路径最近，CDN 需结合实时测量与网络拓扑;
- 代价: 服务费用、区域覆盖不足、供应商或 IP 被封锁、缓存失效与源站保护复杂度;
