# 缓存

缓存为什么快？命中与未命中如何区分？失效策略和淘汰策略有哪些？何时不该用缓存？

## 定义

- 缓存: 通过暂存数据子集提升读取性能，用容量换速度;
- 依据: 时间局部性——最近请求的数据很可能再次被请求;
- 特性: 通常易失、暂存，不能当持久存储;

## 缓存与内存层级

- 层级: L1、L2、L3 等，越靠近 CPU 越快;
- 块与标签: 每次按块读写，块带 tag 标记存储位置;
- 查找: 从 L1 逐级查找，未找到则写入缓存供下次使用;

## 命中与未命中

- Cache hit: 数据从缓存成功读出;
- Hot cache: 从 L1 以最快速度读出;
- Warm cache: 从 L2/L3 读出，速度中等;
- Cold cache: 从更低层级读出，仍算命中但最慢;
- Cache miss: 缓存中找不到，需从下层存储读取并写入缓存;

## 失效策略

- Write-through: 同时写缓存和数据库; 读快、一致性好，写延迟高;
- Write-around: 直接写数据库绕过缓存; 减少写延迟但增加缓存未命中;
- Write-back: 只写缓存，异步同步到数据库; 写吞吐高，但缓存崩溃有数据丢失风险;

## 淘汰策略

- FIFO: 先进先出;
- LIFO: 后进先出;
- LRU: 最久未使用先淘汰;
- MRU: 最近使用先淘汰;
- LFU: 使用频率最低先淘汰;
- Random Replacement: 随机淘汰;

## 分布式与全局缓存

- 分布式缓存: 聚合多台机器 RAM 成单一内存数据存储，突破单机内存限制;
- 全局缓存: 所有应用节点共享一个缓存，未命中由缓存负责回源;

## 使用场景与禁用场景

- 适用: 数据库缓存、CDN、DNS 缓存、API 缓存;
- 不适用: 访问缓存与访问源一样慢、请求重复率低、数据频繁变更;
- 原则: 缓存是瞬态层，不应作为永久数据存储;
