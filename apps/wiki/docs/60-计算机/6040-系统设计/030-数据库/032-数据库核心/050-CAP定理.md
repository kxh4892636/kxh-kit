# CAP 定理

CAP 是哪三个特性？为什么分布式系统通常在 C 和 A 之间取舍？CA/CP/AP 示例？

## 定义

- CAP 定理: 分布式系统只能在 Consistency、Availability、Partition tolerance 中满足两个;

## 三个特性

- Consistency 一致性: 所有客户端在同一时刻看到相同数据;
- Availability 可用性: 任何请求都能得到响应，即使部分节点宕机;
- Partition tolerance 分区容错: 网络分区或消息丢失时系统继续工作;

## 取舍

- 网络分区无法避免，分布式系统必须选择 P;
- 因此实际是在 C 与 A 之间取舍;

## 类型

- CA: 一致 + 可用，无分区容错; 示例 PostgreSQL、MariaDB;
- CP: 一致 + 分区容错，牺牲可用; 分区时关闭不一致节点; 示例 MongoDB、HBase;
- AP: 可用 + 分区容错，牺牲一致; 分区时可能返回旧数据，恢复后同步; 示例 Cassandra、CouchDB;
