# 客户端调用

客户端怎么创建和复用？一次 RPC 调用怎么写？有哪些寻址方式？错误处理应该先看什么？为什么不能每个请求都 `NewClient`？

## 一句话理解

- Client: 调用方持有的“远程服务代理”; 内部管理服务发现缓存、连接池、治理配置和后台 goroutine;
- 核心原则: 一个目标 service 创建一个 Client，进程级复用;
- 类比: Client 像一张长期有效的“会员卡”，不是每次进店都重新办卡;

## 创建与复用

- service name: `NewClient` 的第一个参数; 是服务发现和观测的核心维度;
- 禁止模式: 每个请求调用一次 `NewClient`; 会放大连接、CPU、配置拉取和 goroutine;
- 构造期配置: 连接超时、RPC 超时、重试、熔断等通常在 `NewClient` 时一次性配置;

```go
func newUserClient() (userservice.Client, error) {
	cli, err := userservice.NewClient(
		"user",
		client.WithHostPorts("127.0.0.1:8888"),
		client.WithConnectTimeout(200*time.Millisecond),
		client.WithRPCTimeout(time.Second),
	)
	if err != nil {
		return nil, fmt.Errorf("create user client: %w", err)
	}
	return cli, nil
}
```

## 发起调用

- 每个调用方法都会接收 `context.Context` 和请求对象，返回响应与 error;
- 调用方 context 的 deadline 会向下游传递;
- Call Option: 通过方法尾参传入，只对单次调用生效，优先级高于 Client Option;
- `callopt.WithRPCTimeout`: 单次覆盖超时; 只用于特例，不要到处散落;
- `callopt.WithHostPort`: 单次直连指定实例; 适合诊断，不适合生产流量;

```go
func getUser(ctx context.Context, cli userservice.Client, id int64) (*api.GetUserResponse, error) {
	resp, err := cli.GetUser(ctx, &api.GetUserRequest{ID: id})
	if err != nil {
		return nil, fmt.Errorf("get user %d: %w", id, err)
	}
	return resp, nil
}
```

## 寻址方式

- 本地开发: `client.WithHostPorts` 直接指定实例地址;
- 动态环境: `client.WithResolver` 获取实例列表，由 LoadBalancer 选择;
- URL/DNS: `callopt.WithURL` 或 HTTP Resolver; 解析结果仍需连接目标;
- 预热: 首次调用延迟敏感时用 warming up 初始化 Resolver 和连接池;

## 错误处理

- 先处理 `err`，再读取 response; 不能假设失败时 response 可用;
- 用 `errors.Is`、`kerrors.IsTimeoutError` 或业务异常转换判断错误类别;
- 不因“读请求”就盲目重试; 必须确认接口幂等并留有总时间预算;

## 常见误区

- 误区: 把 Client 存在全局变量里反复创建; 正确做法是依赖注入单例;
- 误区: 忽略 `ctx`; 线上调用必须设置 deadline，避免无限等待;
- 误区: 每个方法都传不同 callopt; 稳定配置应放 Client Option，特例才用 callopt;
