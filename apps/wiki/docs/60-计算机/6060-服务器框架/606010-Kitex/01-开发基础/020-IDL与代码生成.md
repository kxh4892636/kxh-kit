# IDL 与代码生成

Thrift IDL是什么？工具链是什么？演进流程如何运作？Protobuf 分支是什么？

## Thrift IDL

- field id: 线上的字段身份; 发布后不可改变或复用;
- `optional`: 未设置时不序列化; 兼容新增字段的常用选择;
- `required`: 演进约束强; 新增 required 字段会破坏旧调用方;
- 默认值: 接收方可能构造默认值; 需要区分“未传”和零值时使用 `optional`;
- service: 方法集合; 参数与返回值均进入生成契约;

```thrift
namespace go api

struct GetUserRequest {
  1: required i64 id
}

struct GetUserResponse {
  1: optional string name
}

service UserService {
  GetUserResponse GetUser(1: GetUserRequest req)
}
```

## 工具链

```powershell
go install github.com/cloudwego/kitex/tool/cmd/kitex@latest
go install github.com/cloudwego/thriftgo@latest
kitex --version
kitex -module example.com/user -service user api.thrift
```

- `-module`: 生成代码使用的 Go module path; 应与 `go.mod` 一致;
- `-service`: 生成 Server scaffold; 不指定时只生成类型与桩代码;
- `-use`: 复用另一个 module 已生成的 `kitex_gen`, 避免重复类型;
- `-I`: 增加被 `include` 的 IDL 搜索目录;
- 生成结果: `kitex_gen` 是派生产物; 业务逻辑放在 Handler，不直接修改生成文件;

## 演进流程

- 第一步: 先以兼容方式修改 IDL;
- 第二步: 重新运行相同的 `kitex` 命令;
- 第三步: 实现新增 Handler 方法;
- 第四步: 先发布兼容新旧契约的 Server，再发布使用新字段的 Client;

## Protobuf 分支

- Kitex 仅支持 proto3;
- `option go_package` 必须指向稳定导入路径;
- proto unary 默认使用 Kitex Protobuf; IDL 包含 stream method 时切换到 gRPC;
- 没有 stream method 但要求 gRPC 时，Client 显式配置 `client.WithTransportProtocol(transport.GRPC)`;
