# 服务端开发

服务端开发要写什么？Handler 和普通函数有什么区别？`context.Context` 为什么重要？如何启动一个 Kitex Server？服务生命周期有哪些阶段？退出时如何优雅收尾？

## 一句话理解

- 服务端开发: 实现 IDL 生成的 service 接口（Handler），再组装 Server 启动监听;
- Handler: 接收 RPC 请求、执行业务、返回响应; 是“业务和框架的分界线”;
- 类比: Handler 是餐厅后厨的“出菜口”; 框架负责接单和传菜，你只负责把菜做好;

## Handler 编写

- `context.Context`: 携带 deadline、取消信号、元信息和链路信息; 要向下传递，不要存到长期对象;
- response: 每个请求构造独立对象; 不要复用可能被并发修改的响应;
- error: 业务异常用 `kerrors.NewBizStatusError` 表达; 系统异常保留 error chain 交给框架层;
- nil 检查: 生成代码通常保证 req 非空，但防御性检查成本低、收益高;

```go
type UserServiceImpl struct{}

func (s *UserServiceImpl) GetUser(
	ctx context.Context,
	req *api.GetUserRequest,
) (*api.GetUserResponse, error) {
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	if req == nil || req.ID <= 0 {
		return nil, kerrors.NewBizStatusError(400, "invalid user id")
	}
	return &api.GetUserResponse{Name: "Ada"}, nil
}
```

## 启动 Server

- `WithServiceAddr`: 设置监听地址; 不设置时默认监听 `:8888`;
- `WithServerBasicInfo`: 声明服务身份; 注册中心、日志和链路标签都依赖它;
- `WithRegistry`: 接入服务注册; 实例启动时注册、退出时注销;
- `WithMiddleware`: 插入认证、日志、限流等横切逻辑; 注册顺序影响调用顺序;
- `WithExitWaitTime`: 限制优雅退出等待时间; 要和编排平台终止窗口协调;

```go
func main() {
	svr := userservice.NewServer(
		new(UserServiceImpl),
		server.WithServiceAddr(&net.TCPAddr{Port: 8888}),
		server.WithServerBasicInfo(&rpcinfo.EndpointBasicInfo{ServiceName: "user"}),
	)
	if err := svr.Run(); err != nil {
		log.Fatalf("run user service: %v", err)
	}
}
```

## 生命周期

- 启动前: 先初始化依赖（配置、数据库、缓存、exporter），再对外提供健康状态;
- 运行中: Handler 尊重 ctx; 不要异步持有会被池化复用的 RPCInfo;
- 退出时: 先摘除流量，再等待在途请求，最后释放连接和 exporter;
- panic: Kitex 能恢复 Handler panic 并转为错误返回; 但 fatal runtime error（如并发写 map）无法恢复;

## 常见误区

- 误区: 在 Handler 里启动 goroutine 并脱离 ctx; 请求结束后可能泄漏;
- 误区: 把 `WithReadWriteTimeout` 当业务超时; 它只约束传输读写;
- 误区: 启动时依赖尚未就绪就注册服务; 应先 readiness 再接收流量;
