# 服务端开发

## Handler

- Handler: 实现生成的 service interface; 只承载业务编排，不处理底层传输;
- `context.Context`: 传递 deadline、取消、元信息与链路信息; 不保存到长期对象;
- response: 明确构造返回值; 不复用仍可能被并发修改的对象;
- error: 业务异常与 RPC/系统异常分开表达;

```go
type UserServiceImpl struct{}

func (s *UserServiceImpl) GetUser(
	ctx context.Context,
	req *api.GetUserRequest,
) (*api.GetUserResponse, error) {
	if err := ctx.Err(); err != nil {
		return nil, err
	}
	if req == nil || req.ID <= 0 {
		return nil, kerrors.NewBizStatusError(400, "invalid user id")
	}
	return &api.GetUserResponse{Name: "Ada"}, nil
}
```

## 启动

```go
func main() {
	svr := userservice.NewServer(
		new(UserServiceImpl),
		server.WithServiceAddr(&net.TCPAddr{Port: 8888}),
		server.WithServerBasicInfo(&rpcinfo.EndpointBasicInfo{ServiceName: "user"}),
	)
	if err := svr.Run(); err != nil {
		log.Fatalf("run user service: %v", err)
	}
}
```

- `WithServiceAddr`: 设置监听地址; 默认端口为 8888;
- `WithServerBasicInfo`: 声明服务身份; 注册、日志与链路标签依赖它;
- `WithRegistry`: 接入 Registry; 实例启动和退出时注册/注销;
- `WithMiddleware`: 插入认证、日志或治理逻辑; 顺序影响行为;
- `WithExitWaitTime`: 限制优雅退出等待时间; 必须与编排平台退出窗口协调;

## 生命周期

- 启动前: 完成依赖初始化，再对外暴露健康状态;
- 运行中: Handler 尊重 ctx; 不异步持有会被池化复用的 RPCInfo;
- 退出时: 先摘除流量，再等待在途请求，最后释放连接与 exporter;
- panic: Kitex 可恢复 Handler panic 并返回错误; fatal runtime error 仍会使进程退出;
