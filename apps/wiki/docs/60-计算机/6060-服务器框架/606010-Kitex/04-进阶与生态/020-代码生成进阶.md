# 代码生成进阶

## 生成层次

- thriftgo/protoc: 从 IDL 生成类型与基础编解码;
- kitex tool: 叠加 Client、Server、service interface 与 scaffold;
- template: 控制生成项目结构或扩展 service 代码;
- plugin: validator、tag、裁切与性能 Codec 等附加产物;

## 常见能力

- Thrift Validator: 根据 IDL annotation 生成字段校验;
- Protoc Validator: 为 proto message 生成 Go 校验函数;
- Custom Struct Tags: 为生成字段增加 JSON、数据库等 tag;
- Struct Reference: 复用公共 struct，减少重复生成;
- IDL Trimmer: 从根 service 裁掉不可达定义，缩小交付契约;
- Enum Check: 检查 Thrift enum 值溢出目标语言范围;
- Thrift Reflection: 生成运行时 type descriptor，供 FieldMask 与动态能力使用;

## Codec 生成

- Fastpb: Protobuf 高性能生成式 Codec;
- Prutal: 尽量减少生成代码的 Protobuf 序列化方案;
- SkipDecoder: 跳过不需要的 decoder 产物，缩小代码体积;
- Frugal tag: 允许 JIT Thrift Codec; 不支持环境需要生成 Codec fallback;
- Apache Codec: 新项目使用 FastCodec; 迁移旧项目先确认是否直接依赖 apache/thrift;

## 模板

- custom scaffold: 控制 `-service` 生成的工程骨架;
- service template extension: 在稳定扩展点增加生成内容;
- 原则: 生成代码可重复产生，业务代码不得依赖手工修改;
- 升级: 工具、thriftgo/protoc 与 Kitex runtime 保持兼容版本;

## 已弃用能力

- Combine Service: 已弃用; 不用于新项目;
- 多 Service: 使用当前 Multi Service 与 multi-handler 生成方式;
- 旧 netpollmux: 不再维护; 不通过模板继续扩散;

## 变更门禁

- 第一步: 固定并记录生成命令;
- 第二步: 在干净目录重新生成;
- 第三步: 检查生成 diff 是否只来自 IDL/工具升级;
- 第四步: 编译 Server 与 Client;
- 第五步: 做新旧版本互通测试;
