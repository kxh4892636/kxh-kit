# 框架扩展

扩展面是什么？Middleware是什么？Suite是什么？深层扩展原则有哪些注意点？

## 扩展面

| 扩展               | 接入位置       | 典型用途               |
| ------------------ | -------------- | ---------------------- |
| Middleware         | RPC 调用链     | 认证、日志、治理       |
| Suite              | Option 组合    | 组织级默认配置         |
| Registry/Resolver  | 控制面         | 服务注册发现           |
| LoadBalancer       | 选址           | 标签、亲和或自定义权重 |
| Tracer/Monitoring  | 生命周期事件   | 指标与链路             |
| Codec              | payload 编解码 | 私有协议或跨框架互通   |
| Transport/Pipeline | 网络传输       | 特殊连接与帧处理       |
| MetaHandler        | header 读写    | 元信息透传             |
| Diagnosis          | 诊断事件       | 运行态问题定位         |

## Middleware

```go
func latency(next endpoint.Endpoint) endpoint.Endpoint {
	return func(ctx context.Context, req, resp any) error {
		start := time.Now()
		err := next(ctx, req, resp)
		log.Printf("latency=%s err=%v", time.Since(start), err)
		return err
	}
}
```

- Client middleware: 包围一次远程调用;
- Server middleware: 包围 Handler;
- Instance middleware: 负载均衡后运行，可获得具体实例;
- Builder: 根据 context/RPCInfo 动态构造 middleware;
- 顺序: 外层先进入、后退出; 错误转换和统计依赖注册次序;

## Suite

- Suite: 返回一组 Client/Server Option，集中封装注册发现、治理与观测;
- 适用: 多服务共享组织级规范;
- 风险: 隐藏默认值与顺序; 必须提供覆盖方式与版本策略;

## 深层扩展原则

- 优先 Option/Middleware/Suite; 只有协议或网络边界不满足时扩展底层;
- Codec 与 Transport 必须做兼容、模糊输入、并发和故障注入测试;
- Registry/Resolver 必须处理更新、删除、抖动、空结果与关闭;
- Monitoring/Diagnosis 回调不得阻塞请求主路径;
- 查看已实现扩展再自研，避免重复维护生态适配器;
