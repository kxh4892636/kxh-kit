# 特殊架构能力

## Kitex 的特殊能力有哪些? 什么时候使用?

- 高级能力: 解决“运行时才知道接口”“一个进程服务多个接口”“嵌入已有生命周期”“透明代理”等特殊问题;
- 静态业务: 优先用生成代码，不要为“炫技”引入泛化调用;
- 选择原则: 先证明普通方案不够，再引入高级能力;

| 能力            | 解决的问题                        | 使用边界                     |
| --------------- | --------------------------------- | ---------------------------- |
| Generic Call    | 运行时才知道 IDL/service/method   | 网关、测试平台、流量代理     |
| Metainfo        | 跨 RPC 透传键值元信息             | 控制大小、敏感性与传播范围   |
| Multi Service   | 一个 Server 承载多个 service      | 路由必须携带 service name    |
| Server SDK Mode | 将 Kitex 嵌入已有 Server 生命周期 | 自行管理 listener 与启动退出 |
| gRPC Proxy      | 透明代理 gRPC 流量                | 不等于业务网关               |
| xDS             | 从控制面获取路由与治理配置        | 需要兼容的 xDS 环境          |
