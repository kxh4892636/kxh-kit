# 特殊需求的查阅入口

## 普通 RPC 服务需要启用这些能力吗？

- 开发主线: 使用生成的 Client、Server 和 Handler 即可，先完成 [用户服务实战](../03-完整实战/010-从零构建用户RPC服务.md);
- 引入时机: 出现下表中的明确需求时再查对应官方用法；这些能力不是上线前的必修课;

## 遇到特殊需求应该查哪个功能？

| 实际需求 | 官方功能 | 使用前确认 |
| --- | --- | --- |
| 运行时才知道 IDL 或方法 | Generic Call | 是否真的无法使用生成桩 |
| 向下游传递业务元信息 | Metainfo | 数据大小、敏感性与传播范围 |
| 同端口提供多个接口集合 | Multi Service | 路由能携带 service name |
| 接入已有监听与启停流程 | Server SDK / Invoker | 谁负责 listener 和退出 |
| 转发 gRPC 请求 | gRPC Proxy | 是否需要透明转发 |
| 接入已有控制面 | xDS | 团队是否已经提供配套平台 |

- 完成条件: 先让最小请求在目标环境成功，再补超时、错误与资源释放测试;

## 需要核对具体用法时查哪里？

- 官方入口: [高级特性](https://github.com/cloudwego/cloudwego.github.io/blob/38744fc12990bb900765d0235c171a80c9fa2af9/content/zh/docs/kitex/Tutorials/advanced-feature/_index.md);
