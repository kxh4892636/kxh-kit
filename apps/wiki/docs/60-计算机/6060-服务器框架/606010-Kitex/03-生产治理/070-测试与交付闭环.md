# 测试与交付闭环

Kitex 服务怎么分层测试？Service 单测怎么写？Client Mock 用来做什么？RPC 集成测试怎么起真实 Server？交付门禁包含哪些检查？

## 一句话理解

- 测试分层: 从业务规则到真实 RPC，逐层扩大验证范围、减少外部依赖;
- 单元测试验证“逻辑对不对”，集成测试验证“合在一起能不能跑”;
- 交付门禁: 用命令保证生成代码一致、测试通过、可构建、可运行;

## 测试分层

| 层级             | 验证对象                       | 外部依赖                   |
| ---------------- | ------------------------------ | -------------------------- |
| Service 单元测试 | 业务规则、错误传播             | fake Repository            |
| Handler 单元测试 | IDL 映射、业务错误码           | fake Service 或 Repository |
| RPC 集成测试     | 生成代码、Codec、Server/Client | 本机临时端口               |
| 依赖集成测试     | SQL、缓存、Registry 适配       | 临时真实依赖               |
| 运行态验收       | 配置、健康、观测、退出         | 接近生产环境               |

## Service 单元测试

- 表驱动: 覆盖合法输入、非法 ID、not found、Repository error 与 ctx cancel;
- 断言: 使用 `errors.Is` 验证错误类别，不匹配完整错误文本;
- 并发: 共享 request/response、缓存或异步逻辑执行 `go test -race ./...`;

```go
type repositoryStub struct {
	user user.User
	err  error
}

func (s repositoryStub) FindByID(context.Context, int64) (user.User, error) {
	return s.user, s.err
}

func TestServiceGet(t *testing.T) {
	svc, err := user.NewService(repositoryStub{user: user.User{ID: 1, Name: "Ada"}})
	if err != nil {
		t.Fatalf("NewService() error = %v", err)
	}
	got, err := svc.Get(context.Background(), 1)
	if err != nil {
		t.Fatalf("Get() error = %v", err)
	}
	if got.Name != "Ada" {
		t.Fatalf("Get().Name = %q, want Ada", got.Name)
	}
}
```

## Client Mock

- Client interface: 生成代码中的稳定测试边界;
- mock 用途: 上游 Service 测试，不启动真实 RPC;
- 限制: Mock 不验证 Codec、transport、middleware、timeout 与 tracing;

```powershell
go install go.uber.org/mock/mockgen@latest
mockgen -source kitex_gen/api/user/client.go `
  -destination internal/mocks/user_client.go -package mocks
```

## RPC 集成测试

- readiness: 首次调用使用短暂重试或显式同步，避免 Server goroutine 尚未开始 accept;
- timeout: 每次测试调用使用有 deadline 的 context;
- 断言: 同时验证成功响应、BizStatusError、timeout 与 middleware 行为;
- 隔离: 使用 `127.0.0.1:0` 获取临时端口，禁止依赖固定 8888;

```go
listener, err := net.Listen("tcp", "127.0.0.1:0")
if err != nil {
	t.Fatalf("listen: %v", err)
}
svr := hello.NewServer(new(HelloImpl), server.WithListener(listener))
go func() {
	if runErr := svr.Run(); runErr != nil {
		t.Logf("server stopped: %v", runErr)
	}
}()
t.Cleanup(func() {
	if stopErr := svr.Stop(); stopErr != nil {
		t.Errorf("stop server: %v", stopErr)
	}
})

cli, err := hello.NewClient("hello", client.WithHostPorts(listener.Addr().String()))
if err != nil {
	t.Fatalf("new client: %v", err)
}
```

## 交付门禁

- 生成一致性: 重新生成后 Git diff 为空;
- 契约兼容: 新 Client 对旧 Server、旧 Client 对新 Server 的关键调用通过;
- 故障路径: 无实例、数据库失败、timeout、限流、熔断和退出均有证据;
- 可观测: 指标、trace、结构化错误日志包含 service 与 method，不泄露敏感数据;
- 运行态: readiness 摘流后无新请求，终止窗口内完成在途请求并释放资源;

```powershell
go generate ./...
go test ./...
go test -race ./...
go vet ./...
```

## 常见误区

- 误区: 只写 Handler 单测，不写 Service 单测; 业务规则应在无框架依赖下快速验证;
- 误区: Mock Client 当集成测试; 它不验证协议和框架行为;
- 误区: 固定端口跑测试; 并发或 CI 上容易冲突，应使用临时端口;
