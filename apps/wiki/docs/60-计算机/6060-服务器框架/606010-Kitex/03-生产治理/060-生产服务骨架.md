# 后端服务的架构设计

## 分层的目标是什么, 有哪些分层?

- 分层目标: 让“RPC 边界、业务规则、存储访问”各自独立，方便测试和替换;
- Handler 是适配层: 把 IDL 类型翻译成领域调用;
- Service 是业务核心: 只依赖领域接口，不依赖 Kitex;
- Repository 是存储边界: 隔离数据库、缓存等实现细节;

## 后端服务的目录设计

- Handler: 校验 RPC 输入、调用 Service、转换响应与业务异常;
- Service: 业务规则和事务边界; 不依赖 Kitex transport;
- Repository: 隔离数据库/缓存 SDK; 由 Service 依赖接口;
- main: 加载配置、创建依赖、启动 Server、关闭资源;

```text
user-service/
├─ cmd/user-server/main.go       # 组装与进程生命周期
├─ idl/user.thrift               # RPC 契约
├─ kitex_gen/                    # 生成代码
└─ internal/user/
   ├─ handler.go                 # IDL 类型 ↔ 领域调用
   ├─ service.go                 # 业务规则
   ├─ repository.go              # 存储接口
   └─ repository_sql.go          # 数据库实现
```

## 最小代码示例

- repository 隔离数据库/缓存等实现细节, 独立实现;
- 使用 repository 依赖注入 service, service 依赖注入 handler;
- Service 和 Repository 不导入 `kitex_gen`, 只有 handler 导入 `kitex_gen` 生成的代码;

```go
package user

import (
	"context"
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("user not found")

// User 是领域模型: 定义业务规则和数据结构;
type User struct {
	ID   int64
	Name string
}

type Repository interface {
	FindByID(ctx context.Context, id int64) (User, error)
}

// Service 是业务核心: 只依赖领域接口，不依赖 Kitex;
type Service struct {
	repo Repository
}

func NewService(repo Repository) (*Service, error) {
	if repo == nil {
		return nil, errors.New("repository is required")
	}
	return &Service{repo: repo}, nil
}

func (s *Service) Get(ctx context.Context, id int64) (User, error) {
	if id <= 0 {
		return User{}, fmt.Errorf("invalid user id: %d", id)
	}
	user, err := s.repo.FindByID(ctx, id)
	if err != nil {
		return User{}, fmt.Errorf("find user %d: %w", id, err)
	}
	return user, nil
}

// Handler 是适配层: 把 IDL 类型翻译成领域调用;
type Handler struct {
	service *user.Service
}

func (h *Handler) GetUser(ctx context.Context, req *api.GetUserRequest) (*api.GetUserResponse, error) {
	if req == nil {
		return nil, kerrors.NewBizStatusError(400, "request is required")
	}
	entity, err := h.service.Get(ctx, req.ID)
	if errors.Is(err, user.ErrNotFound) {
		return nil, kerrors.NewBizStatusError(404, "user not found")
	}
	if err != nil {
		return nil, fmt.Errorf("get user: %w", err)
	}
	return &api.GetUserResponse{ID: entity.ID, Name: entity.Name}, nil
}
```

## 启动顺序

- 第一步: 读取环境变量/配置文件，并校验地址、timeout、数据库 DSN;
- 第二步: 初始化 logger、tracer、metrics exporter;
- 第三步: 建立数据库、缓存、Registry 等外部 Client，并执行连通性检查;
- 第四步: 创建 Repository → Service → Handler;
- 第五步: 创建 Kitex Server，注入地址、身份、Registry、中间件和退出时间;
- 第六步: 依赖全部 ready 后再通过健康检查接收流量;
