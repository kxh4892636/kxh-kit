# 响应、中间件与错误

## 响应方式

- JSON: API 默认响应; 使用 `c.JSON(status, value)`;
- String/Data: 文本或已编码字节; 必须设置正确 Content-Type;
- redirect: 返回 3xx 和 Location; 不用于掩盖 API 错误;
- render: HTML 模板、文件和自定义 JSON 编码按场景配置;
- 空响应: 204 不包含响应体;

## 中间件模型

```go
func RequestID() app.HandlerFunc {
	return func(ctx context.Context, c *app.RequestContext) {
		id := string(c.Request.Header.Peek("X-Request-ID"))
		if id == "" {
			id = newRequestID()
		}
		c.Set("request_id", id)
		c.Header("X-Request-ID", id)
		c.Next(ctx)
	}
}
```

- 前置阶段: 校验、认证、记录开始时间;
- `c.Next`: 执行后续中间件和 Handler;
- 后置阶段: 读取状态码、记录耗时和指标;
- `c.Abort`: 阻止后续 Handler; 调用方还需写出完整错误响应;
- 顺序: recovery 应包住可能 panic 的链路，日志需要拿到最终状态;

## 统一错误

```json
{ "code": "ARTICLE_NOT_FOUND", "message": "article not found", "request_id": "01J..." }
```

- HTTP 状态码: 表达认证失败、资源不存在、冲突或服务异常;
- 业务错误码: 供客户端稳定分支，不直接暴露 Go 错误文本;
- panic: recovery 返回 500 并记录堆栈; 不把 panic 当成常规错误流;
- 写入一次: Handler 返回前确认响应已经完成，避免重复写 Header 和 body;
