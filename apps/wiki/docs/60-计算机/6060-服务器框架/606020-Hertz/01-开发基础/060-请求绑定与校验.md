# 请求绑定与校验

## 输入模型

```go
type CreateArticleRequest struct {
	Title   string   `json:"title" vd:"len($)>0 && len($)<=100"`
	Content string   `json:"content" vd:"len($)>0"`
	Tags    []string `json:"tags"`
}

func createArticle(ctx context.Context, c *app.RequestContext) {
	var req CreateArticleRequest
	if err := c.BindAndValidate(&req); err != nil {
		writeError(c, consts.StatusBadRequest, "INVALID_ARGUMENT", err.Error())
		return
	}
	// 调用 Service。
}
```

## 绑定来源

- `path`: 资源标识，例如 `/articles/:id`;
- `query`: 分页、过滤和排序;
- `header`: 认证、幂等键和内容协商;
- `json`: JSON 请求体;
- `form`: 表单或文件上传元数据;

## 校验分层

- 语法校验: JSON 是否可解析、字段类型是否正确;
- 结构校验: 必填、长度、范围和格式; 由 binding/validator 处理;
- 业务校验: 用户是否存在、状态能否迁移、标题是否重复; 由 Service 处理;
- 数据库约束: 唯一键和外键作为最终一致性防线; 错误仍需映射为领域错误;

## 兼容性

- 新增可选字段: 通常向后兼容;
- 新增必填字段: 会破坏旧客户端; 应提供默认语义或新版本;
- 未知字段: 公共 API 应决定忽略还是拒绝，并保持一致;
- 数字 ID: 绑定成功后仍需校验正数和业务存在性;

## 错误输出

- 对客户端: 返回字段、稳定错误码和可理解原因;
- 对日志: 记录校验类别与 request_id，不记录敏感原文;
- 对监控: 4xx 通常不是服务故障，但异常突增需要观测;
