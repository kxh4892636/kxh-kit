# 生成布局与增量更新

## 典型布局

```text
article-api/
├─ idl/article.thrift
├─ biz/
│  ├─ handler/article/
│  ├─ model/article/
│  └─ router/article/
├─ router.go
├─ main.go
└─ go.mod
```

- `biz/model`: IDL 生成的请求与响应模型;
- `biz/router`: 生成的路由注册;
- `biz/handler`: Handler 骨架与用户实现的交界;
- `router.go`: 汇总路由注册;
- `main.go`: Engine 组装和进程入口;

## 增量更新

```powershell
hz update -idl idl/article.thrift
git diff -- biz router.go
go test ./...
```

- `hz new`: 创建新项目骨架;
- `hz update`: 契约变化后更新现有项目;
- diff 审查: 生成代码也必须审查，特别是删除、重命名和路由变化;
- 可重复性: 同一版本工具对同一 IDL 应产生稳定结果;

## 所有权边界

- 生成文件: 不手工维护可由 IDL 表达的结构;
- 用户代码: Service、Repository、领域错误和测试由开发者维护;
- Handler: 若生成器保留用户区，也只写轻量适配; 复杂逻辑放独立包;
- 自定义模板: 只有团队长期需要统一骨架时采用，并把模板本身版本化;

## 变更策略

- 新增字段: 优先可选字段和默认语义;
- 重命名字段: 对客户端相当于删除再新增，通常不兼容;
- 删除方法: 先统计调用和公告弃用，再移除路由;
- 生成冲突: 不用覆盖参数盲目解决，先确认文件所有权和模板版本;
