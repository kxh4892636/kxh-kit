# 超时、连接复用与错误

## 时间预算

```text
入口 deadline
  ├─ 排队与业务处理
  ├─ DNS/连接/TLS
  ├─ 写请求
  ├─ 等首字节与读响应
  └─ 重试退避
```

- 总预算: 由调用方 context 决定，所有子阶段之和不能超过;
- connect timeout: 限制建立连接;
- request timeout: 限制单次尝试;
- idle timeout: 控制池中空闲连接，不限制正在执行的业务;
- 下游预算: 小于入口剩余 deadline，为错误处理和响应写出留余量;

## 连接复用

- Client 单例: 为相同代理、TLS 和连接策略复用;
- keep-alive: 减少 TCP/TLS 建连成本;
- 每主机上限: 控制并发和下游压力;
- 空闲回收: 平衡复用收益与资源占用;
- DNS 变化: 理解连接池和解析缓存对实例切换的影响;

## 错误分类

| 类别       | 示例                      | 默认动作         |
| ---------- | ------------------------- | ---------------- |
| 调用者取消 | context canceled          | 立即停止         |
| deadline   | context deadline exceeded | 返回超时         |
| 建连失败   | refused、DNS              | 谨慎重试         |
| HTTP 4xx   | 400、401、404             | 通常不重试       |
| HTTP 429   | 限流                      | 尊重 Retry-After |
| HTTP 5xx   | 临时服务故障              | 幂等请求可重试   |
| 解码失败   | schema 不兼容             | 告警并失败       |

## 防止资源泄漏

- 每条成功路径和错误路径都释放请求、响应或流;
- body 未读取完时确认连接是否还能安全复用;
- 限制响应大小，防止错误页或攻击响应耗尽内存;
- 指标分别记录 transport、status 和 decode 错误;

## 观测字段

- peer service、method、route template 和 status class;
- 尝试次数、连接复用、总耗时和分阶段耗时;
- trace context 通过 Header 注入;
- 不使用完整 URL 作为指标 label;
