# 代理与重试

代理类型是什么？反向代理链路如何运作？重试条件包含什么？重试预算是什么？风险控制有哪些注意点？

## 代理类型

- forward proxy: Client 通过代理访问外部目标; 常用于出口控制和审计;
- reverse proxy: Hertz 接收请求并转发到上游; 常用于网关、聚合和迁移;
- transparent concern: 代理仍需明确 Host、scheme、Header、超时和流式语义;

## 反向代理链路

```text
client → Hertz proxy → upstream
       ← status/header/body ←
```

- 路由重写: 明确原路径到上游路径的映射;
- Header: 删除 hop-by-hop Header，追加规范的转发信息;
- body: 大请求和响应使用流式转发并限制大小;
- 错误: 上游不可达与上游 5xx 分开记录;
- 安全: 不允许用户任意控制目标地址，防止 SSRF 和开放代理;

## 重试条件

- 幂等操作: GET、HEAD 和具备幂等键的写请求更适合重试;
- 可重试错误: 临时建连失败、明确 502/503/504 或 429;
- 不可重试: 参数错误、认证失败、权限失败和多数业务冲突;
- body 可重放: 流式或一次性 body 未缓存时不能安全重试;

## 重试预算

```text
总 deadline = 第一次尝试 + 退避 + 后续尝试 + 响应余量
```

- 次数: 使用小上限，不无限重试;
- backoff: 指数退避加 jitter，避免同步放大故障;
- Retry-After: 在总预算内尊重上游提示;
- 跨层: 只允许明确的一层负责重试，避免次数相乘;

## 风险控制

- retry storm: 配合限流、熔断和总重试预算;
- 写重复: 使用幂等键和服务端去重;
- 指标: 记录原始请求数、尝试数、最终结果和重试原因;
- 日志: 只在最终失败或策略异常时提升级别，避免每次尝试刷屏;
