# TLS、健康检查与优雅退出

## 如何确定 TLS 终止边界？

- 端到端 TLS: Hertz 直接加载证书和私钥; 适合直接暴露或内部 mTLS;
- 网关终止 TLS: Hertz 接收内网 HTTP; 必须验证代理网络和转发 Header 信任;
- 证书: 自动续期并监控到期时间; 私钥作为 Secret 管理;
- 配置: 只允许符合组织安全基线的 TLS 版本和 cipher;

## 如何区分三种健康探针？

- liveness: 进程是否无法恢复; 不因短暂数据库故障频繁重启;
- readiness: 当前实例是否应该接收新流量; 启动和退出阶段返回失败;
- startup: 慢启动服务可使用独立探针，避免初始化期间被误杀;
- 依赖策略: readiness 检查关键依赖，但设置短超时和缓存，避免探针放大故障;

## 如何有序停止 HTTP 服务？

```go
h := server.New(server.WithExitWaitTime(10 * time.Second))
h.Engine.OnShutdown = append(h.Engine.OnShutdown, func(ctx context.Context) {
	// 发出后台任务停止通知；这里不能假设在途 Handler 已经结束。
})
h.Spin()
```

```text
收到退出信号 → readiness=false → 等待摘流传播 → Shutdown
            → 等待在途请求 → flush exporter → 关闭 DB
```

- `Spin`: 监听退出信号并触发优雅退出；`WithExitWaitTime` 设置等待上限，应用需要自行实现 readiness 摘流及传播等待;
- `OnShutdown`: 回调并发触发，而且早于框架等待业务退出；这里适合发停止通知，DB 应在请求排空后由进程入口关闭;
- 信号版本: v0.9.6 起 SIGTERM、SIGHUP、SIGINT 都触发优雅退出；旧版 SIGTERM 立即退出;
- 长连接: SSE、WebSocket 和大文件传输需要单独的关闭协议;
- 关闭预算: 必须小于容器平台终止窗口，并为资源清理留出余量;
- 幂等: 关闭函数允许重复调用，不因部分初始化而 panic;

## 如何处理启动或关闭失败？

- 启动失败: 记录一次明确原因并非零退出;
- 关闭超时: 记录剩余任务，强制结束由进程入口统一决定;
- readiness: 退出第一步关闭，防止负载均衡继续导入请求;
- 后台任务: 停止接收新任务，等待或持久化未完成工作;
