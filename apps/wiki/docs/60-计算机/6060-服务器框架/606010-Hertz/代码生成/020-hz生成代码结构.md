# hz 生成代码结构

## Server 项目结构

```
.
├── biz
│   ├── handler       # handler 文件,用户实现业务逻辑
│   │   ├── hello/example/hello_service.go
│   │   └── ping.go   # 默认 ping handler
│   ├── model         # IDL 结构体生成代码(thriftgo/protoc 产物,update 重新生成)
│   └── router        # IDL 路由注册代码
│       ├── hello/example/{hello.go, middleware.go}
│       └── register.go
├── main.go           # 程序入口
├── router.go         # 用户自定义路由(layout 模板生成)
├── router_gen.go     # 路由注册汇总
├── .hz               # hz 项目标志
├── build.sh / script/bootstrap.sh   # Windows 默认不生成
└── go.mod
```

## 更新行为

- `biz/model`: update 时重新生成;
- handler 文件: 追加新增 method 的 handler 模板;
- router 注册文件: 基于 IDL 重新生成, 用户勿改; middleware.go 尾部追加新增中间件;
- register.go: 新增 IDL 时自动插入注册调用;

## hz client 结构

```
├── biz/model/...       # IDL 生成代码
│   └── hello_service/  # 基于 IDL 的 RPC 风格 HTTP 调用代码
│       ├── hello_service.go
│       └── hertz_client.go
├── go.mod
└── idl
```

## 生成位置规则

- protobuf 推荐定义 go_package(如 `{$MODULE}/{$MODEL_DIR}/x/y/z`);
- handler/router 取 go_package 最后一级作为生成路径;
- thrift 按 namespace 生成路径;
- update 时自定义路径(model_dir/handler_dir/client_dir)必须与 new 一致, 否则产生重复代码;
