# Hertz 网络库与流式处理

## 网络库

- 内置 netpoll 与 go net 两种网络库;
- Server 默认 netpoll, 可通过 `server.WithTransport(standard.NewTransporter)` 切换;
- Client 默认 netpoll, 通过 `client.WithDialer(standard.NewDialer())` 切换;
- `HERTZ_NO_NETPOLL=true` 环境变量可禁用 netpoll;
- netpoll 仅支持 linux/darwin && amd64/arm64, Windows 自动切换 go net;
- TLS 场景自动回退标准网络库;

## 触发模型差异

- go net 为 ET 模型(框架处理 Read/Write 事件), netpoll 为 LT 模型(网络库处理);
- 小包场景 LT 调度更优, 性能更好;
- 大包场景(request > 1M)LT 会把大量数据读入内存, 推荐 go net + 流式;

## 流式读

- `server.WithStreamBody(true)` 开启; 配合 `c.RequestBodyStream()` 读取;
- netpoll 的流式为"伪"流式(LT 触发会先读入网络库 buffer), 大包上传推荐 go net;

## 流式写

- 方式一: `c.SetBodyStream(reader, size)` 传入 `io.Reader`; size=-1 表示 `Transfer-Encoding: chunked`;
- 方式二: `c.Response.HijackWriter(resp.NewChunkedBodyWriter(&c.Response, c.GetWriter()))` 劫持 writer, 用 `c.Write` + `c.Flush` 分块发送;
- 方式一在 handler 执行完后再分块发送, 方式二在 handler 执行中即可发送;
- 流式写数据需异步写入, 避免阻塞;

## 连接劫持

- 劫持的 hijack conn 池化管理, WebSocket 场景不支持异步操作;
- 劫持连接只能关闭一次, 重复关闭会空指针;
- `h.NoHijackConnPool = true`: 关闭连接池复用(提升安全, 降低性能);
- `h.HijackConnHandle(c network.Conn, h app.HijackHandler)`: 自定义劫持处理;
