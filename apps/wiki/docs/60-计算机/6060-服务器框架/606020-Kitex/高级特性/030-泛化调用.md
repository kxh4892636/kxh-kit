# Kitex 泛化调用

## 概念与场景

- 泛化调用: 以 JSON, Map, 二进制等通用数据发起 RPC, 无需依赖服务端 IDL 生成代码;
- 场景: API 网关, 接口测试平台, Proxy 流量中转;
- 支持: Thrift 二进制转发, HTTP 映射, Protobuf 二进制, Map-Thrift, JSON 映射;

## IDLProvider

- `generic.NewThriftFileProvider(path, includeDirs...)`: 本地文件;
- `NewThriftContentWithAbsIncludePathProvider(main, map[string]string)`: 内存内容, 支持 `UpdateIDL`;

## Thrift 二进制泛化(V2)

- v0.15.1+; 必须指定 IDL service name, 一个 client 只访问一个 IDL service;
- Unary 编码的是 `XXXArgs`(不是原始 Request); `frugal.EncodeObject` 编码, `DecodeObject` 解码;
- 动态指定 service: `callopt.WithBinaryGenericIDLService(svcName)`, `streamcall.WithBinaryGenericIDLService`;
- 流式泛化: payload 为原始 request/response 序列化值(不含 Args/Result);
- Server 推荐 `genericserver.RegisterUnknownServiceOrMethodHandler`, DefaultHandler 处理 pingpong(buffered/framed/ttheader), StreamingHandler 处理 grpc/ttstream(grpc unary 也走这里);
- 旧版 `BinaryThriftGeneric` 只支持 Framed/TTHeader, 不支持 oneway;

## 其他泛化

- HTTP 映射: 网关场景, 仅非流式; json 数据格式;
- Map 映射: `map<string, interface{}>` 构造请求;
- JSON 映射: JSON 字符串 ↔ Thrift/Protobuf;

## Dynamicgo 高性能泛化

- 仅支持 JSON 泛化与 JSON 格式 HTTP 泛化;
- Provider: `NewThriftFileProviderWithDynamicGo` / `NewThriftContentProviderWithDynamicGo`;
- 默认 conv.Options: `WriteRequireField: true, WriteDefaultField: true`;
- HTTP 响应 body 类型为 json 字符串(RawBody), `UseRawBodyForHTTPResp(true)` 大幅提升性能;
- 条件: amd64 + go >= 1.16, 不满足自动 fallback 旧实现;
- 差异: thrift 异常信息为 json 字符串; bool 字段不接受字符串 "true";

## Thrift 反射(dynamicgo)

- 不依赖静态代码对 Thrift 数据增删改查; 类似 protoreflect;
- `thrift/generic.Value` / `Node`: 少量字段增删改查(敏感字段擦除, 包裁剪); Value 需绑定 TypeDescriptor, Node 不需要;
- `thrift/generic.PathNode` (DOM): 全量反序列化后的树, 适合 DSL 映射, 数据包合并;
- 二进制泛化 + dynamicgo 性能比 Map 泛化好 3 倍以上(大数据场景);
- 仅支持 thrift-binary 编码与 thrift-framed 传输;
