# Kitex 限流与访问控制

## 限流概述

- 限流保护 server, 防止上游流量突增导致过载;
- 支持 QPS 限流器与连接数限流器, 提供默认实现与自定义接口;
- 注意: `WithLimit` 与 `WithQPSLimiter`/`WithConnectionLimiter` 同时定义时, 只有后者生效;
- 仅对 Thrift, Kitexpb 协议生效, gRPC 暂不支持; gRPC 可用 `WithGRPCInitialWindowSize` / `WithGRPCInitialConnWindowSize` 做传输层流控;

## 默认限流器

```go
svr := xxxservice.NewServer(handler,
	server.WithLimit(&limit.Option{MaxConnections: 10000, MaxQPS: 1000}))
```

- `MaxConnections`: 最大连接数(ConcurrencyLimiter 计数器);
- `MaxQPS`: 最大 QPS(RateLimiter 令牌桶);
- `UpdateControl`: 动态修改阈值(`UpdateLimit(newOpt)`);
- 默认 QPS 限流在 `OnRead` hook 生效(非多路复用场景); 多路复用或自定义限流器在 `OnMessage` 生效;
- `LimitReporter` 接口(`ConnOverloadReport` / `QPSOverloadReport`)通过 `WithLimitReporter` 注入监控;

## 自定义限流器

- QPS: `server.WithQPSLimiter(myQPSLimiter)`, 实现 `Acquire(ctx) bool` 与 `Status(ctx)`;
- 连接数: `server.WithConnectionLimiter(myConnectionLimiter)`, 实现 `Acquire/Release/Status`;
- 可从 `rpcinfo.GetRPCInfo(ctx)` 获取 method, 地址等信息实现按方法/按地址限流;

## 访问控制(ACL)

- `pkg/acl` 提供中间件构造器: `acl.NewACLMiddleware(rejectFunc)`;
- 判断函数: `func(ctx, request) error`, 拒绝请求时返回 error;
- 启用: `client.WithMiddleware(...)` / `server.WithMiddleware(...)`;
- ACL 中间件在调用链中位于业务中间件之后, 服务发现/错误处理之前;
