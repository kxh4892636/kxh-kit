# Kitex 熔断

## 概述

- Kitex 提供熔断器实现, 默认不开启, 需主动配置;
- 大部分服务治理模块通过 middleware 集成, 熔断也是;

## CBSuite

- `circuitbreak.NewCBSuite(GenServiceCBKeyFunc)` 封装服务粒度与实例粒度熔断器;
- 服务粒度: key 默认 `circuitbreak.RPCInfo2Key`, 格式 `fromServiceName/toServiceName/method`;
- 实例粒度: 解决单实例异常; 触发实例熔断后框架自动重试;
- 实例级自动重试前提: 通过 `client.WithInstanceMW` 添加中间件(在负载均衡后执行);
- 默认阈值: `ErrRate=0.5, MinSample=200`;
- 动态更新: `cbs.UpdateServiceCBConfig(key, CBConfig{Enable, ErrRate, MinSample})`, `UpdateInstanceCBConfig`;
- Client 销毁时把 `cbs.Close()` 放入 `WithCloseCallbacks` 释放资源;

## 熔断器状态

- CLOSED: RPC 正常; 错误增多触发熔断进入 OPEN;
- OPEN: 冷却期内(默认 10s, CoolingTimeout 可配)所有请求被拒绝;
- HALFOPEN: 冷却后试探性放行, 连续成功 `DEFAULT_HALFOPEN_SUCCESSES` 个回到 CLOSED, 任一失败回 OPEN;

## 触发策略

- `ConsecutiveTripFunc`: 连续错误数达阈值;
- `ThresholdTripFunc`: 错误数达阈值;
- `RateTripFunc`: 错误率达阈值;
- 每次 Fail/Timeout 时调用 TripFunc 决定是否熔断; 可实现自定义 TripFunc;

## 统计算法

- 统计窗口默认 10s, 分桶计数(BucketTime x BucketNums);
- 默认 2000 桶 x 5ms; 桶过期会产生统计抖动, 桶越多影响越小;
- 统计成功/失败/超时;
