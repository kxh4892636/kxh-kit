# Kitex 重试

## 重试类型

- 异常重试(Failure Retry): 提高整体成功率, 默认只对超时重试;
- Backup Request: 减少延迟波动, 设置时间内未返回则发新请求, 任一结果返回即结束;
- Mixed Retry: 异常重试 + Backup Request 混合;
- 建连失败重试: 框架默认机制, 请求未发出, 一般无需关注;
- 三类业务重试默认不开启(幂等性风险); 流式接口不支持重试;

## 异常重试策略

- `MaxRetryTimes`: 默认 2(不含首次), 合法 [0-5];
- `MaxDurationMS`: 累计最大耗时, 0 不限; 配置须大于请求超时时间;
- `StopPolicy.CBPolicy`: 重试占比/错误率阈值, 默认 10%, 范围 (0-30%];
- `ChainStop`(默认 true): 链路中止, 上游请求为重试请求时不重试;
- `DDLStop`: 链路超时中止, 需 `retry.RegisterDDLStop` 注册实现;
- `BackOff`: 默认立即重试, 可选 FixedBackOff / RandomBackOff;
- `RetrySameNode`: 默认 false, 框架选择其他节点;

```go
fp := retry.NewFailurePolicy()
fp.WithMaxRetryTimes(3)
xxxCli := xxxservice.NewClient("psm", client.WithFailureRetry(fp))
```

## Backup Request

- `RetryDelayMS` 必须手动配置, 建议 TP99;
- `MaxRetryTimes`: 默认 1, 合法 [0-2];
- `retry.NewBackupPolicy(delay)` + `client.WithBackupRequest(bp)`;

## Mixed Retry

- v0.12.0+; `retry.NewMixedPolicy(delay)` + `client.WithMixedRetry(mp)`;
- 等"有效结果", 与 Backup Request 等任意结果不同;

## 自定义重试条件

- `retry.ShouldResultRetry{ErrorRetryWithCtx, RespRetryWithCtx, NotRetryForTimeout}`;
- `client.WithSpecifiedResultRetry(...)` 或 `NewFailurePolicyWithResultRetry(...)`;
- Thrift/KitexProtobuf 的 Resp 是 `*XXXResult`, 真实 resp 需 `GetResult()` 断言;
- 对端错误统一封装为 `kerrors.ErrRemoteOrNetwork`;
- Thrift Exception 场景: 通过 resp 判断而不是 error; 重试成功需重置 Exception 为 nil;
- `NotRetryForTimeout=true`: 非幂等请求不对超时重试;

## 方法与调用级配置

- `client.WithRetryMethodPolicies(map[string]retry.Policy)`: 按方法粒度;
- `callopt.WithRetryPolicy(...)` / `callopt.WithMixedRetry(...)`: 调用级;
- 动态配置: `retry.NewRetryContainerWithPercentageLimit()` + `NotifyPolicyChange(method, policy)` + `client.WithRetryContainer`;
- 代码配置优先于动态配置;

## 中间件注意事项

- 重试在中间件之前实现, 每次重试都执行所有中间件;
- 中间件 next 返回 `kerrors.ErrRPCFinish` 说明结果被丢弃, 直接返回;
- 重试信息在首次请求的 rpcinfo: `ri.To().Tag(rpcinfo.RetryTag)`, `RetryLastCostTag`;
- 下游识别重试: `metainfo.GetPersistentValue(ctx, retry.TransitKey)`; 本地判断用 `retry.IsLocalRetryRequest(ctx)`;
