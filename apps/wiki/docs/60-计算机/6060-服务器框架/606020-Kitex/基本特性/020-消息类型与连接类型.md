# Kitex 消息类型与连接类型

## 消息类型

- PingPong: 客户端发一个请求等一个响应, 才能进行下一次请求;
- Oneway: 客户端发请求后不等待响应(thrift 中 `oneway void` 定义);
- Streaming: 一个或多个请求对应一个或多个响应;
- Thrift 支持 PingPong, Oneway; Protobuf 的 Kitex Protobuf 只支持 PingPong, gRPC 支持 Unary 与 Streaming;

## 连接类型

### 短连接

- 每次请求创建连接, 性能不佳, 通常不建议;
- 上游实例过多时可减少下游连接负担;
- `client.WithShortConnection()`;

### 长连接池(默认)

- 默认配置: `MaxIdlePerAddress=10, MaxIdleGlobal=100, MaxIdleTimeout=1min, MinIdlePerAddress=2`;
- `MaxIdlePerAddress`: 每个实例最大闲置连接数, 最小 1, 估算 `qps*avg_rt`;
- `MaxIdleGlobal`: 全局最大闲置连接数; v0.7.2 起未设置默认不限制;
- `MaxIdleTimeout`: 闲置关闭时间(最小 3s, 默认 30s), 下游为 Kitex 时不可超 10min(server 10min 清理);
- `MinIdlePerAddress`(v0.4.3+): 常驻最小空闲连接, 不被清理, 当前最大值 5;
- 取连接: 池中取不到则新建(可超过上限); 空闲超时则关闭新建;
- 归还: 连接异常直接关闭; 超全局上限关闭; 池有空位放入否则关闭;

### 连接多路复用(已废弃)

- `WithMuxConnection` / `WithMuxTransport` 依赖的 netpollmux 不再维护;
- Client 与 Server 必须同时开启, 否则请求超时;
- gRPC 协议默认就是连接多路复用;

## 连接池状态监控

- `Reporter` 接口: `ConnSucceed` / `ConnFailed` / `ReuseSucceed`, 通过 `SetReporter` 注入(只能设置一次);
