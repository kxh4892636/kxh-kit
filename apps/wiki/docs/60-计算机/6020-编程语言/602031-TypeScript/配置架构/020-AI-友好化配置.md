# AI 友好化配置

## 本质

- 核心目标: 用严格、显式、低歧义的 TypeScript 配置缩短「修改—诊断—修正」反馈环;
- 友好的含义: 不是放宽类型系统，而是让错误更早暴露、诊断更局部、修正更机械;
- 配置位置: 跨项目规则放入 shared baseline，runtime 相关规则留在叶项目;

## 规则与反馈

### 类型形状

| 配置                         | 约束                                         | 反馈价值                            |
| ---------------------------- | -------------------------------------------- | ----------------------------------- |
| `strict`                     | 启用一组严格类型检查                         | 建立最低安全基线，减少错误假设      |
| `exactOptionalPropertyTypes` | 区分属性缺失与显式 `undefined`               | 让对象形状与运行时存在性检查一致    |
| `noUncheckedIndexedAccess`   | 为未声明字段和索引访问的结果加入 `undefined` | 暴露数组越界和字典缺 key 假设       |
| `useUnknownInCatchVariables` | 将 `catch` 变量默认为 `unknown`              | 要求在读取 `message` 前收窄异常类型 |

### 属性与控制流

| 配置                                    | 约束                              | 反馈价值                         |
| --------------------------------------- | --------------------------------- | -------------------------------- |
| `noPropertyAccessFromIndexSignature`    | 索引签名字段必须使用 `obj[key]`   | 区分已声明属性与动态 key         |
| `noImplicitReturns`                     | 报告未显式返回值的代码路径        | 定位分支遗漏                     |
| `noFallthroughCasesInSwitch`            | 报告包含语句的非空 `case` 贯穿    | 防止新 `case` 意外改变控制流     |
| `noImplicitOverride`                    | 要求覆盖基类成员时写出 `override` | 暴露误拼或意外遮蔽               |
| `noUnusedLocals` / `noUnusedParameters` | 报告未使用的局部符号和参数        | 清除重构残片，减少后续上下文噪声 |

### 模块与文件边界

| 配置                               | 约束                                                   | 反馈价值                                      |
| ---------------------------------- | ------------------------------------------------------ | --------------------------------------------- |
| `noUncheckedSideEffectImports`     | 报告无法解析的 side-effect import                      | 捕获样式、polyfill 或注册器的路径拼错         |
| `verbatimModuleSyntax`             | 保留 value import，擦除带 `type` 修饰的 import/export  | 迫使 type/value 边界显式且可稳定重写          |
| `moduleDetection: "force"`         | 将每个非声明文件都视为 module                          | 防止无 import/export 的新文件污染全局         |
| `allowImportingTsExtensions`       | 在 `noEmit` 或仅输出声明的模式下允许 `.ts` import path | 使源码 import 写法与 bundler/runtime 约定一致 |
| `forceConsistentCasingInFileNames` | 校验 import path 大小写与文件名一致                    | 在本地捕获只会于大小写敏感环境失败的路径      |
| `erasableSyntaxOnly`               | 拒绝需要 TypeScript 生成运行时代码的语法               | 确保外部 transpiler 只擦除类型便能处理源码    |

### 项目边界

| 配置                       | 约束                               | 反馈价值                                 |
| -------------------------- | ---------------------------------- | ---------------------------------------- |
| 显式 `types`               | 只引入允许的 ambient type packages | 防止依赖安装后偶然出现 globals           |
| 显式 `rootDir` / `include` | 限定源码根与项目输入               | 防止无关文件扩大诊断与检索范围           |
| project references         | 显式表达项目边界与构建顺序         | 提供稳定全仓入口，避免根配置扫描全部源码 |

## `skipLibCheck` 的 Ownership Boundary

- 实际作用: `skipLibCheck: true` 跳过 `.d.ts` 声明文件内部的完整类型检查;
- 仍然检查: 仓库源码对声明中类型的使用，例如参数不匹配或返回值误用;
- 适用理由: 将上游声明之间的冲突留给其维护者，避免第三方诊断淹没仓库问题;
- 禁止推论: 不得用 `skipLibCheck` 解释或忽略仓库源码错误;
