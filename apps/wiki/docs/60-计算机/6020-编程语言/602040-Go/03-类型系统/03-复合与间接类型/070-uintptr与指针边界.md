# uintptr 与指针边界

uintptr是什么？指针限制是什么？边界对比说明什么？使用原则有哪些注意点？

## uintptr

### uintptr的核心规则

- `uintptr`: 可保存指针位模式的整数类型;
- 整数本质: `uintptr` 只是一种无符号整数，数值宽度足以保存当前平台的地址位模式;
- GC 语义: `uintptr` 不被垃圾回收器当作指针追踪;
- 生命周期风险: 将指针转为 `uintptr` 后长期保存，不能阻止目标被移动、回收或失效;
- 使用限制: 普通业务代码不应把 `uintptr` 当作安全指针使用;

## 指针限制

### 指针限制的核心规则

- 指针算术: Go 不支持普通指针加减运算;
- 临时值取址: 不可对不可寻址的临时结果直接取地址;
- 安全边界: 需要底层地址运算时通常涉及 `unsafe`;

## 边界对比

| 形式       | GC 是否按指针追踪 | 是否支持普通指针算术 |
| ---------- | ----------------- | -------------------- |
| Go pointer | 是                | 否                   |
| `uintptr`  | 否                | 作为整数参与运算     |

## 使用原则

- 普通代码: 使用类型安全的 Go pointer;
- 地址整数: 仅在明确需要底层地址表示时使用 `uintptr`;
- 底层运算: 视为 `unsafe` 相关边界;
- 转换原则: 指针与 `uintptr` 的往返转换必须遵守 `unsafe.Pointer` 文档允许的模式，不能凭数值相同推断地址仍然有效;
- 替代方案: 能用 slice、索引、类型安全 pointer 或标准库 API 表达时，不使用 `uintptr`;
