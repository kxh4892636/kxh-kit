# 泛型设计

什么时候使用泛型设计？什么时候不使用泛型设计？接口与泛型是什么？

## 什么时候使用泛型设计

### 什么时候使用泛型设计的核心规则

- 泛型: 用类型参数描述“一段逻辑可安全用于多种类型”，由编译器检查每次具体使用;
- 类型参数: 写在方括号中的占位类型，例如 `T`;
- 约束: 限制类型参数允许哪些类型或操作的接口;
- 容器结构: stack, set, queue 等持有任意元素类型的数据结构;
- 算法复用: 对多种数值类型执行相同逻辑;
- 类型安全: 避免使用 `any` 后再做类型断言;

## 什么时候不使用泛型设计

### 什么时候不使用泛型设计的核心规则

- 单一类型逻辑: 直接写普通函数更清晰;
- 约束复杂: 需要大量类型分支时泛型收益较低;
- 业务抽象: 优先使用具体类型和接口表达行为;

## 接口与泛型

### 接口与泛型的差异

| 机制      | 关注点             |
| --------- | ------------------ |
| interface | 值能做什么行为     |
| generic   | 代码能适配哪些类型 |

- 接口优先: 调用方只关心对象能做什么时，用 interface 表达行为;
- 泛型优先: 算法需要保留具体类型，或多个输入与输出必须保持同一类型关系时，用类型参数;
- 组合使用: 泛型约束本身由 interface 表达，两者不是互斥方案;
- 判断问题: 若删除类型参数后只能改用 `any` 和类型断言，并且所有类型执行相同算法，泛型通常有价值;
