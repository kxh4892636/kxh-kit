# 记忆的认知科学分类

## 工作记忆与长期记忆如何对应 Agent？

- 工作记忆（Working Memory）: 处理当前任务的临时信息空间，对应 Agent 的上下文窗口;
- 工作记忆内容: 轨迹是最核心的部分，但也可能包含从长期记忆中激活加载的信息;
- 长期记忆: 细分为情景记忆、语义记忆、程序记忆三类，每类都能在 Agent 记忆中找到直接对应;

## 情景记忆是什么？

- 人类例子: “上周三和同事在那家意大利餐厅吃了一顿很棒的晚餐”;
- 定义: 关于具体事件和经历的记忆;
- Agent 对应: “用户订了下周五去东京的 ANA 航班”——记录了一个具体事件的时间、对象和细节;

## 语义记忆是什么？

- 人类例子: “意大利的首都是罗马”;
- 定义: 从具体事件中抽象出的一般性知识;
- Agent 对应: “用户是素食者”“用户偏好靠窗座位”——不是某次对话的记录，而是从多次交互中提炼出的稳定特征;

## 程序记忆是什么？

- 人类例子: 骑自行车的能力;
- 定义: 关于行为模式和流程的记忆;
- Agent 对应: 从用户反复订机票的模式中学到的通用流程——“先搜索直飞航班 → 确认座位偏好 → 使用常旅客号码 → 订餐”;

## 三套记忆分类体系如何区分？

| 分类体系 | 回答的问题 | 具体类别                                                         |
| -------- | ---------- | ---------------------------------------------------------------- |
| 记忆层次 | 存在哪里？ | 轨迹（当前会话）、用户长期记忆（跨会话）、业务状态（任务阶段）   |
| 存储格式 | 怎么存？   | Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards    |
| 认知类型 | 存什么？   | 情景记忆（具体事件）、语义记忆（一般知识）、程序记忆（行为流程） |

- 正交性: 三套体系是正交维度，可以自由组合;
- 组合例: 一条“用户偏好靠窗座位”的语义记忆，可以用 Simple Notes 格式存储在用户长期记忆中;
- 组合例: 一段“先搜直飞 → 确认座位 → 用常旅客号”的程序记忆，可以用 Advanced JSON Cards 格式存储;
- 选择依据: 选格式取决于工程需求（简单性与表达力之间的取舍），选类型取决于业务场景（需要记住事实、事件还是流程）;
- 出处: 记忆层次见 [记忆的层次结构](./030-记忆的层次结构.md)，存储格式见 [用户记忆的四种存储格式](./040-用户记忆的四种存储格式.md);
