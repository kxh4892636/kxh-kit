# 记忆与知识库总览

## 用户记忆与知识库有什么区别？

- 用户记忆: 面向单个用户的个性化记忆，Agent 在交互中逐渐了解其偏好、习惯与需求，构建专属该用户的知识模型;
- 知识库: 面向所有用户共享的集体知识，如行业法规体系、公司内部操作流程、领域专业文档;
- 类比: 前者让 Agent 成为“懂你的助手”，后者让它成为“领域专家”;
- 共性: 两者是同一问题在不同尺度上的表现（个体 vs 群体），共用向量检索、知识压缩等底层技术;
- 共同麻烦: 信息冲突、知识过期、检索不准;
- 定位: 把单次会话的上下文管理扩展为跨会话的持久化知识体系，单次会话侧见 [上下文构成与消融](../010-Agent基础/040-上下文构成与消融.md);

## 为什么需要独立于上下文窗口的持久记忆？

- 不保存每句对话: 用额外的 LLM 调用提取、压缩并审查对未来有用的事实;
- 与上下文学习的差别: 上下文学习只在当前窗口生效，记忆跨会话生效;
- 触发时机: 一次对话结束后，由专门的 LLM 分析会话内容，抽取值得长期记住的信息;
- 判据: 提取结果要舍弃一次性细节、保留可复用的稳定事实;

## 一次记忆提取的结果长什么样？

- 场景: 用户让 Agent 订下周五去东京的机票，声明偏好靠窗座位、素食需特殊餐食，并给出 United MileagePlus 会员号 12345678;
- 提取输出（示意）:

```text
Extracted memories:
- User prefers window seats (preference)
- User is vegetarian, needs special meals on flights (dietary restriction)
- User's United MileagePlus number: 12345678 (loyalty program)
- User has travel plans to Tokyo (recent activity)
```

## 提取结果必须满足哪三条规则？

- 选择性: 丢弃“搜索返回 3 个选项”这类短期细节;
- 抽象化: 把本次“靠窗座位”归纳为长期偏好;
- 结构化: 用可检索的字段保存事实;

## 用户记忆的生命周期是什么？

- 四步: 读取相关记忆 → 后台提取候选 → 来源与策略核验 → 更新;
- 写入门禁: 来源、时间、冲突与隐私检查都不能跳过;
- 存储形态: 可在 Simple Notes、JSON Cards 或可执行状态之间按需求取舍，见 [四种存储格式](./040-用户记忆的四种存储格式.md) 与 [可执行代码记忆](./050-可执行代码记忆.md);
- 全书定位: 对应第一章发现循环中的“提案”段——把一条证据变成一次最小、可审查、可回滚的修改，不负责判断系统整体是否变好;
