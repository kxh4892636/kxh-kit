# 记忆的层次结构

## 轨迹（Trajectory）是什么？

- 定义: 一次 Agent 运行过程中的完整历史记录，即第一章定义的“动态轨迹”（用户消息 + 模型回复 + 工具执行结果）;
- 顺序: 记录从对话开始到当前时刻的所有事件，按时间顺序排列;
- append-only: 只增不改——新事件不断追加到末尾，已写入的记录不被修改或删除;
- 限定: “只增不改”描述的是用于追溯、调试或审计的原始事件记录;
- 长度控制: 每轮实际发送给模型的运行时 Context 可以经过压缩、重组，或用摘要替换部分历史; 原始记录是否完整保留取决于系统的数据保留与审计要求;
- 作用: 为 Agent 决策提供即时上下文——“我刚才说了什么”“用户如何回应”“工具返回了什么结果”;
- 相关: 轨迹的构成见 [上下文构成与消融](../010-Agent基础/040-上下文构成与消融.md);

## 用户长期记忆是什么？

- 定义: 跨会话、跨实例的持久化存储;
- 绑定方式: 通常以键值对形式与特定用户 ID 绑定;
- 内容: 偏好设置、历史交互摘要与提取出的知识点;
- 读写: Agent 通过特定工具调用显式读取和更新长期记忆，实现跨会话的个性化与连续性;

## 业务状态是什么？

- 定义: 开发者定义的高层状态抽象，表示任务的逻辑阶段（“需要澄清”“处理请求中”“等待付款”“请求完成”）;
- 场景: 在事件驱动的 Agent 架构中尤为重要（第六章讨论）;

## 轨迹与长期记忆的分工是什么？

- 性质对比: 轨迹是流水账，长期记忆是档案——前者是单次会话的完整原始记录，后者是跨会话提炼出的稳定信息，会被反复改写、合并、淘汰;
- 分层收益: 依赖轨迹高效处理当前任务，依赖长期记忆获得跨会话个性化能力;

## 工作记忆与轨迹有什么区别？

- 相同点: 两者都为当前决策提供即时上下文;
- 轨迹: 不可变的完整事件序列，按时间追加;
- 工作记忆: 经过筛选和激活的动态子集，按相关性裁剪;
- 交互: 重要信息选择性转移到长期记忆，相关长期记忆被激活并加载到工作记忆;
