# 评估环境五要素

## 可重复运行的评估环境必须具备哪五个要素？

- 前提: 给定同一个初始状态，同一个 Agent 应当得到可比较的结果;
- 五要素: 数据集、环境状态、工具接口、评分标准、执行协议;
- 缺一不可: 五个要素缺其一，评估便无法构成可重复的循环;
- 用途: 考察其他基准时，以这五项作为对照框架;

| 要素                          | 内容                         | 以 telecom 任务为例                                      |
| ----------------------------- | ---------------------------- | -------------------------------------------------------- |
| 数据集 Dataset                | 一条记录即一个用例           | 初始状态 + 工单 + 模拟器规范 + 验收标准打包为一条        |
| 环境状态 Environment State    | 执行中的可变信息，必须可重置 | 客户/线路/套餐/账单 + 飞行模式/漫游/省流开关/剩余流量    |
| 工具接口 Tools                | 两侧各自的原子操作           | Agent 侧查询客户、查询用量、充值、转人工；用户侧设备开关 |
| 评分标准 Rubric               | 分层检查 + 聚合规则          | `evaluation_criteria` 四层检查 + `reward_basis`          |
| 执行协议 Interaction Protocol | 交互顺序与终止条件           | 模拟用户输出 `###STOP###`、轮数上限、耐心耗尽主动结束    |

## 环境状态的真实性要求与控制要求分别是什么？

- 真实性: 状态变化必须符合业务逻辑，如充值后余额与网速的联动必须自洽;
- 可控性: 每次运行前都能回到同一起点，`initialization_actions` 即重置脚本;

## 工具接口为什么要保持原子性？

- 原则: 两侧工具均为原子操作，不存在 “解决用户的上网问题” 这类高层抽象;
- 后果: 抽象层次过高会使评估退化为对单次函数调用的考察，规划与推理环节被工具本身吸收;
- 分工: Agent 侧为运营商侧操作，用户侧为设备侧操作，两侧不可混用，结构见 [评估任务解剖与真实轨迹](./020-评估任务解剖与真实轨迹.md);

## 执行协议规定了哪些终止条件？

- 正常终止: 模拟用户输出 `###STOP###`;
- 硬性上限: 轮数上限;
- 失败终止: 模拟用户因耐心耗尽而主动结束对话，沟通效率过低本身即计为失败;
- 意义: 终止条件决定 “未完成” 与 “超预算” 是否被区分统计;

## 评估环境与 Harness 的边界如何划分？

- 归属: 工具定义、调用适配器、沙箱的权限与重置机制属于 Harness;
- 归属: 沙箱内随行动变化的文件与进程、外部数据库、网页、用户及物理世界属于 Environment;
- 澄清: 物理部署位置不决定概念归属，即使仿真环境与 Agent 同进程，它仍是 Environment;
- 详见: [Harness工程](../010-Agent基础/060-Harness工程.md);
