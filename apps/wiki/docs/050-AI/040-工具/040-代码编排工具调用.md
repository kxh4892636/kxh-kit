# 代码编排工具调用

## 代码编排与一次一调用有什么区别？

- 传统方式: 一次调用一个工具，把每个中间结果都搬进上下文;
- 类比: 就像每做完一步都要写一封邮件汇报给领导，领导读完后再回信告诉你下一步做什么——这些来回的“邮件”就是 token 消耗;
- 代码编排: 领导一次性写好完整的操作手册，照着做即可，只在全部完成后汇报最终结果;
- 机制: LLM 一次性生成一段脚本，中间变量留在代码的执行环境中，只有最终结果才返回 LLM;

## 代码编排能省多少 token？

- 例子: 抓取多个网页再批量提取字段时，页面全文只存在于执行环境的变量中，返回上下文的只有汇总后的结构化结果，避免整页内容反复进出上下文;
- 量级: token 消耗可降低约两个数量级;
- 定位: 这种“让代码来编排工具调用”的模式，属于第五章将系统展开的“代码作为通用 Agent 元能力”范式;
- 前提: 通用执行器使这种串联成为可能，形态选择见 [通用优先、粒度整合与退回专用](./030-通用优先与粒度整合.md);
