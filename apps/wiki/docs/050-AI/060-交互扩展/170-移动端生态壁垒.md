# 移动端生态壁垒

## 移动端的动作空间与桌面有何不同？

- 元素获取: 通常不再采用“鼠标坐标 + 键盘”，而是接入系统无障碍服务 API（如 Android 的 `AccessibilityService`）来读取界面元素、下发点击与文本输入;
- 交互方式: 从鼠标指针变为触摸手势;
- 坐标语义变化: 同一个 (x, y) 可能是手指的单击、长按，也可能是滑动手势的起点，需要额外的手势类型来界定;
- 评测: 移动端基准（如 AndroidWorld）正是在这样的动作空间上评测 Agent 完成真实应用内任务的能力;
- 定位路线差异: 无障碍树提供结构化元素信息，属于视觉定位中的结构化元素索引路线，见 [视觉定位三条路线](./140-视觉定位三条路线.md);

## 移动端真正的阻碍是什么？

- 常见误判: 技术差异（手势语义、无障碍接口）确实存在，但通常不是卡点;
- 现实案例: 曾有手机厂商尝试在消费级手机中集成 AI 助手，自动操作微信、淘宝、支付宝等日常应用，很快遭遇平台限制;
- 阻碍性质: 移动端面对的是**生态壁垒**，与桌面端的 CAPTCHA、IP 信誉检测等技术对抗不同;
- 结构性: 这属于平台与应用之间的结构性利益冲突，而非单纯的工程技术问题;

## 生态壁垒的根源是什么？

- 变现逻辑: 传统互联网应用的核心变现逻辑是**流量与注意力**——用户刷信息流时看到广告，搜索商品时跟随推荐算法引导，浏览页面时产生冲动消费;
- 被绕过的链路: Agent 代替用户操作时，这条变现链路被彻底绕过;
- 行为差异: AI 不会关注广告，也不会冲动消费，直奔目标完成任务就走;
- 结论: 对于靠广告和流量变现的平台，Agent 的每一次操作都在侵蚀其商业模式的根基;

## 这对 Computer Use 落地意味着什么？

- 对抗层次: Computer Use 面对的不仅是验证码等技术层面的对抗，更是一个结构性的利益冲突;
- 时间尺度: 这一矛盾在短期内难以调和;
- 落地判断: 消费级场景中的落地难度高于纯技术问题所暗示的程度;
- 能力边界: 观察与动作空间的扩展并不自动带来生态准入；
- 展开位置: 交互循环与观察接口分别见 [Computer Use 交互循环](./120-ComputerUse交互循环.md) 与 [Agent-电脑观察接口](./150-Agent电脑观察接口.md);
