# 子 Agent 上下文隔离

## 子 Agent 上下文隔离解决什么问题？

- 对比对象: 压缩是在信息已进入上下文之后做减法，隔离是让大体积中间信息根本不进入主上下文;
- 定义: 主 Agent 把“在代码库中大范围搜索”这类会产生海量中间内容的任务，委派给独立的子 Agent;
- 流程: 子 Agent 在自己的上下文中完成探索，只把几百 token 的结论性摘要回传给主 Agent;
- 实例任务: “在代码库中找到处理支付回调的函数”;
- 主 Agent 亲自搜索: 可能把十几个文件中的数万 token 原始代码纳入主上下文，绝大部分在找到目标后沦为永久占据窗口的噪声;
- 委派做法: 主上下文只增加两条消息——一条任务描述，一条结论（“函数位于 src/payment/callbacks.py 的 handle_callback，另有两处调用点”）;
- 代价差异: 中间过程的数万 token 随子 Agent 的上下文一起被丢弃;

## 为什么说隔离优于压缩？

- 压缩的代价: 有损的、需要额外 LLM 调用的事后补救;
- 隔离的优势: 让噪声从一开始就与主上下文绝缘，主 Agent 的 KV Cache 前缀完全不受影响;
- 实现代价: 子 Agent 看不到主 Agent 的完整上下文，任务描述必须自包含、目标明确;
- 呼应主题: 上下文的质量决定能力上限，对子 Agent 同样成立;
- 生产实现: Claude Code 的 Task 工具、各类深度研究（Deep Research）系统的检索子 Agent;
- 展开: 子 Agent 作为协作工具的完整设计见第四章；多 Agent 系统的上下文架构见第十章;
