# 四种更新载体的路由

## 学习信号为什么不能直接决定修改位置？

- 结论: 学习信号说明 Agent 应当改变，但没有说明改变应发生在哪里;
- 判据: 载体选择由**能力的表示性质**决定，而不是由“哪个更容易改”决定;
- 四类落点: 事实与经验写成知识文档；可用语言表达的策略写入提示词或 Skill；可精确执行的流程与约束写成程序；感知、语言风格与隐式策略进入模型参数;

## 四种载体各自适合承载什么？

| 更新方式        | 适合承载                                                   | 主要优势                   | 主要局限               |
| --------------- | ---------------------------------------------------------- | -------------------------- | ---------------------- |
| 经验知识库      | 事实、经验规律、例外与来源                                 | 更新快、可追溯、可按需检索 | 依赖检索和模型正确应用 |
| Prompt 与 Skill | 需要理解语境、例外和优先级，但仍能用自然语言说明的判断原则 | 可解释、作用范围可控       | 容易膨胀、冲突或被忽略 |
| 程序与 Harness  | 可确定解析、可执行验证和高风险硬约束                       | 可测试、执行稳定、成本低   | 开发与维护成本较高     |
| 模型参数        | 高维感知、生成风格和隐式策略                               | 泛化能力强、推理开销低     | 更新与回归成本高       |

## 什么情况下必须更新模型参数？

- 判据: 目标能力无法被外部符号较完整地表达;
- 典型能力: 医疗影像理解、自然的语音韵律、消除文本的模板化“AI 味”、长程规划;
- 手段: 通过后训练写入模型参数（SFT、蒸馏与 RL 的细节见第八章）;
- 中间地带例子: 弯引号的作用域判断——文档语法边界可由程序解析，语境和例外需要 Skill 表达，跨任务的识别习惯才适合通过后训练内化;

## 参数化是否只由“任务是否长期稳定”决定？

- 结论: 不是;
- 反例一: 新影像设备带来的域偏移仍可能需要 LoRA 或持续微调;
- 反例二: 快速变化的语言风格也可以通过周期性偏好训练适应;
- 分工: 稳定性影响更新频率和成本，能力表示性质才决定主要载体;

## 四种载体为什么会同时出现在一个系统里？

- 医疗影像 Agent: 参数识别病灶，知识库提供最新指南，代码计算风险指标;
- 客服模型: 自然语气来自后训练，具体企业政策由知识与 Skill 提供，关键合规则由服务端代码兜底;
- 结论: 四种方式并不互斥，同一能力可以拆到多个载体;

## 路由结果为什么还不是发布？

- 定位: 路由结果只是更新提案，尚未获得发布资格;
- 门槛: 提案必须经过独立验证、回归与安全检查（见[更新能力与受益能力](./150-更新能力与受益能力.md)）;
- 纪律: 可确定性执行的约束应进入程序，而不是继续堆在 Prompt 里（见[将经验写成程序与自我修改的发布流程](./090-将经验写成程序与自我修改的发布流程.md)）;
