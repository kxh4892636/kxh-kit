# 记忆与技能的后台整理

## Claude Code 的自动记忆说明了什么？

- 结构: 为每个项目维护 `MEMORY.md` 索引和按主题拆分的详细文件;
- 加载: 会话启动只加载索引的有界前缀，其余内容按需读取;
- 容量约束: 当索引接近上限时，系统要求 Agent 合并或移走细节;
- 结论: 纯文本记忆也需要容量约束、分层加载和主动整理;
- 边界: 当前公开机制主要是在会话中持续写入，并不能简单等同于一个固定的夜间后台任务;

## Hermes 的后台记忆进化有哪些组成部分？

| 组成         | 说明                     |
| ------------ | ------------------------ |
| 有界长期信息 | `MEMORY.md` 与 `USER.md` |
| 历史会话检索 | 基于 SQLite / FTS5       |
| Skill        | 按需加载                 |
| 外部记忆     | Honcho 等可选提供者      |

- 关键设计: 历史检索返回原始消息而非先由 LLM 摘要，避免把检索和生成混成一个不可审计步骤;

## 后台复盘在什么条件下创建或修订 Skill？

- 触发条件: 一次任务包含较多工具调用、从错误或死路中恢复、收到用户纠正，或发现非显而易见的工作流;
- 产物: 后台复盘可以创建或局部修订 Skill;
- 门控: 记忆和 Skill 写入还可以经过审批门控;
- 清理: 独立的 Curator 跟踪 Skill 的使用、陈旧和归档状态，在空闲期执行确定性修剪，并可选择运行 LLM 合并;
- 可回滚: 变更前保存快照，错误整理可以回滚;

## 持续进化为什么会遇到上下文腐化？

- 机制: 上下文腐化会在更长时间尺度上重现;
- 表现一: 经验文档相互冲突;
- 表现二: Prompt 被边界规则淹没;
- 表现三: Skill 库出现重复能力;
- 表现四: 多次微调造成灾难性遗忘;

## 周期性离线整理包含哪些动作？

- 合并重复经验，保留来源和版本;
- 把局部规则从全局 Prompt 移动到领域 Skill，保持全局 Prompt 整洁;
- Prompt 和 Skill 保持结构清晰;
- 重新验证长期未使用的工具;
- 删除被新证据推翻的知识;
- 从原始基座模型重新训练 LoRA;
- 目标: 持续进化不是让知识、Prompt 和工具无限增长;
