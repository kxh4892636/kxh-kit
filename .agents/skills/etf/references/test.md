# Test Principles

本文件维护 ETF 项目的前后端 BDD/TDD 原则与测试资产位置；[verification.md](verification.md) 只负责具体命令、联调和验收路径。

## 总原则

- 前端验收资产按生命周期分为需求流与主流程：前者服务单次需求，后者承载稳定回归。
- 前端以 BDD 为主，验证用户可观察行为。
- 后端 TDD 原则暂时只保留占位，后续补充。
- 跨端需求按契约顺序推进：先确认 proto/API 语义，再分别维护前后端测试入口，最后做联调验收。

## 前端 BDD

- 前端 BDD 测试用例使用 Markdown 维护，文档结构、场景状态和证据要求遵循 `/e2e`，目录使用本节的 ETF 约定；验收执行走真实浏览器路径。
- **需求流**：每个需求的验收资产保存在仓库根目录 `.scratch/<feature-slug>/e2e/`，需求文档使用 `/e2e` 规定的日期文件名。需求开发期间的 draft、ready、failed、blocked 场景、执行记录和临时排障步骤均在这里维护。
- **主流程**：每个前端业务模块的稳定回归入口是 `apps/etf-dashboard/src/features/<feature-name>/e2e/index.md`；新增或重构后的模块存在可长期复验的用户路径时创建该文件。
- 需求流中的场景经真实浏览器验收达到 passed 后，才把可长期复验的步骤、断言和证据要求合并到受影响模块的主流程；一次性调试步骤留在需求流。
- 新流程替换既有行为时，同步改写或删除主流程中的过期场景，使同一能力只有一套当前验收口径。
