# Anki 制卡

将 Markdown 笔记、词表、现成问答或完形填空转换为卡片。

## 1. 对齐批次

从材料和环境推断配置，只询问阻塞预览的缺项：

- 来源路径/内容与卡片类型。
- 根牌组、子牌组映射、笔记类型、字段、正反面、来源链接、标签和需保留的 HTML。
- 判重委托 `nnf anki` / AnkiConnect，默认整个集合判重，重复项跳过并记录；仅明确要求时创建重复项。

每张候选配置明确，未验证信息标为假设时完成。

## 2. 解析材料

按章节与语义知识点划分，保留层级、来源行号；基础卡聚焦一个回忆目标，答案来自材料，补充内容单独标明。相同输入与规则产生相同牌组、字段和卡片边界。

Markdown 笔记默认每文件一张卡，记录 frontmatter `id`，子牌组取文件名去数字前缀与 `.md`：

| 配置           | 默认值                                                    |
| -------------- | --------------------------------------------------------- |
| 根牌组         | `<topic>`；未指定时作为预览假设                           |
| 笔记类型、字段 | `基础`；`正面` / `背面`                                   |
| 正面           | `根牌组-章节名-知识点`                                    |
| 背面           | `<a href="https://wiki.kongxiaohan.cn/<id>">跳转wiki</a>` |

链接基址与 id 齐全才生成链接，否则背面格式待确认。每张候选有稳定源标识或 Markdown 范围，每个源条目恰好归入候选或排除之一时完成。

## 3. 预览确认

版本递增（v1、v2…），标明源条目与候选总数。每候选一行，展示唯一序号、来源、完整牌组路径及全部实际字段（HTML 原样）；公共类型、映射、标签与判重策略集中列出，差异入行。列明排除及原因、假设、未验证项和冲突。

行数等于候选数、覆盖全部源条目、足以复现批次，且当前版本获用户明确确认后进入创建。用户修改、来源/映射改变或实际模板、字段、目标状态与预览不符时，重新预览并确认。

## 4. 创建

先读 `/nano-flow-cli` 的 Anki 路由，命令与 option 以 `nnf anki --help` 为准。仅通过 `nnf anki` 经 AnkiConnect 写本机 Anki，不直接读写数据库/collection。

创建缺失牌组，按确认序号与判重策略逐条或批量写入；工具明确的重复记跳过，其他错误记失败并保留原因。

**完成条件**：创建数 + 跳过数 + 失败数 = 已确认候选数，每个结果对应唯一预览序号。

## 5. 回读核验

从 Anki 回读笔记，逐项比对牌组、类型和关键字段。报告确认版本、候选总数、各牌组创建数、类型与映射、创建/跳过/失败数及原因、核验方法和未解决问题。

回读与预览已逐项核对、计数和原因符合实际、不一致项均已明列时完成。
