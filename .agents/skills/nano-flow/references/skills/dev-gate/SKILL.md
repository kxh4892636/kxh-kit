# Dev Gate

以唯一、可核查的 spec、issue 或已确认设计为权威输入，交付 `ready` 或 `not ready`；前置未决时保持 `not ready`。

1. **准入**：核对输入已澄清、相关领域结论已落盘。从现场文件和工具查明事实，只将影响执行边界的未决选择交给用户。权威输入唯一、完成证据可核查且未决项清空时完成。
2. **基线**：从权威输入、工作区配置和用户约束建立或复用三项基线：
   - **工作环境**：实现、运行与验证所需的环境、服务和入口。
   - **执行契约**：范围、固定比较点、步骤、停止点、交付物和状态变更授权。
   - **质量门禁**：`/code-test` 与 `/verifying` 的最小集合，每项有事实来源、执行入口和通过条件。

   三项完整、无矛盾且未决项清空时完成。

3. **交接**：提交简短基线卡，按 Flow context 与已有授权取得确认；仍适用的既有确认直接复用。基线确认成立时交付 `ready`。

实现期间基线实质漂移时，更新受影响的权威输入并重新执行本 gate。
