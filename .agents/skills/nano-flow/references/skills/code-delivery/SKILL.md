# delivery

## 交付流程

1. **基线**: 遵循 `## dev gate` , 明确交付基线, 等待用户手动确认, 不可自动进入实现;
2. **实现**：遵循 `/code-spec skill`，完成全部代码实现。
3. **测试**：补齐所需测试，通过基线内全部测试；覆盖率采用仓库口径，增量覆盖率 >= 80% 为准; 无法测量则标记未验证。
4. **验收**：执行 `## verifying`, 进行代码验收。
5. **提交**：提交 commit;

## dev gate

基于 spec、issue 或已确认设计作为权威来源, 根据工作区事实和用户输入, 明确三项交付基线;

- **工作环境**：实现、运行与验证所需的环境、服务和入口。
- **执行契约**：范围、固定比较点、步骤、停止点、交付物和状态变更授权。
- **质量门禁**：代码测试 和 `## verifying` 的最小集合。

代码交付期间基线实质漂移时，更新受影响的权威输入并重新执行本 gate。

## verifying

1. **选择门禁**：从工作区声明的代码规范, 静态检查, 测试, 构建, 代码审查, 运行态和消费者路径中选取验收门禁的最小集合；选中代码审查时执行下方 `## code review`。
2. **执行门禁**：按依赖顺序依次执行最小集合中的门禁;
3. **最小循环**：从最早失败门禁取证, 做最小修复，从最早受影响门禁重验;

基线内所有适用门禁通过且审查发现已处理时完成验收；未执行或未通过项明确记录，保持待验收。

## code review

启动两个 subagent, 并行审查;

- **Spec**：读取交付产物对应的 story, spec, issues, adr, context 和其他来源, 验证是否符合工作需求;
- **Standards**：基于已有知识, 额外遵循 `AGENTS.md` 和 `/code-spec skill`, 判断交付产物是否符合工作规范;

汇总去重后逐项修复或说明不采纳的依据；修复后复验受影响门禁并复查原发现，所有项均有结论且无未解决的阻断项时结束审查。
