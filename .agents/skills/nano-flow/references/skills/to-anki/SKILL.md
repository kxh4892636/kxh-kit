# Anki 制卡

将用户资料转换为 Anki 卡片, 遵循流程 **对齐 → 解析 → 预览 → 确认 → 创建 → 核验**.

## 1. 对齐批次

从用户材料和当前环境中推断可验证的信息, 只询问会阻塞预览的缺项:

- 源材料: 路径, 文件列表或用户直接提供的内容;
- 卡片类型: 学习笔记基础卡, 词汇卡, 问答卡或完形填空卡;
- 目标: 根牌组, 子牌组映射, 笔记类型和字段映射;
- 格式: 正反面格式, 来源链接, 标签及需要保留的 HTML;
- 重复策略: 委托 `nnf anki` / AnkiConnect 判重, 默认范围为整个集合, 跳过重复项并记录; 只有用户明确要求时才创建重复项;

**完成标准：** 每张候选卡的来源, 目标牌组, 笔记类型, 字段映射, 格式, 重复策略都有明确值; 所有未验证信息均已标为假设.

## 2. 解析源材料

原材料按章节和语义知识点划分, 保留标题层级与来源行号

所有候选卡都应满足:

- **原子化** 一张基础卡聚焦一个主要回忆目标;
- **忠实** 答案只来自源材料, 补充内容必须单独标明;
- **可追溯** 记录来源, 或原始条目的稳定标识;
- **可复现** 相同输入和规则产生相同的牌组, 字段与卡片边界.

### Markdown 学习笔记约定

- 记录 markdown 文件可能包含的 YAML frontmatter 中的 `id`; 子牌组名取文件名移除数字前缀和 `.md` 后的部分, 例如 `010-Go-入门.md` → `Go-入门`; 默认一个 markdown 对应一个 anki 卡片;
- 默认配置: 根牌组以 `<topic>` 作为预览假设(用户未指定时); 笔记类型 `基础`, 字段为 `正面` 和 `背面`; 正面 `根牌组-章节名-知识点`; 背面 `<a href="https://wiki.kongxiaohan.cn/<id>">跳转wiki</a>`;
- 只有链接基址与 `id` 同时存在时才生成链接; 缺少任一项时, 把背面格式列为待确认.

**完成标准：** 每张候选卡都能追溯到一个源条目或明确的 Markdown 范围, 每个源条目恰好归入候选或排除之一.

## 3. 生成强制预览

每次预览分配递增版本号, 例如 `v1`, `v2`. 列出全部候选的来源标识, 完整牌组路径和全部字段的实际值, HTML 按原始值展示. 公共笔记类型, 字段映射, 标签与重复策略集中列出, 差异写入对应行; 同时展示解析得到的排除项及原因, 假设, 未验证项和冲突.

以下示例取自 Anki 中的现有笔记, 来源使用对应 Markdown 的 frontmatter `id`; 演示按默认重复策略再次创建这一条候选的预览:

```markdown
预览版本: v1
源条目: 1
候选卡片: 1
笔记类型: 基础
字段映射: 正面 → 正面, 背面 → 背面
标签: []
重复策略: AnkiConnect 判重, 范围=整个集合, 重复项=跳过

|   # | 来源 id                              | 目标牌组          | 正面                   | 背面                                                                                      |
| --: | ------------------------------------ | ----------------- | ---------------------- | ----------------------------------------------------------------------------------------- |
|   1 | 44e45fcf-18c2-5086-a85f-5ada6fad20f5 | kxh::编程语言::Go | Go-并发-Mutex与RWMutex | `<a href="https://wiki.kongxiaohan.cn/44e45fcf-18c2-5086-a85f-5ada6fad20f5">跳转wiki</a>` |

排除项: 无
假设与未验证项: 无
冲突: 第 1 项已存在于目标牌组, 笔记 ID 为 1784645722316; 再次创建预期跳过.
```

**完成标准：** 表格行数与候选总数一致, 已展示解析阶段的覆盖结果与排除原因; 仅凭预览即可复现待执行批次.

## 4. 等待确认

用户明确确认当前预览版本后, 才进入创建. 用户提出修改, 源文件发生变化或任何字段映射改变时, 生成下一个预览版本并重新等待确认.

**完成标准：** 当前版本获得明确确认, 且确认后批次内容未发生变化.

## 5. 创建

写入 Anki 一律使用 `nnf anki` 命令(经 AnkiConnect 操作本机 Anki), 不直接读写 Anki 数据库或 collection 文件; 具体命令与 option 以 `/nano-flow-cli` 的 Anki 路由和现场 `nnf anki --help` 为事实来源.

1. 创建缺失的目标牌组, 并按确认预览的序号与重复策略逐条或批量创建卡片;
2. 将工具明确返回的重复结果记为跳过, 其他创建错误记为失败, 保留对应原因;
3. 若实际模板, 字段或目标状态与预览不一致, 返回预览步骤生成新版本.

**完成标准：** `创建数 + 跳过数 + 失败数 = 已确认候选数`, 且每个结果都能映射回预览中的唯一序号.

## 6. 核验交付

写入后从 Anki 回读目标笔记, 逐项核对牌组、笔记类型和关键字段. 报告已确认的预览版本与候选总数、各牌组创建数、笔记类型与字段映射、创建/跳过/失败数及原因、核验方式与结果及未解决问题.

**完成标准：** 从 Anki 回读的目标笔记在牌组, 笔记类型和关键字段上与已确认预览一致, 报告中的数量与原因均与回读结果相符; 不一致项已明确列出.
