# 原型

原型是**回答一个问题的一次性代码**。按用户输入与周围代码选择：

- 逻辑/状态模型的手感 → [LOGIC.md](LOGIC.md)：可分享的单文件 HTML，自由操作与分页签引导走查，让非开发者驱动边界用例。
- UI 外观 → [UI.md](UI.md)：同一路由的多个独特变体，用 URL search param 与底部浮动栏切换。

问题含糊且用户在场时询问；联系不上时按代码默认匹配（后端模块 → 逻辑，页面/组件 → UI），在原型顶部声明假设。

## 共同规则

1. **一次性**：放在所服务模块或页面旁，名称明确标记原型；UI 路由遵循项目约定。
2. **运行零门槛**：UI 由任务 runner 一条命令启动；逻辑 demo 双击单个 HTML 即开。
3. **内存状态**：默认不持久化；问题涉及数据库时用 scratch DB 或清楚标记“PROTOTYPE，随手可删”的本地文件。
4. **快速取证**：手工走查，不写测试；错误处理以能跑为限，不做抽象。
5. **暴露状态**：每次动作或变体切换后打印或渲染全部相关状态。
6. **证据收口**：动手前写明问题与判断依据。可运行、约定场景或全部变体已走查、观察及访问入口已提供时完成交付；需用户判断则标「待反馈」。观察支撑结论且所需判断已确认时，问题才算回答。
7. **捕获与交付**：原型作为 primary source 提交到一次性分支，不进 main；在 issue 或 commit 记录问题、观察、结论/待反馈状态与指针。正式实现吸收已确认决策：逻辑模块可作候选代码复用，UI 按选定设计实现，均完成项目规范、审查与测试；手工走查只证明实验结果。

## 设计中的写作

文案与间距、色彩同样需要设计：先明确要说什么，以及如何帮助用户走完整个体验。

- **用户视角**：使用用户认知和控制的领域名称，具体、平实地说明功能，避免推销与抖机灵。
- **动作一致**：主动语态，控件说清结果，同一动作全程同名。
- **失败与空态**：用界面自身的声音说明错误与修复入口；空态邀请行动，不道歉或渲染情绪。
- **语域**：对话式、平实动词、sentence case、无填充词，符合品牌与受众。
- **单一职责**：标签标注、示例演示，每个元素只承担自己的角色。
