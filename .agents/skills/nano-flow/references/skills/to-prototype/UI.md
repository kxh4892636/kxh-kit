# UI 原型

用于探索页面外观、比较 dashboard 方案或尝试设置页布局: 在同一路由生成 **数个截然不同的 UI 变体**, 用户在浏览器用底部浮动栏比较, 选定或组合后丢弃其余变体. 逻辑/状态问题使用 [LOGIC.md](LOGIC.md).

## 两种子形态: 强烈偏好 A

原型应放在真实 header、sidebar、数据与密度中判断, 避免孤立展示让所有变体都显得不错:

- **A — 挂在既有页面 (首选)**: 有现成宿主就使用它, 包括自然属于其中的新区块、卡片或流程步骤. 既有数据获取、params、鉴权全部保留在切换逻辑之上, 只切换渲染子树.
- **B — 新建页面 (最后手段)**: 仅用于没有合理宿主的新顶层界面或流程; 按 [SKILL](SKILL.md) 的命名与路由规则建一次性路由.

## 设计原则

以擅长独特视觉识别的小型工作室设计负责人标准, 为每个变体做出针对简报、有主张的配色、字体与布局, 承担一处可自圆其说的美学冒险, 避免模板感.

- **主题**: 简报未定产品/主题时, 设计前自行明确具体主题、受众、页面唯一职责及理由. 可参考用户偏好记忆、项目上下文和过往设计; 全程使用真实简报内容及主题的材料、工具、造物、行话.
- **Hero 是论点**: 用主题最有特征的事物开场, 可用标题、图、动画、live demo 或互动. 大数字配小标签、辅助统计加渐变仅在确实最优时使用.
- **字体即个性**: 刻意搭配 display/body, 避免通用默认组合; 明确 type scale、字重、字宽和间距, 让字体处理可被记住.
- **结构即信息**: 编号、eyebrow、分隔线、标签须表达真实内容. 使用前质疑其依据; 编号仅用于顺序有意义的流程、时间线等序列.
- **动效服务主题**: 按方向选择加载编排、滚动揭示、悬停微交互或环境氛围; 一个编排过的瞬间通常胜过零散特效, 过量会显得像 AI 生成.
- **复杂度匹配愿景**: 极繁执行繁复; 极简精确处理间距、字体和细节.
- **文案**: 简报缺内容时自行写作, 同样避免模板感; 遵循[设计中的写作](#设计中的写作).

## 流程

### 1. 写下问题, 定下 N

默认 **3 个变体, 上限 5 个**, 避免差异被噪音稀释. 在原型所在位置或文件顶部注释用一行写明问题与计划, 供用户随时反驳, 如「设置页的三个变体, 在既有 `/settings` 上通过 `?variant=` 切换」.

### 2. 为每个变体构思设计计划

先校准三种 AI 默认风格: ① 暖奶油色 (约 `#F4F1EA`) + 高对比衬线 display + 赤陶点缀; ② 近黑 + 单一酸性绿或朱红亮色; ③ broadsheet + 发丝分隔线 + 零圆角 + 密集多栏. 它们可适用, 但不应跨主题套用. **简报明确的方向永远优先**, 包括点名这些风格时; 留白处做独特选择, 平衡擅长的做法与实验学习.

先为每个变体拟紧凑的 token 计划:

- **色彩**: 4–6 个命名 hex 值.
- **字体**: 至少 2 个角色; 有性格且克制使用的 display、互补 body, 必要时为 caption/数据加 utility.
- **布局**: 一句话概念 + ASCII 线框图, 用于构思和比较.
- **签名元素**: 恰当体现简报、让页面被记住的唯一独特元素.

再对照简报审查: 通用默认部分须修订并说明改动与理由, 可用类似 prompt 检查是否殊途同归. **确认相对独特性后才写代码**. 构思迭代尽量在思考中完成, 有较高把握取悦用户时才展示.

### 3. 生成截然不同的变体

严格实现修订后的计划, 每个颜色/字体决策均由计划推导; 符合页面目的、可用数据及项目组件库/样式体系, 清晰导出 `VariantA`、`VariantB` 等组件.

- **结构差异**: 布局、信息层级、主要 affordance 都须不同, 仅换色或微调卡片网格不算. 草稿太像时, 用「不许用卡片网格」这类明确约束重做一个.
- **布局独立**: 可共享 `<Header>`, 不共享 `<Layout>`, 保留每个变体推翻整个布局的自由.
- **只读**: 足以回答外观问题; 确需变更数据时接 stub, 不接真实 mutation.
- **CSS specificity**: 检查 class 叠加抵消, 尤其 `.section` 与 `.cta` 等选择器以及 section 间的 padding/margin.

### 4. 接在一起

两种子形态都在路由上按框架实现切换组件: 读取 `?variant=` (缺省 `A`), 将 `data` 传给匹配 key 的变体, 同时渲染接收全部 keys 与当前 key 的 `PrototypeSwitcher`. B 挂载在 `/prototype/<name>` 一次性路由.

### 5. 构建浮动切换栏

在项目共享 UI 位置放单一组件, 两种子形态复用. 小条固定于屏幕底部中央:

- **左箭头 / 当前标签 / 右箭头**: 上一个/下一个均循环回绕; 标签显示 key, 有导出名字时附上, 如 `B (Sidebar 布局)`.
- **URL**: 点击箭头用框架 router 更新 search param (如 `router.replace`、`navigate`), 支持分享和刷新保留.
- **键盘**: `←` / `→` 同样切换; 焦点在 `<input>`、`<textarea>` 或 `[contenteditable]` 时不拦截.
- **外观**: 明显区别于被评估页面, 如高对比胶囊加柔和阴影.
- **生产隐藏**: 用 `process.env.NODE_ENV !== 'production'` 或等价检查门控, 防止误并后发给用户.

### 6. 交出去

提供 URL 和 `?variant=` 的全部 keys, 供用户得空比较; 接受组合反馈, 如「B 的 header 配 C 的 sidebar」.

### 7. 捕获答案并清理

按 [SKILL](SKILL.md) 的「按证据收口」与「捕获与交付」记录选择及理由, 归档整套变体. 正式实现时, **A** 将胜者折入既有页面, 从 main 移除落选变体和切换栏; **B** 将胜者提升为正式路由, 从 main 移除一次性路由和切换栏.

## 克制与自我批判

大胆集中在签名元素, 周围保持克制, 删除不服务简报的装饰. 默默达到质量下限: 响应式覆盖移动端、可见键盘焦点、尊重 reduced motion. 构建中持续自评, 环境支持就截图; 尝试新东西, 有便捷记录处可记下尝试, 供后续迭代参考.

## 设计中的写作

文字服务理解与使用, 投入与间距、色彩同等的刻意. 动笔前明确需要说什么、怎样帮助用户走完整个体验.

- **用户视角**: 用用户认知和控制的名称, 如「通知」而非「webhook 配置」; 平实说明功能而非推销, 具体优于抖机灵.
- **动作明确一致**: 默认主动语态; 控件说清结果, 如「保存更改」而非「提交」. 同一动作全流程同名, 如「发布」→「已发布」toast.
- **失败与空态指路**: 用界面自身的声音明确解释错误及修复方法, 不道歉或渲染情绪; 空态邀请行动.
- **语域**: 对话式、平实动词、sentence case、无填充词, 匹配品牌与受众.
- **单一职责**: 标签标注、示例演示, 每个元素只做一件事.
