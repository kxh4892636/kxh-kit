# UI 原型

在同一路由比较多个 UI 变体，选定或组合后丢弃其余。逻辑/状态问题见 [LOGIC.md](LOGIC.md)；文案遵循 [共同写作规则](SKILL.md#设计中的写作)。

## 选择宿主

在真实 header、sidebar、数据与密度中评估：

- **A：挂在既有页面（首选）**。保留数据获取、params、鉴权于切换逻辑之上，只切换渲染子树；适用于现有页面及自然属于它的新区块或步骤。
- **B：新建页面**。仅限没有合理宿主的新顶层界面/流程，按项目路由约定创建一次性页面。

## 设计原则

以小型设计工作室负责人标准，为每个变体明确针对简报的配色、字体与布局，承担一处有理由的美学冒险。

- **主题**：简报未定时先明确主题、受众、页面唯一职责与理由；参考用户偏好、项目与过往设计，使用真实简报内容、材料和行话。
- **Hero 是论点**：用主题特征开场，选择标题、图、动画或互动；大数字配标签、统计加渐变仅在确实最优时使用。
- **字体即个性**：刻意搭配 display/body，确定 scale、字重、字宽与间距。
- **结构即信息**：编号、eyebrow、分隔线与标签有真实依据；编号只用于有意义的顺序。
- **动效服务主题**：选择加载、滚动、悬停或环境编排；集中表达，控制零散特效。
- **复杂度匹配愿景**：极繁执行繁复，极简精确处理间距、字体和细节。
- **文案**：缺失内容自行补齐，遵循共同写作规则并体现简报特征。

## 1. 明确问题与变体

默认 3 个变体，上限 5 个。在原型位置或文件顶部用一行注释写明问题、数量与计划，供用户反驳。

## 2. 设计计划

简报指定方向优先；留白处做独特选择，兼顾熟悉做法与实验。校准常见模板风格（暖奶油/衬线/赤陶、近黑/单亮色、broadsheet/细线/零圆角/多栏），仅在契合主题时采用。

每个变体先写紧凑 token 计划：4–6 个命名 hex 色值；至少 display/body 两个字体角色，按需加数据/说明字体；一句布局概念和 ASCII 线框图；一个体现简报的签名元素。

对照简报修订通用默认项并说明理由，可用相似 prompt 检查方案是否趋同。确认相对独特性后编码；构思迭代尽量内部完成，有较高把握时再展示。

## 3. 生成变体

按计划实现全部颜色与字体，符合页面目的、数据和项目组件/样式体系，清晰导出 `VariantA`、`VariantB` 等组件。

- 布局、信息层级与主要 affordance 实质不同；仅换色不算。太相似时给一个变体增加明确结构约束后重做。
- 可共享 Header，各自拥有 Layout。
- 默认只读；确需改数据时接 stub。
- 检查 CSS specificity、class 叠加，以及 section 间 padding/margin。

## 4. 接入切换

路由读取 `?variant=`，默认 A，将 data 传给对应变体，并渲染接收全部 keys 与当前 key 的 `PrototypeSwitcher`。B 使用 `/prototype/<name>` 一次性路由，并遵循项目约定。

共享 UI 位置放一个切换栏供两种形态复用，固定屏幕底部中央：

- 左箭头 / 当前标签 / 右箭头，循环切换；标签显示 key，按需附导出名。
- 使用框架 router 更新 search param，支持分享和刷新。
- `←`/`→` 同样切换；焦点在 input、textarea、contenteditable 时保持编辑行为。
- 用高对比胶囊与柔和阴影等形态区别于被评估页面。
- 以 `process.env.NODE_ENV !== 'production'` 或等价检查隐藏生产环境的切换栏。

## 5. 交付与吸收

提供 URL 和全部变体 keys，接受组合反馈。按 [证据收口与归档规则](SKILL.md#共同规则) 记录选择、理由和整套变体。

正式实现时：A 将胜者折入既有页面，移除落选变体与切换栏；B 将胜者提升为正式路由，移除一次性路由与切换栏。main 只保留正式实现。

## 质量下限

大胆集中于签名元素，周围保持克制，删去不服务简报的装饰。覆盖移动端、可见键盘焦点与 reduced motion；持续自评，环境支持时截图。尝试新做法，有便捷记录处时留下经验。
