# Questing

使用同一循环逐轮拷问，复用仍成立的结论和确认；领域文档更新遵循 `/domain skill`。

## 逐轮拷问

**Design tree** 按决策依赖展开，答案决定下游问题。**Frontier** 是前置已有答案、当前可回答的全部问题。

1. **取证**：事实从代码与工具查明并保留来源；需进一步探索时委派 subagent，将其作为未决前置，仅暂停下游，其余 frontier 继续。
2. **拷问**：每轮覆盖整个 frontier，问题按本 quest 唯一递增编号，附推荐与理由；依赖本轮未决答案的问题留到下一轮。
3. **修订**：按模式处理回答与评价，通过 domain 将结论就地写入权威文档, 保留用户反馈及处理结论；更新选择、被排除路径与假设，重算 frontier；上游改变时复核并修订失效的下游结论。
4. **收敛**：可达问题均已处理、frontier 为空、无静默假设，用户反馈有结论；按模式确认后，由 domain 同步进度与恢复入口并校验。

## 每轮记录

在相关 note 中增加「拷问记录」，按轮保留仍影响当前决策的问答；合并重复问答时保留来源、反馈与结论。

```markdown
### 第 {round} 轮

#### Q{question} — {标题}

- 问题：{问题及必要的互斥选择}
- 前置问题：{Q 编号或无}
- 下游边界：{该答案会改变什么}
- 推荐答案及理由：{选择与证据}
- 修改意见：{用户反馈或待评价}
- 处理结论：{已确认/暂定/待取证，以及受影响的文档位置}

每题重复以上结构，编号递增, 按轮追加，补充说明始终位于末尾。

### 补充说明

{尚未被问题覆盖的用户输入及处理结论；没有则写无}
```

## 模式

- manual（默认）：每轮 agent 取证并提出建议，等待用户评价后推进；空白修改意见本身不表示确认，复用用户已给出的明确授权。
- auto：agent 基于证据回答并推进全部轮次；无法确认的事实保留为待定和恢复条件，不将猜测写成已确认事实。
