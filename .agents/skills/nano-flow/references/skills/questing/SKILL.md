# Questing

按任务与已有产物选择分支，使用 `## design tree` 逐轮明确, 复用仍成立的结论和确认：

| 分支     | 触发与流程                                                                       |
| -------- | -------------------------------------------------------------------------------- |
| `story`  | 角色、收益或可验收的用户结果尚未明确, 生成或打磨用户故事： [STORY.md](STORY.md); |
| `design` | 用户结果已明确，进行拷问计划、决策或设计： [DESIGN.md](DESIGN.md);               |

## design tree

**Design tree** 按决策依赖展开，答案决定下游问题。**Frontier** 是前置已有答案、当前可回答的全部问题。

按 **rounds** 推进：

1. **取证**：事实从代码与工具查明并保留来源；需进一步探索时委派 subagent，将其作为未决前置，仅暂停下游，其余 frontier 继续。事实查明后才回答依赖决策；
2. **提问**：每轮覆盖整个 frontier，问题按本 quest 唯一递增编号，附推荐与理由；依赖本轮未决答案的问题留到下一轮。
3. **推进**：记录选择、排除分支、新节点和判断假设，再重算 frontier；上游改变使前置失效时，下游问答一并失效。
4. **收敛**：所有可达分支已访问、frontier 为空且无静默假设。
