# 设计拷问

按 [Design tree](DESIGN-TREE.md) 推进，每轮由 agent 自动回答，先形成草案，再交用户统一评价。涉及领域模型或 ADR 变更时，先读取 [DOMAIN.md](DOMAIN.md)，以现有 glossary 与 ADR 为约束；通用讨论的权威文档由调用者维护。

## 1. 自动回答

每轮自动回答并记录：

1. **问题**：列出互斥选择、前置问题与下游边界。
2. **选择**：agent 为每题作出一项选择并说明理由；与推荐不同时解释分歧。
3. **记录**：首次写入前读取 [TEMPLATE.md](TEMPLATE.md)，在工作区根创建或续写 `.flow/quest/YYYY-MM-DD-中文工作名.md`。日期取首次创建的本地日期，同一 quest 始终续写同一文件；同名文件属于其他 quest 时细化工作名。把本轮全部问题与答案插入末尾的「补充说明」之前，替换所有占位符，保留推荐与选择的可比较性。

每题恰好有一项选择及理由且记录完整时，本轮完成。重复至拷问收敛、全部问题已进入审阅文件；此时仍为草案。

## 2. 统一评价

提供审阅文件路径，请用户统一评价全部问题，并在「补充说明」填写未被问题覆盖的信息。等待用户说明评价完成，再读回全部轮次，按依赖顺序重放：

- 空白「修改意见」确认 agent 选择，但只对仍可达且前置成立的节点生效。
- 非空意见作为新答案或约束；能唯一确定答案时替换选择，否则重开节点。
- 「补充说明」按事实、约束或决策纳入 tree，HTML 注释不算内容；新事实继续取证，判断进入新 frontier。

全部反馈已纳入或因依赖失效而排除、新事实已查明或成为 blocker、新 frontier 已完整计算时，本轮评价完成。反馈均为空时确认草案；产生新 frontier 时返回第 1 节。

## 3. 收口

拷问收敛且未知事实已查明；审阅文件包含全部问题、推荐与选择及各自理由、修改意见，且「补充说明」位于末尾；复述最终结论并获用户明确确认共同理解后完成。用户确认前不执行实现。

有领域变更时，按 [DOMAIN.md](DOMAIN.md) 同步已确认结论并通过校验；其余讨论只直接维护审阅文件。
