# 工作流与交接文档

将当前工作或用户参数拆分成**工作流**（tracer bullet 垂直切片方式），并确认工作流的边界与依赖，再用**交接文档**把工作流和已有上下文交给每个独立会话。

## 1. 探索代码库（可选）

如果尚未探索代码库，先了解代码现状。探索时读取 `CONTEXT.md`（如存在），使用项目的领域语言辅助工作流的确认；同时读取所触及区域的 ADR，使工作流的确认遵循既有架构决策。

## 2. 确认工作流

运行 `/grilling`，讨论范围仅限于如何拆分当前工作，各工作流的具体实现和验证，后续留给独立会话讨论。

工作流的拆分使用 **tracer bullet** 垂直切片方式：

- 工作流以一项完整业务能力或用户路径作为边界，能够独立实现和验证。
- 工作流贯穿业务领域的所有层级（例如编程领域的前端、后端、数据库、测试等），纵向而非层级的横向切片。
- 工作流的执行需要直接依赖的工作流的完成。直接依赖为 `无` 的工作流可立即执行。

每个工作流只包含：

- 唯一标题：`{ID}-{TITLE}`；
- 一句话描述；
- 与其他工作流的边界；
- 直接依赖：`无`，或其他工作流的 ID 列表。

向用户展示完整工作流，询问用户：

1. 拆分方式是否合适？（拆分粒度/边界/垂直切片）
2. 依赖关系是否正确？
3. 是否有需要继续拆分或合并的工作流？

持续迭代，直至用户确认。

## 3. 生成交接文档

用户确认工作流后调用 `/handoff`，生成**交接文档**。

完整读取生成的交接文档，确认其中包含：

- 已确认的完整工作流；
- 每个工作流的直接依赖；
- 当前会话已有的上下文；
- 相关产物的路径或链接（如有）。

各工作流尚未确定的细节后续在工作流的独立会话中决定。

每个工作流及其依赖关系均可从交接文档还原、上下文完整、相关引用无遗漏且文档可读取时，本步骤完成。

## 4. 创建工作流独立会话

使用当前平台提供的会话创建能力，为每个工作流创建**独立会话**。

每个独立会话必须：

- 推理等级设置为「high」；
- 使用工作流标题作为会话标题；
- 获得该工作流的完整定义、完整交接文档和交接文档本地路径；

每个工作流的独立会话创建成功后，等待用户指令，禁止执行任何操作。

每次创建成功后立即记录工作流与会话的映射；重试时只处理创建失败的工作流。

向用户报告交接文档路径、完整的工作流与会话映射、工作流的依赖关系，以及仍未成功的创建失败。
