# 工作流与交接文档

将当前工作或用户参数拆分成**工作流**（tracer bullet 垂直切片方式），并确认工作流的边界与依赖，再用**交接文档**把工作流和上下文交给每个独立会话。

## 1. 探索代码库（可选）

如果尚未探索代码库，先了解代码现状。探索时读取 `CONTEXT.md`（如存在），使用项目的领域语言辅助工作流的确认；同时读取所触及区域的 ADR，使工作流的确认遵循既有架构决策。

## 2. 确认工作流

运行 `/grilling`，讨论范围仅限于如何拆分当前工作，各工作流的具体实现和验证，后续留给独立会话讨论。

工作流的拆分使用 **tracer bullet** 垂直切片方式：

- 工作流以一项完整业务能力或用户路径作为边界，能够独立实现和验证。
- 工作流贯穿业务领域的所有层级（例如编程领域的前端、后端、数据库、测试等），纵向而非层级的横向切片。
- 工作流的执行需要直接依赖的工作流的完成。直接依赖为 `无` 的工作流可立即执行。

每个工作流只包含：

- 唯一标题：`{ID}-{TITLE}`；
- 一句话描述；
- 与其他工作流的边界；
- 直接依赖：`无`，或其他工作流的 ID 列表。

向用户展示完整工作流，询问用户：

1. 拆分方式是否合适？（拆分粒度/边界/垂直切片）
2. 依赖关系是否正确？
3. 是否有需要继续拆分或合并的工作流？

持续迭代，直至用户确认。

## 3. 生成交接文档

用户确认工作流后，为每个工作流生成一份**交接文档**，使其能够在独立会话中无损续接。

每份交接文档包含：

- 该工作流的完整定义，包括目标、边界、交付物和完成条件；
- 该工作流的直接依赖；
- 建议调用的 skill 及调用时机；
- 所需上下文与相关产物的路径或 URL（如有）。

交接文档只携带该工作流所需的上下文。不重复 PRD、spec、ADR、commit、diff 等已有产物，通过路径或 URL 引用。尚未确认的细节后续在独立会话中决定。

当每个独立会话仅凭交接文档及其引用即可定位全部所需上下文、识别直接依赖，并明确第一步行动与完成条件时，本步骤完成。

## 4. 创建工作流独立会话

使用当前平台提供的会话创建能力，为每个工作流创建**独立会话**。

每个独立会话必须：

- 推理等级设置为「medium」；
- 使用工作流标题作为会话标题；
- 获得该工作流的交接文档；

每个工作流的独立会话创建成功后，等待用户指令，禁止执行任何操作。

每次创建成功后立即记录工作流与会话的映射；重试时只处理创建失败的工作流。

向用户报告完整的工作流与会话映射、工作流的依赖关系，以及仍未成功的创建失败。
