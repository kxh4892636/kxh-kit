# Create Domain Skill

把业务模块的当前实现整理成一张可重查的**领域地图**，并交付为可自动调用的领域 skill。代码、契约和配置提供当前实现的证据，领域文档提供术语与决策的证据，用户裁决意图与取舍；外部资料和通用规则通过引用路由。先考古，后写作，全程维护**证据账本**。

## 1. 锚定边界

确认目标业务模块、仓库根目录、skill 名称和交付位置。读取适用的仓库规则；`DOMAIN.md` 存在时，按其路由读取 `CONTEXT.md` 和相关 ADR。沿用已经确认的领域术语与决策，并保留指向其事实来源的引用。领域文档缺失时，继续以仓库事实完成考古。

建立调查矩阵，为每项业务能力记录：

- 入口、消费者以及明确的职责边界；
- 实际存在的层次，包括用户界面、客户端状态与接口、服务端入口、应用与领域逻辑、持久化、异步处理、数据任务、外部系统和运行环境；
- 实际存在的横切边界，包括鉴权、权限、租户、敏感数据、配置和功能开关；
- 当前事实、已确认目标与待核实假设的状态。

完成标准：调查矩阵覆盖所有已发现的业务能力、适用层次和横切边界；每个未适用项都有仓库证据，当前事实与目标设计可以逐项区分。

## 2. 完成考古

遵循仓库规定的检索优先级，从业务入口沿调用和数据流追踪到最终副作用，再反向确认消费者。检索代码、契约、配置、构建与生成规则、测试、运行脚本、可观测资产和交付配置；用文档确认语义与决策，用代码和配置核对当前实现。

为调查矩阵的每一项在证据账本中记录结论、来源锚点、置信度和状态，并闭合四个问题：

1. **职责**：它负责什么，边界在哪里；
2. **依赖**：它依赖谁，谁依赖它，契约与数据由谁持有；
3. **变更**：契约或数据模型、生成物、实现、消费者与联调按什么顺序变化；
4. **证明**：本地运行、数据准备、测试替身与真实依赖如何分界，哪些静态检查、构建、分层测试、集成、端到端、运行态或人工验收能够证明正确，以及如何借助日志、指标、链路、前端异常、任务状态或数据质量完成诊断。

把发布、迁移、兼容、回滚、重跑和故障排查纳入对应链路的运行闭环。目标设计保持“已确认目标”状态，直到仓库出现落地证据。

目标 skill 使用业务术语、符号、契约、配置键和稳定入口作为定位锚点。具体路径仅在其稳定性由仓库约定、模块边界或工具链支撑时保留；代码行为通过锚点回查当前实现。外部资料和通用工程规则留在各自事实源，目标 skill 只提供到达它们的链接或 skill 路由。

完成标准：调查矩阵的每个适用项都闭合职责、依赖、变更和证明；每个当前事实都有来源锚点，跨层契约的源头、消费者和同步顺序形成端到端闭环。

## 3. 关闭未知项

把证据账本中的未确认项分流：仓库能够证明的事实继续考古；业务意图、历史原因、权衡或仓库无法证明的判断交给用户。每轮只询问一个会改变目标 skill 内容的问题，给出已有证据、冲突点和需要用户裁决的判断，获得回答后更新证据账本再继续。

用户答案、外部资料与当前实现冲突时，把各自事实来源并列呈现并请求裁决。已经确认的领域术语和架构决策保持原义。

完成标准：所有影响业务边界、依赖、变更顺序或验证依据的未知项均由仓库证据或用户裁决关闭；保留项均由用户明确接受为待核实假设。

## 4. 编写领域 skill

按仓库约定创建可自动调用的目标 skill：frontmatter 保留面向模型的 `description`，`description` 使用稳定的模块名称、业务术语和彼此不同的任务分支，每个分支只保留一个触发条件。

将 `SKILL.md` 写成领域地图的路由入口：

- 内联每个任务分支都需要的业务边界、关键关系和固定约束；
- 把仅单个分支需要的知识按关注点放入 reference，并用明确的触发条件指向它；
- 让调查矩阵中的每个适用项都有唯一归属，让已有文档和通用 skill 继续持有各自事实；
- 把每类典型变更映射为“影响层次 → 开发顺序 → 验证证据”；
- 仅为容易误判的未适用项保留边界说明；
- 标明领域地图的刷新条件：业务边界、跨层契约、依赖方向、变更顺序或验证入口发生变化。

受管范围是 `SKILL.md` 及其递归引用的 Markdown：总数不超过 21 个，每个文件最多 233 行。接近边界时依次清理失效内容和重复含义、引用已有事实源、合并过细分支；必要信息仍超出边界时，向用户报告阻塞。

完成标准：不了解模块的执行者能够借助目标 skill 定位任一代表性变更的影响面，按依赖顺序开发，并为每项交付主张找到验证证据；Claude 与 OpenAI 均可自动调用目标 skill；每项含义只有一个事实源，定位锚点均有稳定性依据，受管 Markdown 满足数量与行数边界。

## 5. 推演与确认

基于当前仓库事实，分别推演单层变更、跨层契约变更、数据或迁移变更、故障诊断或运行态验证。某类任务不适用时，推演目标 skill 能否给出有证据的边界。每次推演都记录选中的路由、识别出的影响层次、依赖顺序和验证依据；推演保持只读，修改范围限于目标 skill。

检查自动调用配置；递归枚举目标 `SKILL.md` 引用的 Markdown，核对文件数量和逐文件行数；检查 frontmatter、内部引用、单一事实来源、格式和仓库适用门禁。然后向用户提供完整草案，或提供清晰的文件清单与全文，标明用户已接受的待核实假设并请求确认。

完成标准：四类推演均得到正确路由或有证据的不适用边界，结构与仓库门禁全部通过，用户已经看到可审阅的最终草案。确认前保持草案状态，收到反馈后再提交、发布或进入后续实现。
