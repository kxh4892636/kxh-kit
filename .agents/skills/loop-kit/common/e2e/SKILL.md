# E2E

E2E 通过真实系统边界证明消费者可感知的结果。用户输入和仓库约定决定资产、工具、环境、数据与证据；通用 skill 只固定验收流程与结论门禁。

探索代码库或确定验收资产时，读取 `CONTEXT.md`（如存在），使验收资产匹配项目领域语言；同时读取所触及区域的 ADR，使验收资产遵循既有架构决策。

## 执行流程

1. **确定验收主张**：从用户目标、需求或变更范围识别消费者入口和待证明结果。完成标准：每个范围内结果都有外部可观察断言，未知前置已明确。
2. **选择或维护资产**：优先复用仓库已有资产；创建或更新 Markdown 资产时读取 [agent-driven 验收文档](documentation.md)，创建或更新代码资产时读取 [E2E 框架测试](framework-testing.md)。任务不要求持久资产时，直接选择可复现的执行路径。完成标准：所选路径能够从消费者入口执行验收主张。
3. **跑真实路径**：通过消费者可用的浏览器、协议或 CLI 入口执行，并观察系统边界上的结果。完成标准：每个范围内断言都有实际结果或可定位的失败前置。
4. **记录结论**：记录执行范围、环境与版本置信度、关键断言、证据以及 passed / failed / blocked。完成标准：结论足以判断验收主张是否成立，并能复验失败或阻塞项。

## 结论门禁

- 只有实际执行并观察到预期结果才能判定 passed；零收集、零执行或非预期 skip 不能判定 passed，无法满足的必要前置记为 blocked。
- 验收特定变更或部署时，确认运行态承载目标版本；其他运行态检查如实记录版本置信度。
- 断言与证据和验收主张相称，证据不得暴露凭证或个人数据。
