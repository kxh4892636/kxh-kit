# 分配子任务

将当前会话整理成一份**分工图**，再为每个确认的子任务创建一个用户持有的 Codex 任务。

## 流程

### 1. 讨论划分方式

运行 `/grilling`，将当前会话和用户参数视为待划分的工作。

每次只讨论一个决策，并为每个问题给出推荐答案。能从代码库查明的事实直接检索，把需要取舍的决策交给用户。持续讨论，直到分工图为每个子任务明确：

- 标题与目标成果；
- 具体交付物与验收标准；
- 范围内与范围外边界；
- 所需输入、依赖关系以及独占的文件或资源；
- 执行环境与起始状态；
- 建议使用的技能。

每个子任务应能在一个全新上下文窗口内完成，并能在本次分配后立即开始。通过调整切分边界、定义稳定的输入契约或合并依赖链来消除阻塞。分配前必须解决写入范围重叠的问题。

展示完整分工图并等待用户明确确认。只有当用户确认所有子任务、边界、就绪状态和执行环境后，本步骤才算完成。

### 2. 生成共享交接文档

用户确认后运行 `/handoff`，并使用以下交接目标：

> 为多个独立 Codex 任务执行已确认的分工图提供共享上下文。

交接文档必须保留已确认的分工图、共享决策与约束、相关产物引用、集成要求和建议使用的技能。完整读取生成的交接文档。

只有当脱敏后的交接文档已写入操作系统临时目录、绝对路径已知，并且正文包含每个已确认子任务时，本步骤才算完成。

### 3. 创建独立任务

使用 `create_thread` 创建用户持有的 Codex 任务。

对于仓库任务，先使用 `list_projects` 确定当前项目，再调用 `create_thread`。每个子任务使用分工图中确认的执行环境：独立代码修改通常使用 worktree，只读任务或明确需要共享状态的任务使用本地检出目录。保留已确认的起始状态。非仓库任务创建无项目任务。除非用户明确指定，否则沿用用户配置的模型和推理设置。

为每个确认的子任务创建一个任务；彼此独立的子任务应一起分配。

按以下模板构造每个任务的初始提示，替换所有占位内容，并原样嵌入完整交接文档：

```text
你负责已确认多任务分工中的以下子任务。

<子任务>
标题：<标题>
目标成果：<目标成果>
交付物：<交付物>
验收标准：<验收标准>
范围内：<范围内>
范围外：<范围外>
输入与依赖：<输入与依赖>
独占文件或资源：<归属范围>
建议技能：<技能>
</子任务>

开始执行前，完整阅读下方共享交接文档。以子任务块为执行边界，以交接文档为共享上下文。完成子任务并验证全部验收标准，最后报告结果、验证证据、变更产物和剩余风险。

<共享交接文档 path="<交接文档绝对路径>">
<完整交接文档>
</共享交接文档>
```

使用 `set_thread_title` 将每个新任务重命名为对应的子任务标题。每次创建成功后立即记录子任务与 Codex 任务的映射，确保重试时不会重复创建。

只有当每个确认的子任务都恰好对应一个 Codex 任务，并且每个初始提示都包含完整子任务定义和完整共享交接文档时，本步骤才算完成。

### 4. 交付分配结果

报告以下内容：

- 交接文档路径；
- 每个子任务与对应 Codex 任务的映射；
- 仅重试失败项后仍未解决的创建失败。

为每个成功创建的任务输出一条 `::created-thread{threadId="..."}` 指令；如果 worktree 初始化只返回 `clientThreadId`，则使用该标识符。

当每个确认的子任务都能追溯到唯一一个已创建的 Codex 任务时，本技能才算完成。
