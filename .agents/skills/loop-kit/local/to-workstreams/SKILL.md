# 工作流与交接文档

将当前工作拆分成一组**工作流**（垂直切片），并确认工作流间的边界与依赖，再用**交接文档**把工作流图和已有上下文交给每个独立会话。

## 1. 确认工作流图

运行 `/grilling`，讨论范围仅限于如何拆分当前工作，具体的上下文搜索和实现留给拆分后的独立会话。

以一项完整业务能力或用户路径作为工作流边界。使用垂直切片的原则，每个工作流贯穿业务领域的所有层级（例如编程领域的前端、后端、数据库、测试等）。
工作流依赖表示执行前置：工作流的执行需要直接依赖的工作流的完成。直接依赖为 `无` 的工作流可立即执行。

每个工作流只包含：

- 唯一标题：`{ID}-{TITLE}`；
- 一句话描述；
- 与其他工作流的边界；
- 直接依赖：`无`，或其他工作流的 ID 列表。

向用户展示完整工作流图，询问用户：

1. 拆分方式是否合适？（拆分粒度/垂直切片）
2. 依赖关系是否正确？
3. 是否有需要拆分或合并的工作流？

持续迭代，直至用户确认。

## 2. 生成共享交接文档

用户确认工作流图后运行 `/handoff`，生成共享交接文档。

完整读取生成的交接文档，确认其中包含：

- 已确认的完整工作流图；
- 每个工作流的直接依赖；
- 当前会话已有的共享上下文；
- 相关产物的路径或链接（如有）。

交接文档记录已有上下文和本阶段确认的工作流；各工作流尚未确定的细节留给用户后续决定。每个工作流及其依赖关系均可从交接文档还原、共享上下文完整、相关引用无遗漏且文档可读取时，本步骤完成。

## 3. 创建工作流会话

使用当前平台提供的会话创建能力，为每个工作流创建独立会话。

每个会话必须：

- 推理等级设置为「high」；
- 使用工作流标题作为会话标题；
- 获得该工作流的完整定义和完整交接文档；

每个工作流的独立会话创建成功后，等待用户指令，禁止执行任何操作。

每次创建成功后立即记录工作流与会话的映射；重试时只处理创建失败的工作流。

向用户报告交接文档路径、完整的工作流与会话映射、工作流间的依赖关系，以及仍未成功的创建失败。
