# E2E

E2E 是 agent-driven acceptance testing：Markdown 场景是可复验的验收资产，真实系统边界上的操作与证据是验收执行。

## 分支

1. **写验收资产**：创建、更新或沉淀验收文档时，读取 [documentation.md](documentation.md)。完成标准：每个 ready 场景都有稳定 ID、Gherkin、执行通道、入口、前置条件、可观察断言、证据要求和执行记录位置。
2. **跑真实路径**：验收 UI、API、命令行、异步任务或跨服务流程时，读取 [testing.md](testing.md)。完成标准：范围内 ready 场景已在目标版本上执行，外部契约断言、证据、结论和失败重验范围均已记录。

## 共同契约

- 断言只落在系统边界：页面文本与控件状态、URL、HTTP 状态与响应契约、可查询副作用、事件或文件输出、错误反馈以及消费者可感知结果。
- 每个场景声明执行通道 `browser`、`api`、`cli` 或其组合；全栈路径沿同一业务动作关联前端状态、接口响应和后端副作用。
- 文档位置、路由、接口、账号、权限、数据和启动命令优先读取用户输入、仓库规范与领域 profile；通用 skill 只定义验收过程。
- 产物是 Markdown 验收文档和真实执行证据；代码化自动化测试由项目测试体系维护。
- E2E 消费可用环境和可识别版本。环境未就绪时记录失败步骤、版本事实、请求摘要、trace/request ID 和缺失前置，由调用方交付流程处理。
