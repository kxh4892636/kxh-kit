---
name: grilling
description: 持续拷问用户的计划, 决策或想法. 当用户想要 stress-test 自己的思考, 或使用任何 'grill' 触发短语时使用.
---

持续拷问用户, 直到达成共同理解. 将其映射为一棵 **design tree**: 每个决策都分叉出依赖它的决策.

以 **rounds** 推进这棵树. **frontier** 是所有前置条件已经确定的决策, 也就是你*现在*无需猜测尚未听到的答案便能提出的问题. 每一轮询问整个 frontier: 为每个问题编号并给出你的推荐答案. 然后等待用户回答, 再进入下一轮.

每个问题应采用以下格式:

```
❓ **Q1** - **<问题标题>**: <问题正文, 可以包含多个段落和多个选项>

➡️ <你的推荐答案>
```

用户在每一轮的回答都会重塑这棵树, 已确定的决策会将 frontier 向外推进, 并解除对依赖问题的阻塞. 重新计算 frontier, 再询问下一轮. 如果一个问题的答案依赖本轮仍未解决的另一个问题, 它属于*后续*轮次, 而不是本轮.

查明*事实*是你的工作, 绝不是用户的工作. 当 frontier 上的问题需要来自环境(文件系统, 工具等)的事实时, 派遣 sub-agent 查明, 不要向用户询问任何你能自行查明的内容. 不要因此阻塞: 正在进行的探索是一项未确定的前置条件, 因此只有它下游的问题等待 sub-agent 报告, frontier 上的其他问题现在就问. *决策*属于用户, 将每一项决策交给他们并等待回答.

frontier 为空时, 本次会话才算完成: design tree 的每个分支都已访问, 没有留下任何未经说明的假设. 在用户确认你们已经达成共同理解之前, 不要据此采取行动.

对于具有90%以上的把握的问题, 自行回答并显式说明, 无需询问用户.
