# 切片与交接文档

将当前工作或用户参数拆分成 **tracer bullet** 垂直切片, 并确认切片的边界与依赖.

## 1. 探索工作区(可选)

如果尚未探索工作区, 先了解工作区现状. 探索时读取 `CONTEXT.md`和所触及区域的 ADR/Workflow, 使切片的确认遵循工作区的领域语言, 架构决策和工作流.

## 2. 确认切片

运行 `/grilling`, 使用 **tracer bullet** 拆分切片并明确其定义:

- 切片以一项完整业务能力或用户路径作为边界, 能够独立实现和验证.
- 切片贯穿业务领域的所有层级(例如编程领域的前端, 后端, 数据库, 测试等), 纵向而非层级的横向切片.
- 切片的实现和验证需要直接依赖的切片完成. 直接依赖为 `无` 的切片可立即实现和验证.

向用户展示完整切片方案, 持续迭代, 直至用户确认:

1. 拆分方式是否合适?
2. 依赖关系是否正确?

拆分方案确认后, 对于每个切片, 依次询问用户:

1. 目标/边界/依赖关系;
2. 交付物及其完成条件;
3. 验收方式及其门禁;

**完成标准**: 用户确认切片拆分合适, 且每个切片具有清晰的定义.

## 3. 生成交接文档

为整体工作和每个切片生成一份**交接文档**,保存到 `docs/slices/{SLICE_NAME}` 目录下.

```
├── docs/slices/{SLICE_NAME}/
│   ├── {SLICE_NAME}.md     # 整体交接文档
│   ├── {ID1}-{TITLE1}.md   # 切片1的交接文档
│   └── {ID2}-{TITLE2}.md   # 切片2的交接文档
```

交接文档至少包括:

- 上下文环境信息;
- 当前工作/切片的定义;
- 用户故事和 `grilling` 明确的决策;
- 所有切片的状态信息(仅限整体交接文档);
- 相关产物的路径或 URL;
- 推荐调用的 skill;

交接文档只携带所需的上下文. 通过路径或 URL 引用 PRD, spec, ADR, commit, diff 等已有产物.

**完成标准**: 整体交接文档能够维护所有切片的状态信息, 且每个切片的交接文档能够独立定位完成该切片所需的全部上下文.

## 约束

- 用户参数与 skill 冲突时, 以用户参数为准.
