# Tracer-bullet 切片

将一次上下文无法安全完成的工作拆成 **tracer bullet** 垂直切片. 每个切片在直接依赖成立后, 都能独立实现, 交付和验收; 切片内部的设计留给下一步 `/grill-with-docs`.

## 1. 建立工作边界

从用户参数或当前工作中提取目标, 并先自行查明工作区事实. 从 `CONTEXT-MAP.md` 定位所触及业务域, 读取它们的 `CONTEXT.md`, 相关 ADR / Workflow, 以及已有 PRD, spec, issue, commit 或 diff.

形成一份工作简报:

- 用户要得到的结果;
- 范围与非范围;
- 已知约束;
- 事实与决策的来源链接.

**完成标准:** 目标, 范围和约束都有来源, 或被明确标记为待用户决定; 可从工作区查明的事实已经查明.

## 2. 确认切片图

运行 `/grilling`, 将 design tree 限制在切片的边界, 覆盖关系, 直接依赖和最小验收结果. 用 **tracer bullet** 约束每个切片:

- 以一个完整的用户结果或业务能力为边界, 只贯穿实现该能力所需的层级;
- 在直接依赖成立后, 可以独立实现, 交付和验收;
- 使用唯一且稳定的 ID;
- 列出范围与非范围;
- 每条直接依赖都说明原因和本切片消费的产物或契约;
- 用一个可独立判定的结果定义最小验收信号.

实现路径, TDD seam 和具体交付门禁由每个切片后续的 `/grill-with-docs` 决定.

**完成标准:**

- 工作范围无遗漏, 每项交付责任只有一个归属切片;
- 每个切片都有唯一 ID, 用户结果, 范围, 非范围和最小验收结果;
- 依赖只记录直接依赖, 且每条依赖都写明消费的产物或契约;
- 依赖图至少有一个根切片, 无自环, 无环;
- 用户确认切片边界和依赖图.

## 3. 生成交接文档

在 `docs/slices/{SLICE_NAME}/` 写入整体交接文档和逐片交接文档:

```text
docs/slices/{SLICE_NAME}/
├── {SLICE_NAME}.md
├── {ID1}-{TITLE1}.md
└── {ID2}-{TITLE2}.md
```

整体交接文档包含:

- 工作简报;
- 切片索引, 依赖图和逐片文档链接;
- 每个切片的状态;
- 共享约束和上下文链接;

每个切片的交接文档包含:

- 稳定 ID 和用户结果;
- 范围与非范围;
- 直接依赖, 依赖原因及消费的产物或契约;
- 最小验收结果;
- 约束和上下文链接;
- 下一步: 对该切片调用 `/grill-with-docs`.

通过链接引用已有产物, 只携带完成该切片所需的上下文.

**完成标准:** 读回全部文档并确认 ID 唯一且引用可解析, 依赖图与用户确认的方案一致且无环, 每个切片文档包含全部必填字段, 整体文档恰好覆盖全部切片并将初始状态记为 `pending`.

## 切片状态协议

整体交接文档用一张表维护每个切片的 ID, 状态, 障碍或证据链接, 最近更新时间.

### 状态

- `pending`: 尚未开始. 直接依赖全部完成时, 该切片可开始, 状态仍保持 `pending`, 直到实际开始.
- `in_progress`: 已经领取并开始工作.
- `blocked`: 存在阻止继续工作的真实障碍; 同时记录障碍和解除条件.
- `completed`: 交付物已经产生, 最小验收结果已有验证证据; 同时记录产物与证据链接.

### 不变量

- 可执行性由直接依赖的状态推导, 依赖完成只改变可执行性.
- 每个切片只使用一个上述状态.
- `blocked` 切片带有障碍和解除条件.
- `completed` 切片带有交付物和验证证据.
