# 切片与交接文档

将当前工作或用户参数拆分成 **tracer bullet 垂直切片**, 并确认切片的边界与依赖.

## 1. 探索工作区(可选)

如果尚未探索工作区, 先了解工作区现状. 探索时读取 `CONTEXT.md`和所触及区域的 ADR/Workflow, 使切片的确认遵循工作区的领域语言, 架构决策和工作流.

## 2. 确认切片

运行 `/grilling`, 讨论范围仅限于如何拆分当前工作, 各切片的具体实现, 拆分切片后各自讨论.

切片使用 **tracer bullet** 方式:

- 切片以一项完整业务能力或用户路径作为边界, 能够独立实现和验证.
- 切片贯穿业务领域的所有层级(例如编程领域的前端, 后端, 数据库, 测试等), 纵向而非层级的横向切片.
- 切片的执行需要直接依赖的切片完成. 直接依赖为 `无` 的切片可立即执行.

每个切片包含但不限于:

- 切片概述: `{ID}-{TITLE}` + 工作区摘要;
- 与其他切片的边界和直接依赖(`ID`列表或`无`);

向用户展示完整切片方案, 询问用户:

1. 拆分方式是否合适?
2. 依赖关系是否正确?

持续迭代, 直至用户确认.

## 3. 明确切片定义

运行 `/grilling`, 在步骤 2 基础上额外明确各切片的具体定义,包含但不限于:

1. 切片的目标;
2. 切片的实现路径;
3. 切片的交付物和完成条件;
4. 切片的验收方式和门禁;

当每个切片的定义都明确, 不包含模糊或不完整的信息时, 本步骤完成.

## 4. 生成交接文档

为整体工作和每个切片生成一份**交接文档**,保存到 `docs/slices/{SLICE_NAME}` 目录下.

```
├── docs/slices/{SLICE_NAME}/
│   ├── {SLICE_NAME}.md     # 整体工作的交接文档
│   ├── {ID1}-{TITLE1}.md   # 切片1的交接文档
│   └── {ID2}-{TITLE2}.md   # 切片2的交接文档
```

整体工作的交接文档包含但不限于:

- 整体工作的定义;
- 所有切片的定义;
- 切片交接文档的索引;
- 相关产物的路径或 URL(如有).

每份切片的交接文档包含但不限于:

- 该切片的定义;
- 建议调用的 skill 及调用时机;
- 所需上下文与相关产物的路径或 URL(如有).

交接文档只携带所需的上下文. 不重复 PRD, spec, ADR, commit, diff 等已有产物, 通过路径或 URL 引用. 尚未确认的细节后续在对应切片中决定.

当每个切片仅凭其交接文档及引用即可定位完成切片所需的全部上下文时, 本步骤完成.

## 状态维护

整体交接文档是所有切片状态的单一事实来源. 状态项只保留当前快照, 变更历史由 Git 保留.

每个切片使用以下状态: `pending`, `in_progress`, `blocked`, `completed`.
切片创建后为 `pending`, 直接依赖全部 `completed` 后进入 `in_progress`; 等待直接依赖时不属于 `blocked`,遇到实际障碍时进入 `blocked`, 解除后恢复为进入阻塞前的状态. 完成条件或验证结论失效时, 从 `completed` 重新进入 `pending`.

当前执行者在每次状态变化后立即更新整体交接文档中的对应状态项, 并记录:

- 当前状态和更新时间;
- 进入 `blocked` 时的阻塞原因, 解除条件和解除后恢复的状态;
- 进入 `completed` 时的交付物与验证证据路径或 URL;
- 从 `completed` 重新进入 `pending` 时的原因.

当整体交接文档中的状态与实际情况一致, 且任一切片的可执行性, 阻塞解除条件和完成证据均可由该文档及其引用判断时, 本次状态维护完成.

## 约束

- 用户参数优先级高于 skill.
