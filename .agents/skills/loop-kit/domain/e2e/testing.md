# E2E 真实路径执行

本 reference 负责在真实系统边界执行前端、后端或全栈 E2E 验收资产。资产可以是 Markdown 场景或 E2E 框架测试，执行通道可以是浏览器、HTTP/RPC 客户端、项目 CLI 或它们的组合。

执行前先定位主验收资产。Markdown 场景缺失、过期或不覆盖当前目标时，按 [documentation.md](documentation.md) 创建或更新；框架测试存在同类问题时，按 [framework-testing.md](framework-testing.md) 创建或更新。

## 执行顺序

1. 根据用户目标、变更范围或指定内容定位受影响的可部署单元、外部入口和主验收资产。完成标准：待验单元、入口与资产位置都有来自代码、配置、文档或用户输入的来源记录。
2. 确定待执行集合：Markdown 分支读取 ready 场景，代码分支读取目标测试文件、project、tag 或用例过滤条件。完成标准：范围由稳定场景 ID 或可复现的 runner 选择条件完整表达。
3. 检查执行输入：Markdown 场景检查通道、入口、身份/数据、目标版本、等待条件、断言和证据要求；框架测试检查 runner、配置、命令、fixtures、环境、断言和 reporter。完成标准：每条路径可以直接执行；缺失输入已精确到字段、账号、依赖、配置或环境事实。
4. 证明环境承载目标版本并满足访问、权限、数据和依赖前置。完成标准：记录 commit、构建号、镜像/制品版本或其他可复现版本标识；无法证明时将本次执行标为 blocked。
5. 使用与消费者一致的真实入口执行动作：Markdown 分支由 agent 按场景操作，代码分支由项目 runner 驱动。完成标准：动作已穿过资产声明的系统边界并进入预期终态或可诊断失败态。
6. 沿同一路径验证所有关键边界。完成标准：每个主要结果都有外部断言；全栈场景中的 UI、接口和副作用能够通过同一关联标识串联。
7. 记录结果和证据：Markdown 分支回写场景执行记录，代码分支保留 runner 结果与 reporter 产物。完成标准：记录 passed / failed / blocked、环境、版本、时间、执行入口、关键断言、证据及未完成原因。
8. 失败后定位最小失败单元；修复或前置变化后只重验该单元及其直接依赖。完成标准：重验范围与失败证据一一对应。

## 运行态准备

1. 判断目标是本地运行态还是已部署环境，并读取仓库提供的启动、健康检查与路由/接口配置。
2. 本地已有目标进程时确认它承载当前代码；需要新进程时使用项目声明的命令启动受影响单元。
3. 等待编译、迁移、依赖和健康检查达到 ready 状态，再开始场景计时。
4. 从配置、路由、OpenAPI/RPC 定义或运行输出得到入口，不依赖猜测拼接地址。
5. 记录 base URL、端口、环境、版本和启动方式。完成标准：另一执行者可以据此进入同一运行态。

环境发布、流水线和会话准备由调用方流程负责；本 reference 只消费已授权且可识别版本的运行态。

## 分支入口

### Markdown / agent-driven

- 按场景声明使用浏览器、API/RPC 客户端、CLI 或组合工具，从第一条未证实的步骤开始执行。
- 场景状态、关键断言和证据写回主验收文档；直接重验沿用原场景 ID。

### Code / framework-driven

- 使用仓库声明的包管理器、脚本、配置和 runner；先运行受影响测试，再按影响面扩到相邻 project、tag 或 suite。
- 结论同时记录 runner 状态与目标测试的收集数、执行数和结果；零收集、零执行或非预期 skip 记为 blocked。交互式检查用于补充诊断；命令、过滤条件和 reporter 产物共同构成可复现执行入口。
- runner 管理服务或依赖时，保留其启动配置与健康检查事实；连接外部运行态时，单独记录 base URL 和版本标识。

## 执行方法

### Browser

- 操作承载所需登录态的真实浏览器，完成导航、等待、点击、输入、键盘/触摸、下载和截图。
- 读取 URL、标题、可见文本、控件状态、焦点、表单值、列表/图表状态、控制台错误和相关网络请求。
- 需要页面全局变量时进入页面主执行上下文读取，并把变量来源与断言目的写入证据。
- HMR 场景先证明最新编译已生效；只有页面状态异常时刷新，并记录原因。

### API / RPC

- 使用项目真实协议入口与身份上下文发起请求，记录 method、endpoint、关键参数、状态、业务 code/message 和核心响应字段。
- 对写操作通过读取接口、事件、文件或其他外部接口验证副作用；异步结果按场景声明的间隔与超时轮询。
- 保留响应中的 `logId`、`traceId`、`requestId` 或等价关联字段，使失败可进入日志与链路诊断。

### CLI / Worker

- 使用用户会使用的项目 CLI、任务入口或消息入口，记录命令参数、输入标识、退出码和输出摘要。
- 后台任务以可观察终态为断言；队列消费、定时任务和批处理同时记录触发证据与结果证据。

## 接口断言

每个关键请求至少检查：

1. 传输层状态：HTTP/RPC 状态、超时、取消、重定向和协议错误。
2. 业务契约：业务 code/message、schema、核心字段和兼容性。
3. 消费结果：页面、下游读取、事件或文件输出与响应一致。
4. 关联证据：请求时间、环境、版本、触发步骤和 trace/request ID。

## 失败重验

- UI 断言失败：重验失败交互、UI 断言和直接依赖的请求。
- 接口契约失败：重验触发动作、请求契约、消费者结果和受影响入口。
- 异步副作用失败：重验触发、关联标识、轮询终态与超时边界。
- 控制台或进程错误：重验产生错误的动作，并确认同类错误消失。
- 身份、权限、数据或依赖失败：只重做该前置及后续路径，保留此前可信证据。
- 代码修复：先证明目标运行态承载新版本，再回到最早受影响步骤。

## 证据标准

- 视觉结果使用无遮挡截图；接口结果保存请求/响应摘要；CLI 和任务结果保存命令、退出码与输出摘要。
- 敏感凭证、Cookie、Token 和个人数据在证据中脱敏。
- 动态 ID、时间和业务数值作为本次执行事实记录；长期场景断言其生成规则或可重建条件。
- 验证过程使用只读或无源码写入副作用的检查方式；任务授权修复时，修复后再按失败重验规则执行。
