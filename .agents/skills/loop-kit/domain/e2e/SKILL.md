# E2E

E2E 验收资产表达可复验的消费者路径。它可以是由 agent 按 Markdown 场景执行的 acceptance testing，也可以是由项目 E2E 框架执行的测试代码；两者共享外部断言与证据契约。

探索代码库或确定验收范围时，读取 `CONTEXT.md`（如存在），使场景命名和断言匹配项目领域语言；同时读取所触及区域的 ADR，使验收路径和断言遵循既有架构决策。

## 执行流程

1. **分流验收资产**：
   - 用户或仓库明确指定资产形态时沿用该形态。
   - **Code / framework-driven**：项目已有适用框架，或任务明确包含 E2E 基建；场景稳定、前置可控制，且重复执行或进入 CI 的价值足以覆盖代码维护成本。
   - **Markdown / agent-driven**：路径需要灵活跨工具操作或探索性判断，需求、环境或数据前置尚未稳定，或者低频交付验收的重复收益不足以维护测试代码。
   - 混合需求按场景拆分，每个场景选择一种主资产。

   完成标准：范围内每个场景都已确定主资产形态及选择依据，同一验收意图只有一个事实源。
2. **编写或更新资产**：Markdown 分支读取 [agent-driven 验收文档](documentation.md)；代码分支读取 [E2E 框架测试](framework-testing.md)。完成标准：每个 ready 场景都有稳定身份、消费者入口、前置条件、外部动作、可观察断言、执行方法和证据位置，并满足所选资产的项目约定。
3. **跑真实路径**：执行 Markdown 场景或框架测试时读取 [testing.md](testing.md)。完成标准：范围内资产已在可识别的目标版本上执行，外部契约断言、证据、结论和失败重验范围均已记录。

## 共同契约

- 断言只落在系统边界：页面文本与控件状态、URL、HTTP 状态与响应契约、可查询副作用、事件或文件输出、错误反馈以及消费者可感知结果。
- 每个场景可追溯到执行通道 `browser`、`api`、`cli` 或其组合；全栈路径沿同一业务动作关联前端状态、接口响应和后端副作用。
- 文档位置、路由、接口、账号、权限、数据和启动命令优先读取用户输入、仓库规范与领域 profile；通用 skill 只定义验收过程。
- E2E 消费可用环境和可识别版本。环境未就绪时记录失败步骤、版本事实、请求摘要、trace/request ID 和缺失前置，由调用方交付流程处理。
