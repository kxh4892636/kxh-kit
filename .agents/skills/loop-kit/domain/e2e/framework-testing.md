# E2E 框架测试

本 reference 对应代码驱动的 E2E 验收资产：在用户指定或项目既有的 E2E 框架中创建和维护可执行测试、fixtures、外部断言与诊断产物。

## 工作流程

1. 定位项目根、受影响的可部署单元、E2E 配置、测试目录、运行命令、相邻测试、fixtures 和 reporter。完成标准：runner、配置、测试根、目标环境和产物位置均有当前仓库事实来源。
2. 从需求、验收标准、设计、接口契约、现有系统和变更范围提取消费者旅程，并建立覆盖矩阵。完成标准：每个纳入或排除的客户端、服务、角色、平台、环境和数据分支都有依据。
3. 将旅程映射为具有稳定身份的测试或用例组。完成标准：一个测试只证明一个主要结果，名称或元数据能够追溯需求或场景，新增测试不破坏既有身份。
4. 设计可重建的身份、数据、依赖和清理策略。完成标准：每个测试的前置可由 fixture、setup 或项目声明的环境准备复现，并满足隔离、重跑和并行约束。
5. 通过消费者入口实现动作和断言。完成标准：浏览器定位、协议请求、轮询与等待使用框架原生能力；同步点来自可观察 ready 条件；断言落在系统边界。
6. 将测试接入项目运行入口与诊断产物。完成标准：项目声明的命令可以唯一选择目标测试，reporter 能够保留适用的 trace、截图、视频、report 或请求摘要。

## 位置与框架

按以下优先级确定代码资产位置与 runner：

1. 用户指定的框架、目录或命令。
2. 仓库规范和 E2E 配置声明的 test root、project 与脚本。
3. 相邻可部署单元或同类消费者路径的既有约定。

runner 与目标路径不匹配时，返回 [分流步骤](SKILL.md#执行流程) 重新判定主资产。

## 编写规则

- 使用项目现有配置、fixtures、认证状态、数据工厂、locator 约定和 reporter，使测试进入同一维护体系。
- UI 使用角色、标签、稳定测试标识或用户可见文本定位；API/RPC 使用真实协议入口与契约字段；CLI/worker 使用用户可调用入口和退出状态。
- 等待条件绑定页面、响应、事件、文件或任务终态；超时表达业务或环境边界。
- 写操作使用可识别且可清理的数据；共享环境中的测试生成独立标识，并把清理结果纳入执行结论。
- 失败产物保留最早失效的外部断言及其直接上下文，使重验可以从最小失败单元开始。
