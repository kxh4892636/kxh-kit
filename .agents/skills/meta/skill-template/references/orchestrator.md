# Orchestrator Template

用于串联已有 skills、工具或阶段。编排器拥有顺序、输入输出和交接，不复制被调用能力的内部规则。

```markdown
# <Orchestrator Title>

<一句话说明最终交付物和编排范围。>

## 流程

### 1. 准备输入

从 <用户输入、当前会话、issue、spec 或文件> 取得 `<输入>`，并确认适用分支。

**完成标准：** 每个后续阶段的输入和适用性都已确定。

### 2. 执行 <阶段 A>

使用 `/<skill-a>` 完成 `<阶段 A 的职责>`；其内部规则由该 skill 自己拥有。

**完成标准：** `<skill-a>` 的交付物和完成证据已经存在。

### 3. 执行 <阶段 B>

只有在 `<可观察条件>` 成立时使用 `/<skill-b>`；否则记录该阶段不适用的事实依据。

**完成标准：** 适用分支已经完成，不适用分支已有依据。

### 4. 汇总并交接

将各阶段产物组合为 `<最终产物>`，保留来源指针，不重复粘贴已有内容。

**完成标准：** 每个适用阶段都有证据，最终产物可定位，下一责任方可以直接继续。
```

被调用 skill 的名称必须与其 frontmatter `name` 一致；调用语义统一写成 `/skill-name`。
