# Dev Gate

本 skill 只交付 `ready` 或 `not ready`。`ready` 表示实现输入和执行边界已被用户明确确认。

## 1. 核对准入产物

完整读取 [`QUESTIONS.md`](../../QUESTIONS.md) 与 [`workflows/README.md`](../../workflows/README.md)。它们分别是附加准入问题和可复用工作流的扩展点；空文件表示当前没有附加项。把用户输入和现场事实视为已有答案，只追问仍会改变基线的条目。

确定本次实现只由一个权威入口驱动，并核对对应条件：

- `/grilling`：frontier 为空，用户已确认共同理解。
- `/grill-with-docs`：上述条件成立，已确认术语、关系和符合条件的 ADR 均已落入领域文档。
- `/to-issues`：spec 与 issue 图通过领域校验，issue 决策已澄清且下一步均为 `/implement`。

从现场文件和工具查明可检索事实；只把会改变执行边界的未决选择交给用户。权威入口唯一、其完成标准有可核查证据且未知项已清空时，本步骤完成。

## 2. 建立基线

从权威入口、工作区配置和用户约束形成三项基线：

- **工作环境**：目标 workspace、branch/worktree、本地与 CI 入口、运行环境及必需外部服务。
- **执行契约**：本轮范围、固定比较点、步骤顺序、停止点、交付物，以及是否包含 commit 等状态变更。
- **质量门禁**：`/code-test` 与 `/verifying` 必须取得的最小证据集合；每项都带事实来源、执行入口和通过条件。

现场没有声明的值保持为待确认决策，不把猜测写成基线。三项均完整且互不矛盾时，本步骤完成。

## 3. 确认与交接

向用户提交一张简短基线卡，逐项列出触发路径、工作环境、执行契约和质量门禁。用户修正时先更新对应权威文档，再重新提交受影响部分。

用户明确确认且前两步全部成立时结论为 `ready`；否则结论为 `not ready`，并给出缺项及其恢复入口。携带 flow context 时，完整读取 [`FLOW.md`](../../FLOW.md)，以基线卡或权威入口为证据登记结果，再只执行脚本返回的下一步。

实现期间任一基线发生实质漂移时，本 gate 重新打开；更新受影响的权威文档并再次取得用户确认。
