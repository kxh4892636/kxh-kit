# Note Creator

以**覆盖清单**守住知识完整性，以**检索结构**提高复习效率。用户的明确要求优先于本 skill 的默认格式。

## 1. 锁定交付契约

开始前确定三项决策：

- **主模式**：
  - 创建：从材料或主题生成新笔记；
  - 无损优化：重组已有笔记，默认保持知识边界与技术含义不变；
- **解释深度**：
  - 高密度：电报体知识点，服务快速检索；
  - 学习笔记：补足原因、机制、最小示例和边界，服务首次理解；
- **交付位置**：
  - 用户指定路径时在该路径创建或编辑文件；
  - 用户未指定文件时直接返回最终 Markdown；用户要求提纲、差异或说明时再附加相应内容；

创建模式以用户材料和已验证事实为知识边界。学习深度默认在既定知识边界内重写解释；用户明确要求学习笔记、从零理解、详细讲解或补充示例时，为达到该深度所需的已验证解释与示例进入覆盖清单。

**完成标准：** 主模式、解释深度、知识边界、交付位置和用户覆盖项均已明确。

## 2. 建立覆盖清单

先完整读取源材料，再将每个有意义的内容单元登记为独立知识点：

- 标题表达的概念或分类；
- 段落中的独立事实、因果、规则、限制或例外；
- 每条 bullet、每个有语义的表格行；
- 代码、注释或输出展示的行为；
- 公式、图片和重要链接承载的信息；

语义完全相同的重复项合并为一个编号；条件、限定词、例外和反例分别保留。为每个编号指定目标标题与表达载体。仅给出主题而没有源材料时，按本质、机制、用途和边界规划待写知识点，并标明需要验证的事实。

**完成标准：** 每个源内容单元都映射到目标位置，或被明确判定为纯重复/无知识含量；每个计划新增的事实均有可靠依据。

## 3. 按映射写作

- 以概念依赖和检索关系重组材料顺序；
- 每个知识点只保留一个权威落点，通过标题、bullet、表格或代码注释呈现；
- 创建模式将覆盖清单综合为最短完整表达，优先保留本质概念、关键行为和不可直接推导的事实；
- 正文从 frontmatter 与标题直接开始，在最后一个知识点结束；

### 通用格式

所有模式应用以下规则；只采用与当前内容和渲染环境相关的部分。

#### 文档骨架

- 每个 Markdown 笔记以 YAML frontmatter 开头，并包含 `id: <uuid>`；已有文件保留原 `id` 和其他元数据，新文件或缺少 `id` 的文件生成 UUID；
- H1 仅用于文档标题；内容按 H2 → H3 → H4 → H5 连续递进，最深使用 H5；
- 同一主题先放概念/本质，再按需要放语法、命令、机制、示例、复杂度/权衡、边界和图示；
- H4 或 H5 可作为最细知识点层级，深度由内容关系决定；
- 标题用知识对象或关系具体命名，例如“错误传播机制”；

```markdown
---
id: <uuid>
---

# 标题

## 大主题

### 子主题

#### 具体概念

##### API 分组
```

#### 语言与密度

- 一个内容单元承载一个独立知识点，关键词或技术术语前置；
- 高密度模式使用电报体短语；学习笔记允许用必要的完整短句解释原因和机制；
- bullet 及其 sub-bullet 统一以分号 `;` 结尾；
- 技术术语保留英文原文，说明使用中文；术语首次出现时补充最短必要解释；
- 标题层级承担过渡作用，正文只保留可检索的知识内容；
- 细节与例外放在对应知识点的 sub-bullet 中；

```markdown
- Date.parse(dateString) 静态方法: 返回 dateString 对应的毫秒级时间戳;
  - 无法解析时返回 `NaN`;
```

#### 表达载体

| 信息形态 | 首选载体 |
| --- | --- |
| 单个概念、规则、限制或注意事项 | bullet |
| 概念性属性/方法枚举、对比、协议要求、独立运算符枚举 | 表格 |
| 能逐行演示的语法、类型、修饰符、工具类型或运行行为 | 带注释的代码块 |
| 多项内容的共同分类或检索入口 | 具体命名的标题 |
| 复杂度、优缺点和权衡 | 对应概念下的 bullet 或对比表 |
| 数学关系 | LaTeX 公式 |
| 视觉关系 | 对应标题下的图片 |

表格的每列表示稳定维度，每行表示一个可独立比较或枚举的对象。与代码一一对应的知识点以代码块作为唯一落点。

#### 代码与 API

- 代码块标注准确语言，并只保留说明当前知识点所需的最小代码；
- 概念定义、语法规则和关键字含义使用代码上方的独立行注释；
- 运行结果、错误提示和当前行行为使用代码末尾的行内注释；
- 多个并列且与代码强相关的知识点合并到一个代码块中；
- 目录树、配置片段等结构化代码块使用行内注释解释条目，并对齐注释列以便扫描；

```typescript
// 布尔值
const isDone: boolean = false;
handleEvent(element, "dblclick"); // event 不支持 "dblclick" 时类型报错
```

API 使用 TypeScript 风格签名；签名整体用 inline code 包裹，描述放在其后：

```markdown
- `ClassName.method(param: Type): ReturnType` 静态方法: 描述;
- `ClassName.property: Type` 属性: 描述;
```

#### 图片与公式

- 图片使用相对路径并放在对应标题下：`![alt](images/{image-name}.png)`；
- 行内公式使用 `$...$`，行间公式使用 `$$...$$`；
- 图片、公式和重要链接本身承载的知识在相邻文本中给出可检索名称；

#### MDX 兼容

目标由 Docusaurus/MDX 渲染时，所有代码样文本都使用 inline code 或代码块隔离：

- 泛型、类型签名和 API，如 `Promise<T>`、`Map<K, V>`；
- 对象字面量、配置片段和占位符，如 `{ left?: number }`、`${value}`；
- HTML/XML/JSX/Vue/Svelte 标签，如 `<head>`、`<Response>`；
- 含 `<...>`、`{...}`、`=>`、`<=>`、`>` 或 `|` 的数据格式、链路和比较表达式；
- 正文注释使用 MDX 注释 `{/* ... */}`；

### 无损优化

主模式为无损优化时采用**封闭世界**：原笔记定义全部知识边界，改动只改善表达、结构和格式。用户明确授权的补充或纠错作为独立覆盖项记录。

#### 语义不变量

以下内容在优化前后保持等价：

- 每个独立知识点及其条件、限定词、例外、反例和因果关系；
- 技术术语、API 含义、类型关系、复杂度和行为描述；
- 代码逻辑、示例意图、运行结果和错误语义；
- 重要链接目标、图片路径、公式及其表达的关系；

发现疑似事实错误时，先保留原知识边界并在交付说明中指出。用户授权纠错后，验证事实再修改，并把纠错列为独立变更。

#### 等价变换

| 变换 | 允许范围 |
| --- | --- |
| 压缩 | 删除无信息量措辞，把完整句压成等价短语 |
| 去重 | 合并语义完全相同的表述，保留信息最完整的一处 |
| 重排 | 按概念关系移动标题、段落、bullet、表格或代码块 |
| 归并 | 将同类信息收入同一标题、表格或代码块 |
| 换载体 | 在 bullet、表格和代码注释之间转换，保持全部语义 |
| 规范化 | 修复标题层级、标点、代码语言标记、frontmatter 和 MDX 表达 |

按通用格式补充元数据属于文档修复，知识边界保持不变。

#### 覆盖账本

在编辑前建立内部账本；账本默认保留在内部，用户要求时再随结果提供：

| ID | 原始知识点 | 新位置/载体 | 状态 |
| --- | --- | --- | --- |
| K1 | 原文或等价摘要 | 标题、表格行或代码位置 | 已映射 / 纯重复 / 授权纠错 |

编辑后从原文逐项回查：

- `已映射` 项在新笔记中具有等价落点；
- `纯重复` 项能指向保留的同义知识点；
- `授权纠错` 项具有用户授权和事实依据；
- 新笔记中的每个事实都能反向指向账本项；

### 学习笔记

解释深度为学习笔记时，先建立心智模型，再提供可复习的检索结构。信息边界仍由用户材料、已验证事实和用户授权的补充共同决定。

#### 知识点模型

每个关键概念按需要回答以下问题：

| 槽位 | 要回答的问题 |
| --- | --- |
| 本质 | 它是什么，最小定义是什么？ |
| 原因 | 它解决什么问题，为什么存在？ |
| 场景 | 何时需要它，典型上下文是什么？ |
| 机制 | 关键规则、状态变化、数据流或与其他概念的关系是什么？ |
| 示例 | 哪个最小示例能直接展示机制？ |
| 边界 | 限制、易错点、反例或常见误解是什么？ |

本质、机制和最小示例构成关键概念的默认骨架；原因、场景和边界在能增加理解时加入。语法、类型、并发、错误处理、生命周期、状态变化和数据流等抽象主题优先用最小代码或具体输入输出展示机制。

#### 写作规则

- 先解释本质和问题，再展开语法、机制、示例与边界；
- 术语定义同时说明它与当前概念的关系；
- 示例只展示当前机制，注释承担知识解释，运行无关的样板保持最少；
- 每个章节把材料内容重构为可独立复习的知识点；

````markdown
#### 知识点名

- 本质: 最小定义;
- 原因: 解决的问题;
- 场景: 典型使用条件;
- 机制:
  - 关键规则或状态变化;
  - 与相关概念的关系;
- 示例:

  ```typescript
  // 用最小代码展示机制
  const example = 1;
  ```

- 边界: 限制、反例或易错点;
````

没有信息价值的槽位直接省略；省略后仍需保留足以理解机制的上下文。

**完成标准：** 覆盖清单中的每个编号都在草稿中恰好落地一次，草稿中的每个事实都能反查到清单；每种内容载体均满足通用格式；无损优化保持全部语义不变量；学习笔记中的关键概念具备本质、机制和可理解示例，或已在内部确认示例不适用。

## 4. 对抗性验收

逐项反查最终结果：

1. **覆盖**：从源材料回查输出，每个知识点均能定位到等价落点；
2. **语义**：无损优化中的未授权新增、遗漏、含义变化和代码行为变化均为零；
3. **格式**：所有适用的 frontmatter、标题、bullet、表格、代码、媒体、公式和 MDX 规则均满足；
4. **密度**：每个标题和内容单元都提供独立检索价值，同一含义只有一个事实源；
5. **交付**：文件模式复核目标 diff；对话模式返回可直接使用的最终 Markdown；

**完成标准：** 知识点覆盖率为 100%，未解释的新事实为零，适用格式违规为零，交付位置与用户要求一致。
