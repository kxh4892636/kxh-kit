# 学习笔记

以**覆盖账本**守住知识完整性，以**检索结构**提高复习效率，完成 **对齐 → 解析 → 分篇 → 写作 → 验收**。交付终点是 Markdown 笔记；

## 1. 对齐批次

从用户材料和当前环境中推断可验证的信息，只询问会阻塞写作的缺项：

- 源材料：文件、目录、链接、用户直接提供的内容或待研究主题；
- 知识边界：忠实整理现有材料，还是允许补充经验证的解释和示例；
- 笔记目标：输出目录、主题层级、文件命名和已有同类笔记约定；
- 事实状态：区分源材料事实、已验证补充、假设和待确认项。

同名目标文件存在时，先读取并把合并、改名或覆盖方式列为阻塞项。用户未指定文件位置且当前环境无法可靠推断时，直接返回可保存的最终 Markdown。

**完成标准：** 源材料、知识边界、交付位置和命名约定均有明确值；未验证信息均已标为假设或待确认。

## 2. 建立覆盖账本

完整读取源材料，将每个有意义的内容单元登记为独立知识点：

- 概念、术语、事实、因果和机制；
- 规则、限制、条件、例外、反例和易错点；
- 每条有语义的 bullet、表格行、公式和图片；
- 代码、注释、命令、输入输出和错误信息展示的行为；
- 重要链接及其承载的信息。

为每个知识点记录来源位置、目标笔记、目标标题和表达载体。语义相同的重复项合并；限定词、例外和反例分别保留。只有主题而没有源材料时，按本质、机制、用途和边界规划知识点，新增事实先从可靠来源验证。

**完成标准：** 每个源内容单元都映射到一个目标位置，或被明确判定为纯重复或无知识含量；每个补充事实都有依据。

## 3. 按概念树分组与分篇

### 概念目录

目录表达稳定的概念体系和知识边界：

- 相对于主题根目录，最多建立两级概念目录；
- 一级目录表示稳定的大概念，二级目录表示该大概念内部边界明确的子域；
- 只有存在明确子域时才建立二级目录；笔记可以直接放在一级目录中；
- 目录名称直接使用概念名，不带数字前缀；
- 学习顺序由导航、文件编号或独立学习路线表达，目录按概念归属组织；
- 每篇笔记只有一个主归属，所有文件组成严格的树形目录；
- 笔记跨越多个概念时，以 H1 所表达的核心解释对象确定主归属；
- 概念之间的联系通过链接表达，同一文件保持唯一存放位置。

### 笔记边界

一个文件承载一个可独立复习的语义主题：

- 同一主题的概念、机制、示例和边界放在一起；
- 沿用同级文件已有的排序和命名；没有约定时使用三位数字前缀并按 10 递增，例如 `010-主题.md`；
- 每篇只有一个主要回忆目标；多个主主题按语义边界拆分；
- 每篇 Markdown 内容约束在 13–144 行，最佳范围为 34-89 行；超过时按语义拆分，无法再拆的连贯主题可以超出，并在交付说明中记录保持合并的理由；
- 原子主题不足 13 行时，先补足属于同一核心概念的机制、示例或边界；知识已经完整时保持短小，不为达到行数填充内容；

**完成标准：** 每篇笔记都有唯一且可解释的主归属；主题根目录以下不存在第三级概念目录、数字前缀目录或重复文件；覆盖账本中的每个知识点恰好归入一个文件；每个文件只有一个主要回忆目标；超出建议行数的文件均有不可再拆的语义理由。

## 4. 写入笔记

按概念依赖和检索关系写作。每个知识点只有一个权威落点，正文从 frontmatter 与标题直接开始，在最后一个知识点结束。

### 文档骨架

- 新笔记默认以仅含 `id: <uuid>` 的 YAML frontmatter 开头；已有笔记保留原 `id` 和目标环境要求的元数据；
- `id` 创建后保持稳定，并在当前批次及目标知识库中唯一；
- H1 仅用于文档主题；正文按 H2 → H3 → H4 → H5 连续递进，层级由知识关系决定；
- 同一主题先给本质或概念，再按需给语法、机制、示例、对比和边界。

````markdown
---
id: <uuid>
---

# 主题

## 子主题

### 概念

- term: 最短完整解释;

### 语法格式

```text
最小示例
```
````

### 语言与密度

- 使用电报体，一个 bullet 承载一个独立知识点；
- 技术术语或关键词前置，说明使用中文，例如 `term: explanation;`；
- bullet 及其 sub-bullet 以半角分号 `;` 结尾；
- 技术术语、API、关键字和约定名称保留英文原文；
- 标题承担过渡，正文保留定义、机制、约束和不可直接推导的事实；
- 原因或机制需要连贯解释时使用短段落，信息可枚举时使用 bullet。

### 表达载体

| 信息形态                       | 首选载体               |
| ------------------------------ | ---------------------- |
| 单个概念、规则、限制或注意事项 | bullet                 |
| 稳定维度下的枚举或对比         | 表格                   |
| 语法、命令、配置或运行行为     | 带注释的代码块         |
| 多项内容的共同分类             | 具体命名的标题         |
| 数学关系                       | LaTeX 公式             |
| 视觉关系                       | 对应标题下的图片或图示 |

表格每列表示一个稳定维度，每行表示一个可独立比较或枚举的对象。与代码一一对应的知识点以代码及注释作为唯一落点。

### 代码与渲染

- 代码块标注准确语言，只保留展示当前机制所需的最小代码；
- 独立行注释说明概念、语法规则或关键字，行内注释说明当前行行为、结果或错误；
- 示例中的命名、输入和输出直接服务当前知识点；
- Markdown 由 MDX 渲染时，用 inline code 或代码块隔离泛型、对象字面量、标签、比较式和其他可能被解析为语法的文本。

**完成标准：** 覆盖账本中的每个知识点在笔记中恰好落地一次，笔记中的每个事实都能反查到来源或验证依据；所有适用的结构、语言和载体规则均满足。

## 5. 对抗性验收笔记

从源材料和输出两端逐项反查：

1. **覆盖：** 每个源知识点都能定位到等价落点，每个输出事实都有来源；
2. **语义：** 条件、限定词、例外、因果、代码行为和链接目标保持准确；
3. **结构：** frontmatter 有有效且唯一的 `id`，H1 唯一，标题连续且与知识关系一致；
4. **格式：** bullet 结尾、表格、代码语言、围栏、公式、图片和 MDX 表达均有效；
5. **交付：** 文件位于确认的目录，命名和排序符合目标约定，UTF-8 无 BOM、LF 换行、无尾随空白；
6. **运行态：** 目标项目存在 Markdown/MDX 检查或构建命令时，运行与本批次相关的门禁。

修正发现的问题后重新验收，再交付最终笔记。

**完成标准：** 知识点覆盖率为 100%，未解释的新事实为零，适用格式违规为零，相关项目门禁通过或阻塞原因已明确记录
