# Common Rules

读取本文件处理 JavaScript/TypeScript 代码规则：命名、文件大小、函数、模块、注释、错误处理和检查范围。只有涉及 UI、组件、路由页面时再读 `frontend-rules.md`；涉及 Go API/RPC、service、repository、数据库或后台任务时再读 `backend-rules.md`。

## 命名规范

- 文件命名使用 `kebab-case`。
- 变量/函数使用 `camelCase`。
- 类、接口、枚举、泛型参数使用 `PascalCase`。
- 常量使用 `UPPER_SNAKE_CASE`。
- CSS 类名选择器使用 `kebab-case`。
- 布尔变量使用 `is/has/should` 前缀。
- React 组件使用 `PascalCase`，事件属性使用 `on` + 元素名 + 事件动词，事件处理函数使用 `handle` + 元素名 + 事件动词。

## TypeScript 与函数

- 使用 TypeScript 编写代码。
- 单个文件不超过 377 行，超过时拆分。
- 不允许使用 `any`，可使用 `ISafeAny` 代替：

```typescript
type ISafeAny = any;
```

- 函数使用箭头函数，不使用普通函数。
- 函数参数和返回值必须有类型注解。
- 函数参数统一定义为 `params`，并在函数参数中使用解构赋值。
- 单个函数不超过 89 行，超过时拆分。
- 禁止使用 `enum`，使用 `const = {} as const` 替代；枚举对象和值均使用 `PascalCase`。
- 模块导出/导入时，除非框架需要默认导出/导入，否则使用命名导出/导入。
- 使用数据属性或方法时使用 `?` 可选链，避免空指针异常。

## 风险边界

- 网络请求、第三方数据、数据库查询、SDK 调用、文件系统、环境变量、后台任务等外部边界必须有错误处理。
- `catch` 中使用 `console.error` 或项目已有日志工具记录异常。
- 不确定外部数据形态时，先用项目现有 schema/validator 或 Zod 规则收窄类型。
- 影响数据库、文件系统、队列、远程服务或真实环境的命令先确认目标环境和可回滚方案。

## 注释规范

- 注释只写说明性注释，解释代码背后的原因、约束、取舍和风险。
- 禁止用注释复述代码正在做什么或如何执行。
- 注释比例只约束本次新增或修改的增量代码，存量代码不受限制。
- 增量代码的注释行数占代码行数比例必须在 13% 到 21% 之间；小于 8 行的增量代码允许不强制满足比例。
- 计算比例时不统计空行、纯括号/分隔符行、import/export 声明和仅格式化导致的行变化。
- 注释行只统计本次新增或修改的说明性代码注释，不统计文档块、TODO、lint 禁用指令或生成代码注释。

## 检查与修复

- 代码开发任务完成后，执行与改动贴近的代码检查和修复。
- 只对 git change 中的代码进行检查和修复，禁止检查其他代码。
- 遵循当前项目工具链；Vite+ 项目统一使用 `vp`。
