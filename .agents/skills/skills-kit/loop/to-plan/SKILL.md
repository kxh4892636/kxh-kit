# To Plan

基于会话上下文，编写计划文档，用于 Agent 能够持续执行/检查/校准当前计划。

1. 保证 Agent 能够长时间、不失真地执行当前计划。
2. 保证其他 Agent 通过计划文档，交接并继续执行当前计划；并通过计划文档实现多个 Agent 之间状态的同步。

计划文档路径为 `docs/plan/{yyyy-mm-dd}-plan{sessionName}.md`，日期使用创建计划当天的本地日期。

## 工作流程

1. 确定当前项目根目录、sessionName 和计划文档绝对路径；如果当前目录在 Git 仓库内，以 Git 根目录作为项目根目录。
2. 如果计划文档已存在，先读取现有内容，梳理最新上下文，执行增量更新操作，反之则创建计划文档。
3. 基于「更新触发点」，更新上下文变化涉及的所有内容。

## sessionName 规则

- 优先使用会话上下文中的 `SESSION_NAME` 环境变量。
- 如果上下文没有 `SESSION_NAME`，根据当前会话目标生成简短、稳定、可作为文件名的 kebab-case `sessionName`，并将其设置为 `SESSION_NAME`。
- `sessionName` 一旦生成并用于计划文档路径，就不能因为后续目标细化、compact/resume、标题变化或重命名偏好而改动。
- 计划文件名前缀日期一旦生成也不能改动；后续跨日期继续同一计划时，继续使用原计划文件。
- 不使用运行时 `session_id` 作为计划文档文件名，也不要把 `session_id` 写入计划文档作为会话主标识。

## 更新触发点

包括但不限于下列变化都需要更新计划文档，因为 Agent 需要看到最新事实，而不是过期计划：

- TaskList 任一任务进入 `in_progress`、`completed` 或 `blocked`，或从阻塞恢复。
- 追加、收窄或改变目标、完成标准、验证用例、可执行范围。
- 发现新的风险、阻塞、未确认项、环境限制或外部依赖。
- 产生 git stage、commit、push、PR，或确认暂存区/工作区范围。
- compact/resume 后上下文从计划文档恢复，且当前实际状态与文档不一致。

## 内容约束

- 完整性：其他 Agent 不读取当前会话上下文，能够不失真地继续执行当前计划。
- 时效性：与最新上下文一致；根据「更新触发点」，及时更新计划文档。
- 重复性：禁止大段记录推理过程，只保留能指导继续执行的结论、证据和决策；请勿重复其他引用资源（如相关产品/技术文档、设计稿、issue、commits、PR等）中已涵盖的内容，引用其路径或网址。
- 增量性：禁止盲目覆盖仍然有效信息，执行增量更新操作，只删除确定失效信息。
- 隐私性：不记录敏感原文、凭据、密钥、账号或不必要的个人信息。

## TaskList 规则

基于垂直切片拆分任务，使用 TDD/BDD 的原则执行任务

如果当前会话存在 `to-acceptance` 生成的验收文档，TaskList 的「验证用例」必须与验收文档的场景 ID 对应：

- 新增、删除或拆分 TaskList 时，保持「验证用例」引用的验收场景。
- TaskList 验证完成后，更新验收文档中对应验收场景的状态。
- 没有验收场景 ID 的任务只能是准备、清理或发布等非行为验证任务，并必须在「验证用例」写 `N/A` 和原因。

### 反模式：水平切片

不要先写完所有验证用例，再一次性完成所有 task；把 RED 当成“列出所有验证用例”，把 GREEN 当成“完成所有 task”，进而产生低质量验证用例：

- 批量写出的验证用例容易验证想象中的行为，而不是实际行为。
- 验证用例会对真实变化不敏感：行为坏了也可能通过，行为正常也可能失败。
- 在真正理解 task 之前就过早承诺验证用例，后续容易返工。

### 正确做法：垂直切片

- 一个验证用例 → 一个 task → 重复；每个验证用例基于上一个循环的事实，因为刚完成对应 task，最清楚哪些行为重要、该如何验证。

```
错误（水平）：
  RED:   验证用例1, 验证用例2, 验证用例3, 验证用例4, 验证用例5
  GREEN: task1, task2, task3, task4, task5

正确（垂直）：
  RED→GREEN: 验证用例1→task1
  RED→GREEN: 验证用例2→task2
  RED→GREEN: 验证用例3→task3
  ...
```

## 计划文档模板

- 必须包含`环境变量`、`TaskList`、`引用资源`、`推荐技能`。
- 其余章节基于上下文按需添加，不限定具体格式和内容。
- 保留 `<!--  -->` Tag;
