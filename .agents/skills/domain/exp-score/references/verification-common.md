# Experience Score Verification Profile

本 reference 把 verifying skill 的通用门禁链映射到体验分跨仓交付。项目拓扑读取 [workspace.md](workspace.md)，前端命令读取 [command-common.md](command-common.md)，真实路径参数读取 [e2e-common.md](e2e-common.md)。

## 影响面参数

每轮验证先识别：

- 前端 app、workspace、V10 feature/page、H5/PC 端型、抖店/罗盘平台与页面路由。
- 后端/BFF/数据服务仓库、接口或 RPC、配置/TCC 与消费者入口。
- 目标 PPE/BOE、待验 commit/制品、`shopId`、账号权限和测试数据。

前端或后端一侧没有改动时记录“不受影响”；共享 Kit 改动必须映射到受影响的 H5/PC 消费路径。完成标准：所有 touched files、接口与配置都落到一个可执行验证项。

## 体验分门禁链

1. **前后端本地门禁**
   - 前端按 [command-common.md](command-common.md) 确认工具链版本，对少量文件执行 Biome，对跨模块改动执行 changed lint，对受影响 workspace 执行 test/build/HMR 中的适用项。
   - 后端按各子仓规范执行受影响包或服务的 lint、类型检查、测试和 build。
   - 完成标准：受影响两侧的适用门禁均通过；未受影响侧已有明确记录。
2. **后端运行态**
   - 后端版本需要变化时，按项目当前发布流程准备目标 PPE/BOE，并记录部署任务与版本映射。
   - 后端无需变化时，记录目标环境已有所需版本、配置和数据依赖的证据。
   - 完成标准：目标接口所在服务版本与待验版本对齐。
3. **商家态**
   - 按 [e2e-common.md](e2e-common.md) 调用 `/doudian-login`，准备匹配环境、平台、`shopId` 和页面路径的会话。
   - 完成标准：目标 URL 可访问，商家身份和场景数据匹配。
4. **真实路径**
   - 调用 e2e skill 的“跑真实路径”分支，并注入 [e2e-common.md](e2e-common.md) 的端型、平台、路由与数据口径。
   - 完成标准：范围内 UI、交互、相关接口和页面消费结果都有断言与证据。
5. **诊断与最小重验**
   - 前端代码修复回到第 1 步；后端修复在本地门禁通过后重走第 2 步；商家态/环境变化回到第 3 步；只改变验收动作或数据时回到第 4 步。
   - 完成标准：所有受影响路径通过，或每个剩余项都有 blocked 证据和恢复入口。

## 入口映射

- **完整交付**：从第 1 步进入，覆盖所有适用阶段。
- **仅本地验证**：只执行第 1 步，并列明部署、商家态与真实路径未覆盖。
- **从部署继续**：已有本地门禁通过证据，且用户提供部署任务或版本证据时，从第 2 步进入。
- **从商家态继续**：用户要求验收已部署版本，且版本对齐已有证据时，从第 3 步进入。
