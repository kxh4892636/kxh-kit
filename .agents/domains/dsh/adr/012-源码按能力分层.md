# 012-源码按能力分层

`repos/dsh-toolkit/src/nano-flow/` 按能力分组，一个能力目录装它的工具、提示词、模板与实现：

- `assembly/`：组合根（plugin、preset）与组装/跨能力集成测试；
- `session/`：会话装配与生命周期（assets、config、services、workspace、rotate、limits、`prompts/{system,user,limit}.md`、工具共享运行时）；
- `documents/`：领域文档校验（`check-domain.mjs` + `lib/`）、check 工具与模板；
- `planning/`：`plan` / `plan-log` / `notes` 与 create、bind 工具；
- `dream/`：记忆维护（`prompt.md`、`scan.mjs`、dream 工具）；
- `skills/`：随包 skill 资产。

## Considered Options

- **按能力分组（选定）**：改一个功能只在一个目录里挪动，工具、提示词与实现相邻。
- **按类型分组（原状）**：`tools/` / `prompts/` / `templates/` / `scripts/` 摊平，一个功能改动跨四五个目录。

## Consequences

- **发布布局是运行时契约**：`dist/nano-flow/{prompts,templates,skills,scripts}` 不变；`session/assets.ts` 同时认发布布局与源码布局（先试发布路径、再试源码路径），资产复制脚本改用显式源→目标映射。
- **测试随模块**：能力测试与实现同目录；组装与跨能力集成测试（plugin / preset / runtime / prompt-rules / limits / 工具）集中在 `assembly/`。
- **单处实现**：公共面只由 `index.ts` 显式导出，同逻辑只留一处。例外是 frontmatter 解析与 Plan 扫描在 `documents/lib/` 与运行时各有一份——脚本是独立进程的零依赖 `.mjs`，不能 import TS；语义由两侧测试对齐。
- **结构由测试固定**：`layering.test.ts` 断言 `shared` 不依赖 host/client/nano-flow、`nano-flow` 不依赖 client；`prompt-rules.test.ts` 断言提示词里的硬规则句（批量写、新建 Plan 需确认、交付单元）。
- 命名规则仍单点：`planning/create.ts` 从 `documents/check-domain.mjs` 引，不在本地复制。
