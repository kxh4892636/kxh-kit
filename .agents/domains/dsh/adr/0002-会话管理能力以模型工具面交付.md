# 会话管理能力以模型工具面交付

DSH 的会话与模型管理能力以模型工具（注册于 `ctx.tools`、模型可直接调用）单面交付，不提供 CLI 子命令或 HTTP 路由面。会话内 agent 是编排主体，而 `dsh` launcher 无插件级子命令 seam、仓库无官方非浏览器 client 路径，模型工具是唯一低成本的进程内交付面；若未来需要 CLI/HTTP 面，另行决策。

## Considered Options

- **模型工具（选定）**：`defineTool` + `ctx.tools.register`，会话内直调 Host 服务（`ctx.sessionController`），零通信成本。
- **应用层 CLI 子命令**：仅 `dsh --profile web <子命令>` 可达（`parseCmdline`，web-app `startup.ts` 先例），无法成为 `dsh session ...` 启动级命令；且与运行中 Host 的 live session 无进程间通路。
- **HTTP 路由**：`webServer.register` 可行（webhook-github 先例），但 `/api` 受 loopback fence + HMAC cookie + 进程 launch token 三重鉴权，仓库无官方外部驱动；仅适合自用。

## Consequences

- 能力只能由会话内模型触发；GUI 用户需经会话请求调用。
- 验收以在会话中真实调用工具（冒烟）为准。
- 未来若出现 CLI/HTTP 需求，将推翻本决策并重新讨论交付面，而非在既有面上扩展。
