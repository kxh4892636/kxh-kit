# 004-会话初始化上下文以系统消息注入

会话创建时注入的上下文以**系统提示词段**形态加入新会话，而不是用户消息：不触发模型调用，首次模型调用等待第一条用户消息。当前 `plugin.ts` 在预设作用域注册 `systemPrompt.section({ name, order: 1, text })`，把 `prompts/system.md`、`.agents/domains/GUIDE.md` 快照与 `prompts/limit.md` 生成的篇幅限制块按顺序拼接；后续用户输入另走运行时上下文。

## Considered Options

- **系统提示词段（选定）**：上下文进入会话作用域系统提示词；创建零调用成本；上下文恒在用户消息之前。
- **用户消息 seed**：创建后立即 `prompt` 投递种子用户消息；直接触发一次真实模型调用，上下文与用户消息混存。
- **预设 persona 前缀**：只适合短固定文案，无法承载随工作区变化的 GUIDE 与篇幅限制；被拒绝。

## Consequences

- 创建新会话不产生模型调用；首个模型请求由第一条用户消息驱动。
- 固定提示词与 GUIDE 在会话内稳定时保持 KV 缓存前缀稳定；GUIDE 按 agent 缓存，篇幅限制每次 assembly 重读设置。
- 与 `session_prompt`（用户消息，触发调用）语义严格区分；错误地把上下文作为用户消息注入会造成非预期调用。
