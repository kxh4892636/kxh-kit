# 002-会话管理改由宿主路由与按钮

早期决策把会话与模型管理能力以模型工具（注册于 `ctx.tools`、模型可直接调用）单面交付，不提供 CLI 子命令或 HTTP 路由面；理由是会话内 agent 是编排主体，而 launcher 没有插件级子命令 seam。

当前 `@kxh4892636/dsh-toolkit` 的撤回不再是模型工具：它由面板开关控制，在会话工具栏放「撤回」按钮，经 `/api/toolkit/undo-turn` 路由触发，根插件包装 `sessionController.prompt` 并调用 `session/fork` 完成。模型不参与撤回的触发与执行。

## Considered Options

- **模型工具（早期选定）**：会话内直调 Host 服务，零通信成本；但用户需要先在对话里请求模型，无法直接点按钮。
- **宿主路由 + 会话按钮（当前）**：GUI 用户直接操作，根插件持有 `sessionController` 与归档记账；模型不接触会话管理。
- **应用层 CLI 子命令**：与运行中 Host 的 live session 无进程间通路；被拒绝。

## Consequences

- 会话管理能力与模型工具解耦；面板开关关闭时按钮、路由与效果一起消失。
- 验收以 GUI 按钮与宿主路由为准，不以模型调用为准。
- 本 ADR 保留早期理由；当前实现以 `packages/dsh-toolkit` 的 `undo-turn` 与 README 为准。
