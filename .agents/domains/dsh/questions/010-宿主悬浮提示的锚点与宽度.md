# 010-宿主悬浮提示的锚点与宽度

## 适用条件与现象

给宿主 UI 的列表行加悬浮提示（Note 面板三字段提示即此例）时，出现其一：

- 鼠标停在行上没反应，只有正好压住标题文字才出提示；
- 气泡不显示或显示不全，被输入框区域裁掉/压住；
- 换成浅色卡片后卡片很宽，文字只占左边一条，右边大片留白。

## 原因

宿主 `Tooltip`（`@deepseek-ai/dsh-client-ui-primitives`）的行为都由它自身决定，接入方只能选锚点：

- 悬停事件经 `cloneElement` 绑在**子元素**上，气泡定位也用该子元素的 `getBoundingClientRect()`；子元素只包标题文字时，行的其余区域无事件。
- 气泡默认就地渲染为 `position: fixed`；祖先若有 `transform` / `overflow: hidden`（composer dock 就有），`fixed` 会被裁剪或压层，需要 `portal`。
- 气泡样式是唯一的深色（`--dsw-alias-tooltip-bg` + 白字），类名哈希化，没有浅色变体，也**不能**靠全局改 `[role="tooltip"]` 局部覆盖；它用 `white-space: pre-line`，所以 `label` 里的 `\n` 就是换行，不需要自绘浮层。
- 想要浅色卡片只能用 `HoverCard` 的 `preview` 变体：宽度恒为「锚点宽 − 48px」（左右各 24px 内缩），`fitContent` 在该分支不生效；内容再自带 `max-width` 就会在卡片里留白。

## 解决方法

1. **锚点取整行**（`.dshtk-notes-row` 这类行的根元素），不要取标题 `span`；行悬停时给标题提亮作为可交互线索。
2. 气泡开 `portal: true`，`label` 用 `\n` 拼多行（描述 / 有值才带「原因：」「下一步：」，空值不拼，避免空行）。
3. 需要浅色卡片时改用 `HoverCard` `variant: "preview"`，内容 `width: 100%` 跟随卡片，**不要**设 `max-width`，也不要传 `fitContent`。
4. 宿主缺组件时退回原生 `title` 属性，保证至少有一行文本。

## 验证

- 面板单测断言锚点是行元素、`[title]` 上是三行文本（描述 + 下一步 / 描述 + 原因 + 下一步）。
- 真机：鼠标压住状态名或行内空白都能出提示；浅色卡片文字铺满整行且三行左对齐。
