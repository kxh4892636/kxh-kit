# 009-第三方插件自定义会话事件导致历史加载失败

## 适用条件与现象

DSH 0.2.x、会话格式 v4；工作区外的插件（如 `@kxh4892636/dsh-toolkit`）向会话日志追加自定义类型的事件。live 会话一切正常，但重启宿主或冷读历史时报：

```text
session "…" contains event type "<plugin/type>" (seq N) unknown to this harness
and not marked ignorable; refusing to interpret the log
```

## 原因

- 读路径按构建期静态的 `KNOWN_SESSION_EVENT_TYPES` 校验；集合外事件必须带信封字段 `ignorable: true`，否则整条日志拒绝重建，避免静默丢事件后重建出错误会话。
- 写路径的 `Session.append(type, data)` 只接受 `SessionEventMap` 类型，运行时不校验“能否读回”，也没有 `ignorable` 参数；第三方插件的声明合并只影响 TypeScript。
- 0.2.2 唯一写 `ignorable: true` 的入口是 `appendPluginRecord(session, "plugin:…", data)`；它面向仓库内 `packages/experimental/`，README 明确仓库外插件也不得调用。
- 结果：`session.append` 的自定义事件“写得进去、读不出来”，故障延迟到下一次冷读才出现。

## 解决方法

- 派生自工作区/文件系统、只服务 UI 的状态不要写会话日志；宿主按需计算，经 `connection.fetch.register` 暴露 HTTP 路由，客户端挂载时轮询。
- 必须持久化时放进插件自己的存储（`$DSH_HOME/...`），不要借用会话事件；不要调用 `appendPluginRecord`。
- 已损坏的日志：离线逐帧解码，只给该事件补 `"ignorable": true`，保持帧边界与 seq 不变；删除事件会让后续 seq 与 `sourceEventSeqs` 全部错位。改写前备份，改写后校验帧可解、seq 连续、未知非 ignorable 归零。
- 先用全量日志扫描确认影响范围（`$DSH_HOME/sessions/**/session.v*.jsonl.zstd`），不要批量改。

## 验证

- 修复后冷读该会话成功，日志事件数、seq、payload 均不变，仅目标事件多出 `ignorable`。
- 全量扫描 0 个未知非 ignorable 事件。
- 新版本会话里不再出现自定义事件类型。
