# 004-移除全部隐式绑定路径

交付：绑定表只允许 `nano_flow_bind` 写入。验收：check、plan-log、轮转都不创建或修改绑定；未绑定时看板与日志不出现；测试与类型检查通过。

## 移除清单

1. **`nano_flow_check`**：删除「显式 plan 或唯一 active Plan」的绑定逻辑、`listActivePlans` / `listPlans` 相关导入与 `runtime.bind` 调用。`plan` 参数只用于缩小校验范围，工具描述明确「不写绑定」。
2. **plan-log 自动绑定**：删除 `plansFor` 选项、`allowBind` 与「工作区唯一 active Plan」启发式。未绑定时服务只跟踪会话事件：`turn/end` 到达后丢弃已完成轮次，进行中的轮保留缓冲；绑定出现后从当前轮开始写入，绑定前已完成轮次不回填。
3. **轮转继承**：不再调用 `bindSession` 写新会话。autoCheck 仍读旧会话绑定，只作为 seed 的只读线索；seed 明确「新会话不会自动绑定，恢复时先调用 `nano_flow_bind`」。
4. **首写先赢语义**：删除 `recordBinding`、facade `bindSession` 与工具运行期的 `bind`，只保留覆盖写的 `replaceBinding` / `rebindSession`。绑定表只剩一个写入口。

## 回填边界

服务启动时若会话已绑定，仍从会话持久化日志回填未落盘的轮次；但只回填 `turn/end` 时间不早于绑定 `boundAt` 的轮次。这样同一会话中途换绑或重启时，绑定前的旧轮次不会被复制进新 Plan。

## 验证

- `plan-log-service.test.ts`：8 项，覆盖预绑定回填、不自动绑定、非 nano-flow 预设忽略、绑定当轮整轮写入且不回填旧轮、未绑定完成轮丢弃、重启去重、subagent 跳过、换绑后写新 Plan。
- `tools.test.ts`：确认 `nano_flow_check` 在无绑定与显式 plan 两种情况下都不调用 `rebind`。
- `rotate.test.ts` / `plugin.test.ts`：seed 与恢复流程改为显式 bind 口径。
- `pnpm -C packages/dsh-toolkit test`：38 个测试文件、324 项全部通过。
- `pnpm -C packages/dsh-toolkit check`：格式、lint 与类型检查通过。
