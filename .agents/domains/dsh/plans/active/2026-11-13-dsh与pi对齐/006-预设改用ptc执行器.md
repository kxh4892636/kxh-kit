# 006-预设改用ptc执行器

## 目标

用户指出 nano-flow 仍挂在已弃用的选型器上。取证：`@deepseek-ai/dsh-agent-tool-presentation@0.2.2-rc.2` 的 README 首段写明 Deprecated，迁移说明是「replace this selector row with the corresponding executor row and remove `config.mode`; do not load both in the same scope」，package.json 的 description 也标了 Deprecated。

## 交付

- `preset.ts`：删除 `tool-presentation`（`@deepseek-ai/dsh-agent-tool-presentation`，`config.mode = "ptc"`），改为 `{ id: "tool-executor-ptc", name: "@deepseek-ai/dsh-tool-executor-ptc" }`，不带 `config.mode`；不在同一作用域同时挂两者。
- `preset.test.ts` 的插件行断言同步；预设 description 与 README 的 PTC 说明同步。
- 确认宿主 bundle 已挂 `code-runtime`（`dsh-ptc-runtime-node`），否则执行器不会激活。

## 验收

- 构建产物里预设行只含 `dsh-tool-executor-ptc`；`vp test` 通过。
- 真机：nano-flow 会话仍以 `run_code` + 生成 SDK 呈现工具，非 PTC 会话不受影响。

## 风险

- 旧选型器在运行时缺失时会「回退继承执行器」；直接挂执行器则要求 `ctx.ptcRuntime` 存在，缺失时预设激活失败（README 明写「A enabled PTC executor without a runtime stops application startup」）。

## 交付记录（2026-11-13）

- `preset.ts` 删除 `tool-presentation` 行，改挂 `{ id: "tool-executor-ptc", name: "@deepseek-ai/dsh-tool-executor-ptc" }`，不带 `config.mode`；`preset.test.ts` 断言改为「直接挂 PTC 执行器、不再出现已弃用选型器」；README 补一段说明。
- 依据：`@deepseek-ai/dsh-agent-tool-presentation@0.2.2-rc.2` README 首段 Deprecated + 迁移说明。
- 验证：`vp test` 通过；`dist/index.mjs` 只含 `dsh-tool-executor-ptc`，不含 `dsh-agent-tool-presentation`；宿主 web bundle 已挂 code-runtime。
- 风险：宿主缺 code-runtime 时预设激活会直接失败（旧选型器是回退）。
