# 014-收敛重复实现

交付：同一逻辑只有一个实现，其余调用点改为引用。验收：每项收敛后 `test` 与 `check` 全绿；无行为变化（对比收敛前的测试基线）。

## 待收敛清单（012 的取证）

| 逻辑 | 现状 | 计划 |
| --- | --- | --- |
| `describe(error)` | 13 处各自实现 | 抽 `src/shared/errors.ts`，宿主与客户端各自引用 |
| `isRecord` / `asRecord` | 5 处 | 抽 `src/shared/record.ts`，统一两个名字 |

| Plan 扫描 | 2 套（`plan.ts` 与 `check-domain.mjs`） | 让脚本复用同一份扫描逻辑（共享 JS 产物或脚本内联同一实现） |

## 风险

- `check-domain.mjs` 与运行时共享解析会牵动构建（脚本不能直接 import TS）；先在脚本内保持单实现，等 015 拆分时再统一。
- 收敛 `describe` 时注意有的实现会附加前缀（`nano-flow: plan log`），统一后要保留调用点前缀。
