# 010-轮转保留分组与置顶

## 现象

用户反馈：轮转之后，会话的分组与置顶状态都丢失，新会话掉进侧边栏的「未分组」。

## 取证

- `$DSH_HOME/storages/workspace.json` 是工作区注册表：`tables.workspaces.<id>.sessionIds` 是手动顺序下的会话记账，`global.pinnedSessionIds` 是「registry-global 置顶集，最近置顶在前」。
- 轮转（`rotate.ts`）只调 `controller.create({ cwd, agentPreset })` 建新会话；`session-controller` 的 `create` 只有在传 `workspaceId` 时才 `attachSession`，传 `cwd` 不会。旧会话在 `retire` 里被 `detachSession`。所以新会话**从未进过任何工作区**，侧边栏只能归到「未分组」。
- 置顶集同理：旧会话被删掉，新会话没有被写进 `pinnedSessionIds`，置顶丢失。
- 宿主（0.2.2 运行时）已提供所需 API（从 `app.asar` 取证）：`workspace.attachSession` / `insertSessionBefore` / `detachSession`；`workspaceRegistry.pinSession` / `unpinSession` / `get pinnedSessionIds`（置顶要求会话存在且未归档，pin 会 prepend 到置顶集最前）。

## 实现（0.5.23）

`rotate.ts` 在 `controller.create` 之后、投递 seed prompt 之前调用 `inheritPlacement(oldId, newId)`：

1. 读旧会话所在的工作区记录与是否置顶（`pinnedSessionIds`）。
2. 逐个工作区 `attachSession(newId)`，再 `insertSessionBefore(newId, successor)`（`successor` 为旧会话在 `sessionIds` 中的后一条；旧会话在末位时追加到末尾），让新会话落在旧会话原来的槽位。
3. 旧会话置顶时：`pinSession(newId)`（新会话未归档，可 pin；置顶集最前）再 `unpinSession(oldId)`，避免旧 id 残留。
4. 任一步失败只 `logger.warn`，不阻断轮转；宿主没暴露这些面时按缺失跳过。

## 验证

- 单测：`rotate.test.ts` 新增「carries the old session's workspace slot and pin」，断言 attach、顺序 `[session-older, session-1, session-new, session-later]`、pin 新会话、置顶集只剩新会话；rotate 共 9 例通过。
- 全量：`vp test src` 280 例（36 文件）通过；`vp check` 121 文件格式 + 92 文件 lint/类型通过。
