# 016-轨迹日志轮转验收

## 背景

009 的轨迹日志已在 0.5.27 上验完「新会话首轮」：绑定由 `nano_flow_check` 经宿主 facade 写入，`log.jsonl` 新增段头 + 完整 turn（user/assistant/tools/usage/seq）。从 009 拆出，专门跟剩下的「轮转后」一段，避免 009 超过篇幅上限。

## 已知事实

- `log.jsonl` 目前有 2 个会话段：旧会话 `session-17660661`（5 轮，turn 2–4 是 0.5.22 的缺陷形态）与 web 验证会话 `session-6bd003fe`（turn 1 完整）。
- 轮转建新会话、注入 seed、退役旧会话的逻辑在 `rotate.ts`；binding 与回填由 `plan-log-service` 完成。
- web 验证环境：`dsh web`（web profile 0.5.27）+ bsk 驱动 Chrome；token URL 每次启动唯一。

## 验收（`/rotate` 后）

1. 新会话打开后第一条输入是 seed（「上一会话因上下文达到阈值已轮转…」）。
2. 新会话执行一次 `nano_flow_check` 后，`log.jsonl` 出现新会话段头，且新会话的绑定轮记录完整（user/assistant/tools/usage/seq）。
3. 旧会话的回填：轮转前未结束的轮若已在旧会话结束，绑定表/日志不重复写。
4. 同时核对 010（新会话仍在原工作区分组与位置、置顶保留）与 012（客户端切到新会话）。
