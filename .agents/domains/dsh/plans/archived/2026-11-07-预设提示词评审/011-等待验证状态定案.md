# 011-等待验证状态定案

> 迁移自旧 notes.json / story.md / spec.md；正文保留历史记录，旧工具、状态名与路径不再适用。

## 问题

note 只有 pending / in_progress / blocked / completed 四态；「代码完成、等真机验证」只能留在 in_progress，与「正在改」无法区分（note 08 / 10 都踩过：代码与测试都过了，界面却仍显示进行中）。

## 定案(2026-11-07 第 1 轮)

- Q2 标识与流转 → `awaiting_verification`（显示名「等待验证」）；`in_progress → awaiting_verification → completed`；验证失败回 `in_progress`；`complete` 必须先经过该状态。
- Q3 呈现 → `ready` 不列等待验证；`todoGroups` 保留在依赖分组里、排在同层可执行项之后（blocked 之前）。

## 状态机

- `pending → in_progress`；`in_progress → awaiting_verification | blocked`；`awaiting_verification → in_progress | completed`；`blocked → in_progress`。
- `complete` 只接受 `awaiting_verification`；其余状态调用报错并提示先改状态。
- 等待验证的 note 必须写「待验证」小节（要验什么、怎么验）。
- 等待验证算未完成：Plan 不能迁 reference；`planStatusOf` 仍归 `in_progress`。
