# 010 修复轨迹句柄泄漏

修的是审计第 5 条：轨迹服务为每个会话留一份状态和打开的读句柄，只在 `dispose` 清理；轮转每次新建会话、删掉旧日志，旧状态与句柄永远留着。

## 改了什么

`planning/plan-log-service.ts`

- `PlanLogService` 新增 `forget(sessionId)`：把 id 记进有界集合 `gone`（上限 256，超了丢最早的），删 `presets` 条目，从 `sessions` 摘掉状态，**先等排队中的 flush 跑完**再 `close()` 句柄；句柄关闭失败只 warn。
- `ensureState` 与 `onEvent` 都先看 `gone`：已删会话的迟到事件不会重建状态、不会重开句柄。
- 导出 `PlanLogService` 类型给根半用。

`index.ts`

- `planLog` 提前到 `createRuntime` 之前创建，作为第三个参数传进去。
- `registerRemoval`（轮转退休与撤回共用）里调 `void planLog.forget(sessionId)`，与 `api-session/removed` 广播同一处触发。

## 行为变化

| 之前 | 现在 |
| --- | --- |
| 每次轮转留 1 个 SessionState + 1 个打开的读句柄 | 会话被移除时立即释放 |
| 已删会话的迟到事件会重新建状态 | 忽略（`gone` 集合内） |
| `presets` 只增不减 | 随 forget 删除 |

不影响：绑定表、日志内容、写入时机、未绑定时的丢弃规则。

## 验收

- 新增测试 2 条（`plan-log-service.test.ts`）：forget 关闭句柄一次、迟到 turn 不写入也不再开句柄；对从未跟踪的 id 调 forget 不抛错。
- `vp test src`：43 个文件、375 条全绿。
- `vp check`：格式与类型无问题（`index.ts` 已按格式器重排）。
