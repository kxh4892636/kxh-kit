# 008 端到端链路清单

## 场景 1：打开 nano-flow 开关

`toolkit 面板 POST /api/toolkit/state {id:"nano-flow", enabled:true}` → `ToolkitRegistry.setEnabled` → `createNanoFlowTool.apply` → `inject(["agentPresets"])` → `agentPresets.register(createNanoFlowPreset(entryUrl))`。

关闭即 `unregister`，预设选择器里随之消失；已选该预设的会话不受影响（预设行已挂载）。

## 场景 2：选预设开新会话

宿主按预设行逐行挂载 → 最后一行 `nano-flow` 以 `{nanoFlowOnly:true}` 加载同一入口 → `applyNanoFlow` → `inject(["tools","systemPrompt"])` → 注册一段系统提示词、一条每轮上下文、四个工具、一个 skill provider。首轮请求时 `promptText` 读 `GUIDE.md`（按 agent 缓存）并拼篇幅块；`pre-step` 在 step 1 记下 turn。

失败：`recordMount("error")`，会话照常可用但完全没有 nano-flow 能力。

## 场景 3：建域 / Plan / note

`nano_flow_create({kind:"domain"|"plan"|"note"})` → `scaffoldDomain`（只补缺失）→ kind=plan 写 spec 与 notes_index → kind=note 找 Plan、算编号、按模板落盘。

随后 `nano_flow_check`：子进程跑 `check-domain.mjs` → 生成 `CONTEXT-MAP.md`、各 `index.md`、`notes_index.md`、spec 的追踪表，并把「已自动修复」与「已更新索引」回报给模型。

## 场景 4：绑定 Plan

`nano_flow_bind({plan})` → `resolvePlan`（同名需 domain/lifecycle）→ `facade.rebindSession` → 根半先 `pruneDeadBindings` 再整表覆盖写绑定表。

绑定之后：`notesOf` 能返回快照（面板出现），`plan-log-service` 的 `ensureBound` 能解析目录并开始落盘。

## 场景 5：一轮结束写轨迹

宿主 fires `session/event`（`tool/call`、`turn/end`）→ `onEvent` 过滤（非 subagent、preset 是 nano-flow、已绑定或工具名带 `nano_flow_`）→ 串行 `flush` → `read(cursor+1, 5000)` → `groupByTurn` → 出现 `turn/end` 的轮次 `buildTurnRecord` → 追加 `log.jsonl`（首次先写段头）。

未绑定：完整轮次丢弃，只留进行中轮的缓冲；绑定发生在轮中时，该轮在结束后照样落盘。

## 场景 6：上下文压力触顶

用户发 queue 消息 → 包装后的 `prompt` 读 `tokenMeter.contextPressure` → ≥ `0.618 × contextWindow` → 建新会话（同 cwd、同预设）→ 过继槽位/置顶/绑定 → 跑一次校验 → 取上一轮输出 → 拼 seed → 用新会话提交 `[seed, <rotation-prior-input>原文]` → 成功则记轮转、归档旧会话、删日志、广播移除；失败则旧会话继续。

## 场景 7：dream 维护

宿主定时任务把 `dream.md` 投递到新会话 → `nano_flow_dream scan` → 按「Plan + 会话」游标列新增 turn → 读 spec/note/域文档/轨迹切片 → 五个 pass 写领域文档与 GUIDE → `nano_flow_check` → `git commit` → `nano_flow_dream mark`（只前进）。

## 场景 8：改上限

面板 `POST /api/toolkit/nano-flow {patch}` → `parseNanoFlowSettings` 校验 → 原子落盘 → 内存值更新。下一轮系统提示词的篇幅块与下一次 `nano_flow_check` 的 `--limits` 立刻用新值；轮转阈值 `rotateAt` 同样即时生效。

## 场景 9：Plan 迁走 / 换机器

绑定里的 `cwd` 失效 → `resolvePlanDirectory` 退回当前工作区 → 目录仍找不到：面板快照返回 `null`（面板消失）、轨迹 `appendTurn` 跳过且只 warn 一次（不重建旧目录）、bind 报找不到。恢复方式：在新位置重新 `nano_flow_bind`。

## 场景 10：关闭开关 / 卸载

关闭开关只注销预设；已开会话的预设行仍在。卸载包后：路由消失、面板请求 404/501、绑定表与设置文件留在 `$DSH_HOME/toolkit`、Plan 与 `log.jsonl` 留在工作区（`log.jsonl` 被 gitignore）。
