# 001 装配与预设入口

## 范围

`src/index.ts`（根半，595 行）、`nano-flow/assembly/plugin.ts`（预设半，247 行）、`nano-flow/assembly/preset.ts`（预设定义，123 行）、`host/tools/nano-flow.ts`（开关，58 行）、`nano-flow/session/mount-report.ts`（诊断）。

## 分叉点

`apply(ctx, config)` 第一件事是 `recordMount("entry", { nanoFlowOnly, via })`，`via` 取 `preset` 或 `root`。随后：

| 条件 | 行为 |
| --- | --- |
| `config.nanoFlowOnly === true` | 只调 `applyNanoFlow(ctx, config)` 并 return；不建 registry、不注册路由、不挂轮转 |
| 其他 | `createRuntime(ctx, config)` 全量挂载 |

`name = "toolkit"`，`inject = ["skills"]`（预设半要在 `host.skills` 上注册 provider）。

## 根半挂载顺序

`apply` 依序做七件事，顺序有意义：

1. `createRuntime`：建 `ToolkitStateStore`（`$DSH_HOME/toolkit/state.json`）、`nano-flow` 设置存储（`$DSH_HOME/toolkit/nano-flow.json`）、`ToolkitRegistry`（四个工具：nested-skill / undo-turn / office-skills / nano-flow）。
2. `ctx.effect` 挂 `runtime.dispose`，`restoreMountReport()` 读回上次挂载诊断。
3. `ctx.inject(["connection"])` 注册六个路由（见 007）。
4. `ctx.inject(["sessionController"])` 挂会话轮转：`createRotation({ presetId: "nano-flow", autoCheck, adoptBinding, sessionOf, onRotated })`，并 `recordMount("rotation", …)` 记 tokenMeter / sessions / workspaceRegistry / workingDirectory 四个服务是否可见。
5. `ctx.inject(["workspaceRegistry"])` 调 `runtime.cleanupArchive`（待撤销归档与孤儿归档清扫，nano-flow 侧只关心 `unarchive`）。
6. `createPlanLogService` + `ctx.inject(["sessionPersistence"])`：`planLog.attach(persistence)`，并全局订阅 `session/event`（`{global: true}`）。
7. `void runtime.start()`：`settings.load()` → `registry.initialize()` → `runPendingPurge`。

## 根半对外暴露

`provide(NANO_FLOW_SERVICE, facade)`，服务名 `toolkitNanoFlow`，窄接口六个方法：

| 方法 | 作用 | 调用方 |
| --- | --- | --- |
| `settings()` | 当前上限与 `rotateAt` | 预设半的 settingsReader、校验工具、轮转 |
| `updateSettings(patch)` | 合并落盘 | 面板设置路由 |
| `announceRemoved(id)` | 登记隐藏并广播 `api-session/removed` | 轮转退休旧会话 |
| `recordPendingDelete(id)` | 登记「下次启动再删」 | 轮转退休 |
| `sessionsRoot()` | `$DSH_HOME/sessions` | 轮转删日志 |
| `rebindSession(id, dir, workspace)` | 唯一绑定写入口（先回收死条目再覆盖） | `nano_flow_bind`、轮转过继 |

另外 `ToolkitRuntime` 内部还有 `notesOf`（面板快照）、`lastRotation`/`rememberRotation`（客户端切换用）、`inspect`/`undo`（撤销，不属本域）、`cleanupArchive`。

## 预设半挂载链

```text
applyNanoFlow(ctx, config)
└─ recordMount("apply")
└─ ctx.inject(["tools","systemPrompt"], mountNanoFlow)
   ├─ locateAssetsRoot() → prompts/ system|user|limit
   ├─ createSettingsReader(services) → facade.settings() 或默认值
   ├─ createToolRuntime({ services, assetsRoot, domainRoot, rebind })
   ├─ systemPrompt.section({ name:"nano-flow:system", order:1, interpolate:false })
   ├─ tools.register × 4：create / bind / check / dream
   ├─ host.skills.registerProvider(createAssetSkillProvider(<skills>))
   ├─ systemPrompt.context({ name:"nano-flow:input", order:1 })（宿主支持才挂）
   ├─ services.on("agent/pre-step")：step===1 时记 `turnByAgent`
   └─ recordMount("ready", {promptBytes,userPromptBytes,section,context,skillsRoot,templatesRoot,services})
```

任一步抛错：`recordMount("error", {message, stack})` 后原样抛出——预设行挂载失败会被宿主记成启动告警，诊断文件是唯一能区分「没挂上」与「挂上没生效」的证据。

`serviceSnapshot` 探测八个服务：agent / tools / systemPrompt / skills / tokenMeter / sessionController / workspaceRegistry / agentPresets。

## 预设定义（preset.ts）

`id = "nano-flow"`，`name = "Nano Flow"`，`order = 2`，描述写明「工具经 PTC 模式（run_code）呈现」。行清单：

| id | 包 | 配置要点 |
| --- | --- | --- |
| persona | dsh-persona | prefix「本会话运行 Nano Flow…」 |
| agent-instructions | dsh-agent-instructions | `maxBytes: 65536` |
| time-context | dsh-time-context | — |
| tool-executor-ptc | dsh-tool-executor-ptc | 只挂执行器，不挂旧呈现选型器 |
| tool-bash / tool-pwsh | 同名包 | 按 `process.platform` 互斥禁用 |
| tool-fs | dsh-tool-fs | `applyPatch: false` |

| tool-jobs / skill-filesystem / tool-skill / tool-schedule | 同名包 | — |
| **nano-flow** | 本包入口 URL | `{ nanoFlowOnly: true }` |

`nanoFlowEntryUrl(moduleUrl) = new URL("./index.mjs", moduleUrl).href`：用绝对 URL，绕开 profile 的包解析。

## 开关

`createNanoFlowTool({ entryUrl })` 是 toolkit 面板里的 `nano-flow` 开关，`defaultEnabled: false`：

- 打开：`ctx.inject(["agentPresets"])` → `agentPresets.register(definition)`，存下 `unregister`；关闭时先置 `disposed`，注册若在关闭后完成则立刻 `stop()`，再 `dispose` 注入作用域。
- 预设不写在 bundle patch 里，因此「选择器里有没有 Nano Flow」严格等于这个开关。

## 挂载诊断

`$DSH_HOME/toolkit/nano-flow-mount.json`，形状 `{ at, pid, stages }`，五个阶段：`entry` / `apply` / `ready` / `error` / `rotation`。同进程按阶段合并写；`restoreMountReport` 只在 pid 相同时恢复旧阶段，否则清空。`disableMountReport()` 供测试关闭。所有写失败被吞掉。

## 失败与降级

| 缺失 | 表现 |
| --- | --- |
| 找不到资产目录 | `locateAssetsRoot` 抛错 → 预设半 `error` 阶段 → 预设行的工具与提示词全部缺失 |
| `toolkitNanoFlow` 服务缺席 | 设置回落 `DEFAULT_NANO_FLOW_SETTINGS`；`rebind` 抛「宿主未提供 Plan 绑定能力」 |
| `sessionController` 缺席 | `createRotation.attach()` 返回空操作，会话不会轮转 |
| `tokenMeter` 缺席 | 轮转包装仍在，但每次判定直接回落原 prompt |
| `sessionPersistence` 缺席 | 轨迹服务不 attach，`onEvent` 只更新内存状态，不写 log |
| `agentPresets` 缺席 | 开关打开也不注册，只记 warn |
