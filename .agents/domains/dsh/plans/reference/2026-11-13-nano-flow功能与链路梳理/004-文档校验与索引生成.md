# 004 文档校验与索引生成

## 两层实现

```text
nano_flow_check 工具（tools 侧）
└─ documents/check.ts       参数收窄 → runCheck
   └─ documents/check-runner.ts  execFile(process.execPath, [check-domain.mjs, workspace, --domains …, --json, --limits {…}])
      └─ documents/check-domain.mjs  CLI 解析 + checkWorkspace
         ├─ lib/base.mjs   常量、nameProblem、frontmatter 解析、写入边界
         ├─ lib/checks.mjs 单文档规则（readDocument）
         ├─ lib/fix.mjs    确定性字段修复（行级改 YAML）
         └─ lib/render.mjs 生成物渲染
```

规则只有一处实现：create 工具直接 `import` `check-domain.mjs` 转出的 `KEBAB/PLAN_NAME/HAN/NUMBERED_NAME/isValidDate/nameProblem`。子进程调用带 `ELECTRON_RUN_AS_NODE=1`（桌面宿主可能跑在 Electron 主进程）、`maxBuffer 8 MB`、`cwd = workspace`；只解析 stdout 最后一行非空 JSON。

## 校验顺序（checkWorkspace）

1. 解析 `rootDir`、`domainsRoot`（绝对或相对工作区）、`limits`（只接受正有限数，其余回落默认）。
2. 领域根不存在 → `missing` 直接返回，提示先跑 `nano_flow_create`。
3. `GUIDE.md` 缺失 → 写空文件（记一条 updated）；超过 `guideMaxBytes` → `size` 报错。
4. 遍历一级目录（域），`domain` 过滤生效；域目录名必须 kebab-case。
5. 每域：`CONTEXT.md`（必需）→ `questions/`（缺失则创建，记一条 fixed）→ questions / adr / workflows → plans。
6. 全域 `CONTEXT` 的 `name` 去重。
7. 无 domain 过滤且 strict 时，重写 `CONTEXT-MAP.md`。
8. 返回 `{ ok, errors, warnings, fixed, updated }`；`ok = errors.length === 0`。

## 规则清单

头字段：

| 规则 | 触发 | 级别 |
| --- | --- | --- |
| `header` 缺 YAML 头 / 头无效 | strict=false 时降为 warning | error |
| `header` 缺 name / name 多行 / 超 89 字 / 编号类型无 `NNN-` / 无汉字 | `nameProblem`，与 create 共用 | error |
| `header` 缺 description / 多行 / 超 `noteDescriptionMaxChars`(233) | — | error |
| `header` metadata 非对象；未知头字段 | 自由字段必须进 metadata | error |
| `header` spec/note/ADR 的 status 不在枚举 | spec: pending/in_progress/completed；note 四态；ADR 可选四态 | error |
| `header` note `blocked` 缺 reason / 超 233 字 / 非单行 | — | error |
| `header` 非 blocked 却写了 reason | 会被自动清掉，清不掉才报 | error |
| `header` 非 completed 缺 next_step / 超 233 字 / 非单行 | completed 不要求 | error |
| `header` related_noted 非字符串数组 | — | error |

结构与命名：

| 规则 | 触发 |
| --- | --- |
| `index` | 目录里出现 `INDEX.md`（索引必须小写 `index.md`） |
| `layout` | questions/adr 下出现目录、workflows 下出现文件、Plan 内出现嵌套目录、plans 下出现非生命周期目录 |
| `missing` | 必需文件/目录缺失（spec.md、CONTEXT.md、`<workflow>/<workflow>.md`） |
| `name` | name 与文件名/目录名不一致、name 重复、note 文件名不合 `NNN-中文标题.md`、Plan 目录名不合 `YYYY-MM-DD-中文工作名`、域目录名非 kebab |
| `number` | questions/adr/workflows 编号必须从 001 连续 |
| `lifecycle` | `plans/` 下的目录名不在三档 |
| `legacy` | Plan 里残留 `story.md`（warning，可删） |
| `status` | spec 状态与 note 派生不一致且无法自动改 |
| `spec` | `## 追踪 Note` 出现多次，或不是最后一个章节 |
| `related` | `related_noted` 自引用或指向不存在的 note |
| `relation` | CONTEXT `relations` 非数组/元素非对象/`to` 非 kebab/目标域不存在/`description` 空/关系重复 |
| `size` | 正文超该类上限，按 kind 给出不同建议（note/question/adr/workflow 拆新编号、spec 下沉细节、CONTEXT 压缩） |
| `missing`/`domain`/`plan` | 指定 domain / plan 不存在 |
| `read`/`write` | 读枚举失败、写入被拒 |

`## 相关` 段（context / question / adr / workflow 四类检查）：

- 最多一个、必须是最后一章、不能为空。
- 每行必须形如 `- [标题](相对.md) — 原因`；目标只允许 `.md`、按 URL 解码后必须存在；原因不能为空。

## 自动修复（结果由既有事实唯一决定）

| 修复 | 判据 | 登记 |
| --- | --- | --- |
| 多行头字段折单行 | 该 kind 的 `SINGLE_LINE_FIELDS` 里字段含换行 | `header` |
| 非 blocked 的 note 去 reason | status ≠ blocked 且 reason 非空 | `header` |
| name 对齐文件名 | 头里 name ≠ 文件名（`expectedName`） | `name`，并把改名传播到同 Plan 其他 note 的 `related_noted` |
| spec 状态派生 | 全 pending→pending、全 completed→completed、其余 in_progress；仅当原值是合法枚举才改 | `status` |
| 缺 `questions/` 建目录 | — | `missing` |

补齐与生成不计入「修复」：`GUIDE.md` 空文件、`追踪 Note` 章节缺失时追加。

收敛判据：第二次运行 `fixed.length === 0`。真实缺口（编号断档、`## 相关` 目标缺失、blocked 缺 reason、体积超限）只报不猜。

## 生成物（只由校验写）

| 文件 | 内容 |
| --- | --- |
| `CONTEXT-MAP.md` | YAML 头 name/description + `## Contexts`（`common` 置顶，`- [name](./<domain>/CONTEXT.md) - description`）+ `## Relationships`（`**A → B**：说明`） |
| `<domain>/questions/index.md` | 表头 Name/Description |
| `<domain>/adr/index.md` | 表头 Name/Description/Status |
| `<domain>/workflows/index.md` | 表头 Name/Description |
| `<plan>/notes_index.md` | `# Notes Index` + Name/Description/Related Note，含全部 note |
| spec `## 追踪 Note` | 只列未完成 note，按 blocked → in_progress → pending 排序，含 Status/Reason/Next Step/Related Note |
| `GUIDE.md`（仅缺失时） | 空文件 |

每个生成物都带标记 `<!-- 由 nano_flow_check 生成，请勿手改 -->`；链接目标保留中文（只转义破坏链接的 ASCII 字符）。表内单元格转义 `|`、压平空白。

## 过滤与模式

| 参数 | 效果 |
| --- | --- |
| `domain` | 只校验该域；**不**重写 CONTEXT-MAP（避免用不完整集合覆盖全量） |
| `plan` | 只扫该 Plan；找不到报 `plan` 错误 |
| `strict: false` | 缺头/坏头降为 warning；同时不重写 CONTEXT-MAP |

工具侧输出四段：失败明细 / 警告 / 已自动修复 / 已更新索引；全通过只报一句。

## 写盘安全

`writeInsideWorkspace`：路径 resolve 后必须在工作区内；父目录与（已存在的）文件都按 realpath 再判一次，防符号链接逃逸；同目录 `.tmp` 写完再 rename（中断不留半截）；内容相同返回 `unchanged`、不计数、不更新时间戳。越界或失败记 `write` 错误并跳过。

## 模板

`templates/` 十二个：`context.md`、`question.md`、`adr.md`、`workflow.md`、`spec.md`、`note.md`、`guide.md`（空）、`context-map.md`、`notes-index.md`、`questions-index.md`、`adr-index.md`、`workflows-index.md`。create 只消费前六个，其余由校验脚本或 domain 脚手架保持。
