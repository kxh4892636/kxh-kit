# 003 规划工具集

## 范围

`planning/plan.ts`（91）、`planning/create.ts`（324）、`planning/bind.ts`（85）、`planning/notes.ts`（84）。轨迹日志相关的 `plan-log*.ts` 见 005。

## Plan 发现（plan.ts）

```text
.agents/domains/<domain>/plans/<active|reference|archived>/<YYYY-MM-DD-中文工作名>/
```

| 导出 | 行为 |
| --- | --- |
| `PLAN_LIFECYCLES` | `["active","reference","archived"]`，顺序即创建建议顺序 |
| `isPlanLifecycle(v)` | 成员判定 |
| `planRefOf(plan)` | 还原 `<domain>/<lifecycle>/<name>` |
| `planRefFromDirectory(dir)` | 按最后一段 `plans` 反推：前一段 domain、后一段 lifecycle、再后一段 name；lifecycle 非法或层级不足返回 undefined |
| `listPlans(workspace, domainsPath)` | 三层遍历，`spec.md` 存在才算 Plan（story 已并入 spec），按 zh-CN 排目录名 |
| `activePlans(plans)` | 只留 `active`；轮转的 seed 用它判断「工作区只有一个 active Plan」 |

`listPlans` 读目录失败（不存在/无权限）时返回空数组，不抛错。

## create 工具

`nano_flow_create({kind?, domain, name?, title?, description?, lifecycle?, plan?})`，`kind` 缺省 `domain`，`domain` 必填。

### 共用前置

- `domain` 必须匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`（`KEBAB`）。
- 一切写入都过 `ensureInside(root, target)`：`relative` 以 `..` 开头或为绝对路径即抛「路径越界」。
- 每次调用都会先 `scaffoldDomain`：缺什么补什么（`CONTEXT.md`、`questions|adr|workflows/{index.md}`、`plans/{active,reference,archived}`、领域根 `GUIDE.md` 与 `CONTEXT-MAP.md`）。
- 落盘用 `writeFile(..., { flag: "wx" })`：只补缺失，不覆盖；已存在的记进 `skipped` 列表回报，不报错。

### kind=domain

用 `templates/context.md` 渲染 `CONTEXT.md`（占位 `{{name}}` / `{{title}}` / `{{description}}` / `{{description_text}}`；YAML 值里的 `'` 转成 `''`）。`name` 缺省取域名，`description` 缺省「<domain> 域的职责与术语，待补。」。`GUIDE.md` 只在缺失时落空模板——正文只由 dream 维护。

### kind=plan

- `name` 必须是 `YYYY-MM-DD-中文工作名`（`PLAN_NAME` 命中、`isValidDate` 校验日期真实存在、标题含汉字）。
- `lifecycle` 缺省 `active`，必须是三个枚举之一。
- 目录已存在直接抛「Plan 已存在」，不合并。
- 写 `spec.md`（`templates/spec.md`，description 缺省「<标题> 的规格与进度。」）与 `notes_index.md`（`templates/notes-index.md`）。

### kind=note

- `plan` 显式给了就定位到它；没给则按 `lifecycle`（缺省全部三档）找，且只把 `active` 下的目录当作候选；候选 0 个报「当前域没有 active 的 Plan」，多个报「请显式传 lifecycle 或 plan」。
- 编号：给了 `name` 就用；只给 `title` 时扫 Plan 目录已有 `NNN-`，取第一个空号补零成三位。`name` 过 `nameProblem(name, "note")`（规则与校验脚本同一份）。
- 默认头：`status: pending`、`reason:` 空、`related_noted: []`、`next_step`「读取 spec 与 notes_index，确认第一项可推进工作」。
- 文件已存在抛「note 已存在」。

### 输出

按 kind 返回三到五行文本：目标路径、顺带创建的文件、已存在的文件、「下一步」提示（跑 `nano_flow_check`）。

## bind 工具

`nano_flow_bind({plan, domain?, lifecycle?})`：

1. `plan` 必填；`lifecycle` 给了就必须是枚举值。
2. `listPlans` 全量列出后按 `name`（+可选 domain/lifecycle）过滤：0 个报查不到的键值，多于 1 个要求补 domain 或 lifecycle 并列出候选。
3. `runtime.rebind(exec, plan.directory, workspace)`：`session.id` + facade → 根半 `rebindSession`（先 `pruneDeadBindings` 再覆盖写）。
4. 返回三行：已绑定引用、同一会话只保留一个绑定、看板立即跟随且本轮结束后的轨迹写入新 Plan。

工具不改 Plan 内容、不改 note 状态、不清旧 Plan 的 log。

## Note 面板快照（notes.ts）

`readPanelNotes(planDirectory)`：

- 只在 Plan 根目录取 `^\d{3}-.+\.md$`（跳过 `spec.md`、`notes_index.md`、字典序外文件），按文件名排序。
- 逐文件读 YAML 头（`---\n…\n---`，CRLF 先归一），解析失败或缺头 → 跳过该文件，不抛错。
- `status` 必须在 `PANEL_STATUSES = ["pending","in_progress","blocked"]` 内——`completed` 天然不入面板；非枚举值跳过。
- `name` 缺省用文件名（去 `.md`），`description` 缺省空串，`reason`/`next_step` 空白视为没有。

`buildNotesSnapshot(workspace, planDirectory)` → `{ planName, planPath, notes }`：`planPath` 相对工作区、正斜杠，`planName` 取最后一段。

面板可见性不在本模块判定：根半 `notesOf(sessionId)` 先查绑定表，再 `resolvePlanDirectory` + `existsSync`，任一不成立返回 `null`（客户端不渲染面板）。

## 失败与降级

| 情形 | 行为 |
| --- | --- |
| 同名 Plan 跨域 | bind 报错要求补 domain，不猜 |
| Plan 已迁走 | bind 找不到；面板快照返回 null；轨迹跳过写 |
| note 文件名不合规 | create 用 `nameProblem` 拦；已存在的违规文件由校验脚本报 `name` |
| 目录不可读 | `readPanelNotes` 返回空列表（面板显示空态，而不是错误） |
