# 005 轨迹日志与上下文轮转

## 绑定表

`$DSH_HOME/toolkit/nano-flow-plan-bindings.json`（路径可用插件配置 `bindingsFile` 覆盖），形状 `{ [sessionId]: { planPath, cwd, boundAt } }`。

| 函数 | 行为 |
| --- | --- |
| `readBindings` / `readBindingsSync` | 缺失、坏 JSON、非对象一律返回空表；同步版供路由同步返回快照 |
| `writeBindings` | 建目录后整表覆盖写（两空格缩进） |
| `planRelativePath(ws, dir)` | 相对工作区、正斜杠 |
| `resolvePlanDirectory` | 绝对 planPath 直通；相对路径先试 `join(binding.cwd, planPath)`，该目录不存在再退回 `join(workspace, planPath)`（不保证存在） |
| `pruneBindings` | 只留存活会话（存活性由根半算：持久化列表 ∪ 仍存活的会话） |
| `inheritedPlanDirectory` | 旧会话有绑定且目录存在才算 |
| `adoptBinding` | 把旧会话的 planPath 复制成新会话条目（新 boundAt），返回表 + 目录；旧条目保留由启动回收 |

## log.jsonl 记录

Plan 目录下 `log.jsonl`，只追加。两种行：

```json
{"type":"session","v":1,"sessionId":"…","cwd":"…","planPath":"…","boundAt":"…"}
{"type":"turn","v":1,"sessionId":"…","turn":3,"startedAt":"…","endedAt":"…",
 "user":"…","assistant":"…","tools":[{"name":"…","args":"…","ok":true,"result":"…","truncated":{"args":false,"result":false},"resultBytes":12}],
 "usage":{"inputTokens":0},"seq":[41,88]}
```

- 段头每会话每 Plan 写一次（首次写 turn 前）；`cwd` 用会话真实 cwd，不用绑定时的 cwd。
- 截断全在头部：工具参数 4 KB、工具结果 4 KB、单轮 assistant 文本 8 KB（`ASSISTANT_LIMIT`）；截断时去掉切口的 U+FFFD。
- `tool/result` 的 callId 依次取 `message.source.callId`、`message.toolCallId`；缺失对应结果时 `ok: false`、`result: ""`。
- `seq` 取该轮事件的最小/最大 seq；`startedAt`/`endedAt` 取 `turn/start`/`turn/end` 的 `time`，缺失时用首尾事件时间。
- `groupByTurn`：先按 seq 排序；事件带 `data.turn` 时用显式值，`turn/start` 打开当前轮、`turn/end` 关闭；无 turn 的事件（如 `user/message`）落进当前窗口。

## 写入链路（plan-log-service.ts）

```text
session/event（global 订阅）
└─ onEvent(session, event)
   ├─ agent-preset/selected → 记 presets[sessionId]（是否 nano-flow），返回
   ├─ 跳过 subagent 会话（origin === "subagent" 或 delegationDepth > 0）
   ├─ 只处理 tool/call 与 turn/end；preset 明确为别的 → 丢弃
   ├─ preset 未知且未绑定且工具名不是 nano_flow_* → 丢弃（省掉无关会话的开销）
   └─ chain = chain.then(flush)   串行，失败只 warn
flush(state)
├─ ensureBound：重读绑定表；绑定身份 = cwd + planPath，变了才重解析
│   └─ 首次绑定且服务已在跟踪（无 handle、cursor < 0）→ 回填：
│       open(id,"read").read(0) → groupByTurn → 已结束且 turn/end 时间 ≥ boundAt 的轮次逐条 append
│       未结束的轮进 pending；cursor 推到最大 seq
├─ 无 handle → open
├─ read(cursor+1, 5000) → groupByTurn(events, 进行中的轮号)
├─ 与 pending 合并：未出现 turn/end 的继续缓冲
│   └─ 已结束：已绑定才 append；未绑定整轮丢弃（绑定前的轮次不属于该 Plan）
└─ cursor = 读到的最大 seq
appendTurn
├─ Plan 目录不存在 → 跳过（只 warn 一次，绝不重建旧路径）
├─ `<sessionId>#<turn>` 已在 seen → 跳过（跨重启去重：读文件时重建 seen 与段头索引）
└─ 写段头（首次）→ 追加 turn
```

`dispose` 依次 await 每个会话的 chain 并关句柄。服务**从不写会话事件**，只读 `sessionPersistence` 的只读句柄。

## 轮转（session/rotate.ts）

### 触发条件

包装 `sessionController.prompt`，只在这一串全成立时接管：

`mode === "queue"` → `sessionOf(id)` 取到会话 → 非 subagent → 会话预设是 `nano-flow`（读日志里最后一条 `agent-preset/selected`，读不到退回 header）→ `tokenMeter.contextPressure` 的 `projectedTokens ?? pressureTokens` ≥ `contextWindow × settings().rotateAt`（默认 0.618）→ 该会话不在 `rotating`/`rotated` 集合里。

任一不成立：原样调用原 `prompt`。steer 消息不触发。

### 新会话与 seed

`controller.create({ cwd, agentPreset: "nano-flow" })`，`cwd` 取 header.cwd → `workingDirectory.get` → 配置。随后并行准备四件事：

| 件 | 来源 | 失败 |
| --- | --- | --- |
| 槽位与置顶继承 | `workspaceRegistry`：attachSession、insertSessionBefore（插在旧会话的后继之前）、pin 新 / unpin 旧 | 只 warn |
| Plan 绑定过继 | `adoptBinding` → 返回 `<domain>/<lifecycle>/<name>` | 只 warn，seed 仍要求 bind |
| 轮转后自动校验 | 跑随包 `check-domain.mjs`（同一套 `--limits`），生成一句话结论或失败前 5 条 | 只 warn，seed 写失败提示 |
| 上一轮输出 | 最后一个含 `turn/end` 的轮里最后一条非空 assistant 文本，尾部截断 8 KB | 无则省略 |

seed 是拼出来的多段文本：

1. 固定起手「（上一会话因上下文达到阈值已轮转；Plan 在磁盘上，状态不丢。）」
2. 恢复行：绑定已过继 → `恢复当前 Plan：<ref>`；否则若工作区只有一个 active Plan 就自动填它，再否则要求先按 CONTEXT-MAP 询问用户。
3. 绑定已过继 → 说明无需再 `nano_flow_bind`、读 spec/notes_index 后只读报告；否则要求先 bind 再只读报告。
4. 自动校验结论（有才写）。
5. `<rotation-last-output>` 包住上一轮输出（有才写）。

### 发送与退休

新 prompt 的内容是 `[seed 文本, "以下 XML 块是轮转前用户在旧会话发出的输入：", <rotation-prior-input>, …原内容块, </rotation-prior-input>]`，`requestId` 重新生成，`sessionId` 指向新会话。

| 结果 | 行为 |
| 成功 | 记 `rotated` → `onRotated(from,to)`（根半存进内存，供路由给客户端切换）→ 退休旧会话 |
| 失败 | warn「rotation failed」→ 用原 prompt 在旧会话继续，消息不丢 |

退休顺序（每步失败只 warn）：

1. `archiveSession(id, { stopActivity: true })` —— 客户端据此立刻离开旧会话。
2. 从所有工作区记录里 `detachSession`。
3. `recordPendingDelete(id)`（下次启动的重试清单）。
4. 等 150 ms 让归档落盘。
5. `deleteSessionLogs(root, [id])`；`retained` 非空（有文件没删掉）就直接停在这里，不宣布移除。
6. 全部删掉后 `unarchiveSession` + `announceRemoved`（写入隐藏集合并广播 `api-session/removed`）。

### 根半接线（index.ts）

- `autoCheck` → `runCheck({script: assetsCheckScript(locateAssetsRoot()), workspace, domainsPath, limits})`，通过报一句、失败报前 5 条。
- `inheritPlanBinding` → `adoptBinding(await readBindings(file), 旧, 新, workspace, existsSync)`，写过继后的表，返回 `planRefFromDirectory`。
- `sessionOf` → `sessions.get(id)`。
- `onRotated` → `runtime.rememberRotation`（内存即可：命令与客户端切换在同一次宿主运行内）。
