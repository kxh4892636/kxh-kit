# 前后端共同迁移为类型化接口

ETF 合入 kxh-kit 时前后端共同迁移，使用 Node.js、Hono 与 Zod，HTTP JSON 接口通过 Hono AppType 和类型化客户端共享契约。选择停用 Connect/protobuf 及其生成链，接受旧外部客户端不兼容，换取同一 TypeScript workspace 内更少的契约维护与工具链。

Zod 在服务端验证请求、配置和上游输入；浏览器仅消费导出类型并处理 HTTP 状态和网络错误，不加载后端数据库或启动代码，也不重复维护响应 schema。此决策替代源项目 ADR 0003 中 Connect 生成客户端的技术选择，保留服务端拥有语义验证的原则；源项目 ADR 0001 的装配、行情、集成职责划分继续适用。

Hono 路由工厂及其 handler 使用框架上下文类型推导，避免显式拓宽为 Hono/Response 后丢失 AppType 的路径和响应契约；普通业务函数仍显式标注参数与返回类型。
