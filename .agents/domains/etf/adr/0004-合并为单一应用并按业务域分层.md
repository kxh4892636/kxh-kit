# 合并为单一应用并按业务域分层

ETF 前端与后端合并为 `apps/etf` 单一应用，应用根直接分为 `client`、`server`、`shared`；第三方接入放 `libs`，纯逻辑放 `utils`。服务端按业务域 `market` 组织，域内分 handler（控制层）、service（业务逻辑）与 repository（数据库接口与实现）。service/repository 不依赖 Hono，数据库接口归 repository，SQLite 只是可替换实现；依赖在 `server/server.ts` 组合根用工厂函数显式注入，不引入 DI 容器。API 保持 Hono RPC：链式 routes 导出 `AppType`，全局错误经 `ApplyGlobalResponse` 合并，客户端经 `hcWithType` 单点实例化；统一响应为 `{ code, message, extra, data }`，业务码与 HTTP 状态分离。

Considered Options：保留两个 workspace 包、按技术层全局分层、把数据库接口放 service、引入 DI 框架、跨方言 SQL 抽象、OpenAPI/SDK 生成均被拒绝，原因是无法满足单一目录、框架边界、可替换数据库与类型化 RPC 的组合目标，或引入超过当前规模所需的抽象。

Consequences：service/repository 可用假实现单测，替换 MySQL/PostgreSQL 只需新增同接口实现并改组合根；代价是 SQLite schema/迁移仍按方言实现，跨库替换需要新的 schema 与迁移，且统一响应需要前端解包 `data`。
