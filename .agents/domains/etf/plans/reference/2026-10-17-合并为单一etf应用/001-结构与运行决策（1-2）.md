## 决策与证据

已核实的现场事实（2026-10-17，main `17d76733`）：

- 后端已是 TypeScript + Hono，`src/app.ts` 用链式路由与 `validator` 定义接口并导出 `AppType`；`src/server.ts` 用 `@hono/node-server` 启动；前端 `src/libs/api/client.ts` 使用 `hc<AppType>` 与 `InferResponseType` 调用，即 Hono RPC 形式，现状已满足用户要求。
- 前端只有 `src/libs/api/client.ts` 引用 `@kxh4892636/etf-service/api`；`package.json` 将服务包列为 dependency。其余前端代码不感知后端位置。
- 前端 `src/common/cn.ts` 没有任何调用点；`market-number-format.ts` 只服务看板与图表，属纯逻辑；`libs/api/use-market.ts` 是 API 接入之上的 query hooks。
- 服务端 `market/dates.ts` 含 `tradeDate` Zod schema、`addDays`/`dateRange`/`isWeekday`/`shanghaiDate`；`storage/` 是 Drizzle/SQLite 接入并在打开连接时 seed；`integrations/hongsehuojian` 是上游 API 接入。
- 服务端 `market/{securities,daily-bars}.ts` 定义 `Security`/`DailyBar`/`DailyBarsMeta`/`DailyBarsResponse`；前端从 `AppType` 推导同形类型。
- 服务端测试现状：`service.test.ts` 混合配置、入口、HTTP 错误与 SQLite 初始化；`market/daily-bars.test.ts` 混合用例策略与存储事务（179 + 169 行）。按三层拆分后需随层迁移。
- E2E 在 `global-setup` 中编译服务包（`node_modules/@typescript/native/bin/tsc -p tsconfig.json`），`fixture-server.mjs` 直接 import `etf-service/dist/{server,integrations/hongsehuojian}.js`；`playwright.config.ts` 的 webServer 以 `pnpm run dev --host ... --port ...` 启前端。
- `vp run` 只按 workspace 包选择任务并行（`--parallel`），单包内不能并行两个 script；根 `dev:etf` 当前用 `--filter @kxh4892636/etf-*` 选择两个包。
- 本机 `apps/etf-service/data` 不存在；SQLite 缓存无需迁移。
- code-spec：`src/` 为 level-1，不存在时以项目根为 level-1；最多 4 层，level-4 只放文件，泛化名称仅在 level-2 允许。

结构与构建分析：

- 应用根直接分 `client`、`server`、`shared` 三个源码根，层级规则从各自根计算：`libs`/`utils` 位于 level-2，`features` 位于 level-2，`features/market-dashboard/chart/` 位于 level-4 且只含文件；`server/market/{handler,service,repository}` 位于 level-3，文件在第 4 层以内。前端无需拆分 chart 或收敛页面。
- 业务域优先：服务端以 `market` 为业务域目录，域内 `handler`/`service`/`repository` 三层；第三方接入与纯逻辑作为跨域 `libs`/`utils`，避免按技术层全局铺开。
- 服务端编译：`tsconfig.server.json` 必须 `rootDir: "."`、`outDir: "dist"` 才能同时编译 `server` 与 `shared`；`rootDir: server` 即使只做 type-only 引用也会报 TS6059（已用 tsc 实测）。产物为 `dist/server/*`、`dist/shared/*`，`start` 为 `node dist/server/main.js`。
- 迁移目录：产物比源码多一层 `dist/`，同一相对路径无法同时命中；改为 `path.resolve("migrations")`，与现有 `.env`、相对 `DATABASE_DSN` 的「应用根为 cwd」约定一致，dev/start/E2E 均满足。
- 前端构建：Vite `root: "client"`，`index.html`/`public` 归入 `client`，`outDir: "../dist/client"`；`@` → `client`，`@shared` → `shared`。
- Hono RPC 子应用：已用 Hono 4.13.7 + tsc 验证 `new Hono().route("/api", subApp)` 后 `AppType` 仍可被 `hc` 推导出 `/api/securities` 的响应类型，因此 handler 拆分不会破坏 RPC 契约。
- 依赖注入用工厂 + 组合根，不引入容器；`MarketRepository`/`RemoteFetcher` 端口定义在 service，repository/libs 实现端口，`server.ts` 唯一装配。
- 共享内容：`shared/market.ts` 放契约类型，`shared/utils/trade-date.ts` 放前端与后端都需要的日期纯函数；服务端保留 Zod schema（HTTP 输入）与 `shanghaiDate`。
- 数据库接口：`MarketRepository` 定义在 `market/repository/market-repository.ts`（Q12 修订，接口与实现同属 repository），SQLite 实现独立在 `repository/sqlite/`；`libs/sqlite/database.ts` 只负责连接/迁移。已核对 drizzle-orm 0.45.2 的驱动目录（better-sqlite3、libsql、mysql2、node-postgres、sqlite-core 等，无 node:sqlite），better-sqlite3 13.0.3 要求 Node >=22 且提供 Win/Linux/macOS 预编译。
- 框架边界：service 与 repository 不导入 `hono`/`@hono/*`；Hono 仅在 `market/handler`、`server/app.ts`、`server/server.ts`、`server/main.ts`。`MarketError` 只带业务错误码，由 handler 映射 HTTP 状态。
