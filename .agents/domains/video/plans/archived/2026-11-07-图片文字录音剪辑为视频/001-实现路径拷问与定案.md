# 001-实现路径拷问与定案

> 迁移自旧 notes.json / story.md / spec.md；正文保留历史记录，旧工具、状态名与路径不再适用。
## 已取证

- toolchain: Node v24.21.0 + pnpm 11.22.0; 系统无 ffmpeg/ffprobe, 无 winget/scoop/choco; npm 可装包。
- 既有结论: 视频编辑走代码/API 而非 GUI (wiki《代码驱动的多媒体生成》)。
- Remotion 核验: v4.0.541; 自带轻量 ffmpeg/ffprobe (无 afade/sidechaincompress); Chromium 由 `npx remotion browser ensure` 安装。
- 素材: 16 张竖幅照片 (1279×1706, 最后一张 1024×1366), 1 个 m4a 录音 (24.78s); 文案 8 句英文。
- 录音逐句时间轴: `silencedetect noise=-33dB d=0.28` 切出 7 个句间停顿 + 1 个句内停顿 (第 4 句), 9 个语音段合并为 8 句。
- BGM: 本地公共领域曲库 `C:\Users\kxh\Music\musopen-flac` (Musopen, CC PD Mark 1.0), 选 Josef Suk《Meditation》。

## 第 1 轮

#### Q1 - 交付形态

- 问题: 只要一个成品 mp4, 还是要可复用的脚本/工具?
- 前置问题: 无
- 下游边界: 决定是否建参数化 CLI、素材目录约定与测试方式
- 推荐答案及理由: 可复用工具; 若只做一次可退化为单脚本
- 处理结论: 用户选「一次性成品」——不建通用 CLI, 验收物为一个 mp4; 代码按一次性 Remotion 工程交付。

#### Q2 - 画面规格与平台

- 问题: 横屏 16:9 / 竖屏 9:16? 分辨率?
- 前置问题: 无
- 下游边界: 画布尺寸、图片裁切方式、字幕安全区
- 推荐答案及理由: 竖屏 9:16 · 1080×1920
- 处理结论: 用户选「竖屏 9:16 · 1080×1920」; 帧率 30fps (假设, 已采用)。

#### Q3 - 文字呈现

- 问题: 整段静态字幕 / 按句自动断句并随录音出现 / 关键词高亮动画?
- 前置问题: Q2
- 下游边界: 是否需要断句对齐, ASS 模板或 Remotion
- 推荐答案及理由: 按句字幕, 用录音静音段 + 文字分句对齐
- 处理结论: 用户选「按句字幕, 随录音出现」; 对齐方式见 Q9。

#### Q4 - 图片节奏

- 问题: 均分停留 / 跟随讲解切换 / 自由编排?
- 前置问题: Q3
- 下游边界: 时间轴编排复杂度
- 推荐答案及理由: 均分 + Ken Burns
- 处理结论: 用户要求「根据图片数量、文案自由排布, 要有电影版剪辑效果」; 后续追加「所有图片都要使用, 可以一个镜头多图或拼接」——最终 16 图分 9 镜, 3 个镜头用 2×2 网格/左右分屏承载多图。

#### Q5 - 音频处理

- 问题: 仅原录音 / 加 BGM 闪避 / 加降噪与标准化?
- 前置问题: 无
- 下游边界: 是否引入 BGM 与 ducking
- 推荐答案及理由: 原录音 + 响度标准化
- 处理结论: 用户先选「仅原录音 + 标准化」; **2026-11-07 改口追加 BGM**——改为「原录音 + 公共领域 BGM 侧链闪避 + 响度标准化」。

#### Q6 - 环境授权

- 问题: 是否允许 npm/Chromium 安装?
- 前置问题: Q1
- 下游边界: 路径可行性
- 推荐答案及理由: 允许; 无 winget, 系统级安装不可行
- 处理结论: 用户选「改用 Remotion (含 Chromium)」——路径 B 定案。
