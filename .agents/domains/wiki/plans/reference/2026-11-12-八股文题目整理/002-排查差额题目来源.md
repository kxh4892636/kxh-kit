# 002-排查差额题目来源

## 结论

**没有缺题。849 是站点全部唯一题目；1736 是「题目 × 公司」的行数，不是唯一题数。** 已抓到的 11 个 tag 快照即完整集合，001 与 003 无需返工。

## 证据（2026-11-12 实测）

| 探测 | 结果 |
| --- | --- |
| `GET /topk/api/question.json/?page=N`（无 category） | `count 1736`，13 页取满 1736 行，其中 **唯一题面 849** |
| `GET /topk/api/question.json/?sub_category=8&page=N` | 算法 `count 485`，去重后 **315** —— 与 `allcate_question/8/` 完全一致 |
| 11 个 tag 逐页取满 | 行数合计 1732，各 tag 去重后 877 行，全球唯一 849 |
| 19 个公司逐页取满 | 行数合计 1706（另有 30 行未归属公司） |
| 同一 tag 内重复 | 单题最多重复 12 次（Java），重复只来自「不同公司问过同一题」 |

因此 1736 ≈ 「tag 行数 1732」≈「公司行数 1706 + 未归属 30」，三种切法都指向**同一批 849 道唯一题**。差额 887 不是被隐藏的题，而是同一题在多公司重复计数。

## 其它路线（已排除）

- **分页参数**：`allcate_question/8/?page=2|?limit=10|?offset=300` 全部返回同一份 315 条全量，参数被忽略。
- **全 id 扫描**：`allcate_question/1..200/` 只有 1–32 有数据；`121` 补扫返回 `count 0`（此前超时是网络抖动）。
- **静态资源**：`/topk/static/` 与 `/topk/static/data/` 均 404；`robots.txt`、`sitemap.xml` 落到 SPA 首页，非真实文件。
- **其它页面**：`/topk/Q&A/` 是纯静态问答页（仅说明数据来源），`/interview/` 是独立 Hugo 博客，均无题目接口。
- **旧快照**：本机网络访问 `web.archive.org` 的 80/443 均超时，CDX 查不了；结论不依赖它，不再尝试。
- **移动端 / 平行接口**：`m.osjobs.net`、`topk.osjobs.net`、`api.osjobs.net` 均无法解析。

## 顺带发现（未采用）

- 正确写法是 `api/question.json/`（**末尾带斜杠**），不带斜杠一律 `count: 0`——早期探测全被判为「无数据」就是这个原因。
- 该接口比 `allcate_question` 多给 `difficulty`、`resource1..3`（外部答案资料链接）。若以后要做「题目 + 参考链接」，从 `?sub_category={id}&page=N` 取，按题面去重即可。
- 本次交付只用 `allcate_question`（已去重、单页直出），不需要新数据源。
