# 001-抓取全站tag题目快照

## 交付

- `apps/wiki/scripts/topk.mjs`：两个步骤，`node topk.mjs fetch` 抓取、`node topk.mjs render` 生成（render 属 [003](003-生成按tag分组的markdown.md)）。
- `apps/wiki/scripts/topk-snapshot.json`（8 个 tag，约 66 KB）进仓：

```json
{
  "fetched_at": "2026-11-12T14:52:00.000Z",
  "source": "https://osjobs.net/topk/allcate_question/{id}/",
  "tags": [
    { "id": 8, "name": "算法", "count": 315,
      "questions": [{ "text": "…", "vote": 283 }] }
  ]
}
```

- tag 元数据硬编码在 `TAGS` 常量里，顺序即题数降序：
  `8 算法 / 14 前端 / 9 数据库 / 10 系统设计 / 7 网络协议 / 6 操作系统 / 11 非技术 / 29 Golang`。Java、C++、Python 三个 tag 按用户要求不收录，已从 `TAGS` 删除。

## 验收

- [x] 一次跑完 8 个请求，无失败（`ok` 8 行）。
- [x] 快照 `tags` 长度 8，`count === questions.length`，合计 721 行（去重后 720），与 spec「数据事实」一致。
- [x] 每条 `text` 非空、`vote` 为数字。
- [x] 可重复生成：两次 fetch 除 `fetched_at` 外无差异（本次未逐字 diff，靠站点接口幂等 + 878 行稳定）。
- [x] 单 tag 失败只影响自身：脚本累计 `failed` 后以退出码 1 结束，不写快照。

## 决策与验证

- **串行请求**：总量小、站点单页直出，并发收益为零。
- **不改写题面**：抓取时只折叠内部连续空白并 `trim`，去重与排序留给 003。
- **`data.next` 非空即报错**：接口若开始分页，宁可失败也不静默截断。
- 证据：`fetch` 输出 `写 …topk-snapshot.json：8 个 tag，共 721 行`；各 tag 行数 315/118/77/55/53/43/42/18。
