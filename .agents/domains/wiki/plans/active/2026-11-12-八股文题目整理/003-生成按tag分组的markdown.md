# 003-生成按tag分组的markdown

## 交付

- `node apps/wiki/scripts/topk.mjs render` 读 [001](001-抓取全站tag题目快照.md) 的快照，写 8 个文件到 `apps/wiki/docs/020-八股文梳理/`，`sidebar_position` 即题数降序排名（Java / C++ / Python 按要求不收录）：

| 文件 | tag id | 题数 | position |
| --- | --- | --- | --- |
| `算法.md` | 8 | 315 | 1 |
| `前端.md` | 14 | 118 | 2 |
| `数据库.md` | 9 | 77 | 3 |
| `系统设计.md` | 10 | 55 | 4 |
| `网络协议.md` | 7 | 52 | 5 |
| `操作系统.md` | 6 | 43 | 6 |
| `非技术.md` | 11 | 42 | 7 |
| `Golang.md` | 29 | 18 | 8 |

- 文件形态：

```md
---
title: 算法
description: 面经高频算法题 315 道，按出现次数降序。
sidebar_position: 1
---

# 算法

面经统计出现次数降序，共 315 道。
数据来源 [osjobs Top K](https://osjobs.net/topk/)，抓取于 2026-11-12。

- 283 - 使用递归及非递归两种方式实现快速排序
- 216 - 141. 环形链表
```

- 分组配置在 `apps/wiki/scripts/topk-groups.mjs`：`GROUPS[tag]` 是一张有序的 `{ name, keywords }` 表，题干转小写后**首个命中关键词的分组胜出**，都不命中落到「其他」。改分组只要改这张表，渲染逻辑不动。
- 每个文件形态：`## 分组名（题数）` + 该组题目列表；组顺序 = 配置顺序（从具体到泛化），「其他」固定最后，空分组不出现。
- 生成规则：
  - **去重**：题面忽略空白差异后作为键（`从系统层面上，UDP如何保证尽量可靠？` 与 `UDP 如何…` 视为同一题）；同键保留较大 `vote` 与首次出现的位置，保留的题面用折叠空白后的版本。
  - **分组**：先分组，再在组内按 `vote` 降序；同票按源顺序稳定。
  - **格式**：无序列表，`- 次数 - 题目`；次数纯数字，题面原样输出。
  - **计数**：正文「共 N 道」取去重后行数；`description` 同数。

## 验收

- [x] 8 个文件齐备，文件名与上表一致；`Java.md` / `C++.md` / `Python.md` 已删除，`TAGS` 里也移除了对应 tag，`render` 不会再写回。
- [x] 行数与表一致，合计 720 行；每道题在文件内只出现一次（可跨组校验，0 重复）。
- [x] 每行匹配 `^- \d+ - .+`；**每个分组内**次数单调不增（逐文件逐组校验，0 问题）。
- [x] 每个 `## 分组名（N）` 的 N 等于该组实际行数；八组合计 720 道。
- [x] 未分类只有 3 道（算法 2、数据库 1），都落在「其他」：`简述常见的负载均衡算法`（题目在算法 tag 下但属系统设计）、`组件之间通信方式有哪些？`（属前端）、`4. 寻找两个正序数组的中位数`（数据库 tag 下的 LeetCode 题）。
- [x] 文件内无重复题面（忽略空白后比对）。
- [x] `render` 幂等：同一快照连跑两次，8 个文件内容一致。

## 决策与验证

- **关键词分组而非人工标注**：720 道题人工归类写不完也难维护；关键词表 + 组顺序可读、可 git diff、结果可复现。代价是边界题只能靠调关键词，不能保证 100% 符合直觉（如「TCP 与 UDP 的区别」落在 TCP 组，因为 TCP 组在前）。
- **未分类保留「其他」而不丢弃**：3 道题留在「其他」，避免为了好看强行塞进不合适的组。
- **跨 tag 重复保留**：tag 是筛选维度，同一题在算法与前端各出现一次是正常结果；只在文件内去重（这也是「720 行 > 唯一题」的原因）。
- **无序列表而非有序列表**：有序列表渲染会多出一列序号，与行内次数混在一起；`- 次数 - 题目` 只多一个项目符号，格式最接近要求且对格式化工具稳定。
- **中文文件名 + `sidebar_position`**：与既有栏目命名习惯一致，中文排序不可控的问题交给 position。
- 证据：`render` 输出 `共 8 个文件，720 行，未分类 3 道，文件内去重 1 条`；分组数 算法 14、前端 10、数据库 8、系统设计 5、网络协议 5、操作系统 5、非技术 5、Golang 3。逐文件 min/max 次数 算法 1–283、前端 8–338、数据库 8–634、系统设计 2–156、网络协议 2–502、操作系统 10–426、非技术 3–114、Golang 4–26。
- 校验脚本（本次临时跑，未进仓）：逐文件逐组核对行格式、组内降序、`（N）` 与实际行数一致、跨组无重复、总行数等于快照唯一题数 —— 0 问题。
