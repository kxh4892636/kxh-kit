# 006-样例导图与真机验收

> 2026-11-14 更新：本条是「独立页面」时期的交付记录。2026-11-13 改成文档内 `<Mindmap>` 渲染块后，`apps/wiki/mindmaps/` 目录、路由注册与 `allContentLoaded` 校验都已删除，构建门禁改为 remark 直接抛错。示例导图现在写在 `apps/wiki/docs/000-中转/思维导图示例.md` 里。当前形态见 [spec.md](spec.md)「决策」与 [001-在wiki文档里写一个导图块并验收](../../../workflows/001-在wiki文档里写一个导图块并验收/001-在wiki文档里写一个导图块并验收.md)。

## 交付

- 一篇真实导图 `apps/wiki/mindmaps/020-typescript知识地图.md`：从 `apps/wiki/docs/090-归档/010-计算机/020-编程语言/031-TypeScript/` 抽 3 到 4 层标题，节点写成问题式标题（贴合站点 H2 多为问句的习惯），每节点一到三行概述，至少 6 条引用：3 条 doc 引用指向真实文档、3 条节点引用指向同图节点，其中一条用显式 id、其余走自动 slug。
- 交互走查记录：`pnpm --filter @kxh4892636/wiki start` 与构建产物各跑一次，逐条核对下面的验收项，记录证据（截图路径或日志片段）。
- 领域词表收口：把「思维导图文档 / 节点 / 概述 / 引用 / 导图路由」写进 [wiki CONTEXT](../../../CONTEXT.md) 的 Language 段（只写稳定结论，不写实现细节）。
- 性能实测：记录本图节点数与首屏可交互时间；明显卡顿就在 note 里给出下一步方向，不在本 note 里改架构。

## 验收

- [ ] `pnpm --filter @kxh4892636/wiki build` 成功，build/mindmaps 下有两篇导图页面。
- [ ] 浏览器打开 `/mindmaps/<id>`：层级正确（含 3 层以上），点击节点出浮窗，概述与引用与源文件一致。
- [ ] doc 引用新标签页跳到正确文档（不是 404，也不是导图页）；节点引用关浮窗并定位到目标节点。
- [ ] 缩放、平移、fit、Esc 关闭浮窗、深链 #节点 五项逐条通过。
- [ ] 故意写坏一条引用后 build 失败、报错定位到 mindmaps 下的文件与行号；改回后通过。
- [ ] 仓库范围 `vp check` 与 `vp test` 通过；wiki CONTEXT 词表已更新，nano_flow_check 无告警。
