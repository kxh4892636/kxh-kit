# 003-校验与构建门禁

## 交付

- 引用解析 `src/docs-index.ts`：在 `allContentLoaded({ allContent })` 里读 `allContent["docusaurus-plugin-content-docs"]`，遍历各版本的 docs，建 `frontMatter.id → permalink` 映射（id 必须是字符串，缺 id 的文档不入表）。映射为空时直接报错（说明 docs 插件内容形状变了），不静默放行。
- 校验 `src/validate.ts`（纯函数，输入 MindmapDoc 列表 + 映射）：
  - 导图 front matter：id 非空、不含斜杠与空白、跨导图唯一、mindmap 必须为 true；**id 不能与任一 docs 文档的 `id` 相同**（两者共用 `/<id>` 短链命名空间，撞了就是重复路由）。
  - 路径：由目录与文件名算出的路由跨导图唯一，且不与 docs 路由重复（`/mindmaps/...` 前缀天然隔离，只查导图之间）。
  - 结构：恰好一个 H1；层级不跳级；标题文本非空；节点 id 同图唯一（含显式 id 与自动 slug 混用的情况）。
  - 引用：doc: 目标必须在映射里；# 目标必须在本图节点 id 集合里；自引用（# 指向自己）报错。
  - 每条错误带 sourcePath 与行号，格式统一：`mindmaps/xxx.md:12 [duplicate-node-id] 节点 id "tree" 重复`。
- 门禁接线：`src/index.ts` 在 `allContentLoaded` 里跑解析 + 校验，再 `addRoute`（props 里带已解析的 docUrl）；`process.env.NODE_ENV === "production"` 时抛 Error（一次列出全部错误），否则 `console.warn` 后继续。
- 负例测试 `src/validate.test.ts`：引用不存在的 uuid、# 指向不存在节点、同图重复 id、跳级、两个 H1、id 缺失、id 跨导图重复，各一条断言；正例断言不抛错。
- 站点侧验证：临时把示例导图的引用改成不存在的 uuid，`pnpm --filter @kxh4892636/wiki build` 必须失败且日志里有文件名与行号；改回后 build 通过。

## 验收

- [ ] 负例下 build 失败，报错含 `mindmaps/<文件>.md:<行号>` 与错误码。
- [ ] 正例 build 通过，导图路由 props 里的引用已带 docUrl（从 build 产物或 .docusaurus 目录里核对）。
- [ ] dev（docusaurus start）下同样的负例只打印告警，页面仍能打开。
- [ ] 映射为空（模拟 docs 插件内容缺失）时报错而不是放行。

## 风险

- allContentLoaded 里 addRoute 是允许的（actions 与 contentLoaded 同一套），但必须在 codegen 之前完成；若实测路由丢失，退路是 contentLoaded 注册路由、allContentLoaded 只校验，docUrl 用 createData 补。先按前者实现并验证。
- 370 篇文档没有 id，引用它们会报「doc 不存在」；报错文案要指向「目标文档缺 id front matter」，否则会被误读成插件 bug。
## 实施记录（2026-11-13）

- 校验放在 `allContentLoaded`：从 `allContent["docusaurus-plugin-content-docs"]` 取文档 id → permalink，索引到 1217 个 id。
- `future.v4` 下 docs 插件内容是 `{ default: { loadedVersions } }`（版本维度包了一层 `default`），第一版直接读 `loadedVersions` 得到 0 个 id，已按两种形状兼容。
- 负例实测：把一条引用改成不存在的 uuid，`build` 失败并给出 `mindmaps/…/知识地图.md [unknown-ref] …`；改回后通过。
- 额外规则：导图 id 不得与 docs id 相同、导图之间 id/路由唯一（否则 `/<id>` 短链撞车）。
