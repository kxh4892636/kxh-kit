# 005-导图渲染与交互

视觉与交互按 [004](004-导图UIUX设计.md) 的结论做（设计原型已删除）。

## 交付

- 布局 `src/layout.ts`（纯函数，可单测）：输入节点树，输出每个节点的 x / y / width / height 与绘制顺序。横向布局：根在最左，子节点在右一列；兄弟节点纵向堆叠，子树高度按后序累加；节点框宽度按标题长度截断（上限约 260px），高度按行数；间距常量集中声明。同一棵树两次布局结果必须相同。
- 渲染 `src/client/`：
  - `mindmap-view.tsx`：svg 里画父子连线（实线）与引用连线（虚线，只连同图内可见节点）；节点是 rect + text，标题过长截断，title 元素给完整文本。
  - 缩放平移：滚轮缩放 0.3–2 倍（以指针为中心）、拖拽平移、fit 按钮回到全图、双击空白复位；状态用 useState / useReducer，不引入全局 store。
  - 浮窗 `node-popover.tsx`：点击节点后出现在节点旁，显示标题、概述（逐行纯文本，保留缩进）、引用列表；Esc 或点空白关闭；props ≤ 8 个。
  - 引用点击：kind 为 doc 时 window.open(url, "_blank", "noopener")，浮窗保留；kind 为 node 时关浮窗、把目标节点滚到视图中心并高亮约 1.5 秒。
  - 深链：URL 的 #节点id 命中节点时，首屏直接定位并打开浮窗（挂载时读 location.hash）；未知 id 退化为 fit。
  - 样式走 CSS 文件（客户端组件内 import），颜色用 Docusaurus 现有 CSS 变量，跟随明暗模式。
- 可访问性最低线：节点可 Tab 聚焦、Enter 打开浮窗；引用是真链接或真按钮；aria-label 写节点标题。
- 测试：`src/layout.test.ts` 断言层级 y 序、子树不重叠、根坐标稳定；`src/client/node-popover.test.ts`（文件首行 `// @vitest-environment happy-dom`）断言概述行与引用渲染、两种引用点击的副作用。

## 验收

- [ ] 示例导图页面：节点、父子连线、引用虚线都在；缩放平移顺滑，fit 回到全图。
- [ ] 点击节点出浮窗，内容与 markdown 源一致；Esc 关闭。
- [ ] 点 doc 引用开新标签页并落到目标文档；点 node 引用关浮窗并定位到目标节点。
- [ ] 深链 `/mindmaps/<id>#<节点id>` 首屏定位并打开浮窗；未知 hash 不报错。
- [ ] 单测全绿，组件文件 ≤ 377 行、函数 ≤ 89 行。

## 风险

- 大图（005 实测）：全量渲染 SVG，节点多时首屏慢；超过约 1000 节点先做折叠子树，再谈虚拟化。
- 浮窗定位在缩放平移后要跟随变换矩阵，容易算错；用节点屏幕坐标而不是图坐标算位置。
## 实施记录（2026-11-13）

- `src/client/layout.ts`：纯函数布局，左右双向（`ceil(n/2)` 先右后左），兄弟按叶子顺序堆叠再与根垂直居中；连线是三次贝塞尔，线宽按层递减；返回 `{ nodes, edges, minX, minY, maxX, maxY }`，单测锁住左右分侧、同列不重叠、线宽递减。
- `src/client.tsx`：React 页面组件，顶栏（目录按钮 / 词标 / 路径 / 缩放组 / 适应窗口）+ 左侧目录树 + 画布。滚轮以指针为中心缩放（0.35–2）、指针拖拽平移、`适应窗口` 整图缩放；点击节点开浮窗，`Esc`/点空白关闭。
- 引用行为：`doc:` 用 `window.open(url, "_blank")` 开新标签页；`#` 关浮窗、选中并居中目标节点、同步 `#hash`。
- 深链：首屏读 `location.hash`，命中节点则选中 + 居中 + 打开浮窗；未命中退回默认视图。
- 悬浮：节点 hover 用 `--ifm-color-emphasis-200`（深色模式再深一档），第一版用 `emphasis-100` 在浅色下接近纯白，节点像被涂白，已改。
- 样式：`src/client/mindmap.css` 以字符串形式（`styles.ts`）注入 `<style>`——tsdown 打包时 CSS import 会解析失败。配色和字体全部走 Infima 变量（`--ifm-background-surface-color`、`--ifm-font-color-base`、`--ifm-link-color`、`--ifm-color-emphasis-*`），深色模式由站点 `[data-theme="dark"]` 自动带过来，组件里没有自己的配色表。
- 页面外壳：`@theme/Layout` 提供导航栏与页脚；侧栏直接用 `@theme/DocSidebar`（把目录树映射成 `category` / `link` 两种 item），菜单结构、折叠、箭头、选中态、折叠按钮全部来自主题，和 docs 页一致。`@theme/Layout` 的类型在这个 monorepo 里解析不到，组件里用一次 `as unknown as React.FC<…>` 收口。

## 2026-11-13 三次调整：全屏、字体、光标

- 工具栏新增「全屏 / 退出全屏」：对整个导图块调用 Fullscreen API，工具栏留在块内，所以全屏后仍可见；`fullscreenchange` 时按新尺寸重新自适应。样式用 `:fullscreen`，块内画布改为 `flex: 1` 铺满。
- 工具栏字号统一到 `--ifm-font-size-base` 与 `--ifm-font-color-secondary`，跟 docs 正文一致。
- 画布光标从 `grab` 改为 `default`：Windows 的 `grab` 是白色小手，白底画布上会「消失」；节点仍保留 `pointer`。
## 2026-11-13 四次调整：浮窗、TOC、样式收敛

- 浮窗：放弃 Fullscreen API，改成 portal 到 `document.body` 的遮罩层——半透明 scrim + 白色不透明面板 + 四周 2rem gap；面板内工具栏常驻，点遮罩或按 Esc 关闭，打开时锁 body 滚动。
- 默认态不再显示工具栏，只在画布右上角留一个「全屏」按钮。
- 字号收敛到站点：节点标题改 `--ifm-font-family-base` / `--ifm-font-size-base`、不加粗；工具栏 meta 与读数只保留颜色，不再自定义字号；按钮全部用 Infima `button button--secondary button--sm`。
- 目录污染：docs 的右侧 TOC 是用原始 markdown 单独解析的，remark 阶段删不掉；改成 CSS `:root:has(.mindmap-block) .table-of-contents { display: none }`，含导图块的页面不显示右侧目录。
- link 插件已整体回退（`git checkout`），导图插件不再依赖它；`doc:<id>` 直接走 docs 自己的 `/<id>` 短链。
- 2026-11-13 再收敛：导图内所有文字（节点标题、`#id`、引用计数）与工具栏/按钮全部用 `--ifm-font-family-base` + `--ifm-font-size-base` + `--ifm-font-weight-normal`；根节点不再放大加粗，内联「全屏」按钮与浮窗工具栏字号一致（实测均 16px / 400）。

## 2026-11-13 五次调整：编号即 id，引用走原生 markdown

- 节点编号写在标题里：`## 1.2 接口`，编号就是节点 id（`1` / `1.1` / `1.2.1`），不再自动编号、不再支持 `{/* #id */}`；缺编号、编号重复都直接让 build 失败。
- 引用全部是 markdown 原生链接：
  - 文档引用：`[基础数据类型](相对路径.md) doc:<文档id>`——链接给路径（Docusaurus 会解析成站内 URL），后面的 `doc:` 给 id；
  - 节点引用：`[接口](#1.2)`——锚点用编号。
- 坑：MDX 会把 `doc:<uuid>` 里的 `:xxx` 解析成 **textDirective**（`doc` 变文本、`:uuid` 变节点），所以解析时要把 `textDirective` 还原成 `:name` 再匹配 `doc:<id>`。
- 已知问题：默认视图偶尔会把最左侧分支切掉一截，`适应宽度` 按钮能立刻恢复；下次修。

- 已知取舍：滚轮仍然被画布接管（未加修饰键判断）；拖动时整棵树重渲染（节点数大时才需要优化）；客户端交互没有自动化测试。
