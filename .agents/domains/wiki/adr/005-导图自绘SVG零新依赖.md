# 005-导图自绘SVG零新依赖

## 背景

仓库里没有任何图布局或导图依赖（d3、markmap、mermaid、cytoscape、xyflow、dagre、elkjs 全无）。导图的语义也不是现成库的模型：每个节点除父子边外还能指向别的文档（虚线引用边）、节点正文是 markdown 段落。

## 决策

自绘：`src/client/layout.ts` 是纯函数，输入树输出每个节点的 x/y/w/h 与边集合；组件用 React 画 `<svg>`，父子边是三次贝塞尔曲线、线宽按层级递减，引用边是虚线；滚轮缩放（0.35–2 倍，以指针为中心）、拖拽平移、适应窗口、全屏浮窗都本地实现。

## 后果

- 发布包 `dependencies` 为空——新增依赖要写显式版本号（[common 001](../../common/adr/001-发布包生产依赖不使用catalog协议.md)），零依赖省掉这条约定与一次升级跟进。
- 布局可单测：左右分侧（`ceil(n/2)` 先右后左）、同列不重叠、线宽递减、视图数学（指针为缩放中心、上下限夹紧）都有用例。
- 自己承担视觉细节：节点宽 240、根 264、列间距 92、行距 22、标题最多 3 行等常量都在代码里。
- 节点与连线一次性全量渲染，没有虚拟化；上千节点要另做折叠或虚拟化（视图侧已收口，见 [006-视图状态用ref直接改DOM](006-视图状态用ref直接改DOM.md)）。
- 无新依赖也意味着没有现成的无障碍与键盘导航，Tab/Enter、aria 都要自己补。

## 备选与弃用理由

- **markmap**：面向整页、单根、只读展示，没有「节点正文 + 跨文档引用边」的模型。
- **mermaid**：语法即图，标题树要再翻译一次，样式与站点主题也不通。
- **d3-hierarchy + d3-zoom**：只解决布局与手势，引用边与浮窗仍要自己写，还多两个依赖与 SSR 注意点。
- **xyflow / cytoscape**：交互模型（拖节点改结构）与「只读」相反。

## 证据

- 决策来源：spec「决策」段与 [004-导图UIUX设计](../plans/active/2026-11-13-思维导图插件/004-导图UIUX设计.md) 的「零依赖自绘」；调研结论（全仓无导图依赖）见 spec「现状」。
