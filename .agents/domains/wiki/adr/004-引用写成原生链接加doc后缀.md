# 004-引用写成原生链接加doc后缀

## 背景

用户要求引用「用 markdown 原生引用格式」：文档引用给相对路径链接，后面再给 `doc:<文档id>`，解析格式由实现自己定；节点引用不要特殊 id，直接用标题里的编号作锚点。初版的写法是 `[说明](doc:<uuid>)` 这种把文档 id 塞进链接目标的形式。

## 决策

- 文档引用：`> - [基础数据类型](../../…/010-基础数据类型.md) doc:07b40046-e58e-4b78-a552-928d99eb18fb`。链接文本是给人看的说明，括号里是相对路径，链接后面的普通文本 `doc:<文档id>` 是唯一跳转依据；渲染时 `url` 被换成 `/<文档id>`，点击新标签页打开。
- 节点引用：`> - [接口](#1.2)`，或 `#1.2接口`（锚点开头的编号被提取，后面的字随便写）。点击关浮窗、选中并把图移到该节点。
- 引用写在 `>` 引用块或普通段落里都算；同一段落里不带链接的文字仍是概述。

## 为什么不用 `[说明](doc:<id>)`

两个具体故障：

1. MDX 会把 `doc:<uuid>` 里的 `:uuid` 解析成 textDirective 节点（`doc` 变普通文本、`:` 后面的变指令），拼回去才能匹配，见 [001-MDX把doc后缀解析成textDirective](../questions/001-MDX把doc后缀解析成textDirective.md)。
2. 链接目标放的是 id 而不是路径，作者在编辑器里读到的就不再是一篇笔记的地址，跳转依据也混进了 URL 位置。

用户的原话是「markdown 原生引用格式给出相对路径连接，然后后面再给出 `doc:<id>`」——先把链接写成真链接，id 作为附加标注跟在后头。

## 后果

- 相对路径不参与跳转，也没有任何门禁检查它：写错目录、写 `../../` 越过 `docs/` 都照样 build 通过（示例里两种写法并存）。它只服务作者与编辑器。
- `doc:` 后缀写错（不存在或拼错 id）同样不在 build 期报错，运行时落到 404，见 [003-doc引用写错为什么build不报错](../questions/003-doc引用写错为什么build不报错.md)。
- 同一段落多个链接时，每个链接只取自己后面直到下一个链接之间的 `doc:`（曾共用段落末尾导致两个链接拿到同一 id）。
- 节点引用写错编号是硬失败：目标编号不在本图节点集合里直接抛错。

## 备选与弃用理由

- **`doc:` 作链接目标**（已实现、已弃）：撞上 textDirective 与坏链门禁。
- **自定义指令 `:doc[<id>]`**：需要 remark-directive，且作者要记新语法；用户要的是原生 markdown。
- **自动从相对路径反查 doc id**：路径规则与 permalink 映射都在 docs 插件里，还得处理 370 篇无 `id` 的文档，等于把跳转依赖压在不可靠的一侧。
