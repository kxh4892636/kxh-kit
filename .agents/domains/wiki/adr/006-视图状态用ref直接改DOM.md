# 006-视图状态用ref直接改DOM

## 背景

拖动与滚轮每帧 `setState`，整棵 SVG（每个节点 rect/text、每条路径）跟着重渲染；用户实测「节点数上百会发涩」，并要求做性能优化。

## 决策

- 视图（平移量、缩放比）放 `viewRef`，不进 state。
- `applyView()` 一次写三处 DOM：`<g transform>`、右上角缩放读数、浮窗的 `left/top`。
- 视图数学抽成纯函数 `panView` / `zoomView`（指针为缩放中心、0.35–2 倍夹紧），单独单测。
- React 状态只剩选中节点、浮窗开关、全屏开关——只有它们变化才重渲染。

## 后果

- 拖动与缩放期间一次 React 渲染都不发生；节点数增加不再线性拖慢手势。
- 视图不再是渲染的输入：任何需要按视图定位的东西（浮窗）都要自己算初值并在 `applyView()` 里续写，两处逻辑必须同步。
- 破坏「数据驱动」的直觉，后来者容易顺手改回 state；改回去不会报错，只会变卡。
- 节点与连线仍是一次性全量渲染，千级节点仍需折叠或虚拟化。

## 备选与弃用理由

- **每帧 setState**（原实现）：代码最直白，节点上百就发涩。
- **CSS transform 过渡动画**：动的是整块画布，缩放读数与浮窗仍要另写，还得处理 `prefers-reduced-motion`。
- **引入状态库 / 虚拟化**：为几十到几百节点上重武器，且跨包引入 store 的成本高于收益。
