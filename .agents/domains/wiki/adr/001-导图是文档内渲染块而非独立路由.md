# 001-导图是文档内渲染块而非独立路由

## 背景

第一版把导图当成独立页面：扫描 `repos/wiki/mindmaps/` 目录，按路径注册 `/mindmaps/<路径>/` 路由，套 `@theme/Layout`、用 `@theme/DocSidebar` 做左侧目录，link 插件加 `mindmapsPath` 让导图 id 也进 `/<id>` 短链。真机验收通过后，用户的判断是「和 docs 页面 UI 完全不一样，一点都不像」，连续两轮收敛仍未达标（[004-导图UIUX设计](../plans/active/2026-11-13-思维导图插件/004-导图UIUX设计.md)）。

根因不是样式细节：docs 页面的外壳（导航栏、面包屑、目录、页脚、编辑链接、搜索）由主题按文档内容生成，自己拼一份永远差一截。

## 决策

导图是文档 markdown 里的一个块：正文写 `<Mindmap>…</Mindmap>`，remark 阶段把标签内的标题树换成 `MindmapBlock` 组件的 `tree` 属性。不注册路由、不加侧栏、不碰 `docs/` 之外的内容。页面本身仍是普通文档，导航、搜索、面包屑、目录全部由 docs 原生提供。

## 后果

- 插件只剩两个入口 `./remark`（编译期）与 `./client`（渲染），没有 loadContent / contentLoaded / 路由注册。
- 导图与正文可以共存于同一篇文档；标签外的标题照常是正文标题、照常进文档目录。
- 没有了自有路由，文档引用只能跳到目标文档本身的 URL，因此 `doc:<id>` 编译成 `/<id>` 短链（见 [004](004-引用写成原生链接加doc后缀.md)）。
- 代价：不能把导图做成独立导航入口；同步删掉 link 插件的 `mindmapsPath` 扩展、侧栏、`design/` 原型与约 500 行死代码（[005-导图渲染与交互](../plans/active/2026-11-13-思维导图插件/005-导图渲染与交互.md) 的「二次改版」「重构 + CR 修复」）。

## 备选与弃用理由

- **独立路由 + 手拼页面壳**（已实现、已弃）：已被用户判定 UI 不像 docs，且每升一次 Docusaurus 都要跟一遍主题接口。
- **swizzle docs 主题，把某些文档渲染成整页导图**：能把外壳做对，但复制主题代码、升级易碎，而且要为「哪些文档渲染成导图」再发明一套标记。
- **导图目录 + 自定义 docs 实例**：仍然是两套文档系统，侧栏、搜索要各配一遍。

## 证据

- 用户改定：`session-d3d041d7-33a0-4596-8966-d0cc91cceee0` seq 3412（turn 10）——「mindmap 被一个 xml 标签渲染，你只对这个 xml 标签下的 markdown 进行渲染」。
- 落地：`repos/docusaurus-plugin-mindmap/src/remark-mindmap.ts` 只做 mdast 改写；`repos/wiki/src/theme/MDXComponents.tsx` 注册 `MindmapBlock`；`repos/wiki/docusaurus.config.ts` 只挂 remark 插件。
- 验收：`/docs/中转/思维导图示例` 整页是普通文档，正文里 6 节点 4 引用（006 二次验收）。
