# 一个组一个现场，组完成即回收

ADR-0012 / ADR-0014 把 worktree 绑在**某一代 worker** 上：按 `kind` 推导建不建、可显式覆盖、带代际命名、带七态状态机与「作废」，`abort` / 超时还想过自动删。实证代价：一条纯追加的 `steer` 在投递路径上重建了一次 `.worktrees/plan`（白花 13.8s install），同一个组在 `abort` / 合并且回收后换目录名，`abort` 还会把同 Plan 的别组一起摘掉。现在改成 **现场单位 = 组**：一个组一个目录、整组生命周期共用，组内 note 全部 completed 才由代码 `--ff-only` 合并并删除；机制能砍的都砍掉。

## Considered Options

- **保留按代际命名（ADR-0014 的「合并后同组再派重建」）**：每代一个干净目录，但同一组的上下文在磁盘上被切成多份，`state` 里「旧现场」与「当前 worker」糊成一件事，且回收失败会留下无主的目录。
- **现场跟着单条 note**：粒度最细，但组内多条 note 共享一棵树时，同一条 note 又会被两代 worker 同时改 —— 组本来就要求无依赖、串行推进，按组切正好对齐。
- **现场跟着组 + 完成即回收（选定）**：一条 note 有唯一归属，`pnpm install` 天然只花一次，abort / 超时与现场生命周期彻底解耦。
- **`abort` 保持「按 Plan」**：实现最省，但「现场属于组」之后会把别组正在跑的 worker 连带杀掉（实测发生一次）。

## Consequences

- 键 = 组键：单 note `note-<id>`、多 note `grp-<id-id>`，目录 `.worktrees/<键>`、分支 `wt/<键>`；`worktree: true | "<名字>" | false` 覆盖、按 `kind` 推导、代际命名、`ensureForSpawn`/`forHandle` 两入口、七态状态机与 `voided`、dispatch 时的磁盘恢复与作废键集合、`abort`/超时自动删现场、`worktree.merge_blocked` / `worktree.voided` 事件 **全部删除**。`worktree.merge_blocked` 作为一条 error 仍保留（改成「合并失败」语义）。
- 账本只留 `worktree.created` / `worktree.merged` / `worktree.removed`；`state` 从账本投影「组键 → 现场」，每行标出 worker 的组键与对应现场。
- `dispatch` 只认进程内的 live 句柄：句柄不在就新建（会话键带 `#N`），旧 jsonl 只当历史；落盘会话续跑的唯一入口是 `orchestrator_state op=resume`。
- `abort` 粒度跟着现场：`notes` 只摘该组、`plan` 摘该 Plan 全部组、都不给摘全部；摘句柄只有一条路径，不碰目录。
- 并发组多则多份 `node_modules`（每组 ≈183 MB 增量）；组内多 note 共享一棵树，所以组内不能并行改同一文件 —— 与「组内无依赖、串行推进」一致。
- 流式侧栏的卡片绑定跟随该组**当前 live worker**：换了一代就解旧绑新，暂时没有 live worker 只解绑，不再永久丢弃。

## 后续补充：恢复入口收敛为两个（同一个实现）

`session_shutdown` / 崩溃只写 `worker.suspended`，而在此之前恢复只有手动 `orchestrator_state op=resume` 一个入口 —— reload 后 worker 与「待消费」输入会一直悬着。现在 `session_start`（含 reload / 重启）对**本会话当前 Plan** 自动跑一次同一个恢复函数：没有当前 Plan 记录就什么都不做（不猜 Plan、不做全局对账，保住「启动不自动对账」的定案），已 live 的跳过，重复触发幂等。`dispatch` 仍然只认 live 句柄。
