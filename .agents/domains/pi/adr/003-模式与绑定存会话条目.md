# 模式与绑定存会话条目

## 背景

模式（当前会话是否运行）与 Plan 绑定都是「这个会话的事实」。全局 JSON 表需要跨进程同步、死条目清理与目录回退，还会在会话迁移时漂移。

## 决策

- `/nano-flow` 写 `nano-flow-mode { enabled }`；最后一条生效，新会话默认值来自 `pi-toolkit.json` 的 `nanoFlow.always`。
- `nano_flow_bind` 写 `nano-flow-binding { planPath, cwd, boundAt }`；最后一条生效，相对路径先按 `cwd` 解析、目录不在再回退当前工作区。
- 两者都不进模型上下文，只由侧栏、工具门控与恢复 seed 读取。

## 后果

- 好处：随会话文件走，恢复/切换天然一致；不需要清理不存在的会话。
- 代价：跨会话查看绑定要读对方的 JSONL；没有全局索引。
- 替代方案被否：`$PI_HOME` 全局表（需要清理、跨进程一致性与额外写盘）。
