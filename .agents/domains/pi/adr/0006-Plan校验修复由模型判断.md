# Plan 校验修复由模型判断

`notes.json` 的校验很严：摘要超长、`index` 重复/越界/引用不存在的 note 都会让整份文档不可读，而 `nano_flow_write` 需要先加载文档才能写回。此前的实现曾用脚本自动截断摘要、去重和裁剪索引；用户明确指出这些属于语义判断，不允许脚本化直接移除。本决策取代那次自动修复实现，保留「check 发现的问题要能解决」的目标，但解决者改为模型。

## Decision

- **不再自动改写内容**：删除 `repair.ts` 与 `openDocument`；读取/写入/校验不会截断摘要、不会删除或重排 `index`。
- **新增只读诊断**：`nano_flow_read` 的 `op: "inspect"` 在文档无法通过校验时返回原始 note（id/title/status/description/content）与 index，并提示用 repair 修复。
- **新增模型修复**：`nano_flow_write` 的 `op: "repair"` 接受显式 `notes`（按 id 给 title/description/content）与 `index`，应用到原始 JSON 后重新严格校验并原子写回；脚本只执行模型给出的值，不做任何猜测。
- **校验只报告**：`nano_flow_check` 不修复，只返回脚本发现的问题；模型根据问题与 inspect 结果决定修改。
- **收口保持路径级**：`tool_call` 只拦路径/命令字段，避免误伤源码内容与检索词。

## Considered Options

- **脚本自动截断摘要、自动规范化 index**（上一版实现）：会丢失语义、静默改变作者选择的索引；用户明确拒绝。
- **只允许人工改文件**：`notes.json` 被 `tool_call` 收口，正常路径下无法自助恢复；拒绝。
- **check 时自动修复**：与自动修复同样越权，且读路径仍无法加载坏文档；拒绝。
- **放宽校验、允许超长摘要**：会破坏 Plan 的上下文预算与恢复包体积；拒绝。
- **让 repair 接受任意 JSON 覆盖**：等于绕过校验与工具语义，风险过大；只开放 title/description/content/index 四个字段。

## Consequences

- 坏文档保持无效，直到模型显式调用 `repair`；期间 `notes`/`get` 等操作仍报错，`inspect` 可用于取证。
- `repair` 可一次修正多条 note 与 index，避免逐个操作时「修完摘要又被 index 卡住」。
- 摘要与索引的最终内容由模型给出，可在工具调用记录中审计。
- 自动修复测试删除；新增 inspect/repair 测试，覆盖率阈值仍为 80。
