# 上下文按重置时间过滤替代轮转

## 背景

pi 只有命令上下文能新建会话，事件处理器不能自动建会话；会话文件是只追加记录，也没有删除 API。但长任务仍需要在上下文压力过高时丢掉旧历史、保留 Plan 与上一轮结论。

## 决策

- `before_agent_start` 读 `ctx.getContextUsage()`，`tokens / contextWindow >= rotateAt` 时写 `nano-flow-reset { at, seed }`。
- `context` 事件按 `at` 过滤消息，把 seed 作为首条 user 消息插回；本轮用户输入保留为普通消息。
- seed 只包含当前 Plan 与上一轮 assistant 输出（`<rotation-last-output>`），不重复包裹本轮输入。
- 清空后必须等模型重新产出一轮（新的 assistant 时间戳晚于 reset）才允许下一次清空，避免同一条高占用反复触发。
- 会话 JSONL 不裁剪，`/tree`、导出与审计仍能看到完整历史。

## 后果

- 好处：不依赖新建会话与删除能力；Plan 与绑定不丢；行为可预测。
- 代价：模型可见上下文与磁盘历史不一致；排查时要记得过滤发生在 `context` 钩子，不是文件。
- 替代方案被否：自动新建会话（事件上下文没有 API）、物理删除旧会话（无删除 API）、纯靠 pi 自动压缩（丢 Plan 恢复 seed）。
