# pi-deepseek-web 以用户配置文件承载密钥并直连抓取

pi 缺少内置 web 搜索，需要经 DeepSeek 提供。DeepSeek 的 Anthropic 兼容 Messages API 接受 `web_search_20250305` / `web_search_20260209` 服务端搜索工具，但实测拒绝 `web_fetch_20250910`（`unknown variant ... expected web_search_20250305 or web_search_20260209`），即没有可用的抓取 server tool。用户要求以配置文件配置插件使用的 DeepSeek API。

## Decision

以 pi 插件 `@kxh4892636/pi-deepseek-web` 交付：

- **凭据与限额**放在独立用户配置文件 `~/.pi/agent/pi-deepseek-web.json`，项目 `.pi/pi-deepseek-web.json` 覆盖，`PI_DEEPSEEK_WEB_CONFIG` 指向的绝对路径最高优先；不写入 pi `settings.json`，不进入仓库（仓库只留 `.example`）。
- **`web_search`** 经 DeepSeek Anthropic 兼容端点（默认 `https://api.deepseek.com/anthropic/v1`、`deepseek-v4-flash`、`web_search_20250305`）；结果由 `web_search_tool_result` 结果块与 `text` block 的 citations 合成。
- **`web_fetch`** 不经 DeepSeek，直接 HTTP 抓取；`text/*`、`+json`/`+xml` 原样解码，`text/html` 经 `turndown` + `@joplin/turndown-plugin-gfm` 转 GFM markdown，并施加字节/字符/超时限额。

## Considered Options

- **只支持环境变量**：用户明确要求配置文件，且多机/持久化不便。
- **写进 pi `settings.json` 自定义键**：pi 未提供扩展读取自定义配置的接缝。
- **`web_fetch` 经 DeepSeek**：DeepSeek 无 fetch server tool，实测拒绝。
- **自研 HTML→markdown**：表格、链接、代码块会明显退化；turndown 是 DSH 参考已验证的做法。
- **参数用 `queries: string[]`**：pi 无 DSH 的 web seam，合并逻辑没有落点，模型可直接多次调用。

## Consequences

- 明文 API key 落在用户家目录，安全边界由用户环境与文件权限保障；仓库与提交不出现密钥。
- `web_fetch` 不经 DeepSeek，拥有独立的限额、content-type 分类与错误面；不处理需要登录、反爬或 robots 的场景。
- 引入两个运行时依赖（`turndown`、`@joplin/turndown-plugin-gfm`）；本地 `pi install` 不执行 npm install，依赖需先在 workspace 安装落位。
- 端点、模型与限额可通过配置文件更换，无需改代码或重装。
