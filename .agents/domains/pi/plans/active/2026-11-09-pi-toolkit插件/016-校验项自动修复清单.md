# 校验项自动修复清单

## 需求

2026-11-09：`nano_flow_check` 里能自动修复的问题希望自动修，输出只说修了什么。本文先列清单，不动代码。

## 现状：已经在自动修（只出现在「已更新索引」里）

1. spec 的 `## 追踪 Note`：缺段 → 追加；过期 → 整段重写。
2. `notes_index.md`：每次重写。
3. `questions/index.md`、`adr/index.md`、`workflows/index.md`：每次重写。
4. `CONTEXT-MAP.md`：全量模式重写（`domain` 过滤不写）。
5. 缺 `GUIDE.md`：建空文件。

这些属于「生成物不归人维护」，修完不改变任何原文。

## A 档：可机械修，不丢信息

1. `[status] spec 状态应为 X` —— 由全部 note 状态派生，纯计算。
2. `[name] name 必须与文件名/目录名一致` —— 以文件名为准改写 YAML `name`；**必须联动**改其他 note 的 `related_noted` 与各页面 `## 相关` 的链接文本，否则把 1 个错误变成多个。
3. `[related] 只允许一个「## 相关」段` —— 合并去重。
4. `[related] 「## 相关」必须是最后一个章节` —— 整段移到文末。
5. `[related] 「## 相关」不能为空` —— 删掉空段。
6. `[header] 只有 blocked 的 note 才写 reason` —— 删掉该字段。
7. `[header] name / description / reason / next_step 必须是单行` —— 多行合并成一行，文字全保留。
8. `[index] 索引文件名必须是小写 index.md` —— `INDEX.md` 重命名。
9. `[missing] 缺少 questions 目录` —— 建目录 + 生成 `index.md`。
10. `[related] related_noted 不能引用自身` —— 删掉自身项。
11. `[related] 相关链接目标不存在`，且同域/同 Plan 内文件名唯一匹配 —— 重写相对路径（层级算错是最常见成因）。
12. `[number] 编号必须从 001 连续` —— 重命名文件为三位连续编号；同样要联动改 `related_noted` 与链接，且必须整域一次改完。
13. `[related] related_noted 引用了不存在的 note` —— 删掉失效项。**有信息损失**（可能只是笔误），建议默认只列待确认。

## B 档：能生成文本，但属于「写内容」，需要先点头

14. `[header] 缺少 name` —— 用文件名去掉 `.md` 补。
15. `[header] 缺少 description` / `description 超长` —— 取正文首段首句；超长截到上限。
16. `[header] 缺少 next_step`（非 completed）—— 取正文里「下一步 / 待办」的句子；找不到就留空，不编。

## C 档：无法自动修，只能报

- `[size]` 篇幅超限：要压缩或拆分，取决于内容取舍。
- `[name]` 名称重复、名称不含中文、name 超长。
- `[header]` YAML 头缺失/无效、`metadata` 不是对象、未知头字段（旧字段语义映射属一次性迁移，不通用）。
- `[header]` status 不在枚举内（拼写纠错靠猜，不做）。
- `[layout]` Plan 内嵌目录、workflows 不是目录、questions/adr 下放目录、plans 下非生命周期目录。
- `[name]` Plan 目录名不是 `YYYY-MM-DD-中文工作名`、domain 非 kebab-case。
- `[missing]` 缺 `CONTEXT.md` / `spec.md`：内容丢失，造空壳会掩盖问题。
- `[header]` `blocked` 缺 `reason`。
- `[lifecycle]` 生命周期目录名非法。

## 实现注意

- 输出统一成一个 `fixed` 列表：`路径 [规则] 做了什么`；未修的仍进 errors。现在只有 `updated`（索引类），扩展时保留它，另加 `fixed`。
- 两档开关：默认可修就修；`related_noted` 失效项这类删信息的放 `--fix-lossy`（或先只报告）。
- 联动修复（name、编号）必须先算全量改名映射，再一次性写回，避免中间态让引用校验连环报错。
- 顺带修：`check-domain.mjs` 目前把「只剩被 gitignore 轨迹文件」的目录当 Plan（见[问题 001](../questions/001-Plan迁生命周期后log残留旧目录.md)），这条既不报也修不了，属 C 档漏报。

## 落实（2026-11-09）

用户选定：只做 A 档的 1、2、6、7、9，其余一律不修。

- 1 `[status] spec 状态应为 X`：`scanPlan` 里先派生再写回；只在原值是合法枚举时改，缺键/拼错仍报。
- 2 `[name] name 与文件名/目录名不一致`：`readDocument` 收 `expectedName`，改写 YAML `name`；`propagateRenames` 把同 Plan 其他 note 的 `related_noted`（文件与内存两处）一起改。
- 6 非 blocked 的 note 写了 reason：删字段。
- 7 多行头字段：`name`/`description`/`reason`/`next_step` 折成单行；块标量（`|`）的续行一并删，否则重解析会把续行当成同一个标量的接续（这个 bug 由测试拓出后修掉）。
- 9 缺 `questions/`：建目录，`index.md` 由原有生成逻辑补上。

未做（按用户选择）：`## 相关` 段相关四条、`INDEX.md` 重命名、`related_noted` 自身/失效项、链接路径重写、编号重排、B 档生成式、C 档全部。

改动面：`scripts/lib/base.mjs`（`addFixed`、`writeInsideWorkspace`，后者被 `writeGenerated` 复用）、新增 `scripts/lib/fix.mjs`（行级 YAML 改写与改名传播）、新增 `scripts/lib/report.mjs`（文本输出与参数，腾出行数）、`scripts/lib/checks.mjs`（`applyFieldFixes`）、`scripts/check-domain.mjs`、`scripts/check-domain.d.mts`（`fixed`）、`tools/check.ts`（输出「已自动修复 N 项」）、README 一段。

输出形态：保留原有「已更新索引」，新增 `已自动修复 N 项：` 块，每行 `路径: [规则] 做了什么`；没修的问题照旧进 errors。
