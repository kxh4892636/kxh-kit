# 005-轨迹序号不再整文件解析

## 交付

- `log.ts` 的 `countRuns` 改为按固定前缀 `{"type":"run"` 数行（`buildRunRecord` 的 `type` 是第一个键），不再逐行 `JSON.parse`；新增常量 `RUN_LINE_PREFIX` 并写明为什么不解析。

## 验收

- 序号语义不变（坏行、空行、非 run 行都不计入），单轮轮末的开销不再随文件体积解析。

## 证据

- 真实轨迹 `.agents/domains/pi/plans/reference/2026-11-09-pi-toolkit插件/log.jsonl`（3.5 MB / 20 条）：旧实现 12 ms，新实现 2 ms。
- `log.test.ts` 的「空行与非 JSON 行」用例仍然通过；`enqueueAppend` 的串行编号用例仍然通过。
