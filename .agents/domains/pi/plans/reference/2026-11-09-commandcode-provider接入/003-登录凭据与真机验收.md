# 003-登录凭据与真机验收

## 交付

一条被真机证明可用的链路，以及每条验证命令的结果。

## 验证证据

| 项 | 命令/位置 | 结果 |
|---|---|---|
| 登录（无 `apiKey` 仍生成默认 API key 登录） | `~/.pi/agent/auth.json` | `commandcode` 存在，`{"type":"api_key","key":"user_…"}` |
| 模型列表 | `pi --list-models \| grep -c '^commandcode'` | **96**，与上游 `/models` 一致 |
| OpenAI 协议路径 | `pi -p --model commandcode/deepseek/deepseek-v4-flash "回复三个字"` | 正常流式返回「可用了」 |
| 工具调用 | `pi -p --model commandcode/deepseek/deepseek-v4-flash "读 packages/pi-toolkit/package.json，只回答 name"` | 返回 `@kxh4892636/pi-toolkit`，read 工具调用成功 |
| Anthropic 协议路径 | `pi -p --model commandcode/claude-sonnet-5` | HTTP 403，Anthropic 信封 `{"type":"error","error":{"type":"permission_error","message":"MODEL_NOT_IN_PLAN: …"}}` |
| 套餐门禁 | 同上，换 `claude-haiku-4-5-20251001`、`claude-fable-5`、`gpt-6-astra` | 同样 `MODEL_NOT_IN_PLAN`（OpenAI 信封为 `403 {"message":"…","type":"permission_error","code":"FORBIDDEN"}`） |

## 结论

- **端点映射正确**：Anthropic 那条的失败是**套餐权限**而非协议或路径问题——错误由 Anthropic 信封返回且状态码 403。若 baseUrl 拼错会得到 400 `invalid_request_error` 或 404，不会是这个结构。OpenAI 那侧已经完整跑通对话与工具调用。
- **当前账号只开了低档模型**：Claude 全系与 `gpt-6-astra` 需要 Provider 及以上套餐或按需加购。这不影响接入，`/model` 里仍会列出全部 96 条，只是选中受限模型时上游返回 403；错误信息原样透传给用户，可读。
- **未探测项仍开放**：`reasoning`/`image`/`maxTokens` 需要能跑的模型来试，当前可跑的是 `deepseek/deepseek-v4-flash` 等开源模型。`maxTokens` 仍是 `min(窗口/8, 64000)` 的推导值；`reasoning` 对 Claude 系默认关。三项作为已知限制留在 note 002 的「实现偏差」，等账号可用的模型变多或用户加购时再补。
