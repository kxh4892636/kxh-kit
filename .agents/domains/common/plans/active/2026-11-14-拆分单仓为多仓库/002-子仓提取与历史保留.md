# 002-子仓提取与历史保留

## 目标

9 个目录各变成一个带历史的独立仓，放在 `repos/<名>`，分支统一 `main`；`apps/`、`packages/` 从容器仓删除。磁盘上的 ignored 私有内容原样保留、继续被忽略。

## 两条硬约束

1. **历史只认 tracked 文件**：`git subtree split` 只从提交历史里抽该前缀，工作区新文件、ignored 文件不会进去。
2. **私有内容只活在磁盘**：`wiki/docs/010-记录`（86 个）、`000-中转`（2 个）、`070-工作`（6 个）、`etf/data`、`music/.env` 全都不在 git 里。所以**搬目录必须整目录搬**，搬完仍被忽略。

## 每个仓的搬运流程

以 `apps/wiki` 为例，在容器仓根执行（PowerShell）：

```powershell
# 1. 在旧仓库里抽出一条只含该目录的历史分支（回滚点，先不删）
git subtree split --prefix=apps/wiki -b split/wiki

# 2. 整目录搬走：tracked + ignored 一起搬，不经过 checkout
Move-Item -LiteralPath 'apps/wiki' -Destination 'repos/wiki'

# 3. 在新目录里建仓，把抽出的历史挂到 HEAD，再让索引对齐 HEAD
git init -b main repos/wiki
git -C repos/wiki fetch ..\.. split/wiki          # 从容器仓取，split 分支是本地分支
git -C repos/wiki update-ref refs/heads/main FETCH_HEAD
git -C repos/wiki reset                            # mixed：只改索引，不动工作区文件
```

```powershell
# 4. 校验：工作区必须干净，历史必须是 split 的顶端
git -C repos/wiki status --porcelain      # 期望空
git -C repos/wiki log --oneline -1        # 期望 split/wiki 的提交
git -C repos/wiki ls-files docs/010-记录  # 期望 0 行
git -C repos/wiki status --ignored --porcelain docs/010-记录   # 期望 !! 开头的 ignored
```

要点：

- `reset` 用默认 mixed，**不能用 `--hard`**：`--hard` 会按 HEAD 重写工作区，ignored 目录里与新仓无关的本地文件有被覆盖的风险，也让「搬运」变成「重新检出」。
- 搬完目录后容器仓会看到 `apps/` 下这些文件被删；这是预期，最后统一提交。
- `split/<名>` 分支留在旧仓库里当回滚点，全部验收通过后再删。

## 批量顺序

1. **先跑 `packages/docusaurus-plugin-link`**（9 个文件，最小），验证「搬 + 挂历史」这套流程和校验命令。
2. 再按体量从小到大：`docusaurus-plugin-mindmap`、`dsh-infinite-story`、`etf`、`pi-toolkit`、`nano-flow`、`dsh-toolkit`、`music`、`wiki`（wiki 的 ignored 私有内容最多，放最后，全程比对文件数）。
3. 每个仓搬完立刻跑一遍上面的四条校验，不过就停在原地，不继续下一个。

## 容器仓收尾

```powershell
# .gitignore 增加 repos/，避免嵌套仓库被当成 untracked 或 embedded repo
Add-Content .gitignore "repos/"
git add -A            # 记录 apps/、packages/ 的删除；repos/ 被忽略不会进来
git status --short    # 期望只有删除 + .gitignore 变更
git commit -m "chore(workspace): apps 与 packages 拆到 repos/ 下的独立仓库"
```

## 验收

- `repos/` 下 9 个目录各存在 `.git`，`git -C repos/<名> status --porcelain` 为空。
- `git -C repos/<名> log --oneline | Measure-Object -Line` 与 `git log --oneline split/<名>` 的提交数一致。
- 每个仓 tracked 文件数与拆分前 `git ls-files apps|packages/<名>` 的计数一致（92 / 416 / 1760 / 9 / 13 / 19 / 145 / 127 / 97）。
- `repos/wiki/docs/010-记录` 文件数仍为 86，且 0 tracked、状态为 ignored。
- 容器仓 `git status` 干净，`Get-ChildItem apps,packages` 不存在。
