# 004-跑测试会不会在tmp留目录

## 现象

本机 `/tmp`（Windows 上是 `%LOCALAPPDATA%\Temp`）攒了两万多个目录，名字像 `pi-bridge-*`、`dsh-keep-alive-test-*`、`diff-viewer-fixture-*`、`loopx-workspace-*`，容易误判成 kxh-kit 的测试外溢。

## 怎么判断

1. 先看前缀是否属于本仓库：`rg -l "pi-bridge" --glob '!node_modules' .` 无结果，就说明来自本机别的项目，不是这里的产物。
2. 再看包内是否清理：`mkdtemp` 所在文件里应同时有 `rmSync(`/`rm(`，以及 `afterAll`/`afterEach`（或统一 helper）。
3. 最可靠的是实测：先数前缀目录数，跑一次该包测试，再数一次。

```bash
ls -1d /tmp/<前缀>-* 2>/dev/null | wc -l   # 跑测试前后各一次
```

## 现状（2026-11-11 实测）

- `apps/music`：曾经真漏（`server/*.test.ts` 只建不删，一周 878 个 / 198 MB），已改为 `server/temp-dir.test-helper.ts` + `afterAll(cleanupTempDirs)`，跑完前后计数都是 0。
- `packages/pi-toolkit`（298 条）、`packages/dsh-toolkit`（850 条）、`packages/nano-flow`、`apps/etf`：各测试文件已有 `afterEach`/`afterAll` 清理，跑完不留目录。
- 大量残留来自本机其他项目，删掉即可，不需要改本仓库代码。
