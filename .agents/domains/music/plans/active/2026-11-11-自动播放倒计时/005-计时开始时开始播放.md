# 005-计时开始时开始播放

## 交付

- `client/app/playback/use-playback.ts`：`Playback` 增加 `play()`（暂停则 `audio.play()`，已在播则空操作，无当前曲目则不动）；`toggle()` 复用它。
- `client/app/routes/home.tsx`：`onCountdown(minutes)` 与 `onEndless()` 在写 store 之后调用 `playback.play()`。
- `e2e/smoke.spec.ts`：新增「计时开始时音乐从暂停转为播放」；「不限时」用例改成从暂停出发，断言点击后出现「暂停」按钮。

## 验收

- [x] 暂停状态（`currentTime` 0）点「开始计时」→ `paused false`，`currentTime` 继续走，按钮变「暂停」。
- [x] 正在播放时再设一次计时 → 曲目不重启（实测 1.45s → 2.27s 连续）。
- [x] 点「不限时」同样开播。
- [x] 无当前曲目时（按钮 `disabled`）不触发任何播放。
- [x] `vp check`、63 条单测、8 条 e2e 全绿。

## 决策与验证

- **用 `play()` 而不是复用 `toggle()`**：`toggle` 会在播放中把音乐暂停，联动必须是单向的「确保在播」。
- **`play()` 空操作而不是重播**：用户可能已经听到一半，再设一次计时不该把它拉回 0:00。
- **有限与不限时都联动**：两者都是「确定自动播放生效期」的同一个提交动作；只联动有限会让「不限时」从暂停开始，与语义相反。
- 真机实测（5210，1440/390）：`pausedAtStart true` → 开始计时后 `paused false / t 0.97 / cap 暂停`；390 点「不限时」后 `paused false / 读数 不限时`。截图 `.hallmark/shots/timer-play-linked-1440.png`、`timer-linked-390.png`。
- e2e：8/8 通过（新增 1 条，改写 1 条），单测 63/63，`vp check` 通过。
