# 001-倒计时按墙钟计时且不可撤销

2026-11-11 用「倒计时」替换了 2026-11-08 的自动播放开关（布尔 `autoPlay`）。这次改的不只是 UI 形态，而是自动播放的契约：

- 状态为三态 `SleepTimer`：`{ kind: "off" }`（默认，播完停）、`{ kind: "endless" }`（不限时，等同原开关常开）、`{ kind: "until", endsAt, totalMs }`（有限）。`isAutoPlayActive(timer, now)` 判定：`endless` 恒真，`until` 为 `now < endsAt`。
- **按墙钟计时**，不是「仅播放时累计」：暂停听也在消耗时长。
- **不可撤销**：不能暂停、不能取消、不能改时长；「不限时」同样不可取消。唯一逃生口是刷新页面（状态不持久化，`localStorage` 只留 `history`）。
- **到期不打断**：当前曲目照常播完，之后切到下一首但不自动播放，界面回到「定时」。
- 判定在 `onEnded` 时按 `endsAt` 现算，不等控件把状态置回 `off`。
- 开始计时（含「不限时」）时若处于暂停则直接开播，已在播则续播、不回到 0:00。

Considered Options：

- **仅播放时计时（暂停冻结）**：语义更接近「睡眠定时」，但用户明确要的是「自动播放生效的时长」，且需要额外记账累计播放秒数。
- **可暂停 / 取消 / 改时长**：把不可撤销改成可撤销，误设代价变小，但用户明确要求单向不可回头。
- **到期弹「本轮结束后停止」提示或「续 10 分钟」**：多一层交互与状态，用户明确不做，生效期间只显示倒计时本身。
- **状态持久化到 `localStorage`（沿用旧开关做法）**：刷新后继续计时，但会让「刷新即重置」这条逃生口失效。
- **由控件 `setInterval` 归零时置 `off` 作为唯一判定**：标签页在后台时定时器被节流，会漏掉到期。

Consequences：

- 误设时长只能等或刷新（上限 1440 分钟）。用两件事压住误触：快选 5/10/15/30 只填数字不开始，开始只有一个入口「开始计时」；输入校验 1–1440 整数。
- 用户在暂停状态下设 1 小时，实际只剩「是否还记得刷新」这条路；这是用户已明确接受的取舍。
- 到期判定不依赖控件生命周期，控件卸载或后台节流都不漏，但要求每个读自动播放的地方都传 `now`。
- 旧 `localStorage` 的 `autoPlay` 字段被忽略且不做版本迁移，旧数据仍可读。
