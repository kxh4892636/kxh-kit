# 001-音频e2e怎么测到期与播完

## 适用条件与现象

在 `apps/music/e2e/smoke.spec.ts` 里测两类行为时踩到：

- 倒计时到期：用 `page.clock` 推进 61 秒，读数确实过期，但换曲断言等不到。
- 播完换曲：在 jsdom 单测里等 `ended`、读 `audio.duration`，永远是 `NaN` 或事件不来。

## 原因

- `page.clock` 换的是整套定时器与 `performance.now`，音频进度与解码也一起被冻结，`timeupdate` / `ended` 不再推进。
- `ended`、`duration`、`play()` 依赖真实解码，jsdom 只模拟 DOM；`environment: node` 下更没有媒体栈。
- 只有墙钟（`Date.now()`）是应用自己判的，因此只有它需要被伪造。

## 解决方法

1. 音频行为一律在真浏览器（Playwright）里测，不在 jsdom 里测。
2. `page.addInitScript` 覆写 `Date.now`：保留 `realNow()`，暴露 `window.__musicAdvance(ms)` 累加 offset；只动墙钟，不动音频计时。见 `e2e/smoke.spec.ts` 的 `installClock` / `advance`。
3. 触发播完不要真等：把 `audio.currentTime = audio.duration - 0.6`（`jumpToEnd`），让浏览器自然发 `ended`。
4. 到期语义分两步断言：先推墙钟（到期、当前曲仍 `paused false`），再推到曲末（换曲且 `paused true`）。

## 验证

`cd apps/music && pnpm exec playwright test` 全绿（2026-11-11 为 8 条、约 14s）。到期用例与「不限时」用例必须在同一次运行里一起过，否则无法证明时间推进只影响判定。
