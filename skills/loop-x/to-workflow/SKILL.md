# 固化工作流

把重复活动定界为一个**循环**, 运行 `/grilling` 清空决策前沿, 将其**工作流**固化到 `/domain-x` skill 中拥有该循环的业务域目录.
使用 `/writing-for-agents` 编写工作流.

## 词汇

- **循环** - 反复出现且有可辨认起止边界的活动.
- **工作流** - 指导循环每次运行的规格; 可以规定固定步骤, 或提供用于现场派生步骤的上下文, 或混合两者.
- **运行契约** - 工作流的触发条件, 输入, 前置条件, 委派边界, 结束边界, 输出和完成证据.
- **委派边界** - 自动执行与用户确认的分界; 在授权, 风险和可逆性允许的范围内尽可能右移.
- **简报** - 到达委派边界时交给用户的可直接决策摘要, 包含现场事实, 证据, 未决选项和推荐答案.

## 步骤

1. **取证** 读取存在的 `DOMAIN.md` 和 `CONTEXT-MAP.md`, 定位所触及业务域, 再读取它们的 `CONTEXT.md`, 相关 ADR 和 `/domain-x` 中该业务域的 `README.md` 与相邻工作流; 检查当前工作中足以证明重复模式的事实. 在领域语言, 既有约束, 相邻工作流和重复证据均已覆盖, 且现场可检索的事实缺口已清空时完成.
2. **定界** 从用户指出及证据揭示的候选项中, 提出潜在循环, 让用户选择一个并确定拥有它的业务域. 跨域输入输出作为契约引用, 不复制工作流. 在能够明确说出它的 owner, 触发, 起点, 终点和重复结果, 且用户确认选择时完成.
3. **拷问** 以所选循环为根运行 `/grilling`; 清空工作流形态, 运行契约, 委派边界及简报, 失败恢复和推荐技能的决策前沿. 在前沿为空且用户确认达成共同理解时完成.
4. **落盘** 按已确认决策在 `/domain-x` 的业务域目录中创建, 修订, 合并或删除工作流, 并同步该目录 `README.md` 的 路径-触发条件 索引; 每个含义只写在一个权威位置. 新业务域同时创建目录与 `README.md`, 并登记到 `/domain-x` 的 `SKILL.md` 业务域索引. 在每项决策恰好落到一个现场文件位置, 且没有其他文件重复规格化该循环时完成.
5. **读回** 重新读取现场文件, 逐项核对运行契约, 委派边界及简报, 适用的条件分支与失败恢复, 推荐技能, 索引与文件的一致性, 既有文档冲突和下列约束. 在全部决策与约束均有核对结果, 冲突已显式指出, 且已向用户报告文件路径与完成证据时完成.

## 输出约束

- 一个工作流文件只规格化一个循环; 结构由循环决定.
- 触发条件只写在所属业务域 `README.md` 的 路径-触发条件 索引中, 不在工作流文件内重复.
- 工作流包含 `推荐技能` 章节, 说明运行时推荐调用的技能及其时机.
- 文件名与正文使用中文; 与 ADR 或既有工作流冲突时显式指出, 不静默覆盖.
- 工作流的目录结构如下

```text
├── CONTEXT-MAP.md
├── agents/skills/{domain-flow}
│  ├── README.md
│  └── NNNN-{workflow}/
│      ├── NNNN-{workflow}.md
│      ├── script.py
│      └── reference.md
└── ...
```
