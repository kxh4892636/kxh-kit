# Electron CI 跨平台矩阵

## CI 目标

- 重现安装: 使用 frozen lockfile 保证依赖解析不漂移;
- 跨平台门禁: 在 Windows、Linux、macOS 检查代码和构建;
- 原生产物: 每个平台使用对应 runner 生成发行物;
- 证据保留: 上传 package 和 E2E report;

## quality job

- OS matrix: `windows-latest`、`ubuntu-latest`、`macos-latest`;
- setup: checkout v6、pnpm action v6、setup-node v7;
- Node: 24，与 Electron 43 内置 major 对齐;
- 安装: `pnpm install --frozen-lockfile`;
- 门禁: format、lint、typecheck、test、build;
- `fail-fast: false`: 一个平台失败时其他平台仍继续，保留完整差异证据;

## package job

| matrix name | runner           | command                          |
| ----------- | ---------------- | -------------------------------- |
| windows-x64 | `windows-latest` | `electron-builder --win --x64`   |
| linux-x64   | `ubuntu-latest`  | `electron-builder --linux --x64` |
| macos-arm64 | `macos-latest`   | `electron-builder --mac --arm64` |
| macos-x64   | `macos-15-intel` | `electron-builder --mac --x64`   |

- 平台原生构建: 避免跨 OS 工具链、签名和文件格式差异;
- 签名发现: `CSC_IDENTITY_AUTO_DISCOVERY=false` 防止误用 runner 身份;
- artifact name: `lithe-<matrix.name>`;
- retention: 7 天;
- 上传范围: `dist/*`;

## e2e-windows job

- 当前平台: Windows;
- 步骤: frozen install、build、启动真实 Electron E2E;
- 报告: 无论成功失败都上传 Playwright report 与 test results;
- 当前缺口: Linux 与 macOS 没有运行态 E2E;
- 后续方向: 分平台验证 AppImage、DMG 与系统权限行为;

## 为什么按目标 OS 构建

- macOS DMG、签名和公证依赖 macOS 工具链;
- Windows 安装器包含 PE 资源处理与平台工具;
- Linux AppImage 依赖 Linux 用户态文件布局;
- 原生模块还会增加 ABI、libc 和 CPU architecture 维度;
- CI matrix 比单机强行 cross-build 更可预测;

## 失败定位顺序

1. 判断失败属于 install、quality、build、package 或 runtime;
2. 比较是否只在一个 OS/arch 出现;
3. 检查路径分隔符、大小写、权限和系统工具;
4. 下载对应 artifact 或 E2E report;
5. 在相同 OS 和 Node/pnpm 版本复现;
6. 最小修复后先重跑失败 job，再跑完整 matrix;

## 发布前需要增加

- Windows 和 macOS 签名 secret 管理;
- macOS notarization;
- 安装、升级与卸载测试;
- release tag 与版本一致性;
- artifact checksum 和 provenance;
- Linux/macOS 打包态 E2E;
