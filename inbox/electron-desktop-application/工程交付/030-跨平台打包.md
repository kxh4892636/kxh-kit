# Electron 跨平台打包

## electron-builder 的职责

- 输入: electron-vite 的 `out/**`、生产依赖、metadata、图标和额外资源;
- 输出: 安装器、解压应用和增量更新 metadata;
- 配置: `electron-builder.yml`;
- 与编译区别: builder 组装和签名应用，不负责 React HMR 或 typecheck;

## 应用 metadata

- `appId`: `com.kxh.lithe`，用于操作系统识别应用;
- `productName`: `Lithe`，用于用户可见名称;
- `executableName`: Windows 可执行文件为 `lithe.exe`;
- `artifactName`: 安装器使用 `lithe-1.0.0-setup.exe`;
- `buildResources`: 图标和 macOS entitlement 位于 `build/`;

## 文件 allowlist

```yaml
files:
  - out/**
  - package.json
  - LICENSE
extraResources:
  - from: drizzle
    to: drizzle
```

- allowlist: 只把运行必需文件放入 app archive;
- 防止泄漏: 测试、报告、源码、编辑器配置和工程脚本不进入安装包;
- `extraResources`: migration 保持普通文件，main 从 `process.resourcesPath` 读取;
- 经验: 只有排除规则时曾把 E2E 报告和工程配置打入 asar;

## 目标矩阵

| OS      | arch  | format   | 当前状态                     |
| ------- | ----- | -------- | ---------------------------- |
| Windows | x64   | NSIS     | 本地构建与打包态 E2E 已通过  |
| Linux   | x64   | AppImage | CI 配置                      |
| macOS   | x64   | DMG      | Intel runner CI 配置         |
| macOS   | arm64 | DMG      | Apple Silicon runner CI 配置 |

- 不做 universal binary: x64 与 arm64 分开生成;
- 首版无签名: Windows 无证书，macOS 不签名、不 notarize;
- 影响: 用户可能看到 SmartScreen 或 Gatekeeper 警告;
- 首版无发布: `publish: null`，CI 只上传 artifacts;

## node:sqlite 对打包的影响

- 无额外 SQLite `.node` binary: driver 已包含在 Electron runtime;
- `npmRebuild: false`: 当前没有需要 builder rebuild 的生产原生扩展;
- lockfile 可出现 `better-sqlite3` optional peer metadata，但安装包没有其 native binary;
- 未来加入 `node-pty`: 必须重新设计 native rebuild、预构建和多平台验证;

## 打包器兼容覆盖

- 症状: builder 下载 Electron 时读取不到 `ElectronDownloadCacheMode.ReadWrite`;
- 原因: app-builder-lib 使用新版 API，但声明的 `@electron/get ^3` 缺少该 export;
- 处理: 仅覆盖 `app-builder-lib>@electron/get` 为 5.0.0;
- 验证: peer check、Electron 下载和 Windows NSIS 构建通过;

## 产物检查

- 确认 `dist/lithe-1.0.0-setup.exe` 存在;
- 检查 `resources/drizzle` 包含 migration;
- 列出 `app.asar`，确认没有测试报告、源码或 SQLite native binary;
- 使用打包后的 `lithe.exe` 运行 E2E;
- `dist/` 和 `out/` 属于可再生成产物，不提交 Git;
