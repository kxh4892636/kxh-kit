# Electron IPC 调用链与契约

## IPC 的本质

- `IPC`: main 与 renderer 位于不同进程时，用消息传递请求和结果的机制;
- channel: 开发者定义的消息名称，例如 `preferences:get-theme`;
- invoke/handle: `ipcRenderer.invoke()` 发起请求，`ipcMain.handle()` 处理并返回结果;
- Lithe 使用场景: 读取运行环境、读取主题、保存主题;
- 设计目标: renderer 能表达业务意图，但不能获得任意桌面权限;

## 一次调用的完整路径

```text
SettingsPage
  -> useThemeStore.setTheme('dark')
  -> window.lithe.preferences.setTheme('dark')
  -> preload: ipcRenderer.invoke('preferences:set-theme', 'dark')
  -> main: ipcMain.handle(...)
  -> database.preferences.setTheme('dark')
  -> Promise 返回 renderer
```

- UI 起点: renderer 只知道 `window.lithe` 的领域接口;
- 传输层: preload 将函数调用转换为固定 channel 的 IPC 消息;
- 权限终点: main 校验请求并访问 SQLite;
- 返回值: Electron 对可克隆数据进行序列化，函数、DOM 节点和自定义原型不能透明传输;

## 共享类型契约

```ts
interface LitheBridge {
  preferences: {
    getTheme: () => Promise<Theme>;
    setTheme: (theme: Theme) => Promise<void>;
  };
}
```

- `src/shared/app-contract.ts`: 定义 renderer 可见的能力和传输数据;
- `src/preload/index.d.ts`: 把 `window.lithe` 声明加入浏览器全局类型;
- 限制: 类型声明不会自动保护运行时，因此 main 仍接收 `unknown` 并验证;

## channel 契约

- `src/shared/ipc-channels.ts`: 集中维护 channel，避免 main 与 preload 拼写漂移;
- namespace: `preferences:` 和 `runtime:` 只是可读性约定，不会自动提供权限;
- 稳定性: channel 和 payload 一起构成跨进程协议，变更时需同步更新两端和测试;

## preload bridge

```ts
const bridge: LitheBridge = {
  preferences: {
    getTheme: () => ipcRenderer.invoke(ipcChannels.getTheme),
    setTheme: (theme) => ipcRenderer.invoke(ipcChannels.setTheme, theme),
  },
};
```

- 窄接口: 只暴露 `getTheme()` 和 `setTheme()`，不暴露整个 `ipcRenderer`;
- 领域命名: renderer 表达“设置主题”，而不是“向任意 channel 发消息”;
- 审计收益: 搜索 `window.lithe` 即可看见所有页面可使用的桌面能力;

## main handler

- handler 接收 IPC event 和 payload;
- handler 先完成信任校验，再调用数据库 repository;
- renderer 不知道表名、SQL 和数据库路径;
- handler 返回值经过结构化克隆，再由 Promise 交还 renderer;
- handler 重建或退出前需要移除，避免重复注册和悬空引用;
