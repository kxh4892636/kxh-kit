# Electron 进程模型与职责边界

## Electron 的本质

- `Electron`: 将 Chromium、Node.js 与桌面应用生命周期装入同一个发行物的运行平台;
- `Chromium`: 提供 HTML、CSS、DOM、网络栈、渲染和多进程隔离;
- `Node.js`: 提供文件系统、数据库、子进程和操作系统 API;
- 多进程原因: UI 崩溃或恶意页面不应自然获得整个桌面应用的最高权限;

## main 到底是什么

- `main process`: Electron 应用的主进程，也是 `package.json#main` 指向的唯一启动入口;
- Lithe 入口: `package.json` 指向 `out/main/index.js`，源码为 `src/main/index.ts`;
- main 职责: 等待应用 ready、创建窗口、持有 SQLite、注册 IPC、处理第二实例、退出时清理资源;
- main 权限: 默认拥有完整 Node.js 与 Electron 能力，因此能够读文件、启动进程和操作数据库;
- main 不是: React 组件、浏览器页面、所有业务代码必须塞入的单个文件;
- 深层含义: “由 main 实现”表示能力的信任边界和所有权在 main 一侧，具体工作仍可封装为模块或委派给受控子进程;

## 三个执行上下文

| 上下文   | Lithe 入口                  | 可以做什么                          | 不应做什么                    |
| -------- | --------------------------- | ----------------------------------- | ----------------------------- |
| main     | `src/main/index.ts`         | 生命周期、窗口、SQLite、IPC handler | 渲染 React 页面               |
| preload  | `src/preload/index.ts`      | 调用 `ipcRenderer`、暴露窄 API      | 暴露任意 Electron 或 Node API |
| renderer | `src/renderer/src/main.tsx` | React、路由、状态、样式             | 直接访问文件、SQLite、子进程  |

```text
高权限                                           低权限
main  <---------- IPC ---------->  preload  <---->  renderer
桌面能力所有者                     能力适配层          UI
```

## preload 的特殊性

- 执行时机: preload 在页面内容加载前运行，并附着到指定 `BrowserWindow`;
- 权限: sandboxed preload 仍拥有一组受限能力，权限高于普通网页;
- 作用: 把 main 允许的领域能力映射为 renderer 可调用的普通 JavaScript API;
- context isolation: preload 的全局对象与页面的全局对象隔离，不能靠直接赋值共享任意对象;
- Lithe 做法: `contextBridge.exposeInMainWorld('lithe', bridge)` 暴露 `window.lithe`;

## BrowserWindow 的防线

```ts
webPreferences: {
  contextIsolation: true,
  nodeIntegration: false,
  preload: join(__dirname, '../preload/index.js'),
  sandbox: true,
  webviewTag: false,
}
```

- `contextIsolation: true`: 页面不能篡改 preload 所处隔离世界的内建对象;
- `nodeIntegration: false`: renderer 不能直接 `import 'node:fs'` 或使用完整 Node.js;
- `sandbox: true`: renderer 只能通过通信请求更高权限进程完成特权操作;
- `webviewTag: false`: 避免引入额外嵌入页面与更复杂的权限面;
- `will-navigate`: Lithe 阻止当前窗口导航到其他地址;
- `setWindowOpenHandler`: Lithe 拒绝创建新窗口;

## 能力放置规则

| 能力                       | 默认归属                  | 原因                            |
| -------------------------- | ------------------------- | ------------------------------- |
| React 组件、路由、样式     | renderer                  | 纯 UI 与浏览器能力              |
| 文件读取、SQLite、系统信息 | main                      | 需要 Node.js 或 Electron 特权   |
| 能力签名与 IPC 映射        | preload                   | renderer 与 main 的适配边界     |
| CPU 密集任务               | worker 或 utility process | 避免阻塞 main 事件循环          |
| 长期运行的命令或 PTY       | main 管理，子进程执行     | main 持有生命周期，工作负载隔离 |

## 常见误区

- 误区: Electron 页面可以放心启用 Node.js，因为页面是本地文件;
- 修正: 本地页面仍可能存在 XSS、依赖注入和错误导航，权限应保持最小;
- 误区: preload 是“第二个 main”;
- 修正: preload 是能力桥，不应持有数据库和通用文件访问器;
- 误区: 所有 main 能力都应写在 `index.ts`;
- 修正: `index.ts` 负责装配和生命周期，数据库、IPC、窗口状态应分别封装;
- 误区: 将对象暴露到 `window` 就有类型安全和运行时安全;
- 修正: TypeScript 只检查编译期，main 仍必须校验 sender 与参数;
