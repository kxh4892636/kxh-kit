# Electron 测试分层

## 为什么需要分层

- renderer test: 证明 React 组件与浏览器交互;
- main test: 证明 Node.js 模块和 SQLite 行为;
- Electron E2E: 证明进程边界、preload、IPC、窗口和重启链路;
- packaged E2E: 证明 asar、资源路径、Electron runtime 与安装布局;
- 单层测试无法覆盖以上所有风险;

## Node 数据库测试

- runner: Vitest;
- environment: `node`;
- include: `src/main/**/*.test.ts`;
- 数据库: 每个测试使用临时目录内的真实 SQLite 文件;
- 测试目标: 默认主题、主题 upsert、窗口状态 upsert 与读取;
- 清理顺序: 先关闭所有数据库连接，再删除临时目录;

```text
create temp directory
  -> createAppDatabase(temp/lithe.db)
  -> migration
  -> arrange / act / assert
  -> sqlite.close()
  -> remove temp directory
```

- 价值: 不 mock Drizzle 和 SQLite，直接验证 schema、migration 与 repository;
- 局限: Node test 不会验证 Electron 的 `app.getPath()` 和 IPC sender;

## renderer 组件测试

- runner: Vitest + Testing Library;
- environment: jsdom;
- include: `src/renderer/src/**/*.test.tsx`;
- setup: 加载 jest-dom matcher;
- 测试目标: 首页状态展示、设置页主题交互;
- bridge: 测试提供受控 `window.lithe` fake，而不是启动真实 main;

- 查询原则: 优先使用 role、label 和用户可见文案;
- 交互原则: 使用 user-event 模拟用户行为;
- 局限: jsdom 不能证明 BrowserWindow、preload 或真实 IPC 可用;

## 证据强度

| 证据                | 能证明            | 不能证明             |
| ------------------- | ----------------- | -------------------- |
| typecheck           | 类型契约一致      | 运行时数据可信       |
| unit/component test | 模块行为          | 真实进程与打包路径   |
| source E2E          | Electron 进程链路 | 安装资源布局         |
| packaged E2E        | 解压应用真实运行  | 安装器交互与签名信誉 |
| NSIS 构建           | 安装器可生成      | 所有机器都能安装     |

## 质量门禁

```powershell
pnpm run format:check
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run build
pnpm exec drizzle-kit generate
pnpm run test:e2e
pnpm exec electron-builder --win --x64
```

- Oxfmt: 检查格式;
- Oxlint: type-aware、React、Vitest 与 a11y rule，并拒绝 warning;
- TypeScript: Node 和 Web 两套配置分别检查;
- Vitest: main 与 renderer 测试分别运行;
- Drizzle generate: 确认 schema 与 migration 同步;
- Playwright: 验证真实 Electron;
- electron-builder: 验证最终分发链路;

## 测试设计原则

- 越靠近模块越快、越精确;
- 越靠近真实产物越慢、覆盖集成风险越多;
- 真实外部边界不应全部 mock;
- 每种测试只承担它能稳定证明的事实;
- 失败时先在最小层定位，再回到真实路径复验;
