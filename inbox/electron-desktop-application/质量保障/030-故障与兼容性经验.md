# Lithe 任务中的故障与兼容性经验

## Drizzle RC 不能只看 tag 名

- 初始安装: ORM `@rc` 解析为 RC4，Kit `@rc` 解析为 RC3;
- 症状: generate 输出 `SQLiteSyncDialect is not a constructor`;
- 危险点: 命令返回 exit code 0，但输出存在隐藏 TypeError;
- 根因: ORM 与 Kit 不是同一内部 API 构建;
- 修复: 两者固定为 `1.0.0-rc.4-5d5b77c`;
- 通用经验: RC、canary、nightly 包应按同一 build 成组升级;

## node:sqlite 的警告

- Node 24 测试现象: 导入 SQLite 时打印 ExperimentalWarning;
- 官方状态: 当前 Node 文档将 `node:sqlite` 标为 release candidate;
- Electron 运行: 源码态和打包态 E2E 均通过;
- 处理: 记录平台状态，不通过隐藏 warning 假装 API 已稳定;
- 升级: Electron 或 Node 变化时重新验证 Drizzle adapter;

## electron-builder 传递依赖错配

- 症状: 下载 artifact 时读取 cache mode 失败;
- 代码事实: app-builder-lib 使用新版 cache mode API;
- 依赖事实: `@electron/get ^3` 没有对应 export;
- 修复: 只覆盖 `app-builder-lib>@electron/get` 为 5.0.0;
- 验证: peer check、Electron 下载和 NSIS 构建成功;

## 安装包内容检查

- 初始配置: 排除规则没有阻止测试、报告和工程配置进入 asar;
- 风险: 产物膨胀并泄漏内部资产;
- 修复: `files` 改为 `out/**`、`package.json`、`LICENSE` allowlist;
- migration: 通过 `extraResources` 放到 resources;
- 通用经验: 打包成功不代表文件内容正确;

## better-sqlite3 字符串

- 现象: asar 中可见 `drizzle-orm/better-sqlite3/**` adapter;
- 区别: adapter 源文件不是已安装的 native package;
- 真正检查: 根 `node_modules/better-sqlite3` 和 `.node` binary;
- 结果: Lithe 安装包没有 SQLite native extension;
- lockfile: optional peer metadata 不能证明 runtime 依赖存在;

## CSS 级联边界

- 症状: 深色主题 radio label 文字过暗;
- 根因: 组件样式与普通 `text-foreground` specificity 竞争;
- 修复: 使用 Tailwind important variant `text-foreground!`;
- 验证: 重新构建、运行 E2E 并检查截图;
- 经验: DOM 状态通过不代表视觉对比度正确;

## E2E 进程清理

- 症状: 调试运行遗留 Electron/Playwright 进程;
- 排查: 确认 PID、父子关系和命令行;
- 处理: 只终止本次测试进程树;
- 固化: afterEach 关闭 application 并删除临时 userData;
- 经验: 桌面 E2E 必须拥有并清理自己启动的进程;

## “最新”的准确含义

- 约束: electron-vite 5 不接受 Vite 8 peer range;
- 选择: Vite 7 + React plugin 5 的最新兼容组合;
- Node types: 与 Electron 内置 Node 24 对齐;
- CI action: 核对官方版本并使用 setup-node v7;
- 经验: latest 是带兼容约束的求解问题;

## 对抗性排障顺序

1. 读取完整错误和实际 exit code;
2. 查询直接与传递依赖的解析版本;
3. 检查出错代码期待的 export 或 ABI;
4. 采用最小范围的版本对齐或 override;
5. 重跑最小失败命令;
6. 再跑完整门禁和真实产物验证;
