# Electron 应用生命周期与窗口

## 启动链路

```text
Node.js 加载 out/main/index.js
  -> requestSingleInstanceLock()
  -> app.whenReady()
  -> 打开 SQLite 并执行 migration
  -> 读取窗口状态
  -> 创建 BrowserWindow
  -> 注册 IPC handlers
  -> 加载 renderer
  -> ready-to-show 后显示窗口
```

- `package.json#main`: Electron 启动的 main bundle 路径;
- `app.whenReady()`: Electron 初始化完成后才能安全创建窗口和访问依赖 ready 的 API;
- 初始化顺序: Lithe 先创建数据库，再创建依赖数据库的窗口和 IPC;
- 启动失败: 捕获异常、写入 stderr、显示错误框并退出，而不是留下空白窗口;

## 单实例行为

- `requestSingleInstanceLock()`: 第一个实例取得锁，后续实例立即退出;
- `second-instance`: 已运行实例收到事件后恢复最小化窗口并聚焦;
- 用途: 避免多个进程同时竞争单一用户数据库和产生多个主窗口;
- 边界: 单实例锁不是数据库事务，也不能替代 SQLite 的锁与一致性机制;

## BrowserWindow 创建

- 默认尺寸: `1100 × 720`，最小尺寸为 `800 × 560`;
- `show: false`: 页面准备前隐藏窗口，减少白屏和闪烁;
- `ready-to-show`: renderer 首次准备完成后显示窗口;
- `backgroundColor`: 页面绘制前提供与应用接近的背景色;
- `autoHideMenuBar`: Windows/Linux 默认隐藏原生菜单栏;
- preload 路径: 从 main bundle 的 `__dirname` 解析 `../preload/index.js`;

## 窗口状态持久化

- 监听事件: `move`、`resize`、`maximize`、`unmaximize` 和 `close`;
- debounce: 高频移动和缩放事件在 250 ms 后统一写库;
- normal bounds: 最大化时保存正常窗口边界，而不是最大化后的屏幕尺寸;
- 状态字段: `x`、`y`、`width`、`height`、`isMaximized`;
- 恢复顺序: 先应用边界，再按 `isMaximized` 最大化;

## 多显示器防护

- 问题: 用户拔掉显示器后，旧坐标可能让窗口出现在不可见区域;
- Lithe 策略: 保存边界至少与某个 display work area 相交 80 px 才恢复;
- 失败回退: 没有有效状态或状态不可见时使用默认尺寸与系统位置;
- `workArea`: 排除任务栏或 Dock 占用的区域，比完整屏幕 bounds 更适合窗口可见性判断;

## 平台生命周期差异

| 场景          | Windows/Linux | macOS                |
| ------------- | ------------- | -------------------- |
| 所有窗口关闭  | 退出应用      | 应用继续驻留         |
| Dock 再次激活 | 不适用        | 没有窗口时重建主窗口 |
| 第二次启动    | 聚焦已有窗口  | 聚焦已有窗口         |

- `window-all-closed`: Lithe 在非 macOS 平台调用 `app.quit()`;
- `activate`: macOS 用户点击 Dock 图标时，如果没有窗口则重新创建;
- 设计含义: 窗口生命周期和应用进程生命周期不是同一件事;

## 退出清理

- 清理 timer: 防止退出过程中延迟回调继续执行;
- 最后持久化: `before-quit` 再保存一次窗口状态;
- 移除 IPC: 防止 handler 引用已销毁窗口或数据库;
- 关闭 SQLite: 释放文件句柄并完成未决数据库工作;
- 清空引用: 将 `appDatabase` 设为 `undefined`，避免退出阶段误用;

## 开发与生产资源路径

| 资源       | 开发环境                           | 打包环境                        |
| ---------- | ---------------------------------- | ------------------------------- |
| renderer   | `ELECTRON_RENDERER_URL`            | `out/renderer/index.html`       |
| migration  | `app.getAppPath()/drizzle`         | `process.resourcesPath/drizzle` |
| 用户数据库 | `app.getPath('userData')/lithe.db` | 同一逻辑，位置由 OS 决定        |

- `app.getAppPath()`: 当前应用代码根目录，开发时可定位仓库资源;
- `process.resourcesPath`: 安装包解压后的只读资源目录;
- `userData`: 每个用户可写且跨重启保留的数据目录;
- E2E override: `LITHE_USER_DATA_DIR` 仅用于测试隔离，不污染真实用户数据;
