# Electron 文件、命令与终端能力边界

## 当前实现状态

- Lithe 首版没有通用文件读取、命令执行、shell 或 PTY API;
- 当前 bridge 只有运行环境读取和主题设置;
- 本篇记录的是本次设计中确认的放置原则，以及尚未实现的扩展方向;
- 不能把设计结论误写成已交付功能;

## “必须由 main 实现”的准确含义

- 权限所有者: main 决定哪些文件、命令和进程允许访问;
- 生命周期所有者: main 在窗口重建、应用退出和异常时负责清理资源;
- 协议所有者: main 定义可供 renderer 调用的领域化 IPC;
- 实现位置: 具体逻辑可放在 `src/main` 下的深层模块，不必堆进 `index.ts`;
- 工作进程: 长时间运行、容易崩溃或 CPU 密集的任务可由 main 委派给 utility process、worker 或 child process;

## 文件能力

```text
renderer 选择业务对象
  -> IPC 发送对象 ID 或受限参数
  -> main 解析允许根目录内的真实路径
  -> main 校验、读取、限制大小
  -> 返回结构化结果
```

- 不可信输入: renderer 传来的路径、编码、glob 和文件大小都必须验证;
- 路径穿越: `../`、junction、symlink 和大小写差异会绕过简单字符串前缀检查;
- 最小接口: 优先 `documents.read(id)`，避免 `fs.readFile(path)`;
- 大文件: 使用分页、流或分块，不应通过一次 IPC 复制全部内容;
- 写入: 先写临时文件再原子替换，可降低中途崩溃造成的损坏;

## 命令执行能力

- shell 与直接执行: 能直接传 executable 和 args 时，不拼接 shell 字符串;
- 参数边界: 命令、工作目录、环境变量和超时都应使用 allowlist 或明确规则;
- 输出边界: stdout/stderr 需要背压、大小限制和取消机制;
- 生命周期: 应记录进程 PID、退出码、signal、启动时间与所有者窗口;
- 退出策略: 应明确应用退出时终止、保留还是重新连接子进程;
- renderer 权限: renderer 只能请求已定义的动作，不能得到任意 `exec(command)`;

## 普通命令与终端 PTY

| 需求                         | 普通 child process | PTY      |
| ---------------------------- | ------------------ | -------- |
| 执行一次命令并拿结果         | 合适               | 过重     |
| 交互式 shell、颜色、光标控制 | 不完整             | 合适     |
| 模拟真实终端尺寸             | 不支持             | 支持     |
| Windows 实现                 | pipes              | ConPTY   |
| macOS/Linux 实现             | pipes              | Unix PTY |

- `node-pty`: 常见跨平台 PTY binding，但属于原生模块，通常涉及平台编译或预构建二进制;
- `node:sqlite`: Node/Electron 内置模块，与 `node-pty` 的原生打包问题不能混为一谈;
- 当前选择: SQLite 已消除额外 driver 编译，但未来加入 PTY 仍需重新处理 native module 打包;

## 已确认的终端记录方向

- 记录边界: 用户写入 PTY 的 input block，以及 PTY 返回给终端 UI 的 raw output block;
- 原始输出: 保留 ANSI 与控制序列，而不是只保存最终屏幕文本;
- 并发归属: 每个终端使用 `session_id` 区分;
- 转发优先: SQLite 写入不应阻塞 `pty.write()` 或输出到终端 UI;
- 批处理: 事件进入内存队列，约 50 ms 或达到大小阈值时批量写入;
- WAL: 改善记录写入与历史读取并发;
- 崩溃窗口: 接受最多约一个 batch 周期的未落盘数据丢失;

## 仍未确认的终端问题

- Electron 退出后 PTY 是终止、存活还是支持重连;
- SQLite event schema、序号、时间戳与二进制编码;
- batch 的精确大小阈值与 backpressure 策略;
- 崩溃恢复时如何识别未正常结束的 session;
- 历史回放是重放 raw stream 还是重建屏幕状态;
- native module 在 Windows、Linux、macOS 的构建与签名流程;

## 官方资料

- [Electron Process Model](https://www.electronjs.org/docs/latest/tutorial/process-model): 官方建议在需要 fork 工作时考虑 UtilityProcess;
- [Electron UtilityProcess](https://www.electronjs.org/docs/latest/api/utility-process): 独立子进程 API;
- [Electron Security](https://www.electronjs.org/docs/latest/tutorial/security): 不可信内容与本地能力的边界;
