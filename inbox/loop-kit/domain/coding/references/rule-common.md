# Rule Common

体验分代码开发通用规范和 TypeScript 规范。编写或修改 JS/TS 代码前应用本文件；涉及 UI、组件、路由页面时继续读取对应前端 SOP；涉及接口请求、埋点、V10 架构或迁移时继续读取对应 reference。

## 通用开发规范

### 代码行数

- 单个文件不超过 377 行，超过时拆分。
- 单个函数不超过 89 行，超过时拆分。
- 拆分优先按职责和复用边界进行，不为了行数机械拆散强相关逻辑。

### 命名规范

- 文件名使用 `kebab-case`。
- 变量和函数使用 `camelCase`。
- 类、接口、泛型参数使用 `PascalCase`。
- 常量使用 `UPPER_SNAKE_CASE`。
- CSS 类名选择器使用 `kebab-case`。
- 布尔变量使用 `is`、`has`、`should` 前缀。
- React 组件使用 `PascalCase`；事件属性使用 `on` + 元素名 + 事件动词；事件处理函数使用 `handle` + 元素名 + 事件动词。

### 模块导入导出

- 除非框架需要默认导出/导入，否则使用命名导出/导入。
- 不新增无意义 barrel；稳定导出只暴露真实调用方需要的 API。

### 风险边界

- 网络请求、第三方数据、SDK 调用、文件系统、环境变量、后台任务等外部边界必须有错误处理。
- 错误处理中使用项目已有日志工具记录异常。
- 不确定外部数据形态时，先用项目现有 schema/validator 收窄类型。
- 影响真实环境、远程服务或用户数据的命令，先确认目标环境和可回滚方案。

### 注释规范

- 注释只写说明性注释，解释代码背后的原因、约束、取舍和风险。
- 禁止用注释复述代码正在做什么或如何执行。
- 注释比例只约束本次新增或修改的增量代码，存量代码不受限制。
- 增量代码的注释行数占代码行数比例必须在 13% 到 21% 之间；小于 8 行的增量代码允许不强制满足比例。
- 计算比例时不统计空行、纯括号/分隔符行、import/export 声明和仅格式化导致的行变化。
- 注释行只统计本次新增或修改的说明性代码注释，不统计文档块、TODO、lint 禁用指令或生成代码注释。

## TypeScript 规范

### 函数形态

- 函数使用箭头函数，不使用普通函数。
- 函数参数和返回值必须有类型注解。
- 函数参数统一定义为 `params`，并在函数参数中使用解构赋值。
- 单个函数不超过 89 行，超过时拆分。

### 枚举表达

- 禁止使用 `enum`。
- 使用 `const = {} as const` 替代；枚举对象和值均使用 `PascalCase`。
- 需要值联合类型时，从 const 对象派生。

### 空值与外部数据

- 使用数据属性或方法时使用 `?` 可选链，避免空指针异常。
- 外部接口、URL 参数、storage、宿主注入和 SDK 返回值先视为不可信。

### 类型断言

- 类型断言只用于边界处或已验证但 TS 无法推导的场景。
- 不用 `as` 掩盖真实类型不匹配。
- 连续断言或宽泛断言出现时，优先补充类型守卫、schema 校验或转换函数。

### Any

- 不允许直接使用 `any`。
- 确有无法收窄的历史或外部数据边界时，可使用项目约定的 `ISafeAny`。
- 使用 `ISafeAny` 后，应尽快在边界处收窄为业务类型。
