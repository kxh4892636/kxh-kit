# 体验分 E2E

体验分 E2E 是 agent-driven browser testing：功能模块下的 Markdown 验收文档是验收资产，真实浏览器操作和证据是验收执行。

## 分支

1. **写验收资产**：创建、更新、补全或沉淀体验分模块验收文档时，读取 [documentation.md](documentation.md)。完成标准：文档位于对应功能模块 `test/` 目录；每个 ready 场景都有稳定 ID、Gherkin、agent 浏览器步骤、可观察断言和执行记录位置。
2. **跑真实路径**：页面验收、浏览器操作、截图、交互、HMR、DevServer 或网络请求检查时，读取 [testing.md](testing.md)。完成标准：已执行模块验收文档中的 ready 场景，并记录 UI 断言、相关接口断言、证据、结论和失败重验范围。

## 共同契约

- 断言面向用户可观察行为：页面文本、控件状态、URL、焦点、表单值、列表内容、图表状态、加载/错误提示、下载结果、截图证据、接口响应与页面消费结果。
- 产物是 Markdown 验收文档和浏览器执行证据；代码化自动化测试用例属于其他测试体系。
- agent 操作真实浏览器不绑定具体框架；使用当前可用的浏览器控制能力操作承载用户登录态的浏览器，完成打开页面、等待加载、读取页面信息、在页面上下文执行 JavaScript、截图、网络检查和证据采集等操作。
- 通过标准必须指向用户价值、业务流程或界面契约；实现细节、私有函数、组件内部状态和 mock 调用次数不是 E2E 断言。
- 发布、流水线守护和后端排障由调用方流程负责；E2E 只消费可访问 URL、账号、权限和测试数据。发现环境或接口问题时，记录失败步骤、请求摘要、logId/traceId 和证据。
