# Dev Workflow

Dev Workflow 只编排一个垂直切片内的开发循环：**测试 -> 开发 -> 切片审查 -> 重复**。

它假设上游已经给出当前切片的目标、范围、验收依据和不做范围；它只执行当前切片，不扩展到上游决策或下游汇总流程。

## Preconditions

开始循环前，先确认当前切片具备以下输入：

- 当前切片要交付的一个用户可观察结果、后端行为结果或缺陷修复结果。
- 前端或后端边界已经明确；混合切片必须拆成前端子切片和后端子切片分别进入循环。
- 验收依据来自已确认的计划、Gherkin 场景、E2E 文档、接口契约、测试接缝、复现用例或用户明确要求。
- 当前切片的不做范围已知；未知时先停下补齐，不进入开发。

完成标准：能用一句话说明“本轮只证明什么结果”，并能指出对应前端 `bdd/e2e` 或后端 `tdd` 入口。

## Loop

每一轮只处理一个切片。切片未通过审查时，回到同一切片继续循环；切片通过后，才进入下一个切片。

1. **测试**
   - 前端切片：使用 `bdd` 写或更新一个用户可观察 Gherkin 场景，再使用 `e2e` 写或更新真实浏览器步骤、等待条件、断言和证据要求。
   - 后端切片：使用 `tdd` 确认公共接缝，在公开 API、命令、服务或契约边界上写一个会失败的测试。
   - 完成标准：前端有可执行的行为场景和浏览器验收路径；后端测试已经 red，且失败指向当前切片要证明的行为。
2. **开发**
   - 使用 `code-spec` 选择当前切片需要的最小 reference：前端读取前端、React、HTTP、React Query、Ant Design、Zod 或 Vite+ 相关规则；后端读取后端、API/RPC、数据库、集成或通用规则。
   - 只实现刚好让当前切片通过的代码，不预先实现后续切片。
   - 完成标准：实现对应本轮测试入口，相关代码遵循项目现有模式和本轮读取的 `code-spec` 规则。
3. **切片审查**
   - 使用 `verifying` 对当前切片执行最小可信验收：运行对应测试、浏览器路径、接口调用、命令或人工检查，并记录结果和证据。
   - 若失败，先判断失败来自代码、测试、数据、环境、权限还是外部依赖；修复后只重验失败项及受影响项。
   - 若当前切片有清晰 fixed point 且运行环境支持并行 sub-agent，可以使用 `code-review` 对该切片 diff 做 Standards 与 Spec 审查；否则把代码审查结论记录为待汇总事项。
   - 完成标准：当前切片通过验收，审查发现已处理或记录为明确残余风险。
4. **重复**
   - 如果还有下一个切片，用本轮事实修正它的测试入口、实现范围和验证方式，再重新开始 `测试 -> 开发 -> 切片审查`。
   - 如果没有下一个切片，退出本 skill，并报告已通过切片、证据、未处理风险和待汇总事项。

## Branch Rules

- 前端只用 `bdd/e2e` 承载测试入口；不要把前端用户旅程改写成后端 `tdd` 接缝。
- 后端只用 `tdd` 承载测试入口；不要用前端 Gherkin 或浏览器步骤替代后端公共接缝测试。
- 混合需求必须拆成多个垂直切片：后端切片先证明契约或服务行为，前端切片再证明用户旅程。
- `code-spec` 是开发阶段的底层参考，不替代测试入口。
- `verifying` 是切片审查的验收闭环，不替代 `bdd/e2e` 或 `tdd` 的测试先行步骤。
- `code-review` 只用于切片审查中可定位 fixed point 的 diff；没有 fixed point 时记录待汇总事项。

## Loop Constraints

- 禁止一次撰写所有测试或者撰写所有实现，这是水平切片方式，导致低质量测试/开发。
- 每轮只处理一个垂直切片，并完成该切片的测试、开发、审查。
- 每个切片基于上一循环的事实，对当前切片进行修正。
- 审查包括验收；在可定位 fixed point 时，也包括代码审查。
- 如果项目存在计划、状态同步或上下文文档，每个垂直切片状态变化后立即同步状态，不得全部开发完成后再统一同步。

```text
WRONG (horizontal):
  TEST:   test1, test2, test3, test4, test5
  DEV:    impl1, impl2, impl3, impl4, impl5
  REVIEW: verify1, verify2, verify3, verify4, verify5

RIGHT (vertical):
  TEST->DEV->REVIEW: test1->impl1->verify1
  TEST->DEV->REVIEW: test2->impl2->verify2
  TEST->DEV->REVIEW: test3->impl3->verify3
  ...
```
